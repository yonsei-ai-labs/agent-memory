# 데이터 보강의 역할과 제작·검수 인계

2026-11-12. 사용자가 데이터 보강의 담당 방식을 문의하여 정리한 권장 분업과 전달 사항임. **새 세션·원천 제작은 기존 전달 경로 생성기를 다룬 에이전트가 맡고, Codex는 학습용 관계 증강·출처 관리·독립 검산을 맡는 구성이 적절함.** 상대 에이전트와 합의하거나 이 문서를 외부로 전송한 상태는 아님.

목표는 **현재 목표·진행·실패 이력에 따라 과거 기록의 필요성이 달라지는 자료를 보강하고, 그 판단을 실제 기억 제공의 이득·손해와 연결하는 것**임. 새 모델 구조나 별도 영역으로의 확장은 이번 인계의 목표가 아님.

**진행 업데이트:** 사용자 동의 후 Codex가 [인수 준비·기존 자료 자체 검토](reports/2026-11-12-data-intake-readiness.md)를 완료함. 4,224개 판독 입력과 근거 8,448구간이 기계적 검사를 통과했고 관련 테스트 54개가 통과함. 현재 카탈로그 정보를 보완한 별도 검토표도 준비함. 작성자 자체 검토이며 독립 인간 검토는 0임. 새 제작본이나 상대의 착수 확인은 아직 없음.

## 1. 권장 역할

| 담당 | 구체적인 일 | 전달 산출물 |
| --- | --- | --- |
| 기존 전달 경로 실험 에이전트 | [숨은 함정 설계](ai-memory-hidden-memory-traps-plan-2026-11-12.md)를 기존 생성기에 연결하고 새 세션·현재 상태·근거를 제작함. 실제 작업자 측정은 데이터 동결과 실행 조건 확정 뒤 진행함 | 출처 목록, 대본·공개 문장, 관계 라벨, 실행 전 검토 묶음. 실행한 경우 원 입력·출력·비용 |
| Codex | 기존 학습 자료의 상태 관계 증강을 유지하고, 새 자료의 출처 분할·입력에서의 판정 가능성·관계/효용 라벨 분리와 결과 재계산을 검증함 | 학습용 파생 자료, 독립 검산 코드·보고서, 불일치 목록 |
| 독립 검토자 | 기존 정답을 먼저 보지 않고 공개 문장의 의미와 필요 기록을 판정함 | 검토 ID별 판정·모호성·불일치 사유 |

모델 학습의 담당·일정은 이 문서에서 새로 배정하지 않음. 같은 원천을 두 에이전트가 서로 다른 분할·라벨로 동시에 증식하지 않도록 원천 제작본 하나에 버전을 부여함.

## 2. 이미 준비한 자료

Codex가 만든 [memory_state_augmentation / 20261112-v1](../datasets/memory_state_augmentation/20261112-v1/README.md)은 다음 상태임.

- 기존 학습 **11가족·원 기록 477개**만 사용함.
- **1,056상태·고유 pair 입력 4,224쌍**임. 새 독립 출처는 0임.
- 현재 분기 변경·확인한 사실 추가·세 가지 표현을 대조함.
- 정답을 별도 파일로 분리한 검토용 24사례를 준비함. 사람 검토는 미완료임.
- 실제 득실 라벨은 모두 미측정이며 새 학습·작업자 실행은 하지 않음.
- 테스트 41개와 새 디렉터리 10파일의 동일 재생성을 확인함. 이번 인계 준비에서도 audit를 다시 통과함.

이 자료를 숨은 함정 평가 자료로 설명하지 않음. 상태·목표가 명시적인 관계 학습용 증강임. 새 평가용 세션을 그대로 이 학습 자료에 추가하지 않음.

## 3. 저쪽에 전달할 제작 요청

> 새 데이터의 주 제작을 맡아 주세요. 기존 전달 경로 생성기를 이어서 사용하고, 첫 납품은 **작업자 실행 전 검토 가능한 데이터 패킷**으로 부탁합니다. 같은 경험에서 현재 조건에 따라 필요한 기억이 달라지는 대조를 중심으로 구성해 주세요. 아래 입력·정답·분할·비교 기준을 함께 남겨 주시면 Codex가 독립 검산하겠습니다.

### 출처와 분할부터 고정함

- 출처별 원 ID, 부모 세션, 기존 사용 이력, 이번 역할을 목록으로 만듦. 원천 가족을 먼저 나누고 모든 변형을 같은 분할에 둠.
- 새 독립 가족과 표현·이름·관측을 바꾼 변형 수를 따로 보고함. 1,056상태를 1,056독립 경험으로 계산하지 않음.
- `new-a`의 남은 가족 수와 적격성을 실제 manifest에서 확인함. 제안 노트의 수집 목표를 확보 완료 수로 쓰지 않음.
- 현재 확인한 `new-a`는 44가족이며 기존 본 세션 사용 20개를 제외한 후보는 24개임. **24개 모두 이전 stage1 평가에는 등장했음.** 새 시나리오에 안 쓴 출처와 전혀 관찰하지 않은 평가 출처를 구분함. [사용 이력 목록](reports/data/memory-data-intake-20261112-v1/source-inventory.jsonl)을 함께 전달함.
- 봉인된 `new-b`는 마지막 확인용으로 유지함. 새 학습 자료나 생성 문장·라벨을 고치는 재료로 사용하지 않음.
- 기존 20세션과 이미 관찰한 평가 결과는 역할을 유지함. 학습으로 전환해야 한다면 버전과 사용 이력을 명시하고 이후 새 평가라고 부르지 않음.

### 실제 선택기 입력만으로 관계 정답을 판정할 수 있어야 함

- 대본·사건 구조와 작업자/선택기에게 보이는 문장을 따로 저장함. 판정에는 해당 시점까지의 사건만 사용함.
- 다른 기록의 변경·취소로 기존 기록이 무효가 되었다면, 그 근거가 실제 선택기 입력 어디에 있는지 연결함.
- 후보 하나씩 읽는 모델에 이후 기록이 보이지 않는다면, 그 보이지 않는 기록을 알아야만 맞히는 정답을 그대로 학습시키지 않음. 필요한 공개 맥락을 포함하거나 정보 부족으로 구분함.
- 같은 실제 모델 입력에 반대 정답이 붙는지, 표현을 바꾸어도 의미가 보존되는지 검사함. 은행 순서만 바뀌어 pair 입력이 같으면 새 학습 표본으로 세지 않음.
- 간접 서술의 함축이 대본보다 약하면 모호성으로 남김. 예를 들어 호텔의 영업 중단이 과거 예약의 취소까지 뜻하는지는 현재 질문과 문장 근거로 확인해야 함.

### 관계와 실제 득실은 별도로 보존함

- 관계: 현재 필요한 사실, 적용 조건, 이미 확인한 사실, 충분한 기록 집합, 현재 비활성인 기록과 근거 위치를 기록함.
- 효용: 작업자 실행 전에는 `null`임. 기존 문장의 성공·실패를 새 문장이나 다른 상태에 복사하지 않음.
- 실행 후에는 기준 조건 ID와 양쪽 원 입력·출력을 연결하여 이득·손해·둘 다 성공·둘 다 실패를 나눔.
- 무기억 대비 손해와 필요한 근거 조건 대비 손실을 구분함. 후자의 기준이 항상 작업자의 성능 상한인 것은 아님.
- 오답이 무효·다른 기록과 일치하는 유형은 관측 진단으로 남김. 원인 기록을 확정한 라벨로 바꾸지 않음. 여러 기록과 동시에 일치하면 모호성을 표시함.

### 기존 대조를 재사용하고 새 조건의 차이를 먼저 확인함

- 기존 자료의 전역 무효 예약 제거는 `records_latest`와 같았음. 새 자료에서도 기록 ID·순서·본문을 비교하여 같은 조건을 다시 호출하지 않음.
- 취소 후 재예약이나 유효한 보완처럼 사건 구조가 달라지면 두 정책이 달라질 수 있음. 그때 실제 차이와 확인하려는 질문을 함께 기록함.
- 대본의 정답을 사용한 삭제는 진단용으로 표시함. 공개 입력으로 동작하는 규칙·검색·학습 선택과 구분함.
- 모델 간 비교에는 같은 고정 과거를 읽는 비교를 포함하거나, 서로 다른 자기 과거를 읽었다는 범위를 명시함.
- 문맥 예산과 전달 정책을 먼저 고정함. 예산을 사후에 줄이거나 실패 사례만 남겨 선택기의 이득을 만드는 방식은 사용하지 않음.

## 4. 첫 데이터 패킷의 최소 파일

| 파일 | 필수 내용 |
| --- | --- |
| `source-inventory.jsonl` | 가족 ID, 부모 출처, 새 원천/파생 여부, 기존 사용 이력, 분할 |
| `events.jsonl` | 사건·효력 범위·시각·대상. 생성용 정답 구조이며 모델 입력에서 제외 |
| `cases.jsonl` | 판단 시점, 목표, 공개 진행·실패·관측, 후보 은행과 실제 모델 입력 |
| `relations.jsonl` | 필요한 기록·조건·충분 집합·근거 위치·정보 부족·모호성. 실제 효용은 `null` |
| `contrasts.jsonl` | 같은 기억의 상태 변경, 관측 변경, 동등 표현 연결. 바뀌거나 보존돼야 하는 항목 |
| `review-packet` / `review-key` | 정답을 먼저 보지 않는 검토표와 별도 대조 정답 |
| `protocol.json`, `manifest.json` | 생성 기준, 분할, 비교 조건, 실제 입력에 포함하지 않을 필드, 원문·코드 해시 |

실행한 경우에만 별도 `outcomes`를 추가함. `(가족, 상태, 작업자·revision, 기준 조건, 비교 조건, 입력 해시, 양쪽 원 출력, 채점 버전, 비용)`을 연결함. JSONL 행 수를 독립 호출 수로 세지 않음.

문자열·근거·시점의 기계적 확인은 [인수 계약 v1](design-data/memory-data-intake-20261112-v1/README.md)과 예제 adapter를 사용할 수 있음. 외부 제작본을 이 형식으로 다시 쓰도록 강제하지 않고 원본을 보존하는 adapter로 연결함. 현재 검사는 토큰화 전 문자열에 대한 것이며 실제 모델의 토큰화·입력 절단 검증은 별도임.

## 5. Codex가 받을 때 확인할 항목

1. 출처 중복·분할·과거 평가 사용 이력과 증강 전후 원문 근거.
2. 대본과 공개 문장의 의미 일치, 현재 시점 이후 정보의 유입 여부.
3. 실제 입력의 중복·상충 정답·길이·누락, 관계와 효용의 구분.
4. 모든 고정 유형·중립·정보 부족·미완료의 포함 여부. 손해가 적거나 단순 규칙이 잘 맞힌 결과도 보존함.
5. 실행했다면 양쪽 원 출력의 별도 재채점과 가족 단위 집계. 서로 다른 작업자·기준·채점 결과를 합친 손해율은 만들지 않음.

사람 의미 검토와 기계적 검산은 별도 상태로 보고함. 모델이 어느 유형에서 반드시 실패해야 데이터가 유효하다는 채택 기준은 두지 않음. 자료의 타당성과 그 자료에서 학습 선택기가 추가로 유용한지는 각각 판단함.

## 6. 지금 할 일과 현재 미실행 범위

지금은 **기존 학습용 증강은 Codex가 관리하고, 새 독립 세션 제작본을 저쪽에서 하나로 준비하는 분업**을 권함. Codex의 다음 데이터 작업은 그 제작본의 검토·분할 연결·학습용 파생임. 기존 train-only 증강본은 이미 사용할 수 있는 상태로 보존함.

이 문서는 새 세션 생성 완료나 GPU·유료 실행 개시를 뜻하지 않음. 상대에게 실제 전달·합의·담당 수락은 확인하지 않았으며, 여기서는 전달 가능한 작업 명세를 작성함.
