# 기억 실험의 세 미해결점 보완과 검증

2026-11-09. 실험 범위를 확대하기 전에 작업자의 근거 부족 판단, 독립 경험의 수, 후보 개수 편법을 점검하기 위한 제안이다. 아래 비교와 통과 기준은 후속 설계이며 실행 결과가 아니다.

2026-11-10 후속: 최신 실험에서 드러난 네 미해결점의 수행 순서·산출물·완료 기준은 [네 미해결점 보완 실행안](ai-memory-four-issues-catchup-plan-2026-11-10.md)에 정리했다. 아래의 검증 원칙과 후속 점검 노트는 그 실행안의 확인 항목으로 사용한다.

**먼저 현재 측정의 타당성을 보완하고, 방법을 고정한 뒤 새 문제군에서 확인한다.** 같은 작업자와 기억 은행, 공통 컨텍스트 상한을 유지하면서 어떤 기억을 제공해야 실제 성공·오류·비용이 개선되는지 판단하는 것이 목적이다.

세 문제는 증거를 확보하는 방법이 다르다. 작업자의 기본 판단과 후보 개수 편법은 작은 통제 대조로 점검할 수 있다. 독립 경험 부족은 기존 자료의 출처 감사로 범위를 밝힐 수 있지만, 새 경험에서의 확인은 별도로 필요하다. 각 문제에서 **이미 관측한 사실, 확인할 가설, 보완의 통과 조건**을 구분한다.

## 작업자의 근거 부족 판단 검증

### 같은 질문에서 세 판단을 구별한다

요청을 “Alex의 과거 식당을 다시 선택하라”로 고정한다. 현재 카탈로그에는 이용 가능한 R1과 이용 불가능한 R2가 있다. 과거 기록의 개수·배치·길이를 가능한 한 맞추고 다음을 비교한다.

| 제공한 과거 기록 | 현재 입력으로 가능한 판단 | 기대 출력 |
| --- | --- | --- |
| Alex가 R1을 선택했다는 기록 | 과거 선택을 알며 현재 이용 가능하다. | R1 |
| Alex가 R2를 선택했다는 기록 | 과거 선택을 알며 현재 이용 불가능하다. | NONE |
| Taylor의 기록만 있고 Alex의 선택은 없다. | Alex가 R1과 R2 중 무엇을 선택했는지 알 수 없다. | UNKNOWN |

UNKNOWN 정답은 작업자가 실제 받은 현재 관측과 전달 기억을 기준으로 정한다. 은행에만 있고 전달하지 않은 기록을 작업자가 안다고 가정하지 않는다. 다른 근거로 답을 확정할 수 있는 경우도 검토한다. 예를 들어 위 마지막 입력과 양립하는 과거 상황을 Alex=R1, Alex=R2로 두면 정답이 달라지므로, 이 사례에서는 누락한 정보가 실제 결정에 필요하다.

처음에는 식당 하나만 묻는다. 그다음 같은 성분을 조합해 식당·숙소를 함께 묻고, 항목별 정답과 두 항목 동시 정답을 모두 측정한다. 단일 판단에서도 실패하는지, 함께 답할 때 실패가 늘어나는지 구별한다. 이름·날짜·기록 위치를 바꾸는 대조도 포함하되, 원본과 변형은 같은 개발/확인 그룹에 둔다.

### 짧은 구조화 출력의 보완 효과를 비교한다

기존 출력 형식과 “사용한 근거 ID, 판단 상태, 선택 ID”를 반환하는 형식을 비교한다. 긴 추론문을 요구하지 않는다. 같은 모델 revision·생성 설정·입력 근거를 사용하고, 두 형식 모두 응답이 잘리지 않는 공통 출력 상한을 정한다. 출력 형식을 바꾸면 입력 지침과 출력 비용도 달라지므로, 결과는 해당 인터페이스 변경의 효과로 해석한다.

근거 ID는 실제 입력에 존재하는지, 주체·날짜·대상이 맞는지 검사한다. 구조화 출력의 형식 오류와 의미 오류를 따로 기록한다. 검사기가 답을 강제로 교정하는 조건을 추가한다면, 작업자 자체의 판단 개선과 구분한 시스템 보완으로 보고한다.

개발용 문제에서 보완안을 선택한 뒤, 사용하지 않은 이름·수치·표현과 문제 조합으로 만든 확인 묶음에 적용한다. 같은 실패 사례를 반복 수정해 얻은 성적은 개발 결과로 남긴다.

### 통과 조건

- 확인 묶음에서 UNKNOWN과 NONE의 혼동, 근거 없는 구체적 답이 줄어든다.
- 근거가 충분한 문제의 구체 ID·NONE 정답 성능을 유지한다. 모든 항목에 UNKNOWN을 출력하는 방식은 통과하지 못한다.
- 원형과 변형을 함께 맞힌 비율, 항목별 혼동표, 복수 출력 성능을 보고한다.
- 최소 범주별 정확도, 허용할 성능 저하 폭, 오류율 기준을 확인 실행 전에 수치로 정한다. 작은 기능 점검의 통과를 전체 여행 과제의 일반화로 확대하지 않는다.

이 설계는 기본 기능, 의미를 유지하는 변형, 정답이 바뀌어야 하는 변형을 구분하는 [CheckList](https://aclanthology.org/2020.acl-main.442/)의 접근을 현재 과제에 적용한 제안이다.

## 독립 경험과 결론의 안정성 점검

### 기존 자료에서 먼저 확인할 것

현재 평가에는 이미 문제군 단위 제외가 적용돼 있다. 추가 감사에서는 분할 적용 여부와 함께 **전체 결론이 어느 문제군에 의존하는지** 확인한다.

1. 원본 계획·과거 기록·현재 요청·상태 변형·전달 묶음·실제 생성의 연결표를 만든다. 같은 입력의 응답 재사용과 새 생성을 구별한다.
2. 정책별 성공 차이, 개선·악화 수, 근거 없는 행동과 토큰을 문제군별로 표시한다. 현재 상태별 결과도 함께 남긴다.
3. 문제군 하나를 제외했을 때 전체 비교의 방향과 크기가 얼마나 달라지는지 확인한다. 학습 정책은 이미 해당 문제군을 제외해 만든 예측을 사용한다.
4. 불확실성을 문제군 단위로 집계한다. 반복 생성과 학습 seed는 실행 안정성의 별도 축으로 두며, 독립 출처 수에 더하지 않는다.

기존 상위2 대 상위4의 성공 차이는 순 +4/96이지만, 문제군 부트스트랩 구간은 약 −1.0~+10.4%p였다. 이 값은 이미 살펴본 12문제군의 탐색적 기술 통계다. 같은 자료를 재표집하거나 표현을 늘려도 새 출처 일반화의 증거가 생기는 것은 아니다.

### 보완 뒤 새 문제군에서 확인한다

기존 12문제군은 보완·개발용으로 유지한다. 작업자 인터페이스와 편법 통제를 정비한 뒤, 개발 자료에서 정책·임계값·비교·최소 실용 효과·허용 오류와 비용을 고정하고 남겨둔 새 문제군에서 확인한다. 준비된 dev20/test40의 역할과 절차는 [새 문제군 일반화 검증안](ai-memory-fresh-source-evaluation-2026-11-09.md)을 따른다.

동일 계획의 파생 자료는 같은 분할에 두고, 기억 은행·도시·카탈로그의 공유도 기록한다. 같은 여행 도메인의 새 문제군 평가와 다른 은행·도메인으로의 전이는 별도 주장이다. 자료 수는 확인하려는 최소 효과와 문제군별 변동에 맞춰 정하며, 결과가 좋아 보이는 일부만 골라 확인 집합으로 삼지 않는다.

현재 단계의 완료 조건은 출처 연결과 결론의 민감도를 설명하고 확인 절차를 고정하는 것이다. **독립 경험 부족의 해소와 새 문제군에서의 우위는 실제 확인 결과가 필요하다.** 구간이 넓거나 실용적으로 필요한 차이를 구별하지 못하면 결론을 미확정으로 남긴다. 평가 결과를 보고 설정을 수정한 회차는 탐색으로 보존한다. 평가 자료에 반복적으로 방법을 맞추는 위험은 [Cawley와 Talbot의 모델 선택 편향 연구](https://www.jmlr.org/papers/v11/cawley10a.html)가 다룬다.

## 후보 개수 편법의 사용 여부와 보완 검증

### 개수와 근거를 서로 독립적으로 바꾼다

| 후보 은행 크기 | 지정 근거 있음 | 지정 근거 없음 |
| --- | --- | --- |
| 작은 은행 | 지지 기록을 포함한다. | 같은 수의 검토된 비지지 기록으로 교체한다. |
| 큰 은행 | 같은 지지 기록을 유지하고 비지지 기록을 추가한다. | 작은 은행과 같은 부재 조건을 유지하며 비지지 기록을 추가한다. |

각 크기 안에서 근거 있음·없음의 비율을 맞춰 개수가 정답을 구별하지 못하게 한다. 비지지 기록은 허용된 출처·시점 범위에서 만들고, 통제 변형이면 그 사실을 기록한다. 대체 근거가 현재 관측이나 다른 후보에 남지 않았는지 검토한다. 길이·ID 형식·후보 순서 같은 다른 단서도 함께 점검한다.

두 종류의 짝을 평가한다.

- **개수 유지, 근거 변경:** 필요한 기록을 같은 수의 비지지 기록으로 교체하면 근거 확보 판단이 적절하게 바뀌어야 한다.
- **근거 유지, 개수 변경:** 필요한 기록을 유지하며 비지지 기록 수를 바꿔도 근거 확보 판단을 유지해야 한다.

후보 개수·토큰 길이·ID 형식만 보는 기준선, 실제 내용을 읽는 동결 모델, 명시적 참조 규칙을 비교한다. 개수 기준선은 사전에 정한 규칙뿐 아니라 개발 자료에서 다른 단순 규칙을 찾을 수 있는지도 점검한다. 통제 자료에 대한 추가 학습은 동결 모델의 의존성 검사와 별도 비교로 남긴다.

### 통과 조건과 해석 범위

개수 등 형식 정보만 보는 기준선의 이점이 사라지고, 실제 내용을 읽는 모델이 두 종류의 짝을 함께 통과하는지 확인한다. 개별 정확도와 함께 짝의 양쪽을 모두 맞힌 비율, 은행 크기별 결과를 보고한다. 후보 수·길이 분포를 맞췄다는 설계 검사와 모델의 행동 검사를 모두 남긴다.

기존 모델이 통제 자료에서도 잘하면 해당 편법에 의존한다는 우려를 줄일 수 있다. 성능이 떨어지면 그 대조에 취약하다는 증거이며, 다른 입력 변화도 점검한 뒤 개수 의존의 범위를 해석한다. 한 번의 성적 하락만으로 내부 판단 원인을 확정하지 않는다. 벤치마크에서 잘 작동하는 단서와 다른 조건으로 옮겨가는 판단을 구분해야 한다는 문제는 [Shortcut Learning](https://arxiv.org/abs/2004.07780)과 연결된다.

이 검사의 정답은 지정 기록의 확보 또는 별도 검토한 근거 관계다. 지정 기록 ID의 존재를 의미적 충분성 정답으로 자동 승격하지 않는다. 또한 기록을 추가해도 실제 작업자의 성공률이 같아야 한다고 강제하지 않는다. 입력을 바꾼 기억 묶음의 실제 득실은 새 실행으로 측정하며, 이전 결과를 복사하지 않는다.

| 단계 | 수행할 일 | 산출물과 다음 단계 조건 |
| --- | --- | --- |
| 1 | 기존 자료의 출처 연결·재사용·문제군별 효과를 CPU로 감사한다. | 독립 집계 단위와 결론의 민감도 표를 확보한다. |
| 2 | 세 판단과 개수·길이를 통제한 작은 대조 묶음을 만든다. | 근거 인용·허용 정답·변경 요인·개발/확인 분할을 검산한다. |
| 3 | 동결 모델의 편법 의존성을 검사하고, 작업자 출력 보완안을 작은 실행으로 비교한다. | 범주별 오류와 정답 유지, 비용을 확인하고 인터페이스를 고정한다. |
| 4 | 개발 자료에서 선택 정책을 정하고 새 문제군 확인을 수행한다. | 성공·악화·근거 없는 행동·총비용의 차이와 문제군별 불확실성을 보고한다. |

첫 산출물은 **어떤 조건을 바꾸면 판단이 바뀌어야 하고, 무엇은 유지돼야 하는지 명시한 검증표**다. 각 행에 부모 문제군, 현재 관측, 후보·전달 기억, 근거 위치, 허용 정답, 대조 관계와 판정 이유를 연결한다. 원래 상태와 변형을 같은 분할에 두고 정답·조건 이름은 모델 입력에서 제외한다.

작업자 또는 입력 계약을 바꾸면 효용 결과의 조건도 달라진다. 기존 정답·출력·가중치·결과는 보존하고 새 버전으로 기록한다. 통과 기준·호출 상한·중단 기준은 확인 실행 전에 고정한다. 이 보완을 통과한 뒤 새로운 모델 구조나 도메인으로 확대한다.

## 후속 점검 노트

2026-11-09. 이후 논의에서 추가한 연구 완성도 점검 항목이다. 핵심은 **현재 상태를 입력에 넣었는가, 상태와 기억의 관계를 활용하는가, 그 선택이 실제 작업에 이득인가**를 각각 확인하는 것이다. 각 체크박스는 아래 검증의 근거 파일·결과·판정 범위를 연결한 뒤 완료로 표시한다. 기존 코드나 문서가 있다는 사실만으로 통과 처리하지 않는다.

### 모델의 역할과 검증할 주장

Harrier는 텍스트를 벡터로 표현한다. 검색 실험은 질문과 기억을 각각 인코딩한 유사도, 또는 함께 인코딩한 관계 판독 점수를 사용한다. 최근 효용 선택 구현은 목표·현재 관측·제안 묶음을 함께 인코딩하고, MLP의 네 결과 점수에서 `P(개선)-P(악화)`를 계산해 묶음을 선택하거나 보류한다. 실제 답변과 작업은 별도 작업자가 수행한다. [현재 입력·행동 계약](../data_pipeline/prepare_memory_state_ablation.py), [학습 구현](../training/memory_selector/train_memory_state_ablation.py), [선택·평가 구현](../evaluation/memory_state_ablation.py)을 기준으로 역할을 구분한다.

- [ ] 검증할 대상을 검색기, 관계 판독기, 효용 예측기, 선택기+작업자 중 무엇인지 명시한다. 같은 Harrier 기반이라도 서로 다른 adapter·판독층의 성적을 합치지 않는다.
- [ ] 목표와 현재 관측을 구분하고, 판단 시점에 실제로 알 수 있었던 정보만 입력에 넣는다. 현재 여행 자료에 없는 실제 진행·실패 이력의 활용 효과는 별도 수집 전까지 주장하지 않는다.
- [ ] 선택 가능한 행동이 개별 기억, 미리 제안한 묶음, 보류 중 무엇인지 고정한다. 현재 관측 묶음 사이의 선택 결과를 임의의 기억 조합을 탐색한 결과로 확대하지 않는다.

### 입력 ablation으로 각 정보의 기여를 확인한다

여기서 G는 현재 목표, C는 현재 관측, M은 제안된 기억 묶음이다. 현재 코드의 `goal` 조건은 **G+M**, `goal_and_observations`는 **G+C+M**이다. 두 조건 모두 같은 제안 묶음을 읽는다. 아래 G와 G+C는 추가 진단 후보이며, 기존 비교에 이미 포함됐다고 해석하지 않는다.

| 선택기가 읽는 입력 | 확인할 질문 |
| --- | --- |
| G | 목표의 문장 틀·과제 난도만으로 결과를 예측하는가? |
| G+C | 현재 상태만으로 예측하는가? 어떤 묶음인지 몰라도 같은 결정을 내리는가? |
| G+M | 현재 관측 없이 목표와 과거 기억만으로 얼마나 판단하는가? |
| G+C+M | 현재 관측을 명시적으로 추가하면 예측·묶음 선택·작업 결과가 개선되는가? |

- [ ] 주 비교는 같은 구조와 예산의 G+M 대 G+C+M으로 유지한다. 나머지 조건은 문제의 위치를 좁히는 대조로 두며, 확인 결과를 보고 가장 유리한 비교로 주장을 바꾸지 않는다.
- [ ] **각 입력 조건을 별도로 학습하는 ablation**과 **학습된 모델의 입력을 가리거나 교환하는 검사**를 구분한다. 후자는 학습 분포 밖 입력에 대한 민감도일 수 있으므로, 성능 하락만으로 관계 이해를 증명하지 않는다.
- [ ] 각 조건의 학습 행·초기값·판독 구조·데이터 노출·업데이트·checkpoint 선택 규칙을 맞춘다. 입력이 길어진 조건의 토큰·계산 비용도 보고한다. 같은 업데이트 수를 같은 계산량이라고 부르지 않는다.
- [ ] 입력 제거는 선택기에만 적용하고 작업자가 받는 공통 현재 관측은 유지한다. 제안 묶음 집합도 같게 둔다. 상류 검색·규칙이 현재 상태를 사용했다면 G+M 조건의 후보 자체에 남은 상태 신호를 명시한다.
- [ ] 관측을 지운 뒤 동일한 입력에 서로 다른 정답이 붙는지 집계한다. 관측 행에 대한 결정적 분류의 사후 상한을 모델 성적·일반화 상한과 구분한다. 숨긴 정보 때문에 구별 불가능한 사례를 구현 실패로 단정하지 않는다.

### 상태와 기억의 교차 대조로 관계 활용을 확인한다

같은 목표에서 C1·C2와 M1·M2를 준비하고 **C1×M1, C1×M2, C2×M1, C2×M2**를 모두 확인한다. C는 현재 관측의 변경이며 목표 문구만 바꾸는 실험과 구분한다. 네 조합이 각각 유효한 상황인지 먼저 검토한다.

- [ ] 관계 진단에서는 상태 하나나 기억 하나만 보고 정답을 맞힐 수 없도록 정답을 배치한다. 같은 상태·기억이 여러 관계 정답과 함께 등장하도록 만들고 개별 값과 정답의 연결을 검사한다. 실제 효용 라벨을 균형에 맞추려고 임의로 바꾸지는 않는다.
- [ ] 같은 기억에서 적용 조건만 변경한 짝, 같은 현재 상태에서 기억의 주체·시점·전제만 변경한 짝을 만든다. 전체 후보 수·제안 묶음 수·길이·ID·배치가 정답의 단서가 되지 않는지 확인한다.
- [ ] 관계 정답과 그 판독 방법을 먼저 정한다. 현재 네 범주 효용 점수의 부호를 적용성 정답으로 사용하지 않는다. 추가 관계 판독층을 학습한다면 원래 효용 모델과 구분한 진단으로 보고한다.
- [ ] 개별 정확도 외에 대조 쌍의 양쪽을 맞힌 비율과 네 조합을 모두 맞힌 비율을 보고한다. 상태만·기억만 보는 대조, 개수·길이 기준선, 명시적 관계 규칙과 비교한다.
- [ ] 의미·주체·시점을 보존한 바꿔쓰기와 일관된 이름/ID 치환에서도 관계 판단을 확인한다. 표현·전달 순서가 달라진 작업자의 실제 효용까지 같다고 강제하지 않는다.

이 대조를 통과하면 상태와 기억의 관계를 활용한다는 행동 근거를 얻는다. 입력에 따른 벡터·점수 변화, attention 시각화, 모델이 생성한 설명만으로 올바른 매칭이나 내부 추론 과정을 확정하지 않는다. 명시적 문자열 규칙으로 풀리는 대조는 최소 기능 점검으로 보고, 보지 않은 표현·조건 조합·출처에서의 확인과 구분한다.

### 실제 득실 정답과 선택 가능한 신호를 확인한다

- [ ] 관계·충분성 주석과 실제 성공·오류·비용을 별도로 보존한다. 중복 기억을 자동으로 무익, 조건 불일치 기억을 자동으로 유해라고 라벨링하지 않는다.
- [ ] 새로운 C×M 조합이나 전달 순서를 만들면 같은 작업자·동일 사전 상태에서 제공/미제공 결과를 측정한다. 실행하지 않은 행동은 미측정으로 두고 다른 조합의 결과를 복사하지 않는다.
- [ ] 상태별로 무기억과 제공의 결과가 다른 수, 비어 있지 않은 묶음끼리 결과가 다른 수, 순위 학습에 유효한 쌍의 수를 센다. 모든 후보의 결과가 같은 상태가 많은 자료로 세밀한 기억 선택을 입증하려 하지 않는다. [현재 자료의 신호 점검](reports/2026-11-09-memory-state-ablation.md)을 참고한다.
- [ ] UNKNOWN/NONE 혼동, 근거 없는 구체적 행동, 성공 여부와 비용을 따로 측정한다. 한 번의 작업자 오류가 효용 라벨에 섞인 정도는 사전 지정 반복으로 확인하고, 반복을 새 경험 수에 더하지 않는다.

### 기준선과 학습 비교를 공정하게 유지한다

- [ ] 무기억, 기본 검색, 고정 개수/경계 정책, 적용 가능한 규칙을 유지한다. 무기억 대비 개선과 단순 선택 정책 대비 추가 이득을 각각 보고한다. 전체 기억이 공통 상한을 넘으면 별도 비용 진단으로 둔다.
- [ ] 고정 Harrier+학습 판독층과 LoRA+같은 판독층을 구분한다. 입력·학습 목표·구조를 동시에 바꿔 특정 요인 하나의 효과로 해석하지 않는다.
- [ ] 성공률 예측, 네 범주 분류, 같은 상태의 묶음 순위, 최종 선택 후 성공률을 각각 평가한다. 학습 정확도나 분류 F1만으로 좋은 선택을 배웠다고 결론내리지 않는다.
- [ ] 확률 보정·임계값 선택은 개발 자료에서 수행하고 확인 전에 고정한다. `P(개선)-P(악화)`는 현재 모델의 성공 변화 예측 점수이며, 오류·비용까지 포함한 검증된 인과 효용이나 전체 순효용으로 부르지 않는다.

### 독립 평가와 벤치의 역할을 고정한다

- [ ] 부모 문제군·과거 경험·공유 실행·변형을 연결해 같은 그룹으로 분할한다. 이미 여러 번 살펴본 12문제군의 제외 평가와 새 문제군 확인을 구분한다. 반복 행·학습 seed를 독립 과제 수로 세지 않는다.
- [ ] 방법과 주 비교, 최소 실용 효과, 허용 악화·오류·비용, 평가 수와 중단 기준을 확인 실행 전에 정한다. 실패·중단·불리한 결과도 배정과 함께 보존한다.
- [ ] 문제군별 짝 비교와 불확실성, 한 문제군을 뺐을 때의 민감도를 보고한다. 관측 악화가 적거나 구간이 넓으면 손해 방지와 일반화 주장을 제한한다.
- [ ] LongMemEval-S는 검색 전이와 별도 작업자를 붙인 답변 평가로 사용한다. 효용 선택을 평가하려면 제공·미제공 실행을 추가하고, 그 점수를 실제 진행·실패 이력 활용의 증거로 확대하지 않는다.
- [ ] Mem2ActBench는 원문·정답을 검수한 범위에서 도구 인자 적용을 평가한다. BFCL/AppWorld는 과거 경험 은행·선택기·작업자 실행 연결을 검증한 뒤 시스템 평가에 사용한다. 현재 가중치의 동결 전이와 외부 자료로 재학습한 성적을 구분한다. [원천 검토와 연결 작업](ai-memory-next-steps-feasibility-2026-11-09.md)을 따른다.

### 비용과 재현 근거를 완성한다

- [ ] 선택기가 실제 읽은 입력·선택한 순서 있는 기억 ID·분류 점수·행동·작업자 출력·채점 결과를 연결한다. 모델 revision·adapter/head 해시·입력 길이·잘림·파싱 실패도 남긴다.
- [ ] 선택을 위해 점수화한 모든 묶음의 인코딩·판독 비용, 검색 비용, 작업자 입력/출력 비용을 포함한다. 저장 특징의 재생 시간과 온라인 지연을 구분하고 알 수 없는 비용은 `null`로 둔다.
- [ ] 다른 장비에서 측정한 선택기 시간과 작업자 시간을 더해 실제 측정한 전체 지연이라고 보고하지 않는다. 비용 개선을 주장할 때에는 측정 범위를 명시한다.
- [ ] 입력/정답 노출 방지, 분할, 가중치 변화·데이터 노출·선택 규칙, 저장 출력의 재채점을 재현한다. 코드 검사·저장 결과 재생·실제 모델 재실행의 확인 범위를 각각 기록한다.

### 확인 결과에 맞춰 주장을 마무리한다

| 확보한 증거 | 가능한 주장 |
| --- | --- |
| 현재 관측만 달리한 공정한 입력 ablation과 새 문제군 평가 | 현재 관측을 명시적으로 추가한 효과를 관측했다. |
| 편법을 통제한 교차 대조와 새 문제군의 관계 판독 | 해당 조건·출처에서 상태와 기억의 관계를 활용하는 행동을 확인했다. |
| 같은 작업자·은행·예산에서 단순 정책 대비 성공·오류·비용 개선 | 해당 평가 범위에서 학습 선택기의 추가 가치를 확인했다. |

세 주장을 자동으로 이어 붙이지 않는다. 현재 관측 추가로 분류 성적이 올라도 매칭이나 실제 효용이 개선됐는지 따로 확인한다. 결과가 미확정이거나 단순 정책을 넘지 못하면 그 범위와 실패 유형을 보고한다. 첫 마무리 목표는 **입력 기여 → 관계 활용 → 실제 선택 효과**의 각 주장에 필요한 근거를 갖추는 것이다.
