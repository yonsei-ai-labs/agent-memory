# 외부 기억 갱신 대조 평가 계획

2026-11-11. 현재 근거가 충분한 상태에서 옛 기록을 더했을 때 성공이 깨지는지 검증함. 같은 상태의 반복 기록과 답의 대상값을 알려 주지 않는 기록을 대조함. 이 회차는 득실 측정 장치의 외부 검증이며 선택 모델을 새로 학습하는 실험은 아님. 이후 필요성 학습과 실제 효과를 연결할 때 사용할 근거를 확보함.

## 고정할 비교

작업자는 이전 여행 실험과 같은 revision·가중치의 Qwen3.5-9B임. greedy 생성, thinking 비활성, 최대 출력 64토큰을 유지함. 외부 질문용 지시문에는 시간순 규칙과 단일 수량은 숫자로 답하라는 규칙을 명시하며, 모든 조건에 같은 지시문을 사용함. 이 지시문과 과제는 여행 실험과 다르므로 결과 크기를 직접 합치지 않음.

| 조건 | 현재 관측 | 전달하는 기억 |
| --- | --- | --- |
| none | 없음 | 없음 |
| new_only | 없음 | 새 근거 |
| old_only | 없음 | 옛 근거 |
| both | 없음 | 옛 근거와 새 근거 |
| current_new | 새 근거 | 없음 |
| current_new_plus_old | 새 근거 | 옛 근거 |
| current_new_plus_repeat | 새 근거 | 새 근거의 반복 |
| current_new_plus_distractor | 새 근거 | 대상값을 알려 주지 않는 기록 |

동일한 질문과 현재 관측을 사용하고, 기록은 잘라 쓰거나 무관한 문장으로 늘리지 않음. 기억 예산은 모든 조건에서 8기록·1,024토큰임. 방해 기록은 새 근거보다 앞선 발화 중 옛 기록과 개수가 같은 묶음을 고르고, 토큰 길이 차이가 가장 작은 것을 선택함. 동률은 기록 ID로 정함. 의미 검토에서 과거의 다른 대상값을 주는 기록은 제외함.

묶음 개수가 같고 반복·방해 묶음 모두 옛 묶음 길이의 `max(16토큰, 25%)` 이내인 사례를 별도 집계함. 이는 길이가 정확히 같은 대조는 아님. 더 이른 방해 기록이 부족한 경우 해당 조건을 생략하고 다른 비교는 유지함. 문항 수가 다른 정책의 전체 성적을 그대로 비교하지 않음.

## 원문 검토와 분할

[v1 자료](../datasets/external_memory_updates/20261111-v1/README.md)의 원문·분할은 보존함. [v2 자료](../datasets/external_memory_updates/20261111-v2/README.md)와 [문항별 검토](design-data/external-update-validation-20261111-v2/content-reviews.jsonl)를 별도로 둠. 모델 출력을 보기 전에 실행 후보 95문항의 질문·새 근거·옛 근거·선택된 방해 기록을 읽고 15문항을 제외함.

대표 제외 사유는 시작 시각과 소요 시간, 코드 커버리지와 검사 통과율, 전체 마케팅 예산과 특정 광고 예산의 혼동임. 옛 근거에 대상값 자체가 없는 문항과 새 값이 확정된 상태인지 모호한 문항도 제외함. 숫자가 원문에 있다는 것만으로 관계 주석을 승인하지 않음. 근거 ID와 제외 사유를 모두 남김. 입력 검토는 이 에이전트의 단일 검토이며 독립 주석자 간 일치도를 측정한 것은 아님.

| 단계 | 실행 문항 | 묶음 개수와 길이를 맞춘 문항 | 서로 다른 작업자 입력 |
| --- | ---: | ---: | ---: |
| 설계 LongMemEval-S | 32 | 17 | 255 |
| 설계 BEAM dev | 15 | 4 | 117 |
| 확인 BEAM confirm | 33 | 13 | 256 |

LongMemEval-S는 이미 사용한 설계 자료임. BEAM dev는 옛 값이 표시된 수량 문항을 사용함. BEAM confirm의 출력은 설계 단계에서 보지 않으며, 33문항의 입력과 제외 목록까지 미리 고정함. 자료의 질문·정답은 입력 품질 검토에 사용했으므로 라벨까지 완전히 보지 않은 시험이라고 부르지 않음. 나머지 날짜·시각·구절 문항은 이번 단일 수량 평가에서 실행하지 않음.

## 채점과 실행 경계

1. `165`처럼 단일 수량을 단정한 답과 `UNKNOWN`은 자동 채점함. `150, not 165`, 단위 변환·설명·여러 값이 있는 답은 정답 여부를 null로 두고 검토함. 현재 값·옛 값의 언급 여부는 보조 정보로만 남김. 기존 v1의 값 포함 채점기는 재현용으로 보존함.
2. 검토에는 원 출력의 SHA-256, 판정, 근거, 검토자를 기록함. 옛 값을 언급해도 현재 답으로 주장하지 않았다면 옛 답으로 세지 않음. 해결되지 않은 답은 성공·실패 양쪽 가능성을 표시하며 조용히 실패로 바꾸지 않음. 수량 단위가 명시된 답은 질문·원문과 대조함.
3. 설계 단계의 모든 출력과 채점을 문항별로 확인함. LongMemEval-S와 BEAM dev 각각에서 `new_only`와 `current_new` 성공률이 80% 이상이고, 출력 누락·미해결 판정이 없어야 확인 단계로 진행함. 근거를 읽는 능력을 확인하는 경계이며 손해가 몇 건 나왔는지는 진행 조건으로 쓰지 않음.
4. 통과하면 고정된 확인 입력을 한 번 실행함. 확인 성적을 보고 지시문·제외 목록·채점 알고리즘을 수정하거나 결과가 좋아질 때까지 반복하지 않음. 미달하면 그 결과와 원인을 보고하고 확인 출력은 열지 않음.
5. 조건별 성공, 무기억 실패→새 근거 성공, 현재 근거 성공→추가 기억 실패, 옛 값으로의 회귀를 구분함. 옛 값이 없는 문항은 전체 손해에는 포함하고 옛 값 회귀 지표에서는 제외함. 비교는 같은 문항의 쌍으로 계산하고, 대화별 손해 유무와 분모를 함께 보고함. 길이를 맞춘 하위 집합은 별도 표로 표시함.
6. 토큰·시간은 실제 기록을 사용함. 한 문항에서 파생된 여러 조건과 같은 대화의 문항을 독립 표본으로 세지 않음. 가족별 Wilson 구간은 독립 대화라는 근사 가정 아래의 기술 통계임.

확인 자료에서 손해가 관측되면 이 외부 수량 갱신 조건에서도 관측됐다고 기술함. 0건이면 이 작업자·지시문·규모에서는 관측되지 않았다고 기술함. 어느 쪽도 모든 기억의 안전성이나 학습 선택기의 우위를 증명하지 않음. 현재 상태를 새 발화로 만드는 개입과 역사적 기록의 출처를 구분하며, 자연 발생한 에이전트 실패 이력으로 부르지 않음.

## 자원과 재현

설계 372입력·2반복, 확인 256입력·2반복이 상한임. 설계와 확인은 별도 소유 Colab L4 세션에서 수행하고 각 회차 결과를 회수한 뒤 종료함. 컨트롤러 3,300초 상한과 런타임 3,600초 자체 종료를 둠. 새 모델 학습과 유료 모델 API 호출은 없음.

설계·확인 입력 해시, 코드 해시, 통과 기준은 [사전 고정 파일](design-data/external-update-validation-20261111-v2/preregistration.json)에 기록함. 실행 결과와 해석은 별도 결과 보고서에 추가함.
