# AI 에이전트 메모리의 득실: 문헌 검토와 연구 판단

2026-11-02 · 조사 노트 · 실제 벤치 실행 결과가 아닌 문헌 검토와 실험 제안

실행 방향의 후속 판단: [2026-11-03 재검토](ai-memory-pilot-reassessment.md). 공개 데이터의 분할·중복과 에이전트의 입력 연결 지점을 확인하고 첫 실험의 우선순위를 보완했다.

**이 방향은 연구할 가치가 있고, 기존 벤치와 실행 기록으로 실험할 수 있다.** 다만 질문을 “메모리는 좋은가?”에서 “어떤 과거 경험을, 어떤 형태로, 어떤 현재 상황에 제공하면 성공 확률과 비용이 어떻게 달라지는가?”로 좁히는 편이 좋다. 평균 성능 향상은 이미 보고되어 있다. 우리가 먼저 재현하고 살펴볼 지점은 **이득과 손해가 섞이는 조건, 행동이 바뀌는 과정, 특정 기억을 고쳤을 때의 회복**이다.

기존 [연구 스케치](ai-memory-research-sketch.md)를 확장한 문서다. 실행 순서, 대조군, 측정식과 통계적 주의점은 [검증 설계 노트](ai-memory-causal-evaluation-plan.md)에 별도로 정리한다. 아래에서 **논문 결과**, 그 결과의 **한계**, **우리의 가설**을 구분한다. 관련 논문과 공식 문서를 중심으로 조사했으며, 모든 연구를 빠짐없이 수집한 체계적 문헌고찰은 아니다. 특히 2026년의 최근 프리프린트는 검증 수준과 버전을 함께 읽어야 한다.

**1. 먼저 연구 대상을 고정한다.** 여기서 메모리는 모델 가중치 자체가 아니라, 에이전트가 과거 과제의 관측·행동·결과를 저장하고 다음 과제에서 불러오는 외부 기억이다. 같은 과제를 실패 후 재시도하는 경우, 다른 과제로 경험을 전이하는 경우, 여러 과제를 풀며 계속 기억을 갱신하는 경우는 서로 다른 실험이다. 첫 실험은 **과거 과제에서 만든 고정된 기억을 별도의 새 과제에 제공하는 전이**로 둔다.

메모리의 가치는 기억 문장만의 성질이 아니다. 현재 과제, 코드·도구의 버전, 모델의 기존 능력, 검색 결과, 주입 시점과 실행 예산에 의존한다. 예를 들어 과거 환경에서 옳았던 명령도 현재 환경에서는 틀릴 수 있다. 현재도 옳은 사실이지만 해결과 무관한 기억은 탐색을 방해할 수 있다. 따라서 “좋은 기억/나쁜 기억”을 고정된 정답 라벨로 대량 제작하는 것부터 시작할 필요가 없다.

**2. ‘득실을 보여줬다’는 말에도 증거의 수준이 있다.** 아래 구분은 이번 조사를 위한 해석 기준이다.

| 관측·실험 | 말할 수 있는 것 | 이것만으로 부족한 주장 |
| --- | --- | --- |
| 실행 로그에서 기억을 따르다 실패한 장면 발견 | 실패 원인 후보, 행동 패턴 | 그 기억이 없었으면 성공했을 것 |
| 같은 과제·환경에서 기억 유무를 반복 비교 | 해당 메모리 제공 정책의 평균 효과 | 특정 문장이 실패를 일으킨 원인 |
| 특정 항목 삭제·수정 후 반복 재실행 | 그 항목의 조건부 기여에 관한 증거 | 모든 과제에서 그 항목이 해로움 |
| 같은 중간 상태에서 기억만 바꾸고 행동·결과 비교 | 특정 결정 지점에서 작동한 영향 | 전체 과제 분포의 평균 효과 |
| 발견한 기준으로 새 과제에서 사용 여부를 결정 | 설명이 실제 개선 정책으로 이어지는지 | 다른 모델·도메인에도 동일하게 성립 |

한 번 실패한 궤적에 그럴듯한 설명을 붙이는 것과, 기억에 개입해서 결과가 반복적으로 달라지는 것을 확인하는 것은 다르다. 그러나 완전한 내부 해석이 있어야만 연구가 가능한 것은 아니다. 입력으로 주는 기억을 조작할 수 있다면, API 모델에서도 평균 효과와 문구 개입 효과를 측정할 수 있다.

**3. 가까운 선행 연구에서 무엇을 확인했는가.** 수치는 각 논문의 특정 조건에 한정되며 서로 다른 벤치의 수치를 직접 비교하지 않는다. 퍼센트포인트 차이는 `pp`로 표기한다.

| 연구 | 확인한 결과와 우리 연구와의 접점 | 해석의 한계 |
| --- | --- | --- |
| [ReasoningBank, 2025 v1](https://arxiv.org/html/2509.25140v1) | 성공·실패 경험에서 전략을 추출한다. SWE-bench Verified에서 Flash의 해결률 34.2→38.8%, Pro 54.0→57.4%를 보고한다. | 전체 메모리 방식의 비교다. 특정 기억의 원인이나 사실/지침의 분리 효과를 보여주지는 않는다. |
| [MemDev-Bench, 2026 v1](https://arxiv.org/html/2610.27524v1) | 저장소의 과거 개발 경험을 제공하고 3회 반복으로 개선·회귀를 분석한다. 우리의 득실 질문과 특히 가깝다. | 선택된 평가 집단과 한 에이전트·모델 설정의 결과다. 실패 유형 분류는 주로 궤적 분석이다. |
| [Useful Memories Become Faulty When Continuously Updated by LLMs, 2026 v1](https://arxiv.org/html/2605.12978v1) | 기억의 반복 정리가 유용한 내용을 훼손할 수 있다. 특정 워크플로를 삭제하는 개입도 실시했다. | 삭제 실험은 조건별 1회여서 변동성과 유의성에 한계가 있다. |
| [How Memory Management Impacts LLM Agents, ACL 2026](https://aclanthology.org/2026.acl-long.27/) | 과거 경험을 따르는 경향과 오류 전파, 추가·삭제 정책의 영향을 조사한다. | 통제된 과제와 여러 응용 환경의 결과를 SWE의 효과 크기로 옮길 수는 없다. |
| [When Not to Imitate: Boundary-Aware Skill Memory, 2026 v1](https://arxiv.org/html/2608.22339v1) | 성공 절차의 적용 조건을 명시하고 잘못된 도구 선택을 분석한다. 조건 문구에 대한 통제 개입이 있다. | 전체 방법에는 실행 중 검사·수정도 포함된다. 모든 개선을 기억 문구에 귀속할 수 없다. |

| [ConMem, 2026 v1](https://arxiv.org/html/2610.33432v1) | 후보 기억이 미래 질문에 줄 득실을 모의 평가해 저장 여부를 판단한다. | 합성된 미래 질문과 LLM 판정에 의존한다. 실제 후속 과제의 유용성을 직접 측정한 결과로 읽으면 안 된다. |

**ReasoningBank는 첫 재현의 출발점으로 적합하다.** 위 SWE 수치는 Table 2의 메모리 비교이며, 추가 시험 시 계산을 사용하는 MaTTS 효과와 구분해야 한다. 실패 경험을 포함하는 별도 WebArena 실험에서는 ReasoningBank가 개선됐지만 AWM은 악화됐다. 따라서 “실패 경험은 도움이 된다”보다 **실패 경험에서 무엇을 추출하느냐가 중요하다**는 가설이 적절하다. 자기 판정으로 성공·실패를 구분하므로 판정 오류도 고려해야 한다. [논문 §3.2–3.3](https://arxiv.org/html/2509.25140v1)

[공개 저장소](https://github.com/google-research/reasoning-bank)는 mini-SWE-agent 기반의 SWE-Bench 실험 코드를 제공한다. 기존 구현을 출발점으로 삼을 수 있지만, 실행 환경과 모델 연동은 확인해야 한다. 논문 방식을 그대로 실행한 결과와, 비교를 위해 기억 저장소를 고정한 우리의 변형 실험은 구분해서 보고한다.

**MemDev-Bench는 ‘개선과 회귀를 동시에 본다’는 점에서 매우 가깝다.** 전체 구성 규모와 실제 주 실험 집합은 다르며, 주 실험은 Verified에서 파생된 344개 과제와 2,987개 과거 이력에 기반한다. 어려운 과제와 쉬운 과제를 별도로 선정하고, 평가용 무메모리 실행은 선정용 실행과 독립적으로 다시 수행한다. 실패 분석에서는 호환성 불일치, 잘못된 전이, 변경 범위 확대, 반대 증거가 있어도 수정하지 않는 패턴을 보고한다. 이는 **삭제·수정 후 회복을 모두 확인한 원인 목록은 아니다.** 비용 분석도 기억 구축 비용을 포함하지 않아 우리의 총비용 평가와 구분해야 한다. [논문 §4, Appendix H](https://arxiv.org/html/2610.27524v1)

**특정 기억에 개입한 사례는 이미 있다.** *Useful Memories Become Faulty…*의 Appendix I에서는 고정된 WebShop 워크플로 8개 중 계속 페이지를 넘기도록 유도하는 W8을 삭제했다. 50개 평가 세션에서 두 모델의 성공 수가 각각 7→14개, 18→23개로 늘고 페이지 넘기기가 감소했다. **기억 변경 → 행동 변화 → 최종 성과 변화**를 함께 확인한 점이 중요하다. 다만 저자도 조건별 한 번의 실행이며 유의성 검정을 하지 않았다고 명시한다. 길이가 같은 다른 항목 삭제와 반복 실행을 더하면 우리가 원하는 검증에 가까워진다. [논문 Appendix I](https://arxiv.org/html/2605.12978v1)

**BASM은 ‘내용을 바꿨기 때문에 달라졌는가’를 더 좁게 검사한다.** 같은 프롬프트에서 적용 조건 부분으로 향하는 주의를 차단하고, 같은 길이의 다른 부분을 차단하는 대조를 두었다. 조건 정보 차단 시 잘못된 도구 선택의 로짓 지표가 악화되는 결과를 보고한다. 다만 이는 특정 결정의 지표이며 전체 과제 해결과 동일하지 않다. 토큰 수를 맞춘 비교에서도 개선이 모든 설정에서 일관되지는 않는다. 우리에게는 내부 주의 분석 자체보다 **같은 길이의 대조 조건과 특정 행동 지점 개입**이라는 설계가 참고가 된다. [논문 §4 및 부록](https://arxiv.org/html/2608.22339v1)

**기억의 생성·관리도 별도 연구 축이다.** ACL 2026 경험 추종 연구에서 엄격한 추가 판정 일부는 정답과의 비교로 모사되어, 실제 운영에서 그대로 얻을 수 있는 피드백과 차이가 있다. 여러 기억을 함께 제공한 뒤 최종 성공을 각 기억의 유용성으로 배분하는 방식도 개별 항목의 인과 효과와는 다르다. [ACL 논문](https://aclanthology.org/2026.acl-long.27/)

지속 학습 연구는 기존 항목이 삭제되지 않아도 새 경험이 검색 결과를 차지하면 과거 능력이 약해질 수 있음을 보여준다. 따라서 이후의 축적 실험에서는 저장된 내용과 실제 검색된 내용을 함께 기록해야 한다. [경험 재사용 연구](https://arxiv.org/html/2604.27003v1)

**기존 계보를 재현하는 것 자체가 유용하다.** [Reflexion](https://arxiv.org/abs/2303.11366)은 피드백을 언어적 반성으로 저장하는 출발점이고, [ExpeL](https://arxiv.org/abs/2308.10144)은 수집용 과제의 경험에서 통찰을 뽑아 다른 과제에 활용하는 설정이 가깝다. [Agent Workflow Memory](https://arxiv.org/abs/2409.07429)는 반복되는 행동을 워크플로로 정리하며, [ACE](https://arxiv.org/abs/2510.04618)는 경험을 누적하는 문맥의 생성·갱신 방식을 다룬다. 첫 실험에서는 이 방법들을 모두 구현하기보다 하나를 참고해 원본 경험과 요약 기억을 비교하는 편이 해석하기 쉽다.

**4. 득과 실은 같은 기능의 양면으로 보는 편이 생산적이다.** 다음은 위 연구를 바탕으로 만든 **우리의 분석 틀과 검증 가설**이다. 각 행의 원인이 SWE·Terminal-Bench에서 이미 확정됐다는 뜻은 아니다.

| 기억이 바꾸는 부분 | 득이 될 수 있는 조건 | 실이 될 수 있는 조건 | 확인할 관측·개입 |
| --- | --- | --- | --- |
| 탐색 범위 | 관련 파일·도구·검사 위치를 빨리 찾음 | 비슷하지만 틀린 위치에 고착 | 첫 탐색 위치, 불필요한 열람 수; 위치 힌트만 제거 |
| 사실 접근 | 버전·API·환경 정보를 재확인하는 비용 절감 | 오래된 상태 또는 다른 환경의 사실 사용 | 현재 환경과의 일치 여부; 버전 정보 교정 |
| 행동 순서 | 효과적인 검사·수정 순서를 재사용 | 과거 성공 절차를 조건 없이 모방 | 사전 검사 수행 여부; 적용 조건만 추가 |
| 실패 회피 | 이미 확인된 실패 경로를 피함 | 우연한 실패를 일반 규칙으로 확대 | 회피한 선택지, 실패 원인의 근거; 금지 문구 완화 |
| 가설 우선순위 | 유력한 원인부터 검사 | 반례를 보아도 처음 설명을 고수 | 모순 이후 행동 전환; 재검토 조건 추가 |
| 정보 압축 | 긴 기록에서 필요한 증거를 쉽게 읽음 | 예외·불확실성·실패 맥락이 삭제됨 | 같은 출처의 원본/요약 비교; 누락 맥락 복구 |
| 경험 축적·검색 | 관련 사례가 늘어남 | 중복 사례가 검색을 점유하거나 상충하는 지침이 누적 | 검색 ID와 중복도; 저장소 고정 후 검색 방식만 변경 |
| 계산 배분 | 익숙한 부분을 줄이고 어려운 부분에 집중 | 기억 읽기·검증·추종에 예산 소비 | 성공률과 총비용; 같은 비용 상한에서 비교 |

이 틀에서 다음 세 구분이 중요하다.

- **과거 사실의 진위와 현재 적용 가능성은 별개다.** 과거에 사실이었지만 현재는 바뀌었을 수 있고, 현재도 사실이지만 이번 목표에는 무관할 수 있다.
- **과거 실행의 성공/실패와 기억의 유용성은 별개다.** 성공 궤적에도 불필요한 행동이 있고, 실패 궤적에도 유용한 중간 발견이 있다. 전체 실행이 실패했다고 각 행동을 나쁜 행동으로 라벨링하지 않는다.
- **저장·검색·읽기·행동 반영은 별개다.** 좋은 기억을 저장했어도 검색하지 못할 수 있다. 검색했어도 무시하거나 잘못 따를 수 있다. 최종 점수만으로 어느 단계의 문제인지 알 수 없다.

**5. ‘정보가 득인가, 행동 가이드가 득인가’는 가능하지만 정의가 필요하다.** 모든 가이드도 정보이므로 둘을 완전히 독립된 심리적 원인으로 분리하기는 어렵다. 실험에서는 **과거의 관측 사실을 기술한 문장**과 **현재 행동을 권고하는 문장**으로 조작적으로 구분한다.

예를 들어 “이전 환경에서 명령 A는 지원되지 않았고 B는 실행됐다”는 관측이다. “명령 B를 먼저 사용하라”는 권고다. 이 비교에는 문체뿐 아니라 현재 상황으로 전이하라는 의미가 추가된다. 따라서 사실형과 지침형의 점수 차이를 곧바로 ‘정보 대 행동’의 순수 효과로 부르면 안 된다.

첫 비교는 **사실만 제공 / 같은 사실+일반 조언 / 같은 사실+경험에서 나온 구체적 지침**으로 한다. 구체적 지침에 새로운 사실이 들어가면 사실 조건에도 포함한다. 일반 조언과 구체적 지침의 분량·어조를 맞추고, 실제 어떤 행동이 달라졌는지 기록한다. 구체적인 대조군은 [검증 설계의 6번](ai-memory-causal-evaluation-plan.md)에 적었다.

현재 코드에서 원래 찾을 수 있었던 정보를 기억이 빨리 찾아주었다면, 그것도 실질적 이득이다. 다만 이를 모델이 새로운 지식을 습득했다는 주장과 구분한다. 검색 비용 절감인지, 추론·행동 선택 개선인지에 따라 후속 설계가 달라진다.

**6. 득실을 정량화할 수 있지만, 하나의 숫자로 충분하지는 않다.** 최소한 다음 네 축을 따로 둔다.

| 축 | 주 측정값 | 해석할 때의 조건 |
| --- | --- | --- |
| 해결 성능 | 공식 성공률 차이, 반복 실행의 불확실성 | 같은 과제·모델·예산, 공식 테스트의 한계 명시 |
| 회귀와 부작용 | 기존 통과 테스트의 실패, 관측된 성공→실패 전환 | 전환에는 실행의 우연성이 섞임 |
| 효율 | 비용·시간·행동 수와 기억 생성·검색 비용 | 실패로 빨리 종료한 것은 효율 향상으로 단정하지 않음 |
| 행동 과정 | 명령 선택, 반복 실패, 모순 후 전환, 수정 범위 | 해석용 보조 지표이며 해결 성능의 대체물이 아님 |

평균 이득이 양수여도 일부 유형에는 해로울 수 있다. 반대로 평균 차이가 작아도 상당한 개선과 악화가 서로 상쇄됐을 수 있다. 그렇다고 단일 실행의 성공→실패 건수를 그대로 “메모리 때문에 피해를 입은 문제 수”로 해석할 수도 없다. 예를 들어 메모리와 무관하게 매번 성공 확률이 50%라면, 독립 실행 비교에서 실패→성공과 성공→실패가 각각 25%씩 나온다. **평균 효과는 측정 가능하지만 개별 실행의 반사실적 피해는 훨씬 강한 주장이다.** 계산식과 대안은 검증 설계에 적었다.

개인정보 보존, 악성 기억, 사용자 선호 위반도 중요한 손해지만 SWE의 테스트 통과율로 측정되지 않는다. [AgentPoison](https://arxiv.org/abs/2407.12784)은 외부 기억·지식 저장소의 오염이라는 별도 위험을 다룬다. 첫 연구 범위는 **과제 해결과 실행 비용의 득실**로 명시하고, 여기서 얻은 수치가 모든 종류의 메모리 피해를 대표한다고 말하지 않는다.

**7. 벤치는 새로 만들지 않아도 된다. 다만 기존 채점기를 어떻게 쓰는지가 중요하다.** SWE-bench는 패치와 테스트로 결과를 판단하고, mini-SWE-agent는 개별·일괄 실행 도구를 제공한다. Harbor는 여러 에이전트와 사용자 정의 에이전트를 지원한다. 따라서 메모리는 벤치 자체를 바꾸기보다 에이전트 입력에 제공하고, 결과는 기존 채점기로 측정할 수 있다. [SWE 평가 문서](https://www.swebench.com/SWE-bench/guides/evaluation/), [mini-SWE-agent](https://mini-swe-agent.com/latest/usage/swebench/), [Harbor](https://docs.harborframework.com/agents/pre-integrated-agents)

| 출발점 | 적합한 첫 질문 | 부담·해석 범위 |
| --- | --- | --- |
| SWE-bench Lite 또는 고정된 소규모 부분집합 + mini-SWE-agent | 저장소 정보, 파일 탐색, 실패 경험과 수정 전략의 전이 | 빌드·테스트 환경 비용, 과거 코드 시점 정렬이 필요 |
| Terminal-Bench 고정 버전의 부분집합 + 수정 가능한 에이전트 | 명령·도구 선택, 환경 확인, 절차 재사용 | 과제 간 이질성과 자원 제한을 기록해야 함 |
| 별도 중간 상태 재생 실험 | 특정 기억 문구가 다음 행동을 바꾸는지 | 실제 상태 복제와 재생 가능성 확인이 필요 |

첫 선택은 기존 스케치대로 SWE 쪽이 자연스럽다. 다만 처음 조사한 과제에서 재사용할 경험이 거의 없다면, 반복되는 도구·환경이 있는 Terminal-Bench 과제군으로 옮기는 것도 타당하다. 중요한 것은 유명한 벤치 전체를 즉시 돌리는 일이 아니라 **비교 가능한 실행과 실제로 전이할 여지가 있는 경험**을 확보하는 것이다. 선택 기준을 결과를 보기 전에 고정하고, 의도적으로 비슷한 과제를 모았다면 그 조건부 결과라고 보고한다.

Verified라는 이름도 완벽한 정답 보장을 뜻하지 않는다. OpenAI는 2026년 감사에서 어려운 138개 과제를 조사해 테스트·명세 문제를 보고했다. 이는 500개 전체의 오류율 추정이 아니다. 이번 연구에서는 버전을 고정하고, 인프라 오류를 분리하며, 공식 점수와 명백한 평가 불일치 사례를 구분해서 남기면 된다. [감사 보고](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)

환경 자원도 효과를 혼동시킬 수 있다. Anthropic은 같은 모델·하네스의 Terminal-Bench 2.0 실험에서 자원 설정에 따라 6pp 차이가 났다고 보고했다. 이것은 작은 효과가 항상 무의미하다는 뜻이 아니라, CPU·메모리·시간 제한과 실행 배치를 통제해야 한다는 근거다. [인프라 변동성 보고](https://www.anthropic.com/research/infrastructure-noise)

**8. 지금 가장 유망한 후속 가설은 세 가지다.** 아래는 연구 결과가 아니라, 작은 재현 실험에서 우선 관찰할 제안이다.

| 가설 | 예측 | 반박되거나 약해지는 관측 |
| --- | --- | --- |
| 적용 조건이 빠진 지침이 부적절한 전이를 만든다 | 환경 불일치 상황에서 지침이 더 해롭고, 조건을 복구하면 잘못된 행동과 실패가 함께 감소 | 일반 조언이나 같은 길이의 무관한 수정도 똑같이 개선 |
| 요약 중 관측과 추측이 섞이면서 손해가 생긴다 | 원본에는 없던 확정적 규칙을 제거하면 회복 | 원본도 동일하게 실패하거나 문제의 규칙을 사용하지 않음 |
| 반대 증거 이후의 지속적인 추종이 손해를 키운다 | 반례 이후에만 기억을 재검토하도록 하면 불필요한 반복과 실패 감소 | 행동만 바뀌고 성공률·비용에는 이득이 없거나 새 손해 발생 |

첫 파일럿에서 이 중 하나와 맞는 현상이 발견되면 집중한다. 아무 현상도 발견하지 못했는데 억지로 메모리를 망가뜨려 “자연 발생하는 피해”를 입증하려 해서는 안 된다. 인위적으로 만든 충돌 기억은 메커니즘을 시험하는 진단용 데이터로 따로 표시한다.

**9. 이 조사에서 내리는 연구 판단.** 새 대규모 데이터셋보다 **기존 문제 → 실제 경험 → 기억 제공 비교 → 의심 항목 개입 → 별도 문제 재검증**의 순서가 지금 목표에 맞는다. 데이터 제작의 중심은 문제와 정답 작성이 아니라 실행 기록 정리, 출처 연결, 조건 통제다. 상당 부분 자동화할 수 있고, 사람의 정밀 검토는 후보 사례와 확인 실험에 집중할 수 있다.

이미 가까운 연구가 있으므로 “메모리가 때로 도움이 되고 때로 해롭다”만으로 새 기여를 주장하기는 어렵다. 하지만 처음부터 기여를 확정할 필요는 없다. 재현 과정에서 **언제 쓰지 말아야 하는지, 어떤 문구를 고쳐야 하는지, 적은 비용으로 위험을 예측할 수 있는지**에 관한 반복 가능한 현상을 얻으면 후속 연구로 이어질 수 있다.

현재 단계에서 기대할 수 있는 정직한 결론은 “이 모델·과제군·기억 구성에서 이런 평균 효과와 행동 변화가 관찰됐다”이다. 반복 개입과 별도 과제 검증을 더하면 “이 조건 정보의 누락이 손해에 기여하며, 이를 복구하는 정책이 새 과제에서도 유용하다”까지 나아갈 수 있다. 모든 기억에 통하는 보편적인 득실 점수는 훨씬 더 큰 주장이다.
