# 에이전트 메모리 실험 보고서 작성 핵심 정리

2026-11-13 · 실험 계획 보고서 작성용 인계 자료

[프레임워크 상세 설계](ai-memory-framework-detailed-design-2026-11-13.md)에 모듈·실행·도구·은행·기록·분석 계약을 구체화했다. 초기 τ² 실증과 AppWorld·BFCL로의 확장 및 BFCL V4 Memory와의 비교는 이 후속 설계도 함께 참고한다.

**같은 LLM이 경험을 어떻게 저장하고 다시 불러오느냐에 따라 후속 작업의 행동과 성공·실패가 어떻게 달라지는지, 그 이득과 손해를 재현 가능한 비교로 측정한다.** 이를 위한 평가 프레임워크·측정 절차·실증 분석을 연구 산출물로 삼는다.

이번 실험의 작업자 모델은 Luna로 고정하는 방향이다. τ²-bench는 실행 환경 후보이며 정확한 모델 ID·설정, 벤치 버전·도메인·과제와 반복 수는 실행 전에 확정한다. 아래 기대 효과와 현상 예시는 앞으로 검증할 목표다.

## 보고서 첫머리에 사용할 연구 개요

본 연구는 LLM 에이전트가 작업 경험을 자율적으로 저장하고 조회하는 방식을 비교하는 평가 프레임워크와 측정 절차를 제안한다. 동일한 작업자 모델과 업무 환경에서 기억 저장 시점·표현 형태·조회 정책을 바꾸고, 생성된 기억의 내용과 실제 노출, 후속 행동 및 작업 결과를 연결해 기록한다. 같은 과제의 재시도뿐 아니라 관련 새 과제로의 전이와 경험 누적에 따른 개선·회귀를 평가한다. 성공률 변화와 관측된 실패 회복·성공 악화, 부분 진척, 기억 품질·노출, 전체 비용을 함께 측정한다. 자연 실행의 전체 정책 비교와 동일 경험·기억 은행의 교차 적용·내용 개입을 병행해, 어떤 저장·조회 방식이 어떤 조건에서 도움이 되거나 해가 되는지 분석하고자 한다.

## 풀고자 하는 문제와 연구 질문

최종 성공률만으로는 필요한 경험이 저장되지 않았는지, 저장됐지만 조회되지 않았는지, 모델 입력에 들어왔어도 잘못 활용됐는지 구분하기 어렵다. 평균 성공률이 높아져도 일부 과제에서는 기존 성공을 잃을 수 있으며, 같은 과제의 재시도에서 얻은 개선이 새 과제로 전이된다는 보장도 없다.

따라서 다음 질문을 연결해 다룬다.

| 연구 질문 | 확인할 차이 |
| --- | --- |
| 언제 무엇을 저장하는 것이 후속 작업에 유리한가 | 수행 중 기록과 종료 후 정리, 원기록·요약·사실·조건·절차 등의 내용과 결과 차이 |
| 무엇을 언제 불러오는 것이 유리한가 | 시작 시 제공과 필요할 때의 자율 조회, 원문 사용과 조회 후 재가공의 차이 |
| 저장 방식과 조회 방식에 조합 효과가 있는가 | 동일한 저장 방식도 조회 정책에 따라 우열이 바뀌는지 |
| 기억은 언제 이득과 손해를 만드는가 | 실패 회복, 성공 악화, 양쪽 실패의 진척, 같은 과제 재시도와 새 과제 전이의 차이 |
| 기억을 누적할수록 개선되는가 | 새로운 경험 이후의 성능, 이전 능력의 유지·회귀, 과제 순서에 따른 변동 |
| 효과를 얻기 위해 어떤 비용이 필요한가 | 저장·갱신·조회·재가공·작업 수행의 전체 비용과 반복 사용에 따른 비용 회수 |

저장 시점 하나나 특정 손해 사례로 범위를 제한하지 않는다. 저장·조회·반복·전이·누적 변화·득실·비용을 전체 연구 범위로 유지한다.

## 실험 구성과 에이전트의 역할

작업자 Luna의 정확한 모델 식별자·추론 설정·업무 도구와 평가 과제 집합을 정책 간에 맞춘다. 작업자 모델의 가중치를 갱신하지 않고 외부 기억에 따른 변화를 측정한다. 기억 작성이나 조회 후 가공에 별도 호출을 사용하면 그 모델·설정·비용도 기록한다. 실험자가 배정하는 것은 저장·조회 정책이며, 자율 저장·조회 조건에서 무엇을 몇 개 저장하고 어느 항목을 읽을지는 LLM이 결정한다. 저장하거나 조회하지 않는 선택도 관측값이다.

### 기억 도구

| 도구 | 에이전트가 하는 일 | 기록할 내용 |
| --- | --- | --- |
| `store` | 제목·본문을 작성해 여러 기억을 저장하거나 기존 항목을 갱신 | 작성 시점, 원천 경험, 본문, 이전·이후 버전 |
| `list` | 접근 가능한 기억의 ID·제목 등 목록 확인 | 반환한 목록과 실제 모델 입력에 포함된 내용 |
| `get` | 선택한 항목의 본문 확인 | 요청 항목, 반환·노출 본문, 시점과 이후 행동 |

목록의 제목과 메타데이터도 기억 노출에 포함한다. 저장 내용의 정답·효용 라벨을 도구가 자동으로 붙여 에이전트에게 주지 않는다. 분석용 주석과 채점기 전용 정보는 모델 입력과 분리한다.

### 비교할 정책

| 저장 시점 조건 | 수행 중 저장 | 종료 후 저장·정리 |
| --- | --- | --- |
| 무기억 | 없음 | 없음 |
| 종료 후에만 저장 | 허용하지 않음 | 허용 |
| 수행 중에만 저장 | 허용 | 별도 단계 없음 |
| 수행 중 저장과 종료 후 정리 | 허용 | 허용 |

이 조건에 저장 형태와 조회 방식을 교차한다. 저장 형태는 자유 형식, 사건 기록, 단순 요약, 사실·적용 조건, 절차·전략, 실패 원인·주의사항 등이 후보이며, 조회는 작업 시작 시 제공, 수행 중 자율 조회, 두 방식 병행과 조회 후 재가공 등을 비교한다. 배정한 형식 지침과 LLM이 실제로 만든 내용은 구분해 기록한다.

현재 시도에서 방금 저장한 기억을 읽을 수 있는지, 종료 후 어떤 결과 피드백을 공개하는지도 명세한다. 피드백이나 연산량이 달라지면 그 차이를 포함한 정책 효과와 해당 요인만 통제한 비교를 구분한다.

저장 용량·항목 수·한 번에 읽는 양은 서로 다른 설정이다. 실제 문맥 한도와 사용량을 기록하되 BM25나 임의의 2k 배분을 기본 조건으로 넣지 않는다. 추가 한도가 필요하면 목적·단위·초과 시 처리를 실행 전에 정한다.

## 수행 절차와 비교 설계

한 차례 실행에서는 과제를 수행하며 허용된 기억 도구를 사용하고, 종료 결과를 보존한 뒤 조건에 따라 기억을 정리한다. 다음 시도에서는 업무 상태·에이전트 대화·사용자 시뮬레이터를 초기화하고 해당 조건의 기억 은행만 이어받는다. 같은 과제 재시도와 다음 과제로의 진행을 구분한다.

| 실험 묶음 | 비교 방법 | 얻고자 하는 근거 |
| --- | --- | --- |
| 자연 실행과 경험 누적 | 조건별 독립 은행에서 과제 수행과 기억 작성을 이어감 | 저장·조회가 행동과 경험 수집까지 바꾸는 전체 정책 효과 |
| 동일 경험의 저장 비교 | 같은 공개 수행 기록으로 여러 은행을 생성. 수행 중 저장에는 해당 시점까지의 기록만 제공 | 경험 자체의 차이를 통제한 저장 내용·형태의 효과 |
| 저장과 조회의 교차 | 저장 정책 A·B의 은행을 조회 정책 X·Y에 각각 적용 | 특정 저장 방식과 조회 방식의 궁합, 순위 변화와 조합 효과 |
| 재시도와 전이 | 같은 과제, 관련된 새 과제, 중요한 조건이 달라진 과제를 구분 | 원래 실패 복구와 새 과제 활용, 조건이 맞지 않는 기억의 영향 |
| 체크포인트 평가 | 누적 중 같은 확인 과제 집합을 평가하고 이전·새 과제 성능을 비교 | 학습 속도, 전이, 기존 성능의 유지·회귀 |
| 내용과 노출의 개입 | 같은 판단 직전 상태에서 기억 제공·보류·교정·교체를 비교 | 어떤 정보 변경이나 노출 방식으로 결과가 달라지는지 |

기본 비교군은 무기억 반복, 같은 원천 경험의 원기록 접근, 단순 요약이다. 같은 횟수의 무기억 재시도로도 성공이 달라질 수 있으므로 무기억 대 무기억의 변동을 함께 확인한다.

여러 랜덤 과제 순서를 만들고 같은 순서 집합을 정책 간 공유한다. 조건별 은행은 분리하고 순서별 독립 반복을 둔다. 같은 사용자 시드라도 에이전트 행동이 달라진 이후에 동일한 사용자 응답이 보장되는 것은 아니다.

확인 과제마다 시작 은행을 복제하며, 평가 중 저장·갱신을 허용하더라도 변경이 원은행·다른 확인 과제·이후 본실험으로 돌아가지 않게 한다. 새 과제와 그 파생 변형의 출처·노출 여부를 관리해 재시도 성적과 전이 성적을 분리한다.

정확한 상태 복제나 검증된 재생이 가능한 환경에서 국소 개입을 수행한다. 복원이 보장되지 않으면 일반 재실행 비교로 보고한다. 연구자가 정답을 보고 교정한 기억은 진단용 조건이며 자율 기억 정책의 성적과 구분한다.

## 정량적으로 측정할 내용

| 측정 축 | 핵심 수치 | 해석할 내용 |
| --- | --- | --- |
| 작업 성능 | 공식 성공률, 반복 실행에서 추정한 기억·무기억 성공 확률 차이와 불확실성 | 기억 정책이 전체 성능을 얼마나 바꾸는가 |
| 관측된 득실 | 실패→성공, 성공→실패, 양쪽 성공, 양쪽 실패의 수와 비율 | 평균 개선 뒤에 어떤 회복·악화가 있는가 |
| 실패 상태의 진척 | 최종 요구사항 충족률, 최고 진척과 최종 진척의 차이 | 실패하더라도 목표에 가까워졌는지, 달성한 상태를 잃었는지 |
| 기억 작성·갱신 품질 | 보존해야 할 정보의 보존률, 근거와 일치하는 비율, 정정 반영과 지연 | 유용한 사실·조건을 남기고 잘못된 정보를 고치는가 |
| 기억 조회·노출 | 주석 가능한 근거의 실제 입력 도달률, 필요한 판단 이전의 노출, 불필요·부적합 정보 노출 | 필요한 기억을 적절한 시점에 읽었는가 |
| 행동과 개입 | 오류 재발, 유효 행동, 기억 교정·제공·보류 후 성공·진척 차이 | 내용·노출의 변경이 이후 행동과 결과를 바꾸는가 |
| 전이와 누적 안정성 | 같은 과제·새 과제별 성능, 체크포인트 곡선, 이전 과제 유지, 순서별 변동 | 단기 회복이 전이·지속적인 개선으로 이어지는가 |
| 비용과 효율 | 전체 토큰·호출·지연·금액, 성공률 대비 비용, 누적 비용 회수 시점 | 얻은 효과에 어떤 자원이 들며 반복 사용에서 회수되는가 |

회복·회귀를 보고할 때는 전체 쌍의 반전 비율과 조건부 비율을 구분한다. 조건부 회복률은 `무기억 실패·기억 성공 수 / 무기억 실패 수`, 조건부 회귀율은 `무기억 성공·기억 실패 수 / 무기억 성공 수`다. 분모가 0이면 해당 없음으로 남긴다. 개별 한 쌍의 반전을 확정적인 인과 효과로 해석하지 않고 반복에 기반한 정책 효과를 함께 추정한다.

진척은 완료한 하위 목표나 현재 상태의 요구사항 충족으로 채점한다. 단순 호출 수 증가나 정답 예시와 같은 행동 순서를 진척으로 취급하지 않는다. 양쪽 실패만의 진척 변화와 전체 과제의 진척 변화를 함께 제시한다.

기억 내용의 정확성, 실제 입력에 노출됐는지, 성능에 도움이 됐는지는 별도 평가다. 자율 생성 기억에는 유일한 정답 항목이 없을 수 있으므로 주석 가능한 정보·조건·근거의 범위와 판정 불일치·미확정을 남긴다. 조회했다는 사실이나 모델의 사후 설명만으로 활용을 확정하지 않는다.

과제·기억 은행·작업 스트림의 의존성을 보존해 통계와 불확실성을 계산한다. 여러 기억 항목·호출을 독립 실험으로 세지 않는다. 채점 결측과 인프라 오류는 작업 실패와 구분하고, 운영 비용과 연구용 반복·채점·진단 비용도 분리한다. 성능·손해·비용은 각각 보고하며 임의의 가중 종합 점수로 대체하지 않는다.

| 평가 프레임워크와 비교 자료 | 기억 도구·정책 교체·벤치 연결·은행 버전·실행 기록, 같은 경험에서 나온 기억과 후속 결과의 연결 자료 | 동일 조건의 비교와 원 출력 재계산이 가능하며, 기존 공개 기능·자료 대비 추가 분석을 지원하는지 |
| 측정 절차와 진단의 타당성 | 득실·진척·기억 품질·노출·전이·비용을 연결하는 집계·주석·개입 절차 | 실행 변동을 구분하고, 기존 성공 점수만으로 드러나지 않는 차이를 신뢰성 있게 설명하는지 |
| 실증적 발견 | 저장 시점·내용·조회 조합이 회복·회귀·효율을 바꾸는 조건과 반복 관측 | 통제 비교·개입·새 과제 검증으로 어떤 새로운 현상이나 설명을 뒷받침하는지 |

차별화 후보는 **자율 생성 기억의 내용 변화와 실제 노출을 후속 행동의 회복·회귀·진척에 연결하고, 통제 비교와 개입으로 설명을 검증하는 것**이다. 프레임워크를 만들거나 지표를 여러 개 모았다는 사실만으로 노벨티가 확보되는 것은 아니다.

기존 [벤치 비교 보고서](reports/2026-11-13-memory-benchmark-metrics-and-novelty.md)에서 MemTools·EvoMemBench를 가까운 비교 대상으로 검토했다. 구성요소 교체·수행 중과 과제 간 평가·부분 진척·고정 작업자 비교 등은 선례가 있으므로, 어떤 추가 진단·자료·실증적 발견을 제공하는지 구체적으로 대조한다. 새로운 기억 알고리즘이나 새로운 수학적 지표를 필수 기여로 두지는 않는다.

## 이 실험으로 얻고자 하는 효과

**기억 정책을 선택할 근거.** 작업 유형에 따라 언제 저장하고 어떤 내용을 남기며 언제 읽는 방식이 성능·회귀·비용 측면에서 유리한지 판단할 자료를 얻는다. 최고 성공률뿐 아니라 실패를 줄이는 조건과 기존 성공을 잃는 조건을 함께 파악한다.

**실패 원인을 조사할 근거.** 경험에 정보가 있었는지, 기억에 남았는지, 필요한 시점에 노출됐는지, 이후 행동과 결과가 어떻게 달라졌는지를 추적한다. 교정·제공 개입으로 회복되는 범위도 확인할 수 있다. 단계별 개입 효과가 서로 겹칠 수 있으므로 이를 더해 고유한 원인별 기여율로 만들지는 않는다.

**반복 사용과 전이의 가치 판단.** 같은 문제에서의 개선이 새 문제에도 이어지는지, 누적 정리가 정보를 보완하는지 오류를 강화하는지, 작성 비용이 후속 사용에서 회수되는지 평가할 수 있다. 모든 정책에서 개선이 나올 것을 전제하지 않는다.

**후속 연구에 사용할 재현 자료.** 경험·기억 버전·노출·업무 상태·결과가 연결된 기록과 분석 코드를 남겨 다른 저장·조회 정책을 비교하고 향후 정책 개선이나 학습 연구에 활용할 수 있게 한다. 공개 가능한 범위와 실제 제공할 묶음은 정한다.

검증할 현상의 예로는 수행 중 기록한 추측이 종료 후 정리에서 교정되거나 강화되는 경우, 요약에서 적용 조건이 사라져 원래 과제는 돕지만 조건이 바뀐 과제에는 손해를 주는 경우, 정확한 기억을 읽고도 행동에 반영하지 못하는 경우가 있다. 이는 관측 결과가 아닌 가설 예시다. 효과가 작거나 없으면 불확실성과 검증한 조건을 함께 보고하며, 비유의성을 동등성의 증명으로 쓰지 않는다.

## 보고서 작성 순서와 실행 전 결정

보고서는 연구 목적과 문제 정의, 연구 질문, 선행연구와 기여 목표, 실험 구성·비교군·통제, 평가 지표와 분석 방법, 기대 효과와 적용 범위의 순서로 구성한다. 계획·가설·기대 효과를 미래의 검증 대상으로 서술하고, 수치 목표나 달성 성능을 임의로 채우지 않는다.

확정할 실행 항목은 Luna의 정확한 모델 ID·설정, 벤치·도메인·과제와 출처 분할, 저장 형태·조회 정책의 구체적 수준, 종료 피드백·저장 한도·중단 규칙, 독립 스트림·순서·반복 수, 진척·내용 주석 규칙, 통계 방법·비용 범위다. 여러 모델·도메인에서 검증하지 않았다면 Luna와 선택한 환경에서의 실증 결과로 적용 범위를 적는다. 메모리를 이어받는 반복은 일반 벤치의 독립 반복 성공 지표와 구분한다.
