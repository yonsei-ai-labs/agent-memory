# 작은 메모리 선택기의 학습 신호: 문헌 재검토와 후속 아이디어

2026-11-07 · 관련 연구의 방법·평가 범위를 확인한 설계 보완

**현재 방향을 유지한다.** Harrier 0.6B 뒤의 선형층·작은 MLP와 LoRA를 비교하되, 무엇을 정답으로 학습시키고 어떤 대조를 통과해야 실제 선택 능력이라고 부를지 보강한다. 이번 조사에서 Harrier가 정보 효용 예측에 가장 좋다는 근거를 찾은 것은 아니다. 첫 백본을 고정해 데이터·학습 신호의 기여를 확인하려는 선택이다.

새로 확인한 MemReranker, SCARLet, relevance-prior 연구와 기존 문헌을 연결했다. 논문에서 관측한 사실과 아래의 우리 후속 제안을 구분한다. 전체 연구·A0/A1/B0/B1 구성·평가 원칙은 [종합 노트](ai-memory-information-value-note-2026-11-07.md), 실제 배정과 결과는 [복원 파일럿 보고서](reports/2026-11-07-process-restoration.md)를 따른다. 이번 작업은 문헌·문서 검토이며 새 모델 학습이나 유료 실행을 포함하지 않는다.

## 1 이번 검토로 정한 우선순위

| 시점 | 아이디어 | 판단하려는 것 |

MemReranker의 §4.1은 8대의 A800 80GB로 학습했다고 보고한다. 논문의 작은 파라미터 수가 적은 데이터·단일 Colab 학습으로 같은 결과를 낼 수 있다는 보장은 아니다. 공개 모델 카드에서 확인한 로컬 배포 모델은 [MemReranker-4B](https://huggingface.co/IAAR-Shanghai/MemReranker-4B)다. 논문의 0.6B 평가 결과와 0.6B 가중치의 공개·재학습 가능 여부는 구분한다. 이번 조사에서는 후자를 확인하지 못했으며 첫 백본을 교체하지 않는다.

## 3 바로 준비할 학습 신호: 헷갈리는 관계를 구별하기

MemReranker의 단계적 학습에서 가져올 부분은 **쉬운 관련·무관 구별을 넘어, 조건과 근거를 비교해야 하는 자료를 넣는 것**이다. 아래는 우리의 데이터 구성 제안이며 해당 논문이 코드 로그에서 시험한 설계는 아니다.

| 사례 구성 | 근거로 판독할 내용 | 부여하지 않을 라벨 |
| --- | --- | --- |
| 같은 실행기·비슷한 명령이지만 검사 대상이 다른 쌍 | 현재 요구한 검사 범위를 다루는가 | 범위가 다르다는 이유만으로 최종 해결에 해롭다는 라벨 |
| 좁은 검사만 통과한 원문과 “전체 검사 통과”로 넓힌 문장 | 출처가 그 주장을 실제로 뒷받침하는가 | 사실을 과장한 문장의 성공률 효과 |
| 표현이 다르지만 같은 조건·범위를 가리키는 쌍 | 근거·조건의 의미가 같은가 | 두 표현의 실제 실행 효과가 동일하다는 라벨 |
| 과거 도구 부재와 현재 환경의 확인·미확인 상태 | 과거 관측과 현재 전제를 구분하는가 | 미확인을 부적합으로 바꾼 음성 라벨 |

현재 복원 파일럿은 검사 실행 세부 정보 V를 다루므로 첫 두 종류부터 준비한다. 마지막 환경 E 예시는 별도의 미래 축이다. 현재도 도구가 없다고 가정하거나 기존 파일럿이 E의 효과를 측정했다고 기록하지 않는다.

첫 구현에서는 자료에 원문 위치, 주석자·교사·합성 여부, 판단 근거, 난이도와 미확인 상태를 남긴다. 같은 원문에서 나온 모든 변형은 같은 그룹에 두고 분할한다. 다른 정답 후보가 있을 수 있으므로 배치의 나머지 기억을 모두 무용한 음성으로 취급하지 않는다.

학습 순서는 기존 계획을 유지한다. A0/A1/B0/B1 뒤에 출처 근거·검사 범위 손실을 더한 C를 비교한다. 이후 필요하면 C에서 쉬운 사례와 헷갈리는 사례의 구성을 바꾸되 라벨 수·업데이트 수·입력과 평가를 맞춘다. “보조 판독을 먼저 학습한 뒤 효용을 학습”하는 순서 비교도 가능하지만, 자료와 단계 수를 동시에 늘리고 순서의 효과라고 부르지 않는다.

교사·합성 자료는 판독 연습을 늘린다. 실제 제공·보류의 결과를 관측한 독립 경험 수는 늘리지 않는다. **보조 점수는 좋아졌지만 공식 성공 제출률은 그대로인 결과도 가능하다.**

## 4 첫 비교에 더할 대조: 무엇을 보고 맞히는가

성공 확률을 잘 맞히는 것과 도움이 되는 기억을 잘 고르는 것은 다르다. 예를 들어 모델이 쉬운 과제의 성공 확률만 정확히 예측해도 전체 Brier는 좋아질 수 있다. 두 행동의 차이 `p1−p0`가 좋아졌다는 보장은 없다.

아래는 relevance-prior 연구에서 착안한 우리의 진단 제안이다. 같은 분할과 실제 관측 행동의 라벨을 사용하며, 고정 임베딩의 작은 출력층으로 시작할 수 있다.

| 비교 입력 | 판단할 점 |
| --- | --- |
| 행동별 상수 예측 | 훈련 자료의 행동별 평균만 예측하는 수준을 넘는가 |
| 현재 상태만: 문제·관측 환경·공통 S, 후보 u 제외 | 후보 없이도 설명되는 과제 난이도·평균 처리 효과인가 |
| 후보 기억만: 후보·출처 근거·조건, 현재 상태 제외 | 특정 카드의 일반적 특징만으로 설명되는가 |
| 전체 관계 특징 z | 양쪽 입력을 이용하는 이득이 독립 그룹에서도 남는가 |

각 대조도 제공·보류 출력과 관측 행동 마스크를 사용한다. 분할용 ID를 넣지 않는다. 단순 입력 대조가 강하다는 이유만으로 편향을 입증한 것은 아니며, 기본 과제 난이도나 일반적으로 좋은 기억을 배운 결과일 수도 있다. 다만 전체 모델의 개선을 곧바로 조건부 정보 가치 학습이라고 설명할 수는 없게 된다.

추가로 같은 저장소의 유효한 사례 안에서 **상태와 기억의 짝을 바꾸었을 때 점수·선택이 달라지는지** 볼 수 있다. 현재 환경·공통 S의 정합성도 확인한다. 이것은 입력 민감도 진단이다. 짝을 바꾸기 전의 성공 라벨을 바꾼 짝에 재사용하지 않는다. 새 조합의 실제 해결 결과는 실행해야 알 수 있고, 점수가 변한다는 사실만으로 유용한 변화를 배웠다고 결론 내리지도 않는다.

예측 비교의 Brier와 정책 비교의 Q3−Q2는 유지한다. 확률·임계값은 개발 자료에서만 조정하고 테스트에서는 고정한다. 제공 비율, 제공을 보류한 비율, 전체 배정의 성과·비용을 함께 보고, 전부 제공·전부 보류 같은 단순 정책과도 비교한다. 적게 제공해서 오류 수가 줄어든 것인지 판단할 수 있어야 한다. 작은 표본의 무피해 관측은 무피해 보장이 아니다.

## 5 기억 단위와 조합: 같은 경험에서 무엇을 함께 남길 것인가

### 명령과 근거의 연결부터 보존한다

Execution Provenance 연구에서 가져올 첫 아이디어는 그래프 모델보다 **증거가 끊기지 않는 후보 단위**다. 우리 로그에서는 다음 연결을 남길 수 있다.

```text
원문에서 관측한 조건
        ↓
실제 실행 명령과 검사 대상
        ↓
관측 결과와 검사 범위
        ↓
해당 근거를 다시 찾을 수 있는 출처 위치
```

연결된 항목이 항상 한 덩어리로 전달돼야 한다고 가정하지는 않는다. 필요한 근거가 은행에는 있었는지, 검색 후보에서 빠졌는지, 선택 과정에서 끊겼는지 추적한다. 근거 주석을 만들 수 있는 사례에서는 `FullSupport@b`, 즉 b 토큰 안에 사전 정의한 필수 근거를 모두 전달한 비율을 진단 지표로 둘 수 있다. 주석의 완전성과 일치도를 함께 확인하며, 이것을 코드 해결률로 대체하지 않는다.

후보 단위를 바꾸는 실험과 선택 모델을 바꾸는 실험은 분리한다. 모델 대조에서는 동일한 후보·본문·토큰 상한을 사용한다. 단위 비교에서는 포함 내용과 실제 전달량의 차이까지 보고한다. 평가용 필수 근거의 위치나 정답 패치를 운영 중 선택기에 넘기지 않는다.

### 조합 효과는 작은 네 조건에서 시작한다

SCARLet의 부분집합 교란은 조합 기여를 학습 자료로 바꾸는 참고가 된다. 우리의 첫 적용은 모든 기억의 Shapley 값을 계산하기보다, 같은 시작 상태·공통 C에서 근거 있는 두 정보 u와 v를 정하는 것이다.

| 조건 | 전달 내용 |
| --- | --- |
| 00 | C |
| 10 | C + u |
| 01 | C + v |
| 11 | C + u + v |

예를 들어 u는 대체 실행 절차, v는 그 절차의 적용 조건·검사 범위로 둘 수 있다. C에 이미 담긴 내용을 새 정보로 세지 않고, 출처에서 두 정보가 실제 확인되는 경우만 사용한다. 현재 파일럿에 이 네 조건이 이미 있다는 뜻은 아니다.

```text
성과의 조합 효과 = p11 − p10 − p01 + p00
비용의 조합 효과 = c11 − c10 − c01 + c00
```

양의 성과 조합 효과는 해당 성공 확률 척도에서 두 추가 효과의 합보다 함께 제공한 효과가 크다는 뜻이다. 이것만으로 보편적인 정보 보완성을 입증하지는 않는다. 사례·모델·예산에 의존하고, 성공률의 상한도 해석에 영향을 준다. 네 조건 모두 같은 전달 상한 안에 들어가게 설계하고 실제 길이를 기록한다. 길이까지 맞추지 않았다면 정보·길이를 포함한 제공 패키지 효과다.

네 조건은 네 번 실행이면 충분하다는 뜻이 아니다. 반복 수와 독립 출처 수, 불확실성은 별도 설계한다. 공통 기준 실행을 재사용하면 그 의존성을 반영한다. 작은 표본의 관측 차이를 곧바로 개별 정보의 유익·유해 정답으로 고정하지 않는다.

## 6 추가 층과 확인 행동은 언제 시도할까

### 기존 예측을 보정하는 잔차 층

CoEvo-Mem을 참고하면 기존 선형 예측기가 어느 정도 작동한 뒤, 다음 구성을 별도 비교할 수 있다.

```text
행동 a의 성공 로짓 = 고정한 기준 예측기의 로짓 + 작은 보정층 dθ(z, a)
```

보정층의 마지막 층을 0으로 초기화하면 학습 시작 시 기준 예측을 그대로 얻는다. **학습 뒤 성능 악화를 막는 보장은 아니다.** 원시 검색 유사도와 성공 확률을 그대로 더하지 않고 같은 로짓 척도에서 보정한다. 이 식은 우리의 행동별 결과 예측에 맞춘 제안이며 논문의 경로 라우터를 그대로 재현한 것이 아니다.

지금은 A0/A1/B0/B1에 더해 별도 주 실험으로 늘리지 않는다. 독립 사례에서 기준 예측기의 특정 오류가 남고 보정 자료가 있을 때, 같은 정보·비슷한 학습 용량의 MLP와 비교한다. 일반 MLP보다 개선되지 않으면 잔차 설계의 추가 가치는 주장하지 않는다.

### 확인은 불확실성뿐 아니라 행동 변경 가능성을 본다

AMV-Guard가 주는 실용적 질문은 “불확실한가?”에 이어 **“확인 결과가 다르면 선택이나 실행을 바꿀 것인가?”**를 묻는 것이다. 어떤 결과가 나와도 같은 기억·명령을 사용할 계획이라면, 그 판단만을 위한 확인의 이득은 제한된다. 실제로 확인 명령 자체가 환경을 바꾸거나 부가 정보를 주는 경우는 별도로 기록한다.

이 행동을 학습하려면 확인 요청·결과·비용·후속 선택과 과제 결과를 새로 관측해야 한다. 현재 제공·보류 자료에서 확인의 가상 보상을 만들어 넣지 않는다. 검증 비용 감소, 국소 판독 오류, 공식 성공 제출률을 각각 평가한다. 단순히 오류를 줄이려고 제공이나 실행을 거의 하지 않는 정책도 드러나게 한다.

## 7 다음 작업에 반영할 범위

1. 학습 자료 명세에 근거·범위·미확인·파생 관계와 헷갈리는 사례의 유형을 추가한다. 현재 네 출처·대상 조합은 기능 점검 범위로 유지한다.
2. 기존 네 학습 구성의 입력·라벨을 고정하고, 상수·현재 상태만·후보 기억만의 대조와 점수 민감도 진단을 준비한다. 첫 예측 주 대비 B0−A0와 실제 정책 주 대비 Q3−Q2는 유지한다.
3. 독립 자료에서 기본 비교와 보조 과제 C를 평가한다. 예측 개선이 없으면 입력에 필요한 조건이 존재하는지, 근거가 후보에 들어오는지, 라벨·표본이 충분한지 먼저 확인한다.
4. 조합에 따른 오류가 관측되면 두 정보의 네 조건 실험을 설계한다. 잔차 층·그래프·확인 행동은 각 실패 원인과 추가 비용에 맞춰 하나씩 선택한다.

유사도 다음에 결과 점수를 붙이거나 작은 모델을 추가 학습하는 발상에는 선행연구가 충분하다. 여기서 찾아갈 연구 가치는 **같은 경험의 어떤 근거가, 어떤 적용 조건·조합·예산에서 실제 성과와 비용을 바꾸고, 그 차이를 작은 모델이 새 경험에도 사용할 수 있는가**에 있다. 지금은 그 질문을 검증할 학습 신호와 대조를 구체화한 단계다.
