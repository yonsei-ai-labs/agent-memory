# 여행 기억 선택을 실제 결정의 득실에 연결하는 파일럿

사용자의 후속 실험 요청에 따라, 이미 학습한 관계 판독기의 점수를 더 높이는 대신 **같은 작업자의 실제 결정과 비용이 기억 제공 정책에 따라 달라지는가**를 확인한다. 이 문서는 작업자 생성 전에 고정한다. 새 선택기 학습이나 방법 재선택은 하지 않는다.

## 범위와 원래 질문의 연결

MemoryArena 원문의 명시적 식당 참조 요청을 사용하되 전체 여행 계획은 실행하지 않는다. 공개 식당 표의 가격·평점·음식 종류로 검사할 수 있는 한 번의 선택이 단위다. 과거 기록의 사람·날짜·식사 항목은 유지한다. **과거 식당 선택은 Qwen3.5-4B가 새로 수행한 결과**로 바꾼다.

과거 작업은 우리가 구성한 작은 메뉴에서 지정한 음식 종류를 제공하는 가장 저렴한 식당을 고르는 과제다. 동점은 높은 평점, 사전순 ID로 푼다. 메뉴는 원래 과거 기록의 도시에서 해시 순서로 뽑은 6개 실제 데이터 행이며 미래 요청을 작업 모델에 주지 않는다. 이는 원래 과거 여행 문제를 풀어 생성한 전체 계획이 아니다. 공개 정답 계획을 실제 에이전트가 만든 이력이라고 부르지 않는다.

현재 작업은 원문 참조 문장을 유지하고 참조 식당의 도시에서 한 곳을 고르게 한다. 같은 식당 재사용 또는 가격·평점·음식 종류의 비교를 검사한다. 가격과 평점 등의 값은 공개 벤치용 표의 값이며 실제 현재 여행 가격 정보가 아니다. 현재 도시와 전체 도시 식당 목록은 모든 정책에 공통으로 준다. 따라서 이 실험은 **구성한 과거 선택과 원문 참조 요구를 연결한 통제된 하위 결정**이며 공식 MemoryArena 성능이 아니다.

## 자료 선택과 입력 경계

기존 기본 계획 분할을 유지한다. 3·5·7일 여행에서 개발 계획 1개씩, 평가 계획 8개 모두를 사용한다. 각 계획에서 재사용 요청 1개·지원하는 비교 요청 1개를 SHA256 순서로 고른다. 개발 6·평가 16개 원문 요청이며, 작업자 결과나 선택기 오답을 보고 고르지 않는다.

기억은 현재보다 앞선 사람의 식당 항목 6개다. 공통의 첫 기본 계획은 이 후속 기억 개입 후보에 넣지 않는다. 과거 슬롯별 새 선택 작업은 132개다. 식당 이름·도시가 표의 한 행에 연결되는 경우만 사용하며 도시 뒤 괄호의 주 이름만 정규화한다. 모호한 음식 종류·비교 문장은 제외한다. 선택한 22개 원문과 주석은 생성 전에 AI 에이전트가 모두 대조했고 사람의 독립 검수는 없다.

정답 주석 `judgments.json`과 원래 정답 계획은 Colab에 올리지 않는다. 과거 선택을 생성한 뒤 해당 출력과 표에서 관측한 속성을 기록으로 고정한다. 메뉴 밖의 출력·형식 오류는 관측 불가로 보존하고 원래 정답으로 교체하지 않는다. 원래 과거 선택 목표를 어겼더라도 실제 메뉴의 식당을 골랐다면 그 실제 선택이 현재의 참조 사실이다. 원래 목표 성공은 별도로 기록한다.

## 비교와 측정

같은 요청에 두 현재 상태를 만든다: 필요한 사실이 과거에만 있는 상태, 그리고 같은 사실을 현재 도구 관측으로 이미 알게 된 상태. 후자는 정보가 중복될 때 기억 비용을 볼 수 있다. 그 정보는 모든 정책과 선택기에 동일하게 주며, 정책별로 다른 과거 선택을 다시 생성하지 않는다.

비교는 `무기억 / 6개 전체 / 날짜 정규화 BM25 상위 1개 / 고정 LoRA 선택 / 사람·날짜·항목 규칙`이다. LoRA는 앞선 dev에서 선택한 분류 모델과 임계값 0.25를 그대로 쓴다. 순위 손실 모델로 사후 교체하지 않는다. 모델과 검색은 같은 후보 문장을 읽으며, 작업자에게는 선택된 기록의 식당 속성도 함께 제공한다.

작업자는 모든 조건에서 동일한 Qwen3.5-4B revision, greedy, thinking off, 출력 최대 48토큰을 사용한다. 매 생성에 새 cache를 만들고 실행 순서를 seed 731로 섞는다. 전체 기본 생성은 220개이며 개발/평가의 첫 요청에서 5정책을 한 번씩 반복해 10개를 추가한다. 과거 생성 132개와 현재 생성 230개를 구분한다.

현재 성공은 실제 과거 선택에 상대적인 조건을 **모두** 만족하는 도시 목록의 식당을 제출하는 것이다. 유효한 후보가 여러 개면 모두 인정한다. 가능한 식당이 없으면 `NONE`, 필요한 사실이 없으면 `UNKNOWN`을 허용하되 후자는 작업 성공으로 세지 않는다. 과거 출력 자체가 무효면 성공률에 조용히 합치지 않고 이력 가용성과 원인별 결과를 별도로 보고한다.

정책별 성공률과 `무기억 실패→성공 / 성공→실패 / 둘 다 성공 / 둘 다 실패`, 선택한 참조의 정확성, 입력·출력 토큰, 작업자 시간, 선택기 시간을 남긴다. 전체 분모를 고정하고 미완료를 성공으로 처리하지 않는다. 모델 로딩·호환 검사·과거 생성 비용은 별도로 보고한다. 현재 상태 두 변형과 후보 쌍을 독립 경험으로 세지 않으며 평가 기본 계획은 8개뿐이다.

## 실행 전 점검과 자원

Qwen 실행을 위해 transformers 5.22.2를 사용한다. 고정 Harrier 판독기는 이전 4.57.6 환경에서 저장한 dev 6요청·36쌍을 먼저 재계산해 호환성을 확인한다. 모든 분류/Top1이 같고 확률 최대 차이가 사전 한도 0.01 이하여야 후속 생성을 시작한다. 이 검사는 모델 재학습이나 새 효용 정답을 이용한 보정이 아니다.

모의 입력으로 원문 참조·날짜, 숫자 경계, 모든 조건의 동시 충족, 무기억 입력의 기록 배제, 정책 간 공통 정보 동일성을 검사한다. GPU는 준비 후 전용 Colab A100 하나만 할당한다. 최초 controller 상한 2,100초, 모델 실행 상한 1,800초다. 진행 중 부분 결과를 ZIP으로 회수하며 완료·실패 모두 자기 세션 종료를 확인한다. 로컬 GPU는 사용하지 않는다.

결과가 전체 제공이나 단순 규칙보다 나쁘면 그대로 보고한다. 특히 이 명시적 참조 과제에서 규칙이 충분하다는 기존 한계는 유지된다. 성공 사례만 남기거나 손해를 만들기 위해 거짓 기록을 넣지 않는다. 이 파일럿의 목적은 **관계 판독 정확성과 실제 기억 효용 사이의 차이를 측정하는 실행 경로를 확인하는 것**이다.
