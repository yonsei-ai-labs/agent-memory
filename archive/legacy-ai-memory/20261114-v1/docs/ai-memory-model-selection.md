# 메모리 실험의 모델 선정과 저비용 진행안

2026-11-03 · 사용자 비용 선호 반영 · 설계와 첫 연결 점검

**실행 경로 갱신:** 사용자의 지정에 따라 OpenRouter를 사용한다. 현재 설정은 `openai/gpt-6-luna`와 `deepseek/deepseek-v4.1-flash-1017`이며, 제공자는 OpenAI와 DeepInfra FP8로 각각 고정한다. 직접 DeepSeek 경로는 계정 데이터 정책으로 요청이 거절되어 제공 경로를 변경했다. mini-SWE-agent 2.4.6의 OpenRouter Responses 어댑터를 공통으로 사용하며, 아래의 직접 API 연결 설명은 배경 검토다. 실제 결과·과금·제공 버전은 [진행 기록](experiment-log.md)과 [연결 점검 보고서](reports/2026-11-03-openrouter-smoke.md)를 우선한다.

**초기 실험은 GPT-6 Luna와 DeepSeek Flash를 중심으로 진행한다.** 두 모델을 메모리 없이 짧게 점검한 뒤 하나를 주 모델로 정하고, 고정된 기억의 득실을 탐색한다. 다른 모델은 후속 확인에 사용한다. 예산은 두 모델의 반복 실행과 원인 확인에 집중한다.

이 문서는 [첫 실험 실행안](ai-memory-pilot-reassessment.md)의 모델·비용 부분을 구체화한 현재 권고다. 연결 점검과 별개로 모델 선정 집합의 해결률과 메모리 효과는 아직 측정하지 않았다.

**1. 후보는 두 개로 좁힌다.**

| 항목 | GPT-6 Luna | DeepSeek Flash |
| --- | --- | --- |
| API 모델 ID | `gpt-6-luna` | `deepseek-flash` |
| 확인한 DeepSeek 제공 버전 | 해당 없음 | V4.1-Flash-1017 |
| 추론 설정의 출발점 | `medium` | thinking 활성화, `high` |
| 캐시 없는 입력 / 출력 단가 | $0.10 / $0.50 | 비혼잡 $0.15 / $0.60, 혼잡 $0.30 / $1.20 |
| 처음 맡길 역할 | 첫 연결 점검 후보 | 같은 과제에서 함께 점검할 후보 |
| 최종 주 모델 여부 | 예비 실행 후 확정 | 예비 실행 후 확정 |

단가는 100만 토큰당 USD다. Luna는 입력 272K 이하 요청의 Standard 요금이며, 지역·장문 할증과 캐시 쓰기·인프라 비용은 별도다. DeepSeek는 시간대별 요금이 다르다. 현재 가격과 버전은 [OpenAI 공식 Luna 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)와 [DeepSeek 공식 모델·가격](https://api-docs.deepseek.com/quick_start/pricing/)에서 확인했다.

이 표는 직접 API의 조회값이다. 현재 OpenRouter 실행의 예산과 보고에는 선택한 제공자의 endpoint 가격과 실제 응답·generation 과금 내역을 사용한다. 특히 DeepInfra FP8의 가격을 DeepSeek 직접 API 가격과 같다고 가정하지 않는다.

Luna의 캐시 없는 단가가 낮더라도 과제당 비용까지 반드시 낮은 것은 아니다. 반복 명령, 재시도, 출력·추론량과 실제 캐시 사용량이 다르기 때문이다. 메모리 효과가 크게 나올 모델을 예상해서 고르기보다, 정상적인 과제 수행과 실제 지출을 보고 정한다.

두 모델의 effort 이름이 같은 계산량을 의미하지는 않는다. 위 값은 각각의 공식 기본 설정을 출발점으로 삼은 것이며, 동일 계산량 비교라는 주장은 하지 않는다. DeepSeek는 `medium`도 실제로 `high`에 대응하므로 명시적으로 `high`를 사용한다. [DeepSeek 추론 설정](https://api-docs.deepseek.com/guides/thinking_mode/)

**2. 전체 진행은 작은 점검 → 한 모델의 탐색 → 필요한 확인으로 나눈다.**

| 단계 | 제안 규모 | 얻을 정보·다음 조건 |
| --- | --- | --- |
| 과제 관계 점검 | 기존 Lite 비중복 후보의 메타데이터·이력 검토 | 실제 과거 경험을 재사용할 평가 과제가 있는지 |
| 무메모리 연결·환경 점검 | 별도 2과제 × 2모델 × 1회 = 4회 | 도구 실행, 패치 제출, 채점, 사용량 저장 확인 |
| 모델 선정용 실행 | 별도 6과제 × 2모델 × 2회 = 24회 | 기본 수행, 형식 오류, 성공·실패 분포, 실제 비용 |
| 전달 경로 점검 | 주 모델·별도 2과제 × 3조건 × 1회 = 6회 | 시작 제공·자율 조회·미조회의 입력과 기록 경로 |
| 주 모델 경험 수집 | 수집용 10과제 × 1회 = 10회 | 성공·실패 궤적과 기억 카드 |
| 주 모델 메모리 평가 | 다른 10과제 × 3조건 × 3회 = 90회 | 무메모리·시작 제공·자율 검색의 효과·회귀·비용 |
| 후속 확인 | 발견한 현상에 맞춰 사전에 정한 추가 실행 | 항목 개입 또는 다른 모델에서의 재현 |

제시한 최초 단계의 에이전트 실행 합계는 `4 + 24 + 6 + 10 + 90 = 134회`다. 기존 128회 예시에 전달 경로 점검 6회를 추가했다. 이 가운데 기존에 논의한 100회는 경험 수집과 주 모델 평가이며, 주 평가 조건 수는 3개를 유지한다. 기억 작성 호출, 재시도, 검색·채점·컨테이너 비용과 후속 실험은 별도 집계한다. 이 숫자는 표본 수 검정이나 지출 약속이 아닌 계획 예시다.

점검·모델 선정·경험 수집·평가 문제는 구분한다. 선정용 실행 결과를 평가 성공률에 합치거나, 평가 과제의 로그를 기억에 넣지 않는다. 과제 관계와 시간상 이용 가능성이 확보되지 않으면 먼저 그 구성을 수정한다. 작은 파일럿의 효과를 SWE 전체 분포로 일반화하지 않는다.

**3. 모델 선정 기준은 메모리 결과를 보기 전에 정한다.**

| 예비 실행에서의 관측 | 결정 원칙 |
| --- | --- |
| 두 모델 모두 도구와 제출이 안정적이고 문제 해결에 진전이 있음 | 성공·실패 분포와 전체 실행 비용을 함께 보고 주 모델 선택 |
| 한 모델만 정상적인 과제 해결을 수행 | 해당 모델 우선; 다른 모델의 연결 문제와 능력 부족은 구분 |
| 둘 다 거의 모든 과제에서 실패 | 환경·프롬프트·예산 제한·과제 난도를 진단하고 설계 재검토 |
| 둘 다 거의 모두 성공 | 효율과 회귀를 우선 관찰하거나 더 어려운 과제군을 별도 정의 |
| 소수 과제의 성공 수만 약간 다름 | 확정적인 모델 순위를 만들지 않고 비용·안정성과 불확실성 함께 판단 |

6과제의 2회 반복은 선정용 점검이다. 한두 번의 성공 차이를 모델의 일반적인 우열로 해석하지 않는다. 낮은 비용이 빠른 실패 때문인지도 살핀다. 수행이 비슷하면 비용·지연이 적고 연결이 안정적인 쪽을 선택하며, 판단이 어려우면 최초 구현 후보인 Luna로 탐색을 시작하고 그 선택 근거를 기록한다.

결정 후 모델·추론 설정·예산을 고정한다. ‘메모리를 넣었더니 가장 많이 좋아지는 모델’을 사후에 주 모델로 고르지 않는다. 두 모델 모두의 기본 수행이 부족하다면 과제·환경·설정의 타당성을 먼저 다시 점검한다.

**4. 주 모델 한 개로 무메모리·시작 제공·자율 검색을 비교한다.**

| 조건 | 입력 | 주 해석 |
| --- | --- | --- |
| `none` | 메모리 없음 | 기준 성능과 비용 |
| `preload` | 문제 설명으로 사전 검색한 카드를 시작 입력에 제공 | 자동 제공 정책의 효과 |
| `agent_search` | 에이전트가 필요할 때 쿼리를 작성해 같은 저장소를 검색 | 자율 검색 정책의 효과와 시작 제공과의 차이 |

과제마다 같은 초기 환경과 총 실행 예산을 사용한다. 메모리 두 조건은 같은 저장소·검색기·카드 형식·한도를 사용한다. 첫 비교는 검색 최대 1회·카드 최대 1개이며, 자동 검색도 한도·총비용에 포함한다. 자율 검색의 미조회·빈 결과를 제외하지 않는다. 검색 시점과 선택된 내용이 함께 바뀌므로 순수한 시점 효과라고 해석하지 않는다. 구체적인 비교와 후속 대조는 [현재 실험안 4절](ai-memory-pilot-reassessment.md)을 따른다.

경험 수집, 카드 작성과 평가 실행은 선정한 주 모델로 통일한다. 원본 로그와 공식 결과를 보존하고, 카드에는 관측 사실·교훈 후보·알려진 적용 조건·출처를 구분한다. 평가 동안 기억을 갱신하지 않는다. 성공 여부는 공식 채점기로 판정한다.

재배정 기억은 후속 대조로 옮긴다. 같은 카드의 `deferred_same` 조회 대조로 내용 선택 차이를 제거할 수 있지만 조회 여부·시점·비용은 여전히 달라진다. 반복 검색, 여러 작성 모델, 사실/지침의 모든 조합을 한꺼번에 추가하지 않는다. 첫 결과에서 성공률 차이, 기존 통과 테스트의 회귀, 조회 시점, 전체 비용과 탐색 행동을 함께 본다. 성공→실패 전환 하나는 확인할 후보이며 확정된 유해 기억 라벨이 아니다.

**5. 다음 비용은 발견한 현상을 확인하는 데 쓴다.** 두 후속 경로의 질문을 구분한다.

| 후속 경로 | 비교 | 알 수 있는 것 |
| --- | --- | --- |
| 특정 기억의 원인 확인 | 원래 기억 / 의심 문구 삭제·조건 교정 / 분량을 맞춘 일반 조언 | 해당 내용이 행동과 성과에 기여하는지 |
| 다른 모델에서 확인 | 같은 고정 기억으로 상대 모델의 무메모리 / 메모리 비교 | 이 기억의 효과가 다른 사용 모델에서도 나타나는지 |

다른 모델에서 무메모리와 사전에 고른 한 전달 정책을 확인하는 예시는 전체 평가 10과제 × 2조건 × 3회 = 60회다. 최초 134회 예시에 이를 추가하면 194회다. 세 정책 모두 확인하면 추가 90회로 총 224회다. 추가 작성 없이 같은 기억을 재사용할 수 있지만 상대 모델의 새로운 기준 실행은 필요하다. 모델 선정 때 사용한 다른 과제의 기준 점수를 가져오지 않는다.

주 모델에서 좋아지거나 나빠진 과제만 상대 모델에 주면 그 선택에 조건부인 사례 분석이 된다. 가능하면 평가 집합 전체를 사용한다. 같은 10과제의 다른 모델 실행은 **모델 간 확인**이고, 가설을 고정한 뒤 별도 과제에서 확인하는 것은 **새 과제로의 일반화 확인**이다. 둘을 혼동하지 않는다.

Luna가 만든 기억을 DeepSeek가 읽는 실험과 그 반대는 다른 전이다. 먼저 주 모델의 고정 기억을 상대 모델에 주고, 실제로 필요할 때 상대 모델이 자기 경험부터 수집하는 실험을 추가한다. 상대 모델에서 효과가 없으면 그 기억의 전이가 제한될 수 있다는 결과로 해석한다.

**6. 같은 에이전트와 도구를 유지한다.** mini-SWE-agent를 공통 실행체로 두고 모델 API 연결만 바꾼다. 두 모델에 같은 기능의 셸 도구와 같은 문제·기억 텍스트를 제공한다. 토큰화와 추론 계산량까지 같다고 가정하지는 않는다.

Luna는 추론과 함수 호출을 함께 사용할 때 Responses API를 사용한다. mini-SWE-agent에는 `litellm_response` 어댑터가 있다. DeepSeek도 Responses 형식을 제공하지만 지원하는 필드와 상태 관리가 동일하지 않으므로, 같은 어댑터가 수정 없이 작동한다고 단정하지 않는다. [OpenAI 공식 문서](https://developers.openai.com/api/docs/models/gpt-6-luna), [mini-SWE-agent 어댑터](https://mini-swe-agent.com/latest/reference/models/litellm_response_toolcall/), [DeepSeek Responses 안내](https://api-docs.deepseek.com/guides/responses_api/)

DeepSeek Responses는 서버의 `previous_response_id`를 이용한 대화 연속성을 지원하지 않는다. 필요한 대화·도구 호출·도구 결과를 매 요청에 전달하는지 점검한다. Chat Completions 경로를 쓰면 도구 사용 중 `reasoning_content`를 다시 전달하는 요구사항도 확인한다. 여러 차례의 도구 왕복에서 생긴 연결 오류를 모델의 문제 해결 실패로 잘못 분류하지 않는다. [DeepSeek 상태 관리](https://api-docs.deepseek.com/guides/responses_api/), [도구와 추론](https://api-docs.deepseek.com/guides/thinking_mode/)

API에 따라 지원되지 않거나 무시되는 `temperature` 등의 값을 일괄 적용하지 않는다. 실제 전송된 추론·샘플링 설정과 응답 사용량을 기록한다. 외부 기억의 효과는 모델이 설명한 속마음보다 관측 가능한 명령·수정·채점 결과로 판단한다.

**7. 예산은 단계별 실제 사용량으로 관리한다.** 첫 연결 점검에는 과제당 누적 API 비용 $0.25 중단 기준을 설정했다. 마지막 요청 비용만큼 초과할 수 있다. 모델 선정·메모리 실험의 전체 예산은 아직 확정하지 않았으며 한 점검 과제의 비용으로 100회 총액을 확정하지 않는다.

- 실행별 입력, 캐시 읽기·쓰기, 출력·추론 토큰, 재시도, 시간과 실제 청구 비용을 기록한다.
- API 비용과 컨테이너·채점·저장 비용을 분리한다. 기억 생성 비용도 따로 남긴다.
- 연결 점검 후 다음 24회 규모의 예산을 추정하고, 선정용 실행 후 주 모델의 100회 규모를 추정한다.
- 실행 전 과제당 최대 행동 수·출력량·시간·비용과 단계 총액 한도를 설정한다. 한 요청이 끝난 뒤 비용 초과를 알 수 있으므로 여유분도 둔다.
- DeepSeek는 가능하면 비혼잡 시간대에 실행하되, 세 전달 정책을 같은 시간 블록 안에서 섞고 각 요청의 적용 요금을 남긴다. 실제 지출과 동일 단가로 환산한 사용량 비용을 구분하면 시간대 차이를 해석하기 쉽다.
- 캐시 정책과 동시 실행 수는 고정해 기록한다. 조건마다 실제 캐시 적중량이 같다고 가정하지 않는다.

대략적인 첫 탐색 비용은 다음 항목으로 산정한다. 각 C는 해당 실행 종류의 측정된 과제당 비용이다.

```text
C_initial =
  C_environment_check + C_model_selection
  + 10 × C_source + 10 × C_memory_write
  + 30 × (C_A + C_B + C_C)
  + C_infrastructure
```

후속의 추가 실행과 재시도는 별도다. 입력 2,000만·출력 200만 토큰의 단순 예를 사용하면 Luna $3, DeepSeek $4.20–8.40이지만, 이는 캐시·할증·기억 생성·인프라를 제외한 같은 토큰량의 산술 예시다. 실제 벤치 견적으로 사용하지 않는다.

**8. 버전과 결과물을 고정한다.** DeepSeek의 예전 `deepseek-v4-flash` 이름은 현재 V4.1-Flash-1017로 연결된다. 논문의 옛 모델과 현재 API 호출을 동일한 재현으로 취급하지 않는다. 요청 ID·반환 모델 정보·실행 날짜·요금표·하네스 버전·프롬프트·기억 해시를 함께 기록한다. [DeepSeek 모델 이름 안내](https://api-docs.deepseek.com/quick_start/pricing/)

API 모델의 고정 버전을 사용할 수 있는지 확인하고, 고정할 수 없는 부분은 제한으로 남긴다. 모델이나 설정이 바뀌면 기존 조건 결과와 섞지 않고 별도 실험 버전으로 다룬다.

OpenRouter 연결 설정, 점검용 예산, 원본 기록과 공식 채점 경로를 구현했다. 다음 준비 산출물은 **과제 분할과 경험 연결 목록, 본 실험 단계 예산, 24회 선정용 실행표, 기억 카드 형식**이다. 실제 실행 이력은 [진행 기록](experiment-log.md)에 남긴다.
