# 메모리 정보의 가치 측정과 학습 기반 선택 연구 노트

2026-11-07 · 정보 가치 측정과 작은 선택기의 학습 계획

이 연구는 **같은 경험에서 어떤 정보를 보존하고, 어떤 상황에서, 얼마나 전달해야 코드 에이전트의 성과와 비용이 좋아지는지** 측정한다. 그 결과를 이용해 작은 모델이 현재 문제·환경·다른 기억과의 관계를 읽고 유용한 정보를 고르게 한다.

> 핵심 질문은 “메모리가 도움이 되는가?”에서 “같은 제한된 읽기 예산에서 어떤 정보 묶음을 제공해야 실제 문제 해결에 이득인가?”로 좁힌다.

첫 학습 모델은 **Harrier-OSS-v1-0.6B**다. 선형 예측층을 기준으로 작은 관계 학습층, LoRA, 보조 신호의 효과를 나누어 확인한다. 선형층만으로 충분한 결과도 연구 성과이며, LoRA 적용이나 모델 확대 자체가 목표는 아니다.

먼저 [현재 결정](#1-현재-결정과-연구-범위), [실험 설계](#4-정보-복원에서-예산에-맞춘-선택으로), [학습 설계](#5-작은-모델에-무엇을-학습시킬-것인가), [다음 작업](#8-다음-작업과-산출물)을 읽으면 전체 흐름을 파악할 수 있다. 통계적 해석과 비용 계산, 논문별 한계는 부록에 둔다.

추가 문헌에서 얻은 학습 신호·입력 대조·정보 조합 아이디어는 [선택기 문헌 재검토](ai-memory-selector-literature-review-2026-11-07.md)에 정리했다. 첫 백본과 네 학습 구성은 유지하고, 실제 선택 능력과 단순한 난이도 예측을 구분하는 진단을 보강한다.

## 1 현재 결정과 연구 범위

| 항목 | 현재 판단 | 상태 |

**효과 측정, 학습 기능 점검, 독립적인 정책 평가를 구분한다.** 현재 복원 파일럿과 병행해 기존 로그의 근거·검사 범위 자료를 만들고 학습 구조를 준비할 수 있다. 소수 출처의 반복이나 합성 편집은 독립 경험 수를 늘리지 않으며, 보조 판독 점수와 실제 해결 이득은 따로 보고한다.

이 노트는 연구 설계다. 현재 파일럿의 배정·입력·채점·분석 규칙은 [실행 보고서](reports/2026-11-07-process-restoration.md)와 연결된 동결 자료를 따른다. 이 정리로 기존 실행 계획을 변경하지 않는다.

## 2 관측한 사실과 검증할 가설

기존 SymPy 출처의 실제 procedure 카드에는 출처에서 겪은 `rg` 부재, `pytest` 미설치, 대체 검사 명령이 빠져 있었다. 이 경험의 전이를 비교한 **무기억 조건 포함 48회** 중 45회에서 도구 부재가 관측됐고, 성공한 15회 중 14회도 같은 오류를 겪었다. 전체 48회에는 미제출 18회가 포함된다. [출처·명령 근거](reports/data/literature-revisit-20261107/README.md), [성과와 도구 오류의 교차 집계](design-data/component-intervention-20261107/tool-error-outcome-crosscheck.json).

이는 재사용할 정보 후보를 찾은 관측이다. 오류를 줄이면 성공률이 오른다는 결론이나, 미제출이 과도한 검증 때문이라는 결론은 아직 없다. 사용하지 않은 다른 카드 후보에는 일부 과정 정보가 있었으므로 모든 기억 작성이 이를 놓쳤다고 일반화하지도 않는다.

| 질문 | 검증할 가설 | 필요한 비교 |
| --- | --- | --- |
| 요약에서 무엇이 빠지는가 | 생략된 명령·결과·검사 범위를 복원하면 일부 시행착오나 비용을 줄일 수 있다 | 같은 요약과 과정 정보 복원 요약 |
| 어떤 조건에서 재사용 가능한가 | 현재 상태와 과거 전제를 비교하면 부적합한 기억 사용을 줄일 수 있다 | 같은 정보에서 적용 판단 절차 유무 |
| 확인은 언제 도움이 되는가 | 행동에 필요한 전제만 확인하면 확인 비용과 실패를 함께 줄일 수 있다 | 확인 없음·일괄 확인·선택적 확인 |
| 제한된 공간에 무엇을 담을 것인가 | 유사도 외에 실제 결과·적용 조건·중복·조합을 학습하면 선택이 좋아질 수 있다 | 같은 후보와 토큰 상한에서 기존 검색·학습한 선택 |

첫 세 질문은 [Memory Tax](https://arxiv.org/html/2610.34073v1), [MemDev-Bench](https://arxiv.org/html/2610.27524v1), [BASM](https://arxiv.org/html/2608.22339v1), [MemHarness](https://arxiv.org/html/2607.28272v1), [AMV-Guard](https://arxiv.org/html/2610.31446v1)와 연결된다. 각 방법은 기억 표현·학습·실행 절차를 함께 바꾸기도 하므로, 우리 주의 문장 하나의 효과와 동일시하지 않는다. [기존 10편 검토](ai-memory-literature-revisit-2026-11-07.md)에 논문별 근거와 범위를 남겼다.

## 3 이득과 손해의 정의

### 제공 가치와 선택 가치와 보존 가치

| 가치 | 바꾸는 것 | 측정할 결과 |
| --- | --- | --- |
| 제공 가치 | 같은 시작 상태에서 특정 정보를 추가·삭제·교체 | 해당 입력 편집이 만든 성과·비용 차이 |
| 선택 가치 | 같은 기억 은행에서 무엇을 꺼내 전달할지 결정하는 규칙 | 선택기 비용까지 포함한 정책의 성과 |
| 보존 가치 | 무엇을 저장·갱신할지 정하는 규칙 | 미래 과제열의 재사용·검색 경쟁·구축 비용까지 포함한 가치 |

현재 복원 실험은 제공 가치를 잰다. 다음 학습 실험은 선택 가치를 겨냥한다. 한 번 제공한 효과에 재사용 횟수를 곱하는 계산만으로 장기 보존 가치가 검증되지는 않는다.

### 정보 하나의 기여는 조건부 차이로 잰다

사례 x는 출처 경험과 대상 과제의 쌍이다. 공통 기억 C, 추가 정보 u, 기억 전달 예산과 작업 실행 예산을 정한다. p는 **예산 안에 제출한 패치가 공식 검사를 통과할 확률**, c는 전체 배정의 평균 실행 비용이다.

```text
정보 u의 성과 기여 δ_u(x) = p_x(C + u) − p_x(C)
정보 u의 추가 비용 κ_u(x) = c_x(C + u) − c_x(C)
전체 평균 기여       Δ_u = Σ_x w_x δ_u(x),  Σ_x w_x = 1
```

성과는 %p, 비용은 달러·토큰·시간으로 구분한다. `δ>0`은 해당 조건의 성과 이득, `δ<0`은 해당 조건의 성과 손해다. 비용 차이 `κ<0`은 절감이다. 외부 기억이 없는 조건과의 비교는 전체 시스템 효과를 따로 보여준다. 여기서 무기억은 외부 경험 미제공이며 모델의 사전 지식 제거를 뜻하지 않는다.

예산이 꽉 차면 u를 넣으려고 다른 정보 v를 빼야 한다. 이때 비교는 `p(C − v + u) − p(C)`이고, **u의 이득과 밀려난 v의 손실이 함께 들어간다.** 여유 공간에서의 추가 효과와 고정 예산에서의 교체 효과를 구분한다.

기억의 가치는 현재 문제·환경·이미 들어간 정보·예산에 따라 달라진다. 예를 들어 출처에서 도구가 없었다는 관찰과 대체 명령, 그 명령의 검사 범위는 함께 있어야 유용할 수 있다. 개별 정보의 독립 점수를 더한 값이 묶음 전체의 효과라고 가정하지 않는다.

처음에는 **사전에 정한 상황별 평균 차이와 불확실성**을 보고한다. 같은 실행을 기억 있음·없음으로 동시에 관측할 수 없으므로 개별 실행의 확정적인 도움·피해율은 직접 알 수 없다. 이 구분과 상호작용의 수식은 부록 A에 둔다.

## 4 정보 복원에서 예산에 맞춘 선택으로

### 현재 파일럿은 빠진 정보의 복원을 측정한다

| 조건 | 제공 내용 | 역할 |
| --- | --- | --- |
| N | 외부 경험 없음 | 전체 효과의 기준 |
| R | 같은 출처에서 사전 규칙으로 뽑은 원문 근거 | 원문 제공 기준 |
| S | 해결 요령 요약 | 복원 전 기준 |
| M = S + O | 정확히 같은 S에 과정 정보 O를 추가 | **M−S가 주 대비** |

실제 확정 범위는 **출처 2개 × 출처별 대상 2개 × 4조건 × 2반복 = 32개 배정**이다. 출처는 성공한 scikit-learn 경험과 미해결 Django 경험이고, 대상 실행 예산은 20응답이다. 두 출처에서 복원하는 O는 모두 **V인 구체적 검사 실행 정보**다. 도구 부재 같은 환경 관측 E의 복원 효과를 측정한 설계는 아니다.

R은 전체 이력이나 정답 근거를 미리 아는 최적 검색이 아니라 규칙에 따른 발췌다. S에서 O가 의미상 빠졌는지 출처 로그로 확인하고, M에서 O를 제거하면 S가 정확히 복원되도록 한다. 출처의 로컬 검사 통과와 공식 해결 판정, 과거 환경과 현재 환경을 구분한다. 출처가 미해결이었다는 상태도 기억에 함께 남긴다.

M−S에는 정보량·길이·구조가 함께 바뀌는 효과가 포함된다. 첫 결과는 **정보 복원 패키지의 효과**로 해석한다. 같은 길이의 정보 교체나 표현만 바꾸는 비교는 별도 후속 실험이다. 기존 48회는 가설 발견 자료이며 새 배정과 합쳐 확증 표본으로 세지 않는다.

2026-11-07 실행 보고서 기준 한 배정이 외부 중단되어 결과와 마지막 요청 비용이 미확정이다. 미실행분을 같은 설정으로 이어가며, 중단 배정을 정상 실패나 대체 실행으로 바꾸지 않는다. 32는 완료 수가 아니다. 결과 범위·비용 유보·분석 보완의 정확한 상태는 [파일럿 보고서](reports/2026-11-07-process-restoration.md)를 기준으로 삼는다.

### 기억이 늘어나면 세 가지 양을 따로 제한한다

| 구분 | 통제하고 기록할 양 |
| --- | --- |
| 저장된 기억 은행 | 서로 다른 과거 경험 수, 전체 토큰, 구축·갱신 비용 |
| 선택기가 읽는 후보 | 후보 수 k, 후보 토큰, 검색·선택 시간과 연산 |
| 작업 에이전트가 읽는 기억 | 전달 토큰 상한 b와 실제 사용량 |

```text
출처 로그와 근거를 보존한 기억 은행
                  ↓
        키워드·임베딩으로 후보 검색
                  ↓
      제한된 후보에서 학습한 모델이 선택
                  ↓
       b 토큰 이내의 기억과 적용 조건
                  ↓
      코드 에이전트의 실행·제출·사후 평가
```

은행 전체가 작업 에이전트의 문맥에 들어갈 필요는 없다. 검색용 임베딩은 미리 계산하고, 선택기가 읽는 양도 제한한다. b는 작업 에이전트의 tokenizer로 재며 본문·출처 표기·적용 조건을 포함한다. 문제·도구 설명과 이후 작업 문맥을 위한 공간은 별도로 확보한다.

정보 단위는 원문 근거를 가리키는 관찰·명령·결과·적용 범위로 구성한다. 핵심 조건이 잘려 나가지 않도록 필요한 연결을 보존한다. 같은 b는 같은 **상한**이며 실제 사용량을 억지로 맞추지는 않는다. 적합한 정보가 없으면 제공을 중단할 수 있다.

필수 근거를 주석할 수 있는 사례에서는 b 토큰 안의 근거 완결성도 진단한다. 이는 해결 성공과 별개다. 후보 단위를 바꾸는 비교와 선택 모델을 바꾸는 비교를 분리하고, 모델 대조에서는 후보 내용까지 고정한다. [단위·조합 설계의 근거](ai-memory-selector-literature-review-2026-11-07.md#5-기억-단위와-조합-같은-경험에서-무엇을-함께-남길-것인가).

| Q0 | 기억 없음 | 전체 시스템 효과 |
| Q1 | 기본 키워드·임베딩 검색 점수순으로 선택 | 간단한 검색으로 얻는 이득 |
| Q2 | 공개 재순위화 모델과 중복 제거를 적용 | 강한 기존 선택 방식의 성과 |
| Q3 | 실제 성과·비용 신호로 학습한 선택기를 적용 | 결과 학습이 더하는 가치 |

정책 평가의 주 비교는 Q3−Q2이고, Q3−Q1과 Q3−Q0도 함께 보고한다. Q3의 학습 구성을 개발 자료에서 선정한 뒤 평가에서는 고정한다. Q1~Q3는 동일한 검색기가 만든 후보 풀, 기억 본문, 토큰 상한, 작업 에이전트와 실행 한도를 사용한다. 포장·중복 제거·임계값은 개발 자료에서 고정한다. 선택하면서 본문까지 재작성하는 방법은 다음 실험으로 분리한다.

‘정해진 기억을 항상 제공’은 작은 고정 묶음에서의 유효한 진단 기준이다. 현재 S/M에서는 O를 항상 주거나 선택적으로 주는 비교에 쓸 수 있다. 커진 은행의 본 실험에서는 위 검색·재순위화 기준선을 사용한다. 전체 원문 제공은 문맥 안에 들어가는 작은 은행의 보조 조건으로 남긴다.

은행과 b 하나에서 시작한 뒤, 예를 들어 **512·1,024·2,048토큰**으로 예산을 바꾼다. 실제 근거 묶음 길이를 확인해 값을 확정하며, 이 숫자가 최적값이라는 가정은 없다. 그다음 b를 고정한 채 서로 다른 과거 경험을 늘려 관련·유사하지만 부적합·무관한 이력이 섞이는 효과를 본다. 처음부터 은행 크기와 모든 예산의 조합을 실행하지 않는다.

### 다른 질문은 별도 축으로 비교한다

| 후속 축 | 설계의 요점 |
| --- | --- |
| 같은 정보의 서술형·지시형 | 주장·적용 조건·출처·순서를 맞춘 뒤 표현을 변경. 조건부 주의사항을 한쪽에만 넣지 않음 |
| 적용 조건의 실제 판단 | 현재 상태와 기억의 전제를 비교·수정·보류하는 절차를 시험. 일반 재검토의 효과도 대조 |
| 확인 비용 | 확인 없음·일괄 확인·행동 전제의 선택적 확인을 비교. 첫 통과 관측과 실제 제출을 분리 |
| 현재 환경 안내 | 직접 관측한 환경 안내 A_env 이후에도 과거 기억의 추가 가치가 남는지 비교. 안내 작성 비용 포함 |
| 필요할 때 원문 재조회 | 첫 제공량뿐 아니라 한 과제에서 추가로 읽은 누적량·호출·지연을 제한 |
| 작성·보존 정책 학습 | 선택 효과를 확인한 뒤 원문 보존·조건 추가·생략·갱신을 학습 |

실행 중 분기하는 연구는 파일·대화·도구 이력·남은 예산을 같은 상태에서 시작해야 한다. 현재의 패치 저장만으로 전체 상태의 완전한 재현이 보장되지는 않는다. 구체적인 후속 개입은 [상세 실험 설계](ai-memory-intervention-study-plan-2026-11-07.md)를 따른다.

## 5 작은 모델에 무엇을 학습시킬 것인가

### 학습 목표는 조건에 따라 달라지는 가치를 판단하는 것이다

현재 문제·환경·공통 기억이 달라지면 같은 정보의 가치도 달라진다. 가령 “출처에서 pytest가 없었고 대체 검사 명령이 동작했다”는 기억은 현재도 부재가 확인된 경우, 현재 설치된 경우, 같은 대체 명령을 이미 전달한 경우에 서로 다른 효과를 낼 수 있다. 이는 검증할 가설이며, 과거 환경을 현재 환경의 사실로 옮겨 적지 않는다.

| 질문 | 학습할 관계 | 효과를 구분할 비교 |
| --- | --- | --- |
| 언제 적용할 수 있는가 | 현재 관측과 기억의 전제 | 같은 모델·학습법에서 조건 정보 유무 |
| 다른 정보와 함께 있을 때도 가치가 있는가 | 중복·보완·남은 전달 공간 | 공통 기억을 바꾼 추가·교체 효과 |
| 무엇을 같이 배우면 판단이 좋아지는가 | 출처 근거·검사 범위와 실행 결과 | 같은 구조에서 보조 손실 유무 |

System 1은 여기서 긴 추론문을 생성하지 않고 점수를 출력하는 방식을 뜻한다. 선형층도 사전학습 모델의 복잡한 표현을 이용할 수 있다. [Retain or Consolidate?](https://arxiv.org/html/2607.17545v2)는 행동별 효용을 선형회귀로 예측했고, 해당 대화 기억 평가에서는 작은 MLP의 일관된 추가 이득을 확인하지 못했다. 우리의 코드 실행에서도 어느 구조가 필요한지 비교로 판단한다.

### 첫 구현은 별도 임베딩에 관계 특징을 더한다

첫 입력 방식은 문제·관측 환경·공통 기억을 인코딩한 `h_q`, 후보·출처 근거·적용 조건을 인코딩한 `h_u`, 선택 전에 알 수 있는 구조화 특징 `r`이다. `r`에는 환경의 확인 상태, 후보 길이, 전달 예산 등을 넣고 정확한 필드·추출 규칙을 데이터와 함께 고정한다. 임베딩 단계의 원문도 보존한다.

```text
z = [h_q, h_u, h_q ⊙ h_u, |h_q − h_u|, r]
```

`⊙`는 두 벡터의 같은 위치끼리 곱하는 연산이다. 곱과 차이는 선형층에도 문제와 후보의 관계를 읽을 입력을 준다. 별도 벡터를 단일 가산 점수 `s(q,u)=aᵀh_q+bᵀh_u`로만 합치면, 같은 문제에서 첫 항이 모든 후보에 같아서 후보 순위가 문제에 따라 바뀌지 않는다. 이 한계를 가진 점수를 유일한 선형 기준선으로 쓰지 않는다.

첫 비교는 모두 같은 `z`를 사용한다. 관계 특징·조건 특징을 제거하는 비교는 입력 기여를 보는 별도 대조다. 조건 정보가 텍스트와 구조화 필드에 중복되면 양쪽에서 같은 정보를 제거해야 한다. 문제와 후보를 함께 읽는 재순위화 방식은 후속 입력 방식 비교로 둔다. 공동 입력과 별도 임베딩을 동시에 바꾸고 그 차이를 LoRA만의 효과로 해석하지 않는다.

### 제공과 보류 각각의 성과와 비용을 예측한다

첫 행동은 공통 요약만 제공하는 `a0: S`와 후보를 추가하는 `a1: S+u`다. 행동과 출력의 순서는 모든 구성에서 고정한다.

```text
현재 상태와 후보를 인코딩한 관계 특징 z
                   ↓
          선형층 또는 작은 공통 MLP
                   ├─ 보류·제공의 성공 제출 확률 p0, p1
                   └─ 보류·제공의 평균 실행 비용 c0, c1

예상 성과 차이 = p1 − p0
예상 비용 차이 = c1 − c0
```

한 실행은 실제 배정된 행동의 출력에만 정답을 제공한다. 성공은 로짓에 대한 BCE, 비용은 훈련 분할에서만 스케일링한 MSE를 기본으로 둔다. 미확정 결과·불완전한 비용과 라벨이 없는 출력은 해당 손실에서 제외하고 관측 범위는 별도 보존한다. 결과를 알고 있다는 이유로 선택되지 않은 행동의 정답까지 채우지 않는다.

이는 [조건부 평균 효과의 meta-learner](https://arxiv.org/abs/1706.03461)와 [공유 표현·조건별 출력층](https://proceedings.mlr.press/v70/shalit17a.html)을 참고한 구성이다. `p1−p0`는 조건부 평균의 예측이며 개별 실행의 확정적인 이득·피해 확률이 아니다. 실제 배정을 통제한 비교 자료로 효과를 검증하고, 기존 비무작위 로그의 성공 상관을 인과 효과로 취급하지 않는다.

선택 시 성과와 비용을 임의의 상수로 합쳐 유일한 가치 점수를 만들지 않는다. 주 목표·비용 한도·제공 임계값을 개발 자료에서 고정하고, 성과·비용 차이를 각각 보고한다. 적합한 후보가 없으면 제공을 보류한다.

### 선형층과 관계 학습층을 모델 고정과 LoRA로 교차 비교한다

| 추가 층 | Harrier 고정 | Harrier에 LoRA 추가 |
| --- | --- | --- |
| 관계 특징 z에 대한 선형 출력층 | **A0**: 선형층만 학습 | **A1**: 같은 선형층과 LoRA 학습 |
| z를 읽는 작은 공통 MLP와 출력층 | **B0**: MLP와 출력층 학습 | **B1**: 같은 MLP·출력층과 LoRA 학습 |

첫 학습 비교의 주 대비는 **B0−A0**다. 같은 표현에서 작은 비선형 관계 학습층이 더하는 효과를 묻는다. **A1−A0**와 **B1−B0**는 [LoRA](https://arxiv.org/abs/2106.09685)의 표현 적응 효과를, **B1−A1**은 표현을 적응한 뒤에도 MLP가 필요한지를 보는 보조 비교다. 선형층이 충분하면 그 구성을 채택할 수 있다. MLP의 이득만으로 특정 관계를 학습했다고 단정하지 않고, 조건·관계 특징의 제거 대조를 함께 해석한다.

네 구성은 같은 초기 checkpoint·pooling·입력 특징·라벨·분할·출력과 평가를 사용한다. 개발 자료 안에서 비슷한 탐색 예산으로 설정을 정하고 학습 seed, 업데이트 수, 학습 파라미터 수, 자원을 기록한다. LoRA는 선택기의 표현에 적용하고 **후보 검색기는 고정**한다. 고정 인코더의 벡터는 캐시할 수 있지만 LoRA 업데이트 중에는 현재 가중치로 다시 계산한다.

첫 비교 뒤에는 **B1에 보조 손실을 추가한 C**를 B1과 비교한다. 보조 과제의 손실은 공통 MLP와 LoRA에 함께 전달한다. 고정된 표현 위의 독립된 보조 출력층만 학습하고 주 예측기가 그 신호를 배웠다고 보지는 않는다.

### 보조 신호와 실제 효용 라벨을 구분한다

| 신호 | 정답의 출처 | 학습상의 의미 |
| --- | --- | --- |
| 출처에 근거한 주장인가 | 원문 명령·출력·인용 구간 | 과거 기록의 근거 판독. 현재도 참이라는 뜻은 아님 |
| 현재 조건에 적용 가능한가 | 공개 문제·초기 코드·판단 전 환경 관측 | 적합·부적합·미확인을 구분 |
| 검사 방법과 범위가 맞는가 | 실행기와 검사 대상 선택자를 분리해 검토 | 같은 runner를 썼다는 이유만으로 유효 검사로 처리하지 않음 |
| 제공 후 성과·비용은 무엇인가 | 배정을 기록한 실제 실행과 공식 사후 채점 | 행동별 결과 예측의 주 학습 신호 |
| 오류·검사·제출 과정은 어떻게 변하는가 | 실제 실행 로그와 고정 시점 패치의 사후 평가 | 과정 보조 신호. 오류 감소 자체를 성공으로 치환하지 않음 |

처음에는 출처 근거와 검사 범위 두 보조 과제로 시작한다. 적용 조건의 미확인은 부적합과 분리한다. 추가 층은 모델의 숨은 표현에 연결하며, [Laya의 학습 경로](https://nandhakishorm.github.io/laya/finetune/)처럼 교사 판단을 학습하는 방법도 별도 비교가 될 수 있다. 교사나 합성 편집이 만든 라벨은 실제 실행 효용과 구분해 표시한다.

예컨대 단어는 비슷하지만 검사 범위가 다른 쌍, 표현은 다르지만 조건이 같은 쌍으로 대조 학습을 할 수 있다. 같은 원문에서 파생한 쌍은 함께 분할하고 근거 일치를 표본 확인한다. 보조 과제와 효용 라벨의 수가 크게 다르면 손실 가중치와 각 학습 배치의 구성을 남긴다.

[MemReranker](https://arxiv.org/html/2605.06132v2)의 증류·대조 학습은 이 자료 구성에 참고할 수 있다. 다만 교사 선호나 검사 범위의 적합성을 실제 해결 이득으로 바꾸어 쓰지 않는다. 미확인 사례와 다른 정답 후보를 모두 음성으로 취급하지도 않는다. 헷갈리는 사례 구성과 단계적 학습의 구체적 후속 비교는 [학습 신호 보완안](ai-memory-selector-literature-review-2026-11-07.md#3-바로-준비할-학습-신호-헷갈리는-관계를-구별하기)에 둔다.

### 현재 자료와 학습 기록

확정 파일럿의 S/M은 16개 배정이지만 서로 다른 출처·대상 조합은 네 개다. 이 자료로 데이터 변환·손실·학습 동작을 점검하고 기존 로그의 보조 라벨로 학습을 준비한다. 새 출처에서의 효용 예측과 기억 조합 선택은 추가 자료로 평가한다. 학습 손실 감소만으로 기억 선택의 가능성이 입증됐다고 보고하지 않는다.

학습 자료에는 최소한 다음을 연결한다.

| 기록 | 필요한 내용 |
| --- | --- |
| 출처와 분할 | source·target ID, 연결된 그룹 ID, 원문 해시·근거 위치, 파생 편집 관계 |
| 결정 시점 입력 | 문제·공통 기억·후보·당시 관측된 환경, 선택 전 알 수 있었던 정보의 범위 |
| 행동과 예산 | 배정 ID·제공/보류, 배정 방식과 알 수 있는 배정확률, 전달·실행 한도 |
| 관측 결과 | 성공 제출·공식 판정·비용, 완료/중단·누락 사유, 비용 관측 범위 |
| 라벨의 종류 | 실행 결과·원문 근거·연구자 주석·교사 판단·합성 편집을 구분 |

학습·개발·평가는 실행 행이 아닌 출처·대상 그룹으로 나눈다. 둘 모두 처음 보는 평가를 하려면 같은 출처나 대상을 공유하는 사례를 연결된 그룹으로 묶는다. 현재처럼 두 출처 가족뿐인 자료는 안정적인 학습·개발·평가 분할을 보장하지 못하므로 기능 점검용으로 다룬다. ID는 분할·근거 연결용이며 예측 특징으로 넣지 않는다. 관측하지 않은 배정확률이나 결과를 임의로 채우지 않는다.

### 조합 선택과 확인 행동은 후속 확장으로 둔다

다음에는 공통 기억 S를 **이미 선택한 기억 집합과 남은 예산**으로 확장한다. 중복 기억의 추가 가치와 함께 있어야 유용한 근거의 보완 효과를 구분하려면, 같은 상황에서 대안 묶음을 제공한 결과가 필요하다. 단일 후보의 결과만으로 조합 효과의 정답을 만들지 않는다.

점수/토큰 비율로 담는 방식은 간단한 기준선이다. 이후 선택된 기억의 attention pooling이나 원문에서 확인한 출처 관계를 사용하는 층을 비교할 수 있다. 그래프 구조 자체의 효과를 주장하려면 후보·입력 정보·비교 용량을 맞추는 대조도 필요하다.

불확실할 때 전제를 확인하는 행동은 확인 비용과 확인 후 결과를 새로 관측해야 학습할 수 있다. 초기에는 제공·보류부터 평가하고, 작성·갱신이나 순차 RL은 [MGPO](https://arxiv.org/html/2609.37930v1)·[UMEM](https://arxiv.org/html/2602.10652v1)을 참고한 후속 축으로 둔다. 예측층의 점수 상승은 실제 실행 평가를 대신하지 않는다.

## 6 모델 후보와 GPU 계획

### Harrier로 시작하고 같은 실험 안에서 모델 크기를 고정한다

첫 학습 백본은 **[Harrier-OSS-v1-0.6B](https://huggingface.co/microsoft/harrier-oss-v1-0.6b)**로 정한다. 약 600M의 Qwen3 구조를 사용하며 표준 숨은 상태와 last-token pooling에 접근할 수 있고 라이선스는 MIT다. 작은 모델에서 A0/A1/B0/B1을 반복 비교하기 위한 선택이다. 공개 임베딩 평가의 경쟁력이 우리의 기억 효용 예측 순위를 보장하지는 않는다.

| 역할 | 모델 후보 | 사용 범위 |
| --- | --- | --- |
| 주 학습 | Harrier-OSS-v1-0.6B | 선형층·관계 학습층·LoRA·보조 신호 비교 |
| 기본 검색 | [Qwen3-Embedding-0.6B](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) 또는 고정 Harrier | 후보 검색기를 하나 정해 모든 선택 조건에 공통 사용 |
| 공개 재순위화 | [Qwen3-Reranker-0.6B](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B), [Jina Reranker v3.5](https://huggingface.co/jinaai/jina-reranker-v3.5) | Q2의 구체 모델을 개발 단계에서 선정. Qwen은 Apache 2.0, Jina는 CC BY-NC 4.0 |
| 더 작은 학습 비교 | [ModernBERT-base](https://huggingface.co/answerdotai/ModernBERT-base), [EmbeddingGemma 2](https://huggingface.co/google/embeddinggemma-2) | 자원·표현 비교가 필요할 때 검토. ModernBERT의 임의 pooling을 검색 학습된 모델과 동일시하지 않음 |
| 더 큰 모델 | [Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B), [Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B) 등 | 라벨·입력 문제와 표현 능력 부족을 구분하는 후속 비교 |

최근의 강한 모델을 쓰려는 선호는 확장 후보 선정에 반영한다. [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B)와 [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B)는 자원을 더 투입하는 후속 후보이며 첫 학습 범위에는 넣지 않는다. 작은 모델이 개선되지 않았을 때도 곧바로 연구 방향을 기각하지 않고, 데이터·입력·판독 능력을 점검한 뒤 제한된 큰 모델 비교로 원인을 구분한다.

공동 입력 모델, [Jina Embeddings v5 Text Small](https://huggingface.co/jinaai/jina-embeddings-v5-text-small) 같은 추가 임베딩, 생성형 기억 재작성은 각각 다른 비교 축이다. 첫 회차에는 후보 목록 전체를 학습하지 않는다. MTEB·BEIR·RTEB·코드 검색의 다른 표를 숫자 크기만으로 순위 매기지 않으며, 모델 revision·라이브러리·pooling·입력 길이·학습 파라미터 수를 남긴다.

### 연결한 Colab에서 작은 학습부터 자원을 측정한다

2026-11-07 계정 연결 점검에서는 Colab CLI 0.7.5로 **잔여 600 CU, 사용률 0 CU/시간, 활성 세션 0개**를 확인했다. 연결 당시의 조회 기록이며 현재 잔액이나 GPU 할당을 보장하는 수치가 아니다. CU는 GPU 사용 시간이 아니며, GPU 종류에 따라 소모율이 달라진다. [Colab 자원 안내](https://research.google.com/colaboratory/faq.html#resource-limits)

GPU 학습은 연결한 Colab을 이용한다. 로컬 RTX 4080 SUPER 16GB는 다른 Laya 학습과 사용 일정을 분리한다. 데이터 정리와 캐시한 벡터 위의 작은 층 학습은 CPU에서도 수행할 수 있다. 별도 상시 클라우드의 추가 비용은 작업의 시간·CU·완료율을 측정한 뒤 비교한다.

후속으로 [별도 학습 폴더](../training/memory_selector/README.md)를 만들고 T4에서 수치 근거 판독 여섯 구성을 실제 학습했다. 이는 위 A0/A1/B0/B1의 성과·비용 예측과 별개인 3분류 기능 점검이다. 합성 주장 324개는 22과제·81관측에서 나왔고 규칙 판독으로 풀 수 있다. 약 13분 후 결과를 회수하고 세션을 종료했으며 조회 잔액은 600.00에서 599.83 CU로 바뀌었다. LoRA의 평가 개선은 확인하지 못했고, 주장만 보는 대조도 강했다. [실행 결과·데이터 한계·정밀도 기록](../training/memory_selector/reports/2026-11-07-aux-grounding-smoke.md)에 실제 결과와 후속 변경을 구분했다.

| 순서 | 작업과 기록 |
| --- | --- |
| 1 자원 점검 | 할당 GPU·VRAM·라이브러리와 checkpoint 고정. 16~24GB급을 시작 후보로 삼고 실제 적합성을 측정 |
| 2 기능 점검 | 512~1,024토큰의 짧은 입력, 작은 micro-batch, 지원되는 혼합 정밀도로 forward/backward·저장/재개 확인. 필요시 gradient checkpointing |
| 3 표현·층 비교 | 고정 인코더의 벡터를 캐시해 A0/B0를 비교하고, A1/B1에서는 LoRA를 포함해 표현을 재계산 |
| 4 실행 비용 기록 | 최대 VRAM·초/step·총 시간·CU·학습/추론 비용·checkpoint 경로와 중단 상태 보존. 완료 후 자신이 만든 런타임 종료 |

짧은 입력은 기능 점검용이다. 본 학습 길이는 정보·적용 조건이 잘리지 않도록 원문 길이를 보고 정하며, 잘림률과 빠지는 필드를 기록한다. 모든 비교 조건에 같은 입력 규칙을 적용한다. 문서상 최대 문맥 길이나 가중치 파일 크기를 실제 학습 메모리로 취급하지 않는다.

큰 모델로 확장할 때는 자원표를 다시 측정한다. 예를 들어 [Unsloth의 Qwen3.5 학습 안내](https://unsloth.ai/docs/models/qwen3.5/fine-tune)는 BF16 LoRA의 참고 사용량과 4비트 학습의 주의점을 제시하지만, 우리 추가 층·길이·배치의 실측을 대신하지 않는다. 학습 GPU 비용과 효용 라벨을 만들기 위한 에이전트 실행 비용도 별도로 기록한다.

## 7 평가 지표와 공정한 비교

### 벤치마크는 역할별로 사용한다

| 평가 층 | 자료 | 알 수 있는 것 |
| --- | --- | --- |
| 일반 표현·검색 | [MTEB](https://docs.mteb.org/), [CoIR](https://aclanthology.org/2025.acl-long.1072/) | Recall·nDCG 등 후보 검색 능력과 학습 후 변화 |
| 근거·적용 조건 | 출처를 분리한 자체 로그 자료 | 적합·부적합·미확인 판독, 잘못 제공하거나 놓친 항목 |
| 결과 예측 | 관측한 행동별 성과·비용 | 성공 확률의 Brier를 주 예측 지표로 두고 NLL·비용 오차·출처별 실패 양상을 보조 보고 |
| 실제 정책 | 같은 에이전트의 [SWE-bench](https://www.swebench.com/) 실행 | 공식 성공 제출률, 비용·시간·미제출·회귀 |
| 기억 은행 확장 | [MemDev-Bench](https://arxiv.org/html/2610.27524v1)의 설계 참고 | 관련·무관 이력이 섞인 조건과 시간상 유효한 경험 구성 |

SWE-bench Verified는 500개, Lite는 300개 과제다. 개발은 고정한 일부에서 시작하고 부분집합임을 표시한다. 외부 리더보드 점수를 우리의 무기억 기준으로 가져오지 않는다. MemDev-Bench는 과거 이력이 있는 코드 메모리 설계에 가깝지만 실제 배포 자료·환경의 확보는 도입 전에 확인한다. 관련성 주석은 기억의 실제 한계 효용 정답과 다르다.

학습 구성 A0/A1/B0/B1의 예측 비교와 Q0~Q3의 실제 정책 비교는 별개다. Brier는 관측된 행동의 성공 확률 오차를 재며, 관측하지 않은 개인별 효과의 정답 오차가 아니다. 예측 오차가 줄어도 선택한 기억과 실제 성과가 개선되는지는 정책 실행으로 확인한다. 입력이 바뀌면 근거 있는 정보를 더 준 효과인지, 같은 정보에서 학습법만 바꾼 효과인지 표시한다.

**문제 난이도만 잘 예측해도 Brier가 좋아질 수 있다.** 행동별 상수 예측, 현재 상태만 사용하고 후보를 제외한 예측, 후보 기억만 사용한 예측을 저렴한 대조로 둔다. 같은 그룹 분할·관측 행동 라벨로 전체 관계 특징 z와 비교한다. 상태와 기억의 짝을 바꾸는 검사는 점수 민감도 진단이며, 원래 실행의 성공 라벨을 새 짝의 결과로 재사용하지 않는다. [관련성 사전 성향 연구와 대조의 해석](ai-memory-selector-literature-review-2026-11-07.md#4-첫-비교에-더할-대조-무엇을-보고-맞히는가).

예측 확률·제공 임계값은 개발 자료에서만 조정하고 독립 평가에서는 고정한다. 제공·보류 비율과 전체 배정의 성과·비용을 함께 보고한다. 작은 고정 후보 실험에서는 전부 제공·전부 보류 정책도 대조한다. 교사 선호를 0~1로 정규화한 점수를 곧바로 성공 확률로 해석하거나, 적게 제공해서 오류 수가 줄어든 것을 선택 개선으로 단정하지 않는다.

### 최종 성과와 과정 지표를 구분한다

| 지표 | 정의와 해석 |
| --- | --- |
| 공식 성공 제출률 | 예산 내 실제 제출한 패치가 공식 성공한 실행 / 전체 배정. 주 성과 |
| 수정 도달 | 고정된 저장 시점까지 공식 통과 상태를 사후에 한 번이라도 관측. 실제 제출과 별도 |
| 제출 과정의 손실 | 중간 통과를 관측했지만 최종 성공 제출이 없는 실행. 정확한 최초 해결 시점은 아님 |
| 회귀 | 공통 검사에서 기존 통과 항목이 새로 실패. 저장·채점 불명을 무회귀로 세지 않음 |
| 비용과 시간 | 전체 배정의 청구·토큰·시간·모델 응답·도구 호출. 성공 사례만 골라 평균내지 않음 |
| 행동 변화 | 도구 부재·대체 명령·전제 확인·검사 범위. 성공의 원인을 입증한 지표와 구분 |
| 검색과 제공 | 필요한 근거가 은행→후보→최종 입력 중 어디에서 빠졌는지, 실제 전달량과 선택 비용 |

중간 패치는 고정 격자와 종료 시점에 미추적 파일까지 저장하고, 실행 후 별도 환경에서 평가한다. 공식 사후 채점 결과를 실행 중 에이전트에 전달하지 않는다. 정상 미제출과 확정 공식 실패는 주 성공 지표의 0이지만, 원래 `official_resolved=null` 등 원본 필드는 보존한다. 외부 중단·불완전 실행·채점 불명은 관측 실패로 구분하고 가능한 결과 범위를 보고한다.

### 비교 조건과 데이터 누출을 통제한다

- 기억 본문·출처 은행·후보 생성·작업 모델·제공자·도구·제공 위치·실행 한도를 고정하고 조건 순서를 섞는다. 제공자가 완전히 고정하지 못하는 모델·캐시 변동은 기록한다. 서로 다른 조건의 결과가 다음 조건의 기억에 들어가지 않게 한다.
- 출처·대상·과거/미래 관계로 자료를 분리한다. 평가 대상의 정답 패치·숨겨진 검사 결과·이후 로그를 선택 입력이나 기억 작성에 넣지 않는다. 훈련 실행의 사후 결과는 훈련 라벨로 사용할 수 있다.
- 선택기 입력 준비·추론·환경 확인 비용을 포함한다. 같은 작업 실행 한도 비교와 같은 총비용 한도 비교는 별도로 표시한다.
- 필요 근거가 후보에 없는 문제와 후보에서 잘못 고르는 문제를 분리한다. 평가용 정답 근거 위치는 진단에만 사용한다.
- 결과를 보고 임계값·집단·주 대비를 바꾸지 않는다. 새 가설은 발견 자료와 분리한 과제에서 확인한다. 실행 중 정책 갱신은 별도의 온라인 학습 실험으로 둔다.

주 대비, 최소 실용 효과, 중단 규모, 보조 지표와 다중 비교 규칙을 실행 전에 정한다. 공유 출처·대상과 공유 기준 실행의 의존성을 반영한다. 반복이 늘어도 출처 다양성이 늘지는 않는다. 소수 출처의 좁은 bootstrap 구간을 일반화의 보증으로 쓰지 않는다. 기존 [보수적 구간 구현](../experiments/swe_memory/scripts/bounded_effects.py)은 고정 사례·독립 실행 가정 아래의 도구다.

성과 차이가 유의하지 않다는 이유로 성과 보존을 선언하지 않는다. 비용 절감을 주장할 때는 사전에 정한 허용 성과 손실 범위를 함께 확인한다. 보조 판독 점수가 좋아도 최종 성과가 그대로면 그 범위까지만 보고한다.

## 부록 A 이득과 손해의 통계적 해석

### 상황별 평균 기여

먼저 공개 문제·기반 코드·출처 근거만으로 적용 상황 g를 정하고, 각 집단의 평균 기여 `δ_g`와 구간을 보고한다. 예를 들어 과정 정보의 적용 가능성이 확인됨·맞지 않음·불명인 집단이다. 구체적 수정법, 일반 원리, 과정 정보의 적용 가능성은 별도 필드로 둔다.

충분한 자료가 쌓이면 다음과 같이 **집단 평균에서의 양·음 기여**를 정의할 수 있다.

```text
G_group = Σ_g w_g max(δ_g, 0)
H_group = Σ_g w_g max(−δ_g, 0)
Δ = G_group − H_group
```

**합성 예시:** 대상의 절반에서 +20%p, 다른 절반에서 −10%p라면 `G_group=10%p`, `H_group=5%p`, 순효과는 +5%p다. 이는 평균이 상쇄하는 효과를 드러낸다. 집단을 어떻게 나누는지에 따라 G와 H도 바뀌므로 집단 정의와 가중치를 함께 남긴다. 개별 실행의 10%가 도움받고 5%가 피해받았다는 뜻은 아니다.

관측한 차이를 곧바로 양수·음수로 잘라 더하면 두 값이 모두 과대 추정될 수 있다. 다음은 **모든 사례의 진짜 효과가 0이고, 양쪽 성공 확률이 0.5인 독립 이항 실행**을 정확히 열거한 계산이다. 실제 로그의 추정 결과가 아니다.

| 조건별 반복 수 | 진짜 G와 H | 관측 차이의 양수 부분 평균 | 관측 차이의 음수 크기 평균 |
| ---: | ---: | ---: | ---: |
| 2 | 각각 0%p | 18.75%p | 18.75%p |
| 6 | 각각 0%p | 약 11.28%p | 약 11.28%p |

반복 수 R에서 표의 양수 값은 `Σ_a Σ_b max((a−b)/R,0) × C(R,a) × C(R,b) / 2^(2R)`로 계산했다. **첫 결과표에서는 G/H 합계를 주 결과로 쓰지 않고, 사전에 정한 집단별 부호 있는 차이와 불확실성을 제시한다.** 결과를 보고 집단을 발견했다면 별도 출처·대상에서 그 집단 정의를 고정해 확인한다. 이는 집단을 발견하는 자료와 효과를 추정하는 자료를 나누는 [Athey와 Imbens의 honest estimation](https://pmc.ncbi.nlm.nih.gov/articles/PMC4941430/) 원칙을 이 실험에 적용한 제안이다.

### 개별 실행의 이득률과 피해율

같은 잠재 실행에서 비교 입력 C의 결과 Y0와 C+u의 결과 Y1을 동시에 안다면 `P(Y0=0,Y1=1)`과 `P(Y0=1,Y1=0)`을 셀 수 있다. 전체 기억 효과를 볼 때는 무기억·기억 조건을 비교한다. 현재 API 실행은 그 두 결과를 함께 관측하지 못한다. 같은 반복 번호나 seed 값만으로 동일한 숨은 난수·서버 상태가 재현된다고 볼 수도 없다.

진짜 주변 성공률이 p0와 p1일 때, 추가 가정 없는 범위는 다음과 같다. [Tian과 Pearl §4.2.2](https://ftp.cs.ucla.edu/pub/stat_ser/r271-A.pdf)의 이진 반사실 확률 경계와 같은 형태다.

```text
max(0, p1−p0) ≤ 개별 이득률 ≤ min(p1, 1−p0)
max(0, p0−p1) ≤ 개별 피해율 ≤ min(p0, 1−p1)
```

가령 p0=0.4, p1=0.6을 정확히 알아도 이득률은 0.2~0.6, 피해율은 0~0.4까지 가능하며 두 값의 차이는 0.2다. 관측 비율을 이 식에 넣은 값은 통계적 신뢰구간이 아니다. 피해가 없다는 가정을 넣어 한 값으로 만들면 이 연구가 확인하려는 손해를 처음부터 배제하게 된다. 현재 실험에서는 개별 전환 횟수를 진단으로만 남기고, 확정적인 유익·유해 학습 라벨로 사용하지 않는다.

### 조각끼리의 상호작용

E를 환경 관측, V를 검사 절차·검증 근거로 나누면, S를 공통으로 둔 네 조건으로 다음을 잴 수 있다.

```text
E의 기여, V 없음 = p(S+E) − p(S)
E의 기여, V 있음 = p(S+E+V) − p(S+V)
상호작용 I      = p(S+E+V) − p(S+E) − p(S+V) + p(S)
```

두 조건부 기여가 다른 이유를 상호작용으로 표현한다. 하나씩 삭제한 효과들을 더해 전체 순효과라고 보고하지 않는다. Shapley는 여러 조합에서의 기여를 하나의 배분 규칙으로 합치는 후속 선택지다. [Data Shapley](https://proceedings.mlr.press/v97/ghorbani19c.html)는 학습 데이터 가치에 이 접근을 사용하지만, 배분 규칙 자체가 기억의 유일한 인과 원인을 정해 주지는 않는다. 상호작용을 조사하는 후속 회차에서는 E/V처럼 해석 가능한 두 묶음의 네 조건부터 직접 비교한다.

## 부록 B 보존 가치와 비용 계산

운영 비용은 실제 모델 청구, 도구 실행, 선택기 추론을 중복 없이 합산한다. 모델 입력으로 읽은 기억 토큰은 이미 청구에 포함되므로 다시 더하지 않는다. 출처 수집·작성·색인·갱신 비용은 별도로 기록하고 재사용 횟수에 따라 배분한다. 공식 사후 채점 비용은 연구 평가 비용으로 구분한다. 측정하지 못한 인력·인프라 비용을 0으로 적지 않는다.

단순한 손익 민감도는 다음처럼 계산할 수 있다.

```text
K회 제공의 예상 순가치
= K × (v × 평균 성공확률 기여 − 평균 추가 실행비용)
  − 추가 작성·색인비용 − 보관·갱신비용(K)
```

v는 성공 1건의 가치이며 달러 단위를 사용한다. K는 실제 제공·재사용 횟수다. 미래 과제 분포와 사용 방식이 일정하고 검색 경쟁 효과를 무시한다는 가정의 계산이다. v와 K를 여러 값으로 바꿔 보여주며, 임의의 한 값을 넣어 기억의 고유 점수로 만들지 않는다. 실험용으로 출처 경험을 새로 수집했다면 그 비용까지 포함한 결과와, 업무 중 이미 생긴 경험을 재사용하는 증분 비용 결과를 구분한다.

이 식은 선택·저장 정책의 실측을 대신하지 않는다. 실제 보존 정책의 가치를 확인할 때는 은행에 u가 있는 경우와 없는 경우의 미래 과제열을 같은 규칙으로 비교하고, 다른 기억의 검색·노출 변화도 비용과 성과에 포함한다.

## 부록 C 효용 학습과 예산 제약의 추가 문헌

다음 표는 대화 중 검토한 2026년 프리프린트 판본과 그 범위다. 논문의 실험 과제와 우리의 실제 코드 실행을 구분하며, 보고된 효과를 우리 선택기의 기대 개선 수치로 가져오지 않는다.
