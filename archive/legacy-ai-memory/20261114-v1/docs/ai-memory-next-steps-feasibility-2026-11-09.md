# 메모리 득실 연구의 다음 세 단계: 실행 가능성 점검

2026-11-09. 최신 방향은 **어떤 기억이 어떤 상황에서 득·실을 만드는지 측정하고 설명·예측하는 것**임. 상태를 고려한 선택 모델은 이를 검증하는 한 방법이며 전체 연구의 핵심 질문으로 확정하지 않음. 기존 자료·코드와 공개 원문을 확인해 순서·산출물·진입 조건을 정하고, 후속으로 근거 주석·입력 분리·검증 코드를 구현함. 새 학습·작업자 실행·GPU 할당·확정 학습 데이터 편입은 하지 않았음.

권장 순서는 **새 출처의 근거와 과제 정합성 확인 → 제공/미제공의 실제 결과 수집 → 득실 예측과 선택 학습**임. 현재 부족한 것은 단순 행 수보다 신뢰할 수 있는 새 경험과 그 경험을 제공했을 때의 실제 결과임.

## 1. 새 출처에서 비교할 상황 확보

### 첫 후보와 역할

[Mem2ActBench](https://github.com/Cantaloupe-M/Mem2ActBench)는 과거 대화에서 현재 도구 호출 인자를 구성하는 자료이므로 첫 외부 행동 적용 후보로 검토할 만함. 여러 원천 대화를 재구성하고 QA를 생성한 벤치 자료이며, 저장된 tool 응답이 실제 외부 서비스의 실행 성공을 보장하는 것은 아님. 원문을 대조하니 **구조 검사만 통과한 자료를 바로 학습에 넣을 수 없음**. 먼저 의미 검토를 수행하는 조건부 후보로 둠.

[LongMemEval](https://github.com/xiaowu0162/LongMemEval)은 갱신·시간·보류를 포함한 질문과 근거 세션이 있어 별도 외부 검색·답변 평가 후보로 보존함. 이는 도구 실행 성공 평가와 구분함. [PersonaMem-v2](https://github.com/bowen-upenn/PersonaMem-v2)는 합성 사용자별 암묵 선호를 제공하므로 이후 학습 원천 확장의 대안임. 사용자 단위 분할과 원문 근거 검토를 거친 뒤 사용하며, 이번에는 편입하지 않음. 세 자료를 처음부터 한 정답 체계로 합치지 않음.

### Mem2Act 원문 점검에서 확인한 준비 수준

고정 commit `c935c65be9aa19c930b60657c0c4b2b7ea13a34a`의 소형판 400 QA와 429세션을 읽었음. 공개 Git blob ID, 구조 집계, 표본 검토 범위는 [확인 기록](reports/data/memory-next-steps-20261109/source-inspection.json)에 있음.

| 확인 항목 | 결과·의미 |
| --- | --- |
| 과거 원문 ID 연결 누락 | 12 QA에 영향. 원문 연결을 복구하거나 격리해야 함 |
| 도구 이름과 schema 불일치 | 1 QA. 이름 교체만으로 해결할 수 없는 의미 문제도 발견됨 |
| 출처 ID·근거 chain이 모두 비어 있음 | 7 QA. 기억에 근거한 정답이라는 주장을 별도 검토해야 함 |
| 위 구조 조건을 제외하고 남는 검토 후보 | 380 QA. 유효한 학습 사례 380개라는 뜻은 아님 |
| 같은 원본 세션을 공유하는 QA를 연결한 묶음 | 잠정 343개. 전체 은행 공유·도구/표현 유사성까지 해소된 독립 표본 수는 아님 |

추가로 유형별 4개씩 16문항의 질문·도구·생성 주석을 읽고, 5문항은 일부 관련 원문 대화까지 확인했음. 이는 오류율 추정용 무작위 표본이나 전체 의미 검수가 아님.

- `qa_283`: 현재 차량 시동 요청에 꿈풀이·행운 번호 도구를 정답으로 연결함. 확인한 원문은 실제로 `VehicleControlAPI.startEngine` 호출을 포함함. 숫자인 도구 이름을 문자열로 바꾸는 것만으로 복구할 수 없음.
- `qa_399`: 출처가 없으며 정답 주석 자체가 책 분류 정보 부재에도 fallback ID를 사용했다고 기록함. 이를 근거 기반 양성으로 학습하면 추측을 정답으로 배우게 됨.
- `qa_025`: 확인한 두 원문에 여러 event ID가 있는데 현재 요청은 특정 행사 하나를 구별하지 않음. 정답이 하나로 정해지는지 다시 검토해야 함. 출처가 둘이라는 사실만으로 여러 기억을 결합해야 하는 문제라고 볼 수 없음.
- `qa_400`: 원문 식별자 `tt1375666`을 수치로 바꾼 정답임. 해당 대상 API의 변환 계약이 관측되지 않아 자동 정규화로 처리하지 않음.

위 내용은 [고정 QA 파일](https://github.com/Cantaloupe-M/Mem2ActBench/blob/c935c65be9aa19c930b60657c0c4b2b7ea13a34a/Mem2ACTBench_small/qa_dataset.jsonl)과 [과거 대화 파일](https://github.com/Cantaloupe-M/Mem2ActBench/blob/c935c65be9aa19c930b60657c0c4b2b7ea13a34a/Mem2ACTBench_small/Mem2ACT_conversation.jsonl)의 대조에 근거함. 공식 파일을 덮어쓰지 않고 우리 사용 범위에서의 보류·제외·수정 사유를 보존함.

### 실제 수집 절차

1. 원본 세션과 이를 참조하는 질문을 연결한 뒤, 같은 세션을 공유하는 질문 전체를 같은 분할에 둠. 기존 분할 이름이나 QA 수를 독립 경험 수로 간주하지 않음. 전체 은행을 모든 분할에서 공유한다면 새 은행 전이가 아닌 공유 은행의 새 질문 평가라고 명시함.
2. 원문 근거·현재 요청·정답 행동이 일치하는지를 확인함. 생성된 `evolution_chain`·`grounding_info`는 검토 보조 자료이며 원문을 대신하지 않음. 유일하지 않은 답은 허용 답 집합이나 미확정으로 보존하고 임의로 하나를 고르지 않음.
3. 과거 대화·완결된 도구 호출/응답을 기준으로 기억 단위를 나눔. 현재 정답을 보고 풀이를 추가한 요약은 만들지 않음. 일반 검색 은행에는 정답 근거뿐 아니라 같은 분할의 원래 기록을 포함하며, distractor를 추가할 때도 분할을 넘겨 가져오지 않음.
4. 각 원천에서 가능한 대조만 구성함. 필요한 정보가 현재 관측에는 없음 / 현재에 이미 있음 / 현재의 명시적 요구·조건이 과거와 달라짐을 구분함. 조건을 바꾼 경우 정답을 다시 확인하고, 자연 기록과 통제 변형을 따로 표시함. 실제 실패가 없는 사례에 실패 서사를 덧붙이지 않음.
5. 먼저 **20–30개 출처 묶음의 제작·판정 가능성**을 점검함. 이는 모델 일반화를 주장할 학습 규모가 아님. 검수 수율·원천 다양성을 확인한 뒤 독립 출처를 확대하며, 같은 사례를 여러 표현으로 늘린 수는 별도로 셈.

첫 산출물은 원천–과거 기억–현재 관측–근거 위치–적용 조건–허용 정답–분할–미확정 사유를 연결한 검토표임. 처음부터 모든 사례를 득/실로 라벨링하지 않음. 구조 조건을 통과한 후보가 적거나 의미 주석이 불안정하면 모델 학습보다 수집 대상·과제 정의를 먼저 조정함.

## 2. 실제 기억 제공 효과 측정

원문과 정답이 검토된 자료에서 고정 작업자의 결과를 수집함. 첫 외부 실험의 결과는 **도구 호출 인자 정확도와 오류·비용**으로 한정하고, 실제 외부 서비스의 작업 완료라고 부르지 않음. 제공 schema가 목표 도구 하나뿐이면 도구 선택 정확도 자체는 주 지표로 삼지 않음. 환경에서의 최종 성공은 이후 별도 실행 가능한 과제로 확인함.

### 먼저 고정할 것

- 작업자 모델·revision·생성 설정, 현재 목표와 도구 schema, 기억 저장소, 선택 시점, 채점 규칙을 고정함. 기존 9B 작업자를 재사용할 수 있으나 새 과제의 프롬프트·출력 길이·파서는 train의 실행 점검 후 별도로 동결함.
- 공통 기억 전달 상한을 둠. 기존 512토큰을 초기 검토값으로 삼되 원문 단위·필수 근거 길이를 확인한 뒤 실행 전에 정함. 작은 묶음·보류도 허용하고, 잘림이나 예산 때문에 근거가 사라진 경우를 기록함.
- 현재 관측은 모든 정책이 동일하게 받음. 기억을 받은 뒤 생긴 명령·실패를 선택 전 관측으로 소급하지 않음. 선택기 입력만 줄이는 제거 비교에서도 작업자에게 제공하는 현재 상태는 동일하게 유지함.

### 첫 비교와 기록

주 비교는 무기억과 기본 검색으로 제공한 기억임. 적용 조건 규칙이 정의되는 사례에서는 규칙 선택도 포함함. 검토자가 찾은 근거 제공, 가까워 보이지만 조건이 다른 기억, 근거 조각 삭제는 **원인을 점검하는 진단 조건**으로 구분함. 정답 근거를 사용한 선택을 실제 검색 정책과 같은 조건이라고 비교하지 않음. 어떤 조건도 효과가 0이거나 반드시 유해하다고 미리 정하지 않음.

같은 사전 상태에서 제공/미제공을 짝지어 실행하고 개선·악화·둘 다 성공·둘 다 실패를 기록함. 성공 외에 근거 없는 인자 추측, 현재 조건 위반, 잘못된 보류, 토큰·시간·선택 비용을 분리함. 전체 묶음의 효과를 구성 기억 각각의 효과로 복사하지 않음. 작업 중단·파싱 실패·미측정은 별도 상태로 보존함.

규모 계산 예시는 20개 출처 묶음 × 가능한 3개 상태 × 최대 4개 제공 조건 = 최대 240개 배정임. 반복 실행은 추가이며, 동일 입력의 재사용은 별도 집계함. 이는 실행 예산을 계산하는 예시이지 충분한 검정력을 보장하는 표본 수가 아님. 실제 GPU 시간은 토큰 길이와 소수 실행의 처리 시간을 본 뒤 산정함.

다음 단계에 들어가기 전에 입력 재현·정답 판정·누락/실패 보존이 확인되어야 함. 득실 차이가 한 출처에만 몰리거나 모든 제공 정책의 결과가 같다면, 현재 자료로 선택 모델의 가치를 구분하기 어렵다는 결과를 보고함. 효과가 크게 난 사례만 남겨 검증 집합을 만들지 않음.

## 3. 득실 예측에서 학습한 선택으로 연결

### 첫 학습의 입출력

- 입력: 선택 직전의 현재 요청·관측과 제안된 기억 묶음.
- 감독: 같은 상태에서 실제 관측한 제공/미제공 네 결과와 오류·비용. 관계·근거 주석이 검토되면 별도 보조 감독으로 추가함.
- 행동: 우선 모든 모델에 공통으로 주어진 후보 묶음 중 하나 또는 보류를 선택함. 평가 시점에 실행하지 않은 묶음을 골랐다면 별도 작업자 실행이 필요함.

이 제한된 행동 집합은 임의의 기억 조합을 모두 탐색하는 선택기와 구분함. 처음부터 개별 기억에 묶음 효과를 붙여 검색 정답으로 바꾸지 않음. 후보 묶음 생성은 결과를 보기 전에 고정하고 정답을 강제로 후보에 넣지 않음.

### 최소 비교

1. 검색·명시적 규칙·현재 정보만 보는 예측을 기준선으로 둠. 과제 난이도만으로 득실 라벨을 맞히는지 확인함.
2. 첫 통제 비교는 같은 0.6B 시작 모델·판독 구조·학습 방식에서 목표만 / 목표+현재 관측으로 둠. 데이터·후보·행동·학습 노출·개발 선택 규칙은 유지함. 진행·실패 기록이 실제 있는 자료에서만 해당 신호의 제거 비교를 추가함.
3. 이후 같은 입력·단위 표현에서 단순 집계/MLP와 집합 상호작용층을 비교하고, 고정 encoder와 LoRA의 비교는 별도 축으로 수행함. 첫 비교부터 입력·판독층·encoder 업데이트를 동시에 바꾸지 않으며 기존 checkpoint는 보존함.
4. 기본 학습·입력 비교가 작동하면 같은 상태의 묶음 순위 학습이나 검토된 관계 감독을 하나씩 추가함. 오류·비용이 상충하는 두 묶음에 보편적 우열을 강제하지 않음. 상태 입력을 추가하면서 모델 길이 제한 때문에 후보나 근거가 잘리는지도 사전에 검사함.
5. 4B·9B 비교에서도 **선택기만 변경**하고 작업자·후보 묶음·전달 예산을 유지함. 모델이 선택한 ID, 파싱 실패, 전체 선택 비용을 기록함.

관계 판독 성적, 실제 결과 예측 성적, 선택 후 작업 성공·악화를 각각 보고함. 새 출처 평가는 학습·설정 선택과 분리함. 같은 원천의 많은 변형이나 반복을 독립 표본으로 세지 않음. 예측 점수가 높아도 선택 성능이 기본 검색과 같다면 그 한계를 그대로 보고함.

## 동료 제안 검토: 충분성과 실제 득실을 두 축으로 유지함

현재 부족한 근거를 찾고 이를 채우는 기억 묶음을 배우자는 제안은 채택할 가치가 있음. 원래 득실 연구에서 선택 실패와 활용 실패를 분리하고, 선택 이유를 검산하는 데 유용함. 다만 **충분성 판독을 전체 목표나 실제 득실의 대리 정답으로 바꾸지 않음**. 아래는 후속 설계 의견이며 새 학습 설정을 동결하거나 실행한 결과는 아님.

### 제시된 숫자 검산

기존 `original` 작업자 조건에서 두 지정 참조가 공통 은행 또는 현재 관측에 있는 72상태를 재집계했으며 제시된 표와 일치함. 72상태는 기존 12개 계획 계열에서 파생됨. [원본 해시·상태별 집계·짝 비교](reports/data/memory-next-steps-20261109/sufficiency-review.json)를 보존함.

| 정책 | 지정 참조 전체 확보 | 작업 성공 |
| --- | ---: | ---: |
| 학습 검색 top4 | 72/72 | 51/72 |
| 학습 검색 top2 | 70/72 | 55/72 |
| 참조 규칙 rule2 | 72/72 | 55/72 |

주의할 해석은 다음과 같음.

- 현재 관측을 포함한 지표이므로 무기억도 24/72의 참조를 이미 확보함. 선택기의 기여는 현재에 없던 근거를 얼마나 추가했는지도 나눠 봐야 함.
- 현재 코드는 지정된 기억 ID가 전달됐는지를 확인함. 이는 기록 단위 확보 지표이며, 새로운 과제의 사실·시점·대체 근거까지 검증한 의미적 충분성과 같지 않음.
- top4에서 top2로 바꾸면 5상태 개선·1상태 악화임. 참조를 놓친 2상태는 모두 실패함. 따라서 근거를 덜 확보했기 때문에 좋아졌다고 해석할 수 없음. 선택된 내용·개수·길이·위치가 함께 달라진 관측 효과임.
- rule2와 현재 중복을 보류하는 state_rule은 각각 55/72이지만, 서로 비교하면 1상태 개선·1상태 악화가 있음. **정보가 중복된다는 주석과 실제로 불필요하거나 유해하다는 효과는 구분해야 함.**

현재 top4는 이 지표에서 이미 72/72이므로 기존 자료만으로 충분성 판독층이 근거 확보를 개선하는 가치를 입증하기 어려움. 이 자료는 같은 근거 확보 수준에서 제공 내용·양에 따른 작업자 반응을 진단하는 데 사용하고, 충분성 학습의 주 검증에는 근거 결합과 실제 부족이 다양한 새 출처가 필요함.

### 제안을 반영할 때의 다섯 가지 수정

1. **독립적으로 만들 것은 근거·관계·충분성 주석임.** 작업자가 실패했다고 근거를 음성으로 바꾸지 않음. 동시에 최종 제공 정책을 학습하는 실제 개선·악화 라벨도 보존함. 부분적인 단서나 이미 알려진 정보의 재제시가 절차 수행·판독·비용에 도움이 될 가능성을 충분성 기준만으로 배제하지 않음.
2. **충분성을 현재 관측과 묶음의 결합에 대해 판단함.** 현재에 이미 있는 사실·중복·서로 모순된 사실·대체 가능한 근거를 확인함. 지정 참조 하나가 빠졌다고 자동 불충분으로 만들지 않음. 판정하기 어려운 경우 미확정으로 남김. 정답 근거 제공은 진단 조건이며 작업자 성능의 이론적 상한이 아님.
3. **진짜 결합과 단순한 여러 답 모으기를 구분함.** 현재 여행 자료의 식사·숙소는 두 독립 출력을 채우는 성격이 강함. 하나의 판단에 A와 B가 함께 필요한 사례를 확보하고 A/B/A+B를 각각 검토함. 개수·토큰 길이·원천·표현 단서만 사용하는 기준선을 추가함. 정책 비교의 공통 토큰 상한과, 학습 편법을 확인하는 길이 통제 진단은 별개임.
4. **누락의 위치도 구분함.** 현재 관측에는 없지만 후보에 있음 / 은행에는 있으나 후보에 없음 / 은행에도 없음 또는 확인 불가를 나눔. 마지막 두 경우를 묶음 판독층만으로 해결할 수 없음. 누락 출력에는 요구 항목, 확인한 관측 범위, 이미 확보한 근거 ID를 연결함. 존재하지 않는 사실의 span을 만들거나 정답 요구 목록을 추론 입력으로 제공하지 않음.
5. **첫 학습에서 바꾸는 축을 하나로 제한함.** 주석이 준비되면 같은 모델·묶음 판독 구조·학습 목표·노출·후보·예산으로 목표만 / 목표+현재 관측을 비교하는 안에 동의함. 작업자 관측은 두 조건에서 동일함. 이 차이만으로 학습 선택기의 필요성이 증명되지는 않으므로, 관측 가능한 상태를 쓰는 규칙과 검색도 비교함. 이후 같은 단위 표현의 단순 집계/MLP와 집합 상호작용층, 고정 encoder와 LoRA를 순차적으로 비교함. 실제 진행·실패 이력이 없는 현재 자료에 그 이름을 붙이지 않음.

다음 제작 표에는 `요구 항목 → 현재 확보 여부 → 후보별 보충 근거 → 묶음의 충분/부족/미확정`을 추가하는 것이 적절함. 이는 원문 검토와 관계 주석이며 실제 득실 측정을 대체하지 않음. 선택 지표는 새로운 근거 확보·중복·잘못된 충분 판정·보류를, 작업 지표는 성공·오류·비용을 각각 기록해 연결함. 새 확인 자료는 방법을 정하기 전에 출처 단위로 분리함.

## 제안 반영 후 완료한 보완

- [근거 평가용 보조 자료](../datasets/memory_decisions/20261109-evidence-v1/README.md)를 추가함. 기존 96상태·333관측 묶음에서 지정 기록의 위치·새로 보충한 기록·현재 중복을 계산함. **의미적 충분성은 자동으로 채우지 않고 모두 `null`로 보존함.** 원본 입력·성공·오류·비용·해시는 변경하지 않음.
- [주석 검사기](../data_pipeline/memory_evidence_review.py)는 요구별 실제 인용, 적용 조건, 대체/결합 근거, 확인한 범위와 미확정 상태를 다룸. 원문에 없는 인용·허용 은행 밖의 근거·미래 기억·존재하는 지지 근거를 없다고 하는 내부 모순·임시 주석의 자동 정답 승격을 거부함. 의미적 함의의 자동 검증기는 아님.
- [검토 예시 8건](design-data/memory-evidence-review-20261109-v1/README.md)을 기존 첫 계열의 원문에서 작성함. 독립 검수가 아닌 AI 초안이며 확정 학습 라벨 0개임. A만/B만 제공한 두 진단 묶음의 실제 효과는 미측정으로 유지함. 같은 요구의 근거가 현재/선택 묶음/후보/허용 은행 어디에 있는지 구분할 수 있게 됨.
- 목표만 / 목표+현재 관측 렌더러를 구현함. 두 조건의 후보와 순서는 같고 작업자의 현재 문맥은 변하지 않음. 672개 기존 정책 행에 연결된 프롬프트를 원본과 대조함. 당시에는 학습 비교 전이었으며, 이후 수행한 [24개 학습·선택 비교 결과](reports/2026-11-09-memory-state-ablation.md)에서 득실 예측의 개선과 실제 성공의 미개선을 구분해 확인함.
- **후보 수만으로 삭제 조건을 구별하는 편법을 확인함.** 삭제 조건은 25·43·61개, 나머지는 27·45·63개여서 `후보 수 % 3 == 0`으로 지정 기록 존재 여부를 96/96 구별함. 사후 설계 진단이며 의미적 충분성 성능이 아님. 새 충분성 자료에는 개수·길이 통제와 대체 근거 검토를 추가해야 함.
- 관련 테스트 57개가 통과함. 공유 대상 파일만 복사한 별도 환경에서도 동일 검사와 원본 재현이 통과함. 입력 재현, 라벨 유입 방지, 근거/결과 분리, 현재/후보/은행 범위, 원문 span, 미측정 보존과 기존 정책 지표 유지를 확인함. 재현 명령과 파일 해시는 각 자료 README·manifest에 기록함.

이 보완은 잘못된 학습 신호와 평가 해석을 줄이는 기반임. 데이터 부족·새 출처 전이·실제 선택 성능의 해결 결과는 아님. 다음에는 위 검토 형식으로 새 출처의 의미를 확인한 뒤 공통 작업자에서 실제 득실을 확보함.

## 다음 작업의 우선순위와 자원

바로 수행할 일은 **외부 후보의 의미 검토표·출처 분할·짝지은 실행 명세를 만드는 것**임. 기존 관계 자료 91개를 전부 확정해야 시작할 수 있는 작업은 아님. 다른 에이전트의 초안과 이번 정정은 구분하고, 불명확한 라벨은 미확정으로 둠.

원문 연결·의미 검토·분할·실행 명세는 CPU와 문서 검토로 진행할 수 있음. 작업자 결과 수집과 encoder/LoRA 학습 단계에서만 Colab을 할당함. 기존 컨트롤러의 시간 상한·산출물 회수·세션 종료를 재사용하되 새 입력과 결과 형식의 검증을 먼저 추가함. 이번 점검에서는 새 자원을 할당하지 않았음.

현재 원본 근거가 확실한 후보 수와 실제 효과 분산을 알기 전에는 대규모 학습 수량·GPU 시간·일반화 가능성을 확정하지 않음. 첫 수집에서 사용할 수 있는 사례가 얼마나 남는지와 어떤 조건에서 결과가 달라지는지를 확인한 뒤 확대 규모를 정함.
