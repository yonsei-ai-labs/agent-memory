# 새 문제군에서의 일반화 검증안

2026-11-09. 현재 동결 모델의 검증 방법을 정리한 제안이며 새 평가 결과가 아님. [준비된 새 문제군 파일럿](ai-memory-travel-state-transfer-2026-11-09.md)을 읽고 보완점을 정리함. 진행 중인 생성·실행 코드와 고정 입력은 변경하지 않음.

## 먼저 확인할 두 질문

1. **그대로 옮겨도 찾는가:** 기존 검색 LoRA와 관계 판독기를 재학습하지 않고 새 문제군에 적용함. 이는 현재 모델의 전이 평가임.
2. **찾은 기억이 실제로 돕는가:** 같은 상태에서 제공·보류의 성공·악화·비용을 비교함. 새 효용 head를 학습한다면 그 결과는 별도의 적응 실험으로 보고함.

새 자료로 학습한 성적과 동결 모델의 성적을 같은 전이 결과로 합치지 않음. 검색 정답·실제 효용 정답도 별도로 유지함.

## 새 출처의 범위

| 단계 | 확인할 내용 | 현재 자료의 위치 |
| --- | --- | --- |
| 새 문제군 | 기존 요청·기본 계획과 겹치지 않는 여행 사례 | 공개 validation 기반의 120개 경로·기간 문제군이 준비됨 |
| 새 이력·표현 | 실제 생성한 과거 선택, 달리 쓴 질문·기록 | 실제 과거 생성은 현재 파일럿의 대상. 다른 표현은 별도 고정 대조가 필요함 |
| 다른 환경·도메인 | 공유 카탈로그·문장 틀 밖에서도 같은 관계 판단이 되는가 | 별도의 후속 평가로 남김 |

같은 여행 도메인의 새 경로·기간과 다른 출처/도메인 일반화는 구분함. 공개 원본의 파일 이름만 다르거나 기존 문장을 바꿔 쓴 것은 독립 출처 수를 늘리지 않음. 기반 모델의 사전학습 노출까지 없다는 주장도 하지 않음.

## 현재 준비안에서 유지할 점

- 기존 공개 train과 요청·경로/기간이 겹치는 행을 제외하고 120문제군을 60/20/40으로 묶은 분할을 유지함.
- 첫 12문제군은 train의 실행·채점 파일럿임. 그 결과를 새 test 일반화 성적으로 보고하지 않음.
- 실제 worker의 과거 선택을 사용하고, 틀린 과거 선택을 공개 정답으로 바꾸지 않음.
- 필요한 정보가 과거에만 있음 / 현재에도 보임 / 현재 가용성이 달라짐 / 참조가 없음의 네 상태를 유지함.
- none·all·fixed·learned·rule·state_rule 비교를 유지함. all은 별도 전체 기억 비용 기준선임.

## 추가로 통제할 난이도 차이

기존 전체 질문 검색은 은행 26–336개·참조 1–12개·최종 10개였음. 새 상태 과제는 은행 27/45/63개·참조 2개·최종 최대 4개/512토큰임. 따라서 새 성적을 기존 92%와 직접 비교해 전이 성공이나 실패를 판단하지 않음.

특히 **3일형 은행은 27개여서 32후보가 은행 전체를 포함함.** 이 조건은 판독·활용은 평가하지만 후보 검색 누락을 충분히 시험하지 못함. 45·63개 은행과 `은행 크기 > 후보 한도` 조건을 따로 보고함. 64후보는 새 과제의 은행 전체를 포함하므로 역할도 명시함.

저장된 전체 순위·점수를 사용해 기존과 같은 32후보·최종 10개의 검색 진단도 별도 산출할 수 있음. 실제 제공 정책의 4기록/512토큰 결과와 섞지 않음. 기존 자료의 같은 은행 크기·참조 수 조건도 결과와 무관한 규칙으로 묶어 참고함. 더 큰 은행을 추가할 때는 별도 버전에서 실제 이전 기록을 사용하고, 무관한 기록을 섞는 과정에서 인물·날짜의 의미가 모호해지지 않게 함.

## 고정 순서

1. **모델·비교 고정:** 실제 검색/판독 checkpoint와 해시, 입력 형식, 라이브러리·정밀도·배치 방식, 후보·전달 예산을 기록함. 학습 hybrid를 주 방법으로 유지하거나 dense를 포함할 기준을 dev에서 정하고 test 전에 고정함.
2. **train 파일럿:** 첫 12개에서 입력 전달·과거 기록 복원·정답 집합·UNKNOWN/NONE·현재 가용성·비용 집계가 맞는지 확인함. 효과가 좋은 가족만 남기지 않음.
3. **dev 설정:** 20문제군에서 필요할 경우 전달 개수·보류 정책과 실행 방식을 정함. 학습을 추가했다면 동결 전이와 별도 조건으로 등록함. dev의 문제군별 차이 분산으로 표본 정밀도·예산을 점검하고 평가 개수를 test 실행 전에 확정함.
4. **test 확인:** 고정한 40문제군에서 모든 비교를 수행함. 운영상 나눠 실행하면 분할·순서·시간 상한을 미리 고정하고 결과가 좋은 부분만 보고하지 않음. test를 본 뒤 설정을 바꾸면 해당 회차는 탐색으로 보존하고 다음 확인은 새 자료에서 함.

기존 판독 확률은 실행 구성 사이에 큰 차이가 난 쌍이 있었음. 이전 dev 임계값을 그대로 옮기지 않음. 기존 dev의 동일 입력 호환 검사와 새 dev에서의 배치/패딩 안정성 검사를 구분하고, 현재 비교 정책에는 같은 입력·점수를 사용함.

## 무엇을 성공으로 볼까

| 질문 | 주 비교·지표 | 판정의 범위 |
| --- | --- | --- |
| 새 문제군에서도 검색 학습이 도움이 되는가 | 같은 후보·전달 예산의 learned−fixed, 참조 Recall·전체 참조 포함률 | 평균·문제군별 차이·악화 수와 문제군 단위 불확실성 보고 |
| 큰 후보를 읽는 것보다 이점이 있는가 | learned 32와 fixed 64 또는 전체 은행, 품질·실제 시간·토큰 | 더 작은 은행에서는 64가 전체 검색이라는 점을 명시 |
| 작업 성공으로 이어지는가 | learned 제공과 none·검색·규칙·현재 관측 규칙, 두 선택 동시 성공 | 제공의 순이득과 악화를 함께 보고함 |
| 어떤 조건에서 달라지는가 | 네 현재 상태별 개선/악화, 참조 전달 여부·검증 위반·보류 | 관계 점수를 득실 확률로 대신하지 않음 |

‘새 자료에서 90% 이상’ 같은 절대 문턱보다 **같은 새 문제에서 기준선 대비 얼마나 나아졌는지**가 주 판단임. 실용적으로 필요한 최소 개선과 허용할 비용/악화 기준은 test 전에 정함. 차이 구간이 넓거나 0을 포함하면 결론은 미확정으로 남기며, 불리한 평가를 버리고 다시 선택하지 않음.

독립 단위는 test의 40문제군임. 두 요청·네 상태·여섯 정책의 행 수를 40개보다 많은 독립 출처로 세지 않음. 도시·카탈로그가 공유되므로 도시별 민감도도 참고할 수 있음. 여러 학습 seed는 별도 안정성 축이며 같은 문제 반복이 새 출처를 늘리지는 않음.

무효 과거 출력·실행 실패·timeout은 배정과 함께 보존하고 유효한 이력만의 보조 집계를 구분함. 답이 없는 NONE과 근거가 없는 UNKNOWN, 우연히 맞은 구체적 답과 근거에 기반한 성공을 나눔. 추측이 맞았다는 이유로 주 결과를 사후 재채점하지 않음.

## 마지막 연결

첫 확인은 **동결 검색/판독기가 새 문제군에서 기준선 대비 효과를 유지하는가**임. 그다음 같은 기록을 제공·보류했을 때의 실제 득실을 확인함. 이후 공유 문장 틀·카탈로그 밖의 자료에서 공통 관계 과제를 정의해 더 넓은 일반화를 검증함. 여행 모델에 바로 다른 도메인의 다른 정답 체계를 적용해 점수만 비교하지 않음.
