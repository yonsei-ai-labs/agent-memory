# 에이전트 메모리 활용 평가 프레임워크 설계 검토안

2026-11-13 · 검토용 설계 초안

[후속 상세 설계](ai-memory-framework-detailed-design-2026-11-13.md)에서 아래 제안을 모듈·인터페이스·상태·스키마·검증 계약으로 구체화했다. 초기 실증을 Luna·τ²-bench로 두고 AppWorld·BFCL로 확장하는 구조를 제안한다. 아래 문서는 연구 비교의 검토안이며 구현의 세부 계약은 후속 문서와 함께 읽는다.

연구 목표는 **에이전트의 메모리 활용 방식을 비교할 수 있는 평가 프레임워크와 측정 절차를 제안하고, 이를 이용한 실증 분석을 제공하는 것**이다. LLM이 경험을 직접 저장·조회하는 과정과 후속 작업의 성공·실패·행동·비용을 연결해 평가한다.

저장 시점·형태·자율 선택·조회·반복·전이·누적 변화·득실·비용을 연구 범위로 유지한다. 이 문서는 [기존 논의 노트](ai-memory-write-read-experiment-note-2026-11-13.md)를 구현과 실험 시작 전에 검토할 수 있도록 구체화한 제안이다. 아래 기능과 실행 절차는 구현할 설계이며, 구현 완료나 실험 결과를 뜻하지 않는다. 벤치·도메인·모델·반복 수·비용 규모는 검토 후 확정한다.

## 연구 산출물과 기여의 판단 기준

| 산출물 | 제공할 내용 | 기여를 판단할 근거 |
| --- | --- | --- |
| 평가 프레임워크 | 기억 도구, 정책 교체, 벤치 연결, 환경 초기화, 은행 복제·교환과 실행 기록 | 같은 조건에서 여러 기억 정책을 비교하고 원 출력으로 재계산할 수 있는가 |
| 측정 절차 | 전체 정책 효과, 관측된 득실과 성공 확률 차이, 전이·회귀·비용의 집계 | 실행 변동과 비교 조건의 차이를 구분해 해석할 수 있는가 |
| 실증 분석 | 저장 내용과 조회·노출·행동·결과를 연결한 분석과 내용 개입 | 기존 결과로 설명하지 못한 차이를 새 증거로 설명하는가 |

프레임워크 구현, 실험 지원 범위, 효과 측정의 타당성, 실증적 발견을 각각 평가한다. 새로운 기억 알고리즘이나 새로운 단일 종합 점수를 필수 산출물로 두지 않는다. 기존 성공률·득실·비용 지표를 사용해도 비교를 타당하게 만들고 새로운 현상을 검증하면 기여 후보가 된다. 독창성과 성능 개선은 현재 미확정이다.

## 연구 질문과 대응 비교

| 질문 | 비교와 관측 |
| --- | --- |
| 저장 시점과 형태가 후속 작업을 어떻게 바꾸는가 | 동일 경험에서 생성한 기억, 자연 실행에서 생성한 기억을 각각 비교 |
| 무엇을 언제 불러오는 방식이 유용한가 | 같은 은행에서 조회 정책을 바꾸고 실제 노출 내용·시점을 기록 |
| 저장과 조회의 조합 효과가 있는가 | 저장 정책과 조회 정책을 교차 적용해 조건별 성능과 비용 비교 |
| 기억은 언제 이득·손해·전이·회귀를 만드는가 | 같은 과제 재시도, 관련 새 과제, 중요 조건이 다른 과제, 누적 작업의 체크포인트 평가 |
| 어떤 정보가 결과의 차이를 만드는가 | 작성·정정·요약·조회 단계의 내용 변화와 제공·보류·교체 개입을 연결 |
| 결과는 어떤 조건에서 재현되는가 | 독립 작업 스트림, 작업 순서, 반복 시드와 벤치·도메인·모델별 차이 분석 |

이 질문들을 특정 도메인이나 손해 사례 하나로 한정하지 않는다. 실행 순서는 구현상 선택이며, 연구 범위와 구분한다.

## 실험과 분석의 단위

| 단위 | 정의 |
| --- | --- |
| 과제 | 요청, 초기 업무 상태, 허용 도구, 정책 문서와 채점 기준으로 정의한 작업 |
| 시도 | 초기화된 과제를 한 번 수행한 에피소드 |
| 경험 | 저장 시점까지 공개된 관측·대화·도구 호출과 결과. 종료 후에는 허용된 피드백도 포함 |
| 기억 항목 | 제목·본문을 가진 기록. 수정할 때 이전 버전을 보존 |
| 기억 은행 | 한 조건과 작업 스트림에 속하는 기억 집합과 버전 상태 |
| 작업 스트림 | 정해진 순서로 과제를 수행하며 조건에 따라 은행을 갱신하는 실행 묶음 |
| 체크포인트 | 사전에 정한 작업 진행 시점의 은행과 실행 상태 |
| 분기 상태 | 같은 판단 직전 상태에서 노출이나 기억 내용을 바꾸는 비교의 출발점 |

원천 과제와 그 변형, 한 은행에서 파생한 기억·실행, 독립된 작업 스트림을 식별한다. 여러 기억 파일이나 도구 호출을 독립 표본으로 세지 않는다. 과제 단위 성능과 은행·스트림 단위 불확실성을 구분해 보고한다.

## 프레임워크 구성과 책임

| 구성 | 책임 |
| --- | --- |
| 실험 제어기 | 조건 배정, 작업 순서, 단계 전환, 은행 분리·복제와 실행 ID 관리 |
| 벤치 어댑터 | 초기화·행동 실행·종료·채점 연결과 벤치별 상태 관리 |
| 에이전트 어댑터 | 모델·프롬프트·실제 도구 스키마와 요청·응답 연결 |
| 기억 도구와 저장소 | 저장·수정·목록·본문 반환, 정책에 따른 동작 허용, 버전과 노출 기록 |
| 기억 정책 | 저장 가능 시점·형식 지침·조회 방식·현재 작업 중 재사용 여부 정의 |
| 기록기 | 실제 입력·출력·상태·기억 변경·노출·사용량·오류를 원본으로 보존 |
| 분석기 | 저장 결과에서 성능·득실·과정·비용을 재계산하고 비교표·사례 근거 생성 |

구현 위치는 [공동연구 작업 안내](../CONTRIBUTING.md)에 따라 실행·벤치 연결은 `experiments/`, 자료 구성은 `data_pipeline/`과 `datasets/`, 집계·검산은 `evaluation/`에 둔다. 기존 데이터·실행·진입점은 당시 버전의 근거로 유지한다.

### 벤치 어댑터가 명시할 기능

어댑터는 과제와 시드에 따른 초기화, 행동 실행, 종료 사유, 공식 채점과 과정 진단의 반환을 제공한다. 정확한 상태 복제, 초기화 후 이력 재생, 특정 판단 시점부터의 재개가 가능한지도 별도 기능으로 명시한다.

분기에는 업무 상태뿐 아니라 대화, 사용자 시뮬레이터, 난수 상태, 기억 버전과 처리 중인 도구 호출 상태가 영향을 줄 수 있다. 이를 복원할 수 없으면 동일 상태 분기를 지원한다고 표시하지 않는다. 초기화·재생으로 대체할 경우 복원된 입력과 상태를 검사하고, 남은 차이를 기록한다. 일반적인 재실행과 동일 상태의 국소 개입은 다른 실험 유형으로 집계한다.

τ²-bench는 본실험 후보이며, 사용할 버전·도메인·과제 목록과 사용자 시뮬레이터 설정은 미정이다. 채점은 과제의 평가 항목을 따르고, 예시 도구 호출 순서와 일치하는지를 공통 성공 기준으로 만들지 않는다. 공식 성공 판정과 반복 호출·중복 처리 등 과정 진단을 별도 필드로 둔다. [공식 평가 문서](https://github.com/sierra-research/tau2-bench/blob/main/docs/evaluation.md)

## 기억 도구의 제안 계약

다음은 검토용 인터페이스다. 명칭·세부 인수는 구현 전에 확정하되, 반환 내용과 정책 위반 처리까지 기록할 수 있어야 한다.

| 도구 | 입력 제안 | 반환과 동작 |
| --- | --- | --- |
| `store` | `title`, `body`, 선택적인 기존 `id` | 새 항목 ID 또는 갱신된 항목 ID, 버전, 처리 상태. 기존 ID를 지정하면 이전 본문을 보존하고 새 버전 생성 |
| `list` | 선택적인 페이지 커서와 페이지 크기 | 접근 가능한 항목의 ID·제목·버전과 다음 커서. 기본 정렬과 페이지 규칙을 고정 |
| `get` | 항목 `id` | 접근 가능한 현재 버전의 본문과 표시하기로 정한 메타데이터, 또는 명시적인 오류 |

수정은 위 `store`의 갱신 동작으로 지원하는 안이다. 삭제·망각 정책을 비교할 때는 별도 삭제 연산과 보존 이력을 명세한다. 어떤 도구가 제공됐고 어떤 단계에서 사용할 수 있었는지를 조건 설정에 남긴다.

제목과 본문은 자율 작성 조건에서 LLM이 작성한다. 관찰 사실·절차·실패 원인 등의 구분은 형식 비교 조건의 지침 또는 분석용 주석으로 두며, 모든 조건에 같은 구조화 본문을 강제하지 않는다. 검증 여부나 효용 라벨을 저장소가 자동으로 붙여 에이전트에게 제공하지 않는다.

목록의 제목·메타데이터도 기억 노출이다. 요청, 저장소 반환, 실제 다음 모델 입력에 포함된 내용을 각각 기록한다. 기본 목록을 의미 검색으로 구현해야 한다는 전제는 없으며 BM25나 특정 검색기를 필수로 두지 않는다.

항목 미존재, 접근 불가, 정책상 금지된 단계, 잘못된 인수, 저장소 오류는 구분한다. 빈 목록이나 미조회는 오류와 다르다. 저장을 하지 않거나 조회하지 않는 LLM의 선택도 유효한 관측으로 남긴다.

### 종료 후 저장 단계

작업 종료와 종료 후 기억 작성을 별도 단계로 구분한다. 종료 후에는 완료된 작업의 허용된 경험과 정해진 피드백을 제공하고 기억 도구를 사용할 수 있게 한다. 여러 항목 저장·수정이 가능하도록 설계하며, 이 단계에서 업무 도구를 호출해 이미 종료된 과제의 결과를 바꾸지는 않는다. 종료 후 작성의 요청·응답·비용을 별도로 기록한다.

모델의 작성 완료 응답으로 이 단계를 종료하는 안이다. 별도로 정할 호출·시간·비용 중단 조건에 도달하면 완료와 구분해 기록하고, 이미 저장한 내용과 중단 원인을 보존한다. 중단 조건의 수치는 실행 전에 검토한다.

### 용량과 문맥 처리

저장 용량, 항목 수, 한 번에 읽는 분량, 호출 횟수는 서로 다른 설정이다. 모델 고유 문맥 한도와 실제 사용량을 기록하며 **기억 2k나 최근 대화 2k와 기억 2k의 배분을 기본 제약으로 넣지 않는다.** 추가 한도를 둘지는 검토 항목으로 남긴다.

한도를 설정하는 조건은 단위·계산법·초과 시 동작을 명세한다. 저장·조회 내용을 몰래 자르거나 삭제하지 않는다. 모델 어댑터의 자동 문맥 압축·이력 생략도 실제 입력 구성에 영향을 주므로 설정과 적용 내역을 보존한다. 기준 토크나이저의 추정치와 제공자가 보고한 사용량을 구분한다.

## 실험 요인과 기준선

### 저장 시점

| 조건 | 수행 중 저장 | 종료 후 저장 |
| --- | --- | --- |
| 기억 없음 | 제공하지 않음 | 제공하지 않음 |
| 종료 후 저장 | 허용하지 않음 | 허용 |
| 수행 중 저장 | 허용 | 별도 정리 단계 없음 |
| 수행 중 저장과 종료 후 정리 | 허용 | 허용 |

수행 중 작성한 기억을 같은 시도에서도 읽을 수 있는지는 별도 설정이다. 허용하면 첫 작업의 행동과 수집 경험까지 바뀔 수 있으므로 자연 실행에서는 그 변화도 정책 효과에 포함한다.

### 저장 형태와 조회 정책

| 요인 | 비교 후보 | 기록할 내용 |
| --- | --- | --- |
| 저장 형태 | 자유 형식, 사건 기록, 단순 요약, 사실·조건, 절차·전략, 실패 원인·주의사항 | 배정한 지침, 실제 본문과 구조, 준수 여부, 내용 변화 |
| 조회 시점 | 작업 시작 시, 수행 중 LLM이 필요할 때, 두 방식 병행 | 요청·자동 제공 여부, 최초 노출과 재조회 시점 |
| 조회 후 처리 | 본문 그대로 사용, 현재 과제에 맞춰 재가공 | 입력 원문, 가공한 내용, 추가 호출·비용 |
| 피드백 | 작업 중 관측만, 실제 사용자 피드백, 사전 정의한 종료 결과 피드백 | 모델에게 공개한 정보의 정확한 범위 |
| 검증 환경 | 벤치·도메인·과제 유형·모델·작업 순서 | 버전, 설정, 출처 그룹과 배정 |

저장 시점·형태·조회 정책의 유효한 조합을 교차 비교한다. 기억이 없는 조건의 저장 형식처럼 의미가 없는 조합은 별도 실험 수로 부풀리지 않는다. 실험 행마다 고정한 요인과 변경한 요인을 명시하고, 구체적인 수준·조합·반복 수는 검토 후 확정한다.

같은 정책 비교에서는 작업자 모델·추론 설정·허용 업무 도구·과제 집합을 맞춘다. 모델·벤치가 달라지는 비교는 별도의 분석 블록으로 두어 모델 능력 차이를 기억 정책 효과로 합치지 않는다.

### 공통 기준선

| 기준선 | 목적과 정보 조건 |
| --- | --- |
| 기억 없는 반복 | 같은 횟수의 재시도에서 자연적인 성공 변동 확인. 과거 대화·노트는 다음 시도로 넘기지 않음 |
| 원경험 기록 접근 | 같은 공개 경험을 원문으로 보존하고 접근하게 하여, 기억 작성·표현의 추가 효과 비교 |
| 단순 요약 | 같은 경험을 정해진 요약 지침으로 저장해 자율 작성·다른 형태와 비교 |

원기록·요약 기준선의 목록·본문 노출과 조회 경로를 명세한다. 현재 과제의 정답이나 공개하지 않은 채점 정보가 과거 경험에 추가되지 않게 한다. 문맥에 원기록 전체가 들어가지 않을 때는 접근 가능한 저장소와 읽기 규칙을 명시한다.

성능과 전체 비용은 함께 보고한다. 자연 실행의 비용 차이를 포함한 정책 비교와, 동일 경험·정보 접근 조건에서 표현이나 조회의 영향을 보는 비교를 구분한다. 별도 계산량 통제 분석을 한다면 그 통제 조건도 독립된 실험 행으로 둔다.

## 실행 절차

### 자연 실행에서 기억을 누적하는 평가

1. 조건·작업 스트림별로 독립된 은행을 생성한다. 빈 은행 시작과 사전 경험이 있는 시작은 서로 다른 조건으로 기록한다.
2. 과제의 업무 상태·에이전트 대화·사용자 시뮬레이터를 초기화한다. 시작 은행만 해당 스트림에서 이어받는다.
3. 배정한 조회 정책에 따라 기억을 제공하고, LLM이 작업과 허용된 기억 도구를 사용하도록 한다. 수행 중 저장은 현재까지의 경험만 사용한다.
4. 종료 시 업무 결과·공식 채점·과정 진단을 보존한다. 채점기 전용 정보는 모델 입력과 분리한다.
5. 조건이 허용하면 종료 후 기억 작성 단계를 수행한다. 공개할 피드백은 사전에 정한 범위를 따른다.
6. 은행 변경과 비용을 보존한 뒤 같은 과제 재시도 또는 다음 과제로 진행한다. 업무 상태를 이어받는 대신 기억 은행을 이어받는다.

이 평가에서는 저장·조회·행동·경험 수집의 상호작용을 포함한 전체 정책 효과를 측정한다. 기억 없는 조건도 같은 과제 배정과 횟수로 수행한다. 같은 사용자 시드가 행동이 달라진 뒤에도 같은 대화를 보장한다고 가정하지 않는다.

### 동일 경험에서 저장 정책을 비교하는 평가

동일한 공개 수행 기록에서 여러 저장 정책으로 은행을 만든다. 수행 중 저장에는 기록의 해당 시점 접두부만 제공하고, 종료 후 저장에는 전체 공개 기록과 허용된 피드백을 제공한다. 이때 작성한 기억은 원래 수행 기록의 행동을 바꾸지 않는다.

생성한 은행을 같은 작업자·조회 정책·후속 과제에 적용한다. 저장 과정의 추론·노출·비용 차이를 기록하며, 원기록과 단순 요약 기준선도 같은 원천 경험을 사용한다. 이 비교는 주어진 경험에서의 저장 방식 효과이며 자연 실행 전체를 대체하지 않는다.

경험 출처는 결과를 보고 유리한 사례만 고르지 않는다. 성공·실패 경험을 선별하는 정책을 시험한다면 선별 규칙을 명시하고, 원천 과제·파생 변형은 같은 출처 그룹으로 관리한다.

### 저장과 조회를 교차하고 내용을 개입하는 평가

저장 정책 A와 B에서 만든 은행을 각각 조회 정책 X와 Y에 적용해 조합 효과를 비교한다. 같은 출발 은행에서 어떤 기억을 요청·반환·노출했는지 기록한다.

원인을 확인할 때는 최초 정보 노출 직전의 동일 상태에서 제공·보류·본문 교체·적용 조건 변경 등을 비교한다. 앞서 제목이나 요약으로 제공한 정보를 본문 보류만으로 제거했다고 해석하지 않는다. 편집으로 달라지는 분량·표현·출처 표시도 보존한다.

연구자가 정답 정보를 사용해 교정한 기억은 진단용 개입으로 구분하며 자율 작성 정책의 성적으로 합치지 않는다. 국소 개입 효과는 해당 상태와 나머지 기억 조건에 대한 결과이며, 기억 항목 하나의 보편적 가치로 해석하지 않는다.

### 체크포인트에서 전이와 누적 회귀를 평가

사전에 정한 작업 진행 시점마다 은행을 보존한다. 같은 과제 재시도, 관련 새 과제, 중요 조건이 다른 과제의 성능과 이전에 풀던 과제의 회귀를 구분한다. 평가 시점이나 과제 집합을 관측된 최고 성적에 맞춰 사후 선택하지 않는다.

확인용 과제마다 같은 시작 은행을 복제하고 설정된 저장·조회 정책을 수행한다. 평가 중 변경은 원은행·다른 확인 과제·이후 본실험에 반영하지 않는다. 저장을 중지한 고정 은행 판독 진단은 별도 조건이다. 작업 순서와 독립 스트림을 반복해 은행 한 개에서 나온 결과에만 의존하지 않는다.

메모리를 이어받는 반복은 일반 τ²-bench의 독립 반복과 다른 설정이므로, 공식 `pass^k`와 섞지 않고 메모리 적응 실험으로 보고한다. [공식 반복 평가 설명](https://github.com/sierra-research/tau2-bench/blob/main/docs/glossary.md)

## 측정과 집계

### 작업 성공과 정책 효과

공식 성공 여부·부분 점수·채점 버전을 원래 형식으로 보존한다. 기본 집계안은 같은 벤치·도메인의 고정 과제 집합에서 과제별 반복 성공률을 동일 가중으로 평균하는 것이다. 원천 과제의 변형을 포함하는 자료는 원천별 집계도 별도로 제시한다. 벤치마다 점수 의미가 다르면 별도로 보고하며 임의로 하나의 점수로 합치지 않는다. 과제·도메인별 표본 수와 실제 집계 가중 규칙을 명시한다.

주된 효과는 같은 과제 집합에서 반복 실행으로 추정한 기억 정책의 성공 확률과 무기억 성공 확률의 차이다. 저장 정책·조회 정책·조합별 차이와 불확실성을 함께 보고한다. 불확실성 추정은 조건 간 대응을 유지하며 독립된 은행·스트림과 출처 과제를 묶어서 재표집하는 부트스트랩을 기본 후보로 둔다. 실제 독립 반복 구조에 맞는 재표집 단위·세부 통계 방법·신뢰구간 수준·반복 수는 검토 후 확정한다.

### 관측된 득실과 실행 변동

| 무기억 결과 | 기억 결과 | 관측된 분류 |
| --- | --- | --- |
| 실패 | 성공 | 개선 반전 |
| 성공 | 실패 | 악화 반전 |
| 성공 | 성공 | 양쪽 성공 |
| 실패 | 실패 | 양쪽 실패 |

짝짓기 규칙과 분모를 보존하고 네 분류를 모두 보고한다. 이 표는 관측된 반전이며 개별 과제의 확정적인 인과적 득실 라벨이 아니다. 두 조건의 성공 확률이 각각 70%로 같아도 독립 실행을 짝지으면 개선과 악화 반전이 각각 약 21% 생길 수 있다. 이 숫자는 변동을 설명하는 가정 예시다.

무기억 대 무기억의 반복 비교로도 변동 수준을 확인한다. 반전률과 반복에 기반한 성공 확률 차이를 별도로 집계하며, 변동률을 단순 차감해 개별 기억의 인과 효과를 산출하지 않는다.

### 저장과 조회 및 행동

| 구분 | 기록·분석할 항목 |
| --- | --- |
| 저장 | 항목 수·크기·작성 시점·출처 경험·버전 변화·수정·삭제 내역 |
| 내용 변화 | 관찰 사실, 잠정 추측, 적용 조건, 절차, 결과 해석이 작성·정리 과정에서 보존·누락·변형되는지 |
| 조회와 노출 | 요청 여부, 자동 제공 여부, 목록·본문 반환과 실제 모델 입력 노출, 최초 시점과 재노출 |
| 행동 | 도구·인수·상태 변화, 관측된 호출 오류, 반복 호출, 중복 처리와 선택 변화 |
| 전이와 누적 변화 | 재시도·새 과제·조건 변경별 성능, 체크포인트별 개선과 이전 과제 회귀 |

반복 호출 횟수와 불필요한 재시도 판정은 다르다. 오류·중복·잘못된 상태 변경은 환경에서 확인할 규칙을 정의하고, 자동 판정이 어려우면 근거 구간과 미확정 상태를 남긴다. 정성 분석은 주석 기준·판정자·불일치 처리와 조건 공개 여부를 기록한다. 과거 고정 기록의 필요·무효 라벨을 새 생성 기억에 그대로 전용하지 않는다.

기억 조회나 모델의 사후 설명만으로 활용과 원인을 확정하지 않는다. 어려운 작업에서 저장이 늘어날 수 있으므로 저장량과 실패율의 상관관계를 저장의 인과 효과로 해석하지 않는다. 배정한 정책의 효과와 LLM이 실제로 선택한 행동의 기술 통계를 구분한다.

### 비용과 효율

경험 수집, 수행 중 기억 작성·수정, 종료 후 정리, 조회·재가공, 작업 수행을 구분해 토큰·호출·지연·보고 금액을 기록한다. 사용자 시뮬레이션과 평가 채점 비용도 별도 단계로 보존한다. 운영 정책의 비용과 연구용 분기·진단·반복 평가에 지출한 비용을 구분한다.

기억 작성의 일회성 비용과 여러 후속 작업에서의 사용 비용을 함께 보고한다. 분담할 후속 작업 수와 공유 경험의 비용 처리 규칙을 명시해 동일 비용을 중복 합산하지 않는다. 성능 대비 비용을 함께 제시하고 임의의 가중치로 성공과 비용을 합친 점수를 기본 지표로 삼지 않는다.

비용·사용량이 없는 요청은 0으로 채우지 않는다. 기준 토큰 추정값을 실제 사용량에 다시 더하거나 캐시 토큰을 입력 총량에 중복 합산하지 않는다. 호출 지연의 합과 전체 경과 시간도 구분한다.

### 오류와 결측

에이전트의 잘못된 도구 사용, 정책상 금지된 저장 시도, 실제 과제 실패와 환경·채점 인프라 오류를 구분한다. 모델 때문에 발생한 오류를 자동으로 인프라 실패로 분류하지 않는다. 채점 불완료는 성공·실패 대신 결측으로 보존하고, 제외 사유와 전체 배정·완료·실패·결측 수를 함께 보고한다.

| `trajectory.json` | 대화·업무 도구·기억 도구의 순서, 호출 ID와 반환, 종료 사유 |
| `memory-events.jsonl` | 요청·반환·노출의 단계와 순서, 항목 ID·버전·본문 해시, 변경 전후 상태, 실제 모델 요청과의 연결 |
| `memory/` 은행과 버전 이력 | 시작·종료·체크포인트의 원문과 제목, 생성 출처와 수정·삭제 이력 |
| 분기·재생 상태와 기능 메타데이터 | 복원한 상태, 은행 버전, 실제 입력 해시, 복원할 수 없는 상태와 차이 |
| 비용 요약과 오류 원본 | 단계별 사용량·금액·결측, 오류 분류와 반환 내용 |
| 집계표와 사례 근거 | 조건별 표본·분모·점수·득실·불확실성·비용, 원본 실행과 근거 구간 |

기억 이벤트는 최소한 실행·스트림·조건·단계·순서·연산·호출 ID·항목 버전·처리 상태·내용 해시를 연결할 수 있어야 한다. 반환됐지만 다음 모델 입력에 들어가지 못한 내용과 실제 노출을 구분한다. 시간은 구조화 기록에서 UTC를 사용하고 표시할 때 시간대를 명시한다.

집계는 저장된 원본만으로 재계산할 수 있도록 한다. 원본·설정·채점·사후 분석의 버전과 해시를 남기며 기존 실행을 덮어쓰지 않는다. 공유용 산출물의 보존·전달 범위는 실제 데이터와 실행 구성이 정해진 뒤 명세한다.

## 실증 분석에서 제시할 결과

1. 저장 시점·형태·조회 방식별 성공률과 전체 비용, 원기록·단순 요약·무기억 기준선의 비교.
2. 관측된 개선·악화 반전과 양쪽 성공·실패, 반복 실행의 변동과 성공 확률 차이.
3. 같은 과제 재시도, 관련 새 과제, 중요 조건이 다른 과제와 체크포인트별 전이·회귀.
4. 실제 저장 내용·버전 변화·노출 내용·행동·결과를 연결한 대표 사례와 전체 빈도.
5. 동일 경험의 기억 교체, 저장·조회 교차, 내용 개입으로 확인한 효과와 남은 불확실성.

대표 사례는 전체 결과표와 연결하고 선택 기준을 명시한다. 가설의 예는 수행 중 잠정 추측을 종료 후 정리가 수정하는지, 확정 규칙처럼 강화하는지, 그 차이가 후속 판단을 바꾸는지다. 유리한 사례만으로 정책의 일반적인 우위를 주장하지 않는다.

## 선행연구와 차별화 검토

[후속 지표·노벨티 비교 보고서](reports/2026-11-13-memory-benchmark-metrics-and-novelty.md)에서 12개 벤치·프레임워크를 대조했다. MemTools의 구성 교체·평가 프로토콜 분리와 EvoMemBench의 수행 중·과제 간 평가를 직접적인 비교 대상으로 추가한다. 아래 표는 초기 검토 범위이며, 지표·실험 채택과 신규성 판단에는 후속 보고서의 근거도 함께 사용한다.

| 연구 | 이미 다루는 내용 | 이번 설계에서 대조할 부분 |
| --- | --- | --- |
| [MemGym](https://arxiv.org/html/2605.20833) | 여러 에이전트 환경의 기억 평가, 동일 작업자 비교와 수행 중 문맥 압축 | 후속 작업으로 이어지는 자율 작성·조회, 교차 정책·내용 개입의 지원과 분석 범위 |
| [MemoryArena](https://proceedings.mlr.press/v306/he26am.html) | 상호 의존적인 여러 세션에서 기억과 행동이 연결되는 평가 환경 | 실제 작업 루프를 지원하는 것 외에 어떤 정책 비교와 측정이 추가되는지 |
| [When Continual Learning Moves to Memory](https://arxiv.org/html/2604.27003) | 표현·저장 단위·조회 빈도와 전이·간섭 | 자율 저장의 시점·내용 변화부터 행동 결과까지 어떤 추가 설명을 검증하는지 |
| [JitMem](https://arxiv.org/html/2609.27334) | 원경험 저장과 현재 과제에 맞춘 조회 시 가공, τ²-bench 평가 | 저장 시점·형태와 조회 시 가공의 조합 효과 및 비교 조건 |
| [AgeMem](https://aclanthology.org/2026.acl-long.981/) | 도구를 통한 자율 기억 관리와 학습 | 도구 제공 자체와 구분되는 평가 기능·측정 절차·발견 |
| [Useful Memories Become Faulty](https://arxiv.org/html/2605.12978) | 갱신 방식에 따른 기억 변화와 누적 성능 악화 | 작성·정정·조회 단계 중 차이가 생기는 지점과 후속 개입의 설명력 |
| [MemTrim](https://arxiv.org/html/2610.07311) | 일부만 적용 가능한 기억의 손해와 저장·조회 제어 | 이득·손해·효율을 함께 설명하는 조건과 기존 설명을 넘어서는 증거 |

나머지 관련 연구는 [논의 노트](ai-memory-write-read-experiment-note-2026-11-13.md)에 연결돼 있다. 차별화 후보는 에이전트의 자율 작성부터 후속 작업까지 추적하고 통제 비교할 수 있는 기능과, 이를 이용한 측정·설명의 추가 가치다. 기존 프레임워크에서 같은 비교가 불가능하다고 미리 주장하지 않고 공개 기능·실험 조건·재현 가능성을 대조한다.

## 구현 후 실험 시작 전 확인할 사항

구현을 진행한다면 도구·상태·입력·기록의 기능 검증과 실제 효과 평가를 구분한다. 다음 사항은 프레임워크의 인수 기준 제안이다.

- 저장 시점 네 조건에서 허용된 단계에만 쓰기가 가능하고, 여러 항목·수정·목록 페이지·본문 조회가 원본에 일치한다.
- 업무 상태와 대화·사용자 시뮬레이터가 초기화되고 기억 은행만 정해진 조건에서 이어진다. 조건·평가 사본 사이의 변경은 섞이지 않는다.
- 미래 관측·채점기 정보가 저장·조회 입력에 들어가지 않으며 목록·제목·본문의 실제 노출을 재구성할 수 있다.
- 지원한다고 명시한 상태 복원·분기의 입력과 상태가 검산된다. 복원 불가와 일반 재실행을 구분한다.
- 작성·정리·조회·수행·평가의 비용과 오류·결측이 보존되고, 저장 자료에서 점수와 집계표를 재계산할 수 있다.
- 기준선·요인 조합·출처 분할·독립 반복·집계 방법과 실행 비용·중단 조건이 검토 문서와 실제 설정에서 일치한다.

검토와 조건 확정 뒤에 구현·기능 검증·실험 실행·분석으로 이어간다. 이번 요청의 산출물은 시작 전 검토를 위한 설계 문서다.
