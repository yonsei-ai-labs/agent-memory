# 다음 메모리 실험을 위한 데이터 정리와 설계

2026-11-08. [통합 리뷰](../training/memory_selector/reviews/2026-11-08-integrated/README.md) 이후의 작업 기준이다. 새 학습·유료 모델 호출·효용 라벨 생성 없이 기존 자료를 정리했다.

**방향을 유지할 이유는 있다. 다만 “데이터만 더 모으면 학습 선택기가 좋아진다”는 결론은 아니다.** 같은 기억의 효과가 현재 조건에 따라 달라지는 실제 대조를 이미 관측했고, 작은 판독층이 학습 자료를 구분할 능력도 확인했다. 다음에 확인할 것은 그 판단이 여러 출처로 옮겨가며 고정 정책보다 이득을 주는지다. 학습 적합·정답 품질·정책 선택 기준을 함께 보완해야 한다.

## 이번 정리에서 만든 것

- [데이터 역할 목록](../datasets/catalog.json): 기존 데이터 9종과 근거 후보 묶음 2종의 위치·고정 색인 해시·단위·라벨 의미·다음 용도를 연결했다. 서로 겹치는 자료를 합산하지 않는다.
- [근거가 연결된 검토 사례 6개](design-data/memory-selection-next-20261108/review-queue.jsonl): 실제 도움/피해 대조 2개, 관련성과 추가 가치의 경계 2개, 설치 성공과 전제 충족의 경계 2개다. **새 독립 사례나 추가 학습 행이 아니다.** 각 기록은 검토 전용이며 학습 내보내기를 허용하지 않는다.
- 이 문서: 새 자료의 판단 시점·행동·라벨·분할·학습 연결과 다음 작업의 완료 조건을 정한다.

파일 이동이나 일괄 병합 대신 기존 버전으로 연결하는 목록을 만들었다. 고정된 데이터·원래 분할·과거 평가 결과를 보존하면서 다음 실험에 쓸 수 있는 범위를 찾기 위한 정리다.

## 왜 이 방향인가

연구 질문은 **“같은 과거 경험에서 어떤 정보를 지금 전달해야 작업자가 더 잘 해결하는가?”**다. 작은 모델의 역할은 현재 관측과 기억을 비교해 전달 여부와 내용 수준을 고르는 것이다. 관련성 분류는 이를 돕는 중간 감독일 수 있지만 최종 성과가 아니다.

기존 NetworkX 자료에는 다음 대조가 있다. 과거 기억은 두 경우 모두 “입력을 복사하고, 복사본에 작업을 한 뒤, 그 복사본을 반환하라”는 같은 절차다. 현재 요구도 둘 다 원본 보존이다.

| 현재 함수의 차이 | 무기억 | 같은 기억 제공 | 해석 |
| --- | --- | --- | --- |
| `copy=False`: 전달받은 그래프를 직접 바꿈 | 실패 | 성공 | 복사본을 만든 뒤 작업하는 절차가 도움이 됨 |
| `copy=True`: 새 그래프를 반환함 | 성공 | 실패 | 작업자가 새 반환값을 버리고 변하지 않은 복사본을 반환함 |

이는 고정 4B·작성한 두 상태의 기존 관측이다. 자연 SWE 일반화나 기대 효과의 추정값은 아니다. 그래도 단순히 “그래프 관련 기억인가”를 넘어 **변환 결과가 어디에 남는지**를 비교해야 한다는 구체적인 학습 문제를 준다. [원래 입력](../datasets/api_transfer/20261108-v1/test.jsonl)과 [실제 제공 결과](../datasets/api_worker_utility/20261108-v3/judgments.jsonl)를 검토 목록의 ID·해시로 연결했다.

반대로 최신 관련성 자료는 640쌍이어도 실제 효용 라벨이 0개다. 그 자료를 더 많이 바꿔 쓰는 것만으로 위 질문의 정답이 늘어나지는 않는다. 새 데이터를 모으는 이유는 행 수를 키우기 위해서가 아니라 **관계가 달라지는 조건과 실제 효과의 연결**을 여러 출처에서 얻기 위해서다.

## 기존 자료의 다음 역할

| 자료 | 지금 사용할 곳 | 추가로 필요한 것 |
| --- | --- | --- |
| API 4B 효용 | 기존 학습 부분에서 목적함수·입력·최적화 점검 | 여러 새 출처의 현재 상태와 실제 결과 |
| 같은 상태의 9B 전이 | 작업자에 따라 효과가 달라지는지 분석 | 새 독립 문제의 확인 자료 |
| 관계 74행·범위 통제·API 직접 적용성 | 관계 판독의 기능 점검, 지름길·누출 진단 | 실제 기억 제공 효과와의 연결 |
| 관련성 640쌍 | 기억 후보·주석 경계 검토 | 독립 주석과 현재 코드 근거, 정보의 추가 가치 |
| Django 초기화 파일럿 | 정보 조각 추가·삭제와 채점 계약 점검 | 다른 관계·저장소의 사례 |
| 전제 후보 8개·초기 리뷰 후보 9개 | 출처 근거와 설계 예시 | 별도 현재 대상, 관측 시점, 실제 효용 |

원래 test를 조용히 학습으로 편입하지 않는다. 이미 결과를 본 자료로 새 방법을 다듬었다면 그 방법의 확인에는 새 출처가 필요하다. 초기 리뷰 후보 중 공식 검사 정보를 사용한 네 항목은 진단 전용이며 선택기 입력 후보에서 제외한다. “근거 후보 8개”도 실제 현재 대상이나 제공/보류 결과가 갖춰진 여덟 학습 예제가 아니다.

## 새 사례 하나에 무엇을 남길까

첫 정책 시점은 **기억을 주지 않은 공통 초기 조사 직후, 패치 작업 전에 한 번**으로 제안한다. 실제 조사 명령·읽은 파일·비용·snapshot을 모두 기록하고 그 snapshot에서 행동별 실행을 분기한다. 초기 조사 정책·한도는 결과를 보기 전에 정한다. 조사를 완전한 파일시스템·실행 상태로 복원할 수 없다면 독립 분기라고 쓰지 않는다.

| 구분 | 필수 내용 | 선택기 입력 여부 |
| --- | --- | --- |
| 식별·계보 | 과거 경험 ID, 현재 문제 ID, 저장소/revision, 파생 부모·연결 그룹 | 원칙적으로 메타데이터만 |
| 과거 근거 | 원문 위치·해시, 실제 명령·응답, 성공/실패/부분 진행 범위 | 검토된 기억 본문만 |
| 현재 관측 | 문제 설명, 선택 전에 읽은 코드·환경·완료 기록, snapshot ID | 허용 |
| 기억 조각 | 절차 P, 적용 조건·출처 관측 E, 각 조각의 정확한 출처와 해석 구분 | 선택한 행동에 따라 제공 |
| 관계 주석 | 직접 적용 가능성, 이미 관측된 정보인지, 확인되지 않은 전제, 검토자·이견 | 감독용; 입력과 별도 |
| 실제 결과 | 행동별 실행·성공·회귀·제출·토큰·지연·비용·미완료 사유 | 평가/효용 감독용; 입력 금지 |

‘적용 가능’, ‘이미 알려짐’, ‘근거 부족’은 서로 다른 판단이다. 이미 알려진 정보도 주의를 환기해서 도움이 될 수 있고, 직접 적용 불가한 절차도 원리를 수정해 사용할 수 있다. 따라서 관계 주석에서 제공/보류나 도움/피해를 자동으로 정하지 않는다.

현재 작업의 미래 로그, 기억을 받고 생성한 명령, 공식 정답 패치·숨은 검사 결과는 선택기 입력에 넣지 않는다. 출처의 설치 성공 코드나 파일 수정 응답도 전체 문제 해결로 바꾸지 않는다. 특정 명령 직전의 선택을 연구하려면 시작/초기 조사 시점 자료와 섞지 않고 별도 프로토콜로 정의한다.

## 다음 비교의 행동을 고정한다

우선 검토된 같은 과거 경험 하나를 대상으로 다음 네 실행을 비교한다. 이는 기억 내용을 고르는 첫 단계이며, 많은 후보의 검색·은행 관리까지 한 번에 학습하는 실험은 아니다.

| 행동 | 제공 내용 | 비교 목적 |
| --- | --- | --- |
| N | 무기억 | 기존 작업자의 능력과 비용 |
| P | 과거 절차 | 그 절차를 제공하는 효과 |
| P+E | 같은 절차 + 근거 있는 적용 조건·과거 관측 | 필요한 정보 조각을 보존한 효과 |
| P+G | 같은 절차 + 길이를 맞춘 일반 안내 | 추가 길이·주의 환기의 영향을 일부 통제 |

**P+G는 일반 안내만 주는 조건이 아니다.** P+E와 P+G에는 정확히 같은 P가 들어간다. 토큰 길이의 허용 차이·문구·제공 위치·절단 금지는 고정 작업자의 tokenizer로 실행 전에 확정한다. 일반 안내도 행동에 영향을 줄 수 있으므로 무효한 위약이라고 가정하지 않는다. P+E−P는 조건·관측 묶음의 추가 효과이며 순수 의미 하나의 효과로 확대하지 않는다.

학습 선택기의 첫 행동 공간은 N/P/P+E로 둔다. P+G는 효과 해석을 위한 대조다. 모든 상태에 P+E를 주는 고정 정책이 충분한지부터 비교한다. 그 정책이 성공·비용 모두에서 충분하다면 복잡한 선택기의 필요성은 지지되지 않는다. 이후 여러 과거 경험 중 무엇을 고를지 확대할 때 후보 수·검색 재현율·후보 생성 비용을 별도로 통제한다.

## 득실 정답을 만드는 원칙

관계 주석과 실행 효과를 별도 파일로 둔다. 먼저 각 행동의 관측 결과 `Y(action)`을 저장하고, 무기억 대비 차이 `Y(action) − Y(N)`를 파생한다. 성공한 행동 하나만 남기거나 실패를 삭제하지 않는다.

관측 결과가 둘 다 있으면 개선 / 악화 / 둘 다 성공 / 둘 다 실패의 네 범주도 함께 계산할 수 있다. 한 번의 생성 쌍은 그 실행 조건의 관측 차이지, 그 기억의 일반적인 기대 효과 정답이 아니다. 반복을 하면 상태·행동·반복 ID와 원래 결과를 모두 유지하며 반복 수와 비용을 사전에 정한다. seed가 같다는 이유로 두 생성이 같은 확률적 경로를 따랐다고 가정하지 않는다.

관계가 미확인인 것과 실제 효과가 아직 측정되지 않은 것도 구분한다. **미측정 효과는 `null`이며 0이 아니다.** 외부 중단·환경 오류는 관측 상태로 남기고, 예산 내 정상 미제출을 어떻게 성공률 분모에 넣을지 실행 전에 정한다. 서로 다른 비교의 무기억 결과를 임의로 섞지 않는다.

비용은 공통 초기 조사, 선택기 인코딩·판독, 제공 이후 작업자의 실행을 나눠 기록한다. 성공·악화·제공률과 비용을 먼저 각각 보고한다. 하나의 순효용 점수로 합칠 때는 교환 가중치를 미리 정하고, 성공이 같은 경우의 비용 절감도 별도로 평가한다.

## 출처와 분할

다음 목표는 **12–20개 독립 경험 가족의 발견용 자료**를 만드는 것이다. 숫자는 수집 목표이며 학습 충분성·검정력을 보장하지 않는다. 실행 전제, API/출력 계약, 검사 범위 등 몇 가지 관계를 여러 저장소에서 찾되, 각 사례의 구체적인 전이 근거가 있어야 한다. 설치·초기화 로그가 많이 나온다는 이유로 한 종류에 집중하지 않는다.

현재 조건은 전제가 필요한 경우, 이미 충족된 경우, 비슷해 보이지만 다른 원인인 경우, 관측이 부족한 경우를 검토한다. 이런 조건이 모든 출처에 억지로 존재한다고 가정하지 않는다. 자연적으로 관측한 상태와 연구자가 재구성한 상태를 구분하고, 재구성·바꿔쓰기·같은 문제의 다른 rollout은 같은 부모 그룹에 둔다.

분할은 증강 전에 고정한다. 첫 배포 시나리오는 **알려진 기억 은행에서 새 현재 문제로 옮겨가는 선택**이다. 공유 은행을 명시하고 현재 문제·파생 상태의 누출을 막는다. 완전히 새 기억으로의 전이는 별도 평가다. 기억 작성·후보 선정이 평가 대상의 미래 해법을 읽고 이뤄졌다면 독립 확인 자료로 쓰지 않는다.

개발 자료도 한 라이브러리나 한 조건에 몰리지 않게 구성한다. 보류를 검토할 수 있는 현재 상태를 포함하고, 같은 관계가 여러 출처에서 나타나는지 확인한다. 실제 성과를 본 뒤 개선되는 사례만 남기는 방식은 쓰지 않는다. 발견 자료에서 선택의 여지가 없었다면 그 결과를 보고하고 수집 설계 자체를 검토한다. 최종 확인 집합은 성적을 보고 선별하지 않는다.

## 학습과 다시 연결하는 시점

모델을 더 크게 하기 전에 다음 세 조건을 확인한다.

1. **입력으로 판단할 수 있는가:** 동일한 관측 입력에 충돌하는 관계 정답이 붙어 있지 않은지, 필요한 전제가 누락됐는지 점검한다. 관측 불가능성·확률적 결과를 무조건 모델의 암기 실패로 처리하지 않는다.
2. **작은 통제 자료를 학습할 수 있는가:** 일관된 학습 부분에서 분류뿐 아니라 현재 조건별 기억 순위를 확인한다. 실제 평가할 checkpoint의 노출·학습 적합도도 기록한다. 최신 실행의 마지막 128회와 선택된 32/64회 모델을 혼동하지 않는다.
3. **개발 선택이 최종 목표를 따르는가:** 관계 F1은 보조 지표다. 실제 행동 성공·악화·제공률·비용을 기준으로 정책을 정하고 무기억·고정 P+E·전제 규칙과 비교한다. 전부 보류해서 피해만 없는 모델을 좋은 선택기로 읽지 않는다.

이 조건이 갖춰지면 기존 작은 모델과 최소한의 판독층으로 시작한다. 기존 회귀와 네 범주 효용 학습을 우선 비교할 수 있다. LoRA·대조 손실·별도 층은 새로운 학습 신호가 실제로 작동하는지 확인한 뒤 한 요소씩 비교한다. 현재 12–20가족의 발견 결과만으로 신경망 일반화가 입증됐다고 주장하지 않는다.

## 이번 정리의 완료와 다음 산출물

이번에는 데이터 역할 목록과 실제 근거 사례의 연결을 끝냈다. 새 학습 자료와 새 효용 측정은 **0개**다. 이것을 데이터 증강 성과로 세지 않는다.

다음 작업의 산출물은 추가 설명 노트가 아니라 **현재 관측·과거 근거·관계 검토·실행 준비 상태가 연결된 새 사례 표**다. 먼저 검토자들이 같은 기준으로 읽을 수 있게 하고, 이견과 누락은 그대로 표시한다. 그 뒤 실행 가능한 발견 자료의 대상·네 행동·예산·중단 규칙을 고정하고 실제 결과를 수집한다. 다른 출처에서 확인할 평가 자료는 그 설계와 분리한다.

이 방향을 유지할 이유는 작은 학습기의 가능성을 믿어서만이 아니다. **단순한 고정 기억이나 규칙으로 충분한 경우도 포함해, 언제 추가 학습이 필요한지 검증할 수 있는 질문**이기 때문이다.

후속 작업으로 [새 출처 사례 표](design-data/memory-evidence-discovery-20261108-v1/README.md)를 만들었다. 과거 기억을 먼저 고정한 뒤 현재 문제 18개와 수정 전 코드를 대조한 19쌍이다. 실제 효용·작업자 실행은 아직 없으며, 같은 저장소의 문제를 연결하는 것만으로 유익한 재사용 조건이 충분히 생기지 않는다는 수집상의 한계도 남겼다.

그 뒤의 [수집·증강·분류 통합 방향](ai-memory-data-collection-and-taxonomy-2026-11-08.md)은 이 문서의 12–20가족을 발견 단계의 목표로 한정하고, 새로운 현재 문제 100개부터 300–500개로 확대하는 작업 목표와 후보가 여러 개인 선택 평가를 제안한다. 표본 충분성을 보장하는 수는 아니며, 원래 N/P/P+E/P+G 내용 비교와 실제 효용 정답의 정의는 유지한다.
