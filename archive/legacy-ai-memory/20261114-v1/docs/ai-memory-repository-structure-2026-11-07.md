# 동료 공유용 저장소 구성과 이행 시점

2026-11-07. 사용자가 실험을 동료에게 공유하려고 새 저장소와 작업 영역 분리를 제안해 작성한 판단·실행 순서다. 외부 저장소 생성·push·공개나 기존 파일의 일괄 이동은 이 문서 작성에 포함하지 않는다.

## 판단

**지금 하나의 공유 저장소로 구조를 잡고 공동연구용 첫 스냅샷을 준비하는 것이 적절하다.** 측정 실험, 데이터 수집·생성, 모델 학습은 같은 연구 질문·데이터 버전·평가 계약을 공유하므로 한 Git 레포 안에서 작업 영역을 나누는 구성이 좋다. 세 영역을 별도 레포로 나눌 필요는 아직 작다.

현재는 관계 주석·학습 목표·효용 평가의 경계를 동료와 맞추는 것이 특히 가치 있는 시점이다. 성능이 확정된 연구 결과로 소개할 단계는 아니다. 폴더와 데이터 계약을 먼저 합의하고, 실제 효과와 일반화는 후속 실행으로 확인한다.

새 Git 호스팅 레포를 만드는 것과 로컬 Git 역사를 처음부터 만드는 것은 다른 결정이다. 현재 로컬에는 두 커밋이 있고 원격이 없다. 특별히 기존 역사를 분리할 이유가 없다면 **현재 저장소를 정리하고 새 공유용 원격에 연결해 작업 기준을 하나로 유지**하는 방식을 권한다. 별도의 정제 이력이 필요하면 최초 공유 시점의 선별 스냅샷으로 시작할 수 있지만, 이후 두 저장소에서 각각 개발하지 않는다.

## 현재 상태에서 확인한 정리 필요

이번 노트 커밋 전의 작업 트리를 읽어 확인한 상태다.

- Git에는 연구 문서와 일부 학습 코드가 추적돼 있다. `experiments/`의 실행 코드·설정·계획494파일은 아직 추적되지 않았다. 현재 clone만으로 측정 실험이 재현된다고 소개할 수 없다.
- `docs/` 아래 미추적 파일은5,580개·약90.6MB다. 과거 보고서와 감사 사본이 많아 현재 결과의 진입점과 역사 보존 자료를 나누어 보여줄 필요가 있다.
- `datasets/`의 관계 자료, 학습 산출물, 측정 원자료에는 서로의 경로·해시 참조가 있다. 현재 동결 자료의 경로를 일괄 바꾸면 원본 검증과 재실행 스크립트가 깨질 수 있다.
- 원시 측정 `runs/`, 모델 학습 `outputs/`, 다운로드 캐시는 로컬에 있으며 Git 배포와 별도다. 동료에게 무엇을 추가로 받아야 하는지 manifest가 필요하다.
- 다른 학습·보고 작업의 변경도 함께 존재한다. 이번 문서 커밋과 전체 연구 코드의 첫 공유 준비를 구분한다.

문서·로그가 많다는 사실은 외부 공유를 늦출 이유가 되기보다, 명시적인 첫 공유 범위를 정할 이유다. 이 작업 트리 전체를 그대로 첫 공개 커밋으로 삼는 방식은 권하지 않는다.

## 권하는 한 레포의 구조

아래는 목표 구조이며 현재 파일을 이미 옮겼다는 뜻은 아니다. 기존 이름을 가능한 한 유지한다.

```text
ai-memory/
├── README.md                  # 연구 질문, 현재 상태, 읽는 순서, 최소 재현
├── docs/
│   ├── protocols/             # 배정·지표·실패 처리·판정 시점
│   ├── reports/               # 결과·한계와 근거 링크
│   └── decisions/             # 연구·데이터·구조 결정의 이유
├── experiments/               # 측정 실험: 고정 agent, 제공 정책, 채점·분석
│   ├── swe_memory/
│   ├── skillsbench/           # 실제 연결을 구현할 때 추가
│   └── terminal_memory/       # 실제 연결을 구현할 때 추가
├── data_pipeline/             # 수집·정규화·기억 생성·주석·분할·검증 코드
├── datasets/                  # 스키마, 버전 manifest, 작은 허용 자료·예시
├── training/                  # 학습·추론·입력 대조·checkpoint 검산
│   └── memory_selector/
├── tests/                     # 영역 사이의 데이터 계약 검사부터 추가
├── artifacts/                 # 큰 실행 로그·가중치·캐시; Git 밖 보관
├── pyproject.toml
└── uv.lock
```

`data_pipeline/`는 만드는 코드, `datasets/`는 만들어진 자료의 계약과 버전이라는 구분이다. 현재의 동결 자료는 기존 경로에서 보존하고 새 파이프라인 산출물부터 이 규칙을 적용한다. 빈 벤치 폴더나 거대한 공통 프레임워크를 먼저 만들 필요는 없다. 두 영역 이상에서 실제로 재사용하는 코드가 생기면 그때 작은 공통 Python 패키지로 추출한다.

한 레포가 반드시 하나의 Python 환경이라는 뜻은 아니다. 측정·데이터 작업과 Colab 학습의 의존성·정밀도·장치 요구가 다르므로, 각 환경의 고정 설정을 명시하고 실제 지원하는 조합을 검증한다. 폴더 정리를 위해 기존의 정상 동작 환경을 한꺼번에 바꾸지 않는다.

## 영역별 책임과 연결 계약

| 영역 | 책임 | 다른 영역에 전달할 것 |
| --- | --- | --- |
| 데이터 수집·생성 | 원문 수집, 근거 연결, 기억 단위, 주석·분할 | 데이터 버전·schema·예측 입력 허용 목록·출처 해시·분할 그룹 |
| 모델 학습 | 고정 표현·판독층·LoRA, 대조 입력, 저장·복원 | 학습 설정·감독 노출·모델 버전·예측·검산과 비용 |
| 측정 실험 | 고정 agent에서 제공/보류·삭제/복원, 공식 채점 | 전체 배정·중간 패치·제출·성과·비용·상태와 원본 참조 |
| 문서·보고 | 질문·가설·의사결정·관측과 한계 | 주장의 범위와 근거를 찾는 진입점 |

세 영역은 최소한 다음 식별자를 공유해야 한다: 데이터 버전, 출처 경험 ID, 현재 과제/판단 상태 ID, 기억/변형 ID, 연결 분할 그룹, 프로토콜 ID, 모델·정책 버전, 실행 ID와 내용 해시. 구체적 필드 이름은 실제 사용처를 옮길 때 schema로 확정한다.

특히 라벨 종류를 명시한다. **출처의 성공/실패, 현재 관계의 근거 있음/모순/미확인, 관측 행동의 성과, 기억 제공의 평균 효과**는 서로 다른 데이터다. 같은3분류나 같은0/1 숫자라는 이유로 합치지 않는다. 판단 시점에 얻을 수 있는 입력과 평가 뒤에 얻는 메타데이터도 구분한다.

학습이 끝난 뒤 측정 실험은 고정된 정책·모델 버전만 읽는다. 평가 타깃의 결과를 같은 평가의 학습·기억 갱신에 되돌리는 실험은 별도 프로토콜로 취급한다. 이미 분리해 둔 학습 실행 색인과 SWE 실행 분모도 유지한다.

## 첫 공유 패키지에서 동료가 읽을 순서

첫 화면에는 날짜가 붙은 짧은 상태 요약과 다음 내용을 둔다.

1. 연구 질문: 현재 조건과 과거 경험을 비교하는 별도 모델이 기억 사용의 성과·비용을 개선할 수 있는가.
2. 지금까지 측정한 것: 전달 방식·내용 구성의 소규모 탐색과 근거/관계 판독 학습. 적용 관계의 정확도와 실제 에이전트 개선을 구분한다.
3. 현재 자료: 관계 발견 자료는74행·10개 출처·6개 저장소이며, 독립74개 경험이나 유해/유익 정답표가 아니다.
4. 핵심 결과와 미확인: 같은 과제 반복과 제출 행동의 영향, 외부 결과의 분포, 학습 비교가 어떤 목표·입력·분할에서 수행됐는지. 큰 모델이나 기억 추가의 일반 우위를 주장하지 않는다.
5. 다음 질문: 새 출처 확대, 구성요소 개입, 규칙·유사도·작은 분류기와 비교, 고정 정책의 실제 성과.
6. 재현 안내: 모델 API를 호출하지 않는 작은 검증부터 실행하고, 유료 실행은 명시적으로 선택한다.

보고서는 결과표·판정 범위·한계·데이터 버전·원본 참조를 함께 갖춘다. 연대기 전체가 아니라 위 요약을 읽고 필요한 보고서·원자료를 따라가게 한다. 과거 회고와 오류·중단 기록은 보존하되 첫 화면의 중심에서는 뒤로 둔다.

## 무엇을 Git에 넣을까

코드·설정·고정 계획·schema·작은 예시·분할 및 파일 manifest·집계·보고서는 Git에 둔다. 작은 자료라도 출처와 배포 범위를 함께 확인한다. 기본 ignore 규칙도 커밋해서 clone 뒤에 같은 경계를 유지한다.

동결 근거의 파일 바이트는 Git 속성으로 보존해 운영체제의 줄바꿈 변환 때문에 SHA256 검증이 깨지지 않게 한다. 기존 CSV의 CRLF도 원본 그대로 보존한다.

원시 대화·거대한 궤적·다운로드 데이터·모델 가중치·환경 이미지는 별도 artifact 보관처를 사용한다. manifest에 위치·버전·파일 크기·SHA256·접근 방법을 기록한다. 현재 내부 논의에서 실제 저장소를 정할 수 있지만 이번 문서 작성에서 외부 업로드는 수행하지 않았다.

원본 역사 자료의 경로와 해시는 고정해 보존한다. 공유용 읽기 경로나 artifact 위치가 바뀌면 새 manifest에 원래 경로와 새 위치의 매핑을 둔다. 파일을 옮긴 뒤 옛 SHA 목록을 조용히 다시 만드는 것은 금지한다. 보고서에서 원문이 필요한 주장에는 동료가 원문을 실제로 받을 수 있는 경로를 제공한다.

## 지금부터의 이행 순서

1. **이번 조사와 구조 결정을 커밋한다.** HF·논문 조사와 그 근거, 이 문서를 선택적으로 커밋한다. 병행 중인 다른 코드 변경이나 대량 원자료를 한꺼번에 포함하지 않는다.
2. **공유용 v0.1 스냅샷을 만든다.** 측정 코드·데이터 파이프라인·학습 코드의 포함 목록, 현재 상태 요약, 대표 결과, 작은 허용 데이터와 재현 설정을 정한다. 필요한 코드·환경 파일이 Git에 실제 들어 있는지 점검한다.
3. **깨끗한 clone에서 최소 경로를 검증한다.** API 없는 데이터 검증과 결과 재집계, 작은 모델 저장·복원 검사를 각 환경에서 확인한다. 원자료가 별도인 경로는 다운로드·접근 명세와 함께 검증한다. 현재 로컬에서 통과했다는 기록으로 clone 검증을 대신하지 않는다.
4. **새 공유 원격에 연결해 단일 작업 기준으로 삼는다.** 저장소명·조직·공개 범위·artifact 위치를 정해 공유하고, 이후 변경은 그 레포의 작은 커밋/PR로 쌓는다. 이번 요청의 노트 커밋과 원격 생성·push는 별개다.
5. **경로 이동은 후속으로 나누어 한다.** 새 수집·생성 코드부터 `data_pipeline/`로 분리한다. 기존 실행 경로는 필요하면 얇은 호환 entrypoint로 유지하고, 경로 변경과 실험 방법 변경을 같은 변경으로 섞지 않는다.

이 순서라면 동료의 검토를 지금 시작하면서, 수천 개 파일의 일괄 이동 때문에 연구 기록과 재현 경로가 끊기는 일을 피할 수 있다. 현재는 공동연구용 공유를 시작하기 좋은 시점이며, 성능의 확증과 대규모 코드 정리를 모두 끝낼 때까지 기다릴 필요는 없다.
