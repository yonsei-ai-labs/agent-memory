# 실험 기록과 보고서 작성 규약

2026-11-03 · 결과·인사이트·후속 분석 근거를 함께 보존하기 위한 운영 규약

## 기록의 단위

한 실행은 `과제 × 모델·제공자 × 메모리 조건 × 반복 번호`로 정의하고 고유 run ID를 부여한다. 다시 실행하면 기존 폴더를 덮어쓰지 않고 새 ID를 만든다. 같은 과제의 환경 점검, 모델 선정, 경험 수집, 평가 실행을 `phase`로 구분한다. 동일 과제의 반복을 독립적인 여러 과제로 세지 않는다.

## 저장 위치

| 위치 | 기록 내용 |
| --- | --- |
| `docs/experiment-log.md` | 진행 상황, 결정 이유, 관측 사실, 해석·가설, 다음 검증 |
| `docs/reports/` | 특정 실험에 대한 방법·결과·한계·분석 노트 |
| `docs/reports/data/runs.csv`, `runs.json` | 모든 manifest의 목록; 고유 record ID·기록 유형·모델/비용 적용 여부·원본 경로 포함 |
| `runs/<run_id>/` | 원본 요청·응답·명령·패치·공식 채점·설정·코드 사본 |

원본은 로컬 `runs/`에 보존하고 Git에서는 제외한다. 집계와 연구 노트는 Git 관리 대상이다. Git 복제만으로 원본이 복원되는 구조는 아니며, 현재 별도의 외부 백업은 연결하지 않았다. 원본을 정리·삭제할 때는 연구 근거를 잃지 않도록 보존 위치부터 확보한다.

전체 목록에는 모델 없는 사후 검사도 들어간다. 메모리 비교 대상·출처 수집·카드 작성·연결 점검을 구분하며, 없는 비용 정보와 적용 대상이 아닌 비용 검사를 구분한다. 필드와 분모는 [데이터 안내](reports/data/README.md)를 따른다. 원본이 추가된 뒤 전체 목록도 갱신하되 실험별 고정 출력은 덮어쓰지 않는다.

| `audit/`, `audit-summary.json` | 기존 generation ID의 제공자·요금 사후 조회; 원본 요약은 덮어쓰지 않음 |

| `memory/bank.json`, `memory/initial-context.json` | 호스트에만 보관한 고정 카드 저장소 사본과 시작 입력에 실제 넣은 기억 블록 |

| `memory-events.jsonl`, `memory-summary.json` | 자동 검색·에이전트 요청·빈 결과·한도·요청 본문의 카드 포함과 요약 |

소스가 아직 커밋되지 않았으면 `git_commit=null`, `git_dirty=true`로 남기고 코드 사본과 파일 해시로 보완한다. 모델의 변경 가능한 별칭을 고정된 가중치 버전이라고 주장하지 않는다. 공개 모델 목록·가격은 참고 메타데이터이며 실제 과금은 응답과 generation 조회로 확인한다.

## 실패·비용·결측값

- `official_resolved=true/false`는 공식 채점 결과다. 채점하지 못한 실행은 `null`로 남긴다.
- `environment_error`, `agent_error`, `evaluation_error`, `evaluation_incomplete`, `no_submission` 등을 보존한다. 집계에서 성공한 실행만 골라 남기지 않는다.
- 공식 보고서의 `tests_status`만으로 완료를 판정하지 않는다. 실제 로그에서 읽은 테스트 수·기대 테스트 누락·채점 프로세스 종료 상태를 확인하고 불완전하면 `evaluation_incomplete`로 기록한다. 모델 패치가 테스트 수집 오류를 낼 수도 있으므로 이를 인프라 실패로 자동 분류하거나 분모에서 빼지 않는다. 공식 점수는 그대로 보존한다.
- 보고된 비용의 합은 `reported_cost_usd`, 전체 요청의 비용 정보 확보 여부는 `cost_complete`다. 응답을 못 받은 요청은 청구 여부도 불명확할 수 있어 비용 0으로 단정하지 않는다.
- `audit_usage.py`의 사후 조회 값과 응답 비용을 비교하되 두 금액을 더하지 않는다. 같은 비용의 별도 확인이다.
- 입력·출력·캐시·추론 토큰은 원본 사용량 필드를 보존한다. 상세 필드가 없으면 `null`이며 0으로 채우지 않는다. 캐시 토큰은 입력 토큰의 부분량이므로 입력 총량에 다시 더하지 않는다.
- 인프라 비용은 현재 측정하지 않아 `null`이다. API 비용에 포함된 것처럼 보고하지 않는다. 앞으로 기억 작성·검색 비용을 별도 단계로 추가한다.
- 보고서의 시각은 UTC 또는 KST를 명시한다. 구조화 JSON의 `now()` 시각과 실행 ID는 UTC다. 라이브러리의 텍스트 디버그 로그에는 실행 환경의 현지 시각(KST)이 표시되기도 하므로 혼용하지 않는다.

## 관측과 해석을 구분한다

진행 노트와 보고서는 다음 순서로 쓴다.

1. **관측:** 실제 판정·명령·시간·비용. 반드시 run ID 또는 원본 경로를 연결한다.
2. **해석:** 관측이 시사하는 범위와 가능한 다른 설명.
3. **가설:** 아직 확인하지 않은 메모리의 작용 원인.
4. **다음 검증:** 기억 삭제·교정, 같은 과제의 반복, 다른 과제·모델 확인 등 구체적인 비교.

모델의 설명이나 추론 텍스트만으로 행동 원인을 확정하지 않는다. 첫 환경 점검의 성공은 연결이 작동한다는 근거이고 모델의 일반 성능이나 메모리 이득의 근거는 아니다. 성공→실패 전환 한 번도 확정된 유해 기억 라벨로 삼지 않는다.

기억 실험에서는 기억 원문·카드 ID·출처 실행·출처 과제·작성 모델·작성 비용·이용 가능한 시점·선택 규칙·검색 점수·입력 위치·내용 해시를 저장한다. `none`, `preload`, `agent_search`, 진단용 `deferred_same`의 전달·조회 기록을 구현했다. 과거 무메모리 run의 원본에는 새 필드를 소급해 채우지 않는다.

## 시작 제공·자율 검색 비교의 기록

현재의 [전달 방식 비교 설계](ai-memory-pilot-reassessment.md)에 따라 다음을 기록한다. 현재 기능 점검에서는 `delivery_mode`로 조건을 구분한다. 내용 교정·재배정 대조를 확장할 때 `content_condition`을 별도로 추가한다. 단어·문자 수를 토큰 수와 혼동하지 않는다.

| 파일 또는 항목 | 추가할 내용 |
| --- | --- |
| `manifest.json`의 기억 설정 | `delivery_mode`, `interface` (`bash_command` 또는 `native_tool`), 저장소 SHA-256·검색기 버전, 과제별 이용 가능 카드 ID, 조회·카드·본문 문자 한도. 배정 순서·seed는 배치 계획에 기록 |
| 사전 선택 기록 | 시작 검색에 쓴 문제 설명·검색어·카드 ID·점수·동률 처리·내용 해시. 같은 카드 대조에 쓸 ID는 평가 실행 전에 고정 |
| `memory-events.jsonl` | 순서, 검색 시작/반환/오류, 자동 검색 또는 에이전트 조회, API 시도 번호·경과 시간, 검색어, 후보·반환 ID와 점수, 빈 결과·한도 초과, 검색 시간·API 비용 |
| 실제 전달 근거 | 반환 원문·해시·절단 여부, 입력 역할·위치, 처음 포함된 `api/*.request.json` 번호, 이후 대화 재전송에 따른 토큰·캐시 사용량 |
| `memory-summary.json` | 요청·실제 검색·빈 결과·형식 오류·한도 초과 횟수, `ever_requested`, `ever_exposed`, 최초 요청 시점, 반환·노출 카드 ID와 본문 문자 수. 카드별 토큰 수는 미측정이며 전체 API 사용량을 별도 기록 |
| 행동 분석 | 명령·파일 수정과 조회의 순서는 원본 궤적에서 확인한다. 자동 원인 라벨러는 미구현이며 후속 코딩 규칙·판정자·불확실성을 함께 보존 |

조회 시작 이벤트를 반환 전에 기록한다. 중단·검색 오류·빈 결과·미조회는 서로 다른 상태다. 조회하지 않은 경우 조회 횟수는 0, 최초 시점·반환 카드·검색 점수는 `null` 또는 빈 목록으로 표현한다. 반환된 내용이 다음 모델 입력에 들어가기 전에 중단됐다면 반환과 노출을 구분한다. `preload`는 에이전트 요청 0회여도 자동 검색·노출이 있을 수 있다.

`ever_exposed`는 카드가 저장된 API 요청 본문에 들어갔다는 뜻이다. 요청·응답 상태를 함께 봐야 하며 실제 주의·이해·행동 활용을 입증하지 않는다. 범위 인덱스는 카드 본문이 아니지만 과거 경험에 관한 정보다. 카드 노출 0과 모든 과거 정보 노출 0을 혼동하지 않는다. 출처의 공식 판정은 생성 모델의 요약과 별도로 원본 결과에서 읽어 표시한다. 카드 본문의 해시와 표시 형식·실제 입력 기록을 함께 보존한다. 본문 상한은 구성의 `max_card_chars`를 따른다. 초기 1,800문자, R02 이후 일부 실행은 1,400문자다. 출처 메타데이터·공통 안내는 그 밖의 입력이므로 최종 요청 사용량으로 비용을 계산한다.

함수 도구 조건에서는 API `tools`의 실제 스키마, `memory_search` 호출의 인수·call ID, 호스트 처리와 동일 call ID의 반환을 보존한다. bash 예약 명령과 함수 도구의 왕복을 별도로 검증한다. 명시적으로 조회를 요구한 연결 점검은 `guided_memory_tool_check` 단계와 `forced_lookup`/`forced_native` 조건으로 구분하고 자율 조회율에 합치지 않는다.

주 비교에는 배정된 전체 실행을 포함하고 검색한 사례만의 점수는 설명용으로 표시한다. 기억의 유익·유해 라벨을 조회 여부나 에이전트의 자기 설명으로 확정하지 않는다. 검색 결과가 달라진 정책 비교, 같은 카드의 조회 시점·선택 비교, 문구 개입 결과를 별도 분석 열로 유지한다. 원본 API 사용량에 이미 들어 있는 기억 입력 비용을 별도 토큰 추정값으로 다시 더하지 않는다. 시작 전 자동 검색의 시간·비용도 총비용에 포함한다.

`runs/audit-*`에는 정답 패치를 사용하는 감사 대조군이 포함될 수 있다. 이 폴더는 모델 경험 실행이 아니며 기억 수집·모델 선정·효과 평가의 데이터 집합에 자동 편입하지 않는다. 원래 실행과 감사 실행의 근거를 분리해 유지한다.

## 후속 측정과 프롬프트 버전

`tool_prompt=any_tool_v1`은 upstream 핵심 요구사항 한 곳의 bash 필수 지시를 바꾼다. 후속 감사에서 다른 위치의 `Provide one or more bash tool calls to execute`가 남아 있음을 발견했다. `any_tool_v2`는 그 한 줄도 사용 가능한 도구 호출로 바꾼 별도 조건이다. 실제 입력에서 두 버전의 차이를 검사하며 과거 v1 실행을 v2 결과로 소급 분류하지 않는다.

중간 패치 측정을 켠 실행은 `[measurement].checkpoint_attempts`에 저장 격자를 고정한다. 저장은 한 모델 응답의 도구 실행이 끝난 뒤 `git diff --binary HEAD`로 수행하며 `commands.jsonl`의 `phase=checkpoint`에 기록한다. 이 명령·출력을 에이전트 메시지에 넣지 않는다. 종료 시점에도 별도 저장한다. 모든 추적 파일의 작업 트리 차이이므로 최종 제출에서 선택한 파일과 다를 수 있고, 미추적 파일은 포함하지 않는다.

`grade_checkpoints.py`는 전체 배치가 완료되기 전에는 실행을 거부한다. 후속 공식 평가는 별도 `runs/audit-checkpoint-*`에 저장하고 기억 출처로 쓰지 않는다. 원본 실패 대조, 최종 제출과 동일한 패치, 동일 과제·이미지·패치의 기존 평가를 재사용하면 그 경로·해시·이유를 기록한다. 중간 채점 실패나 패치 변조를 성공/실패 점수로 조용히 바꾸지 않는다. 저장 시간은 별도 기록하며 API 비용과 인프라 비용을 섞지 않는다.

새 계획의 `core_sha256`이 있으면 실행 전과 각 과제 시작 전에 주요 제어 코드·의존 보조 모듈을 검사한다. 실행별 사본에서도 같은 해시를 대조한다. 프롬프트 문구가 실험 축이면 사전 계획의 정확한 한 줄만 정규화해 다른 기본 입력이 같은지 검사한다. 수신 모델이 실험 축이면 모델 설정은 각 수신 모델 안에서, 나머지 공통 입력·이미지·코드는 전체에서 검사한다.
