# 데이터 품질 문제의 보완 순서와 실행안

2026-11-09. [내용 점검](reports/2026-11-09-data-content-review.md), [추가 품질 감사](reports/2026-11-09-memory-data-quality.md), [전달량·지침 후속](reports/2026-11-09-travel-policy-followup.md)을 함께 검토함.

**해결 방향은 기존 자료의 용도를 구분하고, 주석을 재검토하며, 필요한 판단 구조가 있는 독립 원천을 늘린 뒤, 같은 작업자에서 선택기의 추가 가치를 확인하는 것임.** 기존 자료를 버리거나 수치가 좋아지는 라벨로 바꾸지 않음. 작업자의 계약 점검과 자료 수집·선택기 비교는 병행할 수 있음.

이번 작업은 보완 설계와 **학습 split 한정의 미주석 재검토 묶음 준비**까지임. 새 학습·GPU·worker/API 호출·독립 재주석은 수행하지 않았음.

## 문제별 조치

| 문제 | 조치 | 확인할 산출물/기준 |
| --- | --- | --- |
| 관련성의 모호한 주석 | 기존 라벨·이유·모델 예측을 가리고 다른 검토자가 출처와 현재 관측으로 재판정함 | 구체적인 연결 근거, 출처 충실성, 범주별 이견표. 미확정은 미확정으로 유지 |
| 640쌍 중 양성이 31개인 불균형 | 검토 후 학습에서 부모 가족·라벨 표집을 조정하고 가까운 음성 후보를 추가함 | 전체 후보 은행 평가를 유지하며 양성 재현·정밀도·제공률·집합 확보율을 함께 확인 |
| 문자열·길이 편법 | 정확한 규칙 기준선을 유지하고 관계 합성·부분 누락·예외·시점 전환을 추가함 | 같은 단어/같은 길이에도 정답이 달라지는 쌍과 의미 유지 쌍의 동시 정답 |
| 많은 행·적은 독립 원천 | 새 기억·현재 문제를 먼저 확보하고 가족 분할 후 변형함 | 새 부모 수·저장소/사용자/에피소드 수·변형 수를 별도 보고 |
| 손해 5개와 성공 중심 라벨 | 성공·근거 없는 행동·부적절한 불가능 판단·비용을 별도 저장함 | 실제 결과 벡터와 worker/지침/전달량을 명시한 감독 |
| 작업자의 UNKNOWN 실패 | 작은 계약 진단을 병행하고 주 선택기 비교의 worker를 고정함 | 원문 응답·오류 유형을 보존. 실패를 삭제하거나 정답 응답으로 교체하지 않음 |
| 서로 다른 과제/작업자의 정답 혼합 | task·시점·worker·행동을 버전 계약에 명시함 | 관계와 효용, 4B/9B, 기존/새 지침을 조건 없이 같은 라벨로 합치지 않음 |

검토 후 균형 표집은 학습 신호를 주기 위한 방법임. 양성 복제는 새로운 긍정 원천을 늘리지 못하고 주석 오류도 증폭할 수 있으므로 재판정을 먼저 함. 개발·평가의 전체 후보 은행과 사전 고정한 수집 분포는 유지함. 그 분포가 실제 서비스의 자연 발생 비율이라고 주장하지 않음. 표집을 바꾼 분류 점수를 보정 없이 성공 확률로 해석하지 않음.

## 1. 지금 할 수 있는 재검토

[재검토 묶음](design-data/memory-data-remediation-20261109-v1/README.md)을 준비함.

- 기존 train 양성 18개·미확인 23개·어휘가 겹치는 기존 음성 후보 23개, 총 64개임.
- 현재 이슈 27개·기억 16개를 재사용함. 원래 입력 문자열과 과거 근거를 그대로 보존함.
- 검토자에게는 `review-batch/reviewer/`만 전달함. 기존 정답 대응표는 `maintainer/`에 분리함.
- 판정은 관련성, 원문 충실성, 현재 입력에 이미 있는 정보 여부를 나눔. 실제 유익/유해를 추정 정답으로 쓰지 않음.
- dev/test 현재 문제는 선정하지 않았음. 같은 기억 은행을 공유하는 기존 연구의 범위는 유지함.
- 새 원천·재주석 완료·학습 정답은 모두 0개임. 준비된 양식을 완료한 검증 데이터로 세지 않음.

별도 검토자 두 명의 첫 판정을 서로 보지 않고 받은 뒤, 범주별 일치·혼동·판정 불가 이유를 비교함. 원리의 경계를 바꿔야 한다면 train의 안내를 고친 후 새 검토 묶음에서 확인함. 이견을 제거해 점수만 높이거나 test 결과에 맞춰 정답을 바꾸지 않음. AI만 재판정했다면 사람 이중 검수로 부르지 않음.

수정 결과는 원본 v1을 보존한 새 버전에 두고, original_id·이전 정답·새 판정·변경 이유·검토자·근거를 연결함. 이 64개는 별도 최종 평가가 아니라 주석 기준을 다듬는 train 검토임.

## 2. 추가 수집은 판단 구조를 먼저 정함

초기 확장은 이름·날짜만 바꾼 더 많은 행보다 다음 세 가지를 우선함.

1. **필요한 두 기억을 결합해야 한 답을 낼 수 있는가.** 최신 96상태는 저녁과 숙소가 각각 한 참조를 쓰는 두 출력임. 참조 두 개가 있다는 사실과 한 답의 다단계 추론을 구분함.
2. **현재 조건이 바뀌면 같은 기억의 사용 방법도 바뀌는가.** 과거·현재 가격/정책/버전이 실제로 달라지는 상태를 포함함. 현재 데이터의 가용성 변경과 별도로 구성함.
3. **부족한 근거를 알고 무엇을 확인해야 하는가.** 일부 근거만 있는 경우, 대체 근거가 있는 경우, 현재에 이미 관측된 경우를 구분함.

다음은 설계용 가상 예시임.

| 입력 | 내용 |
| --- | --- |
| 기억 A | 민수가 과거 시점 t0에 H호텔을 선택함 |
| 기억 B | 그때 H호텔의 예약 가격은 180임 |
| 현재 카탈로그 | H는 240, J는 170, K는 210임. 필요한 가격 외 조건은 모두 충족 |
| 현재 요청 | 민수가 당시 지불한 가격 이하인 현재 숙소를 선택함 |

이 조건에서는 A+B로 과거 기준 가격 180을 알아야 J를 선택할 수 있음. A만으로 과거 가격을 알 수 없고, B만으로 민수의 숙소를 식별할 수 없음. 현재 카탈로그가 과거 가격을 대신 제공하지 않도록 함. 원래 가격을 알 수 있는 다른 입력·대체 증명이 있으면 해당 부족 라벨을 다시 계산함.

none/A/B/A+B를 제공하는 비교와, 현재 관측에 A가 이미 있는 비교를 구성할 수 있음. 모든 예산과 입력이 바뀐 버전을 기록함. 이것은 통제 환경에서 새로 정의할 상태이며 실제 사용자의 과거 기록을 발견했다는 뜻은 아님.

가격·버전 수치만 문장에서 바꾸는 증강으로 끝내지 않음. 과거 생성에 사용한 상태와 현재 카탈로그/DB를 함께 고정하고, 각각의 시점·정답을 실행 또는 구조화한 판정으로 검산함. 기존 120가족 v1을 조용히 수정하지 않고 v2에서 계보·이전 분할을 보존함.

새 독립 부모 20–30개에 3–5개 검증된 조건을 붙이는 규모를 첫 제작 목표로 제안함. 이는 설계·수율·비용 확인용이며 통계적 충분성의 보장이 아님. 더 큰 수집은 원천별 수율·가족 변동·관심 효과를 보고 정함.

## 3. 기존 외부 자료는 역할을 나눠 활용함

- **실제 경험의 원천:** 개발 실행 로그, 정제한 Mem2Act, PersonaMem 등에서 주체·범위·갱신·도구 인자에 관한 사례를 확보함. 앞선 조사의 연결 예외·분할 문제를 해결한 버전만 사용함.
- **검증 가능한 추론 보조:** ProofWriter의 누락 전제·증명, MuSiQue-Full의 충분/부족 대조 구조를 참고함. 각 원출처 조건을 확인하고 자연 경험의 실제 효용과 구분함.
- **외부 확인:** LongMemEval 등은 우선 학습과 분리해 보존함. 이미 본 test를 다른 파일 이름으로 독립 확인에 재사용하지 않음. CL-bench 계열은 평가 전용 조건을 유지함.

같은 원천의 파생 벤치·표현·대화 길이를 새로운 원천으로 중복 집계하지 않음. 외부 QA를 섞었다는 사실만으로 기억 선택의 실제 이득이 증명되지는 않음.

## 4. 효용 정답은 하나의 점수보다 결과 벡터로 남김

각 상태·행동에 다음을 저장함.

| 필드 | 의미 |
| --- | --- |
| task_success | 전역 과제를 해결했는가 |
| input_contract_success | 실제로 받은 근거 범위에서 정당한 행동을 했는가 |
| unsupported_specific_action | 근거 없이 구체적인 선택/행동을 했는가 |
| false_infeasibility | 충분한 근거 없이 불가능하다고 답했는가 |
| appropriate_abstention | 근거 부족을 적절히 식별했는가. 과제 성공과 별개임 |
| worker_cost | 입력/출력 토큰·실행·확인 횟수·지연 |
| selector_cost | 검색·인코딩·판독의 비용. 은행 최초 생성과 재사용을 구분 |
| execution_context | worker/revision·지침·decoding·반복·선택 기억·현재 snapshot |

미실행·외부 중단·판정 불가는 null과 상태 코드로 남김. 같은 worker 입력으로 적절히 보류했더라도 은행에 답이 있는데 검색기가 전달하지 않았다면 시스템 과제 실패일 수 있음. 두 판정을 구분함.

초기에는 성공·행동 오류·비용을 각각 예측/보고함. 하나의 보상으로 합친다면 교환 가중치를 개발 자료에서 먼저 정함. 항상 보류하는 정책이 낮은 오류만으로 우수해 보이지 않도록 성공률·제공률·완전 근거 확보율도 함께 봄.

드문 악화를 확보하려고 실행 결과가 나쁜 사례만 사후 선택하지 않음. 사전에 과거/현재 상태 불일치·오래된 수치·충돌·누락·과잉 제공 상황을 정의해 수집하고, 실제로 도움이 된 경우·중립인 경우까지 보존함. 같은 악화 다섯 건의 재표현은 보조 자료이며 새 손해 조건의 증거가 아님.

## 5. 선택기를 비교하면서 작업자 진단을 병행함

추가 품질 감사의 제안처럼 **작업자 하나를 고정하고 선택기들을 같은 계약에서 비교하는 축**을 유지하는 것이 적절함.

- 단순 검색·명시적 규칙·학습 전 0.6B·학습 판독층/LoRA를 기준선으로 둠.
- 고정 4B/9B가 기억 선택을 직접 수행하는 비교는 비용 내에서 별도로 둘 수 있음. 최근 이 모델들의 작업자 역할과 구분함.
- 같은 후보 풀·같은 현재 관측·같은 전달 예산에서 시작하고, 후보 풀 자체의 근거 누락을 따로 기록함.
- 필요한 기억 수가 1–12개인 질문 전체에 항상 상위2만 주지 않음. 상위2는 해당 진단의 비교 정책이며 집합 완전성과 보류를 함께 평가함.
- 선택 결과는 같은 worker에게 전달함. 더 큰 선택기의 좋은 결과를 worker 변경 효과와 섞지 않음.
- 새 데이터의 효과는 모델·학습 예산을 고정한 기존/표현 증강/검증된 추론 증강 비교로 먼저 확인함. layer·loss·worker 변경을 동시에 섞지 않음.

작업자의 UNKNOWN 실패를 모두 해결해야만 선택기 비교를 할 수 있는 것은 아님. 이 실패도 해당 worker의 실제 기억 효과 일부이므로 행을 삭제하지 않음. 작은 계약 점검에서 한 항목/두 항목·주체 혼동·가능/불가능/미확인을 진단하고, 그 결과로 변경한 worker/지침은 새로운 조건으로 고정함.

외부 규칙이 잘못된 출력을 보정하는 시스템도 비교 가능하지만 별도 정책으로 명명함. 원문 응답을 바꾸어 모델의 정답으로 보고하거나 이 효과를 선택기 학습의 이득으로 합산하지 않음.

## 6. 실행 순서와 완료 판단

| 순서 | 수행 | 다음 단계로 넘어갈 근거 |
| --- | --- | --- |
| 1 | 준비한 train 재검토와 라벨 기준 정비 | 근거가 있는 새 판정·이견·미확정·변경 계보가 남음 |
| 2 | 고정 worker/공통 후보 풀에서 기존 선택기 비교; 계약 진단 병행 | 검색 누락·선택 오류·작업자 오류와 비용을 분리할 수 있음 |
| 3 | 새 부모에서 결합·누락·시점 변화 사례 제작 | 실제 상태·시점·정답·대체 근거·분할을 검산함 |
| 4 | 고정 예산의 데이터 구성 비교 | 새 가족에서 표현 증강 이상의 개선이 있는지 확인함 |
| 5 | 개발에서 방법을 정하고 독립 확인 | 남겨둔 test40 또는 별도 외부 원천을 한 번의 확인 절차로 사용함. 조건 변경은 새 버전으로 기록 |

학습 표집을 균형화하는 것과 평가를 균형화하는 것은 다름. 확인 평가는 고정한 후보/수집 분포를 보존하고, 어려운 조건을 모은 진단은 별도 표로 보고함. 불균형 자료의 precision/recall 추정에도 표본 설계를 고려해야 함. [Shang et al., 2023](https://proceedings.mlr.press/v206/shang23a.html).

의미 유지 변형과 정답이 바뀌어야 하는 최소 변형을 나누는 원칙은 [CheckList](https://aclanthology.org/2020.acl-main.442/)와 [Contrast Sets](https://aclanthology.org/2020.findings-emnlp.117/)를 참고함. 이 연구들이 우리 데이터의 효용 향상을 보장하는 것은 아님. 원형과 변형의 동시 정답·의미 유지 일관성·필요 근거의 완전 확보·실제 성공/악화/비용을 차례로 확인함.

이번에 완료한 것은 보완안과 검토 준비임. 데이터 품질 개선·학습 향상·실제 효용 개선을 이미 달성한 결과로 표현하지 않음.
