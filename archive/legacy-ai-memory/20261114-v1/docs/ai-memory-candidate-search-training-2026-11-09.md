# 관계에 기반한 기억 후보 검색의 추가 학습

2026-11-09, 학습 전에 고정한 계획.

## 목적과 자료

기존 판독기를 고정하고 후보 수 확대와 검색용 LoRA의 효과를 구분한다. 이전 결과에서 정답 768개 중 298개가 첫 후보 32개에서 누락됐다. 이는 이미 관찰한 동일 test의 발견이며 이번 회차를 새 독립 확인으로 부르지 않는다.

기본 계획 45개(train/dev/test 30/7/8), 질문 813/189/219개를 그대로 사용한다. 정답은 공개 참조 이력의 명시적 사람·날짜·항목 관계다. 새 경험·새 출처를 추가하지 않는다. 질문–기억 쌍을 늘려도 독립 경험이 늘지는 않는다. 기존 `travel_retrieval/20261109-full-request-v1`의 입력·주석·분할·해시를 유지한다.

## 사전에 고정한 비교

| 구분 | 후보 생성 | 판독 후보 수 | 판독기 | 최종 한도 |
| --- | --- | ---: | --- | ---: |
| 주 A | 기존 BM25+고정 임베딩 RRF | 32 | 이전 LoRA+MLP 고정 | 10기록 |
| 주 B | 같은 기존 RRF | 64 | 같은 판독기 | 10기록 |
| 주 C | BM25+새 검색 LoRA 임베딩 RRF | 32 | 같은 판독기 | 10기록 |
| 보조 D | 고정 임베딩 단독 | 32 | 같은 판독기 | 10기록 |
| 보조 E | 새 검색 LoRA 임베딩 단독 | 32 | 같은 판독기 | 10기록 |

RRF 상수 60을 유지한다. C에서 결합 방식을 바꾸지 않아 A와의 차이를 검색 임베딩 학습에 연결한다. D/E는 결합 방식의 영향을 분리하는 보조 비교이며 test 결과에 따라 주 방법을 바꾸지 않는다. 모든 방법의 후보 합집합을 같은 고정 판독기로 한 번 읽어 공통 후보의 점수가 같게 한다. 후보에 정답을 강제로 삽입하지 않는다. 한도는 기록 개수이며 동일 토큰 수를 보장하지 않는다.

고정 판독기는 `travel-full-request-retrieval-20261109-a100/artifacts/lora-mlp/best`다. 이전 종료·검산 상태와 실제 results.zip의 바이트를 확인하고 adapter·head 해시를 업로드 계약에 고정한다. 학습 optimizer에는 이 판독기를 포함하지 않는다.

## 새로 학습하는 부분

Harrier 0.6B의 원래 고정 revision에서 **검색용 q/v LoRA(rank 8, alpha 16)**를 새로 시작한다. 이전 판독용 adapter를 임베딩에 그대로 적용하지 않는다. 질문과 기억을 각각 인코딩하되 같은 검색 LoRA를 공유한다. 질문은 기존 검색 지시문을 포함하고 문서는 지시문 없이 인코딩한다. 마지막 토큰·L2 정규화·cosine을 사용한다.

질문마다 정답 기억을 모두 포함해 최대 32개 학습 후보를 만든다. 남은 자리의 약 75%는 기존 RRF의 높은 오답, 나머지는 그 질문의 동일 기억 은행에서 무작위로 뽑는다. 후보가 32개보다 적으면 실제 은행 크기만 사용한다. 모든 정답을 음성 표본에서 제외하고, 다른 질문의 기억을 자동 음성으로 쓰지 않는다. ID·분할·주석은 인코더 입력에서 제외한다.

손실은 cosine/0.05의 log-softmax에서 모든 정답에 균등 목표 질량을 주는 다중 정답 순위 손실이다. 판독 점수 증류는 이번 비교에 넣지 않는다. seed 731, 2epoch, LoRA LR 0.0001, gradient clip 1.0을 고정한다. dev 계획별 **learned-hybrid Recall@32**가 가장 높은 첫 checkpoint를 선택한다. 작은 한 번의 학습 점검이며 seed 간 안정성을 검증한 결과는 아니다.

## 평가와 시간

첫 후보의 Recall, 최종 Recall@10, 정답을 전부 찾은 질문 수, 계획별 nDCG를 나눈다. 같은 기본 계획을 묶어 차이를 요약하고, 단일/복수 참조·기억 은행 크기의 조건별 결과를 함께 본다. 이미 노출한 test에서 최종 지표를 계산하되 이를 보고 재학습하거나 설정을 고치지 않는다.

학습 환경에는 test 정답과 정답 제거 변형을 보내지 않는다. 이번 회차는 고정 최대 10개 전달 비교이며 보류 임계값·실제 작업자 득실은 새로 평가하지 않는다. 검색률 향상을 작업 성공으로 치환하지 않는다.

시간 측정은 dev 계획 7개에서 은행 크기의 최소·중앙·최대 질문을 골라 21개로 고정한다. 주 A/B/C의 실행 순서를 질문마다 seed로 섞고 각 방법을 예열한다. GPU 동기화를 사용하며 **질문 토큰화·인코딩 → CPU 검색·RRF → 후보 토큰화·판독 → 상위 10개 정렬**을 독립 실행으로 잰다. 문서 임베딩은 미리 구축하고 모델은 메모리에 올린 상태다. 인덱스 구축·모델 로딩·네트워크·작업자 생성 비용은 별도다. 각 질문/방법 한 번의 측정이며 서비스 운영 지연으로 일반화하지 않는다. 품질 점수는 정해진 배치 인코딩 결과로 계산하고 시간 측정의 선택도 별도로 보존한다.

## 검증과 한도

학습 전에는 다중 정답 표본 보존, train/dev/test 입력 경계, 후보 합집합, T4 사전 거부, 실패·인터럽트 시 자기 Colab 종료를 검사한다. 손실의 정답/오답 방향과 질문·문서 양쪽 gradient도 CPU에서 확인한다.

학습 후 실제 가중치 변화·optimizer·학습 질문 노출 수·고정 판독기 불변을 검산한다. 저장된 임베딩으로 검색 점수, 판독 특징과 실제 head로 확률, 최종 후보·선택·지표를 CPU에서 다시 계산한다. encoder 전체를 CPU에서 재실행하는 검산은 아니다.

Colab A100 한 세션, 학습 스크립트 3,600초·컨트롤러 3,900초 한도. 로컬 GPU와 유료 모델 API는 사용하지 않는다. 중간 checkpoint와 최종 산출물을 회수하고 완료·실패 모두 자기 GPU를 종료한다. 데이터 원본과 이전 실험 출력은 보존한다.
