# 메모리 연구의 수집·증강 방향

**공유 시 현재 방향은 [수집·증강·분류 통합판](ai-memory-data-collection-and-taxonomy-2026-11-08.md)을 먼저 읽는다.** 이 문서의 N/G/F/FP와 12묶음은 검토한 제안으로 보존한다. 첫 내용 비교는 기존 계약의 N/P/P+E/P+G를 유지하고, 작은 파일럿 이후의 데이터 확대·후보 선택·주 평가 시나리오는 통합판을 따른다.

2026-11-08. 현재 수집 코드·주석 분포와 공개 자료·원문을 확인해 다음 데이터 구성안을 정리함. **아래 수집 규모와 실행 비교는 제안임. 새 작업자 호출·학습·GPU 할당은 수행하지 않음.** Notion의 완료 결과와는 구분되는 후속 설계 노트임.

**우선순위는 과거 경험과 현재 문제의 구체적인 재사용 관계를 확보하는 것임. 실제 로그에서 출처를 넓히고, 그 관계를 실행 가능한 조건 대조로 보강하며, 실제 제공 효과가 필요한 부분에 작업자 실행을 집중하는 구성을 권함.** 문장 증강은 그 뒤 표현 견고성을 확인하는 용도로 사용함.

## 1. 현재 병목: 수집 목적과 감독 밀도

- 현재 [수집 코드](../data_pipeline/collect_development_memory_sources.py)는 Parquet 첫 row group에서 저장소·이슈 ID로 30개 저장소를 정하고, 저장소별 앞선 서로 다른 이슈 최대 3개를 확보함. 결과를 보지 않고 출처를 넓힌 장점이 있으나, 같은 원리가 반복되거나 조건이 충돌하는 관계를 충분히 확보하도록 설계한 표집은 아님.
- 마지막 640쌍은 40이슈×16기억의 조합임. 학습 긍정 18쌍은 기억 10개에 분산돼 각 기억당 1–3쌍뿐임. 둘 이상의 현재 저장소에 학습 긍정이 있는 기억은 5개임. 이 수치도 기존의 단일 assistant 주석 기준이며 같은 원리라는 판단을 독립 검증한 결과는 아님. [재집계](design-data/collection-augmentation-20261108/coverage.json).
- 추상적인 공통점으로 연결한 사례와 현재 이슈가 이미 같은 단서를 제공하는 사례가 있음. 관련성·추가 정보·실제 성과 변화의 라벨을 구분해야 함.
- 마지막 640쌍의 실제 효용 라벨은 0개임. 별도의 API 효용 자료와 혼합해 ‘이 640쌍도 득실 정답을 가짐’으로 해석하지 않음.
- 학습 예산도 별도 문제임. 마지막 128 update의 행별 노출은 4–5회였지만 **실제 평가에 선택된 32/64 update checkpoint의 노출은 1–3회**였음. 긴 MLP 적합 진단은 학습 자료만 채점함. 모든 실패를 데이터 부족 하나로 확정하지 않음. [통합 리뷰](../training/memory_selector/reviews/2026-11-08-integrated/README.md).

## 2. 데이터는 세 층으로 수집함

| 층 | 확보할 내용 | 라벨 근거 | 비용·역할 |
| --- | --- | --- | --- |
| 출처 경험 | 실제 명령·응답·수정·검사 범위와 당시 조건 | 원문 위치·ID·SHA, 재현 가능한 관측 | 공개 로그로 넓게 확보함 |
| 관계·적용 조건 | 현재 관측에서 과거 경험의 무엇이 성립·충돌·미확인인지 | 현재 코드·문서·실행 및 독립 주석 | 비교적 넓은 보조 학습 자료로 구성함 |
| 작업자 효용 | 같은 상태에서 기억 제공/보류가 성공·악화·비용을 어떻게 바꾸는지 | 고정 작업자의 실제 생성·실행 | 선택한 소규모부터 측정함 |

출처 실행의 성공을 ‘유익한 기억’, 실패를 ‘유해한 기억’으로 치환하지 않음. 실패 경험의 원인·피해야 할 조건도 유용할 수 있으며, 성공한 과거 절차도 현재에는 부적합할 수 있음. [ReasoningBank](https://github.com/google-research/reasoning-bank)는 성공·실패 경험에서 기억을 구성하는 선례임. 해당 방법이 우리 선택기의 라벨 품질이나 효용을 보증하는 것은 아님.

## 3. 수집 경로와 우선순위

| 경로 | 구체적인 확보 방법 | 우선순위·제약 |
| --- | --- | --- |
| SWE-rebench OpenHands | 이슈·저장소별 로그를 인덱싱하고, 같은 API·설정·모듈·검증 절차를 쓰는 다른 이슈를 연결함 | 주 출처로 사용함. 현재 임의 조합의 낮은 긍정 밀도를 보완함 |
| 같은 저장소의 이전 이슈·PR | 현재 base commit 이전의 수정·테스트·설정 변경을 추적하고 기존 로그와 연결함 | 실제 재사용 맥락을 확보함. 로그가 없으면 PR 기반 사실 기억으로 표시하며 실행 경험을 꾸며내지 않음 |
| SWE-smith | 같은 코드 기반에서 검증된 결함·조건 변형과 tool 형식의 실행 기록을 확보함 | 통제한 적용/충돌 대조를 추가함. 합성 결함·실제 자연 이슈를 구분함 |
| SWE-Gym | 여러 실행과 검사 결과가 있는 과제를 기존 자료와 중복 제거해 보완함 | 실행 환경과 반복 출처의 보조 후보임 |
| 직접 수행한 추가 실행 | 고정된 현재 상태에서 선택 기억·무기억·일반 안내 등을 비교함 | 실제 효용 라벨을 생성함. 원문 수집만으로 대체할 수 없는 비용임 |

[SWE-rebench 카드](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories)는 전체 대화·행동·관측, 이슈 ID, 패치와 종료 정보를 제공함. [SWE-smith](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories)는 실행 기록을 제공하고, [공식 생성 문서](https://swesmith.com/guides/create_instances/)는 코드 변형 후 테스트로 결함을 검증하는 경로를 설명함. [SWE-Gym 자료](https://huggingface.co/datasets/SWE-Gym/OpenHands-Sampled-Trajectories)는 반복 실행 ID·메시지·검사 결과 구조를 제공함. 세 자료 모두 기억의 실제 제공 효과를 바로 정답으로 주는 것은 아님.

공개 HF 메타데이터에 접근 가능함을 다시 확인했으며 revision을 [확인 기록](design-data/collection-augmentation-20261108/source-metadata.json)에 보존함. 새 원본 trajectory는 내려받지 않음. SWE-Gym의 확인한 메타데이터에는 license 값이 없었으므로 파일·원출처의 조건은 별도 확인 대상임.

### 관계를 먼저 찾는 수집 절차

1. **메타데이터 인덱스부터 확장함.** 첫 row group만 사용하는 제한을 풀고 여러 구간에서 저장소·이슈·실행 ID를 확인함. 모든 trajectory 본문을 내려받기 전에 후보 이슈를 정함. 같은 이슈 반복과 다른 포맷 복제를 분리함.
2. **현재 시점의 관측으로 후보를 검색함.** 이슈 설명·현재 base 코드에서 확인 가능한 함수·설정 키·오류·테스트 모듈을 사용함. BM25·임베딩은 후보 제안용이며 관련성 정답으로 사용하지 않음.
3. **같은 주제 안의 차이를 확보함.** 같은 함수라도 버전·옵션·원본 보존 요구가 다른 경우, 같은 오류 이름이지만 원인이 다른 경우를 함께 남김. 무관한 주제만 음성으로 쓰면 조건 판단을 배우기 어려움.
4. **출처와 현재를 근거로 연결함.** 과거의 어느 명령·응답이 현재의 어느 전제를 뒷받침하는지 기록함. 연결이 추상적이거나 정보가 부족하면 미확인으로 둠.
5. **시간과 재현 가능성을 확인함.** 가능한 경우 과거 PR의 merge commit과 target base commit의 이력을 대조함. 이 검사를 하지 않은 쌍은 역사적 전이로 주장하지 않음. 현대 모델로 과거 문제를 재실행한 기록은 실제 과거 시점의 모델 경험과도 구분함.

[MemDev-Bench 원문](https://arxiv.org/html/2610.27524v1)은 같은 저장소의 이전 PR을 찾아 관련성을 주석하고, 실행 가능한 과거 과제로 복원하는 구성을 제시함. 우리의 가까운 수집 선례임. 이번 계획은 그 공식 데이터 패키지를 이미 확보했다고 가정하지 않으며, 같은 구성을 새 기여로 주장하지 않음.

수집용 검색과 선택 입력의 정보 경계를 분리함. target 정답 patch를 주석 검산에 사용했다면 숨은 감독으로 표시하고, 선택 입력·검색 키·과거 기억 내용에 소급해 넣지 않음. 초기 주 경로는 현재에 관측 가능한 정보로 후보를 만드는 것임.

## 4. 먼저 다룰 관계는 구체적인 세 종류로 좁힘

| 관계 | 실제로 수집할 장면 | 함께 확보할 경계 |
| --- | --- | --- |
| 동작·데이터 보존 | 반환값과 원본 변경, null/빈 값, 복사·공유 상태의 차이 | 같은 용어지만 결과가 남는 위치·요구 동작이 다른 경우 |
| 버전·설정 전제 | 현재 버전·옵션에서 유효한 사용법과 수정 절차 | 이전 방식이 바뀐 경우, 이미 전제가 충족된 경우 |
| 검증 근거의 범위 | 어떤 검사·옵션·환경이 무엇을 확인했는지 | 좁은 검사 통과, 다른 변경 범위, 수집 성공과 실행 성공의 차이 |

초기화·설치에만 집중하지 않음. 같은 종류의 관계가 여러 출처에서 반복되도록 확보함. 문서·로그의 표현이 비슷하다는 이유만으로 서로 다른 메커니즘을 하나의 긍정 범주에 묶지 않음.

## 5. 증강 방향: 표현, 조건, 기억 조각을 구분함

| 증강 | 바꾸는 것 | 고정·검증할 것 | 주 용도 |
| --- | --- | --- | --- |
| 표현 변경 | 문장·순서·서술형/지시형 | 사실·함수명·조건·검증 범위의 동일성 | 표현 견고성과 전달 방식 비교 |
| 현재 조건 변경 | 버전·옵션·요구 동작·완료 상태 | 실제 코드·환경도 그 조건을 만족하는지 실행 확인 | 같은 기억의 적용/충돌 판단 |
| 관측 일부 제거 | 판단에 필요한 현재 정보의 공개 범위 | 남은 정보만으로 결론을 낼 수 있는지 재검토 | 미확인·추가 확인 판단 |
| 기억 조각 포함/제거 | 관측·처방·적용 조건·검증 근거 | 같은 출처에서 해당 조각이 실제로 있었는지 | 정보 보존과 실제 효과 분석 |
| 판단 시점 변경 | 문제 시작, 첫 재현 실패 뒤, 수정 후 검증 전 | 기억 제공 전에 동결한 상태와 관측 이력 | 언제 기억이 필요한지 분석 |
| 새 출처 추가 | 같은 원리가 나타나는 다른 코드·저장소 | 관계 근거와 분할 | 실제 출처 일반화 검증 |

**우선 권하는 증강은 현재 조건 변경과 기억 조각의 포함/제거임.** API·Django에서 이미 작은 형태로 수행했으므로, 다음 목표는 같은 템플릿의 행 수를 늘리는 것과 함께 실제 출처·관계의 폭을 확보하는 것임. 표현 변경만으로 독립 경험이 늘었다고 세지 않음.

### 예: 같은 기억과 달라지는 현재 조건

기억은 ‘복사본에 작업하고 복사본을 반환한 과거 절차’로 고정함.

| 현재 조건 | 확인할 관계 |
| --- | --- |
| 작업이 복사본을 직접 바꾸며 원본 보존이 목표임 | 직접 재사용 가능한지 실행으로 확인함 |
| 작업이 새 결과를 반환하고 복사본 자체는 그대로임 | 반환값을 버리는 절차가 현재 요구와 충돌하는지 확인함 |
| 현재 작업의 반환·변경 동작을 알 수 없음 | 관측이 부족한지 판단함 |

이 표의 직접 적용성은 이미 유사한 API 진단에서 다룬 관계임. 실제 작업자가 기억을 수정·무시할 수 있으므로 ‘적용 가능=이득’, ‘충돌=손해’로 자동 라벨링하지 않음. 새 출처에서의 실제 득실은 제공/보류 실행으로 측정함.

### 문헌에서 가져올 검증 원칙

[Counterfactually-Augmented Data](https://arxiv.org/abs/1909.12434)는 라벨이 달라지는 최소 수정과 내부 일관성을 요구하는 선례임. [CheckList](https://aclanthology.org/2020.acl-main.442/)는 바뀌지 않아야 할 판단과 바뀌어야 할 판단을 나눠 테스트하는 선례임. 두 연구가 코드 메모리의 실제 효용 증강을 입증한 것은 아니며, 여기서는 데이터 생성·검사 원칙에 적용함.

- 표현만 바꾸면 관계 라벨이 유지되는지 검사함. 코드·숫자·검사 범위가 바뀌면 단순 바꿔쓰기로 처리하지 않음.
- 현재 조건을 바꾸면 환경·코드도 함께 바꾸어 실행으로 확인함. 문장에 버전이나 옵션만 바꾸고 실제 환경을 그대로 두지 않음.
- 정보를 지워도 다른 관측으로 판단 가능하면 라벨을 유지함. 삭제했다는 이유만으로 모두 미확인으로 바꾸지 않음.
- 기억의 조건을 삭제했다고 실제 효용이 반드시 악화되는 것은 아님. 내용 개입의 효과는 재측정함.
- 서술형/지시형 비교는 주장 목록을 맞추고 길이·위치를 통제함. 새 함수명·진단법·검사 정보를 추가하면 표현 효과와 정보 추가 효과를 구분함.

## 6. LLM과 자동 검증의 역할

**LLM은 출처 단위 추출·후보 쌍 제안·표현 변형에 사용함. 실행 근거와 실제 득실 정답은 별도 확인함.**

- 각 기억을 관측 사실, 당시 전제, 수행한 행동, 검증 범위, 실패한 대안으로 구조화함. 원문 offset·call ID·SHA를 연결함.
- 외부 근거가 있는 필드와 작성자의 해석을 구분함. ‘명령 성공’, ‘일부 검사 통과’, ‘문제 해결’을 합치지 않음.
- 현재 학습 긍정 18쌍과 논쟁적인 연결부터 독립 검토를 받는 것이 효율적임. 새 핵심 긍정·가까운 음성·미확인 사례도 독립 검토하고 불일치를 기록함.
- 이후에는 모델·검색·규칙 간 불일치가 큰 **학습 후보**를 우선 검토할 수 있음. 별도의 미사용 평가 풀에는 이 선택 규칙을 적용하지 않음.
- 교사의 설명만으로 실제 이득·손해를 생성하지 않음. 큰 작업자의 성공을 작은 작업자의 효용 정답으로 복제하지 않음.

## 7. 실제 효용 수집을 줄이되 필요한 비교는 확보함

먼저 싼 관계 검산·코드 재현으로 자료를 점검하고, 재현 가능한 묶음에 작업자 실행을 붙임. 문제를 못 푸는 환경 오류와 모델의 오류를 구분하기 위해 원본·기대 수정·무동작 대조를 선행함.

초기 비교안은 다음 네 조건임.

| 조건 | 제공 내용 | 볼 수 있는 것 |
| --- | --- | --- |
| N | 과거 기억 없음 | 작업자의 기본 능력 |
| G | 일반적인 현재 상태 확인 안내 | 과거 경험 고유 정보와 일반 안내의 차이 |
| F | 실제 출처의 관측·적용 조건 | 과거 사실이 추가하는 효과 |
| FP | F + 당시의 구체적인 행동 절차 | 처방 묶음의 추가 효과 |

F→FP는 정보와 길이도 바뀌는 묶음 비교임. 순수한 지시형 문체 효과로 부르지 않음. 이후 후보 기억이 여러 개 확보되면, 같은 상태에서 가까운 다른 기억도 배정해 선택기 자료로 확장함. 전체 기억과 개발에서 고른 고정 기억도 정책 기준선으로 유지함.

효용 라벨은 worker ID·설정·예산·입력 상태를 포함한 관측으로 저장함. 한 번의 greedy 실행은 그 고정 프로토콜의 관측임. 반복 성공 확률을 추정하려면 별도의 확률적 반복 설계를 적용함. 동일 greedy 재생성을 독립 경험이나 효과의 통계적 반복으로 세지 않음.

판단 시점을 늘릴 때는 무기억 발견 실행이나 고정된 절차의 prefix에서 상태를 동결하고, 그 복제본을 각 조건에 제공함. 기억을 받은 실행의 사후 상태를 공통 시작점으로 사용하지 않음. 오류 뒤 상태만 모은 자료는 오류 조건부 진단이며 전체 SWE 시작 시점 성적으로 바꾸지 않음.

## 8. 분할과 평가를 수집 전에 정함

- 같은 이슈 반복·공통 결함/PR 가족·모든 증강 자식은 한 분할에 둠. 파생 자료를 만든 뒤 행 단위로 무작위 분할하지 않음.
- **새 경험·새 저장소 전이**를 주 평가로 삼는다면 출처 기억 은행도 분할별로 분리함. **같은 은행에서 새 문제 선택**은 별도의 현실적인 평가 설정으로 보고함. 같은 은행을 공유하면서 새 기억에 대한 일반화라고 주장하지 않음.
- 관련 후보를 풍부하게 찾는 학습 수집과, 실제 분포를 관찰하는 평가 수집을 구분함. 학습용의 긍정 비율을 실제 발생 비율로 해석하지 않음.
- 현재 이슈의 선택은 결과 전 기준으로 고정함. 실제로 개선된 상태만 사후에 남겨 ‘선택이 필요한 benchmark’를 만들지 않음. 모든 행동이 같거나 간단한 규칙으로 충분한 사례도 보존함.
- 학습·개발에서 고정 행동과 관측 oracle의 간격을 점검함. 간격이 작으면 성공 수로 복잡한 선택기의 필요성을 검증하기 어렵다고 보고함. 확인 결과를 보고 유리한 과제만 교체하지 않음.

수집의 성과는 원문 후보→근거 연결→주석 검토→실행 재현→효용 측정으로 나누어 집계함. 출처·현재 이슈·관계 묶음·변형 행 수를 각각 보고함. 기억 ID별 학습 긍정 수와 이를 뒷받침하는 출처 폭도 함께 봄.

## 9. 권하는 첫 회차

1. **기존 긍정 18쌍과 논쟁적인 사례를 재검토함.** 라벨을 사후 수정해 기존 평가를 다시 승리로 만들지 않고, 검토 결과를 다음 버전에 반영함.
2. **과거 경험→현재 문제 연결 12묶음을 구성하는 소규모 수집을 제안함.** 최소 6개 저장소와 위 세 관계 유형을 포함하는 작업 목표임. 통계적 검증에 충분하다는 표본 수 계산은 아니며, 같은 저장소의 묶음도 독립이라고 가정하지 않음.
3. **각 묶음에 자연 상태와 근거 있는 조건 변형을 확보함.** 자연 로그·재구성·합성 변형을 구분함. 먼저 관계 주석과 재현 가능성을 확인함.
4. **재현을 통과한 상태에 N/G/F/FP를 비교함.** 예를 들어 12묶음×2상태×4조건이면 96개 작업자 실행임. 이는 계획의 상한 예시이며 내부 모델 요청 수와 같지 않음. 실제 실험 범위·비용을 산정한 뒤 실행함.
5. **선택기의 학습과 독립 확인은 다음 단계로 둠.** 이번 작은 묶음은 수집·주석·효용 수집의 작동 여부와 수율을 확인하는 발견용임. 실행 뒤 효과가 큰 사례만 골라 확인 집합으로 재사용하지 않음.

이후 증강의 효과는 같은 고정 학습 방식에서 `원자료만 / 표현 증강 / 조건 대조 증강 / 새 출처 추가`를 비교함. 표현·조건 비교는 원형 출처를 맞추고, 새 출처 추가는 출처 수가 변한 비교로 명시함. 학습 계산량과 행 노출·적합을 함께 확인하고, 별도 새 확인 가족에서 관계 판독·선택·실제 효용을 순서대로 평가함. 학습 자료를 더 잘 맞힌 것만으로 증강의 일반화 효과를 판단하지 않음.
