# 외부 공개 자료에서 가져올 것과 준비한 지식 갱신 대조 자료

2026-11-11. 실험을 수행하지 않는 별도 검토 세션(Claude Code)이 작성함. 공유받은 PDF 두 개를 검토한 결과에서 이 연구가 가져올 내용·기법·자료를 정리하고, 그중 바로 쓸 수 있는 자료를 평가와 학습에 넣을 수 있는 형태로 준비함. 새 작업자 호출·GPU 할당·학습은 없었음.

**핵심: “현재 상태에 맞지 않는 기억이 이미 되던 성공을 깨뜨린다”는 파일럿 결과를 공개 자연어 자료에서 다시 잴 수 있도록 168문항의 대조 자료, 작업자 입력 1,206개, 문자열 채점기를 준비함.** 실행은 하지 않았으므로 결과는 없음. 작업자가 이 문항들을 근거를 받고 푸는지도 아직 모름.

이 작업은 별도 worktree(`worktree-external-memory-updates` 가지)에서 만들었고, 새 파일만 추가하는 커밋 하나로 main에 합쳤음. 기존 파일은 바꾸지 않았으며 로컬 GPU와 Colab은 쓰지 않았음.

PDF의 사실 확인과 근거는 `docs/reports/2026-11-11-shared-pdf-review.md`에 정리했음. 그 보고서와 PDF 원본은 커밋하지 않은 로컬 파일이라 이 저장소에는 없음.

## 1. 가져올 내용

실험 없이 설명과 보고에 바로 쓸 수 있는 것임.

- **보고의 틀.** 기억 벤치마크의 표준 절차는 주입 → 선택 → 답변 → 채점의 네 단계임. 이 연구는 선택만 바꾸고 나머지를 고정한 실험임. 표준 절차에는 기억 없이 풀었을 때의 결과와 기억 때문에 틀린 수가 없고, 이 둘을 잰 것이 이 연구가 더한 부분임.
- **선행연구 대비 위치.** Mem0와 Memory-R1은 바뀐 정보를 저장할 때 고쳐 쓰거나 지워 낡은 기억의 피해를 막음. 이 연구가 잰 손해는 그 정리가 없을 때 치르는 비용의 크기에 해당함. 같은 문제를 저장할 때가 아니라 줄 때 고르는 쪽에서 다룸.
- **가장 가까운 선행연구.** Memory-R1은 후보 기억에서 쓸 것을 고른 뒤 답하게 하고 최종 답의 정확 일치만 보상으로 학습함. 고르는 주체가 답하는 모델 자신임. 작업자를 고정하고 작은 선택 모델을 따로 학습한 이 연구의 부정 결과에는 이 차이를 조건으로 붙여야 함.
- **라벨의 출처.** Self-RAG의 “검색할까” 라벨은 GPT-4의 판단임. 이 연구의 라벨은 같은 작업자에게 기억을 줬을 때와 안 줬을 때의 실제 결과임.
- **채점 형식.** BEAM은 문항마다 “이 값을 말해야 함”이라는 짧은 기준을 둠. 자유 서술 답을 심판 모델 없이 채점할 때 이 형식을 쓸 수 있고, 아래 자료가 그렇게 채점함.

## 4. 준비한 자료

위치는 [`datasets/external_memory_updates/20261111-v1`](../datasets/external_memory_updates/20261111-v1/README.md)임. 파일별 설명, 제외 사유, 명령은 그 README에 있음.

### 4.1 무엇을 비교하는가

지식 갱신 문항은 같은 사실에 대해 옛 값을 말한 발화와 새 값을 말한 발화가 있고 질문은 지금의 값을 물음. 예: “Git 저장소의 main 가지에 병합된 커밋은 몇 개인가”에 대해 옛 발화는 150, 새 발화는 165임.

| 조건 | 현재 대화에 보이는 것 | 과거 기록으로 주는 것 | 보는 것 |
| --- | --- | --- | --- |
| `none` | — | — | 기억 없이 맞히는가(추측·자료 노출 점검) |
| `new_only` | — | 새 근거 | 맞는 기억을 받으면 푸는가(작업자 능력) |
| `old_only` | — | 옛 근거 | 낡은 기억만 받으면 옛 값을 답하는가 |
| `both` | — | 옛 근거와 새 근거 | 둘을 함께 받으면 최신 값을 고르는가 |
| `current_new` | 새 근거 | — | 이미 답을 아는 상태의 기준 |
| `current_new_plus_old` | 새 근거 | 옛 근거 | **낡은 기억이 그 성공을 깨뜨리는가** |
| `lexical_top2` | — | 어휘 순위 상위 2개 | 단순 검색 정책 |
| `latest_of_top2` | — | 그 2개 중 더 나중 것 | 최신 기록 규칙 |

`current_new` → `current_new_plus_old`가 파일럿의 손해 조건과 같은 구조임. 파일럿에서는 현재 관측에 정답 근거가 다 있는 6가족 중 4가족에서 맞지 않는 기록이 성공을 깨뜨렸음([상태별 수집 파일럿](reports/2026-11-11-memory-state-screen.md)).

### 4.2 규모와 분할

| 분할 | 문항 | 독립 단위 | 숫자 정답 문항(단위) | 옛 값이 정의된 문항 | 근거 조건 6개의 호출 |
| --- | ---: | --- | --- | ---: | ---: |
| longmemeval_s/design | 47 | 문항 47 | 33 (33) | 0 | 282 |
| beam/train | 28 | 대화 19 | 22 (17) | 17 | 168 |
| beam/dev | 29 | 대화 18 | 23 (17) | 18 | 174 |
| beam/confirm | 64 | 대화 44 | 44 (31) | 35 | 384 |

- `design`은 이미 결과를 본 LongMemEval-S임. 지시문·조건·채점 규칙을 정하고 예행하는 데만 씀.
- BEAM은 대화 단위로 나눴음. 한 대화의 두 문항은 같은 분할에 있음. 크기별로 대화 ID의 해시 순서에 따라 confirm·confirm·train·dev를 반복 배정했으므로 결과와 무관함.
- `confirm`은 한 번의 확인 실행에만 씀. 그 전에 confirm의 작업자 출력을 보지 않음.
- `train`과 `dev`는 선택 모델 학습이나 추가 예행에 씀. 학습에 쓰지 않는다면 예행에 합쳐도 됨.

### 4.3 포함 규칙

원 문항 252개 중 168개를 썼음. 규칙은 모두 원 자료의 내용만 보고 정했고 작업자 출력을 보지 않았음.

- BEAM: 옛 정보와 새 정보의 발화 ID가 따로 있고 겹치지 않으며, 채점 기준이 5낱말 이하의 값 하나임.
- LongMemEval-S: 두 근거 세션 모두에 표시된 발화가 있고, 정답이 5낱말 이하임.
- 공통: 새 근거에 정답 값이 있고 옛 근거에는 없음. 옛 발화가 새 발화보다 앞섬. 근거 발화가 512토큰 이하임.

BEAM의 근거 표시에는 잡음이 있었음. 표시된 새 발화에 답이 없는 문항이 14개였고 모두 제외함. 예를 들어 “웨비나가 언제로 바뀌었는지 다시 알려 달라”는 발화가 새 근거로 표시돼 있었음.

### 4.4 채점

성공은 답에 정답 값이 있는지로 정함. 심판 모델을 쓰지 않으므로 같은 출력은 항상 같은 점수를 받음.

- 숫자 하나짜리 정답(122문항)이 가장 믿을 만함. `165`는 `1650`이나 `165.5` 안에서는 인정하지 않음.
- 날짜·시각·여러 숫자 정답(41문항)은 해당 토큰이 모두 있어야 성공임. 표현이 조금 달라도 실패가 될 수 있음.
- 구절 정답(5문항, LongMemEval-S)은 구절 전체가 있어야 함.
- 옛 값을 답했는지는 BEAM 70문항에서만 가릴 수 있음. 원 자료의 혼동 설명에 나온 옛 숫자가 옛 근거에 있고 새 근거에 없을 때만 넣었고, 70건 모두 설명과 대조해 확인함. LongMemEval-S에서는 옛 값을 추정하지 않음. 옛 근거에만 있는 숫자를 옛 값으로 잡으면 틀리는 사례가 있었음(“10명 중 절반이 여성”).

주 분석은 숫자 정답 문항으로 하고 나머지는 보조로 두는 것을 권함.

## 5. 평가에 쓰는 순서

실행은 실험 에이전트나 사용자가 정함. 아래는 권하는 순서임.

1. **예행(design, 282호출).** 작업자 능력과 채점기를 점검함.
   - `new_only` 성공이 낮으면 이 자료는 선택이 아니라 작업자 한계를 재게 됨. 이전 가격 비교 요청에서 같은 문제가 있었음.
   - `none` 성공이 0에 가까워야 함. 높으면 추측이 가능하거나 작업자가 학습 중에 본 자료일 수 있음.
   - 출력 표본을 사람이 읽고 문자열 채점과 비교함.
2. **규칙 고정.** 지시문, 조건, 채점 규칙, 주 분석 대상(숫자 정답), 통과 기준, 통과했을 때와 미달했을 때 쓸 문장을 confirm 실행 전에 적어 둠.
3. **확인(beam/confirm, 384호출).** 한 번 실행함. 결과를 본 뒤 지시문·조건·채점을 바꿔 다시 하지 않음.
4. **읽기.** 채점기의 `old_record_breaks_current_statement`가 주 결과임. `current_new`에서 맞힌 문항 중 `current_new_plus_old`에서 틀린 문항 수와, 그런 문항이 하나라도 있는 대화의 비율과 95% 구간을 냄.

```bash
# 업로드 폴더(메시지만)
python -m data_pipeline.prepare_external_updates export \
  --data datasets/external_memory_updates/20261111-v1 --output <업로드 폴더> \
  --worker-provenance datasets/memory_state_screen/20261111-v2/source-provenance.json \
  --split design --condition none new_only old_only both current_new current_new_plus_old

# 작업자 실행 (Colab L4, 기존 작업자 그대로)
python training/memory_selector/run_external_updates_colab.py --data <업로드 폴더> --output <실행 폴더>

# 채점
python -m evaluation.external_updates \
  --data datasets/external_memory_updates/20261111-v1 \
  --predictions <실행 폴더>/artifacts/predictions.jsonl --answer-kind number
```

- 업로드 폴더는 기존 실행과 같은 구성임(`inputs.jsonl`, `config.json`, `worker-provenance.json`, `input-manifest.json`). 작업자는 Qwen3.5-9B의 같은 revision, greedy, 출력 64토큰임.
- **실행 진입점 세 파일은 Colab에서 실행해 보지 않았음.** `run_external_updates.py`, `run_external_updates_colab.py`, `external_updates_bootstrap.py`는 상태 대조 파일럿의 파일을 본떠 이름과 시간 상한만 바꾼 것임. 입력 검증([프로토콜](../training/memory_selector/external_updates_protocol.py))은 CPU 테스트로 확인함.
- 입력은 중앙 215토큰, 최대 866토큰임(지시문 포함, 채팅 틀 제외). 파일럿의 실제 속도는 입력 약 1,000토큰에서 호출당 1.76초였음. 출력이 더 길 수 있어 호출당 2–3초로 잡으면 예행 282호출은 10–15분, 확인 384호출은 13–20분임(추정).

## 6. 학습에 쓰는 방법

- `selector-inputs.jsonl`은 (질문, 후보 기록) 1,451행이고 `selector-labels.jsonl`에 같은 순서로 역할과 `needed`가 있음. 새 근거만 `needed=1`임.

| 분할 | 행 | 새 근거 | 옛 근거 | 방해 기록 |
| --- | ---: | ---: | ---: | ---: |
| longmemeval_s/design | 377 | 47 | 48 | 282 |
| beam/train | 258 | 36 | 54 | 168 |
| beam/dev | 246 | 31 | 41 | 174 |
| beam/confirm | 570 | 71 | 115 | 384 |

- 이 라벨은 “이 기록이 지금 질문의 답에 필요한가”라는 관계 라벨임. 기록을 줬을 때의 효과를 잰 값이 아님. 실제 성공·손해 라벨은 작업자를 실행한 뒤 `decisions.jsonl`의 조건별 결과에서 만들어야 함.
- 옛 근거는 질문과 가장 비슷하면서 필요하지 않은 기록임. 어휘 순위만으로는 새 근거가 상위 2개에 드는 문항이 BEAM 121개 중 65개, 옛 근거가 드는 문항이 65개임. 관련성만 보는 선택으로는 둘을 가르지 못하는 자료임.
- 학습에는 `design`, `train`, `dev`만 씀. `confirm`의 라벨을 학습이나 방법 선택에 쓰면 확인 자료로 쓸 수 없음.
- 규모가 작음. 학습 가능한 새 근거가 114행(design 47, train 36, dev 31)임. 여행 자료로 학습한 모델이 이 자료로 옮겨 가는지 보는 평가용으로 먼저 쓰는 것이 맞음.

## 7. 한계와 확인하지 못한 것

- 작업자를 한 번도 실행하지 않았음. 5절의 순서는 제안이며 결과가 아님.
- 실행 진입점 세 파일은 GPU에서 실행해 보지 않았음.
- 문자열 채점은 심판 모델 채점과 다를 수 있음. LongMemEval의 공식 채점은 심판 모델이고, BEAM의 공식 채점도 기준별 심판 점수임. 이 자료의 점수를 두 벤치마크의 공식 점수와 비교하면 안 됨.
- BEAM의 시간 표지는 대화 구간 단위라 옛 기록과 새 기록의 날짜가 같은 경우가 많음. 순서는 기록 번호와 지시문으로만 전달됨.
- 방해 기록에 원 자료가 표시하지 않은 더 이전 값이 들어 있을 수 있음.
- `current_new` 조건은 새 근거 발화를 현재 대화로 옮겨 만든 통제 개입임. 자연 발생한 대화 상태가 아님.
- BEAM 10M 크기와 BEAM의 다른 능력은 넣지 않았음.
- 지시문은 “가장 최근 진술이 현재 사실”이라고 알려 줌. 이 문장을 빼면 손해가 더 커질 수 있고, 그 비교는 준비하지 않았음.
