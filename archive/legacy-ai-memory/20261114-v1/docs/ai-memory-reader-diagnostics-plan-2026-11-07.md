# 기존 성과 재검토와 세 가지 관계 판독 실험

2026-11-07 · 실험 설계 v0.3 · 역할 구별 진단 완료, 자료 보강 후 재학습 설계

**기존 LoRA의 개선이 어떤 사례에서 생겼는지 먼저 확인하고, 판독층·두 입력의 비교 방식·표현 층을 차례로 진단한다.** 작은 모델이 관계를 배울 수 있다는 신호를 더 명확히 해석하고, 다음 추가 학습에 필요한 구조와 자료를 정하는 것이 목적이다.

저장 예측의 CPU 재집계, 추가 분석의 재검산, 라벨·손실 연결 점검에 이어 **원래 모델 재현·18행 단독/공동 학습·새 통제 96행 평가까지 완료**했다. 공동 모델은 학습 18/18이 가능했지만 통제 21/96·핵심 0/24로 일반화에 실패했다. [실행 결과와 재학습 조건](../training/memory_selector/reports/2026-11-07-scope-role-diagnostic.md)을 먼저 확인한다. 아래 선형/MLP 비교, joint 인코딩, 중간층 추출은 아직 실행 계획이다. [전체 데이터·모델 확대 계획](ai-memory-data-and-model-next-steps-2026-11-07.md)의 작은 모델 실험을 구체화한다.

| 순서 | 질문 | 비교 | 다음 결정 |
| --- | --- | --- | --- |
| 먼저 | 기존 LoRA가 두 관계를 구별하는가 | 저장 예측 분해 → 18행 학습 가능성 → 기존 모델의 조건·표현 변화 검사 | 개선의 범위와 필요한 새 자료 |
| 실험 1 | 복잡한 판독층이 필요한가 | 같은 특징의 선형 판독기와 MLP | 단순한 head로 충분한지 |
| 실험 2 | 두 내용을 비교하는 방식이 제한인가 | 별도 인코딩과 함께 읽기, 각각 고정/LoRA | 추가 학습할 입력 구조 |
| 실험 3 | 어느 층에서 관계를 잘 읽을 수 있는가 | 소수 중간층과 마지막 층의 선형 판독 | 사용할 표현과 후속 학습 위치 |

## 0 기존 성과부터 깊게 확인한다

### 이미 확인된 것과 아직 남은 것

[독립 검토](../training/memory_selector/reviews/2026-11-07-followup/README.md)는 실제 가중치 변화, optimizer 업데이트, 감독 노출, 저장 예측과 집계를 확인했다. **어떤 조건을 이용해서 정답이 늘었는가**를 다음 질문으로 삼았다. LoRA 전체 encoder forward는 그 검토에 포함되지 않았으므로, 이번 새 Colab 실행에서 원래 세 모델을 로드해 270행·540개 출력을 재현했다. 원래 argmax가 모두 일치했다.

기존 범위 과제는 두 출력, 즉 요청한 범위와 기억의 일치 여부 및 이미 검사한 범위와의 중복 여부를 평가한다. 저장된 개발 예측을 재집계하면 다음과 같다. 각 셀은 두 출력을 모두 맞힌 행 수다.

| 개발 하위 집단 | 행 수 | 고정 표현과 MLP | LoRA와 MLP | LoRA와 상태 대조 손실 |
| --- | ---: | ---: | ---: | ---: |
| 전체 | 72 | 26 | 48 | 50 |
| 두 관계 모두 알려짐 | 32 | 5 | 13 | 14 |
| 한 관계만 미확인 | 32 | 13 | 27 | 28 |
| 두 관계 모두 미확인 | 8 | 8 | 8 | 8 |

LoRA는 고정 모델보다 **22행을 새로 맞혔고 기존에 맞힌 행을 잃지 않았다.** 개선 22행 중 8행은 두 관계가 모두 알려진 경우, 14행은 한 관계만 미확인인 경우다. 후자의 행에도 알려진 관계 하나가 있으므로 14행 전부를 미확인 표현 학습으로 해석하지 않는다. 상태 대조 손실의 추가 개선은 2행이며 각 하위 집단에서 1행씩이다. 이는 같은 두 개발 출처의 사후 분해이며 독립 반복 결과가 아니다.

[집계와 변경 사례 ID](reports/data/reader-diagnostics-20261107/scope-gain-breakdown.json) · [읽기 전용 재집계 코드](reports/data/reader-diagnostics-20261107/recompute_scope_gains.py)

개선의 의미를 제한하는 근거도 함께 유지한다.

- 내부 범위 필드를 추출해 길이만 비교하는 사후 규칙은 개발 72행을 모두 맞혔다. 모델이 그 규칙을 사용했다는 증거는 아니지만, 개발 성적만으로 의미 비교를 입증할 수 없다.
- 학습 서식 A에서 새 서식 B로 바꾸면 LoRA와 대조 손실 구성 모두 동시 정답률이 22.2%p 낮아졌다.
- 자연 관계 74행의 고정 Harrier는 전체 입력과 현재 상태만이 각각 38/74였다. 전체 입력에서 정답으로 바뀐 3행과 오답으로 바뀐 3행을 별도로 봐야 한다. 이 실험은 앞의 범위 LoRA를 전이한 결과가 아니다.

### 먼저 할 검사는 기존 모델을 고정한 입력 대조다

**추가 분석에 따른 우선순위 조정:** 아래 입력 대조를 넓히기 전에, 기존 작은 학습 집합에서 두 관계를 동시에 맞힐 수 있는지부터 확인한다. 다음 하위 집단이 전체 점수의 해석을 바꾼다.

| 조건 | 학습 LoRA | 학습 LoRA와 대조 | 개발 LoRA | 개발 LoRA와 대조 |
| --- | ---: | ---: | ---: | ---: |
| 알려진 요청·완료 범위가 같음 | 36/36 | 36/36 | 12/16 | 13/16 |
| 알려진 요청·완료 범위가 다름 | 1/36 | 0/36 | 1/16 | 1/16 |
| 하나 이상의 관계가 미확인 | 90/90 | 90/90 | 35/40 | 36/40 |

이 수치를 원본 `upload.zip`의 행과 저장 예측에서 별도로 재계산했다. 앞서 확인한 알려진 두 관계의 개선 8행은 요청·완료 범위가 같은 집단의 7행과 서로 다른 집단의 1행이다. 따라서 그 개선만으로 두 관계의 역할을 독립적으로 충분히 배웠다고 말할 수 없다. 새 문제로의 전이 이전에 학습 집합 안의 특정 조합을 해결하지 못하고 있다.

[성과 분해 보고서](../training/memory_selector/reviews/2026-11-07-performance-analysis/README.md)의 읽기 전용 `analyze.py --check`도 통과했다. 자연 관계에서 같은 head의 기억 특징 제거 37/74 → 전체 특징 38/74, 개선 5행·악화 4행을 재현했다. 별도 확인에서는 제거된 특징이 기억 벡터·곱·절댓값 차이·기억 길이이고, 현재 벡터와 현재 길이는 그대로임을 확인했다. 입력 분포가 바뀌는 진단이며 실제 기억 효용은 아니다.

### 구현 점검의 범위와 다음 작은 학습

실행 당시 `train_scope.py`, `prepare_scope_pilot.py`, `train_aux.py`의 archive 바이트·실행 기록 해시·현재 코드가 일치했다. 라벨과 CE의 행/출력 순서, 대조 쌍의 방향, 반대쪽 필드가 고정되는 조건을 확인했다. 어려운 학습 36행도 각각 6회 노출됐고, 각 미니배치에서 양쪽 출력의 대조 쌍에 모두 포함됐다.

원래 대조 함수의 배열 연산을 NumPy로 실행해 정답 로짓의 손실 0, 반대 로짓의 양의 손실, 명시적 식과의 일치를 확인했다. 수치 미분과 수식의 최대 차이는 약 `2.33e-11`이었다. 이는 CPU에서 식의 부호와 인덱스를 점검한 것이며 Torch autograd나 LoRA encoder 전체 forward를 새로 재현한 검사는 아니다. 확인한 범위에서 실패 패턴을 강제하는 구현 오류는 찾지 못했다.

현재 두 출력은 **encoder와 MLP 은닉층을 공유**하고 마지막 여섯 로짓만 나뉜다. 출력 값의 독립성과 학습 경로의 독립성을 혼동하지 않는다. 현재 hinge는 두 사례의 상대 점수를 벌리므로 두 사례가 모두 정답이어야 0이 되는 손실이 아니다. 별도 CE는 존재하며, pair loss가 작다는 사실만으로 절대 분류를 충분히 학습했다고 판단하지 않는다.

이번 작은 학습은 한 출처에서 **두 기억 × 요청 세 상태 × 완료 세 상태 = 18행**을 모두 포함했다. 하나의 기억만 쓰면 기억을 무시한 채 현재 필드만 외워도 진단을 통과할 수 있다. 학습 집합에 대한 적합 가능성을 보는 검사이며 일반화 평가가 아니다. 아래 비교 원칙을 [실행 전 설계](../training/memory_selector/reports/2026-11-07-scope-role-diagnostic-design.md)에 고정하고 수행했다.

1. 별도 프로세스에서 기존 체크포인트의 원래 예측부터 재현한다.
2. 같은 초기화·입력·노출에서 요청 출력만, 완료 출력만, 두 출력 함께를 비교한다. 다른 출력의 손실을 0으로 마스킹하고, 남은 출력의 CE 계수는 공동 학습 때와 같게 유지해 손실 스케일 차이를 줄인다.
3. 하나씩은 맞히고 함께 학습할 때만 실패하면 공유 표현·학습 간섭을 우선 살핀다. 하나씩도 실패하면 입력 표현·판독층·최적화를 더 점검한다. 요청/완료를 역할별로 분리한 입력은 같은 원문 필드에서 만들고 새 정보를 추가하지 않는다.
4. 학습 길이 변경은 별도 축으로 두고, 미리 정한 상한 내에서 epoch별 전체/핵심 조건의 정답과 CE·pair loss를 저장한다. 훈련 점수 개선을 새 출처 성능으로 보고하지 않는다.

### 다른 데이터도 필요하지만 역할을 나누어 확인한다

첫째는 기존 두 범위 설계에 의존하는지 보는 **새 통제 자료**다. [세 범위·같은 문자 길이 진단 자료](design-data/role-binding-controls-20261107/README.md)에 48개 기본 조건을 두 서식으로 표현한 96행을 준비했다. 입력·정답 생성과 기존 규칙 판독의 일치를 CPU에서 검사했다. [검사 결과](design-data/role-binding-controls-20261107/validation.json)에서 범위의 문자 길이만 비교한 규칙은 24/96이었다. 이후 이번 Colab에서 기존 세 모델과 새 세 모델의 예측도 저장했다. 자료 생성 당시의 README·검사 JSON은 당시 상태로 보존하고, 모델 성적은 [후속 결과](../training/memory_selector/reports/2026-11-07-scope-role-diagnostic.md)에 기록한다. 실제 출처가 추가된 자료는 아니다.

세 범위에서는 ‘요청과 완료가 서로 다르지만 둘 다 기억과 다름’이 가능하다. 따라서 `요청 != 완료`만으로 이전 실패 집단과 같은 난도를 뜻하지 않는다. **둘 다 기억과 일치 / 요청만 일치 / 완료만 일치 / 둘 다 불일치 / 근거 부족**을 별도 집계한다. 알려진 조건의 클래스 비율도 바뀌므로 전체 정확도의 단순 증감을 개선으로 읽지 않는다.

둘째는 다른 이름·문체에서 역할 판단을 유지하는지 보는 자료다. 현재 두 서식과 같은 이름을 재사용한 96행으로 새 문체·새 출처 일반화를 주장하지 않는다. 길이를 맞춰도 토큰 수나 이름의 다른 단서가 남을 수 있다.

셋째는 **새 실제 출처**에서의 확인이다. 모델·학습 조건을 개발 자료로 고정한 뒤, 그 전에 분리한 출처에서 판단한다. 현재 보고서의 72행·74행 재분석이나 위 96행 합성 자료로 이 확인을 대신하지 않는다. 새 코드 환경·실행 범위의 의미를 사람이 검토하고, 실제 제공/보류의 성공과 비용은 별도 실험으로 남긴다.

가중치와 head를 고정한 채 아래 조건을 평가하면 재학습 효과를 섞지 않고 현재 모델의 경계를 볼 수 있다. 모델 출력을 보기 전에 새 입력의 근거·정답·부모 사례를 검토한다.

| 검사 | 보존하거나 바꾸는 것 | 확인할 점 |
| --- | --- | --- |
| 길이가 같은 서로 다른 범위 | 길이 단서를 맞추고 범위 의미는 다르게 구성 | 길이 비교로 풀리지 않을 때의 판단 |
| 다른 표기의 같은 범위 | 명령·경로의 실제 의미를 확인한 뒤 표현만 변경 | 문자열 동일성과 실행 의미의 구별 |
| 현재 조건 또는 기억 하나 변경 | 같은 기억·다른 현재와 같은 현재·다른 기억을 모두 구성 | 양쪽 관계에 따른 올바른 판단 변화 |
| 필요한 관측 제거 | 근거를 가리고 정답을 재검토 | 모순과 미확인의 구별 |
| 의미를 보존한 바꿔쓰기 | 사실·범위·관측 시점은 유지 | 서식 변화 후에도 함께 맞히는지 |

단순 이름 치환이나 공백 채우기가 의미와 토큰 길이까지 보존한다고 가정하지 않는다. 통제한 가상 상태와 실제 코드·명령에서 검증한 사례를 표시하고 따로 집계한다. 이미 본 출처의 변형은 개발 진단으로 남긴다. 동일한 검사를 새 실제 출처에도 만들되, 그 확인 집합은 모델·층·threshold 선택에 사용하지 않는다.

그다음에는 **전체 입력·현재만·질문과 기억만을 같은 LoRA 학습 조건으로 비교**한다. 기존 고정 encoder의 입력 제거 대조와 전체 LoRA의 차이에는 encoder 학습 차이도 들어 있기 때문이다. 제거 입력으로 원래 전체 입력 라벨을 예측하는 점수는 지름길 진단이며, 제거 후 근거에 맞는 관계 판단을 평가하려면 따로 재주석한다.

가중치를 단순히 교차 교체한 head/adapter 성적은 좌표계와 공동 학습의 영향도 받는다. 표현 자체의 개선을 더 보고 싶다면, 동일한 학습 출처에서 얻은 base/LoRA encoder를 각각 고정하고 새 head를 같은 데이터·노출로 학습한다. 해당 평가 출처를 이미 본 adapter는 사용하지 않는다.

## 완료한 적합 진단이 바꾸는 다음 순서

요청 단독, 완료 단독, 공동 학습은 각각 14/10/35 epoch에 학습 18행을 모두 맞혔다. 그러나 새 통제 자료에서 공동 모델은 요청 48/96·완료 58/96·동시 21/96이었고, 단독 모델은 감독한 출력에 대해 각각 92/96·80/96이었다. 공동 모델은 알려진 54행 모두에서 요청과 기억이 호환된다고 예측했다. 학습 가능성과 새 조건의 역할 판단은 구분된다.

공동 학습의 개발 동시 정답은 24 epoch의 44/72에서 48 epoch의 25/72로 떨어졌고 최종 26/72였다. 같은 18행을 더 반복하는 것만으로는 개선되지 않았다. 기존 기반 가중치와 원래 checkpoint는 보존되며, 현재 adapter의 과도한 특화를 원본 모델의 손상으로 해석하지 않는다.

다음 주 비교는 원래 Harrier revision에서 새 LoRA와 head로 시작한다. 먼저 새 이름·문체·출처를 분리하고, 세 범위 전체 관계 조합과 다양한 이름 묶음을 늘린다. 합성 자료량 곡선과 실제 출처 보강을 구분하며, 현 공동 학습과 역할을 명시하는 입력의 비교를 같은 조건에서 수행한다. 구체적인 합성 192/768/3,072행 후보 및 실제 신규 출처 20–30개 수집 목표는 [재학습 조건](../training/memory_selector/reports/2026-11-07-scope-role-diagnostic.md)에 정리했다. 아직 이 자료를 생성하거나 추가 학습하지 않았다.

## 실험 1 같은 특징의 선형 판독기와 MLP

**질문:** 고정된 Harrier 표현에서 관계를 읽는 데 비선형 판독층이 필요한가?

현재 상태 벡터 `q`, 기억 벡터 `u`에 대해 기존 특징을 그대로 사용한다.

```text
x = [q, u, q*u, abs(q-u), log1p(현재 문자 수)/10, log1p(기억 문자 수)/10]
선형 판독기: Linear(4098, 3)
현재 MLP:   Linear(4098, 128) → GELU → Linear(128, 3)
```

Harrier의 표현은 1,024차원이며 기존 마지막 유효 토큰의 L2 정규화 방식과 특징 순서를 유지한다. 두 판독기는 같은 `x`와 정답을 받는다. 곱과 절댓값 차이가 이미 들어 있으므로 선형 판독기는 **이 특징 위에서 선형**이지 원래 두 입력에 대한 완전한 선형 함수는 아니다.

주 비교는 전체 입력의 선형/MLP다. 현재만·질문과 기억만은 같은 head 학습 조건의 진단으로 둔다. 제거한 쪽의 벡터·상호작용·길이에서 정보가 남지 않도록 기존 view 계약을 따른다. 별도로 두 길이만 사용한 학습 기준선과 입력 구조·실행 의미 규칙의 적용 범위를 보고한다. 전체 특징에서 길이 두 개를 빼는 실험도 가능하지만, 임베딩 안의 길이 정보까지 제거했다고 주장하지 않는다.

로컬 원본의 `outputs/20261107T112302Z/artifacts/harrier-embeddings.pt`에 고정 특징이 있어 CPU로 시작할 수 있다. 캐시의 모델·입력 해시·행 순서·정규화를 확인하고, 기존 MLP의 저장 예측을 재현한 뒤 같은 캐시에서 두 head를 학습한다. 캐시는 Git clone에 포함되지 않으므로 없으면 별도 제공하거나 encoder 추론이 필요하다.

첫 비교는 같은 업데이트 예산에서의 결과다. 학습 손실이 계속 크게 줄어드는 등 선형 모델의 최적화가 불충분하면 구조의 한계로 해석하지 않는다. 추가 학습률·정규화·노출 예산은 개발 자료에서 양쪽에 같은 탐색 기회를 주고 고정한 뒤, 새 출처에서 확인한다.

| 관측 | 다음 결정 |
| --- | --- |
| 선형과 MLP가 새 출처의 조건 대조까지 비슷함 | 간단한 head를 기준으로 유지하고 입력 구조·자료에 투자 |
| MLP가 양방향 대조와 알려진 관계에서 일관되게 개선 | 비선형 판독층 유지. 깊이 추가는 폭 증가와 별도 비교 |
| 둘 다 전체 점수만 높고 대조 묶음은 실패 | 상태·문장 단서와 대조 자료의 구성을 먼저 점검 |

## 실험 2 별도 인코딩과 함께 읽기

**질문:** 두 입력을 각각 압축한 뒤 비교하는 방식이 현재 관계 판독의 성능을 제한하는가?

별도 인코딩은 현재 방식 그대로다. 함께 읽기는 같은 Harrier에 `과제 지시 → 현재 질문과 근거 → 과거 기억과 근거`를 한 입력으로 제공하고, 마지막 유효 토큰의 정규화된 표현 `z`로 판독한다. 이는 작은 모델을 관계 판독에 사용하는 설계이며, Harrier가 처음부터 이 용도로 학습됐다는 가정은 하지 않는다. 두 문장을 함께 처리하는 방식과 별도 임베딩의 계산 차이는 [Sentence-BERT](https://aclanthology.org/D19-1410/)를 구조적 참고로 삼는다.

| 구성 | Encoder | 판독 입력 | 맡는 역할 |
| --- | --- | --- | --- |
| 별도 고정 | base 고정 | 기존 `x` | 실험 1의 MLP 재사용 |
| 함께 고정 | 같은 base 고정 | `z`와 같은 두 문자 길이 | 추가 학습 전 입력 방식 진단 |
| 별도 LoRA | 같은 base에서 새 LoRA | 기존 `x` | 자연 관계의 추가 학습 기준 |
| 함께 LoRA | 같은 base에서 새 LoRA | `z`와 같은 두 문자 길이 | 함께 읽기와 추가 학습의 조합 |

먼저 두 고정 구성을 진단한다. 자료 보완 뒤 두 LoRA를 같은 학습 출처·노출로 비교한다. 고정 joint 성적이 낮다는 이유만으로 joint 추가 학습이 무효라고 결론 내리지 않는다. 예전 범위 과제의 두 출력 LoRA를 자연 관계의 새 학습 성적으로 재사용하지 않는다.

주요 통제는 다음과 같다.

1. **같은 사실을 제공한다.** joint 전체를 2,048토큰 이내로 사전 검사한다. 넘으면 자동 절단하지 않고, 공통 발췌 규칙이나 입력 한도를 먼저 정해 두 방식에 동일한 근거를 제공한다. wrapper를 포함한 실제 토큰 수는 따로 기록한다.
2. **판독층 크기를 공개한다.** MLP 은닉 128로 시작하되 별도 입력 4,098차원과 joint 입력 1,026차원은 head 파라미터 수가 다르다. 각각 525,059개와 131,843개다. 차이를 더 분리할 필요가 있으면 joint 은닉 510의 525,303개 구성으로 용량을 가깝게 맞춘 보조 비교를 한다. 이것도 입력 방식과 head 폭이 함께 달라지므로 순수 attention 효과로 부르지 않는다.
3. **LoRA 학습 조건을 맞춘다.** 초기 제안은 q/v, rank 8, alpha 16, adapter 학습률 0.0001이다. 같은 adapter 초기화·훈련 모듈·유효 batch·감독 노출을 사용하고 head 조건을 기록한다. 메모리 때문에 microbatch를 줄이면 gradient accumulation으로 유효 batch를 맞춘다. 12 epoch 출발점의 실제 업데이트·학습 곡선을 남긴다.
4. **현재 근거와 기억을 모두 써야 하는지 본다.** 각 구조와 학습 방식 안에서 전체/현재만/질문과 기억만의 대조를 맞춘다. 입력 순서는 본 실험에서 고정하고, 순서 변경은 별도 강건성 진단으로 남긴다.
5. **후보 수에 따른 비용을 본다.** 후보 1/8/32개에서 같은 후보 묶음을 사용해 정확도, encoding/head 시간, peak VRAM을 보고한다. 실제 후보가 없는 규모는 반복 입력의 처리량 측정이라고 표시한다. 별도 방식의 기억 캐시 구축 비용과 재사용 비용, joint의 후보마다 다시 읽는 비용을 나눈다. LoRA 중에는 바뀌는 encoder의 옛 캐시를 재사용하지 않는다.

joint가 조건 대조에서 개선되고 새 출처에서도 재현되면 그 구조의 학습을 이어간다. 다만 개선만으로 기존 벡터에서 정보가 완전히 사라졌음을 증명하지는 못한다. 입력 직렬화·학습 적합성·판독 용량도 설명 후보다. 정확도가 비슷하면 캐시와 지연을 고려해 더 단순한 방식을 유지할 수 있다.

## 실험 3 중간층과 마지막 층의 선형 판독

**질문:** 같은 관계를 어느 깊이의 표현에서 더 잘 읽을 수 있는가?

고정 revision의 Harrier는 [28층·1,024차원](https://huggingface.co/microsoft/harrier-oss-v1-0.6b/blob/f9b9dc8d367d443f2479d27aa5d8d2850c0774ee/config.json)이다. 우선 **7/14/21/28번째 transformer block**만 비교한다. 입력 임베딩을 0번째로 세는 라이브러리 인덱스와 혼동하지 않는다.

추출 계약은 각 block 직후, 모델의 마지막 정규화가 적용되기 전 출력의 마지막 유효 토큰을 L2 정규화하는 것이다. 같은 층의 `q`와 `u`로 실험 1과 같은 4,098차원 특징을 만들고 같은 선형 판독기를 학습한다. 기존 `last_hidden_state` 경로와 연결하기 위해 28번째 block의 **마지막 정규화 전/후**도 한 번 비교한다. 라이브러리 `hidden_states[-1]`를 다른 중간 block 출력과 무심코 섞지 않도록 hook 위치·padding·정규화·캐시 재현을 먼저 검사한다.

네 층은 한 encoder 추론에서 필요한 토큰 벡터만 추출해 CPU에 저장한다. 모든 층의 전체 토큰 텐서를 장기간 보관하지 않는다. 입력·판독 특징·head 용량·학습 예산·seed를 맞추고, 층 선택은 개발 자료에서만 한다. 현재 저장된 최종 임베딩만으로 중간층을 복원할 수는 없다.

[control-task probing 연구](https://aclanthology.org/D19-1275/)가 지적하듯 판독기 성적에는 표현과 판독기 학습 능력이 함께 반영된다. 길이·서식 기준선, 의미 보존/조건 변경 대조, 출처 분리를 유지한다. 높은 판독 성적은 해당 판독기로 정보가 읽힌다는 증거이며, 원래 모델이 그 정보를 실제 판단에 썼다는 인과 증거가 아니다. 낮은 선형 성적도 정보 부재의 증명은 아니다.

특정 층의 이점이 새 출처에서도 반복되면 표현 층 선택이나 적은 수의 층 혼합을 후속 후보로 둔다. LoRA 위치 비교는 그 뒤, 학습 블록 수·adapter 파라미터·감독 노출을 맞춘 별도 실험으로 진행한다. 첫 실행에서 모든 층 × head 깊이 × LoRA 위치를 탐색하지 않는다.

| 완료한 재검토 | 원본 저장 예측의 개선/악화 재집계 | 입력 해시·하위 집단·변경 사례 ID |

| 완료한 입력 진단 | 같은 문자 길이의 세 범위 96행, 기존/새 모델 고정 평가 | 새 공동 모델 21/96·핵심 0/24, 원래 예측 재현 및 검산 |
| 다음 자료 보강 | 새 분할 고정, 관계 조합·이름·실제 출처 확대 | 합성 묶음과 실제 출처 수를 구분, 자료량별 성적 |
| 다음 판독 비교 | 캐시 기반 선형/MLP, 역할을 명시한 학습 | 같은 자료·감독·비용 조건의 비교 |
| 표현 비교 | 고정 joint와 소수 층 표현 추출 | 추출 계약·동일 근거·자원 기록과 판독 결과 |
| 추가 학습 | 보완 자료의 별도/joint LoRA와 같은 학습 방식의 입력 제거 대조 | seed별 결과·실제 감독 노출·새 출처 성적 |
| 정책 검증 | 고정 작업 에이전트의 기억 제공/보류 비교 | 성공·제출·추가 검사·비용·시간 |

세 실험은 연구 가설을 구분할 가치가 있지만, 어느 구성의 우위도 미리 가정하지 않는다. 관계 개선이 실제 정책으로 이어지려면 항상 제공·항상 보류·검색·전제 확인 규칙과 비교해야 한다. 관계 라벨을 실제 이득/손해 정답으로 대체하지 않는다.

기존 `relations` 실행 경로는 Harrier 뒤에 9B도 로드한다. 이번 18행 진단에는 별도 `scope-diagnostic` profile을 만들었고 [실행 설계](../training/memory_selector/reports/2026-11-07-scope-role-diagnostic-design.md)에 CLI를 기록했다. 이 profile이 위 선형/MLP·joint 인코딩·중간층 실험까지 수행하는 것은 아니다. 학습·추론은 로컬 Laya GPU와 분리된 Colab에서 유한 시간 예산으로 실행하고, 캐시 기반 head 비교는 CPU로 옮긴다. 이번 세션은 결과 회수와 함께 종료했다. 27B/MoE 생성 판독은 [별도 계획](ai-memory-data-and-model-next-steps-2026-11-07.md)의 동일 프로토콜 비교로 유지한다.

## 재집계와 기록 위치
