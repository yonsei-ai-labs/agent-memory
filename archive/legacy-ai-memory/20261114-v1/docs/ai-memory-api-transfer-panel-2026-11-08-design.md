# 실행으로 검토하는 API 절차 기억의 적용 경계 — 구축 전 설계

기존 자연 관계의 `output_contract_change`와 ‘과거 처방을 그대로 쓰면 되는가’라는 연구 질문을 확장한다. 파일 범위 일치와 별도로, **반환값·원본 변경 조건이 다른 현재 API에서 과거의 처리 절차를 재사용해도 되는가**를 묻는다. 단일 모델의 통제 진단에 멈추지 않고 실행 가능한 후보 선택으로 연결할 작은 실험판이다.

이는 공개 SWE 과제의 자연 발생 대상 로그를 추가 수집한 것이 아니다. 실제 공개 라이브러리 API로 새 출처 경험과 현재 작업을 실행해 만드는 **통제한 절차 전이 자료**다. 라이브러리·API 가족·기본 상태·표현 행 수를 분리 보고한다. 성공이 곧 SWE 해결 개선이나 전체 기억 효용의 증거라는 주장을 하지 않는다.

## 좁힐 관계와 근거

현재 작업은 정해진 변환을 수행해 변환된 값을 반환하면서, 요청에 따라 원본을 보존하거나 원본 자체를 바꿔야 한다. `sort`·`sort_values`·이미지 크기 변경·희소 행렬 정리·그래프 변환·전처리 같은 실제 API의 반환/변경 계약을 사용한다. 현재 입력·호출·요구를 먼저 제시하고, 후보 절차를 실행한 결과는 모델 입력에 넣지 않는다.

과거 기억은 네 종류의 절차 중 실제 출처에서 성공한 실행으로 만든다: 호출 반환값 사용, 호출 뒤 수신 객체 사용, 복사한 객체에 호출 후 반환값 사용, 복사한 객체에 호출 후 그 객체 사용. 후보마다 원래 입력·실행 코드·관측 출력·원본 변화·검사 결과를 연결한다. 같은 절차가 현재에도 맞는지는 현재 작업의 실제 반환값·원본 효과를 실행 검사해 정한다. 후보가 둘 이상 맞을 수 있고, 아무 후보도 맞지 않을 수도 있다. 다른 후보를 모두 음성으로 처리하지 않는다.

이 라벨은 **해당 입력과 명시한 검사 계약에서 절차를 직접 재사용할 수 있는가**다. LLM 작업자에게 기억을 알려줄 때의 효용과 구분한다. 실제 작업자 비교는 같은 입력으로 기억 없음·고정 제공·규칙·학습 선택을 별도로 실행해야 한다. 입력에 이미 충분한 API 설명이 있으면 기억이 중복일 수 있으며, 그 경우도 결과로 남긴다.

## 자료 선정과 분할

사용할 API 가족은 NumPy, pandas, Pillow, SciPy sparse, NetworkX, scikit-learn preprocessing, Python 표준 컨테이너로 제한한다. 버전·실제 함수·고정 fixture를 보존하고, 속도나 설치 문제로 제외하면 이유를 기록한다. 임의 라이브러리를 결과에 맞춰 더하지 않는다. 재현 가능한 실제 실행과 값/변경 검사 둘 다 확보하지 못한 사례는 학습 자료에 넣지 않는다.

초기 분할은 NumPy·SciPy·Pillow·표준 컨테이너를 학습, pandas를 개발, NetworkX·scikit-learn을 확인으로 고정한다. 같은 라이브러리의 과거 기억·현재 작업·변형·표현은 함께 묶는다. 이 일곱 묶음이 충분한 독립 표본 수라는 뜻은 아니다. 특히 NumPy 배열을 쓰는 SciPy/scikit-learn의 공유 의존성과 API 관습은 해석의 한계로 남긴다.

보이는 입력이 같아도 숨긴 호출 모드에 따라 후보의 적용성이 달라지는 경우를 만들 때는, 가능한 현재 상태를 전부 실제 실행한다. 모든 상태에서 통과하면 적용 가능, 모두 실패하면 충돌, 갈리면 미확인이다. 정보를 가렸다는 이유만으로 전부 미확인 라벨을 붙이지 않는다. 이 모드 가림은 구성한 관측 제한이며 자연 발생 미확인 사례로 세지 않는다.

## 반드시 먼저 볼 진단

실제 출처의 성공, 대상 실행과 라벨 연결, 같은 현재 상태에서 후보에 따라 달라지는 정답, 같은 후보에서 현재 상태에 따라 달라지는 정답을 확인한다. 현재만·기억만·길이·API/flag 문자열 규칙과 항상 제공/보류 기준선을 둔다. source/target 입력에 미래 실행 결과나 효용 주석이 들어가지 않는지 점검한다. 숫자·문체만 바꾼 행을 새 경험으로 세지 않는다.

먼저 일부 API에서 데이터 제작 자체가 의미 있는 대조를 만드는지 검토한다. 대부분의 후보가 항상 같거나 단일 단어로만 맞힐 수 있으면 규모를 늘리지 않고 설계를 고친다. 마지막 확인 집합을 모델 선택에 쓰지 않으며, 그 예측을 본 뒤 고친 모델은 새 확인이 필요하다.
