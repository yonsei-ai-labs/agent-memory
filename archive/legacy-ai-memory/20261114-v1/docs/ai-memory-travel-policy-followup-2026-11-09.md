# 기억 개수·보류·작업자 지침을 분리하는 후속 실험

실행 완료: [결과와 회고](reports/2026-11-09-travel-policy-followup.md), [원본 예측·CPU 재현](../evaluation/results/travel-policy-followup-20261109-v1/README.md). 아래 설계와 임계값은 실행 전에 고정한 내용이다.

실행 전 고정: 2026-11-09. 이 문서는 이전 train12 탐색 결과를 보고 만든 후속 설계이며, 새로운 확인 평가의 사전등록을 뜻하지 않는다.

## 질문

이전 파일럿에서는 관련 기억 2개를 잘 찾았지만 상위 4개를 항상 전달했다. 근거가 없을 때 `UNKNOWN` 대신 `NONE` 또는 구체적 ID를 출력하는 작업자 오류도 있었다. 이번에는 **기억을 고르는 문제와 받은 근거를 사용하는 문제를 분리**한다. 새 학습을 추가하기 전, 기존 모델의 점수와 단순 정책으로 어디까지 해결되는지 측정한다.

## 고정하는 것

- 기존 실제 생성 기록 540개, train12 가족·24질문·4조건(96상태), 카탈로그, 원래 정답 규칙을 그대로 사용한다. 새 과거 기록을 만들거나 틀린 과거 선택을 정답으로 교체하지 않는다.
- Qwen3.5-9B의 같은 리비전·BF16·greedy·thinking off·입력 최대 8192·출력 최대 64토큰을 사용한다.
- 기존 Harrier 검색/관계 모델의 저장 점수를 그대로 사용한다. 새 인코딩·모델 학습은 하지 않는다.
- 원문 메시지가 완전히 같은 이전 생성만 재사용한다. 이전 메시지 4개를 다시 실행해 토큰 일치를 확인한다. 일치하지 않으면 캐시 비교의 한계를 명시하고 통합 결과를 확정하지 않는다.
- dev20/test40은 사용하지 않는다. 1,536개 정책 결정은 독립 경험 1,536개가 아니라 같은 12개 가족의 반복 비교다.

## 비교

2개 지침 × 8개 정책 × 96상태:

| 축 | 수준 |
|---|---|
| 지침 | 기존 / 정확한 과거 참조를 먼저 확인하고, 근거 없음과 불가능을 순서대로 구별하도록 명시 |
| 정책 | 무기억 / 전체 / 고정 검색 상위4 / 학습 검색 상위2 / 학습 검색 상위4 / 학습 점수≥0.5 / 참조 규칙 / 관측에 이미 있는 참조를 제외하는 규칙 |

새 지침도 같은 JSON 스키마와 정답을 사용한다. 결과 후 `NONE`을 `UNKNOWN`으로 변환하지 않는다. 모든 정책에 같은 지침을 적용하며, 지침 변경과 선택 정책 변경의 효과를 따로 보고한다.

점수 기준 정책은 **기존 첫 단계의 상위32개를 재순위화한 후보 안에서** 0.5 이상을 최대4개·512토큰까지 전달한다. 기존 회고의 전체 후보 점검과 범위가 다르다. 0.5는 이진 분류의 고정 경계이며 보정된 확률이나 최적 임계값이 아니다. 다른 임계값을 탐색하지 않는다. 전체 기억 정책에는 별도의 더 큰 토큰 예산이 적용된다.

별도로 36개 작은 계약 점검을 두 지침에 각각 적용한다. 각 구성 요소의 정답이 ID / NONE / UNKNOWN인 9가지 조합, 재사용 / 가격 관계, 기억 / 현재 관측에 근거가 있는 두 형식을 포함한다. 이 합성 점검은 새 출처의 효용 평가에 합산하지 않는다. 결과를 보고 지침을 다시 고르거나 수정하지 않고 두 지침 모두 보고한다.

## 평가

1. **원래 과제 성공**: 두 구성 요소가 모두 정답인가. 답할 수 있는 72상태와 필수 근거가 없는 24상태를 나누어 제시한다.
2. **주어진 입력에 맞는 행동**: 필요한 근거가 전달되지 않았을 때 UNKNOWN을 쓰는지 별도 집계한다. 전역 기억 은행에는 정답 근거가 있는데 선택기가 보류한 경우, 적절한 보류가 곧 과제 해결 성공은 아니다.
3. 무기억 대비 개선·악화, 상위4 대비 개선·악화, 참조가 전달되지 않은 구체적 선택, 잘못된 NONE, 파싱 실패, 출력 제한 도달을 구분한다.
4. 입력·출력 토큰, 전달한 기억 수, 생성 시간, 실제 신규 호출량을 기록한다. 검색은 저장 결과를 사용하므로 온라인 선택기 전체 비용을 측정했다고 주장하지 않는다.
5. 12가족별 차이와 가족 단위 부트스트랩을 기술적으로 제시한다. 작은 탐색 자료와 여러 비교의 한계 때문에 확정적인 일반화나 유의성 주장을 하지 않는다.
6. 원문 프롬프트·입출력 토큰·모델 가중치 해시·기존 캐시 일치·독립 SQL 정답을 재검산한다.

## 실행 범위

준비 결과: 기존 365개 고유 프롬프트의 724개 결정을 재사용하고, 신규 고유 프롬프트 517개와 반복 확인 4개를 실행한다. Colab L4 전용 세션, 스크립트 최대 3,000초·컨트롤러 최대 3,300초. 로컬 GPU는 사용하지 않고 완료/실패 시 해당 세션을 종료한다. 원본 실험 산출물과 다른 작업자의 변경은 보존한다.

관련 코드: `training/memory_selector/{prepare_travel_policy,travel_policy_protocol,run_travel_policy}.py`, 설정 `configs/travel-policy-followup-v1.json`.

## 판단 기준

- 단순히 4개를 2개로 줄이거나 낮은 점수의 기억을 보류해서 나아지면, 더 복잡한 효용층보다 제공 개수와 보류 정책을 먼저 고친다.
- 지침만으로 크게 나아지면 기존 실패의 일부가 작업자 계약 문제였다는 근거다. 이를 선택기 학습 성과로 합산하지 않는다.
- 관련성 점수는 좋아도 실제 잘못된 선택이 남으면, 그 잔여 사례가 다음 상태·효용 학습의 대상이다. 현재 12가족의 개선만으로 학습 선택기의 필요성을 입증하지 않는다.
