# 누적 세션 전환의 CPU 설계 검사

[데이터 정리·누적 실험안](../../ai-memory-data-cleanup-and-context-stream-plan-2026-11-12.md)의 재현 자료임. 실제 작업자 입력이나 새 학습 데이터가 아님. 봉인 출처를 읽지 않으며 원본 패킷을 변경하지 않음.

`check_read_only.py`는 납품된 4세션의 실제 공개 카탈로그와 구조화된 사건을 읽어 별도 장부를 계산함. 원 생성기의 장부나 평가 함수를 호출하지 않음. 필요한 입력은 저장소의 `datasets/hidden_memory_traps/pilot-20261112-v1`뿐이고 외부 모델·토크나이저·작업 트리가 필요 없음.

| 파일 | 내용 |
| --- | --- |
| `check_read_only.py` | 원본 해시 검사, 대본 답 저장 유무의 비교, 질문 접두부 재생 |
| `checks/feasibility.json` | 패킷/검사 코드 해시·범위·집계 |
| `checks/read-only-answer-checks.jsonl` | 92판단별 재생 일치·필요 근거의 사건 종류·과거 정답 저장 생략 수 |

92/92에서 원본 정답·읽기 전용 정답·각 시점 접두부 정답이 같음. 질문 답을 새 예약으로 넣던 72회 저장을 빼도 결과가 유지됨. 필수 근거가 이전 질문 답에서 생긴 경우는 0임. 4세션 각각 30확인 사건·23질문이며, 같은 사건을 두 표현·세 길이로 렌더링한 것을 추가 독립 세션으로 세지 않음.

기존 `events.jsonl`과 이 검사의 결과에는 생성 구조·정답이 있으므로 모델 입력에 넣지 않음. 기존 “예약해줘” 문장을 조회형으로 바꾸는 작업, 새 순서의 라벨 재계산, 최근 창·기억 예산 구현은 아직 없음. 질문 답이 환경을 바꾸지 않는다는 조건에서만 이 결과가 성립함.

저장소 루트에서 새 폴더를 지정하여 재현함. Python 표준 라이브러리만 사용함.

```bash
python3 -S -B docs/design-data/memory-context-stream-20261112-v1/check_read_only.py \
  --output /tmp/memory-context-stream-check
```

`--data`로 다른 패킷 위치를 지정할 수 있음. 결과 폴더는 덮어쓰지 않음. 위 2개 산출 파일은 동일한 입력과 코드로 재실행하면 바이트 단위로 일치함.
