# 세 범위의 역할 구별 진단 자료

2026-11-07 · 새 모델 예측 전의 통제 입력

기억 범위·현재 요청·완료 기록의 역할을 구별하는지 확인할 자료다. 기존 두 범위 조합을 세 범위로 늘리고 이름의 문자 길이를 맞췄다. 실제 파일이나 실행 기록에서 가져온 사례가 아니며, 아래 입력 문장의 과거 명령과 현재 완료 기록도 가정한 상황이다.

- [controls.json](controls.json): 세 기억 × 네 요청 상태 × 네 완료 상태 × 두 서식, 96행. 미확인 상태를 포함한 기본 조건은 48개이며 독립 실제 출처는 0개다.
- [build_controls.py](build_controls.py): Python 표준 라이브러리로 같은 내용을 생성해 표준 출력에 내보낸다.
- 문자 길이는 같지만 tokenizer의 토큰 수가 같다고 보장하지 않는다. 모델 평가 전에 실제 토큰 수를 기록한다.
- A/B는 기존 범위 과제의 두 서식이다. 새 문체 일반화를 시험하는 자료가 아니다.
- 모델 예측·학습 결과·효용 라벨은 없다. 실제 출처 증거를 요구하는 기존 `scope` profile에 바로 넣는 자료도 아니다.

알려진 관계 27개 기본 조건을 나누면 둘 다 기억과 일치 3개, 요청만 일치 6개, 완료 기록만 일치 6개, 둘 다 불일치 12개다. 두 서식 때문에 저장된 행 수는 각각 두 배다. 따라서 전체 정확도만으로 이전 두 범위 과제와 비교하지 않는다.

특히 요청과 완료 범위가 다른 18개 기본 조건 중 6개는 둘 다 기억과 다르다. 이전 두 범위 과제에는 이 조합이 없었다. 핵심 비교는 계속 **요청만 일치**와 **완료 기록만 일치**를 따로 보고, 무관한 필드 변화와 서식 변화에 대한 정답 유지도 확인하는 것이다.

기존 모델을 고정해 먼저 예측한다. 이 자료로 설정을 고른 뒤 같은 자료의 성적을 독립 확인 결과로 보고하지 않는다. 추가 학습에 쓰려면 별도 새 이름 집합과 출처를 평가용으로 고정하고, 같은 조건의 서식 변형은 같은 분할에 둔다.

관련 판단과 기존 성과의 검증은 [판독 실험 노트](../../ai-memory-reader-diagnostics-plan-2026-11-07.md)를 따른다. 자료 수정이 필요하면 기존 파일을 덮어쓰지 않고 새 버전을 만든다.
