# 복합 기억 보존을 유지하며 과잉 제공 줄이기

2026-11-12. 첫 모델 실행 전에 자료·학습량·제공 기준·평가 범위를 고정함.

질문은 “부분적으로 알려진 복합 기억을 보존하는 능력을 유지하면서, 같은 주제의 비필수 기억을 덜 제공하도록 학습할 수 있는가”임. 이전 보강 모델의 두 seed에서 시작하고, 같은 320개 핵심 대조를 유지한 채 복습 80상태의 구성만 비교함.

| 조건 | 핵심 대조 | 복습 | 학습량 |
|---|---:|---|---|
| 고정 이전 모델 | 추가 학습 없음 | 없음 | 이전 augmented seed 731/1729 |
| control | 기존 atomic/compound 320상태 | 기존 incremental 80상태 | 400상태 항목·2epoch·200update |
| replay | 같은 320상태 | BEAM train 52상태 + Mem2Act train 28상태 | 같은 상태 항목·epoch·update |

Harrier 0.6B, 기존 rank-8 q/v LoRA와 동일 판독층, 학습률과 손실 가중치 산정법을 유지함. 상태 안의 양·음성을 먼저 균형화하고, 학습 전체 클래스 손실 질량을 각각 0.5로 맞춤. 같은 seed의 시작 가중치·상태 순서·핵심 대조를 맞추지만, 복습 후보 길이와 감독 쌍 수는 다름(control 716, replay 1,166). 따라서 토큰·연산량이 같은 비교는 아님. 핵심 대조 출처와 복습 목표 출처를 합한 수는 각각 30·37그룹이며, 후보 은행에는 별도 train 출처의 대조 기록도 있음.

복습은 `아직 모름 / 이미 확인 / 다른 정보만 관측 / 조회 실패`를 함께 제시함. 무관한 **현재 관측**이 있다고 필요한 기억을 음성으로 바꾸지 않음. BEAM의 기존 갱신 상태는 이번 학습에서 제외함. 새 설정을 시도한 것과 실제 적용, 수정된 과거 값의 범위가 섞일 수 있어, 같은 필요 라벨의 명시적 조회 실패 대조로 대체함. 실제 실행 실패 로그를 추가한 것은 아님.

기존 Mem2Act 후보 중 거의 같은 좌표와 은유적인 Apple 언급 2개는 정보 부족 상태에서 판단이 불확실하여 총 6개 감독 라벨을 가림. 이미 필요한 사실을 다 확인한 상태에서는 추가 제공이 필요 없다는 라벨을 유지함. 원본 파일은 수정하지 않음. `replay-review.jsonl`과 원본 위치를 보존함.

새 출처 평가는 이전 원문 풀의 미사용 예약 test 그룹 12개임. 원문의 두 역할별 구절을 읽고 주석하며, 단일 사용자 문단에서 분리 가능한 명시적 사실만 선택함. 방향 없는 도시 쌍, 순서에 의존하는 병렬 목록, 원문과 도메인이 어긋난 질문, 자격 증명을 포함한 자료는 이 파일럿에서 제외함. 현재 목표는 원문 필드 복원으로 작성하여 원래 외부 작업을 실행하지 않음. 알려진 단어·단위·원문 명사구의 허용 표현을 실행 전에 고정함.

새 평가는 12출처 × 10상태 × atomic/compound = 240상태이며, 두 정보가 모두 필요한 조회 실패와 일부만 확인된 조회 실패를 포함함. 같은 출처의 변형을 독립 경험으로 세지 않음. 이번 이전 test 12출처는 성능 유지 검사로 전환함. 기존 incremental·source-scale·BEAM 개발도 성능 유지 검사이며, BEAM 확인 27출처의 모델 출력은 계속 미실행 상태로 둠.

제공 임계값은 모든 모델에 0.5, checkpoint는 마지막 epoch로 고정함. 결과를 보고 seed·epoch·제공 기준을 선택하지 않음. 필요한 근거 확보와 불필요 제공, 실제 작업의 개선·악화를 모두 보고하며, 하나의 관계 점수로 모델을 자동 교체하지 않음.

## 제한된 예산에서의 비교

기존 검토된 BEAM 개발 52상태의 같은 7–8개 원문 은행을 유지하고 128·512토큰을 비교함. 모든 은행은 355–767토큰이고, 검토된 필요 근거는 최대 84토큰이므로 두 상한 모두에서 필요한 근거가 들어갈 수 있음. 예산을 만들려고 문장을 늘리거나 무관한 기록을 새로 붙이지 않음. 이 비교는 이미 본 개발 자료의 진단이며 새 출처 일반화 결과로 부르지 않음.

모든 모델·검색·규칙·예산 채우기 정책에 같은 은행·관측·목표·토큰 상한을 적용함. 검색은 BM25, 기본 Harrier, 이전 고정 검색 adapter를 비교하며 두 임베딩 조건에 같은 일반 검색 지시문을 사용함. 검색 상위 2개, 관측 중복 제거 규칙, 필요 근거 진단, 같은 과거 근거를 항상 제공하는 진단도 유지함. 미확인 관계 라벨을 음성으로 채우지 않음.

작업자는 동일 Qwen3.5-4B로 고정함. 새 자료는 사전 지정 compound 120상태의 JSON 필드 복원, BEAM은 두 예산의 전체 52상태에서 기존 단일 수치 응답 계약을 사용함. 관계 정답을 작업자 성공 라벨로 치환하지 않음. 필요한 근거가 있는데 작업자가 실패하는 경우와 근거를 놓친 경우를 구분함. 기존 BEAM의 작업 계약 한계와 미개봉 확인 조건을 유지함.

로컬 GPU 한 작업만 사용함. 학습 최대 3시간, 새 작업 입력·반복 합계 최대 1,600호출이며 유료 API·Colab 할당은 없음. 실제 상태와 가중치·입력 해시를 남기고 종료함.

```bash
.venv/bin/python -m data_pipeline.balanced_replay_data audit
.venv/bin/python -m unittest tests.test_balanced_replay tests.test_partial_records
runs/memory-source-scale-20261111-v1/env-harrier/bin/python -m training.memory_selector.train_balanced_replay
```
