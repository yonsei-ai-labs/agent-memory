# 기억 연결성 눈가림 재검토 안내

이 폴더만 검토자에게 전달함. 기존 관계 정답·주석 이유·모델 예측을 보지 않고 판정함. 같은 저장소에 접근할 수 있는 agent는 상위 폴더의 maintainer 자료와 원래 supervision 파일을 열지 않도록 명시함. 자료를 준비한 것만으로 독립 검토가 완료된 것은 아님.

## 검토 범위

- `cases.jsonl`: 현재 관측과 후보 기억의 원문 복사, 공개 근거를 찾는 source key.
- `source-evidence.json`: 후보 기억의 실제 과거 명령·응답. 같은 source key를 여러 사례가 공유할 수 있음.
- `review-form.jsonl`: 아직 정답을 쓰지 않은 제출 양식. null은 미작성이지 미확인 정답이 아님.
- 현재 관측은 행동 전 이슈 발췌임. 공개 패치·현재 문제의 사후 해법을 찾아 이 관측에 소급하지 않음.
- 과거 로그가 있다는 사실은 현재 문제보다 시간상 먼저 발생한 배포를 재현한다는 뜻이 아님.

## 판정 기준

`relation`은 다음 중 하나임.

| 값 | 기준 |
| --- | --- |
| shared_diagnostic_mechanism | 과거 근거의 구체적인 점검 원리가 현재 관측의 특정 현상·요구와 연결됨. 단순히 같은 분야·자료구조·오류 단어라는 이유로 긍정하지 않음 |
| different_mechanism | 현재 관측과 후보의 핵심 점검 원리가 다르다는 구체적 근거가 있음 |
| insufficient_connection | 연결을 판정할 현재 전제나 출처 근거가 부족함. 긍정 근거 부재만으로 different라고 강제하지 않음 |

`source_alignment`은 후보 기억의 관측·일반화가 제공 원문에 얼마나 근거하는지 적음: supported / partial / contradicted / not_established. 수정 명령의 실행은 전체 과제 해결·검사 통과를 뜻하지 않음.

`added_information`은 현재 입력과의 관계임: explicitly_redundant / not_explicitly_present / unclear. 현재에 없다는 것은 실제 도움을 보장하지 않음. 현재에 반복된다는 이유로 관련성 정답을 바꾸지도 않음.

모든 판정에 현재 발췌의 근거 인용과 이유를 남김. `source_event_indices`는 해당 source의 events 배열에서 0부터 세는 위치임. 정보 부족이면 `missing_evidence`에 무엇을 더 확인해야 하는지 적음. 숨은 상태를 상상하거나 실제 제공 효과를 정답으로 작성하지 않음.

검토자마다 양식 사본을 새 위치에 저장함. 기존 양식·원문을 수정하지 않음. 원본 관측에 문제가 있거나 판단이 불가능하면 그대로 보고하며, 일치율을 높이기 위해 억지로 한 범주를 고르지 않음.

## 완료 이후

독립된 검토자들이 먼저 각각 제출한 뒤 서로의 판정을 비교함. 이견은 근거를 대조해 합의하거나 미확정으로 남김. 기존 정답과의 차이·범주별 혼동·출처 충실성·정보 추가 여부를 각각 기록함. 이 결과를 실제 득실 정답으로 전환하지 않음.
