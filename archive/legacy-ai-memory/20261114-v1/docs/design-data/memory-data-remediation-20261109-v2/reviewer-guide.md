# 기억 관계 재검토 안내 v2

이 reviewer 폴더 또는 reviewer.zip만 사용함. 기존 정답·선정 이유·모델 예측을 확인하지 않음. 이미 보았다면 `original_labels_seen=true`로 기록하며 맹검·독립 판정으로 제출하지 않음. 현재 공개 패치나 사후 실행 결과를 찾아 판단 시점에 소급하지 않음.

`cases.jsonl`의 현재 관측과 기억 문장은 원본 복사임. `observation_scope`는 발췌가 잘렸는지, 원문 메시지의 어느 범위인지 설명함. 잘린 부분을 추측하지 않음. 전체 이슈를 복원하는 것은 새로운 입력 버전에서 별도로 수행함. 후보의 과거 명령·응답은 `source-evidence.json`에서 source key로 확인함.

같은 파일의 `historical_issue_context`는 해시를 확인한 과거 원자료에서 복원한 이슈 설명임. 과거 사용자의 보고와 실제 수정 명령을 구분함. 이슈가 어떤 문제를 보고했다는 사실만으로 에이전트가 그 옵션을 수정했거나 실행으로 해결했다는 근거가 되지는 않음. 현재 대상의 숨겨진 결과·후속 패치는 포함하지 않음.

## 관계 판정

판정 대상은 **제시된 과거 경험의 구체적인 점검 행동이 현재 관측의 특정 현상·요구와 연결되는가**임. 과거와 현재의 최종 원인이 동일하거나 과거 패치를 그대로 적용할 수 있다는 주장은 아님.

| relation | 필요 근거 |
| --- | --- |
| shared_diagnostic_mechanism | 과거에서 점검한 대상·동작, 현재에서 점검할 대상·동작, 두 점검을 연결하는 현재 관측을 구체적으로 적을 수 있음 |
| different_mechanism | 현재 관측이 가리키는 대상·동작과 후보의 점검 대상·조건이 다르다는 근거가 있음. 단순히 양성 증거가 없다는 이유로 선택하지 않음 |
| insufficient_connection | 연결 여부를 가르는 전제·현재 동작·출처 근거가 부족함. 필요한 관측을 `missing_evidence`에 명시함 |

같은 ‘검증’, ‘타입’, ‘문자열’이라는 단어만으로 양성으로 판정하지 않음. 반대로 서로 다른 프로젝트라는 이유만으로 음성으로 판정하지 않음. 추상적인 유사성만 가능하고 구체적 점검의 연결을 설명할 수 없으면 미확인으로 남길 수 있음.

양성이어도 현재 이슈에 그 점검이 이미 명시되어 있을 수 있음. 이 경우 관계는 양성으로 유지할 수 있으나 정보 추가 여부를 별도로 기록함. 어떤 관계도 실제 유익/유해·제공/보류 정답으로 치환하지 않음.

## 기록 필드

- `relation`: 위 세 값 중 하나. 작성 전 null과 미확인 판정은 다름.
- `source_alignment`: supported / partial / contradicted / not_established. 실제 관측 서술이 출처에 근거하는지 판단함. 수정 명령 성공은 테스트 통과·전체 해결을 뜻하지 않음.
- `generalization_limit`: 출처에서 확인한 동작과 후보의 일반 원칙 사이에 남는 범위를 설명함.
- `added_information`: explicitly_redundant / not_explicitly_present / unclear. 추가 정보가 실제 도움이 됐는지는 측정하지 않음.
- `current_evidence_quote`: 현재 관측에 실제로 있는 연속 문자열. 서로 떨어진 문장을 하나의 인용문으로 만들지 않음.
- `source_event_indices`: 해당 source의 events 배열에서 0부터 세는 위치.
- `bridge`: `past_inspection`, `current_inspection`, `connecting_observation`을 작성함. 양성이면 세 항목 모두 필요함.
- `reason`: 두 근거로 해당 관계를 선택한 이유.
- `missing_evidence`: 미확인이면 필요한 전제를 구체적으로 작성함. 전제가 없다는 것을 모순으로 간주하지 않음.
- `reviewer_id`, `reviewer_type`, `original_labels_seen`: 실제 검토자와 노출 여부. AI 판정을 사람 검수로 부르지 않음.
- `status`: 첫 판정은 submitted_provisional임. 독립 검토·조정 전 adjudicated로 작성하지 않음.

검토자는 양식 사본을 별도 위치에 저장함. 원문·빈 양식은 수정하지 않음. 판단을 완료할 수 없는 항목은 이유를 남기고 미작성 상태로 둘 수 있음. 반드시 한 범주를 억지로 선택하지 않음.

## 후속 처리

각 검토자의 최초 판정을 보존한 뒤 이견을 확인함. 필요한 근거를 읽지 않은 합의나 동일한 모델 출력을 복제한 두 제출은 독립 검토로 세지 않음. 미확정은 미확정으로 유지함. 원본 v1과 이 묶음의 원문은 보존하고 변경 사유·판정자·출처·분할을 연결한 별도 버전을 만듦.

이 자료는 학습 split에서 주석 기준을 점검하기 위한 묶음임. 새 자연 경험이나 독립 최종 평가 자료가 아님. 준비된 빈 양식과 비맹검 초안은 학습 정답으로 내보내지 않음.
