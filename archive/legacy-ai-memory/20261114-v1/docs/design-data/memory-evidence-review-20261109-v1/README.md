# 근거·충분성 검토 형식과 원문 대조 예시

2026-11-09. 기억의 실제 득실을 설명하기 위한 근거 주석임. 작업자 정답 여부로 주석을 만들지 않음. 원문 의미·적용성 검토와 실제 성공·오류·비용을 별도 축으로 보존함.

`provisional-reviews.jsonl`은 기존 첫 출처 계열의 재사용 요청에서 현재/선택된 문맥을 읽고 작성한 **비독립 AI 초안 8개**임. 기존 결과에 노출된 검토자이므로 `outcomes_seen=true`, `review_status=provisional`, `training_eligible=false`로 기록함. 독립 경험 추가 0개·확정 정답 0개이며 일반화 평가나 오류율 추정에 사용하지 않음. `review-check.json`은 인용 검산 후 기존 결과를 별도로 연결한 보고서임.

## 원문에서 확인한 예

고정 시뮬레이션의 요청은 Jacob의 3일째 저녁과 Ben의 3일째 숙소를 재사용하되 현재 이용 불가이면 NONE을 선택하는 것임. A는 과거 식당 `R577`, B는 과거 숙소 `H1087` 기록임. 사람·날짜·성분이 일치하는 과거 기록과 현재 카탈로그 가용성을 함께 확인함.

| 현재 상태 / 전달 묶음 | 의미 검토 초안 | 부족한 근거 위치 | 저장된 작업 성공 |
| --- | --- | --- | --- |
| 과거 선택 미관측 / 없음 | 불충분 | A·B가 후보에 있음 | 0 |
| 과거 선택 미관측 / A만 | 불충분 | B가 후보에 있음 | 미측정 |
| 과거 선택 미관측 / B만 | 불충분 | A가 후보에 있음 | 미측정 |
| 과거 선택 미관측 / A+B | 충분 | 없음 | 1 |
| 현재에 A·B가 이미 있음 / 없음 | 충분 | 없음 | 1 |
| 현재에 A·B가 이미 있음 / A+B | 충분, 정보 중복 | 없음 | 1 |
| 현재 두 장소 이용 불가 / A+B | NONE을 결정할 근거가 충분함 | 없음 | 1 |
| 허용 은행에서 A·B 제거 / 없음 | 불충분 | 검토한 25개 은행에서 해당 근거를 찾지 못함 | 0 |

이 표의 두 답은 독립 성분임. A+B가 필요한 하나의 복합 추론 문제를 확보했다는 뜻은 아님. 마지막 상태는 전역 `memories.jsonl`에 해당 기록이 있어도 현재 허용 은행에서는 사용할 수 없음. 이용 불가 상태에서 과거 기록은 여전히 사실이며, 현재 적용 결과가 달라짐. 중복 주석만으로 중복 제공의 득실을 단정하지 않음.

## 주석 필드와 검산

각 묶음은 `state_id`와 순서 있는 전달 ID로 식별함. 요구마다 다음을 기록함.

| 필드 | 작성 기준 |
| --- | --- |
| `requirement_id`, `description`, `goal_evidence` | 현재 목표의 어느 요구를 만족해야 하는지 짧게 작성하고 실제 목표 span을 인용함 |
| `support_alternatives` | 서로 대체 가능한 근거 경로의 목록임. 한 경로 안의 여러 span은 모두 함께 필요함. 예: `[[A, B], [C]]`는 A+B 또는 C를 뜻함 |
| `counter_evidence` | 충돌하는 현재/과거 사실의 실제 span임. 과거와 현재의 단순한 시점 차이를 자동 모순으로 취급하지 않음 |
| `reviewed_document_ids` | 실제 읽은 현재 문맥·기억 범위를 기록함. 전역 파일에 있다는 이유로 허용 은행 밖의 문서를 인용하지 않음 |
| `context_status` | 현재 관측+선택된 묶음에서 supported / missing / conflicted / undetermined를 판단함 |
| `applicability_note` | 사실의 주체·시점·조건이 지금 적용되는 이유, 또는 부족/모순/판단 보류 이유를 짧게 남김 |
| `requirements_complete` | 현재 요구를 빠짐없이 검토했는지 명시함. 단순히 정답 기록 ID 두 개를 찾았다고 true로 만들지 않음 |
| `bundle_sufficiency` | 충분 / 불충분 / 미확정을 직접 검토함. 기록 확보 수나 작업 성공으로 자동 대입하지 않음 |

인용은 `document_id, start, end, quote`를 사용함. Python 문자열의 문자 위치이며 바이트 위치가 아님. 없는 사실의 span은 만들지 않음. 부족 판단에는 확인한 범위를 기록하고, 실제 존재하는 대체 근거가 있는지 검사함. 검증기는 인용·범위·내부 정합성을 확인할 뿐, 인용의 논리적 함의나 검토자가 정말 모든 문서를 읽었는지 증명하지 못함.

검토된 지지 경로의 위치는 현재 관측 / 선택된 묶음 / 후보 / 후보 밖 은행 / 검토한 은행에서 미발견 / 미확정으로 계산함. 마지막 두 경우를 구분하려면 은행 목록이 완전하고 해당 요구에 대해 은행 전체를 검토했어야 함. 불충분함과 손해, 충분함과 이득은 서로 대체할 수 없는 라벨임.

## 새 출처에 적용할 수집·검토표

아래 항목을 **사례를 만들 때** 연결함. 기존 여행 예시의 판단 문장을 새 출처에 복사하지 않음.

1. 원천 주소·고정 revision·라이선스/사용 범위·원문 해시·세션/가족 ID와 분할을 먼저 정함. 같은 원문을 공유하는 파생 사례는 같은 분할로 묶음.
2. 현재 목표, 선택 직전 관측, 과거 기억 단위, 허용 은행과 후보 풀을 고정함. 실제 진행·실패 이력이 없으면 없다고 표시함. 선택 후 생긴 명령이나 실패를 입력에 소급하지 않음.
3. 목표의 요구→현재 이미 아는 사실→후보가 보충할 사실→적용 조건→충분/부족/미확정을 원문과 연결함. 한 답에 두 기억이 함께 필요한지, 두 독립 답을 각각 채우는 것인지도 구분함.
4. 원문을 읽어 얻은 주석과 자동 지정 ID 지표를 분리함. 첫 검토자는 작업자 출력·효과·기존 라벨을 보지 않도록 별도 묶음으로 전달함. 현재 예시는 이미 노출된 초안이므로 이 독립성 조건을 충족하지 않음.
5. 삭제/교체 대조는 현재 관측이나 다른 기억에 대체 근거가 남았는지 재검토함. 후보 개수·전달 개수·토큰 길이·원천·표현만 쓰는 기준선으로 편법을 점검함. 개수 통제는 실제 비지지 기록 교체로 구성하며, 단순 빈 문자열 padding을 의미 보존 대조로 취급하지 않음.
6. 과거 선택과 현재 가격이 같은 자료에서 가격 문구만 삭제했다고 가격을 모르는 상태로 단정하지 않음. 원본 ID와 현재 카탈로그 등 남은 경로도 확인함.
7. 독립 검수 후 충분/부족의 범위를 합의함. 미확정은 별도 보존하고 확정 학습 정답으로 승격하지 않음. 작업자가 실패했다고 근거를 음성으로 바꾸지 않음.
8. 작업자 실행은 원문 검토 후 별도 단계임. 무기억 / 필요한 근거만 / 같은 근거+추가 기억 / 학습 선택을 공통 작업자·은행·상한에서 비교함. 필요한 근거 조건은 진단용이며 작업자 성능 상한이 아님. 미시도 A/B 묶음의 효과를 A+B 결과에서 추정하지 않음.

새 자료의 출처별 의미 검토와 짝지은 효과 수집이 다음 우선순위임. 기존 여행 자료를 여러 표현으로 늘리는 것으로 대체하지 않음. 실제 진행·실패 입력은 원문에서 확보된 경우에만 후속 어댑터에 추가함.

## 실행

저장소 루트에서 실행함. GPU나 새 모델 호출은 필요 없음.

```bash
python3 -m data_pipeline.memory_evidence_review \
  --inputs datasets/memory_decisions/20261109-evidence-v1/selector-inputs.jsonl \
  --memories datasets/memory_decisions/20261109-observed-v2/memories.jsonl \
  --reviews docs/design-data/memory-evidence-review-20261109-v1/provisional-reviews.jsonl
python3 -m unittest evaluation.tests.test_memory_evidence -v
```

검증기는 임시 주석의 자동 학습 편입을 허용하지 않음. 검토 출력의 `missing_requirement_ids`·위치·충분성은 감독/진단 자료이며 선택기의 추론 입력에 넣지 않음.
