# 기억 개수·보류·작업자 지침 후속 실험

**판단: 문제의 위치를 좁히는 데 의미가 있었다. 상위 2개 제공은 소폭 개선됐고, 점수 기준 보류는 성공률에 드러나지 않는 잘못된 행동을 줄였다. 반면 지침 강화는 실패했다. 작은 선택기에 더 복잡한 학습층을 추가해야 한다는 근거는 아직 얻지 못했다.**

실행 전 설계는 [후속 실험 노트](../ai-memory-travel-policy-followup-2026-11-09.md), 이전 결과는 [상태·효용 파일럿](2026-11-09-travel-state-utility-pilot.md), 원문 답변과 재현 명령은 [공유 결과](../../evaluation/results/travel-policy-followup-20261109-v1/README.md)에 있다.

## 무엇을 실행했나

기존 모델이 실제 생성한 과거 기록 540개를 그대로 사용했다. 원래 12개 경험 묶음의 24질문에 네 상태를 적용한 **96상태**에서, 2개 작업자 지침 × 8개 제공 정책을 비교했다. 별도로 근거 있음·조건상 불가능·근거 없음의 조합을 다루는 합성 계약 점검 36개를 두 지침에 적용했다.

- 작업자: 같은 리비전의 Qwen3.5-9B, BF16, greedy, thinking off, 출력 최대 64토큰.
- 검색·관계 판독: 기존 Harrier 모델의 저장 점수. 새 인코딩이나 LoRA·판독층 학습은 하지 않았다.
- 기존 지침과 새 지침은 **같은 JSON 스키마와 정답**을 사용한다. 새 지침만 참조 확인→근거 부족→현재 조건 검사 순서를 명시했다. 결과를 보고 정답이나 지침을 다시 바꾸지 않았다.
- `threshold`는 첫 단계의 상위32개를 재순위화한 후보 중 점수≥0.5를 최대4개·512토큰까지 제공한다. 보정된 확률이나 최적 임계값이 아니다.
- 신규 고유 입력 **517개**, 반복 확인 **4개**를 실제 실행했다. 이전 고유 입력365개의 724개 정책 결정을 정확히 재사용했다. 총 1,536개 정책 결정과 72개 기본 점검 답변을 평가했다.
- Colab L4 컨트롤러 경과 시간 **1,192초, 약19.9분**. 신규 실행 입력825,657·출력8,977토큰. GPU 최대 할당 약20.22GB. 해당 세션을 종료했고 서버의 활성 세션 없음까지 확인했다. 로컬 GPU와 유료 모델 API는 사용하지 않았다.

여기서 1,536개 결정은 독립 자료 1,536개를 의미하지 않는다. 같은 12개 경험 묶음을 반복 비교한 탐색 실험이다. 새 출처를 추가하지 않았고, 준비돼 있는 dev20/test40은 열지 않았다.

## 1. 기존 지침에서는 4개보다 2개가 조금 나았다

성공은 저녁·숙소 두 결정을 모두 맞춘 경우다. 필수 과거 근거가 은행에 존재하는 72상태와, 제거된 24상태를 구분한다. 후자는 두 항목 모두 `UNKNOWN`이어야 성공이다.

| 제공 정책 | 답할 수 있는 상태 /72 | 근거 없는 상태 /24 | 전체 /96 | 전체 입력 토큰 | 근거 없는 상태의 무근거 구체 선택 /48항목 |
|---|---:|---:|---:|---:|---:|
| 무기억 | 33 | 0 | 33 | 95,887 | 9 |
| 전체 기억 | 39 | 0 | 39 | 325,104 | 48 |
| 고정 검색 상위4 | 52 | 0 | 52 | 116,942 | 31 |
| 학습 검색 상위4 | 51 | 0 | 51 | 116,890 | 31 |
| **학습 검색 상위2** | **55** | **0** | **55** | **106,094** | **30** |
| 점수≥0.5, 최대4 | 51 | 0 | 51 | 104,576 | 12 |
| 참조 규칙 | 55 | 0 | 55 | 103,420 | 9 |
| 이미 관측한 참조를 제외하는 규칙 | 55 | 0 | 55 | 100,909 | 9 |

상위2 대 상위4는 **5상태 개선·1상태 악화**, 순4상태 개선이었다. 전체 입력 토큰은 **9.2% 감소**했다. 특히 현재 조건이 바뀐 상태는 15→18/24, 이미 관측한 상태는 18→19/24였다. 기억이 필요한 상태는 두 방식 모두18/24였다.

그러나 가족 단위 부트스트랩의 성공률 차이 구간은 약 **−1.0~+10.4%p**였다. 소수 가족에서 여러 비교를 한 탐색 결과이므로 일반화나 통계적 우위를 확정할 수 없다.

또한 상위2는 근거 없는 상태에서도 2개를 채워 넣는다. 성공 수는 참조 규칙과 같지만, 무근거 구체 선택은30항목으로 규칙의9항목보다 많다. **같은 성공 점수여도 행동의 질과 비용은 다르다.**

## 2. 점수 기준 보류의 이득은 성공률만 보면 보이지 않았다

점수≥0.5 정책은 필요한 근거가 없는 24상태 중19상태에서 기억을 전혀 주지 않았다. 나머지는1개를 주는4상태, 2개를 주는1상태였다.

상위4와 비교하면 성공은51/96으로 같고, 1상태 개선·1상태 악화가 서로 상쇄됐다. 그러나 근거가 없는 상태에서 무근거 구체 선택은 **31→12/48항목**, 그런 선택이 하나라도 있는 상태는 **19→8/24**로 줄었다. 전체 입력은 **10.5% 감소**했다.

이는 부족한 근거를 잘 처리하도록 완전히 고쳤다는 뜻은 아니다. 같은 상태에서 `NONE`을 근거 없이 출력한 항목은17→36으로 늘었고, `UNKNOWN`은 여전히0이었다. 구체적인 잘못된 선택은 줄였지만, 근거 없음과 불가능의 혼동은 남았다.

원래 연구 질문인 ‘기억의 득과 실’에는 중요한 관측이다. 단순 성공 증감만 학습하면 이러한 상태는 계속 ‘둘 다 실패, 차이0’으로 들어간다. 다음 학습 자료에는 **문제 해결·근거 없는 선택·부적절한 불가능 판단·토큰 비용**을 별도 필드로 남겨야 한다. 이들을 하나의 보상으로 합칠 가중치는 이번에 정하지 않았다.

전체 기억 조건에서는39→44로 좋아졌지만, 주요 선택 정책에서는 성공이 줄었다. 상위2 대 상위4의 이득도 새 지침에서는 사라졌다(각48/96). 따라서 ‘2개가 항상 최적’이라고 볼 수 없다.

새 지침과 점수 기준을 함께 쓰면 근거 없는 상태의 무근거 구체 선택이2/48까지 줄지만, 두 항목을 모두 적절하게 보류한 상태는2/24뿐이다. 나머지 다수는 여전히 `NONE`과 `UNKNOWN`을 혼동한다. 잘못된 행동의 한 종류가 감소한 것을 전체적인 해결로 해석하면 안 된다.

지침은 입력마다165토큰을 추가했다. 새 지침+점수 기준의 총입력120,416은 기존 지침+상위4의116,890보다 약3.0% 많다. 기억 분량 감소가 전체 비용 감소를 보장하지도 않았다.

## 실제 답변에서 확인한 득과 실

**줄여서 좋아진 사례 — Amarillo.** 현재 숙소는 과거 가격528 이하이면서 평점3 이상이어야 했다. 상위4는 가격900인 `H3339`를 골랐다. 상위2는 가격445인 `H1049`를 골라 성공했다. 해당 상태는 `0f5fff20dbab0a91--case-1--changed`이다. 필요한 두 참조는 양쪽 모두 전달됐다. 추가 기록 두 개를 제거한 정책 변화로 결과가 달라졌지만, 길이 감소와 내용 변화 중 어떤 내부 메커니즘 때문인지는 증명하지 않았다.

**줄여서 나빠진 사례 — Portland.** 과거 숙소 가격206 이하·평점3 이상인 현재 숙소가 없어 정답은`NONE`이었다. 상위4는 맞혔지만 상위2는 가격724인`H4701`을 골랐다. 두 필수 참조는 양쪽 모두 들어 있었다. `1a514b14afa774d6--case-1--needed`의 사례다. 질문의 직접 참조가 아닌 기록을 제거하는 일이 항상 이득인 것은 아니며, ‘관계상 불필요’라는 라벨을 ‘실제 해롭다’로 치환할 수 없다.

**기본 근거 부재 실패 — 합성 점검.** 요청은 Alex의 저녁을 재사용하는 것이었으나 제공된 저녁 기록은 Taylor의 것이었다. Alex의 숙소 기록은 있지만 현재 이용할 수 없었다. 정답은`{"dinner":"UNKNOWN","accommodation":"NONE"}`인데, 두 지침 모두`{"dinner":"R901","accommodation":"NONE"}`을 출력했다. `sanity-0-reuse-UN`이다. 다른 사람의 기록을 사용하면 안 된다는 지침만으로 해결되지 않았다.

반대 방향 사례를 포함한24개 변화 쌍과 전체 원문은 [사례 파일](../../evaluation/results/travel-policy-followup-20261109-v1/contrasts.json)에 있다.

## 원래 연구 방향에 주는 판단

**관계 판독과 실제 득실을 연결해야 한다는 방향은 유지할 만하다.** 이번에는 같은 모델과 과거 기록에서도 제공 개수·보류 정책에 따라 성공, 무근거 행동, 비용이 달라지는 것을 직접 관측했다. 또한 관계상 필요한 두 기억을 제공해도 작업자가 잘못 사용할 수 있고, 직접 참조가 아닌 기억을 제거해 오히려 실패할 수도 있었다.

다만 별도 학습 선택기의 필요성은 입증되지 않았다. 단순 참조 규칙이 상위2와 같은 성공 수를 더 적은 비용과 더 적은 무근거 구체 선택으로 달성했다. 현재 과제의 사람·날짜·항목 참조가 규칙으로 풀기 쉽다는 한계도 유지된다. 이번 결과를 ‘LoRA 효과가 추가로 검증됐다’거나 ‘새 효용층이 좋아졌다’고 표현하면 안 된다.

다음 순서를 권한다.

1. **상위2와 고정 점수 기준을 비교 기준으로 보존한다.** 새 지침은 개선안으로 채택하지 않는다. 더 많은 임계값을 현재 자료에서 탐색하지 않는다.
2. **작업자의 근거 처리 능력을 독립적으로 확인한다.** 새로운 작고 명확한 계약 점검에서 작업자/추론 설정을 비교한 뒤 고정한다. 단순히 지침을 길게 만드는 작업을 반복하지 않는다. 작업자의 기본 실패를 전부 선택기 학습 탓으로 돌리지 않는다.
3. **새 출처 자료에서 관계와 효용을 함께 기록한다.** 같은 관계가 다른 경험에서 반복되고, 필요한 기억·현재 이미 아는 정보·근거 없음·현재 조건 변경이 구분되는 사례를 수집한다. 모델 학습에는 관계 라벨과 실제 제공 결과를 별도로 보존하고, 문제 해결·무근거 행동·비용을 함께 평가한다.

이것은 연구를 ‘기본 UNKNOWN 분류기’로 바꾸자는 제안이 아니다. 원래 목표인 기억의 득실을 평가할 때, 작업자의 계약 실패가 효용 라벨에 섞이는 정도를 먼저 통제하자는 뜻이다. 연구의 중심은 계속 **현재 상황에서 어떤 기억을 얼마나 제공하는 것이 실제로 이득인가**에 둔다.
