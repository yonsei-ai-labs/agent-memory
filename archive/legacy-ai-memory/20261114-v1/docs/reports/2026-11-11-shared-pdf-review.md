# 공유받은 PDF 두 개 검토: 쓸 수 있는 부분과 마무리 절차

2026-11-11. 실험을 수행하지 않는 별도 검토 세션(Claude Code)이 작성함. 사용자가 받은 PDF 두 개를 저장소로 복사하고, 내용을 원 논문·공식 저장소와 대조한 뒤 현재 연구에 쓸 수 있는 부분을 정리함. 새 작업자 호출·GPU 할당·학습은 없었고 기존 파일은 수정하지 않았음.

**핵심: 두 문서는 기억 시스템 전체를 만드는 일반 로드맵이어서 대부분은 이 연구의 범위 밖임. 쓸 수 있는 것은 세 가지임. ① 상태별 수집 파일럿의 손해 결과를 공개 자료에서 다시 확인할 길(LongMemEval-S와 BEAM은 옛 값과 새 값의 근거를 따로 표시함), ② 마무리 보고의 틀(4단계 표준 절차), ③ 선행연구 대비 위치(Memory-R1, Self-RAG).** 문서에는 고쳐 읽어야 할 사실 오류가 여럿 있음(3절).

## 2. 두 문서의 내용

**논문 요약 문서(9쪽)** 는 기억 연구를 세 단계로 나누고 단계마다 논문 세 편을 비유와 함께 소개함.

| 단계 | 문서의 질문 | 소개한 논문 |
| --- | --- | --- |
| 1 저장 | 어떤 구조로 압축·구조화해 저장할 것인가 | MemGPT, HippoRAG, MemoryBank |
| 2 선택 | 무엇을 인출·통합·수정·폐기할 것인가 | Generative Agents, RAPTOR, A-MEM |
| 3 학습 | 모델 자체를 기억 관리에 최적화할 수 있는가 | Self-RAG, MemoryLLM / M+, “Larimar / RL 기반 제어(Mem0 등)” |

**벤치마크 문서(6쪽)** 는 세 부분임.

1. 벤치마크 공통의 4단계 절차: 기억 주입 → 질문과 기억 선택(상위 K개, 근거 세션을 꺼냈는지 채점) → 답변 생성 → 심판 LLM의 예/아니오 채점.
2. 데이터셋 7개 비교: LoCoMo, PerLTQA, LongMemEval, MemoryAgentBench, BABILong, BEAM, STATE-Bench.
3. 권장 5단계 순서: ① LoCoMo 또는 PerLTQA(기본 회상) → ② LongMemEval-S(갱신·시간) → ③ MemoryAgentBench(실시간 추가·수정·삭제) → ④ BABILong·BEAM(초대용량·잡음) → ⑤ STATE-Bench(기억을 실제 행동에 반영).

이 저장소의 질문은 그중 2단계의 한 부분임. 작업자와 기억 은행을 고정하고, 어떤 기억을 주거나 주지 않을 때 작업 결과가 어떻게 달라지는지를 잼.

## 3. 사실 확인

하위 검토 세션 세 개가 arXiv, ACL Anthology, 공식 GitHub, Hugging Face 카드를 열어 대조함. 그중 STATE-Bench 문서, BEAM 질문 파일 100개와 대화 파일 1개, LongMemEval-S 로컬 사본은 이 세션이 직접 다시 확인함. 나머지는 하위 세션이 가져온 인용을 옮긴 것임.

### 3.1 고쳐 읽어야 하는 곳

### 3.2 맞는 것으로 확인한 곳

- LongMemEval: S는 약 115k 토큰, M은 500세션·약 150만 토큰, 지식 갱신과 보류를 평가함, ICLR 2025. 로컬 사본의 세션 수 중앙값은 47–50개임. 공식 채점은 `gpt-4o-2024-08-06`에 유형별 예/아니오 지시문 다섯 종을 주는 방식임. [논문](https://arxiv.org/abs/2410.10813)
- BEAM: 100대화·2,000문항, 능력 10종, 최대 1,000만 토큰, ICLR 2026.
- MemoryBank의 망각 곡선 갱신 규칙, Generative Agents의 세 점수(최신성·중요도·관련성) 합산.
- MemGPT, HippoRAG, RAPTOR, A-MEM의 한 줄 요약은 대체로 맞음.

### 3.3 LoCoMo의 평가 논란

LoCoMo를 1단계로 권하지만 평가 자료로서 논란이 있음. Mem0 논문에서 전체 대화를 그대로 넣는 방식이 약 73%로 자사 기억 시스템(68.44%)보다 높았음. Zep과 Mem0는 서로의 LoCoMo 점수를 반박했음. 제3자 점검은 1,540문항 중 99개(6.4%)의 정답 오류를 보고함(동료 심사를 거친 자료는 아님). [Mem0 논문](https://arxiv.org/abs/2504.19413), [Zep 글](https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/), [점검 저장소](https://github.com/dial481/locomo-audit)

| 2 | BEAM (벤치마크 문서 4단계) | 같은 비교를 처음 보는 자료에서 한 번 확인 |

**1. LongMemEval-S.** 로컬 사본 500문항을 계산함.

| 유형 | 문항(보류 30개 제외) | 근거 표시 |
| --- | ---: | --- |
| 지식 갱신 | 72 | 모든 문항에 옛 값 세션 1개와 새 값 세션 1개가 있고 날짜가 다름. 70문항은 양쪽 발화까지 표시됨. 표시된 발화는 세션당 중앙 65토큰, 최대 171토큰 |
| 여러 세션 | 121 | 근거 세션 2–5개. 111문항은 모든 근거 세션에 발화 표시가 있음. 정답이 숫자인 문항 97개 |
| 시간 추론 | 127 | 근거 세션 1–6개. 87문항은 2개 이상이 모두 표시됨 |
| 단일 세션 세 유형 | 150 | 근거 세션 1개, 모두 표시됨 |

- 근거 세션 전체는 중앙 약 6,000토큰이라 현재 전달 예산(1,024토큰)에 들어가지 않음. 표시된 발화만 쓰면 470문항 모두 들어감.
- 지식 갱신 70문항에서 무기억 / 새 값만 / 옛 값만 / 둘 다의 네 조건을 만들 수 있음(280호출).
- 여러 세션 111문항에서는 무기억 / 전부 / 하나씩 뺀 묶음을 만들 수 있음(502호출). 근거의 일부만 줬을 때의 결과를 봄.
- 이 500문항은 선택기의 근거 검색 평가에서 이미 결과를 본 자료임. [피드백 검토](2026-11-10-ranking-and-collection-feedback.md)는 이를 봉인 test로 부르지 않기로 했음. 따라서 설계와 예행에 쓰고, 확인은 아래 BEAM에서 하는 것이 맞음.

**2. BEAM.** 문서는 초대용량 시험으로 소개하지만, 이 연구에 쓸모 있는 것은 크기가 아니라 근거 표시임. 공식 저장소의 질문 파일 100개를 계산함.

- 대화마다 능력 10종에 두 문항씩 있음. 지식 갱신은 200문항임.
- 지식 갱신 190문항에 옛 정보 발화와 새 정보 발화의 ID가 따로 표시돼 있음(`original_info`, `updated_info`). 두 ID가 겹치지 않는 것은 181문항임.
- 180문항의 채점 기준은 “이 값을 말해야 함” 형식이고 값이 5낱말 이하임. 예: `LLM response should state: 1,350 words`.
- 두 조건을 모두 만족하는 것은 164문항·95대화임. 네 조건이면 656호출임.
- 대화 한 개(100K의 1번)에서 ID가 실제 발화와 맞는 것을 확인함. 근거는 사용자 발화였고 81–348토큰이었음.
- 저장소가 한 번도 쓰지 않은 자료임. 근거 발화만 전달하므로 대화 길이와 무관하게 쓸 수 있음. 자료는 CC BY-SA 4.0임.
- 다른 능력에도 역할이 나뉜 근거 ID가 있음. 시간 추론은 두 사건의 발화가 따로 표시되고(`first_event`, `second_event`), 모순 해결은 두 진술이 따로 표시됨. 능력마다 200문항 중 짧은 값으로 채점할 수 있는 것은 정보 추출 130, 지시 따르기 108, 여러 세션 추론 97, 시간 추론 41개임.
- 지시 따르기는 사용자가 예전에 준 지시를 나중 답에 반영하는지를 봄. 벤치마크 문서가 STATE-Bench의 설명으로 적은 내용은 오히려 이쪽에 가까움.

**3. 4단계 표준 절차.** 이 절차로 보면 우리 실험은 2단계(선택)만 바꾸고 1·3·4단계를 고정한 것임. 문서의 “근거 세션을 꺼냈는가”와 “답이 맞는가”는 우리 보고서의 근거 확보와 작업 성공에 해당함. 표준 절차에는 기억 없이 풀었을 때의 결과와 기억 때문에 틀린 수가 없음. 이 두 칸을 잰 것이 이 연구가 더한 부분이라고 정리할 수 있음.

**4. Memory-R1과 Self-RAG.**

- Memory-R1은 가장 가까운 선행연구임. 후보 기억 60개에서 쓸 것을 고른 뒤 답하게 하고, 최종 답의 정확 일치만 보상으로 학습함. 고르는 단계를 넣으면 LoCoMo F1이 41.0 → 45.0으로 오름(LLaMA-8B, GRPO). 학습 문항은 152개임.
- 고르는 주체가 답하는 모델 자신임. 이 저장소는 작업자를 고정하고 0.6B 선택기를 따로 학습했으며 [단순 규칙을 넘지 못했음](2026-11-10-memory-direct-ranking.md). 이 부정 결과에는 “작업자 밖의 작은 모델을 따로 학습한 경우”라는 조건을 붙여야 함. 저장소에는 [대조학습 대안 노트](../ai-memory-alternatives-to-contrastive-learning-2026-11-08.md)에 한 번 인용돼 있음.
- Self-RAG의 세 판단(검색 여부, 관련성, 근거 지지)은 이 저장소가 따로 보존하는 세 필드(제공·보류, 관계 정답, 근거 있는 성공)와 대응함. 차이는 라벨의 출처임. Self-RAG는 GPT-4의 판단을 쓰고, 이 저장소는 같은 작업자에게 기억을 줬을 때와 안 줬을 때의 실제 결과를 씀.
- Mem0와 Memory-R1의 기억 관리자는 바뀐 정보를 저장할 때 고쳐 쓰거나 지움. 낡은 기억이 답을 망치는 일을 저장 단계에서 막으려는 것임. 이 저장소가 잰 손해는 그 정리가 없을 때 치르는 비용의 크기에 해당함. 저장할 때 정리하는 방법과 줄 때 고르는 방법은 같은 문제의 두 해법이며, 이 연구는 뒤쪽을 다룸.

**5. STATE-Bench.** 문서의 설명은 틀렸지만 실제 내용은 이 연구의 질문과 가까움.

- Agent Learning Track은 영역별 과거 실행 궤적 100개에서 얻은 내용을 제공했을 때 보류 과제 50개의 성공이 오르는지를 잼. [트랙 문서](https://github.com/microsoft/STATE-Bench/blob/main/docs/AGENT_LEARNING_TRACK.md)
- 에이전트는 `retrieve_learnings(query, top_k=3)` 한 곳으로만 기억을 받음. 선택 정책을 끼워 넣는 자리가 정해져 있고 전달 개수가 고정임.
- 궤적은 실제 에이전트 실행 기록임. [현재 상태 문서](../current-status.md)가 다음 단계로 찾는 “자연스러운 진행·실패 기록”의 후보가 됨.
- 제약이 큼. 공식 실행은 모의 사용자와 심판에 GPT-5.4를 고정해 API 비용이 들고, 과제마다 5회 실행함. 9B 작업자가 이 과제를 풀 수 있는지 모름. 문항별로 필요한 과거 정보는 표시돼 있지 않음(과제 파일 한 개만 확인).
- 따라서 마무리 전에 시작할 일이 아님. 궤적에 실패가 얼마나 들어 있는지도 확인하지 않았음.

**6. 최신성 점수.** 값이 바뀌는 자료에서는 “관련 기록 중 가장 최근 것”이 가장 강한 단순 기준선이 됨. 1·2번의 비교에서 학습 선택기를 다시 시험한다면 이 규칙과 먼저 비교해야 함.

### 4.3 써 볼 기법

| 기법 | 문서의 출처 | 판단 |
| --- | --- | --- |
| 관련 기록 중 가장 최근 것을 고르는 규칙 | Generative Agents의 최신성 점수 | 바로 씀. 값이 바뀌는 자료에서 가장 강한 단순 기준선이며 학습과 호출이 필요 없음 |
| 큰 모델이 후보에서 직접 고르게 하기 | Memory-R1의 선택 단계를 학습 없이 쓴 형태 | 96상태에서는 [이미 측정함](2026-11-10-selector-size-and-transfer-validation.md)(4B 56, 9B 54, 규칙 55). 상태 대조 자료에는 아직 없어 기준선으로 붙일 만함 |
| 날짜·순서를 붙여 옛 값과 새 값을 함께 주기 | 벤치마크 문서의 3단계 | 5.2절의 “둘 다” 조건이 이것임. 고르지 않고 표시만 해도 손해가 사라지는지 봄 |
| 읽는 방식 바꾸기(기록별 메모를 쓴 뒤 답하기, 구조화 형식) | LongMemEval 논문의 Chain-of-Note와 JSON 형식 | 보류함. 출력 형식을 바꾼 [작업자 계약 점검](2026-11-10-worker-contract-check.md)이 사전 기준을 통과하지 못했고 출력 토큰이 약 5.6배였음 |
| 결과 보상 강화학습, 성찰 토큰 미세조정 | Memory-R1, Mem-α, Self-RAG | 하지 않음. 답하는 모델을 학습시키므로 작업자를 고정하는 설계와 맞지 않고, 보상마다 작업자 호출이 필요함 |

관계 라벨로 선택 모델을 감독하는 방식은 Self-RAG의 비평 라벨과 같은 계열임. 에이전트의 [새 실험](2026-11-11-memory-need-learning.md)이 이미 이 방식을 씀(실제 성공·실패 라벨을 학습에 쓰지 않음).

### 4.4 지금은 쓰지 않는 것

- 저장 구조 논문(MemGPT, HippoRAG, MemoryBank, RAPTOR, A-MEM): 이 연구는 기억 은행을 고정하고 선택만 바꿈. 배경 설명에만 씀.
- 모델 내부 기억(MemoryLLM, M+, Larimar): 외부 기억을 고르는 문제와 다른 접근임.
- BABILong: 긴 글 속에서 단서를 읽는 시험이며 기억 은행에서 고르는 문제가 아님. 공개 파일에 근거 위치도 없음.
- PerLTQA: 중국어 원자료이고 영어판의 근거 위치가 맞지 않음.
- LoCoMo: 독립된 대화가 10개뿐이고 지식 갱신 유형이 없으며 3.3절의 논란이 있음.
- MemoryAgentBench: 충돌 해결이 8행뿐이고 대체 관계가 표시돼 있지 않음. LongMemEval을 포함하므로 독립 자료로 세지 않음.
- 5단계 순서 전체: 기억 시스템을 만들어 가는 순서이며 이 연구의 질문과 다름. 2단계와 4단계의 자료만 위 용도로 씀.

## 5. 긍정 결과를 검증하고 마무리하는 방법

### 5.1 파일럿의 긍정 결과를 원 출력에서 다시 계산함

[상태별 수집 파일럿](2026-11-11-memory-state-screen.md)의 작업자 원 출력 120개를 별도 코드로 다시 채점함. 보고된 수치와 모두 일치함.

| 기억이 필요한 24상태 | 성공 | 가족별(6가족, 각 4상태) |
| --- | ---: | --- |
| 무기억 | 0 | 모두 0/4 |
| 목표만 읽는 판독기 | 6 | 모두 1/4 |
| 목표의 첫 참조를 고르는 규칙 | 12 | 모두 2/4 |
| 필수 근거 | 24 | 모두 4/4 |
| 반대 상태용 기억 | 0 | 모두 0/4 |

| 정보가 이미 충분한 12상태 | 성공 | 무기억 성공을 깨뜨린 수 |
| --- | ---: | --- |
| 무기억 | 12 | — |
| 목표만 읽는 판독기 | 10 | 2 (첫 시도 실패 조건, 2가족) |
| 반대 상태용 기억 | 8 | 4 (첫 시도 실패 조건, 4가족) |

함께 확인한 것은 다음과 같음.

- 무기억 메시지 36개에는 필수 기록이 없음. 필수 근거 메시지에는 필수 기록이 모두 있고, 반대 상태용 메시지에는 하나도 없음.
- 메시지 120개에 정답 표지나 정책 이름이 없음.
- 원 출력에서 답을 뽑은 결과가 저장된 추출과 120개 모두 같고, 안정성 반복 2개가 원 출력과 같음.

두 결과는 성격이 다름.

- **0 → 24는 설계가 정한 결과에 가까움.** 여섯 가족이 한 상태도 다르지 않게 같은 값을 냄. 작업자가 받은 기록의 ID를 답에 옮기는 과제이기 때문임. 이 결과는 작업자가 필수 근거를 받으면 푼다는 것과, 같은 목표·은행에서 상태에 따라 필요한 기록이 달라지게 자료를 만들 수 있다는 것을 보여 줌. 새 가족에서 반복해도 같은 값이 나올 가능성이 높고, 그만큼 새로 알게 되는 것은 적음.
- **충분한 상태의 손해는 설계가 정하지 않은 결과임.** 현재 관측에 정답 근거가 다 있는데도 맞지 않는 기록을 더하면 작업자가 그쪽으로 답을 바꿈. 다만 첫 시도 실패 조건의 6상태(가족당 하나)에서만 나왔음. 반대 상태용 기억은 4/6, 판독기는 2/6이며 가족 단위 95% 구간은 0.30–0.90과 0.10–0.70으로 넓음(Wilson). 이미 확인한 항목 조건의 6상태에서는 0/6임.

검증해서 닫을 가치가 큰 것은 손해 쪽임.

### 5.2 마무리 순서 (제안)

지금까지의 보고서는 긍정 결과마다 한계를 적고 다음 탐색으로 넘어갔음. 닫으려면 탐색과 확인을 나누고, 확인 실험은 결과가 어느 쪽이든 그 주장에 대한 작업을 끝내도록 실행 전에 정해야 함.

| 주장 | 지금의 근거 | 닫는 방법 |
| --- | --- | --- |
| 가. 필요한 기억은 현재 상태에 따라 달라지고, 맞는 기억을 받으면 작업자가 푼다 | 24상태·6가족, 재계산 일치, 설계가 정한 결과 | 추가 실험 없이 “통제 개입에서의 기능 확인”으로 확정함. 자연 발생 이력으로의 일반화는 주장하지 않음 |
| 나. 현재 상태에 맞지 않는 기억은 이미 되던 성공을 깨뜨린다 | 6가족 중 4가족, 한 조건에서만 관측 | 아래 확인 두 가지를 각각 한 번 실행함 |
| 다. 작은 학습 선택기는 단순 규칙을 넘지 못했다 | 96상태에서 46–51 대 규칙 55 | 추가 학습 없이 부정 결과로 확정함. 재개 조건을 미리 적어 둠(규칙은 실패하고 다른 묶음은 성공하는 상태가 새 가족에서 일정 수 이상 확인될 때) |

주장 나의 확인은 두 가지임.

1. **같은 도구로 새 가족에서 확인함.**
   - 에이전트가 2026-11-11 06:12에 고정한 [새 실험](2026-11-11-memory-need-learning.md)(`3c67f8e`)이 첫 관측을 만들어 냄. 쓰지 않은 train 24가족으로 같은 두 대조를 만들고, 그중 확인 6가족에서 무기억·필수 근거·반대 상태용 기억을 실제 작업자에게 실행함. 주 비교는 학습 모델 두 조건이지만 주장 나에 대한 새 가족 6개의 결과가 함께 나옴.
   - 이 보고서를 쓰는 시점에 그 결과는 없음. 읽는 법을 미리 적어 둠. 볼 것은 “첫 시도 실패 조건의 이미 충분한 상태에서 반대 상태용 기억이 무기억 성공을 깨뜨린 가족 수”임. 6가족 중 3가족이어도 95% 구간이 0.19–0.81이라 크기를 정할 수 없음. 방향을 확인하는 정도로 읽음.
   - 크기까지 확정하려면 봉인된 dev 20가족에서 같은 조건을 한 번 실행함. 20가족 중 5가족 이상에서 손해가 나면 95% 하한이 0.10을 넘음. dev 가족에는 아직 과거 선택 기록이 없고 [입력 명세](../../datasets/travel_state_transfer/20261109-v1/README.md)만 있어 기록 생성 호출이 먼저 필요함. 이 비용은 확인하지 않았음.
2. **공개 자료에서 확인함.** LongMemEval-S 지식 갱신 70문항으로 지시문·조건·채점 규칙을 정하고 예행함. 그 뒤 BEAM 지식 갱신 164문항·95대화에서 한 번 실행함. 조건은 무기억 / 새 값만 / 옛 값만 / 둘 다이고, 파일럿과 같은 구조를 보려면 “새 값이 현재 대화에 있을 때 옛 값을 기억으로 더한 경우”를 추가함.

두 확인에 공통으로 미리 정할 것은 다음과 같음.

- 통과 기준과, 통과했을 때와 미달했을 때 보고서에 쓸 문장.
- 실행은 한 번임. 결과를 본 뒤 지시문·조건·채점을 바꿔 다시 하지 않음. 미달이면 “파일럿에서만 관측됨”으로 기록하고 끝냄.
- 작업자 능력 점검. “새 값만” 조건에서 작업자가 충분히 풀지 못하면 그 자료는 선택이 아니라 작업자 한계를 재게 됨. 이전 가격 비교 요청에서 같은 문제가 있었음.
- 무기억 조건의 성공이 0에 가까운지. 높으면 추측이 가능하거나 작업자가 학습 중에 본 자료일 수 있음.

비용은 크지 않을 것으로 봄. 파일럿의 실제 속도는 호출당 1.76초였음(입력 약 1,000토큰, 출력 약 16토큰). 공개 자료의 호출은 입력이 더 짧고 출력이 더 길 수 있어 호출당 2–3초로 잡으면, LongMemEval-S 420호출과 BEAM 약 1,000호출을 합쳐 L4에서 한 시간 안팎임(추정).

에이전트의 새 실험은 다시 학습 모델의 비교임. 그 보고서도 규칙이 구조상 정답을 고를 수 있는 자료라고 적었고, 파일럿에서 규칙은 24/24였음. 같은 구조의 자료이므로 학습 모델이 규칙보다 나은 결과를 낼 여지가 거의 없음. 이 실험이 보여 줄 수 있는 것은 작은 모델이 현재 상태를 읽도록 학습되는지임. 주장 다는 그 결과와 무관하게 남음.

마무리가 목표라면 이 실험에서 주장 나의 관측을 받아 위 확인으로 이어 가고, 자연스러운 사례 탐색과 STATE-Bench는 그 뒤의 별도 질문으로 두는 것이 맞음.

### 5.3 채점이 남은 문제임

공개 자료로 가면 지금의 ID 정확 일치 채점을 쓸 수 없음.

- LongMemEval의 공식 채점은 심판 LLM임. 외부 API를 쓰거나, 검증하지 않은 로컬 심판을 써야 함.
- LongMemEval-S 지식 갱신 72문항 중 정답 문자열이 새 값 발화에만 그대로 있는 것은 46문항임. 나머지는 계산이나 바꿔 말하기가 필요함.
- BEAM은 채점 기준이 짧은 값으로 주어져 문자열 포함으로 채점할 수 있는 문항이 많음(180/200). 다만 `1,350`과 `1350`, `250ms`와 `250 ms` 같은 표기 차이를 처리하는 규칙을 실행 전에 고정해야 함.
- 옛 값을 답했는지를 자동으로 가리려면 옛 값 문자열이 필요함. BEAM에는 혼동 설명 문장(`potential_confusion`)만 있어 값을 따로 뽑아야 함.

## 6. 한계와 확인하지 못한 것

- 5절은 제안이며 실험 결과가 아님. 작업자가 LongMemEval-S와 BEAM의 문항을 근거를 받고 푸는지는 측정한 적이 없음.
- 손해 결과는 6가족·한 조건의 관측임. 구간이 넓어 크기를 말할 수 없음.
- BEAM은 질문 파일 100개를 모두 확인했지만 대화 파일은 한 개만 열었음. 근거 발화의 길이 분포와, 옛 값이 실제로 그 발화에 적혀 있는지는 전체를 받아 확인해야 함.
- LongMemEval-S의 “정답이 근거 발화에 그대로 있음”은 단순 문자열 대조이며 자동 채점 가능 문항의 하한임.
- 사실 확인에서 OpenReview와 AAAI 페이지는 열리지 않아 학회 정보는 ACL Anthology, PMLR, 학회 공식 페이지, arXiv 주석에서 가져옴. Mem-α의 게재처, LongMemEval-M 파일, STATE-Bench 궤적의 내용은 확인하지 않았음.
- 벤치마크 문서의 세부 수치 가운데 “상위 K개는 보통 3–5개”, “Colab A100 한 장이 적합”은 대조할 출처가 없어 확인하지 않았음.
- PDF의 작성자와 출처를 모름.
- 이 보고서는 [결과 색인](README.md)에 연결하지 않았음. 색인 파일에 다른 작업의 커밋되지 않은 변경이 있어 수정하지 않았음.
