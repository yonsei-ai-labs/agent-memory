# 정확한 여행 기억이 실제 결정에 주는 득과 실

**이번 파일럿에서는 같은 기억의 제공이 현재 정보와 작업자에 따라 성공을 늘리기도, 줄이기도 했다.** 9B 작업자의 평가 16요청에서 필요한 사실이 과거에만 있을 때 무기억 1 → 학습 선택 10건, 같은 사실이 현재에도 보일 때 무기억 11 → 학습 선택 9건이었다. 그러나 단순 참조 규칙과 학습 선택의 평가 입력·결과가 같았다. 학습 선택기의 별도 필요성은 아직 입증되지 않았다.

이 결과는 [참조 판독 학습](2026-11-09-memoryarena-travel-references.md)의 후속 **작업자 효용 평가**다. 새 신경망 학습은 하지 않았다. [4B 사전 계획](../ai-memory-travel-worker-utility-plan-2026-11-09.md)을 실행하고, 4B의 약한 수행을 본 뒤 [9B 진단 계획](../ai-memory-travel-worker-9b-transfer-2026-11-09.md)을 고정했다. 9B 결과는 사후 비교이며 새 독립 확인 집합이 아니다.

## 실제로 실행한 범위

MemoryArena 원문에서 명시적인 식당 재사용·상대 비교 요청 22개를 사용했다. 개발 3계획·6요청, 평가 8계획·16요청이다. 원래 관계 학습의 계획별 분할을 유지했고, 계획마다 두 요청을 작업자 결과를 보기 전에 해시 순서로 골랐다. 같은 요청의 두 정보 상태와 여러 정책을 독립 경험으로 세지 않는다.

과거 기록 132개는 Qwen3.5-4B가 실제로 생성했다. 다만 **우리가 구성한 6개 식당 메뉴에서 고르는 작은 과거 과제**이며, 원래의 전체 여행 계획을 에이전트가 수행한 기록은 아니다. 원문의 사람·여행 날짜·식사 항목과 도시를 유지했다. 실제 선택은 모두 메뉴 안에 있었고, 지정 음식 종류·최저가·동점 조건의 원래 과거 목표를 만족한 선택은 **104/132**였다. 과거 목표를 틀려도 실제 선택 사실을 그대로 기억으로 사용했으며 정답 식당으로 교체하지 않았다.

현재 작업자는 참조한 과거 식당과 같은 도시의 공개 목록에서 식당 하나를 고른다. 원문의 가격·평점·음식 종류 조건을 모두 만족해야 한다. 이 도시와 전체 선택지는 모든 정책에 공통으로 제공했다. 가능한 식당이 없으면 `NONE`이 정답이며, 필요한 사실이 없다는 `UNKNOWN`은 허용된 응답이지만 작업 성공에는 포함하지 않는다. 데이터 표의 가격·평점은 벤치용 값이며 현실의 현재 식당 정보가 아니다.

| 현재 정보 | 공통 입력 | 기억 제공이 더하는 것 |
| --- | --- | --- |
| 과거에만 있음 (`memory_needed`) | 현재 요청·도시·식당 목록 | 사람·날짜·식사에 해당하는 실제 과거 선택 |
| 현재에도 보임 (`reference_visible_now`) | 위 입력 + 정확히 같은 과거 사실의 현재 도구 관측 | 이미 관측한 사실의 중복 또는 다른 과거 기록 |

후자에서 ‘무기억’은 현재 관측까지 없앤다는 뜻이 아니다. 이 관측은 작업자와 선택기, 모든 정책에 동일하게 제공했다.

정책은 무기억, 6후보 전체, 날짜 표현을 정규화한 BM25 상위 1개, 기존 LoRA 선택기, 사람·날짜·식사 참조 규칙이다. 후보 6개에는 주석상 참조 기록이 반드시 들어 있다. **후보 수집부터 수행하는 전체 검색 과제는 아니다.** 선택기는 기존 dev에서 정한 CE checkpoint와 임계값 0.25를 유지했다.

4B에서 과거 132회와 현재 230회, 9B에서 같은 과거를 재사용하고 현재 230회를 생성했다. 총 **새 생성 592회**다. 현재 230회는 요청 22 × 정보 상태 2 × 정책 5 = 220회와 정확한 입력 반복 10회다. 두 결과 묶음에 과거 132행이 각각 저장되어 있지만 새 생성으로 두 번 세지 않는다. 모델은 고정 revision의 Qwen3.5-4B·9B, greedy, thinking off, 출력 상한 48토큰이다.

## 평가 결과

각 셀은 **같은 평가 16요청 중 성공 수**다. 9B는 4B와 과거 기록·현재 메시지·입력 토큰·선택한 기억이 같고 현재 작업자만 달라졌다.

| 작업자 | 현재 정보 | 무기억 | 전체 6개 | BM25 | 학습 선택 | 참조 규칙 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 4B | 과거에만 있음 | 3 | 4 | 8 | 7 | 7 |
| 4B | 현재에도 보임 | 7 | 3 | 4 | 3 | 3 |
| 9B | 과거에만 있음 | 1 | 7 | 8 | 10 | 10 |
| 9B | 현재에도 보임 | 11 | 10 | 9 | 9 | 9 |

학습 선택기의 참조 포함은 두 상태 모두 **16/16**이다. 참조 규칙도 동일하다. 정확한 참조를 줬다는 사실과 작업자가 그 정보로 최종 조건을 만족했다는 사실을 분리해야 한다. 개발의 학습 선택 참조 포함은 과거 전용 5/6, 현재 관측 6/6이었다. 개발과 평가 효용을 합쳐 선택기를 재선택하지 않았다.

학습 선택을 무기억과 **요청별로 짝지으면** 다음과 같다. 순증감만 보면 가려지는 악화도 함께 센다.

| 작업자·현재 정보 | 실패→성공 | 성공→실패 | 둘 다 성공 | 둘 다 실패 | 순증감 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 4B·과거 전용 | 7 | 3 | 0 | 6 | +4/16 |
| 4B·현재 관측 있음 | 1 | 5 | 2 | 8 | −4/16 |
| 9B·과거 전용 | 10 | 1 | 0 | 5 | +9/16 |
| 9B·현재 관측 있음 | 0 | 2 | 9 | 5 | −2/16 |

이 ‘득·실’은 **고정한 작업자·프롬프트·현재 상태에서 관측한 출력 변화**다. 기억 자체의 보편적 유익·유해 라벨이나, 아직 학습하지 않은 효용 예측기의 정확도가 아니다.

## 성공 수만으로 놓치기 쉬운 부분

새 과거 선택을 기준으로 계산하면 22요청 중 6개는 만족하는 식당이 없다. 개발 3/6, 평가 3/16이며 모두 상대 비교 요청이다. 구성 전에 실제 과거 선택을 알 수 없었고, 이런 사례를 사후 삭제하지 않았다. 가능한 답이 없는 조건을 따로 분석했다.

4B의 과거 전용 무기억 출력은 **16개 모두 `NONE`**이었다. 그중 3개 성공은 불가능한 요청에서 우연히 맞은 것으로, 과거를 추론했다고 해석하면 안 된다. 가능한 식당이 있는 평가 13개로 한정하면 4B 무기억 0 → 학습 선택 7, 9B 무기억 0 → 학습 선택 10이다. 반면 불가능한 3개에서 학습 선택을 받은 두 작업자는 모두 0/3이었다.

9B의 과거 전용 조건을 나누면 재사용은 학습 선택 **8/8**, 가격·평점·음식 종류의 상대 비교는 **2/8**이다. 실패 원인은 참조 대상을 고르는 문제만으로 설명되지 않는다. 정확한 참조 이후 조건을 함께 적용하는 작업자의 능력이 큰 병목이다. 개발·평가의 모든 정책별 세부 집계는 [comparison.json](data/travel-worker-utility-20261109/comparison.json)에 보존했다.

현재 관측이 있으면 기억을 더 주지 않는 단순 규칙은 다음 자료에서 반드시 비교할 기준선이다. 이번 결과를 본 뒤 그 규칙을 선택한 것을 새 확인 결과나 학습 성과로 보고하지는 않는다.

## 같은 기억이 이득과 손해를 보인 예

9B의 `travel-92-turn-8-clause-0`은 “첫날 Elijah와 저녁을 함께하고 싶다”는 요청이다. 실제 과거 선택은 `R5591`이었다.

| 현재 정보 | 추가 기억 없음 | 정확한 기억 추가 |
| --- | --- | --- |
| 과거에만 있음 | `R130`, 실패 | `R5591`, 성공 |
| 현재에도 `R5591`이 보임 | `R5591`, 성공 | `NONE`, 실패 |

같은 원문 요청과 같은 사실인데 현재 관측 여부에 따라 제공 효과가 달랐다. 왜 중복 입력에서 `NONE`으로 바뀌었는지에 관한 내부 원인은 이 실행만으로 알 수 없다. 잘못된 기억을 심어서 손해를 만든 사례는 아니다.

다른 예인 `travel-247-turn-4-clause-3`은 과거 비용 37보다 최소 50% 비싸고, 평점 이상이며 Desserts를 제공해야 한다. 가격 하한은 55.5다. 현재 관측이 있는 무기억 조건에서는 비용 86의 `R4147`로 성공했지만, 정확한 기억을 추가하자 비용 20의 `R384`를 골라 실패했다. 참조를 잘 찾아도 가격 조건을 제대로 사용하지 못할 수 있다.

불가능한 요청의 `travel-178-turn-6-clause-1`에서는 비용 11보다 최소 10% 저렴해야 하므로 상한이 9.9다. 무기억의 `NONE`은 결과상 맞았지만, 기억을 받은 작업자는 비용 13인 `R7058`을 선택했다. 이 경우의 무기억 정답을 정보에 근거한 추론 성공과 혼동하지 않는다. 원문·과거 선택·조건·실제 출력을 [사례 JSON](data/travel-worker-utility-20261109/examples.json)에 연결했다.

## 비용과 자원

9B 평가의 평균 입력·선택기 포함 시간은 아래와 같다. 단일 A100 실행의 탐색적 측정이며 모델 로딩·공통 과거 생성·전송은 제외했다. 정책별 출력 길이와 성공 여부도 달라 시간 차이를 순수한 방법 속도로 해석하지 않는다.

| 현재 정보 | 정책 | 평균 입력 토큰 | 선택기+작업자 초/결정 |

| 과거 전용 | 무기억 | 1,163.4 | 0.619 |
| 과거 전용 | 전체 6개 | 1,468.3 | 0.792 |

| 과거 전용 | 참조 규칙 | 1,209.8 | 0.763 |
| 현재 관측 있음 | 무기억 | 1,219.8 | 0.766 |
| 현재 관측 있음 | 전체 6개 | 1,524.7 | 0.804 |
| 현재 관측 있음 | BM25 | 1,265.9 | 0.771 |
| 현재 관측 있음 | 학습 선택 | 1,266.2 | 0.811 |

선택한 한 기록은 전체 6개보다 입력 토큰을 줄였지만, 학습 선택기 자체가 약 57–59ms 필요했다. 규칙은 약 0.2ms였고 평가에서는 학습 선택과 결과가 같았다. 따라서 토큰 절감만으로 별도 모델의 비용 이득을 주장할 수 없다. 성공률·악화 수·토큰·시간을 분리해 보고하며, 사후에 유리한 비용 가중치를 골라 하나의 효용 점수로 만들지 않았다.

과거 132선택 생성에는 입력 46,920·출력 1,309토큰과 생성 86.07초가 들었다. 9B에서 이 비용을 다시 청구하지 않는다. 판독기 로딩·호환 확인은 실행별 약 11.8초, 작업자 로딩은 4B 31.8초·9B 62.4초였다.

전용 Colab A100을 두 번 사용했다. controller 경과 시간은 329.13초와 308.89초, 합계 약 10.63분이다. 설치·전송·회수를 포함한 시간이며 정확한 과금 GPU 시간이 아니다. **두 세션 종료와 최종 사용률 0.00/hr를 확인했다.** 로컬 GPU·다른 에이전트의 GPU·유료 모델 API·새 신경망 학습은 사용하지 않았다. [자원 기록](data/travel-worker-utility-20261109/resource-history.json)에 회수 묶음 해시와 비용 집계 범위를 남겼다.

## 검산과 공유 범위

- 실행 전 데이터·설정·코드 고정 해시를 실제 `upload.zip`과 대조했다. 4B 후 9B 재사용 경로를 추가한 실행 코드는 각각의 업로드 사본으로 검산했다. 주 채점 코드는 최초 채점 전 고정한 해시와 같다.
- 실제 과거 출력에서 기억을 재구성하고, 230개 입력·정책·출력·가격/평점/음식 조건·짝지은 득실·기록 비용을 작업자별로 재계산했다.
- 별도 SQLite 조건식과 Decimal 경계 계산으로 22개 요청의 가능한 식당 집합을 대조했다. 이는 같은 주석의 다른 구현 검산이며 독립 주석 검토는 아니다.
- CPU tokenizer로 모든 입력 토큰과 저장 출력 토큰→문자를 재계산했다. 두 묶음 각 362행이 일치하며, 9B의 과거 132행은 재사용이다.
- 4B와 9B의 과거 기록 132행은 바이트 단위로 같다. 현재 230개 메시지·입력 토큰·선택한 기억도 같다.
- 실행별 반복 10개는 모두 출력 토큰까지 같았다. 반복은 split별 첫 요청의 과거 전용 조건에 한정되며 모든 조건의 변동성을 측정한 것은 아니다.
- Harrier의 transformers 버전 이동은 이전 dev 36쌍에서 분류·Top1 동일, 확률 최대 차이 약 0.00000942로 확인했다. 새 44선택의 전체 인코더 순전파를 다른 구현에서 다시 수행한 것은 아니다.

## 연구 방향에 주는 의미

처음 질문인 “현재 상황에서 기억을 제공하면 무엇이 좋아지고 나빠지는가”를 실제 출력과 연결했다는 점은 진전이다. 그러나 명시적 참조 요청, 정답이 포함된 작은 후보 집합, 구성한 과거 과제이므로 과거 전용 조건의 이득은 설계상 기대되는 부분도 크다. 공식 MemoryArena 전체 점수나 자연 에이전트 기억의 일반적 효과로 확대하지 않는다.

이 자료는 새로운 효용 모델을 학습할 만큼 크지 않다. 같은 AI 에이전트의 주석 22개와 이미 관계 진단에 쓴 평가 계획 8개뿐이며, 9B 비교도 사후다. 592회 생성이나 두 정보 상태를 독립 출처 수로 부풀려서는 안 된다.

다음은 층을 더 추가하기보다 **새 출처에서 현재 정보의 충분성·참조의 유무·조건 적용의 난도**가 달라지는 자료를 확보하는 것이다. 실제 과거 전체 작업의 기록, 참조가 없는 후보 집합, 현재 사실의 중복, 관련은 있지만 조건이 다른 경험을 포함해야 한다. 명시적 참조 규칙과 현재 관측을 확인하는 규칙을 기준선으로 고정하고, 별도 학습/개발 출처에서 관계 판단과 실제 득실을 함께 학습한 뒤 새 평가 출처에서 선택기의 필요성을 판단한다. 이번 22요청에 맞춰 효용 선택기를 학습하거나 프롬프트를 계속 수정하지 않는다.
