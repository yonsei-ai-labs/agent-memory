# 기억 순위 학습과 선별 수집 피드백 검토

**기존 자료에서 제공 후 성공을 직접 예측하는 순위 학습을 제한적으로 점검하고, 다음 수집은 상태별 선택 여지를 먼저 측정하는 방향이 적절함.** 다만 세 번의 호출 결과로 사례를 영구 제외하거나, 한 번의 학습 실패를 작은 모델의 능력 한계로 결론내리는 기준은 수정해야 함.

사용자가 전달한 두 피드백의 코드와 저장 결과를 대조함. [독립 재계산과 원본 검토 코드](data/memory-ranking-feedback-20261110/README.md)를 보존함. 추가 작업자 호출·GPU 할당·신경망 학습은 없었음. 저장 벡터의 CPU 선형 판독층은 다시 적합해 검토 결과를 확인함.

## 재현된 선택 성능

24개 fold별 모델을 합친 8개 조건의 평가 예측을 재계산함. 네 학습 설정 × 두 초기값이며, 24개의 독립 평가 결과가 아님. 같은 12개 개발 가족 안의 교차 검증임.

| 확장 후보에서 고르는 방법 | 성공 / 96상태 | 후보 순위 / 177쌍 |
| --- | ---: | ---: |
| 상태마다 비어 있지 않은 묶음을 균등 무작위 선택 | 기대값 43.42 | 기대값 0.50 |
| 기존 학습 선택 | 40–43 | 0.367–0.520 |
| 가장 긴 묶음 | 52 | 0.777 |

| 측정한 후보와 무기억 중 사후 최선 | 58 | — |

순위는 같은 상태에서 실제 성공이 다른 후보 쌍만 평가하고, 점수 동률에는 0.5를 부여함. 177쌍은 28상태·10가족에서 파생돼 독립 표본 177개가 아님. 상태·가족 평균도 공유 JSON에 보존함. 원래 237후보의 무작위 기대 성공은 52.67이며 기존 52–55만으로 선택 능력을 입증하기 어려움. ‘어떤 능력도 없다’보다 **현재 평가에서 무작위를 넘는 선택 이득이 확인되지 않았다**가 정확함.

원래 후보의 결과가 다른 16쌍에서는 짧은 묶음이 13쌍을 이겼지만, 확장 후보에서는 긴 묶음의 순위 정확도가 0.777임. 후보 구성에 따라 길이와 결과의 관계가 뒤집힘. 이것은 데이터 편향의 진단이며 학습 모델이 실제로 길이 편법을 사용했다는 직접 증거는 아님.

보강 자료로 학습한 조건의 점수를 `P(개선)−P(악화)`에서 `P(개선)+P(둘 다 성공)`으로 바꾸면 다음과 같음.

| --- | ---: | ---: | ---: |
| CE, 초기값 1729 | 41 | 46 | 0.480→0.576 |
| CE, 초기값 731 | 41 | 47 | 0.486→0.616 |
| CE+선택 손실, 초기값 1729 | 42 | 45 | 0.497→0.616 |

순 개선은 정확히 **3–6상태**임. 항상 제공하는 비교와 기존 정책의 제공/보류 결정을 유지한 비교에서 성공 수가 같았음. 반면 원래 후보로 학습한 네 조건에서는 같은 점수 변경이 확장 후보 성공을 40–43에서 37–41로 낮춤. 점수 교체만으로 보편적인 개선이 보장되지 않음.

## 학습 보완에서 구분할 것

`P(개선)−P(악화)`는 기대 득실의 올바른 표현임. 네 범주 확률을 쓰면 다음 항등식이 성립함.

```text
P(개선) − P(악화)
= P(제공 후 성공) − P(무기억 성공)
```

같은 상태에서는 무기억 결과가 고정이므로, 그 추정도 후보에 무관하게 같다면 두 점수의 후보 순위는 같아야 함. 현재 네 범주 판독층은 기억을 포함한 입력에서 두 항을 함께 예측함. 보강 조건에서 후보별 무기억 성공 확률의 상태 내 범위 평균은 0.079–0.118이며, 4–14상태에서는 후보에 따라 0.5의 위아래가 바뀜. **수식의 오류보다 추정 구조의 불일치**를 고칠 근거임.

다음 학습 진단은 같은 입력·모델·분할을 유지한 두 조건으로 제한하는 것이 적절함.

1. 묶음마다 제공 후 성공 logit 하나를 출력하고 이진 교차 엔트로피로 학습함.
2. 같은 모델에 상태 내 성공/실패 후보의 순위 손실을 추가함. 예를 들어 `softplus(실패 점수 − 성공 점수)`를 비교쌍별로 계산하고, 먼저 상태 안에서 평균한 뒤 정보를 가진 상태 사이에서 평균함. 모든 후보가 같은 결과인 상태의 순위 손실은 제외하되 이진 성공 감독은 유지함.

순위 손실에는 sigmoid 이전 logit을 사용함. 순위 손실만으로 성공 확률이 보정되거나 제공 문턱이 정해지는 것은 아니므로 이진 성공 감독을 함께 둠. 무기억 성공은 **현재 상태만 읽는 별도 출력**으로 분리하고, 관측한 무기억 정답을 추론 입력으로 넣지 않음. 먼저 후보 순위를 평가한 뒤 제공/보류·비용 보정을 비교함.

별도 무기억 출력이 반드시 더 정확하다는 뜻은 아님. 후보 순위에 들어가는 기준선 추정의 흔들림을 줄이는 비교이며, 최종 제공 판단의 정확도는 따로 검증해야 함.

첫 비교는 기존 작업 성공 라벨을 유지해 목적함수 변경의 효과를 분리함. 근거 준수 목표는 별도 버전으로 비교해야 함. 현재 `input_contract_success`로 네 범주를 다시 만들면 82/408개가 바뀜. 이 지표에는 적절한 정보 부족 응답도 들어갈 수 있으므로, 앞으로는 사실 정답·근거를 준수한 작업 성공·정보 부족의 적절한 보류를 따로 보존함.

CE는 보강 조건에서 계속 감소했고 학습 순위도 미완성이었음. 그러나 손실 값의 크기만으로 기울기 영향이나 학습 부족의 원인을 확정할 수 없음. 피드백의 0.172→0.049는 **균등 점수와 완벽한 네 범주 확률에서의 평균 선택 손실**이며, 실제 학습 곡선이나 가능한 손실 전체 범위가 아님.

CPU 선형 판독 결과 44–45/96·순위 0.627–0.718도 재현함. 이는 기존에 학습된 1,024차원 벡터를 상태 안에서 중심화하고 ridge 회귀로 읽은 결과임. 표현을 순위 목표로 다시 학습한 결과가 아니며 ‘관계 정보가 없다’는 증거로 사용할 수 없음. 내부 검증은 판독층의 규제를 고르는 절차로, encoder까지 매번 새로 학습한 내부 교차 검증은 아님.

epoch·문턱·가중치는 학습 가족 안의 분할로 정하고, 바깥 가족에는 설정을 고정함. 현재 12가족은 이미 반복 검토했으므로 결과는 개발 진단으로 표시함. 목표는 긴 묶음 기준선 52/96·0.777을 넘어 참조 규칙 55/96·0.879에 접근하는지임. 여기에 도달해도 학습 선택기의 추가 연구 가치를 입증한 것은 아님. 실패 시에는 학습 적합과 가족 전이를 나눠 원인을 남기며, 작은 모델 전체가 불가능하다고 결론내리지 않음.

기존 검색기의 점수·가중치 활용은 다음 원인 분리 조건으로 남김. 먼저 출처 중복·fold 누출을 확인하고, 상태×묶음 점수와 혼동하지 않도록 참조 검색 점수의 역할을 고정해야 함. 손실·초기 가중치·입력 특징·라벨을 한꺼번에 바꾸지 않음.

## 선별 수집 제안에서 확인된 사실

- 비어 있지 않은 후보의 결과가 같은 68상태에 261/408묶음이 있음. 무기억까지 같은 결과인 것은 62상태·239묶음임. 후보 순위 정보가 적다는 뜻이며, 전부 낭비한 측정이라는 뜻은 아님. 제공 여부·비용·근거 없는 행동·전체 분포 추정에는 남겨야 함.
- 근거가 있는 재사용 요청은 필수 참조 규칙과 사후 최선 모두 36/36임. 가격 비교는 규칙 19/36·사후 최선 22/36이며 현재 화면에 필요한 사실이 있는 조건의 무기억도 7/12임.
- 준비한 명세 120가족 중 파일럿은 train 12가족임. 남은 명세는 train 48·dev 20·test 40이며 선택하지 않은 적격 원천 53가족도 확인함. 이들은 아직 실행 이력과 득실 라벨이 없는 자원임.

같은 두 요청 틀로 나머지를 대량 실행하지 않는다는 제안에 동의함. 다만 세 조건의 결과는 **추가 측정의 우선순위**이지 과제의 해결 가능성을 확정하는 판정이 아님.

| 무기억 / 필수 참조 / 검색 상위 2개의 기존 결과 | 상태 수 | 해석 |
| --- | ---: | --- |
| 실패 / 실패 / 실패 | 39 | 이 중 1상태는 다른 묶음이 성공함 |
| 실패 / 성공 / 성공 | 24 | 현재 단순 검색으로도 개선됨 |
| 성공 / 실패 / 실패 | 2 | 기억의 손해·보류를 검토할 상태. 1개는 근거 없는 무기억 정답임 |
| 성공 / 성공 / 성공 | 31 | 쉬운 성공·불필요한 제공·비용 대조로 유지 |

제안한 넷째 줄인 **실패 / 성공 / 실패는 현재 0개**임. 또한 `1a514b14afa774d6--case-1--needed`는 세 조건이 모두 실패하지만, 필수 두 기록을 포함한 네 기록 묶음은 성공하고 근거 계약도 준수함. 무기억은 `NONE/NONE`, 필수 참조와 검색 상위 2개는 `R7078/H4701`, 성공한 네 기록은 `R7078/NONE`을 출력함. 이 한 관측을 안정적인 효용으로 단정할 수는 없지만, 첫 두 실패만으로 선택 불가능이라고 제외하는 규칙의 반례임.

따라서 수율은 **추가 이득을 찾는 수율**과 **기억의 손해를 피하는 수율**로 나눔. 세 조건 모두 실패한 집단에도 사전에 정한 일부를 무작위로 뽑아 다른 묶음을 점검하고, 선별에서 놓친 비율을 기록함. 쉬운 집단·실패 집단을 모두 보존하며, 선택해 확장한 학습 자료의 점수를 전체 모집단 성능으로 보고하지 않음. 최종 확인 자료에는 모델 출력에 따른 사후 제외를 적용하지 않음.

## 수집 순서와 해석 범위

1. **기존 train에서 소수의 교차 사례를 설계함.** 먼저 수정 전/후 기록과 현재 가용성에 따라 다른 기억이 필요한 조건을 검토함. 다리 기록을 요구하는 조건은 정확한 근거를 줬을 때 작업자가 활용하는지 별도로 확인함. 같은 요청·은행에서 상태만 달라지는 대조가 핵심임.
2. **선별 호출과 제한된 추가 묶음 점검을 수행함.** 작업자·은행·순서·토큰 예산을 고정하고 무기억/필수 근거/검색을 비교함. 필수 근거는 진단용이며 성능 상한으로 부르지 않음. 입력이 같은 조건은 재사용할 수 있지만 독립 호출 수로 중복 계산하지 않음. 유익·유해·전부 성공·전부 실패의 수와 가족 분산을 모두 기록함.
3. **확장 비용과 수율을 함께 판정함.** 한두 가족에만 효과가 몰리거나 필요한 근거 묶음 자체가 예산에 들어가지 않으면 설계를 수정함. 기록 개수만 제한하지 않고 실제 tokenizer로 전달량을 재며, 최소 충분한 묶음은 예산 안에 들어가도록 함. 기존 dev 20·test 40은 설계 탐색에 사용하지 않음.
4. **반복은 평가할 실행 정책에 맞춤.** 현재처럼 greedy가 고정이면 동일 호출 5–8회는 주로 실행 안정성 점검임. 확률적 작업자를 평가한다면 온도·표집 정책을 먼저 고정하고 성공 수와 시행 수를 보존함. 5–8회 성공 비율은 불확실성이 큰 초기 추정이며 정확한 효용 정답으로 취급하지 않음.

40가족은 보장된 필요 규모가 아님. 가족별 **정책 차이**의 표준편차가 0.11이고 양측 5%·검정력 80%를 가정하면 `(1.96+0.84)^2 × 0.11^2 / 0.05^2 ≈ 38`이라는 근사 계산은 가능함. 새 설계에서의 분산·가족 간 독립성·반복 오차·다중 비교를 다시 고려해야 함. 성공률 자체의 표준편차와 정책 차이의 표준편차도 다름. 450호출 약 17분·0.5 CU 역시 이전 짧은 입력/출력을 이용한 추정이며, 새 기억 길이와 출력 형식의 비용을 보장하지 않음.

계산 생성 자료는 관계·필수 전제·근거 충분성 감독을 넓히는 데 적절함. 실제 제공 이득까지 계산으로 만드는 것은 아니며 같은 원형의 변형을 독립 경험으로 세지 않음. 일부 정보 부족 상태는 위험·보류 진단에 유지하되 현재 작업자의 `UNKNOWN` 개선만을 성공 조건으로 삼아 수집을 확대하지 않음.

PersonaMem-v2는 선호 갱신·주체·관련 대화와 정답/오답 보기가 있어 후보가 됨. 다만 **실제 사용자의 자연 발생 로그가 아니라 GPT-5로 생성한 자연어 자료**임. 원 저자의 text train에서 persona 단위로 작은 표본을 검토하고, 질문·보기만으로 푸는 기준선과 근거 제공의 차이를 확인해야 함. 설명용 선호·정답·관련 대화 주석은 선택기 입력으로 유출하지 않음. [공식 데이터 카드](https://huggingface.co/datasets/bowen-upenn/PersonaMem-v2/blob/main/README.md).

LongMemEval-S는 이미 500문항을 평가했고 답할 수 있는 470문항의 근거 확보 252→161 등의 결과를 관측했음. 계속 학습에서 분리할 수는 있지만 ‘아직 보지 않은 봉인 test’라고 부를 수는 없음. 외부 성능 회귀를 점검하는 자료로 유지하고, 새 확인 주장은 별도 미노출 자료에서 해야 함. [기존 외부 평가](2026-11-10-selector-size-and-transfer-validation.md).

작업자 계약 보완의 실패는 새 대규모 효용 수집을 보류할 근거임. 이미 측정한 28개 경쟁 상태에서 선택 목표를 점검하는 저비용 학습까지 막을 근거는 아님. **작은 순위 학습 진단 → 실패 원인 분리 → 선택 여지를 확인한 새 자료 수집**으로 이어가는 것이 처음의 기억 득실 연구와 맞음.
