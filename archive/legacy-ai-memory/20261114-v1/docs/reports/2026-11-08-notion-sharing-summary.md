## 연구 목표

**과거 코드 경험의 이득·손해 요인을 분석함. 작은 별도 모델이 필요한 기억을 골라 실제 성과를 개선할 수 있는지 봄.**

메모리는 과거의 관측·수정 절차·적용 조건을 저장한 외부 텍스트임. Harrier 0.6B가 현재 상황과 기억을 판독하고, Qwen3.5-4B/9B 작업자가 이를 활용해 코드를 작성함.

<callout icon="💡" color="gray_bg">
**기억 제공에 따른 개선·악화를 수치로 관측함. 새 문제에서 학습 선택기가 고정 기억보다 유리한지는 아직 미확인임.**
</callout>

## SWE를 실험 기반으로 선택한 이유

실제 코드 문제 해결 과정에서 메모리의 효과를 행동·성과에 연결하기 위해 SWE를 선택함.

- **실행으로 평가 가능함:** 수정 패치와 테스트로 문제 해결·기존 동작 유지를 확인할 수 있음.
- **득실 비교가 가능함:** 같은 문제·모델·예산에서 기억 유무와 내용을 달리해 성공·악화·토큰·시간 차이를 비교할 수 있음.
- **경험을 분해하기 좋음:** 과거의 탐색·오류·수정·검증 기록을 정보·행동 지침·적용 조건으로 나누어 무엇이 기여했는지 분석할 수 있음.

초기 SWE-bench 파일럿 이후, 효과의 원인을 분리해 보기 위해 API·초기화 과제로 범위를 좁혀 실험함.

## 전체 접근: 경험에서 선택 모델까지

| 단계 | 수행 내용 | 현재 상태 |
| --- | --- | --- |
| 1. 경험 수집 | 실제 개발 로그에서 관측·수정·검증 근거를 추출하고 기억으로 정리 | 실제 로그 기반 자료 확보 |
| 2. 관계 학습 | 현재 문제와 기억의 관련성, 적용 조건, 이미 수행한 작업인지 구분 | 작은 모델로 학습·진단 |
| 3. 득실 측정 | 같은 현재 상태에서 기억 제공·보류를 실행하고 성공·악화·비용 비교 | 제한된 API·Django 과제에서 실행 |
| 4. 선택기 학습 | 관측한 득실로 제공할 기억 또는 보류를 학습 | 일부 개선 신호, 안정적인 우위는 미확인 |
| 5. 확장 검증 | 다른 작업자·실제 개발 이슈에서도 결과가 유지되는지 확인 | 9B 전이·실제 이슈의 관련성 학습까지 완료. 새 자연 이슈의 실제 효용은 후속 과제 |

**측정 기준:** 무기억 실패→기억 제공 성공은 ‘개선’, 반대는 ‘악화’로 집계함. 전체 성공·악화·토큰·시간을 각각 보고 선택기 계산 비용도 고려함. 관련성 분류와 실제 작업 성과는 별도 평가함.

## 실험별 목표·예시·결과

### 1. 초기 SWE 파일럿 — 전달 방식과 기억 내용

- **목표:** 시작 주입·자율 조회 방식과 관찰·수정 절차·적용 조건의 영향을 봄.
- **예시:** 과거 수정 절차를 시작 입력에 넣거나 검색 도구로 조회하게 함. 같은 경험의 관찰과 처방도 분리 제공함.
- **결과:** 첫 자율 조회는 0/2회임. 별도 내용 비교 48회에서 무기억 3/12, 관찰+처방 5/12 성공함. 추가 반복에서 처방의 우위는 재현되지 않음.
- **해석:** 전달·채점 경로의 동작을 확인함. 소수 과제와 조건별 정보량 차이로 일반적인 효과는 미확인임.

### 2. 범위 관계 판독 — 관련성·완료 여부 분리

- **목표:** 작은 모델이 현재 요청과 과거 기록의 서로 다른 관계를 구분하는지 봄.
- **예시:** 요청=검사 A, 완료 기록=검사 B, 기억=검사 A인 경우, 정답은 ‘요청에 관련 있음 / 아직 완료되지 않음’임.
- **방법:** 선형·MLP·LoRA, 따로 읽기/함께 읽기, 대조학습·불변성·학습 충돌 완화를 비교함.
- **결과:** 일부 구조·학습 신호에서 개선을 관측함. seed 변경 시 우위가 재현되지 않음. 문자열 규칙으로도 풀리는 진단이므로 실제 기억 효용은 별도 검증이 필요함.

### 3. API 직접 적용성 — 과거 절차의 재사용 조건

- **목표:** 현재 함수의 반환·원본 변경 조건에 맞는 과거 절차를 고르는지 봄.
- **예시:** ‘복사본에 작업 후 복사본 반환’은 복사본을 직접 변경하는 함수에 적용 가능함. 새 결과를 반환하는 함수에서는 반환값을 버리게 되어 실패할 수 있음.
- **방법:** 실제 라이브러리 7가족의 96상태에 네 절차 후보를 연결하고, 실행으로 적용성을 판정함.
- **결과:** 확인 112쌍에서 일반 LoRA 76개, 반환·변경 속성 병목 모델 87개, 단순 구문 트리 84개 정답임. 직접 적용성 판독 수치이며 작업자의 문제 해결률과 구분함.

### 4. 실제 효용 학습 — 기억 선택에 따른 작업 성과

- **목표:** 실제 성공을 늘리고 악화를 줄이는 기억 선택기를 학습함.
- **예시:** 원본 수정이 필요한 작업에 ‘복사본만 수정’하는 기억을 주면 기존 성공이 실패로 바뀔 수 있음.
- **방법:** 4B에서 96상태×10행동=960개 기본 코드를 생성·실행함. 학습/개발/확인은 50/18/28상태임. 무기억과 단일 기억 8개 중 선택하도록 학습함. 9B에는 4B에서 고정한 선택을 그대로 적용함.

| 정책 | 4B 성공 /28 | 9B 성공 /28 |
| --- | ---: | ---: |
| 무기억 | 15 | 18 |
| 개발에서 고른 고정 기억 | 14 | **21** |
| 전체 기억 제공 | 11 | 17 |
| 사전 주 선택기: 가치 회귀 | 13 | 16 |
| 선호 학습: 두 seed 각각 | **17** | 20 |
| 개발에서 고른 보정층 | 11 | 16 |

**해석:** 4B에서 전체 기억 제공은 개선 2·악화 6, 선호 학습은 개선 2·악화 0임. 선호 학습은 9B에서도 두 상태를 개선하고 기존 성공을 유지함. 개발에서는 선택되지 않았으며 9B 성적도 고정 기억보다 낮음. 주 선택기의 성공·비용 이득은 미확인임. 개발 자료는 고정 기억이 이미 관측 성공 상한에 도달해 상황별 선택의 추가 이득을 검증하기 어려운 구성임.

### 5. 과정 정보 복원 — 요약에서 빠진 실행 전제의 영향

- **목표:** 과거 경험에서 빠진 초기화 정보의 복원 효과를 봄.
- **예시:** Django 설정 후 앱 초기화 전이라면 `django.setup()`이 필요함. 기존 설정을 덮어쓰면 현재 요구를 어길 수 있음.
- **방법:** Django 2버전×4프로세스 상태, 총 8상태에서 기억 내용을 달리해 비교함.
- **결과:** 현재 설정 계약 충족은 무기억 2/8, 수정 절차만 1/8, 초기화 정보만 6/8, 수정 절차+초기화 정보 6/8임.
- **해석:** 정보 보존의 효과를 관측함. 초기화 정보만 고정 제공해도 최고 성공 수와 같아 학습 선택기의 필요성은 미확인임. 초기화 계약 충족 실험이며 SWE 전체 문제 해결률과 구분함.

### 6. 실제 개발 이슈 — 새로운 문제에서의 기억 선택

- **목표:** 실제 이슈 설명과 과거 개발 경험의 관계를 학습함.
- **예시:** ‘직렬화에서 null 필드가 사라짐’ 이슈에 ‘변환 과정의 필드 보존을 확인한 과거 경험’을 연결함. 이슈에 같은 단서가 이미 있으면 관련성이 있어도 추가 이득은 작을 수 있음.
- **방법:** 공개 로그의 기억 16개×현재 이슈 40개=640쌍임. 선형·MLP·LoRA·후보 순위 손실 등을 6방법×2seed로 비교함.
- **결과:** 관련 기억이 있다고 주석한 평가 이슈 4개에서 **학습 모델 12개 모두 첫 선택 0/4**임. 별도 학습 자료 전용 진단에서는 MLP가 432/432쌍을 맞힘. 해당 진단 모델은 새 평가에 사용하지 않음.
- **해석:** 이번 자료·학습 예산에서 선택 일반화에 실패함. 학습 긍정은 18쌍이며 주석은 한 assistant의 판단임. 라벨은 진단 관련성이며 실제 제공 이득은 미측정임.

## 지금까지 배운 점과 다음 단계

- **관련성·직접 적용성·실제 효용은 별도 목표임.** 라벨을 서로 대체하지 않고 분리 평가함.
- **기억 효과는 현재 조건과 작업자에 의존함.** 같은 224개 단일 기억 행동 중 46개는 작업자를 4B에서 9B로 바꾸자 무기억 대비 효과가 달라짐.
- **단순 기준선 대비 우위 검증이 필요함.** 고정 기억·검색·규칙과 비교하고 선택기 비용까지 포함해 별도 모델의 가치를 판단함.

**다음 단계(계획):** 독립 출처·적용/보류 사례 확대 → 주석 독립 검토 → 같은 상태의 제공/보류 결과 수집 → 한 가지 학습 변경을 고정해 새 문제에서 검증함.

현재 결과는 탐색 파일럿임. 상태·후보·반복은 독립 경험으로 합산하지 않음. API·초기화 성적과 자연 SWE 전체 해결률은 구분함.
