# 기본 검색과 학습 선택기의 격차 진단

2026-11-12. [두 외부 벤치 평가](2026-11-12-external-memory-benchmarks.md)의 저장 점수·선택·실제 답변과 학습 자료·손실 코드를 대조함. 새 학습·신경망 추론·작업자 호출·GPU 사용 없이 CPU에서 6,400개 선택 결과를 재계산함. 원래 평가 입력·모델·점수·채점은 변경하지 않음.

현재 확인한 핵심은 **이전 모델은 근거 순위가 약하고, 보완 모델은 순위를 개선했으나 제공 기준에서 필요한 근거를 많이 보류한다는 것**임. 기본 검색과 아직 격차가 있지만 보완이 전부 무효였다는 해석도 맞지 않음. 어느 변화가 encoder의 원래 검색 표현을 손상시켰는지는 이번 저장 결과만으로 분리할 수 없음.

## 기본 Harrier가 높은 이유

높은 점수는 ConvoMem에서 나온 결과임. 기본 Harrier 83/100에 BM25도 80/100임. 같은 문항의 대응 차이는 9개선·6악화이며 설명용 재표집 95% 구간은 −4~+11%p임. Harrier만 특별히 뛰어나다는 증거보다, 이 구성에서는 일반 검색이 상당 부분 해결한다는 증거가 강함. AMA에서는 Harrier 11·BM25 13/100으로 모두 낮음. 두 벤치에서 기본 검색이 모두 높은 것은 아님.

ConvoMem은 지정 범주에서 근거 수가 가장 작은 원래 파일을 고른 통제 부분 집합임. 근거 수 1개 파일에서 82문항, 2개 파일에서 18문항을 선택했고, 원래 근거 대화에 같은 프로필의 배경 대화 2개를 섞음. 후보 은행은 22–50조각으로 모두 공통 상한 64개 안에 들어감. 원문 위치가 확인된 제공 주석 109개도 공통 후보에 모두 있음. 질문에 맞는 사실을 검색하는 데 유리한 조건이며 공식 전체 맥락 길이·난이도 평가가 아님. 모든 정책은 이 같은 은행을 받았음.

Harrier는 대규모 다국어·다과제 자료의 대조 학습과 큰 임베딩 모델의 증류를 거친 모델임. 기본 검색은 공식 사용 방식과 같은 질문 지시문, 마지막 토큰 pooling, 정규화한 질문/문서 벡터의 내적을 사용함. 새로 학습하지 않았다는 이유로 약한 기준선이라고 볼 수 없음. [고정 revision의 공식 모델 카드](https://huggingface.co/microsoft/harrier-oss-v1-0.6b/blob/f9b9dc8d367d443f2479d27aa5d8d2850c0774ee/README.md)

## 같은 Harrier를 쓰지만 판독 방식이 다름

| 항목 | 기본 검색 | 이번 학습 선택기 |
|---|---|---|
| 모델 입력 | 질문과 기록을 따로 인코딩 | 질문·현재 관측·기록을 붙여 인코딩 |
| 점수 | 질문/기록 벡터의 코사인 유사도 | LoRA 표현 위 128차원 GELU 판독층의 필요성 점수 |
| 전달 | 높은 순서부터 예산까지 | 필요성 점수 0.5 이상인 후보를 높은 순서로 전달 |
| 최근 추가 학습 | 없음 | 해당 기억이 지금 필요한지 이진 교차엔트로피 학습 |

최근 partial-record augmented와 balanced-replay는 `need` 교차엔트로피를 사용함. 같은 상태의 후보 순위를 직접 학습하는 별도 항이나 기본 검색 표현·점수를 보존하는 항은 없음. 교차엔트로피도 좋은 순위를 학습할 수 있지만, 현재 코드가 검색 보존이나 순위 향상을 직접 보장하지는 않음. 과거 여행 검색의 대조 학습 LoRA와 이번 모델을 혼동하지 않음.

따라서 이번 결과는 단순한 “같은 검색기에 LoRA만 더한 비교”가 아님. encoder 적응, 입력 방식, 판독층, 보류 정책이 함께 다름. 두 방법의 최종 점수만으로 LoRA가 기본 임베딩을 망가뜨렸다고 결론 내릴 수 없음.

## 보류와 순위를 나눈 재계산

아래는 **답할 수 있는 문항에 달린 원문 위치 확인 주석 93구간의 확보 수**임. 새 답변 정답률이 아니며, 이 주석이 최소 충분 근거나 유일한 정답 표현이라는 보장도 없음. 정보 부재 문항의 주석 16개를 뺀 수치임. 원래 전체 109구간의 결과도 JSON에 유지함.

모든 변형은 같은 점수·후보·1,024토큰·최대 12조각을 사용함. 보류 제거는 점수 임계값만 없애므로 실제 전달량이 증가함. 예산 일치 진단은 문항마다 원래 학습 정책이 사용한 토큰 수를 기본 검색의 상한으로 적용함.

| 정책 | 원래 제공 결과 /93 | 보류 제거 후 /93 | 근거가 확보되는 순위의 중앙값 |
|---|---:|---:|---:|
| BM25 | 77 | 77 | 2 |
| 기본 Harrier | 82 | 82 | 2 |
| 이전 seed 731 | 21 | 21 | 12 |
| 이전 seed 1729 | 26 | 26 | 11 |
| 보완 seed 731 | 25 | 47 | 5 |
| 보완 seed 1729 | 22 | 56 | 4 |

순위는 해당 주석 구간을 전부 덮는 데 필요한 최소 순위 접두 집합의 크기임. 한 주석이 두 조각에 걸치면 둘 다 확보된 시점으로 측정함.

**이전 모델의 주된 문제는 순위임.** 보류 기준을 없애도 21·26으로 같음. 이미 ConvoMem에서 평균 약 981토큰을 보냈으므로 단순히 전달량이 적어서 기본 검색보다 낮았던 것도 아님. 기존 모델이 허용한 후보만 남기고 기본 Harrier 순위로 바꾸면 주석 확보는 77·73으로 늘어남. 원래 문항별 사용 토큰을 상한으로 기본 검색을 실행해도 82·82임.

**보완 모델에는 순위 개선과 과도한 보류가 함께 있음.** 보류 전 순위 중앙값은 12·11→5·4로 개선됐고, 보류 없는 같은 최대 예산의 확보도 21·26→47·56임. 그러나 전체 후보에서 점수 0.5를 통과하는 주석은 29·23개뿐임. 이 후보들 안에서 기본 검색 순서로 바꿔도 29·23개라 초기 보류로 사라진 근거를 복구하지 못함.

**보류만 고쳐도 완전히 해결되지는 않음.** 보완의 47·56은 기본 검색 82보다 낮음. 보완이 원래 사용한 문항별 토큰 상한으로 기본 검색을 실행하면 59·43개를 확보해 원래 보완의 25·22개보다 높음. 평균 전달 토큰도 각각 443·286으로 보완의 449·289 이내임. 적게 보내는 것과 잘 골라 보내는 것은 구분해야 함.

같은 조각 개수 상한을 맞춘 기본 검색 진단에서도 위 확보 수는 동일함. 비교용 무작위 순서 20개는 전체 주석 109개 중 평균 15.3개를 확보함. 이 값은 실제 작업 성공의 무작위 기준선이 아니며 관계 분류 정확도로 사용하지 않음.

## 학습 자료와 평가에서 요구하는 일이 다름

| 항목 | 이전 augmented 학습 | 보완 replay 학습 | ConvoMem 평가 | AMA 평가 |
|---|---:|---:|---:|---:|
| 상태 | 400 | 400 | 100 | 100 |
| 목표 출처 그룹 | 30 | 37 | 100 | 100 |
| 후보 수 중앙값 | 2 | 2 | 34 | 64 |
| 후보 1–2개인 상태 | 343 | 320 | 0 | 0 |
| 기록 텍스트 토큰 중앙값 | 9 | 23 | 196 | 196 |
| 현재 관측이 없는 상태 | 60 | 60 | 100 | 100 |

길이는 같은 작업자 토크나이저로 센 기록 텍스트임. 평가 텍스트에는 짧은 Conversation/Step 표지가 있고 학습 텍스트에는 바깥 프롬프트 접두사를 넣지 않은 수치임. 정확히 같은 렌더링 길이의 비교는 아니지만 길이와 내용 형태의 차이는 큼.

보완의 핵심 320상태는 원래 두 사실의 포함·관측·묶음 구성을 바꾼 대조임. 순서 학습에 직접 도움이 되는 양성/음성 혼합은 핵심에서 80상태이고, 복습 80상태에서 60상태임. 나머지 상태는 전부 필요한 후보 또는 전부 불필요한 후보임. 이런 데이터는 “이미 아는 필드인가, 복합 기록의 일부가 남았는가”를 배우는 데 의미가 있지만, 여러 주제와 화자가 섞인 수십 개 기록 중 답의 위치를 찾아내는 요구와 다름.

학습 균형 정확도는 이전 약 99.7%, 보완 98.6–98.7%이고 AUC도 약 0.999임. 학습이 전혀 실행되지 않았거나 현재 자료조차 맞추지 못한 상황은 아님. 넓은 검색 평가에서 실패한 것은 확인됐지만 평가 과제와 분포도 달라졌으므로, 이를 동일 과제의 단순 과적합 또는 encoder 전체의 망각으로 단정하지 않음.

현재 근거로는 **짧은 기록·명시적 필드·현재 관측 대조에 맞춰진 판독을 자연 문장의 넓은 검색에 그대로 적용한 전이 문제**, 그리고 **새 분포에서 필요성 점수와 0.5 제공 기준이 맞지 않는 문제**가 유력함. 정확한 원인 기여도는 아직 분리되지 않음.

## 실제 사례

[원문과 점수](../../evaluation/results/memory-external-diagnosis-20261112-v1/examples.json)에 모두 보존함. 결과를 본 뒤 고른 설명용 사례이므로 발생 비율 추정에는 쓰지 않음.

Lily의 생일 나이를 묻는 질문에는 원문에 “다섯 살이 된다”는 문장이 있음. 그 조각은 기본 검색 1위, 이전 seed 731의 37위, 보완 seed 731의 14위임. 이전 모델은 행사 설문·호텔 객실 관련 기록을 먼저 보내고, 보완 모델은 모두 보류함. 실제 작업자는 둘 다 답하지 못하고 기본 검색에서는 맞힘. 후보에 답이 없거나 채점만 잘못된 사례가 아님.

Project Falcon의 개발자 투입일과 마감일을 비교하는 질문에서는 기본 검색이 May 1st와 April 15th를 담은 조각을 3위·1위에 놓아 답함. 보완 seed 731은 투입일을 1위에 놓지만 마감일은 41위로 놓고, 대신 regex 설명을 전달함. 필요한 사실 둘 중 하나만 찾는 것이 질문 전체에 충분하지 않은 사례임.

## 구현 점검과 남은 분리

- 현재 평가의 질문·관측·기억 입력 렌더링은 plain 학습 렌더링과 9,399쌍에서 같음. 새로운 배포 템플릿 오류는 확인되지 않음. 시간 표지를 가진 일부 복습은 별도 renderer를 쓰므로 모든 학습 형태와 같다는 뜻은 아님.
- 이전 평가에서 입력 잘림 없음, 실제 판독층과 저장 특징의 전체 점수 일치, 기본 검색과 학습 선택의 공통 후보·예산 일치를 확인함. 이번에는 원래 정책 1,200개를 다시 구성해 일치를 검사함.
- 보류 제거·예산 일치·무작위 순서를 포함한 6,400개 선택 결과의 토큰/조각 상한과 원래 입력 해시를 검산함. 원래 채점의 17/20 표본 일치 및 오류는 그대로이며 이 진단으로 자동 점수의 신뢰도가 올라간 것은 아님.
- AMA에는 공식 조각별 정답이 없으므로 이 근거 순위 진단을 그대로 확장하지 않음. AMA의 낮은 점수를 학습기만의 문제라고 분리할 근거는 부족함.

다음에 encoder의 검색 능력 변화를 확인하려면 **질문과 기록을 각각 인코딩하는 같은 코사인 검색에서 LoRA를 켠 것과 끈 것을 비교**해야 함. 현재 저장한 LoRA 벡터는 질문·기억을 붙인 입력의 벡터라 이 비교를 대신하지 못함. 이는 다음 진단안이며 이번에는 새 encoder 추론을 하지 않음.

학습 보완의 우선순위는 기본 검색의 관련성 신호를 보존하면서 현재 상태의 기확보·조건 불일치 판단을 추가하는 구성을 비교하고, 별도 개발 자료에서 순위와 제공 기준을 따로 검증하는 것임. 같은 짧은 대조의 수만 늘리거나 시험 자료에서 임계값을 고르는 것으로 대체하지 않음. 지금 확인한 순위 개선은 살리되 원래 검색의 장점을 유지하는 방향이 연구 목표에 맞음.

## 재현

[분석 산출물](../../evaluation/results/memory-external-diagnosis-20261112-v1/README.md)과 [CPU 스크립트](../../evaluation/diagnose_external_selection.py)를 제공함. 모델의 추가 학습·추론과 새 답변 채점은 포함하지 않음. 사후 진단의 근거 확보를 새 실제 성공률로 바꾸어 보고하지 않음.
