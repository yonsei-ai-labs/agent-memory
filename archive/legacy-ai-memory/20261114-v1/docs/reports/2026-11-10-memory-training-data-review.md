# 현재 메모리 학습 데이터 리뷰

**현재 자료는 통제된 관계·득실 진단에는 유용하나, 일반적인 메모리 선택을 학습·입증하기에는 내용 다양성과 독립적인 득실 사례가 부족함.** 최신 입력·라벨이 뒤섞였다는 증거는 발견하지 못했음. 반면 기억 내용을 읽지 않는 기준선도 분류 정확도 65.4%를 얻었으므로, 전체 정확도의 상승을 관계 학습의 증거로 쓰기 어려움.

기존 여행 **검색 LoRA**와 최근 **득실 선택 LoRA**는 서로 다른 모델임. 전자는 명시적 참조를 검색하도록, 후자는 고정 작업자의 제공/보류 결과를 예측하도록 학습했음. 두 자료와 외부 평가를 나눠 점검했으며, 과거 코드·범위 실험 전체를 새로 검산했다는 뜻은 아님. 새 신경망 학습·GPU 할당·작업자 호출은 없었음.

집계: [summary.json](data/memory-training-data-review-20261110/summary.json), [입력 해시](data/memory-training-data-review-20261110/source-manifest.json), [기억을 읽지 않는 기준선의 408개 예측](data/memory-training-data-review-20261110/structure-baseline-predictions.jsonl), [사례 원문과 저장 출력](data/memory-training-data-review-20261110/case-review.jsonl). 사례는 설명을 위해 사후 선택했으며 독립·맹검 주석 표본이 아님.

득실 자료의 504배정은 480개 고유 작업자 입력에 연결됨. 무기억 96배정도 고유 입력은 72개임. `needed`와 `missing`처럼 은행 상태는 다르지만 무기억 작업자에게 보이는 입력이 같은 경우가 있기 때문임. 408행이나 여러 초기값의 결과를 독립 경험 수로 합산하면 안 됨.

## 유지할 만한 부분

- 검색 자료의 고정 파일 7개와 득실 자료 13개 해시를 대조함. 실제 학습 ZIP에 들어간 입력·정답·분할 등 5파일도 현재 자료와 바이트 단위로 일치함.
- 현재 사용하는 **목표+관측+기억** 입력은 408개 모두 서로 다르며, 동일한 전체 입력에 다른 라벨이 붙은 사례는 없음. 가족 분할도 겹치지 않음.
- 저장된 작업자 출력으로 504배정·408학습 라벨을 다시 구성했고, 96상태의 SQL 기반 해답과 대조한 검산이 통과함. 실제 GPU 순전파를 다시 한 것은 아님.
- 대조 57상태는 19요청의 38개 기록 쌍에서 나옴. 사람 또는 날짜 **하나만** 바꾸고 기록의 항목은 유지했으며, 비교 상대는 실제 과거 기록임. 관계 비트를 실제 득실 정답으로 대체하지 않았음.
- 기존 후보와 새 후보를 같은 작업자 환경에서 모두 재측정했음. 관측하지 않은 행동을 임의의 실패 정답으로 채우지 않았음.

위 검사는 저장·연결·채점의 정합성에 대한 근거임. 모든 자연어 주석이 독립 검토됐거나 데이터가 실제 사용 분포를 대표한다는 보장은 아님.

## 가장 중요한 약점: 관계를 읽지 않아도 분류 점수가 높음

현재 24요청은 사람·날짜를 치환하면 **두 가지 문장 틀**임.

1. 과거 사람의 특정 날짜와 **같은 식당/숙소 선택**: 12요청.
2. 과거 가격을 기준으로 **더 저렴한 식당/특정 가격 이하 숙소 선택**: 12요청.

관측은 과거 선택 표시 유무와 카탈로그 이용 가능 여부를 통제한 정적 상태임. 실제로 연속 작업을 수행하며 생긴 진행·실패·복구 이력은 포함하지 않음. 기억도 같은 `Recorded plan for ... Day ...` 형식임. 식별자에 사람 인덱스·날짜·항목이 들어가고 실제 모델 입력에 포함되지만, 식별자 교체나 표현 변경에 견디는지는 아직 평가하지 않았음.

이번에 다음 세 신호만 사용하는 빈도 기준선을 계산함. **제안 기억의 본문·ID·정답·사후 출력은 읽지 않음.**

- 요청이 같은 장소 재사용 문장인가?
- 현재 관측에 과거 선택이 이미 표시돼 있는가?
- 현재 카탈로그의 이용 불가 행은 몇 개인가?

기존과 동일한 3개 가족 분할에서 학습 가족의 최빈 클래스를 정하고, 해당 fold의 남겨둔 가족에 적용함. 동점이면 작은 class ID, 학습에서 없던 신호 조합이면 학습 전체 최빈값을 사용함. 평가 라벨로 빈도나 동점을 정하지 않았음. 다만 이번 리뷰에서 정한 **사후 진단**이며 새 방법의 확증 결과가 아님.

| 분류 진단 | 정답 / 408 | 개선 recall | 악화 recall |
| --- | ---: | ---: | ---: |
| 항상 ‘둘 다 실패’ | 172 (42.2%) | 0/74 | 0/23 |
| 현재 상태의 세 구조 신호만 사용 | **267 (65.4%)** | **0/74** | **0/23** |
| 최근 보강 학습의 최고 전체 분류 결과 | 258 (63.2%) | 아래 원 보고서 참조 | 0/23 |

신호 기준선은 ‘둘 다 실패/둘 다 성공’만 예측함. balanced accuracy는 42.9%이며, 기억을 잘 선택하는 정책이 아님. 이 결과가 학습 모델도 같은 편법을 썼다는 증거는 아님. 다만 [최근 학습](2026-11-10-memory-refreshed-learning.md)의 전체 분류 점수만으로 기억 간 관계 판독의 개선을 주장할 수 없음을 보여줌. 같은 상태에서 비슷한 후보의 순서를 맞히는지, 개선·악화를 찾아내는지와 실제 선택 결과가 필요함.

현재 관측의 필요성을 보여주는 양성 근거도 있음. 관측을 지운 `goal` 보기(목표+기억)에서는 174개 고유 입력 중 96개 입력에 서로 다른 관측 라벨이 붙음. 이 관측 표본을 동일 입력별 최빈값으로 외워도 291/408까지만 맞힐 수 있음. 이는 의도한 정보 제거 진단의 한계이며, 현재 전체 입력의 라벨 오류는 아님.

## 득실 신호의 양과 의미

| 라벨 | 묶음 수 | 해당 상태 수 | 해당 가족 수 |
| --- | ---: | ---: | ---: |
| 둘 다 실패 | 172 | 58 | 12 |
| 개선 | 74 | 25 | 12 |
| 악화 | 23 | 9 | 6 |
| 둘 다 성공 | 139 | 32 | 12 |

상태·가족은 클래스 사이에서 중복됨. 중립 두 범주가 311/408, 약 76.2%임. 무기억을 포함해도 모든 후보가 실패하는 상태 38개, 모두 성공하는 상태 24개이며, 실제 선택에 따라 성공이 달라지는 상태는 34개임. 무기억을 제외한 후보끼리 성공이 갈리는 상태는 [기존 검산](2026-11-10-memory-worker-refresh.md)의 28개임.

악화 23묶음 중 **무기억도 근거를 준수하며 성공한 답을 망친 것은 7묶음·2상태·2가족**임. 나머지 16묶음은 무기억이 근거 없이 정답과 일치하던 상태에서 실패로 바뀐 것임. 둘 다 정답률 기준의 악화지만, 신뢰할 수 있는 행동을 망친 것과 구분해야 함. 전체 504배정에서도 정답 일치와 입력 근거 준수가 다른 성공이 47개 있음.

fold 0의 남겨둔 가족에는 악화가 **0개**, 다른 두 fold에는 13개·10개가 있음. 이 분할을 사후 재배치해 기존 점수를 고칠 필요는 없으나, 다음 수집에서는 악화가 여러 독립 가족에 분산되도록 설계해야 함.

두 필수 참조 ID를 모두 제공한 177묶음도 개선 57·둘 다 성공 78·둘 다 실패 33·악화 9개로 나뉨. **참조를 맞게 고르는 것과 그 기억이 실제 성공을 높이는 것은 같은 정답이 아님.** 여기서 참조 ID 확보는 현재 관측이나 같은 값을 가진 대체 기록의 의미적 충분성까지 평가한 지표도 아님.

대표 사례는 다음과 같음.

- `0f5fff20dbab0a91--case-0--needed`: Emma의 2일차 숙소가 필요한데 6일차 숙소를 선택해 실패함. 같은 기억 수와 비슷한 길이에서 날짜 관계가 바뀐 진단 사례임. 관계 학습으로 해결할 가치가 있는 문제임.
- `015f64adf40542a3--case-1--needed`: 두 참조를 모두 맞게 제공했지만, 작업자가 ‘과거 식당보다 5 이상 저렴하게’라는 요구에 과거 식당 자체를 반환해 실패함. 선택의 관련성 오류로 잘못 라벨링하면 안 됨. 무기억의 성공도 필요한 과거 가격을 관측하지 않은 정답 일치였음.
- `0245d6cdd36d5364--case-1--visible`: 필요한 과거 가격이 현재 관측에 이미 있음. 무기억은 숙소 `NONE`으로 올바르게 답했지만, 관련 기록과 중복 기록을 추가했을 때 `H3934`로 바뀌어 실패함. 거짓 기억만이 손해를 만드는 것은 아님.
- `015f64adf40542a3--case-0--changed`: 정확/근접 기록의 네 조합이 모두 작업 정답과 일치하지만, 정확한 두 참조 조합만 입력 근거 계약을 준수함. 관계 비트를 그대로 득실 라벨로 바꾸면 이 차이를 잃음.

이 효과는 한 고정 작업자·프롬프트·greedy 출력에서 관측한 결과임. 4개 입력의 반복 일치는 실행 안정성 점검이며, 모든 행동의 평균 성공 확률이나 보편적인 기억의 유해성을 추정하지는 못함.

## 검색 자료·출처·평가의 제한

검색 자료 47,573개 기억 ID의 고유 본문은 43,759개임. 기본 계획과 전체 질문은 분할 간 겹치지 않지만, train/dev에는 같은 기록 본문 81개가 있고 dev 1질문의 정답에 해당함. test와 train/dev 사이의 동일 기억 본문은 0개임. 부분 기록의 재등장은 기본 계획 단위 분할의 한계이며, 전체 질문/정답이 test로 직접 누출됐다는 결과는 아님.

검색 정답은 명시적인 사람·날짜·항목 규칙으로 만들어짐. 원문 참조 4,805건의 위치·연결은 검산했지만 이는 의미 주석의 독립 검증이 아님. 기존 내용 검토는 주 에이전트가 본 18질문·75참조이고, 독립 이중 주석은 없음. 규칙이 처리할 수 없는 관계는 수집 단계에서 제외돼 있어 자연스러운 모호성·간접 참조·오래된 지식의 적용성을 대표하지 못함. 같은 test 8계획을 여러 실험에서 이미 살펴봤으므로 새 확인 집합으로 부를 수 없음.

현재 과거 기록 540개는 모두 유효한 카탈로그 ID이지만, 당시 제약을 충족한 것은 409개, 최저가·동점 규칙까지 충족한 것은 252개임. **기록된 행동은 사실이어도 성공한 해결책은 아닐 수 있음.** 실패 기록을 전부 버리기보다 기록의 사실성·당시 성공 여부·현재 적용성을 각각 보존하는 것이 적절함.

120가족 설계의 train/test에는 도시 6개가 공유됨. 경로·기간이 다르다고 모든 환경·개체가 새로운 것은 아님. 새 가족 전이와 새 도시/도메인 전이는 구분해서 분할해야 함.

외부 LongMemEval 평가는 주석 발화 전체를 포함하는 후보가 286/470문항에만 있음. 후보 8개 중 최적의 4개를 골라도 이 지표는 286개를 넘을 수 없음. 나머지를 모두 선택 모델의 실패로 돌릴 수 없고, 주석 발화 전체가 없다는 이유만으로 실제 답변 불가능이라고 할 수도 없음. 원본 시각 불일치 76문항(미래 날짜는 0)도 기존 분리 집계대로 유지함. 이미 결과를 분석한 500문항은 향후 학습·방법 선택에 참고하면 개발 진단으로 관리하고, 별도 확인 자료가 필요함.

실제 전달 길이는 49–254토큰으로 512토큰 상한보다 작음. 같은 상한을 지킨 비교는 맞지만, 큰 은행에서 예산이 빠듯할 때 어떤 기억을 남길지에 대한 증거는 아직 약함. 작업자의 토큰·시간은 측정됐으나 현재 득실 라벨/학습 목표는 정답 일치 중심이고 비용 가중치는 0임.

## 다음 자료를 만들기 전에 보완할 순서

1. **현재 버전을 진단 자료로 고정하고 정답 축을 유지함.** 관련 참조·현재 적용성·이미 관측한 정보·묶음 충분성과 실제 성공/근거 준수/비용을 별도 필드로 둠. 기존 관측 득실을 관계 규칙의 정답으로 덮어쓰지 않음.
2. **같은 형식 안에서 판단이 달라지는 독립 사례를 수집함.** 현재 두 요청 틀의 단순 바꿔쓰기를 행 수 확대의 중심으로 삼지 않음. 같은 관계가 여러 원본 경험에서 반복되도록 하며, 현재 정보와 중복되는 기억·잘못된 대상/시점·현재 전제와 충돌하는 기억·둘을 모아야 충분한 기억을 확보함. 선택에 따라 성과가 달라지지 않은 사례도 보존해 수집 편향을 기록함.
3. **표현 변경과 관계 변경을 다른 시험으로 둠.** 의미를 유지한 이름/ID/문장/순서 변경에서는 판단 유지, 사람·날짜·필수 전제 변경에서는 필요한 판단 전환을 확인함. 이때 작업자에게 보이는 문장이 달라졌다면 기존 실제 득실 라벨을 자동 복사하지 않고 재측정하거나 관계 진단으로만 사용함.
4. **새 자료의 검토·분할을 학습 전에 확정함.** 원본 경험 및 그 모든 변형을 같은 그룹으로 묶고, 가족 수·요청 틀·공유 개체·악화 지원 수를 함께 공개함. 원문 근거를 가진 관계 주석은 별도 검토자가 독립 검토하고 불일치를 남김. 새 가족 전이와 새 도메인 전이는 별도로 평가함.
5. **관계 점수와 실제 선택 성과를 함께 보고함.** 같은 상태의 후보 순위·개선/악화 recall·묶음 충분성·보류를 먼저 확인하고, 고정 작업자·동일 후보 은행·동일 예산에서 성공/근거 준수/비용으로 연결함. 전체 정확도가 쉬운 중립 사례 때문에 올라가는지는 이번 구조 신호 기준선으로도 점검함.

발견한 생성 코드 보완점도 있음. [대조 후보 생성기](../../data_pipeline/prepare_memory_contrasts.py)의 가격 동일성 제외 조건은 `mode == 'price'`를 검사하지만 실제 요청의 mode는 `comparison`임. 동일 가격·다른 장소인 작은 가상 입력으로 이 조건이 작동하지 않음을 재현함. **현재 보존된 가격 비교 대조에는 동일 가격 쌍이 0개여서 이번 데이터의 실제 영향은 확인되지 않았음.** 다음 버전 생성 전에 조건과 사후 검증을 보완해야 함. 이번에는 고정 해시 자료·생성 코드를 덮어쓰지 않았음.

데이터 형식 편중과 외부 전이 저하는 과적합 우려를 뒷받침하지만, 원인을 확정하지는 못함. 최신 득실 모델은 학습 자료의 악화도 충분히 맞히지 못했으므로 학습 부족·표현·목표의 문제도 남아 있음. 지금의 우선순위는 모델을 버리거나 같은 자료로 학습량만 늘리는 것이 아니라, **독립적인 관계 대조와 의미가 분명한 득실 감독을 보강하는 것**임.

## 재현

검토 스크립트와 단위 검사는 Python 표준 라이브러리만 사용함. 검색의 큰 JSONL은 Git 밖에 있으므로, 새 clone에서는 먼저 고정 공개 자료를 재구성함. 첫 명령은 다운로드가 필요할 수 있으며 모델 실행은 하지 않음. 로컬 원본이 있다면 재구성 명령에 `--source <원본>`을 지정할 수 있음.

```bash
python3 -m data_pipeline.reproduce_travel_retrieval \
  --output /tmp/memory-review-retrieval
python3 -m evaluation.review_memory_training_data \
  --retrieval-dir /tmp/memory-review-retrieval \
  --output /tmp/memory-training-data-review
python3 -m unittest evaluation.tests.test_memory_training_data_review -v
```

출력의 `summary.json`, `source-manifest.json`, `structure-baseline-predictions.jsonl`, `case-review.jsonl`을 이 노트의 공유 파일과 비교할 수 있음. 기존 원시 작업자 출력/토큰/SQL까지 재검산하려면 [worker 검산 안내](../../evaluation/results/memory-worker-refresh-20261110-v1/README.md)를 따름. 이번 검토의 명령·결과는 [verification.json](data/memory-training-data-review-20261110/verification.json)에 보존함.
