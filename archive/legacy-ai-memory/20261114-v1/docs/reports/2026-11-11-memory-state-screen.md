# 현재 상태에 따라 필요한 기억이 바뀌는 수집 파일럿

**2026-11-11 실행 완료.** 기억이 필요한 24상태에서 무기억 0·목표 판독기 6·목표 규칙 12·필수 근거 24 성공을 관측함. 이미 정보가 있는 12상태에서는 불필요한 기억으로 성공 4건이 깨졌음. 수집 설계 점검을 통과했으나 현재 상태 규칙도 풀 수 있어 신경망 선택기의 필요성은 입증하지 못함. 아래 실행 전 계획과 결과를 구분함. 실제 측정은 표시 형식을 보완한 v2 자료를 사용함.

목표는 같은 요청·기억 저장소라도 이미 확인한 사실이나 실패 이력에 따라 필요한 기억이 달라지고, 그 선택이 고정 작업자의 결과를 바꿀 수 있는지 확인하는 것임. 데이터 관계 정답과 실제 성공·손해는 별도로 보존함.

## 자료와 비교

기존 여행 pilot의 **이미 사용한 train 6가족**을 결과와 무관한 해시로 선택함. 실제 모델이 생성한 과거 선택 기록을 그대로 사용함. 현재 요청·관측·실패 상태는 통제해서 만든 개입이며 자연 발생한 새 에이전트 경험으로 부르지 않음. dev 20·test 40은 사용하지 않음.

실행 전 카탈로그 점검에서 `Sonder | 180 Water | Pleasant 2BR + Rooftop`의 이름 안 구분자가 열 구분자와 겹치는 문제를 찾음. v1 초안은 보존하고 v2에서는 이름·속성 안의 문자만 `\|`로 표시함. 이름 원문·가격·정답·상태·은행·목표·분할은 동일함. 선택기 입력 36상태와 관계 주석의 동일성을 검증해 기존 CPU 판독 점수를 재사용하고, 작업자 메시지만 다시 구성함. v1의 작업자 호출은 0임.

| 대조 | 같은 쌍에서 바뀌는 것 | 전달 제한 |
| --- | --- | --- |
| 이미 확인한 항목 | 저녁 기록을 현재 알고 있음 ↔ 숙소 기록을 현재 알고 있음 | 기록 1개·128토큰 이하 |
| 첫 시도 실패 | 첫 계획을 아직 시도하지 않음 ↔ 첫 계획 결제 실패로 대안 계획 필요 | 기록 2개·256토큰 이하 |

쌍 안의 목표·기억 은행·현재 카탈로그는 동일함. 첫 시도 실패는 특정 과거 장소 ID를 공개하지 않는 합성 상태이며, 카탈로그의 가용성 변화로 답을 새어 주지 않음. 원래 기록과 다른 현재 카탈로그도 통제 개입임. 두 사람의 실제 저녁·숙소 선택이 각각 다른 조합만 사용해 대안이 실제로 달라지는지 확인함.

각 대조에 필요한 정보가 현재 모두 보이는 상태도 추가함. 총 24개 대조 상태 + 12개 쉬운 상태 = 36상태임. 쉬운 상태는 손해·비용 점검용으로 유지함. 필요한 기록은 제한 안에 들어가며, 은행 전체는 전달하지 않음. 개수 제한과 토큰 상한을 함께 사용한 작은 진단이라는 점을 명시함.

각 상태에서 무기억 / 필수 근거 / 목표만 읽는 기존 판독기 / 다른 상태용 또는 불필요한 기억을 비교함. 144개 정책 결정은 동일 메시지를 합치면 **120개 작업자 호출**임. 고정 greedy 출력 안정성 확인 2회를 추가함. 근거가 충분한 상태의 성공, 근거가 부족한데 우연히 맞힌 답, 형식 오류, 비용을 분리함. `UNKNOWN`을 잘 출력해야만 실험 전체가 성립하도록 설계하지 않음.

기존 판독기는 고정 Harrier 0.6B LoRA와 이진 head를 사용함. 현재 상태를 넣지 않고 목표–기록 576쌍을 CPU FP32로 계산함. 은행 전체를 판독하며, 과거 GPU hybrid 검색 파이프라인의 완전한 재현으로 부르지 않음. 대조 24상태의 필수 근거 확보는 6/24였음. 이것은 작업 성공 측정이 아님.

약한 판독기와의 비교만 남기지 않기 위해 **목표의 첫 참조를 고정해서 고르는 규칙**도 대조 24상태에서 비교함. 해당 행동 모두가 이미 위 120개 메시지에 포함돼 있어 새 호출을 만들지 않음. 현재 상태를 읽는 단순 규칙은 별도로 구현했으며, 필수 근거 주석과 36상태 모두 일치함. 따라서 좋은 결과가 나와도 이 자료에서 신경망 선택기가 꼭 필요하다는 증거는 아님.

## 판정과 경계

선별 표는 무기억·필수 근거·목표 판독기의 관측 성공을 모두 보존함. 세 조건이 모두 실패한 상태에서도 다른 기억을 제공한 결과를 확인하고, 쉬운 상태에서의 손해도 보고함. 결과가 잘 나온 사례만 남기거나 실패 사례의 관계 정답을 바꾸지 않음.

사전 수율 기준은 대조 24상태 중 `무기억 실패 / 필수 근거 성공 / 목표 판독기 실패`가 4상태·3가족 이상이고 필수 근거 성공이 20/24 이상인 것임. 목표만 보는 규칙까지 실패한 교집합을 추가로 보고함. 작은 설계 점검의 공학적 기준이며 표본 수 충분성·통계적 유의성 기준이 아님. 통과하더라도 다음 수집 여부의 근거로만 사용함.

작업자는 기존 Qwen3.5-9B revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a`·BF16·SDPA·greedy·64출력 토큰으로 고정함. 기존 기본 시스템 문장을 유지함. 정답·관계 주석·정책명은 Colab 입력에서 제외하고 메시지만 전달함. 전용 L4의 작업자 실행 1,800초·controller 2,400초 상한을 두고, 결과 회수 후 해당 세션을 종료함. 기존 계약 실험의 실행 코드는 보존하고, 공통화한 복사본을 새 실행 ID에서 사용함.

## 이득과 손해를 연결한 사례

`558439bbd8869b27ae617bd9`는 Henry의 4일차 기록으로 시작하되 첫 시도 실패 시 Clara의 5일차 기록을 쓰라는 동일 목표의 실패 상태임. 현재 상태를 읽는 선택은 Clara의 저녁·숙소 기록을 전달해 `R2552/H2155`로 성공함. 목표 규칙은 Henry의 기록을 전달해 `R9348/H722`로 실패함. 기존 판독기는 Clara·Henry의 숙소 두 개를 고르면서 필요한 저녁 기록을 놓쳤음. 이 사례는 현재 실패 상태와 부족한 항목을 함께 고려할 필요를 보여 줌.

정보가 이미 충분한 12상태에서는 다음 손해가 있었음.

| 정책 | 작업 성공 | 근거가 있던 무기억 성공을 망친 수 |
| --- | --- | --- |
| 무기억 / 필수 근거 정책의 보류 | 12/12 | 0 |
| 목표 판독기 | 10/12 | 2 |
| 불필요한 반대 상태용 기억 | 8/12 | 4 |

손해 2건·4건은 모두 첫 시도 실패 조건의 이미 알고 있는 상태에서 발생함. 이미 확인한 항목 대조의 쉬운 상태에서는 손해가 없었음. 모든 상황에서 같은 손해율이 나타난다고 일반화하지 않음.

예를 들어 `5e2d9f803f6e68cf8f61df8b`는 실패 후 사용할 Lena의 저녁·숙소가 현재 관측에 모두 있음. 무기억은 `R1896/H1305`로 성공함. 처음 계획인 Iris의 두 기록을 다시 넣으면 `R3909/H4936`으로 바뀌어 실패함. 이는 근거 없는 무기억 추측을 우연히 맞힌 경우가 아니라, 현재 정답 근거가 이미 있었던 성공의 회귀임.

## 해석과 다음 경계

이번 수집 틀에서는 작업자가 필수 근거를 활용할 수 있고, 같은 목표라도 현재 관측·실패 상태에 맞지 않는 기억을 고르면 실패하며, 이미 충분한 상태에서는 불필요한 기억이 해를 줄 수 있음을 함께 관측함. 원래의 ‘기억의 득과 실’ 질문과 연결되는 긍정적인 설계 점검임.

다만 **새 상태 선택기를 학습한 결과가 아님.** 직전 [이진·순위 학습](2026-11-10-memory-direct-ranking.md)은 이전 408후보의 별도 실험임. 여기서는 기존 목표 판독기와 규칙·필수 근거의 결과를 측정함. 새 선택기의 개선으로 두 결과를 합치지 않음.

현재 규칙은 명시적인 상태 표지와 요청의 사람·날짜·항목을 읽으면 정답 근거를 고름. 신경망의 필요성, 자연 발생한 실패 이력의 이해, 새로운 출처의 일반화를 평가하기에는 자료가 쉬우며 두 가지 좁은 틀뿐임. 기존 train 6가족의 통제 개입이므로 이 24상태를 새 독립 경험 24개로 세지 않음. MemoryArena 공식 전체 에이전트 점수도 아님.

다음은 이 틀의 관계·근거·실제 결과 필드를 유지하면서 **아직 사용하지 않은 train 출처의 소수 사례를 먼저 검토**하는 단계가 적절함. 자연스러운 진행·실패 기록에서 목표만으로 풀리는지, 공개 상태 규칙으로 충분한지, 기억을 받으면 작업자가 풀 수 있는지를 구분해 확인함. 필요한 기억이 달라지는 사례뿐 아니라 쉬운 성공과 해로운 추가 기억도 유지함. 같은 문장을 대량 변형하거나 이번 6개 성공 교집합만 늘려 학습하지 않음. dev 20·test 40은 계속 사용하지 않았으며 이번 결과로 봉인을 해제하지 않음.

남은 여행 명세만으로 실제 실패 이력이 확보되는 것은 아님. 원문에 없는 이력은 새로 수집하거나 통제 개입으로 구분해야 함. 아직 그 자연 발생 자료를 확보했다는 뜻은 아님.

## 완료·자원·공유 검산

자료·메시지 동결은 `2f79034`, 근거가 있는 손해와 근거 없는 행동을 나누는 보조 평가 동결은 `782529f`에서 작업자 실행 전에 완료함. 원본 기록 동등성 1,764건·현재 정답 항목의 실행 가능성 72건을 사전 확인함. v1의 구분자 표시 문제를 고친 뒤 v2만 작업자에 실행했음.

전용 L4 `memory-state-screen-20261110T182905Z`에서 controller 406.0초·작업자 347.7초를 사용함. 계정 잔액은 556.56→556.43 CU로 관측 차이 0.13 CU임. 직접 계측한 청구액이나 화폐 비용으로 해석하지 않음. 결과 회수·세션 종료 후 사용률 0.00/hr·활성 할당 0을 재확인함. 기존 판독 점수 준비는 앞서 CPU 394.2초를 사용했으며 새 선택기 학습은 없음.
