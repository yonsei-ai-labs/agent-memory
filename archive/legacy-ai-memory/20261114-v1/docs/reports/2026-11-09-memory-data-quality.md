## 3. 데이터 확대 전에 보완할 구체적 약점

**불균형과 쉬운 규칙이 높은 점수를 만들 수 있음.** 개발 단서 train의 양성은 18/432쌍이며 기억 10개에 분산됨. test는 항상 다른 원리라고 답해도 85/96=88.5%임. 여행 6후보는 모든 6,381요청에 정답이 정확히 하나씩 있어, 후보 단위로 항상 비참조라 해도 83.3%임. 자연스럽게 필요한 기억이 없는 요청은 이 자료에 없음.

범위 과제는 파싱한 범위의 문자 길이만 비교해도 dev 594/594·첫 external 108/108임. 후속 동일 길이 진단에서는 이 규칙이 48/108로 낮아지지만, 정확한 범위 비교라는 제한된 과제는 유지됨. 높은 점수만으로 일반적인 적용성이나 별도 학습 모델의 필요성을 주장하지 않음.

**최신 실제 효용 자료는 질문 구조도 좁음.** 24질문 전부 필요한 참조가 2개이고, 이름·날짜를 마스킹하면 질문 틀은 재사용/가격 비교 두 종류임. 저녁과 숙소는 각각 하나의 과거 참조를 이용하는 별도 출력임. 따라서 한 답을 위해 서로 다른 두 기억을 결합해야 하는 문제와는 구분해야 함. 전체 질문 검색 자료에는 1–12참조가 있으므로 프로젝트 전체가 항상 2개인 것은 아님.

**과거 가격의 변화는 시험하지 않았음.** 과거 기록 540/540의 가격·평점이 현재 카탈로그와 같으며, 비교 질문의 24참조 가격도 참조 ID와 현재 카탈로그를 알면 복원 가능함. 사람·날짜→선택 ID는 여전히 과거 기억이 필요하므로 전체 정답 누출이라는 뜻은 아님. 다만 과거/현재 속성이 달라지는 갱신·오래된 수치의 위험을 학습했다고 볼 수 없음. 기존 `changed`는 주로 가용성 변경임.

**실제 악화의 다양성이 부족함.** 최신 96상태는 개선 23·악화 5·둘 다 성공 28·둘 다 실패 40임. 성공 증감으로는 68/96=70.8%가 중립이며, 악화는 4가족에만 존재함. 같은 다섯 사례의 표현만 늘려서는 손해 조건의 다양성이 충분해지지 않음. 성공 여부와 별도로 근거 없는 선택·적절한 보류·토큰·시간을 보존할 필요가 있음.

API에는 실제 득실 결과가 더 있으나 같은 좁은 API 상태를 재사용함. 모든 비무기억 행동과 무기억의 비교에서 4B는 개선 47·악화 154·양쪽 성공 242·양쪽 실패 421이고, 9B 확인 28상태에서는 각각 15·41·121·75임. 이 비교 쌍들은 같은 상태·무기억 결과를 공유하므로 독립 표본이 아님. 4B의 dev18에서는 최선의 고정 행동과 관측 행동별 최대치가 모두 11/18이어서, 그 개발 자료에서는 상황별 선택의 추가 이득을 구별하기 어려움. 확인 자료의 최선 고정 행동은 사후 진단값이며 배포 정책 선택에 사용하지 않음.

## 5. 4B·9B는 선택기 비교에 먼저 투입함

최근 4B/9B 비교는 기억을 전달받은 **작업자의 활용 능력**을 진단하기 위한 것이었음. 원래 질문인 “작은 학습 모델이 어떤 기억을 선택해야 하는가”의 주 비교를 대신하지 못함. 작업자 오류 진단의 비중을 줄이고 아래 비교를 주축으로 삼는 것이 적절함.

| 구성 | 역할 | 확인할 질문 |
| --- | --- | --- |
| Harrier 0.6B, 추가 학습 전 | 기억 선택 기준선 | 사전학습 표현만으로 얼마나 고를 수 있는가 |
| 같은 0.6B + LoRA | 학습한 기억 선택기 | 관계 학습이 같은 입력에서 선택을 개선하는가 |
| Qwen3.5-4B, 고정 | 기억 선택기 | 더 큰 생성 모델의 직접 판단과 비교하면 어떤가 |
| Qwen3.5-9B, 고정 | 기억 선택기 | 선택 품질과 비용의 기준점이 얼마나 달라지는가 |
| 작업자 하나, 고정 | 모든 선택 결과를 받아 동일 과제 수행 | 선택 차이가 실제 성공·악화·비용으로 이어지는가 |

0.6B+학습 판독층과 LoRA의 기여도 따로 구분함. 큰 고정 모델과 추가 학습한 작은 모델의 비교는 실용적인 시스템 비교이며, 순수 모델 크기 효과는 아님. 크기의 효과를 주장하려면 같은 감독·학습 조건의 별도 비교가 필요함.

공통 평가 계약은 다음과 같음.

1. 같은 현재 질문·판단 시점의 관측·후보 기억을 제공함. 미래 작업자 출력·정답 ID·효용 라벨은 입력에서 제외함. 후보 순서도 동일하게 맞추고 순서 변경 민감도를 별도로 확인함.
2. 우선 공통 후보 풀에서 재선택을 비교함. 후보 풀이 필요한 기억을 놓쳤는지 따로 측정하고, 이후 전체 검색 경로의 비용·정확도를 별도 평가함.
3. 전달 토큰 예산을 맞추고 선택 기억 ID 또는 빈 집합으로 출력하게 함. 모든 자료를 top2로 고정하지 않음. 필요한 기억 수가 다른 질문과 보류를 포함함. 출력 파싱 실패도 그대로 기록함.
4. 검색·규칙 기준선과 함께 필요한 근거 재현율·선택 정밀도·근거 완전 확보율·오제공·보류를 비교함. 두 기억을 합쳐야 충분한 문제에는 집합 단위 정답도 둠.
5. 선택 결과를 같은 작업자에게 전달하여 무기억 대비 개선/악화와 비용을 비교함. 선택기 추론 비용을 포함하고, 기억 벡터의 최초 생성 비용과 재사용 시 비용을 구분함. 전체 기억 제공은 예산이 다른 진단 기준선으로 명시함.
6. 프롬프트·문턱·전달 예산은 개발 자료에서 결정함. 현재 45계획·train12는 발견/회귀 평가로 사용하고, 새로운 출처의 확인 평가는 방법을 고정한 뒤 수행함.

이미 [자연 관계의 9B 직접 판독](../../training/memory_selector/reports/2026-11-07-natural-relations-model-comparison.md)은 있었으나, 현재 여행 선택 과제에서 세 모델 크기와 LoRA를 동일 계약으로 비교한 결과는 아님. 과거 단일 토큰 판독 성적을 새 생성형 선택 성적과 직접 비교하지 않음.

## 6. 다음 데이터 보강 순서

1. **현재 자료로 공통 선택기 평가를 구성함.** 선택기 자체의 차이를 먼저 확인하고, 별도 작업자는 고정함. 새로운 대규모 학습 전에 수행 가능한 진단임.
2. **독립 원천과 판단 유형을 함께 늘림.** 남은 train 원천 수집 시 1개/2개/3개 이상 필요 근거, 부분 누락, 중복, 시점 갱신, 같은 주제의 다른 주체·조건, A만/B만으로 부족하고 A+B가 충분한 경우를 확보함. 기존 120가족 명세와 다른 설계는 새 버전으로 보존함.
3. **관계·충분성·실제 결과를 따로 주석함.** 먼저 현재 관측으로 판단 가능한 범위와 근거 위치를 검토하고, 정해진 제공/보류 행동으로 실제 결과를 측정함. 긍정·어려운 부정·미확인 경계는 다른 검토자의 재판정을 우선함.
4. **수집 결과를 보고 좋은 사례만 남기지 않음.** 효과를 보기 전에 포함 규칙·부모 출처 분할을 정함. 실패·중립·악화 모두 보존하고, 분포를 조절한 학습 자료와 발생 비율을 보존한 평가 자료를 구분함.

현재 자료는 기능 점검과 선택기 비교를 시작하기에는 쓸 수 있음. 다양한 경험에서 기억의 득실을 일반적으로 예측한다는 결론에는 독립 원천과 실제 행동 결과의 보강이 필요함.

## 재현

```bash
python3 evaluation/audit_memory_data_quality.py --output /tmp/memory-data-quality-review
python3 -m unittest evaluation.tests.test_memory_data_quality -v
```

출력 경로가 이미 있으면 덮어쓰지 않고 거부함. 표준 라이브러리와 저장소의 기존 범위 감사 코드를 사용하며 데이터 원본은 읽기만 함. 큰 여행 6후보 원자료는 Git에 해시로 등록되어 있고 로컬 `training/memory_selector/outputs/memoryarena-travel-data-draft-v4`에 있어야 전체 감사를 재현할 수 있음. 없으면 해당 측정을 불가로 표시하며, 파일 누락을 품질 통과로 처리하지 않음. 이번 실행에서는 모두 존재했고 고정 해시가 일치했음.

추가 검사 6개는 빈 test 대신 실제 validation 분할을 검사하는지, 참조 유형을 올바르게 읽는지, 같은 기억/다른 현재를 중복으로 오인하지 않는지, 묶음을 숨긴 대조의 정보 제한, 해시 형식 미인식, ZIP 내부 훼손을 다룸. 외부 의미 주석·전체 모델 재추론·전체 저장소 회귀 검사를 수행한 것은 아님.
