# ConvoMem·AMA-Bench의 고정 외부 평가

2026-11-12. 두 벤치 각 100출처의 평가와 저장 예측 검산을 완료함. **ConvoMem에서는 보완 모델이 더 적은 기억으로 비슷한 정답 수를 얻었으나, 기본 검색보다 크게 낮음. AMA에서는 보완 모델의 정답 수가 감소함.** 기존 통제 실험의 개선이 범용 선택 우위로 이어졌다고 주장할 수 없음.

기존 12출처의 통제 평가에서 관찰한 개선이 다른 종류의 원문에서도 유지되는지를 확인함. 추가 학습 없이 기존 partial-record augmented 모델과 balanced-replay 모델을 두 seed에서 고정하고, ConvoMem 100개 프로필 및 AMA 100개 실행 이력의 원래 질문에 적용함. 작업자·후보 은행·전달 예산은 정책 간 동일함.

후속 [검색·순위·보류 진단](2026-11-12-external-selection-diagnosis.md)에서 보완의 근거 순위 개선과 과도한 보류를 분리함. 답변 가능한 문항의 위치 확인 주석 93개는 보완의 원래 제공에서 25·22개, 보류를 제거한 같은 최대 예산에서 47·56개, 기본 검색에서 82개임. 새 작업자 성공률이 아닌 저장 점수의 사후 진단이며 아래 원래 점수를 변경하지 않음.

## 결과와 현재 판단

아래는 **고정 9B 자동 채점의 원래 점수**임. 표본 20개 중 별도 Codex 검토와 3개가 불일치하므로 절대 정답 수는 잠정적인 자동 측정치임. 사람이 확인한 정답률이나 공식 벤치 점수가 아님.

| 정책 | ConvoMem 정답 /100 | AMA 정답 /100 | 평균 전달 토큰: ConvoMem / AMA |
|---|---:|---:|---:|
| 무기억 | 16 | 0 | 0 / 0 |
| BM25 | 80 | 13 | 983 / 961 |
| 기본 Harrier 임베딩 재순위 | 83 | 11 | 979 / 961 |
| 이전 augmented, seed 731 | 49 | 9 | 982 / 847 |
| 이전 augmented, seed 1729 | 47 | 9 | 981 / 806 |
| 보완 replay, seed 731 | 50 | 4 | 449 / 323 |
| 보완 replay, seed 1729 | 51 | 5 | 289 / 307 |

ConvoMem의 무기억 16정답은 모두 원래 정보 부재 문항의 보류 답변임. 답할 수 있는 나머지 84문항에서는 무기억 0, 기본 임베딩 68, 이전 33·31, 보완 34·35정답임. 따라서 기억의 효용은 관찰되지만, 학습 선택기가 기본 검색보다 좋은 것은 아님. 입력·기억 예산이 같은 후보 비교에서 보완 모델은 기본 임베딩보다 32–33문항 낮았고, 제공 주석 위치 확보도 낮아 이 차이를 자동 채점만의 현상으로 설명하기는 어려움.

ConvoMem에서 보완은 이전 대비 기억 토큰을 54.3%·70.5%, 전체 입력 토큰을 48.3%·62.8% 줄였음. 비슷한 관측 정답 수로 전달량이 감소한 점은 유지할 성과임. 다만 같은 정답을 모두 유지한 것이 아니며 비열등성을 입증한 실험도 아님.

| 보완 대 이전의 대응 비교 | 개선 | 악화 | 순변화 | 출처 재표집 95% 구간 |
|---|---:|---:|---:|---:|
| ConvoMem seed 731 | 16 | 15 | +1 /100 | −10~+12%p |
| ConvoMem seed 1729 | 18 | 14 | +4 /100 | −7~+15%p |
| AMA seed 731 | 3 | 8 | −5 /100 | −12~+1%p |
| AMA seed 1729 | 3 | 7 | −4 /100 | −10~+2%p |

위 구간은 설명용 재표집이며 채점 오차와 다중 비교를 반영하지 않음. 작은 전후 차이를 확정적인 개선·회귀 크기로 해석하지 않음. AMA는 기준선도 11–13/100으로 낮고 정답 근거만 제공한 진단은 없으므로, 후보 검색·선택·작업자 추론·출력 길이·채점 중 어느 병목이 지배적인지 이번 실행만으로 분리할 수 없음.

범주별로는 ConvoMem 사용자 사실이 이전 7·5→보완 10·11/17, assistant 사실은 8·9→11·10/16임. 반면 암묵적 연결은 4·5→3·1/17, 갱신은 8·8→7·7/17임. 같은 전체 점수 안에서도 유지되는 능력과 놓치는 관계가 다름. 특히 선호·중간 단서가 답변에 주는 가치를 직접 사실 조회와 함께 학습할 필요가 있다는 후속 가설과 연결됨.

두 사례를 [별도 파일](../../evaluation/results/memory-external-test-20261112-v1/posthoc-examples.json)에 원문·선택 ID·답변과 보존함. 결과를 본 뒤 고른 설명용 사례임.

- François Dubois의 시간대를 묻는 질문에서 이전 두 모델은 답하지 못했지만, 보완 두 모델은 CET를 담은 기록을 선택해 맞힘. seed 731의 전달량은 984→787토큰임. 기본 검색도 맞혔으므로 검색을 넘어선 새 능력이라고 부르지 않음.
- 바쁜 생활에 맞는 반려동물 선호를 활용하는 질문에서 기본 검색과 이전 seed 731은 맞혔지만 보완 모델은 둘 다 답하지 못함. 한 seed는 196토큰만 전달하고 다른 seed는 전부 보류함. 특정 사실이 직접 답을 담지 않더라도 선호나 조건을 제공하는 기억의 가치를 놓칠 수 있음을 보여줌.

## 채점 검토와 손해 해석

채점 기능 검사 6/6과 반복 4/4는 통과했고, 미채점 출력은 0개임. 그러나 **기능 검사를 통과했다고 의미 채점이 정확한 것은 아님.** 사전 선정 20답변의 별도 검토와 일치는 17/20임. 검토는 9B 출력이 생기기 전에 고정했지만 Codex의 보조 검토이며, 자료·정책 배정표에 접근할 수 있었으므로 독립적인 사람 맹검 평가라고 부르지 않음.

불일치에는 올바른 정보 부재 답변과 보고서 후속 절차를 오답으로 처리한 경우, 반대로 핵심 구분은 맞지만 근거 없는 원인 설명을 덧붙인 답변을 정답으로 처리한 경우가 있음. 원래 자동 점수는 덮어쓰지 않고 [20개 검토](../../evaluation/results/memory-external-test-20261112-v1/manual-review-comparison.json)를 함께 보존함.

자동 채점에서 무기억 대비 손해는 ConvoMem의 BM25 1건·기본 임베딩 1건이고 학습 선택은 모두 0건임. 이 2건을 원문까지 검토하니 모두 타당한 보류와 원문에 근거한 설명이었음. [전체 손해 사례 검토](../../evaluation/results/memory-external-test-20261112-v1/reported-harm-review.json)에 기록했으며 **이 차이를 학습 선택기의 손해 감소 성과로 주장하지 않음.** 무기억이 거의 못 푸는 이 자료는 원래 성공을 망치는 위험을 풍부하게 평가하는 자료도 아님.

현재 결론은 작은 관계 모델의 학습 가능성과 특정 데이터 보강의 효과를 유지하되, 범용 기본 선택기로 교체하지 않는 것임. 후속 학습에서는 별도 개발 자료에서 자연 문장·선호·중간 단서의 양성을 보존하면서, 공통 후보 안의 순위와 제공·보류를 나눠 확인하는 것이 적절함. 이번 200출처를 이미 관찰했으므로 임계값을 여기에 맞춘 뒤 미사용 시험 성적이라고 다시 보고하지 않음.

## 자료와 평가 단위

| 자료 | 출처·질문 | 구성 |
|---|---:|---|
| ConvoMem | 100개 합성 프로필에서 각 1문항 | 원래 근거 대화 전체 + 같은 프로필의 원래 배경 대화 2개 |
| AMA-Bench | 100개 실행 이력에서 각 1문항 | 원래 행동·관측 이력 전체 |

질문과 참조 답변을 다시 생성하지 않음. 원문 10,217,285토큰을 192토큰 창·160토큰 간격으로 나눠 66,719조각을 만들고, 질문 BM25 상위 64개를 공통 후보로 사용함. 후보는 총 9,399개이며 정답 근거를 강제로 넣지 않음. 모든 정책은 전달 상한 1,024토큰·12조각과 원래 기록 순서 표시를 공유함. 따라서 기본 임베딩 검색 역시 **공통 BM25 후보 안의 재순위**이며 전체 은행을 직접 검색하는 비교가 아님.

ConvoMem은 선호 17·사용자 사실 17·갱신 17·암묵적 연결 17·정보 부재 16·assistant 사실 16문항임. 프로필별 지정 범주에서 가능한 가장 작은 근거 수의 원래 문항 파일을 선택하고 해시로 문항을 결정함. 공식 pre-mixed context 길이별 벤치 전체와 다른 통제 부분 집합임. 원래 근거 대화의 상대 순서는 유지함. 원본 Hugging Face 메타데이터의 split 명칭은 `train`이나 공개 core benchmark이며, 우리 선택기의 추가 학습에는 사용하지 않은 평가 자료임. 공식 별도 test split 성적이라고 부르지 않음.

AMA는 SOFTWARE 36개를 제외한 EMBODIED_AI·Game·OPENWORLD_QA·TEXT2SQL·WEB 각 20개임. 공식 질문 유형 A/B/C/D는 각 25개임. 과거 실행의 성공 여부로 자료를 걸러내지 않음. 원래 에이전트 작업을 다시 수행한 것이 아니라 **실행 이력에 대한 회상·추론 질문의 응답**을 평가함.

200개 출처에 질문 문자열은 195개임. 반복 질문도 다른 실행 이력의 문항으로 유지함. 출처 수가 200개의 독립 과제 유형을 뜻하지는 않음. 기존 232개 정리된 JSONL 파일의 질문 필드와 정규화한 완전 일치는 0개이나, 의미 중복이나 기본 모델의 사전 학습 오염까지 배제한 것은 아님.

## 고정 모델과 측정

- 선택기: Harrier 0.6B, rank-8 q/v LoRA + 기존 128차원 GELU 판독층. 이전 augmented와 replay의 seed 731·1729를 모두 유지함.
- 기준: 무기억, BM25, 기본 Harrier 코사인 검색. 학습 선택기는 기존 임계값 0.5를 유지함.
- 작업자: Qwen3.5-4B, BF16·greedy·비추론, 출력 상한 256토큰. 질문·선택 기억만 받고 정답 주석은 보지 않음.
- 채점: 별도 Qwen3.5-9B, NF4·greedy·비추론. 정책 이름을 숨기고 원래 참조 답변/루브릭에 따른 YES/NO를 판정함. 이는 공식 벤치 채점기나 사람 정답이 아닌 로컬 자동 채점임.
- 품질 확인: 사전 고정 6개 채점 기능 검사, 모델별 4회 생성 반복, 사전 선정 20답변의 별도 참조 검토를 사용함. 별도 검토 역시 Codex의 검토이며 사람 주석으로 부르지 않음.

200상태 × 7정책 = 1,400결정이며 같은 프롬프트를 공유하는 결정을 묶으면 작업자 입력은 1,121개임. 반복 생성이나 정책 결정을 독립 출처로 세지 않음. 성공률과 함께 무기억 대비 개선·악화·공동 성공·공동 실패, 전달 토큰, 같은 출처의 대응 차이를 기록함. 신뢰구간은 해당 100개 프로필/에피소드 재표집에 조건부이며 과제 유형 전체의 일반화 보장이 아님.

## 근거 확보 지표의 경계

ConvoMem 제공 주석 118개 중 원문 문자열 위치가 직접 대응한 109개만 위치 기반 확보율로 집계함. 나머지 9개도 원문 의미 검토에서는 대응 내용이 확인됐으며 문항을 제외하지 않음. 다른 표현으로 반복된 같은 사실은 위치 지표에서 누락될 수 있음. 제공 주석 전체가 최소 충분 집합이라는 보장도 없으므로 이 수치를 관계 정확도나 충분성 정답으로 부르지 않음. AMA에는 공식 조각별 정답이 없어 새 관계 라벨을 만들지 않음.

1024토큰 이외의 12조각 제한은 짧은 기록이 많은 AMA 5상태에서 BM25·기본 임베딩의 10결정에 실제로 걸림. 결과를 보고 이 제한을 완화하지 않음. 현재 관측은 모두 없음으로 고정했으므로, 실제 진행·실패 이력에 따라 선택을 바꾸는 능력을 직접 입증하는 평가도 아님.

## 재현 자료

원본 질문·참조 답변 200개, 원문 기록 7,852개, 전체 66,719조각과 공통 후보 9,399개를 다시 대조했고 불일치는 없었음. 실제 판독층과 저장 특징으로 학습 모델 점수 37,596개를 재계산한 최대 오차는 9.81×10⁻⁸이며, 기본 임베딩 점수 9,399개와 1,400개 정책 결정도 일치함. ConvoMem의 제공 주석 위치 109개는 공통 후보에 모두 있었고 최종 확보는 BM25 90·기본 임베딩 95·이전 24/30·보완 29/25개임. 위치 지표의 의미상 제한은 위 설명을 따름. 확률 대신 logit 차이로 정렬한 사후 진단에서도 ConvoMem 선택이 바뀌지 않아 단순 수치 포화로 설명되지 않음.

작업자 고유 입력 1,121개·반복 4회, 채점 입력 1,123개(기능 검사 6개 포함)·반복 4회를 실행함. 두 모델의 반복은 각각 4/4 동일함. 작업자 출력 68개가 256토큰 제한에 닿았고 입력 잘림은 없었음. 선택기·작업자·채점의 최대 입력은 각각 839·1,673·2,324토큰임. 출력 제한으로 불완전해진 응답도 제거하지 않음.

로컬 RTX 4080 SUPER에서 선택 약 544초, 작업자 약 4,752초, 채점 약 352초를 사용함. 단계 시간 합계 약 94.1분임. 기억 토큰 감소를 전체 실행 시간 우위로 바꾸어 해석하지 않음. 새 학습·유료 API·Colab 할당은 없었으며 GPU 계산 프로세스 종료를 확인함.
