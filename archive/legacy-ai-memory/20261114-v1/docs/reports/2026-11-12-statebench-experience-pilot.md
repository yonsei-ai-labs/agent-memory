# STATE-Bench 경험 기억: 첫 실제 업무 파일럿

2026-11-12. 공개 과거 기록에서 검토한 기억 20개를 만들고, 개발 과제 8개에 세 전달 정책을 적용하여 24개 실행을 처리함. **작업 성공은 무기억 5/8, 요청 기반 Harrier 6/8, 요청+관측 Harrier 5/8임.** 기억 제공으로 완료한 사례와 추가로 잘못 처리한 사례를 실제 도구·DB 변화로 확인했으나, 상태 입력이나 학습 선택기의 우위를 입증한 결과는 아님.

## 이번에 검증한 질문

과거 경험을 조건과 함께 전달하면 현재 업무의 성공·실수·비용이 달라지는지, 그 차이를 검산 가능한 형태로 측정할 수 있는지 확인함. 이전의 과거 사실 질문 응답에서 실제 도구를 사용하는 업무로 평가 범위를 넓힌 단계임.

선택기는 **추가 학습하지 않은 Harrier 0.6B**임. 기존 LoRA 모델의 새 벤치 성적이나 학습 개선 결과가 아님. 먼저 기억 은행·작업자·채점의 작동 여부와 선택 여지를 확인했으며, 기존 ConvoMem·AMA의 부정 결과도 그대로 유지함.

## 데이터와 조건

- 공개 train의 기억 출처 239개 중 20개 기록에서 고객지원·쇼핑 각 10개 기억을 작성함. 과거 관측 / 현재 확인할 전제 / 조건부 활용 제안 / 적용 경계를 구분하고 원문 80곳을 연결함. 단일 에이전트 검토이며 다중 독립 주석은 아님.
- `approved_for_pilot`은 파일럿 사용 허용임. 원래 성공 여부와 실제 득실 라벨은 `null`로 유지함. 파일명에만 있는 만료 주장, 실제 도구 실패가 없는 오류 주장은 경험 근거로 채택하지 않음.
- 개발 출처 61개에서 영역별 4개를 결과를 보기 전에 해시 순서로 선택함. 8개의 정규화 그룹은 기억 출처와 겹치지 않으나, 의미상 독립적인 과제 가족 8개를 보장하지 않음. 공식 test 과제·환경 내용은 열지 않음.
- 고정 작업자는 OpenRouter `qwen/qwen3.5-9b`, 공급자는 `primeintellect/bf16`임. 사용자 시뮬레이터·과제 채점기는 `openai/gpt-5.4`, 공급자는 `openai`임. 이전 로컬 4B와 비교한 실험이 아님.
- Harrier revision은 `f9b9dc8d367d443f2479d27aa5d8d2850c0774ee`임. 같은 영역의 후보 10개에서 최대 3개·1,024토큰을 선택함. 안내문·ID를 포함하여 계산함.
- 요청 조건은 첫 요청과 현재 사용자 요청을 읽음. 관측 조건은 여기에 완료된 이전 대화·도구 결과를 더함. 첫 턴처럼 이력이 없으면 입력이 완전히 같음. 숨겨진 과제 요약·채점 요건·DB 원본은 선택기나 작업자에게 주지 않음.
- 비종료 사용자 턴마다 한 번 선택함. 같은 턴의 도구 루프에서는 다시 선택하지 않음. 선택기 입력은 4,096토큰 상한이며 첫 요청·현재 요청을 보존하고 오래된 완전한 관측 메시지부터 제거하는 규칙임. 이번 실행에서는 제거가 없었음.

## 결과와 비용

성공은 공식 상태 요건과 과제 요건을 모두 통과한 경우임. 원래 8라운드 도구 한도에서 끝나지 않은 실행은 실패로 포함함. 이 4개 실행에는 최종 요건 채점 값을 임의로 만들지 않고 `null`로 남김. 성공·실패가 판단된 실행 24개 중 최종 요건까지 채점한 것은 20개임.

| 정책 | 성공 / 8 | 도구 루프 미완료 | 무기억 대비 개선 / 악화 | 도구 호출 | 중복 호출 | 작업자 입력 토큰 합계 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 무기억 | 5 | 2 | — | 53 | 5 | 242,772 |
| Harrier 요청 | 6 | 1 | 1 / 0 | 55 | 8 | 281,895 |
| Harrier 요청+관측 | 5 | 1 | 1 / 1 | 59 | 12 | 308,606 |

중복 호출은 공식 효율 지표의 동일 호출 반복 수이며 모두 불필요한 행동이라는 주석은 아님. 작업자 입력은 정책별 논리적 토큰 합계로, 반복 호출에 들어간 대화·기억도 포함함. 시뮬레이터·채점·선택기 비용은 이 열에 포함하지 않음. 관측상 성공 수가 유지되거나 늘어도 입력·도구 비용은 감소하지 않았음.

`*`는 도구 루프 한도에서 미완료임. 8개 개발 과제의 한 번 관측이며, 1건 차이를 일반화된 12.5%p 향상으로 주장하지 않음. 똑같은 API 요청은 저장 응답을 재사용했으므로 조건 사이에 같은 경로는 결합되어 있음. 반복 독립 표본이 아님.

실패한 준비 시도까지 포함한 API 요청은 298회, 성공 응답은 285회임. 응답에 기록된 비용 합계는 **$0.691699669**, 비용을 알 수 없는 실패 요청의 사전 예약액까지 포함한 보수적 장부는 **$0.863237569**임. 후자는 실제 청구액이 아님. 전체 $5 상한 안에서 종료함. 로컬 GPU는 Harrier 추론에만 사용하고 종료했으며 Colab 할당·새 모델 학습은 없음.

## 행동 차이를 확인한 사례

**개선: 예산 $100의 무선 헤드폰 탐색.** 실제 후보는 $110이었음. 무기억은 여덟 번째 라운드에도 프로모션 조회를 호출해 답변을 마치기 전에 한도에 도달함. 두 기억 조건은 일곱 번의 도구 호출 후 초과 금액을 설명하고, 구매하지 않겠다는 사용자 선택을 받아 완료함. 제공 기억에는 과거 품절·예산 제약에서 비싼 대체품을 임의로 선택하지 않는 경험이 포함됐음. 다만 검색 반복이 양쪽에 남아 있고 기억 3개를 함께 줬으므로, 특정 기억의 효용이나 안정적인 효율 개선은 아직 분리되지 않음. 요청·관측 조건은 같은 기억을 골라 같은 응답 경로를 재사용함.

**악화: 교환이 끝난 뒤 다시 교환을 실행함.** 관측 조건은 사용자가 차액의 스토어 크레딧 처리를 수락한 후 교환을 완료했으나, 같은 행동을 다시 호출함. 재실행 거부 후 새 미리보기를 거쳐 또 확정하여 교환 상품 레코드가 두 개 생김. 언어 채점은 통과했지만 실제 DB 상태 검사가 실패함. 같은 관측 접두부에서 요청 조건의 수수료 구성 기억이 관측 조건에서는 이미 반품된 물건의 재처리 경계 기억으로 교체된 것을 확인함. 이것이 중복 실행의 원인이라는 증거는 아님. **문제 행동은 한 사용자 턴 안의 도구 루프에서 발생하여 선택기가 새 결과를 받고 다시 판단할 기회가 없었음.**

**공통 실패: 품절 교환의 환급 방식.** 기억 조건들은 스토어 크레딧을 안내하고도 실제 `process_return`에서 원 결제 수단으로 환급함. 요청 조건은 언어 채점만 통과했음. 실제 상태 채점으로 이 차이를 확인함. 현재 20개 은행에는 이 전환을 직접 뒷받침하는 경험이 없어 은행 범위와 작업자 실행을 함께 점검해야 함.

**공통 실패: 계절·반복 반품 배송비.** 무기억은 116 대신 121을 환급했고 기억 조건은 도구 루프에서 멈춤. 금액 구성요소를 구분하는 일반 경험은 있으나 해당 조건 조합을 직접 다루지 않음. 세 정책 모두 실패했다는 이유만으로 기억을 유해 라벨로 바꾸지 않음.

요청/관측 정책에서 같은 관측 접두부로 맞출 수 있는 선택은 18개임. 이 중 기억 집합이 달라진 것은 3개, 같은 기억의 순서만 달라진 것은 2개임. 상태 입력의 효과를 충분히 다양하게 시험한 자료는 아님.

## 검산과 실행 중 수정

원본 런타임·자료 398파일, 기억 근거 80곳, 선택 65회, 작업자 응답 단계 209개를 대조함. 저장 임베딩에서 점수와 전달 문자열을 재계산하고 **도구 호출 167개를 같은 초기 환경에서 재실행하여 결과와 DB 변화를 검산함.** LLM 채점은 원래 요청·저장 판정을 검산했으며 독립 재채점은 아님. 임베딩도 새 신경망 순전파로 재생산한 검산은 아님. 관련 테스트 23개가 통과함.

첫 시도의 빈 관측 이력 표기가 두 조건 입력을 다르게 만드는 문제를 발견해 수정하고 이전 결과를 보존함. 이후 DeepInfra의 반복 429 오류로 공급자를 고정 PrimeIntellect로 바꾸어 모든 정책을 다시 실행함. 이 공급자는 seed를 지원한다고 명시하지 않아 거부된 시도를 보존하고 seed를 제거함. 최종 비교표는 `live-v3`만 사용함.

도구 한도 미완료를 빠진 값으로 두지 않고 실패로 집계하도록 실행 중 보완함. 원래 8라운드 한도는 유지했고, 운영 호출 상한만 400→600으로 늘렸으며 $5 상한은 유지함. 기존 완료 결과와 정확히 같은 캐시 응답을 재사용함. 공급자·데이터·정책이 다른 이전 시도는 성적에 합치지 않음. 한 시뮬레이터 오류는 개선 전 로거가 응답 본문을 저장하지 못해 원인 전체가 확인되지 않음. 이 파일럿을 수정 없는 사전 확정 평가로 설명하지 않음.

공유 압축에는 코드·자료·토크나이저·API 응답·임베딩·실패 기록을 포함함. 공급자 오류 본문의 계정 식별자만 공유 사본에서 가렸으며 원본은 보존하고 변경 내역·원본 해시를 기록함. 합성 업무의 고객 ID·실제 실험 입력은 유지함. 새 폴더에서 API·GPU·모델 캐시 없이 같은 검산이 가능함.

## 남은 판단과 다음 범위

이번 성과는 **과거 근거가 연결된 경험 은행과, 실제 업무의 이득·손해·미완료를 분리해 측정하는 경로를 마련한 것**임. 언어적으로 맞는 설명과 실제 잘못된 변경을 구분한 점도 원래 연구 질문에 도움이 됨. 현재 결과로 관측을 무조건 길게 붙이거나 작은 자료에 바로 LoRA를 더하는 선택을 지지하지 않음.

다음은 기존 8개를 개발 진단으로 유지하면서 다음 순서가 적절함.

1. 기억 출처 쪽에서 품절 전환·이미 완료한 행동·복합 금액 조건의 직접 근거를 보강함. 이번 실패 과제의 정답을 기억으로 복사하지 않고 출처 근거·적용 조건·보류 상태를 검토함. 근거가 은행에 존재하는지부터 선택 정확성과 분리해 기록함.
2. 같은 진행 시점에서 환경 내부 추적 상태와 대화를 복제하는 분기 평가를 구성함. 정답 근거 진단 / 검색 / 상태 선택을 같은 후보·예산으로 비교하여, 선택 누락과 충분한 기억을 받은 작업자의 오용을 나눔. 도구 직후 재선택은 모든 정책에 같은 기회를 주는 별도 실험으로 다룸.
3. 선택이 달라져야 하는 관계 대조와 실제 분기 득실을 확보한 뒤 기존 모델의 동결 전이와 추가 학습을 비교함. 정책 캐시·간단한 상태 규칙도 기준선으로 유지함. 정책이 고정된 후 다른 개발 출처·공식 확인 자료로 확대함.

24개 실행 결과를 기억 20개의 이득·손해 정답으로 소급 변환하지 않음. 앞으로의 학습 목표는 **현재 조건에서 필요한 경험을 찾아 잘못된 재적용을 줄이는 것**이며, 관계 판독 점수와 실제 성공·손해·비용을 계속 별도로 측정함.
