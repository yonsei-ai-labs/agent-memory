# 현재 관측을 사용하는 메모리 효용 선택기: 진단 학습

전체 연구 목표는 기억이 어떤 상황에서 득·실을 만드는지 측정하고 설명·예측하는 것임. 이번 비교는 **현재 관측을 추가로 읽는 작은 선택기가 같은 과거 기록 묶음의 실제 득실을 더 잘 예측하고 선택하는가**를 확인함. 새로운 출처나 자유로운 검색 정책의 검증으로 해석하지 않음.

**학습·평가 완료. 현재 관측을 읽으면 득실 분류와 예측 오차는 개선됐지만, 실제 선택 후 성공은 늘지 않았음.** 모든 모델의 악화 범주 재현율은 0/9였음. 따라서 긍정적인 결과는 관측을 사용한 결과 예측의 개선이며, 유용한 메모리 선택기를 확보했다는 결론은 아님.

## 결과

각 행은 같은 초기값으로 목표만 / 목표+현재 관측을 비교한 결과임. 득실 분류의 분모는 237관측 묶음, 성공의 분모는 96상태임. 3개 family fold의 미학습 계열 예측을 합쳤으며 두 초기값을 독립 표본으로 더하지 않음.

| 학습 | 초기값 | 네 결과 분류 정확도 | 득실 값 예측 MAE | 선택 후 작업 성공 |
| --- | ---: | ---: | ---: | ---: |
| 고정 encoder + MLP | 731 | 54.4% → 67.5% | 0.320 → 0.342 | 55 → 55 / 96 |
| 고정 encoder + MLP | 1729 | 53.2% → 57.4% | 0.382 → 0.361 | 55 → 54 / 96 |
| LoRA + 같은 MLP | 731 | **55.7% → 67.5%** | **0.358 → 0.295** | **54 → 54 / 96** |
| LoRA + 같은 MLP | 1729 | **52.7% → 66.7%** | **0.368 → 0.298** | **55 → 55 / 96** |

LoRA의 macro F1도 0.377→0.502, 0.368→0.501로 개선됨. 다만 초기값 731에서는 고정 encoder도 같은 67.5%에 도달함. 현재 관측의 이득과 LoRA 자체의 이득은 구분해야 함. 고정 encoder의 한 회차에서는 분류 정확도가 좋아져도 득실 MAE는 악화됐음.

LoRA 731은 입력을 바꿔도 모든 상태의 작업 성공 여부가 같았음. 1729는 **2상태 개선·2상태 악화**로 상쇄됐음. 이 차이를 계열 단위로 재표집한 탐색적 95% 구간은 −4.17~+4.17%p임. 731의 관측 차이가 모두 0이어서 나온 [0, 0] 구간은 다른 자료에서도 효과가 없다는 증명이 아님.

### 놓치면 안 되는 실패

1. **악화 범주를 맞힌 모델이 없음.** 신경망·개수/길이 대조·사전 확률 모두 평가의 악화 9묶음에 대한 argmax 재현율 0/9임. 악화 확률을 아예 0으로 출력했다는 뜻은 아니지만, 손해를 안정적으로 구분하는 모델이라는 주장은 불가능함. 악화는 5상태·4계열에 집중돼 있음.
2. **분류 개선이 묶음 순위 개선으로 이어지지 않음.** 서로 다른 관측 효과를 갖는 16쌍에서 LoRA의 올바른 순위는 731에서 12→12쌍, 1729에서 9→10쌍임. 현재 관측을 쓰는 개수·길이 대조도 11쌍을 맞힘. 같은 상태 내 선택을 잘하는지 별도로 검증해야 함.
3. **학습 자료도 완벽하게 맞춘 것은 아님.** 현재 관측 LoRA의 학습 정확도는 fold·초기값별 83.8~90.3%였음. 이번 고정 8 epoch 비교만으로 구조의 최적 성능이나 학습 길이의 적정성을 확정하지 않음. 평가 자료를 보고 반복 조정하는 대신 새 검증 분할에서 결정해야 함.
4. **성공 여부와 근거 준수를 구분해야 함.** 무기억의 과제 성공 33개 중 입력 근거까지 만족한 것은 19개였음. 731은 현재 관측을 추가했을 때 작업 성공 54개는 그대로였으나 입력 근거 만족은 52→54개로 개선됨. 이 작은 개선도 보존하되 전체 성공의 개선으로 바꾸지 않음.

### 추가 진단: 무엇이 좋아졌고 무엇을 더 학습해야 하는가

기존 예측을 다시 분해한 사후 분석이며 재학습 결과가 아님. [계산 코드](../../evaluation/analyze_memory_state_effects.py)와 [수치·원본 해시](../../evaluation/results/memory-state-ablation-20261109-v1/effect-decomposition.json)를 보존함. 원래 confusion matrix 8개와 전부 일치함.

| 초기값 | 개선 범주 정답 / 57묶음 | 악화 범주 정답 / 9묶음 | 실제 악화 9묶음에 준 평균 악화 확률 |
| --- | ---: | ---: | ---: |
| 731 | 10 → 42 | 0 → 0 | 1.83% → 0.47% |
| 1729 | 32 → 43 | 0 → 0 | 1.46% → 0.12% |

유익한 기억의 판별이 좋아진 점은 유지됨. 동시에 악화 사례에 부여한 확률은 더 낮아져, 전체 분류 개선이 손해 감지의 개선이라는 뜻은 아님. 위 확률 평균은 악화 9행에 한정한 진단이며 전체 확률 보정 성능을 나타내지 않음.

네 범주 확률을 `p0=P(악화)+P(둘 다 성공)`, `p1=P(개선)+P(둘 다 성공)`으로 합하면 무기억/제공 후 성공 예측을 따로 볼 수 있음. `p1-p0=P(개선)-P(악화)`이므로 기존 선택 점수와 대수적으로 같음.

| 초기값 | 무기억 성공 예측 Brier | 제공 후 성공 예측 Brier |
| --- | ---: | ---: |
| 731 | 0.1987 → 0.1912 | 0.1036 → 0.1031 |
| 1729 | 0.2312 → 0.1850 | 0.0986 → 0.1076 |

Brier는 작은 값이 좋으며 237묶음 단위 평균임. 같은 상태의 무기억 정답이 반복되므로 237독립 경험의 평가가 아님. 무기억 성공 예측은 두 초기값에서 개선됐지만 제공 후 성공 예측은 일관되게 개선되지 않음. 상태 자체의 성공 가능성을 구별한 효과가 분류 개선에 기여했을 가능성과 양립함. 기억과 현재 상태의 관계를 더 잘 읽었다는 원인 증명은 아니므로, 후속에 상태만 보는 대조도 필요함.

### 손실함수 보완안: 분류와 실제 선택을 연결함

현재 네 범주 분류 손실을 대조로 유지하고, 첫 변경은 **관측한 후보 중 잘못된 선택으로 잃은 성과**를 학습하는 항 하나로 제한하는 것이 적절함. 예측 정확도와 의사결정 목적의 차이를 다루는 [Decision-Focused Learning](https://ojs.aaai.org/index.php/AAAI/article/view/3982), [Smart Predict, then Optimize](https://arxiv.org/abs/1710.08005)를 참고한 제안임. 아래 유한 후보의 softmax 손실은 이 프로젝트의 단순한 비교안이며, 해당 논문의 최적화 알고리즘·이론을 그대로 구현한 것은 아님.

상태 `x`의 실제 실행된 행동 집합 `A_x`에 무기억 `∅`와 관측 묶음을 넣음. 실행 성공을 `y_x(a)`라 두고 우선 효용을 `u_x(a)=y_x(a)-y_x(∅)`로 고정함. 미실행 묶음의 결과는 채우지 않음. 모델의 현재 점수를 `s(x,a)=P(개선)-P(악화)`, `s(x,∅)=0`으로 두고 학습 중 선택 분포를 `q(a|x)=softmax(s(x,a)/τ)`로 계산함.

```text
u*(x) = max_{a∈A_x} u_x(a)
L_select(x) = Σ_{a∈A_x} q(a|x) × [u*(x) - u_x(a)]
L_total = L_four_way + λ × mean_x L_select(x)
```

무기억 성공·A 제공 성공·B 제공 실패 상태라면, B를 선택할 확률에 비례해 손실이 증가함. 반대로 무기억 실패·A 성공·B 실패 상태라면, A를 고르지 않는 확률에 비례해 손실이 증가함. 성공률 차이만 볼 때 결과가 같은 후보 사이에는 우열을 강제하지 않음. 현재처럼 한 번의 이진 결과를 쓰면 같은 상태에서 무기억 대비 +1과 −1이 동시에 나올 수 없다는 점도 자료 제작에 반영함.

이 손실은 후보별 숫자를 독립적으로 맞히는 데서 더 나아가 **같은 상태 안의 선택**에 벌점을 연결함. 모든 관측 행동의 결과가 있는 범위에서는 보상을 새로 탐색하는 RL을 시작하지 않아도 계산 가능함. 정답과 `u*`는 학습에만 사용하고 실제 추론 입력에는 넣지 않음. 추론은 기존의 점수 최고값과 0을 비교하는 제공/보류 규칙을 유지하며, softmax 학습이 실제 argmax 정책을 개선하는지는 별도로 검증함.

구현·평가에서는 다음을 고정함.

- 같은 상태의 후보를 한 그룹으로 학습하고 상태별로 손실을 평균함. 분류항도 현재의 상태별 총 가중치를 유지함. 후보가 많은 상태나 같은 무기억 결과의 중복이 감독을 독점하지 않게 함.
- 첫 비교는 기존 분류 / 분류+선택 손실만 바꿈. encoder·LoRA·head·입력·분할·노출·추론 규칙은 유지하고, 추가 그룹 계산 비용과 실제 optimizer 업데이트 수를 기록함. 두 성공 예측 head로 나누는 구조 비교나 별도 순위 손실은 동시에 추가하지 않음.
- 두 후보의 실제 우열만 학습하는 [RankNet식 순위 손실](https://www.microsoft.com/en-us/research/publication/from-ranknet-to-lambdarank-to-lambdamart-an-overview/)도 별도 대조가 가능함. 다만 현재 묶음 간 유효 쌍이 16개뿐이므로, 기존 순위 학습의 재적용 자체를 새로운 기여로 주장하지 않음.
- 악화를 더 비싸게 다루려면 `u=개선-β×악화`라는 명시적 정책 목표로 별도 비교함. 첫 비교는 `β=1`, 비용 가중치 0으로 두고 성공·오류·토큰 비용은 계속 분리해 보고함. 악화에 대한 학습 가중치 증가와 실제 정책에서 손해를 더 싫어하는 설정을 같은 것으로 취급하지 않음.
- [비용 민감 학습](https://cseweb.ucsd.edu/~elkan/rescale.pdf)처럼 가중치·표집·결정 기준은 연결돼 있음. 악화 사례를 반복하거나 분류 가중치를 높인 뒤 출력 확률을 원래 분포의 확률로 바로 해석하지 않음. 선택 손실을 더한 출력의 보정과 임계값도 개발 자료에서 검토함. 평가 성적을 보고 `λ`·`τ`·임계값을 고르지 않음.
- 현재 7상태의 묶음 차이, 9묶음의 악화만으로 손실 설계의 일반적 효과를 결론내리지 않음. 기존 자료에서는 기능 진단을 하고 새 출처에서 같은 기억의 조건별 득실과 경쟁 묶음 결과를 측정해 확인함.

보완된 목적은 평균 분류 정확도 상승과 실제 선택 개선을 연결하려는 것임. 부족한 실제 득실 사례를 손실함수가 대신 만들 수는 없음. 이번 추가 작업은 원래 예측 재집계와 설계이며 새 학습·GPU 할당·작업자 호출을 하지 않았음.

| 학습 정답 | 실제 제공/미제공의 둘 다 실패·개선·악화·둘 다 성공. 임시 충분성 주석은 사용하지 않음 |
| 자료 | 기존 12계열·96상태의 비어 있지 않은 237묶음. 개선 57·악화 9·둘 다 성공 78·둘 다 실패 93 |
| 분할 | family ID의 고정 해시 순서로 3분할. 각 회차 8계열 학습·4계열 평가. 초기값 731·1729로 반복함 |
| 업데이트 | 8 epoch, 모든 학습 행을 epoch마다 한 번씩 사용함. 상태별 묶음 수의 역수로 손실을 가중해 상태별 총 비중을 맞춤 |
| 모델 선택 | 마지막 epoch로 고정함. 평가 계열 성적을 보고 checkpoint·임계값을 고르지 않음 |
| 행동 | 이미 실행된 묶음 중 하나 또는 무기억. `P(개선)-P(악화)>0`인 최고 점수 묶음을 제공함 |
| 고정 작업자 | 기존 Qwen3.5-9B의 원래 입력·출력·결과를 연결함. 새 작업자 호출 없음 |
| 예산·자원 | 기존 전달 상한 512토큰 유지. 로컬 RTX 4080 SUPER, 프로세스 메모리 상한 50%. Colab 할당 없음 |

정확한 설정은 [고정 config](../../training/memory_selector/configs/memory-state-ablation-v1.json)에 있음. 모델 구조·revision은 [공식 고정 config](https://huggingface.co/microsoft/harrier-oss-v1-0.6b/blob/f9b9dc8d367d443f2479d27aa5d8d2850c0774ee/config.json)를 사용함. 실제 가중치 해시·라이브러리 버전·학습 노출·초기 head/adapter 해시·optimizer·최종 adapter를 실행 산출물에 저장함.

두 입력 조건은 같은 학습 행·순서·초기 가중치·업데이트 수를 사용함. 목표 입력은 평균 327.0토큰, 현재 관측을 포함한 입력은 평균 1,131.1토큰이며 최댓값은 1,325토큰임. 입력 잘림은 허용하지 않음. 모델 비교는 입력 정보량 차이를 포함하므로 선택기 비용도 별도로 기록함.

## 자료에서 먼저 확인한 제한

목표+묶음 입력은 237행에서 117종만 다름. 그중 48종은 현재 관측이 달라져 같은 선택기 입력에 서로 다른 실제 득실이 붙음. 네 결과의 결정적 분류를 동일 입력에 항상 동일하게 출력한다면 이 자료에서 맞힐 수 있는 최대 행 수는 184/237임. 이는 관측 자료의 입력 충돌을 계산한 사후 진단이며 달성한 모델 점수나 새 출처의 성능 상한이 아님. 현재 관측까지 포함하면 237입력이 모두 구별되지만 그것만으로 관계 일반화가 보장되지는 않음.

악화 9묶음은 5상태에만 분포함. 기존 데이터에는 실제 순차적 진행·실패 이력이 없으며, 인위적인 조건·같은 도메인·카탈로그·문장 틀을 공유함. 앞서 확인한 삭제 조건의 후보 개수 편법도 자료 자체에는 남아 있음. 이번 신경망은 제안 묶음만 읽으며 전체 후보 수를 별도 입력으로 받지 않음. 개수·길이 기준선에는 신경망이 읽는 제안 기록 수·기록 토큰 수·입력 토큰 수만 사용함.

무기억과 제공 사이에서 결과가 달라지는 상태는 30개지만, 비어 있지 않은 묶음끼리 결과가 달라지는 상태는 **7개·서로 다른 결과를 가진 묶음 쌍 16개**뿐임. 나머지 상태에서 서로 다른 묶음의 성공 결과는 같음. 따라서 이번 자료는 제공/보류 진단에 더 적합하며, 묶음 순위와 세밀한 기억 선택의 학습을 검증할 신호는 매우 적음. 기존 top2와 규칙은 55/96, 상태마다 관측 결과를 미리 알고 최선의 행동을 고르는 진단용 선택은 58/96임. 후자는 현재 관측 행동 집합의 사후 값이며 작업자 성능의 일반적 상한이 아님.

모든 선택기는 같은 관측 묶음 집합을 받음. 이 집합에는 기존 검색·규칙 정책의 제안이 포함되므로 검색기의 가치를 새로 입증하는 실험이 아님. 상류 검색기를 이번 family 분할마다 다시 학습한 것도 아님. 현재 관측을 직접 주지 않는 조건에서도 공통 후보 제안 자체에 상태의 영향이 남을 수 있음. 이 실험은 **같은 제안 집합에서 현재 관측을 명시적으로 추가하는 효과**를 다룸.

## 평가와 재현

네 결과 분류, 관측된 득실 값의 예측 오차, 같은 상태 내 묶음 순위, 선택 후 실제 작업 성공·악화를 나눠 평가함. 무기억·기존 검색·규칙 결과도 함께 유지함. 확률 점수를 검증된 인과 확률로 부르지 않음. 두 초기값을 독립 과제 수로 더하지 않고, 출처 계열을 묶어 차이를 계산함.

선택기는 모든 제안 묶음을 점수화한 비용을 포함함. LoRA의 로컬 추론 시간과 저장된 작업자의 다른 GPU 실행 시간을 더해 새 end-to-end 속도처럼 보고하지 않음. 고정 특징 재사용의 인코딩 비용은 별도 추정치이며 실시간으로 재측정한 정책 지연과 구분함. 기존 검색·규칙의 선택 비용이 없으면 `null`로 유지함.

고정 encoder 12회·LoRA 12회, 총 24개 학습을 3,535.7초에 완료함. 학습 자료 237행을 원래 관측 입력·결과에서 다시 구성해 모두 대조함. 학습행별 8회 노출, 두 입력 조건의 초기 가중치 동일성, optimizer의 160/168 step과 유한한 상태, LoRA의 112개 파라미터 텐서 변화도 확인함. 기본 모델 가중치는 학습하지 않음.

저장 특징·판독층에서 1,896개 신경망 평가 예측을 재계산함. 또한 GPU에서 원본 모델과 LoRA 12개를 다시 불러 고정 특징 354개 및 LoRA 평가 입력 948개를 재인코딩했음. 특징은 동일했고 948개 분류가 모두 일치했으며 최대 확률 오차는 약 2.27×10⁻⁷임. 관련 테스트 71개가 통과함. 공유 대상 파일만 복사한 임시 사본에서도 같은 71개 검사·1,896개 예측 검산·237행 학습 자료 내보내기가 통과함. 학습·검산 GPU 프로세스는 종료됐으며 Colab 할당과 새 작업자 호출은 없었음.

실행 중 Transformers 4.57.6의 Mistral regex 경고가 발생했음. 설치 코드의 offline 판정이 config 버전 4.57.6의 Qwen3에도 경고를 내는 것을 확인하고, 354개 실제 입력을 고정 공식 tokenizer JSON·실행 tokenizer·저장 tokenizer로 각각 토큰화했음. 모든 토큰 ID와 pre-tokenizer가 일치함. Mistral 전용 수정을 적용하거나 학습 입력을 변경하지 않았으며 검사 코드·해시·결과를 공유 묶음에 보존함.

```bash
python3 -m data_pipeline.prepare_memory_state_ablation prepare --path /tmp/memory-state-ablation-data
python -m training.memory_selector.train_memory_state_ablation \
  --data /tmp/memory-state-ablation-data --output /tmp/memory-state-ablation-run
python -m evaluation.memory_state_ablation \
  --data /tmp/memory-state-ablation-data --run /tmp/memory-state-ablation-run \
  --output /tmp/memory-state-ablation-evaluation
```

준비 검사는 표준 라이브러리만 사용함. 학습은 고정 모델 파일이 로컬 HF cache에 있어야 하며 GPU와 [기존 학습 패키지](../../training/memory_selector/requirements-colab.txt)가 필요함. 이미 존재하는 출력은 덮어쓰지 않음. 이 명령은 Colab을 할당하지 않음.

학습 환경의 정확한 패키지 버전은 공유 묶음의 `environment-lock.txt`에 있음. GPU 없이 원본 해시·1,896개 예측을 재검산하는 명령과 전체 checkpoint 보관 위치는 [결과 README](../../evaluation/results/memory-state-ablation-20261109-v1/README.md)에 정리함. Git 공유 묶음에는 특징·판독층·예측·코드·검증 근거를 넣고, 큰 adapter·optimizer는 로컬 전체 검토 묶음과 해시 목록으로 보존함. 새 clone에 LoRA 전체 가중치가 포함된다고 주장하지 않음.

## 다음에 바꿀 것

이번 결과는 원래의 득실 연구와 연결됨. **현재 관측이 결과 예측을 돕는 신호는 있었지만, 어떤 기억을 제공할지 정하는 이득은 아직 확인하지 못했음.** 같은 자료에서 판독층을 늘리기보다 다음 데이터에 실제 선택 차이를 만드는 조건을 확보하는 것이 우선임.

- 새 출처에서 같은 목표·비슷한 주제의 기억들이 서로 경쟁하는 상태를 수집함. 현재 조건 하나가 달라질 때 같은 기억이 개선·중립·악화를 만드는지 원문과 실행으로 확인함.
- 기억의 적용 조건·누락/중복 근거에 대한 관계 주석은 결과와 독립적으로 검토하고, 실제 득실은 같은 작업자·같은 문맥 상한에서 제공/보류·경쟁 묶음을 실행해 측정함. 길이·개수만으로 조건을 구별할 수 없는 대조도 포함함.
- 수집한 모든 상태의 결과를 보존함. 효과가 큰 사례만 새 평가로 골라 놓지 않으며, 새 확인 출처는 결과를 보기 전에 분리함. 악화 사례를 추가 수집하거나 학습 가중치를 바꿀 경우 원래 분포의 평가도 유지함.
- 첫 새 자료에서 무기억·검색·짧은 후보·규칙·이번 고정 설정을 비교함. 분류·같은 상태 내 순위·실제 성공/악화·비용을 연결해서 보고함. 순차 진행·실패 이력은 실제 관측된 자료가 있을 때 별도 비교함.

별도의 최종 배포 모델은 선택하지 않았음. 24개 checkpoint는 이 진단 비교의 근거이며 평가에서 잘 나온 초기값을 최종 모델로 채택하지 않음.
