# 데이터 보강 인수 준비와 기존 자료 자체 검토

2026-11-12. 사용자와 정한 권장 분업에 따라 Codex가 맡은 출처 사용 이력·기존 증강 자료 점검·새 제작본 인수 검사를 진행함. **새 세션을 중복 제작하거나 모델을 학습하지 않고, 현재 자료의 검수와 받을 자료의 검사 경로를 준비함.** 상대 에이전트의 제작 착수·담당 수락은 이 작업에서 확인하지 않음.

[역할·인계 문서](../ai-memory-data-augmentation-handoff-2026-11-12.md) · [검산 자료](data/memory-data-intake-20261112-v1/README.md) · [인수 계약](../design-data/memory-data-intake-20261112-v1/README.md)

## 1. 새 세션에 안 쓴 원천과 미관찰 평가 원천을 구분함

기존 `new-a` metadata와 실제 stage1 결정의 가족 ID를 대조함. 봉인된 `new-b`의 내용은 읽지 않음.

| 항목 | 확인 결과 |
| --- | ---: |
| `new-a` 원 가족 | 44 |
| 기존 여행 세션 본 실행에 사용 | 20 |
| 그 세션 구성에 아직 사용하지 않은 후보 | 24 |
| 위 24 중 과거 9B 작성 기록의 stage1 평가에 등장 | 24 |
| 위 24 중 과거 27B 작성 기록의 stage1 평가에 등장 | 24 |
| `new-a`와 기존 `memory_need` 출처 중복 | 0 |

따라서 **24개는 새 세션 설계 후보이지만, 프로젝트에서 전혀 관찰하지 않은 평가 출처는 아님.** 실제 사용 이력과 분할을 유지하며 새 시나리오의 기능 점검·개발 자료로 사용 범위를 명시해야 함. 이번에는 이 후보를 예약하거나 학습으로 전환하지 않음. 새 과제에서의 적격성도 아직 검사하지 않음.

[출처 목록](data/memory-data-intake-20261112-v1/source-inventory.jsonl)은 `new-a`, 기존 `memory_need`, 전달 경로 파일럿·본 세션에 연결된 68가족의 목록임. 모든 공개 벤치와 프로젝트 전체 출처를 포괄하는 목록은 아님. 이름만 다른 파생 사례를 새 원천으로 세지 않도록 가족 ID와 과거 사용 역할을 보존함.

9B의 과거 생성에서는 43가족이 기존 상태를 만들었고 1가족이 제외됐으며, 27B에서는 42가족과 제외 2가족이었음. 제외 가족을 포함해 두 metadata가 같은 44가족을 가리킴을 확인함. 이때의 제외는 기존 생성 과제의 조건이며, 다른 세션 생성 과제에 곧바로 재사용할 적격·부적격 판정은 아님.

## 2. 기존 24사례를 작성자 자체 검토함

정답 키를 복사하는 대신 공개 목표·상태·관측·네 후보를 읽고 필요한 기록과 짧은 판정 근거를 작성하여 별도 파일로 남김. 다만 **같은 구축 에이전트가 생성 규칙을 이미 알고 있는 상태의 자체 검토**임. 독립 인간·외부 에이전트의 눈가림 주석으로 계산하지 않음.

| 항목 | 결과 |
| --- | ---: |
| 검토한 공개 사례 | 24 |
| 관계 정답과 일치 | 24 |
| 자체 검토에서 찾은 관계 정답 불일치 | 0 |
| 독립 인간 검토 | 0 |
| 실제 작업자 득실 측정 | 0 |

내용 검토에서 한 가지 범위 설명을 보완함. 원 검토표는 과거 사실 중 무엇이 현재 필요한지 판단하는 데 쓰지만, 요청에는 “현재 이용 가능해야 한다”는 조건도 있었음. 원 검토표에는 현재 카탈로그가 없어서 전체 예약의 실행 가능성까지 검토하기에는 부족함.

원 은행에 보존된 카탈로그에서 24×4개의 현재 이용 가능성을 확인하여 **96개 모두 참**임을 확인함. [보완 검토표](data/memory-data-intake-20261112-v1/review-packet-with-context.jsonl)에 이 사실과 관계 검토의 범위를 추가함. 원 증강본·라벨·모델 입력은 수정하지 않음. 이 보완으로 실제 성공이나 손해가 측정된 것은 아님.

현재 목표의 기본/대안 역할, 현재 확인된 사실, 다른 조회의 실패, 문장 절 순서를 구분하는 관계 자체는 24사례에서 일관되게 읽혔음. 이는 작성자의 내용 점검이며 모델 판독 성적이 아님.

## 3. 새 자료를 받을 때 사용할 기계적 인수 검사를 구현함

[memory_data_intake.py](../../data_pipeline/memory_data_intake.py)는 다음을 검사함.

- 증강 전 원 가족의 분할 중복, 같은 실제 판독 입력의 분할 중복·상충 판정.
- 후보 입력·관계 주석의 일대일 연결과 입력 문자열 해시.
- 정답 근거 사건의 원천·가정 시나리오·시점이 해당 상태에 속하는지.
- 선언한 근거의 문자 구간이 실제 판독 문자열에 있는지.
- 정보 부족을 명시하고, 작업자 실행 전에는 실제 효용을 `null`로 두는지.

현재 증강본을 원본 수정 없이 adapter로 인수 계약에 맞춰 검사함.

| 인수 검사 대상 | 결과 |
| --- | ---: |
| 원 가족 / 현재 상태 | 11 / 1,056 |
| 판독 입력 / 고유 판독 입력 | 4,224 / 4,224 |
| 필요한 후보 / 불필요한 후보 | 1,056 / 3,168 |
| 선언한 근거 문자 구간 | 8,448 |
| 분할 중복 / 상충 입력 | 0 / 0 |
| 실제 효용 라벨 | 0 |

테스트에는 다른 시나리오나 미래의 사건, 실제 입력에 없는 변경 근거, 누락된 주석, 같은 입력의 반대 정답, 과거 사용 원천을 새 원천으로 표시한 경우가 포함됨. 관련 검사 **54개가 통과함**.

결과는 `mechanical_checks_passed`임. 선언하지 않은 필수 전제를 자동으로 발견하는 의미 판독기나 학습 승인 시스템은 아님. 과거 사용 이력의 사실 여부는 출처 목록과 사람이 연결해야 함. 토큰화·길이 절단 후에도 근거가 남는지는 실제 모델 연결 시 추가 확인해야 함.

## 4. 다음 인수 순서

1. 저쪽이 새 제작본의 출처 목록·사건·공개 문장·관계 주석을 원본 형태로 전달함.
2. Codex가 버전과 출처 사용 이력을 대조하고, 내용 보존 adapter로 인수 검사에 연결함.
3. 기계적 오류와 의미 검토의 이견을 별도 목록으로 반환함. 필요한 전제가 보이지 않는 경우를 학습 음성으로 바꾸지 않음.
4. 관계 자료를 동결한 뒤 학습용 파생을 만들고, 실제 작업자 결과는 별도의 기준 조건·원 입력·원 출력과 연결함.

이번 작업은 위 인수 준비와 기존 자료 검토까지임. 새 세션·새 독립 평가·모델 학습·GPU·유료 호출은 없음. 보완 검토표에 대한 독립 검토와 저쪽의 새 제작본은 아직 대기 중임.

마지막 검증에서 새 임시 디렉터리에 만든 분석 파일 5개가 모두 바이트 단위로 재현됨. 원 증강본의 hash audit, 새 Python 구문, 문서 링크 18곳과 공백 검사도 통과함.
