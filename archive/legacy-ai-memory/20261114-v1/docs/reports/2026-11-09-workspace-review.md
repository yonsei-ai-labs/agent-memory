## 현재 유지할 검색 결과

test 219질문·기본 계획 8개이며, 최종 10기록의 질문별 평균 Recall임.

| 조건 | Recall@10 | 정답 전부 포함 | 후보 정답 → 최종 정답 연결 |
| --- | ---: | ---: | ---: |
| A. 기존 검색 32후보 | 68.57% | 96/219 | 470 → 468 |
| B. 기존 검색 64후보 | 86.87% | 144/219 | 643 → 633 |
| C. 학습 검색 hybrid 32후보 | 92.00% | 166/219 | 675 → 667 |
| D. 고정 dense 32후보·보조 | 69.92% | 92/219 | 489 → 486 |
| E. 학습 dense 32후보·보조 | 96.96% | 191/219 | 734 → 722 |

C는 A 대비 +23.43%p, 후보를 두 배로 늘린 B 대비 +5.13%p임. 후보 검색이 병목이라는 이전 분석과 새 학습 결과가 연결됨. E는 사전에 정한 보조 조건이므로 이를 test에서 새 주 방법으로 바꾸지 않음. 정답 생성 규칙이 거의 완전한 과제에서 학습 모델의 일반적 필요성을 증명한 것은 아님.

같은 고정 후보 안의 후단 누락도 구분함. 이번 저장 결과에서는 후보에 들어온 정답이 10개를 초과한 경우가 없어 **후단 누락 A 2개·B 10개·C 8개·D 3개·E 12개는 모두 순위에 따른 누락**이었음. 원문 정답이 12개인 질문은 존재하지만 현재 후보에 모두 들어오지는 않았음. 일반적으로 존재하는 10개 한도의 제한과 이번 실제 누락 원인을 혼동하지 않음.

## 우선 해결할 문제

### 1. 판독 확률의 실행 구성 간 안정성이 확인되지 않음

가중치·소프트웨어 버전이 같은 이전 실행과 비교한 공통 9,378쌍에서 확률 절대 차이 중앙값은 약 5.22×10⁻⁷이지만, **61쌍은 0.01을 넘고 최대 0.18913**이었음. 차이를 전부 사소한 반올림이라고 설명할 수 없음. 서로 다른 후보 합집합의 배치를 사용했으나 원인 자체는 아직 분리되지 않음.

현재 A 조건과 이전 결과의 **정답 선택 집합은 219질문 모두 같고**, 전체 10개 집합은 212질문에서 같았음. 현재 A/B/C/D/E는 같은 후보 합집합에서 계산한 점수를 공유하므로 저장된 비교 수치를 폐기할 근거는 발견하지 못함.

그러나 이전 dev에서 고른 보류 임계값 0.99346923828125를 공통 쌍에만 적용하는 사후 진단에서는 **정답 쌍 6개의 임계값 경계 판정이 바뀜.** 이는 새 보류 정책의 평가가 아니며 후보 집합 전체의 제공량 변화도 아님. 확률을 활용하는 보류 정책을 옮기기 전 동일 입력의 단건/여러 배치 크기/패딩 길이/수치 정밀도 대조를 고정해야 함. 이미 본 test로 임계값을 다시 맞추지 않음.

### 2. 품질 측정과 지연 측정의 실행 방식이 다름

온라인 지연은 dev 21질문·3조건의 단건 실행 각 1회임. 이 63실행 중 6개는 배치 평가와 선택 집합이 달랐고, 1개는 찾은 정답 수가 5/7→6/7로 바뀜. 따라서 test 검색 성적과 dev 단건 중앙값을 동일한 실행의 품질·지연이라고 취급하지 않음.

워밍업한 단일 A100·미리 만든 인덱스에서 C의 중앙값은 약 283.4ms, B는 439.4ms였음. 후보 수 절감의 실용적 신호는 있으나 로딩·인덱스 생성·추가 학습·작업자 비용을 포함한 전체 경제성은 미측정임. 10기록이라는 같은 개수도 같은 토큰 예산을 보장하지 않음.

### 3. 반복해서 본 8개 평가 계획의 성적임

문장 참조 → 전체 질문 판독 → 후보 검색 학습에서 같은 기본 계획 분할을 재사용함. 이번 실행에서 test 정답이 optimizer나 checkpoint 선택에 들어간 누출은 발견하지 못했지만, 이전 test 결과를 보고 다음 연구 방향을 선택한 적응적 탐색임. 단일 seed의 같은 계획에서 얻은 92.00%·96.96%를 새 출처의 확증 결과로 부르지 않음.

다음 평가에는 새 기본 계획·실제 생성한 과거 이력·다른 표현·유효 참조 부재를 확보할 필요가 있음. 새 평가 자료는 성과가 큰 사례만 골라 만들지 않음. 규칙보다 좋아야 할 판단이 무엇인지도 데이터 계약에서 분명히 해야 함.

### 4. 검색 개선과 실제 득실을 연결하는 검증이 남음

최신 실험은 최종 10개를 항상 제공함. C의 전달 2,190개 중 canonical 정답은 667개로 정밀도 30.46%임. 나머지가 곧바로 해로운 기억이라는 뜻은 아니지만 높은 검색률만으로 실제 전달 정책이 적절하다고 판단할 수 없음.

이전 식당 효용에서는 같은 정확한 기억도 현재 정보에 따라 개선·악화를 보였음. 이번 공개 참조 이력의 검색 실험과 실제 선택 이력의 효용 실험은 자료·행동·분모가 다르므로 검색률 92%를 작업 성공률로 치환하지 않음. 같은 작업자와 정보·토큰 예산에서 무기억·고정 기억·검색·규칙·학습 검색의 성공·악화·보류·비용을 비교하는 단계가 필요함.
