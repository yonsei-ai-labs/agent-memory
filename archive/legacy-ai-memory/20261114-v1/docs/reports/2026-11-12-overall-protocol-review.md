# 전체 재검토: 데이터의 일관성과 누적/분리 평가의 타당성

2026-11-12. **기존의 좁은 학습 개선과 데이터 검산 결과는 유지됨. 새 누적/분리 실험은 방향이 적절하지만, 현재 패킷과 설계만으로 바로 학습·성능 주장을 하기에는 보완할 부분이 있음.** 수치가 무효가 됐다는 결론과, 새 실험의 준비가 끝났다는 결론 모두 피해야 함.

검토 범위는 [현재 실험안](../ai-memory-data-cleanup-and-context-stream-plan-2026-11-12.md), 최근 세 데이터의 버전 경계, 새 숨은 함정 패킷과 생성 코드, 데이터 보강의 원인 분해 결과임. 저장소 전체의 모든 과거 실험·실행 환경을 검증한 것은 아님. 설계 작성에 참여한 Codex의 재검토이며 독립 인간/외부 심사로 부르지 않음.

[CPU 진단과 재현 기록](data/memory-overall-protocol-review-20261112-v1/README.md)에 계산·입력 해시를 보존함. 원본 패킷·이전 보완본·학습 가중치·다른 작업 트리는 수정하지 않았고 GPU·작업자 호출·새 학습은 없음.

## 2. 실행 전 우선 보완할 사항

### P1 같은 총예산의 기준선이 빠져 있었음

기존 초안은 추가 기억 없음에서 최근 대화 2k, 검색/학습에서 최근 2k+기억 2k를 사용함. 이 비교는 기억 추가의 제거 진단으로 쓸 수 있으나, **같은 총 컨텍스트 예산의 실용적 이득**을 입증하는 비교로는 부족함. 더 많은 과거 텍스트를 읽어서 생긴 이득일 수 있음.

현재 실험안에 **최근 대화만 4k**를 주 기준선으로 추가함. 최근 2k만 읽는 조건은 국소 제거 진단으로 유지함. 최종 채팅 템플릿까지 적용한 전체 입력 상한도 같아야 함. 개별 본문 길이만 맞추고 대화 역할·머리말의 비용을 빼면 다시 예산 차이가 생김. 새 입력 생성기와 최종 예산 검사는 아직 구현 전임.

원본에서는 S/M의 BM25 2k가 필요한 기록을 모두 확보하고, L에서만 일부 누락이 생김. 길이만 늘렸다고 별도 학습 선택기가 필요한 과제가 되는 것은 아님. 올바른 근거를 줬을 때의 실제 성공·추가 기록의 손해·선택 비용을 함께 측정해야 함. 기준선으로 충분히 풀리더라도 득실을 검산하는 데이터의 가치는 별도로 평가함.

### P1 서로 다른 누적 경로를 국소 득실의 짝으로 쓰면 안 됨

같은 외부 사건의 같은 질문이라도 C의 검색 정책과 C의 무기억 정책은 이전에 한 답이 다를 수 있음. 두 결과의 차이에는 현재 선택한 기억뿐 아니라 과거 답변의 영향이 포함됨.

전체 세션 비교는 그 경로를 포함하는 **정책 효과**로 유효함. **현재 기억 한 번의 제공 효과**를 재려면 한 궤적의 질문 직전 상태를 고정한 제공/보류 분기가 필요함. 현재 실험안에 스냅샷 해시·반복 경로 ID·행동·실제 입력 해시를 결과 키로 명시하고, 기억 추가 전 상태가 다른 결과를 국소 득실로 합치지 않도록 보완함. 실행기의 자동 거부 검사는 미구현임.

C/D 차이도 이전 오답만의 영향으로 단정하지 않음. 이전 질문·답변이 최근 창에서 사실을 밀어낸 효과가 함께 있으므로, 보이는 사실과 제공 기억을 고정한 재생 진단으로 원인을 좁혀야 함.

### P1 정답 저장을 생략하는 것 외에 원본 은행도 재생성해야 함

새로 집계한 결과 원본 기록 테이블에는 과거 질문의 대본 정답으로 만든 예약 확인이 **S/M/L 각각 136행, 총 408행** 있음. 표현·길이 변형을 포함한 행 수임. S에서는 376행 중 136행이며, 408개의 독립 경험이 아님.

예: request 14의 열린 예약 정답을 `Recorded booking from request 14: ...`라는 확정 기록으로 바꾼 경우임. 원래 행동 대본에서는 타당함. 질문을 읽기 전용으로 바꾼 새 실험에서 그 기록까지 외부 확인 사건으로 가져오면 **가짜 확인 이력**이 됨.

이 출처의 후보 주석 772출현은 모두 irrelevant이며 필수 근거는 0임. 따라서 은행에서 분리할 수 있는 근거는 있으나, 현재 입력을 그대로 재사용해도 된다는 뜻은 아님. 새 버전에서 기록·후보 은행·관계 대상·최근 창·선택 ID·메시지 해시를 함께 다시 생성해야 함. C의 실제 이전 답은 자기 답변 이력으로만 남김.

### 범위 정정: Harrier 비교는 이번 측정의 필수 조건이 아님

초기 검토에서 학습 선택기의 검색 대비 우위를 검증하는 기준을 이번 데이터·누적/분리 평가에 필수로 적용했음. 현재 질문에는 과도한 요구였으며 사용자 지적을 반영해 정정함. 이번에는 주 모델과 기억 전달 정책을 고정한 채 세션 구성과 제공/보류의 차이를 측정함.

기본 Harrier 비교는 이후 학습 선택기가 기본 검색보다 낫다는 주장을 별도로 검증할 때 의미가 있음. 과거 외부 평가의 기본 Harrier 결과는 유지하지만, 현재 실행의 선행 조건이나 새 필수 비교군으로 두지 않음.
### P1 이미 알려진 예산·선택기 입력 문제는 여전히 구현에서 남아 있음

[새 패킷 검토](2026-11-12-hidden-memory-traps-pilot-review.md)의 예산 초과가 이번에도 재현됨. 2k의 254/552, 8k의 132/552가 실제 전달 블록에서 초과함. 안내를 고쳤어도 원본 입력·생성기가 고쳐진 것은 아님.

또한 다른 근거가 필요한 주석 20개, M/L의 미주석 후보 5,852출현, 작은 선택기의 최대 입력과 긴 은행의 차이는 남아 있음. 입력만으로 판단 가능한지·정보 부족인지·loss 마스킹인지 먼저 정해야 함. `needs_memory`를 UNKNOWN 여부가 아닌 효용 정답처럼 쓰지 않는 계약도 새 스키마에 반영해야 함.

## 3. 데이터 품질에서 추가로 확인한 점

### 전체 정확도는 거의 무관 판정만 해도 높음

92판단의 S 후보 주석은 2,786개임. irrelevant 2,609, needed 92, distractor 65, invalid 20임. 전부 irrelevant라고만 해도 **정확도 93.65%**, 필요한 기록 재현율은 **0%**임. 과거 숫자 판독 성과와 별개인 새 패킷의 구성 통계임.

평가 분포를 인위적으로 모두 균형화하기보다 실제 비율을 보존하면서 필요한 근거의 완전 확보·무효/다른 사람 기록 제공·유형별 재현율·출처별 지표를 함께 보고하는 편이 적절함. 후보 주석 수와 독립 경험 수를 구분함.

### 단순 위치 암기로 관계를 푸는 징후는 이번 진단에서 약했음

모든 S 입력에 요청 번호가 공개되어 있어, 세 가족으로 `(현재 요청 번호, 후보 기록 번호) → 관계` 조회표를 만들고 나머지 한 가족을 평가하는 교차 진단을 수행함.

- 전체 정확도 90.42%, 4유형 평균 재현율 25.97%, 필요한 기록 재현율 7.61%임.
- 필요한 기록 집합을 전부 맞힌 것은 10/92임.
- 마지막으로 보이는 기록 번호로 현재 번호를 추정해도 필요한 기록 재현율 5.43%·집합 정답 9/92임.

단순 위치 조회가 높은 관계 성적을 설명한다는 근거는 얻지 못함. 긍정적인 구성 점검이지만 이름·날짜·문장 틀과 위치를 결합한 다른 편법까지 배제한 결과는 아님. 네 가족만의 검사임.

## 4. 주장의 범위와 공유 준비

4파일럿과 본 후보 20가족은 stage1 노출 이력이 있음. 길이·표현·순서를 늘려도 새 독립 출처가 되지 않음. `new-b` 40가족의 내용·정답은 이번에도 열지 않음. 현재 누적/분리 실험은 모델의 예약 행동이 환경을 바꾸는 자율 에이전트 평가도 아니며, 2k 창+외부 은행의 성적을 대규모 전체 문맥 추론 성적으로 부르지 않음.

현재 여행 자료의 기억은 주로 과거에 확인한 사실과 상태 변경임. 실제 작업 실패에서 얻은 절차를 다른 문제에 재사용하는 경험 기억을 검증한 자료는 아님. 처음의 넓은 기억 득실 질문과는 연결되지만, 이번 기여는 **상태가 바뀌는 사실 기억의 선택과 제공 효과**로 한정해 설명하는 것이 적절함. 목표·진행·실패 이력 전체를 고려하는 범용 에이전트 메모리를 입증했다고 하지 않음.

사람의 눈가림 의미 주석은 아직 없음. Codex의 42문장·16판단 해석 일치와 코드 장부 일치는 각각 유용하지만 인간 의미 검토의 대체가 아님. 실제 효용 `null`을 보존한 것은 적절함.

현재 최신 증강·보완 데이터, 검토 코드와 여러 보고서는 아직 작업 트리의 미추적 파일임. 동료가 main의 새 clone만으로 이번 전체 검토를 재현할 수 있는 상태는 아님. 공유 전에는 필요한 코드·자료·부모 의존성·정확한 revision을 선별해 고정해야 함. 이번 검토에서는 관련 없는 변경을 묶어 커밋하거나 푸시하지 않음.

## 5. 결론과 다음 한 단계

연구 방향을 다시 바꾸기보다 **현재 비교의 입력·예산·결과 짝을 구현에서 고정하는 것이 우선**임. 모델 크기·새 손실·새 벤치를 추가할 시점은 아님.

1. 기존 정답 생성 기록을 제외한 새 조회형 패킷을 별도 버전으로 만들고, 실제 예산·접두부·정답·은행 일치를 확인함.
2. 스냅샷 기반 국소 득실과 세션 정책 효과를 다른 결과로 저장하는 실행기를 점검함.
3. 주 모델·기억 전달 정책을 고정한 뒤 같은 문제의 누적/분리 차이와 같은 상태의 제공/보류 득실을 분석함. 검색 모델·학습 모델의 비교는 별도 후속 질문으로 둠.

살릴 성과는 조건별 기억 득실의 검산, 통제된 관계 대조의 좁은 학습 효과, 그 둘을 구분해 평가하는 데이터 설계임. 새 누적/분리 비교의 성능과 선택기의 실용 우위는 앞으로 측정할 질문으로 남김.
