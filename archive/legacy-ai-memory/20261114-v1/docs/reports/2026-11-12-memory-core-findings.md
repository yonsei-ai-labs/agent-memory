# 기억의 득실: 현재 확보한 데이터·학습·측정 결과

2026-11-12. 기존 실험을 원 출력과 대조해 정리함. **현재 상황에 따라 같은 기억의 필요성이 달라지는 자료, 그 차이를 학습시키는 데이터 보강, 관계 판단과 실제 득실을 구분하는 측정 절차**를 이번 연구의 우선 성과로 묶음. 새 모델·벤치·상황을 추가하지 않고 이 범위에 집중함.

시작 질문은 “에이전트 메모리의 득과 실을 판단할 수 있는가?”였음. 지금 확보한 답은 **제한된 상황에서는 기억 제공 전후의 이득과 손해를 측정할 수 있고, 특정 선택 오류는 대조 자료를 보강하여 줄일 수 있음**임. 아래 관측·학습·실행 검증은 서로 다른 실험이며, 하나의 범용 선택기가 모든 결과를 얻은 것으로 설명하지 않음.

[재계산 코드와 원자료 연결](data/memory-core-findings-20261112-v1/README.md) · [수치 전체](data/memory-core-findings-20261112-v1/summary.json) · [대표 사례 5개](data/memory-core-findings-20261112-v1/examples.jsonl)

후속으로 승인한 [데이터 보강의 원인 분해](2026-11-12-augmentation-ablation.md)를 완료함. 아래는 최초 성과를 정리한 원래 결과이며, 후속 비교의 새 수치를 이 표에 소급하여 바꾸지 않음.

이어 [득실 자료의 정량 검증](2026-11-12-memory-effect-measurement-audit.md)에서 같은 목표·은행·제공 묶음을 연결한 12가족 중 7개가 현재 상태에 따라 이득→손해로 바뀜을 확인함. 관측 효과의 원 출력 검산과 일반적인 성공 확률·득실 예측의 차이, 채점 민감도와 실제 표본 단위를 함께 기록함.

## 1. 현재 남길 수 있는 세 가지 결과

| 결과 | 직접 확인한 근거 | 주장 범위 |
| --- | --- | --- |
| 현재 상태와 맞지 않는 기억이 실제로 해로울 수 있음 | 변경 전 계획의 기억 두 개를 추가하면, 무기억으로 맞던 12가족 중 7에서 답이 깨짐. 같은 실험에서 현재 관측을 반복한 30입력은 회귀 0건 | 생성한 여행 계획·명시적인 계획 변경 상태·고정 9B 작업자에서의 관측임 |
| 관계 대조를 보강하면 특정 선택 오류를 줄일 수 있음 | 새 12출처의 필드 복원에서 단순 추가 학습 67·71/96 → 보강 학습 87·86/96. 각 seed에서 개선 20·15건, 새 악화 0건 | 필요한 정보가 남은 기록을 통째로 보류하던 오류의 개선임. 전체 제공·검색은 88/96 |
| 선택 점수·답변·실제 행동을 분리하면 실패 원인을 더 구체적으로 볼 수 있음 | 필요한 기록을 줬는지, 채점 규칙에 맞게 답했는지, 도구가 올바른 상태를 만들었는지를 각각 저장함. 실제 업무에서는 언어 채점 통과와 중복 교환의 DB 실패가 동시에 관측됨 | 데이터·측정 절차와 진단 사례의 성과임. 새 벤치에서 학습 선택기의 우위를 보인 결과는 아님 |

독립 출처의 수와 현재 기준선 격차는 계속 보고함. 데이터·측정 방법의 기여 후보는 상황 대조의 타당성, 원문 근거, 재현 가능성으로 설명하고, 학습 선택기의 추가 가치는 별도의 비교 주장으로 둠. 선행연구 대비 새로움이나 출판 가능성이 이번 재집계만으로 확정되는 것은 아님.

## 2. 상황별 손해: 관련 있어 보이는 과거 계획을 잘못 재적용함

현재 필요한 답이 관측에 이미 있는 상태를 사용함. 무기억 조건은 해당 상태를 모두 맞혔음. 과거 계획과 현재 상태의 관계를 나누어 추가 기억의 영향을 확인함.

| 추가한 기억 | 관측된 손해 | 집계 단위 |
| --- | ---: | --- |
| 변경 전 계획의 기록 2개 | 7/12 | 파일럿 6가족의 4건 + 새 확인 6가족의 3건 |
| 변경 전 기록 1개 + 현재 관측의 반복 1개 | 4/12 | 같은 12가족, 파일럿·확인 각 2건 |
| 현재 관측에 있는 내용을 반복 | 0/30 | 두 상태 유형의 서로 다른 `(상태, 작업자 입력)` 30개 |
| 다른 사람의 무관한 기록 | 0/12 | 항목 확인 유형의 12가족 |

30입력은 30개의 독립 경험이 아님. 마지막 두 행은 앞의 두 행과 모두 같은 상태·같은 길이를 맞춘 대조가 아니므로, 표의 비율 차이를 기억 종류만의 인과 효과로 해석하지 않음. 기억 종류를 세분한 분석은 사후 분석이며, 반대 상태 기억 제공 조건 자체는 사전 설계에 있었음. 7/12도 일반적인 메모리 손해율이 아님.

**대표 사례 — 실패한 첫 계획으로 돌아감.** 현재 요청은 “Clara의 3일차 계획으로 시작하되, 첫 결제가 실패했으면 Alice의 1일차 계획을 사용”임. 현재 도구 보고는 첫 시도 실패이며, 관측에는 Alice의 식당 `R8278`과 숙소 `H195`가 이미 있음.

| 제공 조건 | 작업자의 실제 출력 | 판정 |
| --- | --- | --- |
| 무기억 | `R8278`, `H195` | 맞음 |
| 과거 숙소 + 현재 숙소 반복 | `R8278`, `H1917` | 숙소를 과거 계획으로 되돌림 |
| 과거 식당·숙소 | `R3754`, `H1917` | 두 항목 모두 과거 계획으로 되돌림 |

이 사례는 기억의 사실 자체가 거짓이어서 발생한 문제가 아님. 과거에는 맞던 계획을 현재 실패 상태에도 재사용한 문제임. 상태 학습 모델은 이 사례에서 제공을 보류하고 정답을 유지했으나, 이 한 사례로 모델의 일반적인 손해 예방률을 주장하지 않음.

같은 상태 입력을 읽히는 별도 비교에서는 기존 판독기의 필요 기억 집합 일치가 3/36, 상태 대조로 학습한 모델은 두 seed 모두 36/36이었음. 규칙도 36/36이므로 명시적 상태 관계의 학습 가능성을 확인한 결과임. 목표만 입력한 모델과 상태까지 입력한 모델의 차이를 순수한 학습 효과로 계산하지 않음.

근거: [독립 재집계 노트](2026-11-11-reportable-insights-note.md), [동일 입력 검증](2026-11-11-memory-selector-regression.md). 출처 ID·원 기억·선택·원 출력은 이번 사례 파일의 `plan_replaced`에 있음.

## 3. 데이터 보강: 이미 아는 내용과 아직 필요한 내용을 구분함

기존 모델은 한 기록에 사실 두 개가 있을 때, 하나를 이미 안다는 이유로 기록 전체를 버리는 오류가 있었음. 같은 원문의 사실 두 개를 분리해서 제시하는 상태와 한 기록에 함께 제시하는 상태를 대조하여 추가 학습함. 제공할 때는 기록 전체를 그대로 전달함.

| 조건 | 학습 자료 | 고정한 조건 |
| --- | --- | --- |
| 단순 추가 학습 | 같은 상태의 분리 기록을 두 번 제시 | seed별 시작 가중치, 원문·요청·현재 관측, 400상태 항목, 200업데이트 |
| 보강 학습 | 같은 상태의 분리 기록과 복합 기록을 한 번씩 제시 | 위와 같음 |

Harrier 0.6B의 기존 LoRA와 필요성 판독층을 계속 학습함. 구조·새 손실함수의 효과를 주장하는 실험이 아님. 학습 전체는 30출처 그룹이며 고유 입력은 235개와 395개로 다름. 기록 길이·후보 쌍 수·계산량까지 같았다고 주장하지 않음.

새 평가 출처는 12개이며, 관계 평가는 384상태, 고정 4B 작업자의 필드 복원은 그중 복합 기록·새 관측 표현의 96상태임. 384상태는 같은 출처에 대한 8상태 × 2기록 구성 × 2표현으로, 독립 경험 수는 12출처임.

| 방법 | seed 731: 필요 복합 기록 보존 / 48 | seed 1729: 보존 / 48 | seed 731: 필드 복원 / 96 | seed 1729: 복원 / 96 |
| --- | ---: | ---: | ---: | ---: |
| 이전 모델 | 19 | 18 | 58 | 60 |
| 단순 추가 학습 | 25 | 30 | 67 | 71 |
| 보강 학습 | 48 | 44 | 87 | 86 |
| 전체 제공 / BM25 상위 2개 | 모두 제공 | 모두 제공 | 88 | 88 |

48은 두 표현을 포함한 부분 관측 조건이고, 96은 한 표현의 전체 상태 조건이므로 서로 같은 평가 분모가 아님. 두 seed가 같은 작업자 입력을 고르면 같은 저장 출력을 공유함. 17정책의 1,632결정은 1,632회의 독립 작업자 실행이 아니며, 실제 서로 다른 본 입력은 192개임.

**대표 사례 — Ubuntu는 알지만 서버 크기는 아직 모름.** 현재 관측은 `server template is Ubuntu`이고 필요한 답은 템플릿과 설정 크기 두 가지임. 과거 기록은 `the Ubuntu template`와 `with a medium configuration`을 함께 담고 있음.

| 방법 | 기록 선택 | 실제 출력 |
| --- | --- | --- |
| 두 seed의 단순 추가 학습 | 보류 | `{"field_1":"Ubuntu","field_2":null}` |
| 두 seed의 보강 학습 | 기록 전체 제공 | `{"field_1":"Ubuntu","field_2":"medium"}` |

두 seed에서 동시에 고친 15상태 중 ID 순 첫 사례임. 예시 선택은 사후이며, 위 전체 성적은 모든 대상 상태를 포함함. 보강 학습의 이득은 새 테스트 출처에서 관측됐지만, **복합 조건의 은행에는 기록 1개, 분리 조건에는 2개뿐**임. 많은 후보를 순위화하는 능력보다 제공·보류 관계를 학습한 결과로 설명하는 것이 정확함.

보강 모델의 평균 기억 토큰은 전체 제공보다 약 34–35% 적었으나 전체 입력 감소는 약 3%였고 시간 개선은 확인되지 않음. 이전 BEAM 자료의 과잉 제공·회귀도 남았음. 따라서 이번의 긍정적 주장은 “특정 판단을 위한 대조 자료 설계가 효과가 있었다”임. 현재 모델을 범용 검색기의 대체품으로 제안하지 않음.

**채점도 분리해서 봄.** 원래 채점에서 전체 제공 88/96이더라도 남은 8건을 모두 추론 실패로 부르면 안 됨. 예를 들어 정답 `vegetarian`에 `vegetarian diet`를 출력한 경우 원래 고정 규칙은 실패로 처리함. 표현 동등성의 사후 검토 6건은 원래 성적과 따로 보존했으며, 유리한 숫자로 교체하지 않음. 사례 파일의 `complete_evidence_failure`가 이 채점 경계의 예임.

근거: [데이터 보강 실험](2026-11-12-partial-record-learning.md), [출처·학습 자료 명세](../../datasets/memory_partial_records/20261111-v1/README.md). 이 학습 결과를 앞 절의 여행 기억 손해 7/12가 감소했다는 증거로 이어 붙이지 않음.

## 4. 측정 방법: 필요한 기억과 실제 득실을 연결하되 합치지 않음

재사용할 데이터 단위는 **과거 경험의 근거 + 판단 시점의 현재 상태 + 전달한 기억 묶음 + 작업자의 결과**임. 기억 하나의 고정적인 “좋음/나쁨”으로 환원하지 않음.

| 층 | 보존할 내용 | 확인하는 질문 |
| --- | --- | --- |
| 관계 주석 | 현재 목표·관측, 출처 구절, 적용 조건, 이미 아는 정보, 남은 요구, 충분한 기억 집합 | 현재 이 기록을 줄 이유가 있는가? |
| 선택 결과 | 후보 은행, 실제 선택 ID, 보류, 전달 토큰, 선택 시점 | 필요한 정보가 전달됐는가? |
| 작업 결과 | 원 입력·출력, 답변 채점, 도구 호출, 상태 변화, 미완료 | 실제 작업이 나아졌거나 나빠졌는가? |
| 비교·비용 | 동일 작업자·상태의 기준 정책 결과, 개선·악화 각각의 수, 선택기와 작업자의 비용 | 얻은 성공과 줄인 실패가 얼마의 비용을 요구했는가? |

이진 성공을 쓰는 경우, 같은 상태에서 `기준 실패 → 제공 성공`은 관측 이득, `기준 성공 → 제공 실패`는 관측 손해로 집계함. 둘 다 성공·둘 다 실패도 따로 남김. 한 번의 실행은 성공 확률이나 기억의 일반적 인과 효과가 아니며, 기준 정책·작업자·시점이 달라지면 별도 비교임. 원문으로 붙인 관계 라벨을 작업자 실패만으로 유해 라벨로 바꾸지 않음.

STATE-Bench 개발 8과제의 기존 파일럿은 이 측정을 실제 행동까지 연결한 예임. 고정 Harrier 검색을 사용했으며 새 선택기 학습은 없었음.

| 전달 정책 | 전체 성공 / 8 | 도구 한도 미완료 | 언어 과제 요건 통과 | 실제 상태 요건 통과 |
| --- | ---: | ---: | ---: | ---: |
| 무기억 | 5 | 2 | 5 | 5 |
| 요청 기반 검색 | 6 | 1 | 7 | 6 |
| 요청+관측 검색 | 5 | 1 | 6 | 5 |

미완료는 전체 성공에서 실패로 포함하고, 실행하지 못한 최종 요건 채점은 `null`로 둠. 요건 통과 수의 대상은 끝까지 채점한 6·7·7실행이며, 미완료에 가상의 판정을 넣지 않음. 토큰 상한은 있었지만 이번 파일럿에서는 차지 않았음.

**행동 개선 사례.** 예산 $100에 실제 상품이 $110인 상황에서 무기억은 프로모션 조회를 반복하다 도구 한도에 도달함. 두 기억 조건은 초과 금액을 설명하고 사용자의 구매 거절을 받아 완료함. 제공 기억 3개 중 어느 하나의 효과인지, 반복 실행에서도 유지되는지는 분리되지 않았음.

**행동 악화 사례.** 관측 기반 검색 조건은 교환을 완료한 뒤 같은 턴에서 재확정을 시도하고, 거부되자 다시 미리보기·확정을 수행함. 교환 상품 `ITEM-10214`와 `ITEM-10215`가 둘 다 생겼음. 언어 채점은 통과했으나 DB 상태는 실패함. 선택기는 사용자 턴마다만 동작하여 이 도구 루프 중 재판단 기회가 없었고, 선택 기억이 중복 실행의 원인이었다고 확정할 수 없음.

이 사례들이 보여주는 측정상의 성과는 “선택이 맞았나”와 “작업자가 실제로 무엇을 바꿨나”를 함께 추적할 수 있다는 점임. 8과제 한 번의 관측에서 상태 입력·학습 모델의 우위를 추정하지 않음. [기존 파일럿과 전체 한계](2026-11-12-statebench-experience-pilot.md)를 보존함.

## 5. 이번 검산의 범위와 고정할 초점

- 여행 실험은 기존 독립 파서로 원 출력을 다시 읽고, 중복 입력을 제거하여 상황별 손해와 동일 입력 비교를 재집계함.
- 데이터 보강 실험은 원 데이터와 압축본의 일치, 메시지 해시, 192개 원 출력과 1,632정책 결정의 원래 고정 채점, 두 seed의 개선·악화 수를 재계산함. 저장된 확률의 0.5 기준으로 여섯 모델의 관계 집계도 대조함. 새 encoder 순전파·독립 재주석은 아님.
- STATE-Bench는 최종 24실행의 저장된 요건 판정에서 완료를 다시 계산하고 사례 궤적의 해시를 대조함. 이번에 도구 167개를 새로 실행한 것은 아니며, 그 재실행 검증은 링크한 기존 공유본 검증 결과임. LLM 채점도 새로 호출하지 않음.

현재 주석은 대부분 구축 에이전트의 검토이며 독립 다중 주석이 아님. 대표 사례는 설명을 위한 사후 선택이고, 수치표는 각 실험의 정해진 전체 대상과 기준선을 유지함. 실험별 출처·작업자·라벨의 차이를 보존하며 결과를 합산한 하나의 정확도를 만들지 않음.

**이제 집중할 산출물은 이 세 가지 결과와 그 근거 묶음임.** 기억 일부를 가공하는 연구를 필수 목표로 삼지 않음. 특정 업무·상황 안에서 성과를 설명할 수 있으며, 이전 문서의 새 상황 후보는 보류함. 새로운 모델·벤치 확장과 추가 GPU/API 실행은 이번 범위에 포함하지 않음.

동료에게 전달할 중심 문장: **“현재 상황과 과거 기억의 관계를 통제한 데이터로 기억의 득실을 측정하고, 그 관계를 구분하는 데이터 보강이 특정 선택 오류와 후속 작업을 개선함을 확인했음. 관계 판단·실제 행동·비용을 분리해 검증하는 자료와 절차를 함께 제공함.”**
