# 복습 자료 교체와 제한된 기억 예산의 효과

2026-11-12. 4회 추가 학습, 기존 자료 회귀·새 출처 평가, 동일 작업자의 예산별 효과 측정과 저장 결과 검산을 완료함.

이번 질문은 “이전에 얻은 복합 기억 보존 능력을 유지하면서, 지금 필요하지 않은 기록의 과잉 제공을 줄일 수 있는가”임. 이전 모델을 유지한 기준, 같은 자료로 더 학습한 control, 복습 자료를 교체한 replay를 두 seed에서 비교함. 현재까지는 **BEAM 과잉 제공 감소와 기존 복합 기억 보존이라는 성과가 있으나, 새 출처의 근거 누락과 다른 자료의 회귀가 있어 전면 교체 조건은 충족하지 못함.**

## 비교한 내용

이전 augmented checkpoint에서 Harrier 0.6B의 rank-8 q/v LoRA와 같은 판독층을 이어 학습함. 구조·학습률·손실 가중치 산정법·200업데이트·마지막 checkpoint·제공 임계값 0.5를 고정함. 원래 320개 핵심 대조를 유지하고 복습 80상태만 바꿈.

| 항목 | control | replay |
|---|---:|---:|
| 학습 상태 항목 | 400 | 400 |
| 목표 출처 그룹 | 30 | 37 |
| 후보 은행까지 포함한 출처 그룹 | 30 | 67 |
| 감독 후보 쌍 | 716 | 1,166 |
| 고유 감독 입력 | 699 | 1,166 |
| epoch당 비패딩 토큰 | 68,204 | 149,661 |

Replay는 BEAM train 13질문과 Mem2Act train 7질문에 `미확인 / 이미 확인 / 다른 정보 관측 / 조회 실패`를 구성함. 단순 주제 일치와 현재 요청에 필요한 속성을 구분하는 후보를 포함함. 기존 갱신 상태는 시도·완료 해석 문제가 있어 학습에서 제외하고 명시적인 조회 실패로 대체함. 거의 같은 좌표와 은유적인 회사명 언급 2후보는 불확실한 6개 감독 쌍을 가림. 부모 자료는 수정하지 않음.

양·음성의 학습 전체 손실 질량은 각각 0.5로 맞춤. 복습의 출처·문장 길이·후보 수가 함께 바뀌므로 어느 요소만의 효과인지는 분리하지 못함. 실제 비패딩 입력량은 약 2.2배, 패딩을 포함한 학습 토큰 위치 수는 약 2.4배임. 같은 연산량에서의 비교가 아님.

새 평가는 미사용 예약 출처 12개 × 10상태 × atomic/compound = 240상태임. 동일 출처의 변형을 독립 경험으로 세지 않음. 문자 위치·역할·정답·허용 표현은 새 모델 출력 전에 고정함. 학습과 평가의 원래 출처 및 완전 동일 입력 겹침은 없음. 이전 복합 기억 시험 집합과 나머지 개발 자료는 회귀 검사로 명시함.

## 사례로 해석하기

같은 운동화 주제라도 연간 예산을 묻는 질문에 착용감·일반 가격 조언을 주는 기록은 필수 근거가 아님. Replay는 이런 같은 주제의 다른 속성을 덜 제공하도록 바뀜. 이 개선은 기존 목표와 맞는 성과임.

반대로 “아까 물어본 암호화폐의 현재 가격”이라는 요청에는, 과거의 Bitcoin 언급이 조회 대상을 정하는 데 도움을 줄 수 있음. 이 양성 기억의 seed 731 제공 확률은 0.966→0.012로 낮아짐. 현재 가격 자체가 없는 기록도 현재 작업의 인수나 중간 판단을 도울 수 있다는 경계를 더 보강해야 함. 이는 사례에 근거한 해석이며 학습 내부의 원인을 입증한 것은 아님.

새 출처의 Unicode 속성 표현 기록은 모든 비교 모델에서 낮게 평가됨. 원문에서 잘라 낸 표현과 요청의 역할을 연결하지 못한 사례임. 낯선 표현, 잘라 낸 문맥, 관계 학습 중 무엇이 원인인지는 이 실행만으로 분리하지 못함. 해당 자료와 점수를 사후에 삭제하거나 바꾸지 않음.

## 동일 작업자와 예산의 평가

작업자는 동일 revision의 Qwen3.5-4B, greedy·비추론 모드로 고정함. 새 출처는 사전 지정 compound 120상태의 필드 복원이며, BEAM은 기존 개발 52상태 전체에서 128·512토큰을 비교함. 실제 외부 도구를 실행하는 에이전트 성공률과는 구분함.

BEAM의 원래 7–8개 기록은 355–767토큰이며 검토된 필요 근거는 최대 84토큰임. 원문을 늘리거나 새 방해 기록을 붙이지 않음. 상위 2개 BM25·기본 Harrier·기존 검색 adapter·관측 중복 제거 규칙·예산 채우기·검토된 근거 진단을 같은 상한에서 비교함. 전체 기록은 512토큰에도 항상 들어가지는 않으므로 `budget_fill`을 무제한 전체 제공으로 부르지 않음.

새 출처의 근거 있는 필드 복원 결과는 다음과 같음. 모든 조건에서 출력 형식은 120/120 유효함.

| 정책 | 근거 완전 확보 /120 | 근거 있는 성공 /120 |
|---|---:|---:|
| 무기억 | 36 | 36 |
| 전체 제공 = 검색 상위 2개 | 120 | 108 |
| 중복 제거 규칙 | 120 | 108 |
| 검토된 필요 근거 진단 | 120 | 108 |
| 이전 고정 모델 | 114 / 113 | 105 / 104 |
| control | 113 / 115 | 104 / 106 |
| replay | 112 / 110 | 102 / 101 |

새 출처에서는 replay의 성공이 이전보다 각각 3개 감소함. 이 자료의 작은 은행은 모두 예산에 들어가므로, 전체 제공과 검색의 성공이 같다는 것을 검색 경쟁에서의 성과로 해석하지 않음.

전체 근거를 줘도 실패한 12개 출력은 모두 필요한 필드에 `null`을 반환했으며, 과거 실험에서 발견한 명사구 채점 차이와는 다른 실패임. 이 중 9개는 조회 실패 조건임. 같은 목표·기억을 유지하고 실패 관측을 추가한 쌍에서는 `미관측→첫 조회 실패`가 12→9/12, `첫 값 확인→두 번째 조회 실패`가 12→6/12로 낮아짐. 작업자가 조회 실패 문장을 어떻게 활용하는지도 실제 효과를 제한함. 내부 판단 원인을 입증한 것은 아니며, 이 결과를 이유로 기억의 관계 라벨을 음성으로 바꾸지 않음.

BEAM의 **근거 있는 성공 /52**는 다음과 같음. 현재 관측에 수치가 있어 우연히 답을 맞혔더라도 필요한 대상·기간 맥락이 빠진 경우는 성공으로 세지 않음. 원래 수치 일치 점수도 결과 JSON에 별도로 남김.

| 정책 | 128토큰 | 512토큰 |
|---|---:|---:|
| 무기억 | 22 | 22 |
| BM25 상위 2개 | 38 | 40 |
| 관측 중복 제거 규칙 | 38 | 40 |
| 기본 Harrier 임베딩 상위 2개 | **44** | 45 |
| 이전 검색 adapter 상위 2개 | 43 | 44 |
| 예산 채우기 | 39 | **47** |
| 검토된 필요 근거 진단 | 44 | 44 |
| 같은 과거 근거를 항상 제공하는 진단 | 44 | 44 |
| 이전 고정 선택기 | 33 / 31 | 44 / 43 |
| control | 34 / 36 | 41 / 44 |
| replay | **38 / 39** | **41 / 43** |

128토큰에서 replay는 이전 선택기보다 8개선·3악화, 10개선·2악화임. Control 대비는 6개선·2악화, 5개선·2악화임. 따라서 제한된 예산에서 과잉 제공을 줄이는 학습이 실제 답변에도 이득이 된 조건을 확인함. 그러나 기본 임베딩 검색의 44/52보다 낮아 학습 선택기의 우위를 입증하지 못함. 이 결과는 이전에 본 12출처 개발 진단임. 출처별 재표집 구간을 저장했으나 적은 출처·여러 비교를 감안한 설명용 구간이며 확증적 유의성 판단에 사용하지 않음.

512토큰에서는 이전 대비 2개선·5악화, 4개선·4악화임. 총점이 같은 두 번째 seed에도 성공을 깨뜨린 사례가 있음. 예산에 따라 선택 개선의 이득과 근거 누락의 비용이 달라짐.

메모리 자체의 득실도 분리함. 512토큰 예산 채우기는 무기억 대비 **26개선·1악화**임. 현재 관측에 최근 초과근무가 12시간이라고 명시된 사례에서, 무기억은 `12`, 추가 기록을 받은 조건은 `0`을 출력함. 해당 사례와 입력을 보존하며 단 한 번의 결정적 생성 결과를 일반적 손해 확률로 확대하지 않음. 같은 예산에서 replay의 무기억 대비 득실은 19개선·0악화, 21개선·0악화임.

검토된 근거만 제공한 진단은 44/52인데 예산 채우기는 47/52임. 비필수로 주석한 추가 문맥이 작업자에게 도움이 될 수도 있으므로, 필요 근거 주석과 실제 이득을 같은 정답으로 합치지 않음. 정답 근거 진단은 작업자의 성능 상한이 아님.

## 비용과 다음 판단

128토큰에서 replay의 평균 전달량은 40.1·46.1토큰이며 이전의 89.8·84.1토큰보다 약 45–55% 적음. 기본 임베딩 검색은 107.4토큰임. 512토큰에서는 이전 296.3·275.2→62.2·71.8토큰으로 줄지만, 성공은 감소하거나 같음. 새 출처에서도 전달량은 줄었으나 성공 3개씩을 잃었으므로 토큰 절감을 그대로 효율 개선으로 주장하지 않음.

선택기의 batch-4 추론 시간을 나누어 포함한 128토큰의 평균 시간은 이전 두 seed 모두 약 0.74초, replay 약 0.72–0.74초임. 일관된 지연 개선은 확인하지 못함. 이는 순차 작업자 생성·중복 입력 재사용과 batch 단위 판독의 측정이며 온라인 서비스 지연이나 모든 검색 기준선의 전체 비용을 재현한 벤치마크가 아님.

이번 replay 모델을 기본 모델로 교체하지 않음. 보존할 성과는 **같은 주제의 비필수 정보를 덜 보내는 학습이 작은 예산에서 실제 성공을 개선할 수 있다는 점**, 그리고 **같은 개선이 다른 자료·큰 예산에서는 손해가 될 수 있음을 함께 측정한 절차**임.

후속 보완은 이미 확보한 train 자료에서 직접 답을 담은 기억뿐 아니라 조회 대상·작업 인수·선호처럼 중간 판단을 돕는 양성을 다시 포함하는 것이 우선임. 새로운 구조나 손실을 동시에 늘리기보다 같은 학습량에서 이 양성 범위의 보존을 확인하는 편이 적절함. 이번 새 평가 12출처는 이제 결과를 본 자료이므로 후속 조정의 새 확인 자료로 재사용하지 않음. 조회 실패를 추가했을 때 작업자가 기존 근거를 활용하지 못하는 문제도 별도 점검 대상으로 남김.

## 검산과 보존

저장된 19,016개 후보 예측을 실제 임베딩과 판독층으로 다시 계산함. 이전 고정 모델의 과거 예측과 차이는 0이며, 네 학습 모두 112개 LoRA tensor가 변함. 감독 쌍은 모두 두 번씩 사용됐고 미확인 6쌍은 학습에 들어가지 않음. 각 optimizer의 116개 parameter state가 모두 200 step이며 저장 모멘트는 유한함. 원래 checkpoint·자료 해시를 보존함.

작업자 입력은 새 출처 240개·BEAM 450개를 실제 실행하고, 2,776개 정책 결정에 연결함. 별도 반복 6개는 모두 같은 출력을 냈고 출력 한도에 걸린 사례는 없음. 관련 테스트 31개를 통과함. 220파일을 8개 압축 파일로 나눈 뒤 해시·저장 판독·작업자 채점을 다시 실행해 동일 결과를 확인함. 합계 약 101.9MiB이며 실제 모델의 기본 가중치와 optimizer pickle은 공유 압축에 넣지 않음.

로컬 학습·판독과 두 작업자 프로세스의 측정 시간 합계는 약 35.9분이며 데이터 검토·문서·CPU 검산 시간은 제외됨. 모든 GPU 실행이 종료됐고 활성 계산 프로세스 0개를 확인함. 유료 API·Colab 할당은 없음.

BEAM 개발은 이미 본 자료이고 확인 27출처는 미실행 상태를 유지함. 현재 결과로 새 도메인 전이·전체 에이전트 효용·학습 선택기의 일반적 우위를 주장하지 않음.
