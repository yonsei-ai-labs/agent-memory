# 대조 자료와 선택 손실 보완: 2026-11-10 오전 점검

**손실 보완은 분류를 소폭 개선했지만 실제 선택의 일관된 이득은 확인되지 않았음.** 원래 자료의 12회 학습·가중치 재실행·평가를 완료함. 대조 자료는 원문 검수와 실행 준비까지 마쳤으나 작업자 재현 검사에서 중단돼 새 효용 라벨과 보강 자료 학습은 **0건**임. 계획한 2×2 전체가 완료된 결과가 아님.

연구 목표는 기억의 조건부 득실을 예측하고 실제 제공/보류에 연결하는 것임. 아래 비교는 새 대조 출력을 수집하기 전에 고정했으며 새 모델·도메인·손실 종류로 범위를 넓히지 않았음.

## 이번에 바꾸는 두 가지

| 학습 자료 | 기존 네 범주 분류 | 분류 + 관측 선택 손실 |
| --- | --- | --- |
| 원래 237묶음 | 기준 | 손실 효과 |
| 원래 자료 + 검증한 대조 묶음 | 자료 효과 | 두 보완의 결합 |

현재 상태+목표+제안 묶음을 읽는 Harrier 0.6B, LoRA/MLP 구조·초기값 2개·기존 3 family fold·8 epoch·제공 경계 0을 유지함. 손실은 기존 네 범주 CE에 같은 상태의 관측 선택 후회를 더함. `λ=1`, softmax 온도 `τ=0.5`, 개선/악화 대칭 효용을 결과 확인 전에 고정함. 정확한 값은 [config](../../training/memory_selector/configs/memory-contrast-loss-v1.json)에 있음.

선택 손실 때문에 같은 상태의 후보를 묶어 학습해야 하므로 **기존 분류 대조도 같은 상태 배치로 다시 학습함**. 이전 무작위 행 배치의 점수와 새 손실의 점수만 직접 비교하지 않음. 4상태/update, epoch마다 모든 학습 상태·해당 후보를 한 번씩 사용함. 상태별 CE를 먼저 평균해 후보 수가 많은 상태의 학습 비중을 키우지 않음. 네 조건의 상태 노출·optimizer step은 같으나, 자료 보완 조건은 더 많은 후보·토큰을 처리하므로 동일 계산량이라고 부르지 않음.

상태 `s`의 후보 `a`마다 관측 효과를 `u(a)=성공(s,a)-성공(s,무기억)`으로 두고, 무기억은 `u(∅)=0`으로 둠. 모델 점수는 `z(a)=P(개선)-P(악화)`, `z(∅)=0`임. 다음을 최소화함.

```text
q(a) = softmax(z(a) / 0.5)
L_select = Σ_a q(a) × [max_b u(b) - u(a)]
L = 상태 안의 평균 네 범주 CE + λ × L_select
```

결과가 같은 후보들에 임의의 순서를 요구하지 않으며, 무기억까지 포함해 모두 같은 결과면 선택 손실은 0임. 실행하지 않은 조합은 손실에 넣지 않음. 시험 시에는 softmax 표본 추출 대신 `z`가 가장 크고 0보다 큰 후보를 제공하고, 그 외에는 보류함. 분류 확률을 이용한 점수는 이 작은 개발 자료에서 교정된 인과 확률이라는 의미가 아님. 토큰 비용의 손실 가중치는 이번 비교에서는 0이며, 비용은 평가에 별도로 보고함. 따라서 이 목적함수 자체가 성공·시간·비용을 모두 최적화한다고 해석하지 않음.

## 대조 자료의 조건

이미 생성·보존한 과거 기록에서 같은 주제이지만 사람 또는 날짜 하나가 다른 실제 기록을 찾음. 목표가 가격 비교이면 과거 가격도 다른 기록을 사용함. 기록의 사실이나 문장을 새로 만들지 않음. 기록별 토큰 차이 8 이내, 각 묶음 2기록, 동일 512토큰 상한으로 통제함.

각 요청에서 식사·숙소 각각의 참조 기록/가까운 다른 기록을 교차해 네 묶음을 만들고, 필요한 정보가 현재에 없음/현재에 이미 있음/현재 가용성 변경의 세 상태에 연결함. 조건에 맞는 19요청·11기존 가족에서 228행을 만들고 171개 새 고유 worker 입력의 실행 계획을 고정함. 5개 요청의 제외 이유는 결과를 보기 전에 기록함. 기존 12가족의 전체 평가 상태는 제외하지 않음.

관계상 다른 기록이라는 사실을 곧바로 유해 라벨로 바꾸지 않음. 동일 Qwen3.5-9B revision·실제 weight 해시·원래 지침·greedy 설정에서 새 묶음의 결과를 측정함. 기존 프롬프트 네 개를 다시 실행해 입력·출력 토큰 일치를 확인한 뒤에만 저장 결과와 병합함. 달라지면 비교 가능한 자료를 확보하기 전 병합하지 않음.

이 작업은 **기존 12가족 안의 실제 기억 제공 대조를 보완하는 것**이며 독립 경험의 수를 늘리지 않음. 새 원천 전이는 이번 파일럿의 결론으로 주장하지 않음. 후보 수·길이 편법이 모두 사라졌다고도 주장하지 않으며 기록 길이 차이·대조 형태를 별도로 집계함.

38개 기록쌍의 목표·원문을 모두 확인함. 다른 사람/날짜의 기록은 같은 후보 은행 안의 실제 과거 출력이며, 현재 판단보다 앞선 round의 기록임. 다만 다음 한계는 유지됨.

검토 근거: [38개 원문 대조표](data/memory-contrast-loss-20261110/record-review.csv), [사전 제외 목록](data/memory-contrast-loss-20261110/excluded-cases.json), [고정 설계](data/memory-contrast-loss-20261110/contrast-protocol.json), [설정·마감 해시](data/memory-contrast-loss-20261110/pre-outcome-freeze.json).

- 바뀌는 신원 조건은 하나이나, 별개 기록을 사용하므로 장소·가격·평점·속성도 다를 수 있음. 문장 한 요소만 바꾼 완전한 인과 대조라고 부르지 않음.
- 원래 카탈로그에는 다른 지역을 암시하는 숙소명이 포함됨. 주어진 표 안에서 판단하는 통제 과제이며 실제 여행지 지식의 정확성을 측정하지 않음.
- 과거 출력이 저장됐다는 사실과 과거 여행 계획이 성공했다는 사실은 구분함. 성공한 경험만 모은 자료라는 라벨을 붙이지 않음.
- 현재 조건 세 가지를 반복하는 자료임. 실제 연속 수행의 진행·실패 이력이 새로 생긴 것은 아님.

선택기는 모든 기억 조합을 탐색하는 것이 아니라 **실제로 작업 결과를 측정한 후보 묶음** 중 하나를 고르는 구조임. Qwen 9B는 그 묶음을 받은 작업자이며 학습하지 않음. 현재 검증은 전체 MemoryArena 환경의 종단 실행 점수가 아닌, 저장 상태의 두 선택 응답을 사용하는 통제 실험임. 새 묶음만의 분류 점수도 따로 보고해, 쉬운 중립 사례가 늘어 전체 정확도만 올라가는 현상을 구분함. 정답 선택과 입력 근거에 맞는 선택 역시 별도로 집계함.

## 판정 순서와 중단 기준

1. 원문 연결·기록 전제·가족 분할·길이 통제·worker 재현·정답 SQL 검산을 먼저 통과시킴. 실패한 단계를 완료로 간주하지 않음.
2. 선택 손실의 도움이 되는 기억/손해 기억/동일 결과/보류에 대한 기울기를 검사함. 미측정 결과와 모순된 네 범주 라벨을 거부함.
3. 네 조건에서 같은 평가 후보 집합을 사용함. 원래 후보 집합 성적과 대조를 포함한 확장 후보 성적을 각각 보고함. 학습·평가 가족은 분리하며 추가 기억 조합도 부모 가족을 따름.
4. 분류·득실 오차 외에 관측 최선 행동 대비 손실, 실제 성공, 무기억 대비 개선·악화, 보류·근거 오류·비용을 확인함. 분류만 좋아지면 선택 개선으로 판정하지 않음.
5. 초기값별 결과와 가족별 변화를 보존함. 작은 차이나 한 가족에 집중된 효과는 탐색적 신호로 남김. 현재 자료의 결과에 맞춰 손실 가중치·온도·임계값을 반복 변경하지 않음.

Colab L4/A100/L4/L4/L4 할당 요청 다섯 번이 실패함. 마지막 재시도도 할당 단계에서 시간 초과됐음. 로컬 BF16 CPU offload 대안에서는 모델·revision·프롬프트·greedy 설정을 유지함. PyTorch `2.14.1+cu130`, Transformers `5.22.2`, Tokenizers `0.23.3`, Accelerate `1.13.0`, NumPy `2.4.6`도 원래 실행과 맞췄음. GPU와 offload 경로는 다르므로 같은 모델이라는 이유만으로 출력을 동일하다고 간주하지 않음.

**재현 기준을 한 번 수정했으며 이를 결과 해석에서 숨기지 않음.** 사전에 고정한 네 반복은 입력·출력 토큰까지 일치했으나, 추가 검사 25번째에서 숙소 선택이 `H3321`에서 `H1145`로 바뀜. 두 답은 모두 원문의 가격·평점 조건을 만족했고, 성공·근거·구성요소별 오류의 전체 비비용 판정이 같았음. 이를 새 대조 출력 **0건인 시점**인 2026-11-10 01:35 KST에 기록하고 [기준 변경](data/memory-contrast-loss-20261110/compatibility-amendment.json)을 고정함. 최초의 완전한 문자열 재현 기준이 그대로 통과했다고 보고하지 않음.

원래 네 반복은 계속 입력·출력 토큰 일치를 요구함. 추가 111건은 모든 입력이 같고, 그 입력과 연결된 각 상태·행동의 성공·근거·구성요소별 오류·미확인 판정이 모두 같아야 통과함. 총 성공이 같아도 구성요소 오류가 다르면 수집을 중단함. 다른 정답 ID와 출력 토큰 수 차이도 그대로 보존하며 비용을 같다고 처리하지 않음. 실패했던 검사에서 이미 생성한 25건은 입력·설정·가중치·환경·device map을 대조하고 재사용함. 당시 완주 계획은 새 호출 261회였으며, 이 중 새 대조 출력은 171회였음. 재시도·중단 회차 비용은 별도 집계함.

네 반복 중 필요한 기록이 은행에 있음/없음의 무기억 입력은 동일하므로 고유 프롬프트는 3개임. 전체 비교 대상은 114고유 입력·115개 기록임. 추가 검사는 관측한 라벨의 호환성 검사이며, 모든 입력에서의 동일한 실행이나 수치적 동등성을 증명하지 않음. 기존 L4와 로컬 offload의 실행 시간은 선택 정책 비용으로 합산 비교하지 않음.

작은 모델 학습과 작업자 실행은 로컬 GPU에서 순차 수행함. 학습 마감은 2026-11-10 05:30 KST로 두고 06:00까지 검산·보고 시간을 남김. 시간 내 완료되지 않은 조건은 미완료로 명시함.

## 결과

원래 자료에서 CE/CE+선택 손실 × 초기값 2개 × fold 3개의 12회 학습을 완료함. 실제 adapter를 다시 읽어 948개 평가 특징·확률을 오차 0으로 재현하고, 원래 후보에서 선택한 384개 상태별 행동도 모두 일치함을 확인함. 별도의 NumPy 판독층 재계산 최대 확률 오차는 `1.53e-7` 미만임.

| --- | --- | --- | --- |
| CE, 초기값 731 | 65.8% | 52 | 3 |
| CE+선택 손실, 731 | 67.9% | 53 | 3 |
| CE, 초기값 1729 | 63.3% | 53 | 3 |

현재 구성에서 손실 보완은 분류를 소폭 개선했으나 선택 정답과 악화 억제의 일관된 개선은 아직 없음. 기존 검색 상위 2개/참조 규칙의 55/96도 넘지 못함. 원래 데이터의 무기억은 정답 33/96, 입력 근거에 맞는 성공 19/96이므로 두 기준을 섞지 않음.

학습 데이터의 악화 사례에는 12개 모델 모두 음수 효과 점수를 줬음. 다만 원래 보류 출처의 악화 9건은 네 모델군 모두 악화 범주 정답이 0/9이며, 음수 점수도 세 모델군에서 0/9, 선택 손실·초기값 1729에서만 1/9임. 학습 출처에서의 적합과 출처 간 전이가 다름을 보여주는 진단임. 학습 사례의 암기 가능성과 악화 사례가 4가족에만 있다는 한계 때문에 관계 추론을 학습했다고 결론내리지 않음.

선택 손실이 정답을 바꾼 상태는 초기값 731에서 개선 1건, 1729에서 개선 1건·악화 1건이었음. 개선 두 건은 4개 기록 대신 필요한 2개 기록을 고른 경우이고, 악화 한 건은 2개 대신 3개를 고른 경우임. 기록 개수만으로 결과를 설명하거나 특정 조각의 작용을 단정하지 않음. 동일 상태에서 실제 제공된 묶음과 작업자의 출력이 달라진 [세 사례의 원문·기억·출력](data/memory-contrast-loss-20261110/original-case-changes.json)을 모두 보존함.

손실 자체도 점검함. 원래 자료에서는 학습 fold의 64상태 중 16–23상태만 무기억을 포함한 결과 차이가 있어 선택 손실이 활성화됨. 최종 모델 출력에 대한 선택 손실/CE 기울기 노름 비율의 활성 상태 중앙값은 약 0.094–0.130임. 이는 최종 출력 로짓의 미분 진단이며 전체 학습 중 parameter gradient의 크기나 실패 원인을 증명하지 않음. 독립 NumPy 미분을 PyTorch 자동미분 8조건과 대조했으며 최대 오차는 `2.8e-17`임. 이 결과를 보고 λ·온도·epoch를 바꾸지 않았음.


분류 개선의 내용도 구분함. 개선 범주의 정답은 초기값 731에서 35→39/57, 1729에서 42→45/57로 늘었음. 반면 비어 있지 않은 후보의 성과가 다른 7상태·16대조에서 올바른 순위는 각각 9→8/16, 8→7/16이었음. 효과 예측 MAE는 소폭 줄었지만 순위와 선택이 함께 개선된 것은 아님. [범주별 변화](data/memory-contrast-loss-20261110/classification-change-decomposition.json)를 보존함.

실제 선택의 가족 단위 bootstrap 기술 구간은 초기값 731에서 순 +1/96, 95% 구간 0~+3.125%p이며, 1729는 순 0/96, 구간 −3.125~+3.125%p임. 12개 개발 가족을 반복해 분석한 탐색적 결과이며 두 초기값을 독립 표본으로 세지 않음.

| 비교 | 정답/96 | 무기억 대비 악화 | 근거 없는 구체적 출력 항목 | 전달 기억 토큰 | 작업자 입력 토큰 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 무기억 | 33 | 0 | 34 | 0 | 95,887 |
| 검색 상위2 | 55 | 2 | 32 | 10,495 | 106,094 |
| 현재 관측 기반 규칙 | 55 | 1 | 9 | 5,166 | 100,909 |
| CE+선택 손실, 731 | 53 | 3 | 28 | 12,718 | 108,323 |
| CE+선택 손실, 1729 | 53 | 4 | 28 | 13,334 | 108,945 |

선택기는 각 조건에서 237개 제안 묶음을 점수화하느라 268,064입력 토큰을 추가로 읽었음. 실제 체크포인트 재실행에서 후보 점수화 시간은 조건별 약 16초였음. 모델 적재·상류 검색·작업자 실행을 포함한 종단 지연이 아니며, 서로 다른 모델의 토큰을 같은 단가로 합산하지 않음. 현재 규칙과 비교한 성공·오류·비용 우위는 확보하지 못했음.

## 대조 자료 수집이 중단된 이유

수정한 재현 기준에서도 추가 검사 80번째에서 전체 비비용 판정이 달라졌음. Detroit 가격 비교의 무기억 입력에서 원래 출력은 `NONE/NONE`, 로컬 출력은 `R4734/H4543`였음. 두 실행 모두 최종 정답은 0이지만, 식사 항목의 사실적 정답 여부와 근거 없는 행동 유형이 달라졌음. 총 성공만 검사했다면 놓쳤을 차이임.

전체 80검사 중 출력 토큰이 다른 기록은 2개였으며, 전체 비비용 판정이 다른 기록은 1개였음. 처음으로 판정이 다른 시점에서 종료됐으므로 이 비율을 일반적인 실행 변동률로 추정하지 않음. [중단 사례와 판정](data/memory-contrast-loss-20261110/worker-compatibility-failure.json), [독립 CPU 재검산](data/memory-contrast-loss-20261110/worker-failure-verification.json)을 함께 남김. 통과 기준을 추가로 완화하거나 실패 사례를 제외해 계속하지 않았음.

따라서 다음 상태를 구분해야 함.

| 항목 | 실제 완료 범위 |
| --- | --- |
| 원래 자료 + CE/선택 손실 | 12회 학습, 948예측과 384선택 재현 완료 |
| 대조 설계·원문 검수 | 19요청, 38기록쌍, 57상태의 228조합 준비 |
| 새 작업자 결과·효용 라벨 | 0건; 재현 검사에서 중단 |
| 보강 자료 + CE/선택 손실 | 미실행; 자료 보강 효과 미확인 |
| 새 독립 출처 | 0개; 기존 12가족 안의 보완 설계 |

로컬 작업자 검사에는 완료된 생성 96회가 사용됐음. 25개 재사용 출력을 중복 계산하지 않은 값이며, 처음 중단된 생성의 소요 시간은 별도 실행 시간에 포함됨. 유료 모델 API 호출은 없었고, Colab 잔여 단위는 확인 전후 566.31, 마지막 사용률 0·활성 할당 0이었음. 마지막 자원 점검에서 GPU compute 프로세스도 없었음. 학습 자료·기존 원문·정답·고정 가중치는 보존함.

## 공유와 재현

[공유 결과 묶음](../../evaluation/results/memory-contrast-loss-20261110-v1/README.md)에 판독층·저장 특징·실제 출력·선택 결과·재현 실패 근거를 포함함. 25.4MiB의 `predictions.zip`은 Git으로 공유하며, 183.5MiB의 실제 adapter/optimizer 전체 검토본은 로컬 `runs/memory-contrast-loss-20261110-v1/full-review.zip`에 별도 보존함. 두 검토 범위와 해시는 결과 README에 구분함.

Python 3.11 이상과 [CPU 검산 패키지](../../evaluation/requirements-memory-contrast-check.txt)를 사용함.

```bash
.venv/bin/python -m data_pipeline.export_memory_contrast_loss check \
  --path evaluation/results/memory-contrast-loss-20261110-v1
```

CPU 재검산은 저장 예측·선택·비용·원래 작업자 결과 연결·중단 판정을 확인함. 실제 adapter 재인코딩은 이번 실행에서 별도로 완료했고, 다른 컴퓨터에서 다시 수행하려면 전체 검토본과 해당 모델 가중치가 필요함.

새 clone에서도 README 첫 실행의 74행 검사·444예측 검산, 관련 검사 58개, 새 948예측·전체 정책·중단 원인의 재검산이 모두 통과함. 새 결과 재생은 PyTorch가 없는 별도 최소 환경에서 확인함. 오류 개수를 고치고 집계·archive 해시까지 다시 만든 사본도 원래 관측과 달라 거부됐음. [새 clone 검증 기록](../../evaluation/results/memory-contrast-loss-20261110-v1/fresh-clone-verification.json)에 코드 commit·archive 해시·원시 검사 출력을 연결함.

이번 결과로 손실 가중치나 epoch를 재조정하지 않았음. 남은 비교는 동일한 작업자 실행 조건에서 새 171입력과 기존 기준을 함께 검증한 뒤, 이미 고정한 자료 보강 두 조건을 학습하는 것임. 그 전에는 분류의 작은 개선을 실제 기억 선택의 개선이나 새 출처 일반화로 확대하지 않는 것이 적절함.
