## 우선 보완할 문제

### 1. 학습 정답·입력이 최종 효용 질문과 다름 — 우선순위 높음

최신 Harrier의 정답은 `재사용 참조 / 비교 참조 / 비참조`임. 선택 점수도 앞의 두 확률 합임. 높은 점수는 참조 대상이라는 뜻이며, 제공했을 때 성공이 늘 확률이라는 뜻이 아님. 정확한 참조 기억의 제공이 실제로 악화된 경우에도 높은 참조 점수는 자연스러움.

입력도 참조 탐색에 맞춰져 있음. 과거 전용 조건에서 선택기는 사람·날짜·식사·식당 이름·도시를 읽지만, 작업자는 추가로 과거 식당의 가격·평점·음식 종류와 현재 도시의 전체 식당 목록을 읽음. 선택기가 가격 조건·실행 가능성을 판단했다고 해석할 근거가 없음. 현재 관측 조건에는 과거 식당의 수치가 선택기에도 보이지만, 현재 전체 목록은 선택기에 주어지지 않음.

참조 판독기의 기능 점검으로는 타당함. 다음 효용 학습에는 판단 시점에 이용 가능한 근거를 입력 계약에 넣고, **관계 정답과 제공/보류의 실제 효과를 다른 목표로 보존**해야 함. 근거: [입력 구성](../../training/memory_selector/travel_worker_protocol.py), [실제 선택 루프](../../training/memory_selector/run_travel_worker.py).

### 2. 학습 모델의 추가 가치를 구별하기 어려운 평가임 — 우선순위 높음

후보 6개에 참조 정답이 항상 있고, 사람·날짜·식사가 명시적으로 주어짐. 학습과 평가의 기본 계획은 분리했지만 문장 틀·관계 형식은 공유함. 100%는 이 좁은 참조 과제에 대한 결과로 유지해야 함. 과거 이력도 참조 학습에서는 공개 정답 이력이고, 후속 효용에서는 구성한 작은 메뉴 과제의 실제 선택임. 원래 전체 MemoryArena 여행 수행 성적으로 해석하지 않음.

두 작업자 각각의 평가 32상태에서 학습 선택과 참조 규칙은 선택 기억·메시지·입력 및 출력 토큰까지 같았음. 학습 선택은 약 57–59ms, 규칙은 약 0.2ms였음. 이 평가에서는 학습 모델의 별도 필요성을 입증하지 못함.

또한 효용 평가 16요청은 **8개 기본 계획**에서 나왔고, 두 정보 조건·여러 정책·두 작업자는 독립 출처가 아님. 이미 참조 평가에 사용한 계획이며 9B는 4B 결과를 본 뒤 추가한 진단임. 다음 확인 실험에는 새 출처가 필요함.

### 3. 무기억 정답의 의미가 일부 다름 — 지표 보완 필요

4B의 과거 전용 무기억은 평가 16건 모두 `NONE`을 출력함. 가능한 식당이 실제로 없는 3건에서만 맞았음. 결과 정확도 집계는 맞지만, 기억 없이 과거 사실을 이해했다는 근거는 아님. 반대로 필요한 정보 부족을 정확히 밝힌 `UNKNOWN`은 현재 작업 성공으로 세지 않음.

기존 주 성적은 유지하고, **가능한 답 있음/없음, 적절한 정보 부족 보류, 근거 없는 선택**을 따로 보고해야 함. 가능한 답이 있는 13건에서는 무기억 0 → 학습 선택 7건(4B), 0 → 10건(9B)이었음. 불가능한 3건에서는 학습 선택이 두 작업자 모두 0/3이었음. 성공률만으로 검색·추론·보류 능력을 함께 설명하지 않음.

### 4. 실제 악화는 관측했으나 원인 조각까지 특정하지 못함 — 해석 제한

아래는 평가 16요청의 저장 출력을 별도 재채점한 결과임.

| 작업자·현재 정보 | 무기억 → 학습 선택 | 실패→성공 | 성공→실패 |
| --- | ---: | ---: | ---: |
| 4B·과거에만 있음 | 3 → 7 | 7 | 3 |
| 4B·현재에도 보임 | 7 → 3 | 1 | 5 |
| 9B·과거에만 있음 | 1 → 10 | 10 | 1 |
| 9B·현재에도 보임 | 11 → 9 | 0 | 2 |

정확한 사실을 추가해도 고정한 입력·작업자에서 출력이 악화될 수 있다는 관측은 유지됨. 그러나 기억 추가는 사실 외에도 길이·배치·중복·표현을 함께 바꿈. 따라서 “이 정보 내용 자체가 해로움”이나 “중복 때문에 실패함”까지 증명한 것은 아님. 동일한 사실의 제시 위치 변경, 길이를 맞춘 안내, 이미 있는 사실의 반복 여부를 새 프로토콜에서 대조할 필요가 있음.

9B의 과거 전용 학습 선택은 재사용 8/8, 상대 비교 2/8임. 참조 탐색 이후 조건을 함께 적용하는 작업자의 병목도 큼. 관측된 모든 실패를 선택기 개선으로 해결할 수 있다고 가정하지 않음.

### 5. 이전 학습의 부정 결과가 최신 100%로 해소된 것은 아님

[기존 통합 리뷰](../../training/memory_selector/reviews/2026-11-08-integrated/README.md)의 주 비교 8모델은 학습·개발·평가에서 동일한 기억 종류를 1순위로 골랐음. 개발 F1과 실제 선택 성적도 어긋났음. 이번에 저장 예측 재검산으로 같은 결과를 확인함. 최신 여행 참조는 다른 과제이므로 이를 자연 코드 적용성의 개선으로 연결하면 안 됨.

이미 기록된 [최신 회고](../../training/memory_selector/reviews/2026-11-09-retrospective/README.md)도 재검산함. 현재 관측이 있으면 무기억, 없으면 참조 규칙을 고르는 사후 조합은 9B 평가에서 21/32이고 관측한 다섯 정책 중 최대치는 22/32임. 다만 같은 조합은 개발에서 학습 선택보다 낮았음. 학습 모델뿐 아니라 단순 규칙의 우위도 새 확인 집합에서 판단해야 함. 이 조합은 새 정책 실행 결과가 아님.

### 6. 비용·재현 기록에 남은 제한 — 성적 오류와 구분

- 작업자 시간은 프롬프트 작성·토큰화·입력 GPU 전송 이후부터 측정함. 선택기 시간의 측정 범위와도 다름. 현재 시간표는 전체 요청 처리 시간이나 전체 운영 비용의 비교로 확대하지 않음.
- 작업자 모델 revision은 실행 설정에 고정했으나 `worker_resolved_revision`은 두 실행 모두 null임. 실제 로드된 가중치 해시를 독립 대조했다고 주장할 수 없음. 다음 실행부터 해석된 snapshot commit·파일 해시를 별도로 남기는 편이 적절함.
- 과거 경로·해시 목록 5,760항목 중 알려진 가변 경로 차이 5개가 다시 검출됨. 3개는 당시 사본을 찾았고, 2개 설명/검사 파일의 옛 버전은 미확보임. 현재 실험 출력이 바뀌었다는 발견은 아니지만 과거 작업 공간 전체의 완전 복원은 보장되지 않음. 원래 해시는 보존함.

## 다음 실험에 적용할 순서

1. 기존 여행 패널은 기능·회귀 점검용으로 동결함. 같은 평가 결과를 보며 문턱·층·정책을 계속 조정하지 않음.
2. 새 출처에서 과거에만 필요한 정보 / 현재 이미 보이는 정보 / 전제가 달라진 관련 기억 / 유효한 참조가 없는 상황을 수집함. 출처별 학습·개발·평가 분할과 수집 규칙을 결과 생성 전에 고정함.
3. 같은 현재 상태와 실제 과거 경험에 대해 제공·보류를 실행함. 성공 변화·악화 수·입출력 토큰·전체 지연을 각각 저장하고, 관계 주석을 효과 정답으로 대신하지 않음. 반복도 출처 수와 구분함.
4. 개발에서 무기억·고정 기억·검색·참조 규칙·현재 관측 확인 규칙보다 선택할 여지가 있는지 확인함. 그다음 필요한 입력을 읽는 최소 효용 모델과 관계 감독 추가 모델을 비교함. 개발에서 정한 기준으로 새 평가 출처를 한 번 판정함.

이 순서의 목적은 모델 규모를 더 비교하기 전에 **무엇을 판단할 수 있는 입력인지, 무엇을 배운 정답인지, 배운 선택이 실제 성과를 더하는지**를 연결하는 데 있음.
