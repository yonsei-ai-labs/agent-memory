# 첫 연결 점검의 타당성 감사

2026-11-03 · 원본 기록 대조와 로컬 패치 재실행 · 새 모델 호출 0회

## 결론

**현재의 ‘Luna 제출 패치 해결 / DeepSeek 제출 패치 미해결’ 판정을 뒤집을 실행·채점 오류는 찾지 못했다.** 원본 입력과 실행 조건을 대조했고, 수정 전 코드·정답 패치·두 제출 패치를 새 컨테이너에서 검사하여 같은 판정을 재현했다. DeepSeek의 실패는 포맷 이름의 표기 차이만으로 생긴 것이 아니라 상위의 사용자 지정 포맷을 반영하지 못하는 동작으로도 확인했다.

다만 첫 시도에는 대조군 검사와 채점 증거 검사가 부족했다. 이번 감사에서 대조군을 실행했고, 테스트가 실제로 실행됐는지 확인하는 코드를 보강했다. 또한 한 과제·모델별 한 번의 결과이므로 **모델의 일반 성능, 비용 효율 순위, 메모리의 득실은 아직 판단할 수 없다.**

## 판정이 정상인지 대조군으로 확인

원본 과제와 같은 이미지에서 네 개의 새 컨테이너를 사용했다. 각 조건에 지정한 패치만 적용한 뒤, 공식 채점기의 테스트 스크립트와 파서를 사용했다. 수정 전 대조군은 모델 패치를 적용하지 않고 공식 테스트 스크립트를 직접 실행했다. 따라서 빈 제출을 건너뛰는 배치 CLI의 동작과 구분한다.

정답 패치는 고정된 리비전의 로컬 데이터 캐시에서 감사 대조군용으로만 읽었다. 모델에 전달하거나 원래 실행의 결과를 수정하지 않았다. 아래 결과는 새 모델 샘플이 아니라 **고정된 코드의 재검사**다.

| 코드 상태 | 공식 목표 테스트 | 기존 유지 테스트 | 추가 동작 점검 8개 |
| --- | --- | --- | --- |
| 수정 전 코드 | 0/1 | 76/76 | 2/8 |
| 정답 패치 | 1/1 | 76/76 | 8/8 |
| Luna가 제출한 패치 | 1/1 | 76/76 | 8/8 |
| DeepSeek가 제출한 패치 | 0/1 | 76/76 | 4/8 |

수정 전에도 유지 테스트 76개는 모두 통과했다. 따라서 유지 테스트 통과만으로 버그를 고쳤다고 판정하면 안 된다. 정답 패치가 통과하므로 해당 환경에서 목표 테스트가 항상 실패하는 상황도 아니었다.

추가 8개는 결과를 본 뒤 실패 원인을 구분하려고 작성한 진단 항목이다. 독립적인 8개 벤치마크 과제로 세거나 모델 성능 점수로 사용하지 않는다. [진단 코드](../../experiments/swe_memory/diagnostics/format_inheritance.py), [감사 원본 · 별도 원본](../reproduction.md) (`runs/audit-20261103T131300Z-459716/audit-result.json`).

## DeepSeek의 실패는 어떤 종류였나

첫 공식 실패는 내부 필드의 포맷이 `iso8601` 대신 `iso`였다는 assertion이었다. 이 둘은 일반적인 날짜 출력이 같을 수 있어 이 사실만으로 사용자에게 보이는 기능 실패를 확정하면 과한 해석이다.

이를 구분하기 위해 날짜 `2019-08-21`에 상위 Schema의 포맷을 `%Y/%m/%d`로 설정했다.

- 기대한 출력: `2019/08/21`.
- Luna와 정답 패치: `2019/08/21`.
- DeepSeek 패치: `2019-08-21T12:34:56`.

List, Tuple, 중첩 List와 Date의 상위 포맷 설정에서 같은 종류의 미충족이 나타났다. 한편 기본 포맷의 List·Tuple은 DeepSeek 패치로 예외가 사라졌다. **전체 목표를 충족하지 못했지만 일부 문제는 고친 패치**라는 해석이 맞다. ‘완전히 쓸모없는 실패 경험’으로 분류하면 얻은 정보까지 버리게 된다.

이 결과는 실패 패치의 동작에 대한 증거다. 기억이 해로웠다는 증거는 아니다. 이번 실행에는 기억을 넣지 않았다.

## 발견한 절차·구현상 부족함과 조치

### 1. 결과 모양의 보고서만 보고 채점이 완료됐다고 판단할 가능성

기존 실행기는 `tests_status`가 비어 있지 않으면 `evaluated`로 분류했다. 그런데 공식 파서는 테스트 출력 구간 표시는 있지만 실제 테스트 상태를 하나도 읽지 못한 로그에서도 기대 테스트들을 실패 목록으로 채운 보고서를 만들 수 있다. 기존 코드는 이를 정상적인 미해결 결과와 구분하지 못했다. 채점 프로세스 종료 코드도 저장만 하고 판정에는 쓰지 않았다.

이 문제를 모델 호출 없이 재현하고 다음 검사를 추가했다.

- 공식 채점 프로세스가 정상 종료했는지.
- 실제 테스트 결과를 파싱했는지.
- 기대한 목표·유지 테스트들의 결과가 모두 관측됐는지.

미충족이면 `evaluation_incomplete`와 세부 진단을 남기고 공식 점수는 그대로 보존한다. **불완전한 채점이 곧 인프라 오류라는 뜻은 아니다.** 잘못된 모델 패치가 import·collection 오류를 낼 수도 있으므로 원인은 대조군과 로그로 판단해야 한다. 이런 사례를 성공률 분모에서 자동 제외하지 않는다.

이번 두 원본 실행은 실제 77개 결과가 모두 있었고 프로세스도 정상 종료해 판정이 바뀌지 않았다. [검사 코드](../../experiments/swe_memory/scripts/evaluation_checks.py), [회귀 검증](../../experiments/swe_memory/tests/test_evaluation_checks.py).

### 2. 첫 실행에 수정 전·정답 패치 대조군이 없었음

첫 실행은 연결 점검이었지만, 결과의 타당성을 해석하기 전에 대조군까지 확인하는 것이 더 적절했다. 이번 감사에서 네 조건을 검사했다. 본 실험에서는 새 과제의 환경 적합성 검사를 모델 결과와 독립적으로 수행하고, 적용 기준을 사전에 정한다.

### 3. 메모리 효과를 평가할 조건이 아직 없음

현재는 두 모델 모두 메모리 없는 조건이다. 따라서 관찰한 성공·실패 차이를 메모리 효과로 해석할 수 없다. 다음 비교는 **동일 모델·동일 제공자·동일 과제에서 메모리 조건만 바꾸는 것**이어야 한다. 다른 모델은 이후 효과가 옮겨가는지 확인하는 데 사용한다.

### 4. 모델·비용 비교에는 표본과 통제 조건이 부족함

- 과제 1개, 모델별 1회다. 성공 확률·변동성·일반 성능을 추정할 수 없다.
- Luna medium과 DeepSeek high는 같은 계산량이 아니다. DeepSeek는 직접 제공 경로가 계정 정책으로 거절되어 DeepInfra FP8로 변경됐다. 비교 대상은 이 제공 구성까지 포함한 시스템이다.
- 반환된 샘플링 메타데이터는 두 모델 모두 temperature=1, top_p=1이었지만 요청에서 동일한 난수 seed를 지정하지 않았으며 반환값만으로 내부 샘플링의 동일성을 증명할 수 없다.
- Luna를 먼저, DeepSeek를 나중에 실행했다. 지연·비용 비교는 순서, 캐시, 제공자 상태의 영향을 분리하지 못한다. 메모리 A/B/C는 실행 순서를 섞어 반복하고 시간 블록을 기록한다.
- 캐시 읽기 비중이 높았으므로 이 과제의 비용을 전체 실험 견적으로 바로 확대하지 않는다. 입력·출력·캐시·추론량과 실제 비용을 함께 보고한다.

### 5. 대규모 실행 전에 남은 운영 보완

원본과 코드 사본·해시는 남겼지만 아직 최초 Git 커밋 전이며 외부 백업도 없다. 단계별 실행표·재시도 규칙·분모 처리·전체 예산을 고정하는 작업은 아직 남아 있다. 현재 요청 로그는 응답 또는 오류 처리 후에 기록되므로 프로세스가 강제 종료되면 완료되지 않은 요청의 추적이 부족할 수 있다. 대규모 실행 전에 요청 시작 이벤트와 중단 복구를 추가하는 것이 적절하다. 현재 저장된 두 실행에는 요청·응답 누락이 없었다.

## 이후 실험에 반영할 것

1. 이 문제는 환경 점검·사후 분석 전용으로 유지한다. 정답과 테스트를 검토한 뒤 만든 지침을 이 문제에 넣어 새 과제로의 전이 성과라고 보고하지 않는다.
2. 별도 과제의 분할과 선정 기준을 먼저 고정한다. 작은 모델 선정용 반복 실행에서 성능·비용의 변동성을 본다.
3. 주 모델을 고른 뒤 같은 모델 안에서 무메모리 / 관련 기억 / 재배정 기억을 비교한다. 발견 후 문구 삭제·수정으로 원인을 검증한다.
4. 기억에 자체 테스트 통과, 공식 목표 충족, 기존 기능 유지, 환경 오류, 관측된 부분 개선을 구분해 저장한다. 공식 성공/실패 한 비트만으로 기억의 내용 전체를 유익/유해로 라벨링하지 않는다.

원래 모델 실행 4건과 감사 대조군은 별도 집합이다. 감사 폴더에는 정답 패치가 들어 있으므로 경험 기억 수집 대상으로 사용하지 않는다. 이 감사에서는 API 모델 호출이나 새로운 메모리 실험을 수행하지 않았다.
