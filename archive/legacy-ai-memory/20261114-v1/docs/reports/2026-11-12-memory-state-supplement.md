| 점검에서 발견한 문제 | 적용한 보완 |

기존 4출처를 재사용했으므로 새 독립 경험이 늘어난 것은 아님. 모두 이전 stage1 노출 이력이 있는 설계용 `dev` 출처이며, 본 자료 20가족과 봉인 new-b의 원천은 열지 않음. 원 작업 트리도 수정하지 않음.

## 같은 관측도 현재 목표에 따라 역할이 달라짐

다음 네 상태는 같은 은행과 같은 두 공개 관측을 사용함. 각 목표 안에서는 대상 기억도 고정함.

| 현재 요청 | 현재 관측 | 해당 요청의 대상 기억 역할 |
| --- | --- | --- |
| Stefan의 3일차 예약 사용 | Lena의 3일차 예약을 확인함 | Stefan의 기록이 필요함 |
| Stefan의 3일차 예약 사용 | Stefan은 그날 다른 도시에 있어 기존 저녁·숙소를 쓰지 않음 | Stefan의 옛 기록은 현재에 맞지 않음 |
| Lena의 3일차 예약 사용 | Lena의 3일차 예약을 확인함 | 현재 관측으로 이미 충분함 |
| Lena의 3일차 예약 사용 | Stefan은 그날 기존 예약을 쓰지 않음 | Lena의 기록이 여전히 필요함 |

첫 Stefan 쌍의 과거 기록은 `R661/H3887`임. 현재에 무효화가 관측된 상태의 정답은 두 항목 모두 UNKNOWN임. Lena 쌍의 정답은 두 상태 모두 `R661/H4494`이나, 현재 관측에 그 예약이 있는지에 따라 과거 기록의 필요성이 달라짐.

변경 사건에서는 현재 관측이 새 식당·숙소 ID를 포함함. 따라서 과거 기록의 필요→불필요 전환과 실제 답의 변화를 함께 구분할 수 있음. 제공하면 해롭다는 정답을 붙인 것은 아니며, 실제 손해 여부는 같은 작업자에 제공·보류한 결과로 측정해야 함.

위 관측은 새 사실을 임의로 만든 것이 아니라 부모 패킷의 공개 기록을 현재 확인한 상황으로 재배치한 통제 상태임. 두 목표를 교차한 `observation_coverage` 쌍은 시간순 실행 경로를 뜻하지 않음.

## 단순한 표시만 보는 지름길을 점검함

초안의 “관측 없음/변경 관측 있음”만으로 정답이 갈리는 구성을 보완함. 최종 대조는 모두 같은 `Observed result` 머리말을 가진 실제 공개 관측을 포함하며, 같은 관측 문장을 두 목표에 재사용함.

| 사용 가능한 정보 | 현재 192상태에서 가능한 최대 표 조회 정답률 |
| --- | ---: |
| 관측 문자열만 | 50% |
| 목표·대상 기억, 관측 제외 | 50% |

관측별 41집단과 목표·대상 기억별 29집단 모두 정답이 갈림. 이는 입력을 가렸을 때의 유한한 구성 표 진단이며, 모델의 성능이나 자연 분포의 한계가 아님. 전체 공개 입력을 쓰는 간단한 사람·날짜 규칙은 이 자료를 풀 수 있음. 신경망이 규칙보다 필요하다는 주장은 하지 않음.

## 판독 입력과 작업자 입력을 분리함

선택기는 현재 요청·관측과 함께 후보 저장소를 볼 수 있음. 저장소는 작업자에게 이미 제공된 관측이 아니며, 후보 하나를 판독할 때도 다른 공개 기록을 확인할 수 있게 함. 원 주석의 근거 위치는 감독·검산에 사용하고 실제 입력을 고르는 기준으로 쓰지 않음.

원 168사례의 후보 5,472행 중 모호한 18행을 마스킹함. 여기에 불충분 진단 40행과 새 상태 192행을 연결한 인수 검사는 399사례·5,686입력이며 고유 입력은 5,666개임. 근거 구간 17,003개·판단 시점·출처 분할·동일 입력의 상충 정답 검사가 통과함. 원 20관계가 두 표현으로 확장된 진단이므로 40개의 독립 경험으로 세지 않음.

고정 Harrier tokenizer로 검사한 실제 판독 입력은 1,208–3,582토큰으로 4,096초과가 없음. 기존 짧은 pair보다 읽기 비용은 증가함. 충분한 근거를 주는 비용까지 포함해 순이득을 확인해야 하며, 이번 결과를 지연·비용 개선으로 해석하지 않음.

## 실제 득실 측정 입력을 준비함

192상태에서 다음 여섯 조건의 실제 메시지를 고정함.

- 무기억.
- 동일한 대상 기록 제공.
- 전체 과거 기록 제공.
- 목표 BM25로 2,048토큰 안에서 선택.
- 현재 관측의 사람·날짜를 확인하는 공개 문자열 규칙.
- 필요한 기록만 제공하는 정답 기반 진단.

1,152개 조건 배정은 실제 메시지 402개에 대응함. 같은 입력은 같은 작업자 출력을 공유하도록 해 중복 호출을 피할 수 있음. **지금까지 실행한 작업자 호출은 0임.** 모델·revision·디코딩·반복·실행 상한을 정한 뒤 연결할 입력 명세이며 현재 Colab 실행기의 완성된 설정 파일은 아님.

기억 예산은 머리말·구분자를 포함한 실제 전달 블록을 세며 검색·규칙 조건은 2,048토큰 이하임. 전체 제공 192배정 중 8개가 예산을 초과하여 진단으로 표시함. 나머지 정책에는 예산 초과가 없음. 정답 기반 필요 기록 조건도 작업자 성능의 상한으로 가정하지 않음.

채점은 엄격한 JSON 형식과 과제 정답을 먼저 구분하고, UNKNOWN·대상 기억의 제공·현재 관측의 해소 여부를 별도로 저장함. 기억이 전달되지 않아 정상적으로 보류한 응답을 작업 완료나 근거 없는 행동으로 바꾸지 않음. 관계 라벨과 실제 득실 라벨은 계속 분리함.

## 검증과 다음 단계

원 패킷의 파일 해시를 확인한 뒤 메모리 안의 스냅샷으로 보완 자료를 생성함. 별도 폴더에서 다시 생성한 24파일이 바이트 단위로 일치함. 관련 검사 78개가 통과함. 또한 원 작업 트리·runs·tokenizers가 없는 최소 코드·데이터 사본에서 `python -S`로 인수 검사와 신규 검사 24개가 통과해 기본 검사는 표준 라이브러리만으로 재현됨. 원 패킷 12파일의 해시도 그대로임. 검증 수치는 [검증 기록](data/memory-state-supplement-20261112-v3/verification.json)에 보존함.

다음은 보완된 검토표의 의미 판정과 제한된 작업자 측정임. 전자는 사람이 수행한 결과가 아직 없으며, 후자도 현재 모두 `null`임. 지금 자료로 새 모델을 학습하거나 새 독립 평가를 완료했다고 설명하지 않음. 먼저 이 4출처에서 측정 계약을 점검하고, 남겨둔 출처에 같은 방법을 적용하는 것이 적절함.
