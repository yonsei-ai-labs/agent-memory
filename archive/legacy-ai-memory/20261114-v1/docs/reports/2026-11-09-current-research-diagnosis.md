## 실제 측정에서 확인한 진전

[새 문제군 파일럿](2026-11-09-travel-state-utility-pilot.md)의 원자료를 재생해 주 집계와 진단이 일치함을 확인함.

- 무기억 33/96 → 학습 검색 기억 제공 51/96임. 같은 상태의 관측 개선 23, 악화 5로 순차이는 +18상태임.
- 현재에 없는 과거 선택을 제공하면 3→18/24, 이미 현재에도 보이면 19→18/24였음. 가용성 변경은 11→15/24였음.
- 따라서 기억 효과를 하나의 평균으로만 보면 현재 정보·가용성에 따른 차이를 놓침. 다만 네 조건의 동일 비율은 설계한 분포이며 실제 사용 환경의 발생 빈도가 아님.
- 필요한 사실을 일부러 과거에만 두는 구성도 포함됨. 이 조건의 이득은 정보 제공의 가치를 보여주지만, 학습 기반 선택의 필요성을 자동으로 입증하지 않음.
- 실제 기록 540개 중 원래 속성 제약 통과는 409개임. 실패한 과거 선택도 기록으로 보존했으므로 모두 성공 경험으로 부르지 않음.

현재는 공개 여행 자료를 이용한 통제된 후속 식당·숙소 선택 과제임. 자연 사용자 전반이나 SWE 전체 에이전트의 성과를 확인한 것이 아님.

## 최신 후속 결과가 더 분명하게 만든 것

[고정한 후속 설계](../ai-memory-travel-policy-followup-2026-11-09.md)에 따라 새 고유 호출 517개와 반복 4개를 실행했으며, 기존의 동일 입력 365개 고유 응답을 재사용함. 최종 1,536정책 행은 같은 96상태·12가족에 대한 비교임.

아래 성공은 두 선택을 모두 맞힌 상태 수임. 근거 없는 구체적 선택은 두 구성 요소를 합친 항목 수로 단위가 다름. 입력 토큰은 96상태에서 worker가 받은 전체 입력 합이며 온라인 검색·인코더 비용이 아님.

| 지침·정책 | 성공 / 96 | 근거 없이 구체적 ID를 낸 항목 | 입력 토큰 합 |
| --- | ---: | ---: | ---: |
| 기존·무기억 | 33 | 34 | 95,887 |
| 기존·학습 상위4 | 51 | 31 | 116,890 |
| 기존·학습 상위2 | 55 | 32 | 106,094 |
| 기존·점수≥0.5 | 51 | 14 | 104,576 |
| 기존·상태 규칙 | 55 | 9 | 100,909 |
| 근거 우선 지침·학습 상위4 | 48 | 10 | 132,730 |
| 근거 우선 지침·점수≥0.5 | 49 | 2 | 120,416 |
| 근거 우선 지침·상태 규칙 | 50 | 1 | 116,749 |

‘근거 없이’는 해당 과거 참조를 작업자가 전달받지 않았다는 입력 기준임. 모든 구체적 선택이 사실적으로 틀렸거나 실제 예약 피해를 일으켰다는 뜻은 아님.

**제공량의 제어에는 실용적인 신호가 있음.** 기존 지침에서 상위4→상위2는 5상태 개선·1상태 악화, 순 +4였고 입력 토큰도 줄었음. 다만 가족 부트스트랩 95% 기술 구간은 약 −1.0~+10.4%p로 0을 포함함. 확정적인 성능 우위나 최적 개수로 주장하지 않음. 상위2의 근거 없는 구체적 출력은 줄지 않았음.

**보류의 가치는 성공률만으로 포착되지 않음.** 0.5 경계는 성공 51점을 유지하면서 근거 없는 구체적 출력을 31→14, 입력 토큰을 116,890→104,576으로 줄였음. 그러나 이 값은 보정된 확률도 독립 검증한 최적 임계값도 아님. 잘못된 NONE 등 다른 실패가 남았음.

**지침을 명시해도 기본 계약은 해결되지 않았음.** 작은 점검 36문제씩에서 정답 ID가 있는 항목은 양쪽 모두 24/24였지만, UNKNOWN이어야 하는 항목은 양쪽 모두 0/24였음. 불가능을 뜻하는 NONE 항목은 기존 13/24, 새 지침 10/24였음. UNKNOWN을 못 낸 것을 파싱 실패·출력 제한 탓으로 설명할 근거는 이 점검에서 없었음. 예컨대 Alex의 과거 숙소는 없고 Taylor의 숙소만 있는 사례에서 Taylor의 숙소 ID를 그대로 골랐음.

긴 지침이 여러 요소와 입력 길이를 함께 바꾸므로, 이 결과만으로 전제 확인 자체가 해롭다는 결론을 내리지 않음. 현재 worker·표현·greedy·thinking off 조건에서 시도한 지침이 충분하지 않았다는 결과임. 원문과 출력이 확인된 일부 사례에서 보인 행동을 전체 내부 추론 원인으로 확정하지 않음.

## 학습 연구의 현재 병목

주 효용 head는 96상태 중 92개에서 기억을 제공했고, 문제군을 제외한 평가에서 악화 5개를 하나도 막지 못했음. 입력을 읽지 않고 학습 fold의 평균 효과만 쓰는 정책도 항상 제공해 51점이었음. 분류 정확도나 학습 집계만으로 유용한 상황 판단을 배웠다고 말할 수 없음.

손해 관측은 5상태·4가족뿐임. 원천 확대 없이 이 소수 사례의 표현만 늘리면 반복 행은 늘지만 손해 조건의 다양성은 부족함. 또한 이전 네 범주 라벨은 성공 여부만 구분해, 둘 다 실패하되 근거 없는 구체적 추측이 증가한 차이를 놓쳤음.

관계 점수는 개별 기억에 붙지만, 효용은 현재 관측·기억 묶음·worker·지침·예산에 의존함. 다음 목표는 다음 세 층으로 분리하는 것이 적절함.

1. 과거 근거를 정확한 주체·시점·대상에 연결하는가.
2. 현재 요구를 풀기에 충분하며 지금 적용할 수 있는가.
3. 실제로 제공·확인·보류했을 때 성공·악화·비용이 어떻게 달라지는가.

[추론 대조 설계](../ai-memory-reasoning-contrasts-and-data-2026-11-09.md)의 충분성·기억 결합·누락 전제는 이 간격을 메울 후보임. 논리 보조 과제를 잘 푸는 것이 실제 효용 개선으로 옮겨가는지는 별도로 검증해야 함.

## 권장하는 다음 순서와 판단 기준

1. **작업자 계약부터 작은 자료에서 진단함.** 한 선택만 묻는 경우, 주체만 바꾼 경우, 정보 부족/명시적 불가능/가능을 분리함. 짧은 출력 계약·소수 예시·필요시 다른 추론 설정을 각각 비교하되 여러 요인을 동시에 바꾸지 않음. 현재 36개에 지침을 반복 최적화한 결과와 새 점검의 성능을 구분함.
2. **단순 정책을 강한 기준선으로 고정함.** 상위2/상위4/고정 경계/현재 관측 보류를 포함함. 성공·근거 없는 선택·토큰을 각각 보고, 더 복잡한 head가 어느 지표에서 추가 이득을 내야 하는지 먼저 정함.
3. **독립 가족과 필요한 판단 유형을 함께 늘림.** 남은 train48과 새 도메인 후보에서 정보 부족·주체 혼동·갱신·전제 전환·두 근거 결합을 확보함. 정답은 원문/추론기/실행으로 확인하고 실제 효용은 별도 측정함. 어려운 음성은 무관한 문장보다 “주제는 같지만 다른 사람·버전·시점·조건”을 포함함.
4. **그다음 보조 추론 학습을 비교함.** 같은 부모·학습 예산에서 기존 학습/표현 증강/검증된 추론 증강을 비교함. 손해 행동·정보 부족·비용 라벨을 분리하고 새 가족의 제외 평가에서 개선이 남는지 확인함.
5. **개발과 확인 평가를 분리함.** 현재 train12는 이미 탐색에 사용됨. dev20은 선택·보정에, test40은 방법 동결 후 확인에 사용함. 같은 TravelPlanner 계열의 새 가족 전이와 다른 도메인 전이를 별도 주장으로 남김.

정보 부족을 현재 worker가 구별하지 못하는 채 대량 확장하면 선택기 자료에 작업자 오류가 많이 섞임. 반대로 모든 데이터 수집을 기다릴 필요는 없으며, 원문·출처 가족 확보와 정답 검산은 위 계약 점검과 병행할 수 있음.

## 재현·공유 상태의 진단

이번 확인에서 수행한 범위는 다음과 같음.

- 공유 원자료의 SHA를 검사하고 기존 파일럿 주 결과·진단을 재생함.
- 저장 특징·checkpoint를 이용한 회고를 기존 `.venv`의 NumPy로 재계산해 공유 JSON과 완전히 일치함을 확인함. 시스템 `python3`에는 NumPy가 없어 이 단계만 가상환경으로 실행함.
- 후속 원문·tokenizer·저장 토큰·정책·SQL 정답을 재검사하고 결과 JSON 5종을 별도 임시 폴더에 재구성함. 원 집계와 완전히 일치했음.
- 후속 평가·선택 정책의 로컬 검사 10개가 통과함. 전체 코드의 모든 검사를 이번에 다시 실행한 것은 아님.
- GPU/모델을 새로 실행하지 않았고, 다른 작업자의 코드·원시 산출물을 수정하지 않았음.

검사 당시 README와 실행 원장은 이전 후보 검색 결과까지 주로 안내했고 새 파일럿·후속 결과의 반영이 뒤따르는 상태였음. 동료 공유 때에는 검색 92%와 함께 **효용 head 미개선, UNKNOWN 실패, 새 가족/도메인 확인 전**을 같은 진입 문서에서 볼 수 있게 정리하는 것이 필요함. 진행 중인 미커밋 분석 코드·공유 산출물과 완료한 실행도 구분해야 함.
