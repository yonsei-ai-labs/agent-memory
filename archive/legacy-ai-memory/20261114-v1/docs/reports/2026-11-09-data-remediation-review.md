# 데이터 내용 점검·보완안에 대한 추가 검토

후속 보완: [실행 결과와 연구 질문 정렬](2026-11-09-data-remediation-implementation.md)에 검토 묶음·출처 문맥·현재 상태 입력·오류 의미를 실제로 보완한 범위를 정리함.

2026-11-09. `0e9a6c8` 기준 원자료와 작업 공간의 `docs/reports/2026-11-09-data-content-review.md`, `docs/ai-memory-data-remediation-plan-2026-11-09.md`를 검토함. 검토 당시 파일 해시는 [출처 기록](data/data-remediation-review-20261109/source-snapshot.json)에 보존함.

**보완안의 방향은 적절함. 다만 데이터 수를 늘리기 전에 정답의 의미와 선택기 입력을 맞추고, 성공 외 오류의 정의를 수정할 필요가 있음. 64개 재검토는 채택하되, 이것으로 원천 부족이 해결되거나 기존 데이터의 오류율이 추정됐다고 보지 않음.**

이번에는 실제 입력·라벨·생성 코드, 재검토 묶음과 후속 작업자 출력을 대조함. 새 주석 확정·학습·모델 호출·GPU 할당은 수행하지 않았음. 원래 데이터와 다른 에이전트의 초안은 수정하지 않았음.

## 1. 보완안에서 채택할 부분

| 제안 | 판단 |
| --- | --- |
| 원본 v1을 보존하고 재주석을 별도 버전에 연결함 | 채택함. 기존 성적을 새 라벨로 소급해 덮어쓰지 않음 |
| train의 64개를 기존 정답을 가리고 재검토함 | 채택함. 현재 입력·과거 근거·빈 양식을 준비한 단계이며 아직 새 학습 정답은 없음 |
| 관계·출처 충실성·현재에 이미 있는 정보를 구분함 | 채택함. 관련성 양성을 실제 이득으로 바꾸는 오류를 줄임 |
| 과거/현재 상태와 근거 누락·결합을 함께 검증함 | 채택함. 기억의 사용 여부가 현재 조건에 따라 달라지는 사례를 먼저 확보함 |
| 작업자 하나를 고정하고 선택기를 비교함 | 핵심 실험으로 유지함. 0.6B 학습 전·LoRA·Qwen 4B·9B가 같은 선택 과제를 수행해야 함 |
| 실패·중립·악화 결과를 보존함 | 채택함. 작업자가 실패했다는 이유로 효용 행을 삭제하지 않음 |

개발 자료에서 서로 다른 정답 의미를 하나의 0/1/2로 합치거나, 새 결과를 보고 기존 라벨을 바꾸는 방식은 사용하지 않음. 외부 데이터의 최신 이용 조건과 논문 근거는 이번 검토에서 새로 조사하지 않았음.

## 2. 주석 문제는 표본 수와 별개로 다뤄야 함

실제 train 사례에서 다음 경계가 확인됨. 아래는 원문을 읽은 검토 의견이며, 독립 재주석의 확정 정답이 아님.

| 기존 사례 | 현재 양성/음성 판단의 불명확한 부분 | 보완할 질문 |
| --- | --- | --- |
| `rebench-963--numeric_validation` | 기억은 빠진 수치 유효성 검사를 추가하는 경험임. 현재는 비표준 문자열 길이를 허용하도록 검사를 끄는 옵션 요청임. 기존 양성은 ‘검증 정책’이라는 넓은 공통점에 의존함 | 어떤 구체적 점검 행동이 전이되며, 현재 요청에 이미 제시된 내용에 무엇을 더하는가 |
| `rebench-1074--specific_precedence` | 기억은 태그 병합 순서로 특정 값이 덮어써지는 문제임. 현재는 클래스 문맥을 잘못 사용한 기본값 생성임. 병합·덮어쓰기가 실제 원인인지는 제시되지 않음 | 같은 진단 원리인가, 더 추상적인 비유인가, 추가 근거가 필요한가 |
| `rebench-1228--literal_escaping` | f-string 중괄호 escaping 경험을 공백에서 잘리는 파일명 문제에 연결함. quoting/tokenization을 점검할 단서는 되지만 정확한 처리 경로는 제시되지 않음 | ‘구체적인 진단 후보’의 양성과 ‘원인이 동일함’을 구분할 수 있는가 |
| `rebench-1274`의 후보 16개 | 현재 내용은 IO 클래스 세 개의 테스트가 없다는 두 문장임. 네 후보는 미확인, 나머지 열두 후보는 다른 원리로 지정됨 | 원인을 모르는 상태에서 ‘다르다’는 판단과 ‘연결 근거가 없다’는 판단의 경계가 일관적인가 |

생성 코드는 질문별로 양성·미확인 목록을 명시하고 그 외 후보를 `different_mechanism`으로 기록함. 이것만으로 해당 음성이 전부 잘못됐다는 뜻은 아님. 다만 **양성 근거가 없다는 사실만으로 다른 원인임이 입증되지는 않음.** 새 안내에서 이 경계를 정의한 뒤 양성뿐 아니라 가까운 음성과 일부 일반 음성을 함께 검토해야 함.

기존 640쌍은 후보 단서라는 별도 과제로 보존함. 원리의 연결이 모호한 라벨을 반복 복제하여 새 기억 선택기의 주 감독으로 사용하는 것은 우선 보류하는 편이 적절함. 관련성·적용성·실제 효과를 한 번의 재판정으로 모두 채우지 않음.

## 3. 재검토 묶음은 유용하나 세 가지 보완이 필요함

준비 코드로 별도 임시 폴더에 재생성했으며 **생성 파일 5개가 원 묶음과 바이트 단위로 일치함.** 64개는 train 양성 18·미확인 23·음성 후보 23개임. 입력 문자열 보존·train 한정·빈 양식·기존 라벨 분리를 확인함.

1. **일반 음성도 일부 포함함.** 23개는 어휘 중복으로 선정한 후보이며 train 음성 391개의 약 5.9%임. 모호한 경계를 찾는 목적에는 적절하지만 전체 음성의 오류율을 추정할 표본은 아님. 첫 판정 이후 같은 train에서 남은 음성을 출처·길이별로 표집한 별도 점검을 권함. 기존 test를 기준 정비에 추가하지 않음.
2. **발췌 범위를 표시함.** 원자료 40질문 중 8개가 잘렸고, 이번 묶음에는 잘린 6질문에서 나온 15행이 있음. `rebench-1627`은 예외의 세부 내용 전에 로그 발췌가 끝남. 원래 발췌를 보존한 채 `clipped`와 관측 범위를 검토자에게 제공하고, 정보 부족을 기록하게 하는 편이 적절함. 전체 이슈를 복원한다면 새 입력 버전에서 다시 판정해야 함.
3. **안내문도 재생성에 포함함.** 현재 준비 코드는 `reviewer/README.md`를 새 출력 폴더에 만들지 않음. 저장된 묶음에는 안내문이 있지만 문서의 재생성 명령만 실행하면 판정 기준이 빠짐. 재생성 코드에서 안내문 버전·해시를 함께 복사하도록 보완할 필요가 있음.

기존 라벨을 본 검토자의 재판정을 맹검으로 부르지 않음. 두 검토자의 최초 판정·근거·이견을 보존하고, 합의하지 못한 사례는 미확정으로 남김. `null`은 미작성이고 `insufficient_connection`은 작성된 판단이라는 차이도 유지함.

## 4. 보완안의 불가능 판단 라벨은 수정해야 함

보완안은 `false_infeasibility`를 “충분한 근거 없이 불가능하다고 답함”으로 설명함. 다음 두 축은 분리해야 함.

- `unsupported_infeasibility`: 제공된 근거가 부족한데 NONE이라고 답함.
- `false_infeasibility`: 실제로 조건을 만족하는 선택지가 있는데 NONE이라고 답함.

기존 지침·동일 최대 전달 예산의 고유 상태–기억 묶음 **333개, 구성 요소 666개**에서 다시 집계함. 정책 이름만 다르고 전달 입력이 같은 경우는 한 번만 셈.

| NONE 출력 분류 | 구성 요소 수 |
| --- | ---: |
| NONE 전체 | 221 |
| 근거 부족 상태의 NONE | 154 |
| 위 154개 중 실제로도 불가능 | 26 |
| 위 154개 중 실제로는 가능 | 45 |
| 위 154개 중 공통 근거 자체가 없어 판정 미확인 | 83 |
| 근거 유무와 무관하게 실제 가능했던 NONE | 48 |

예를 들어 `015f64adf40542a3--case-0--changed`의 무기억 저녁 응답은 NONE임. 제공 근거는 부족하지만 실제 참조 식당도 이용 불가능하므로, 근거 없는 판단이면서 전역 정답은 맞은 경우임. 이를 ‘사실적으로 잘못된 불가능 판단’으로 학습시키면 정답 의미가 흐려짐.

이 수는 같은 12가족을 여러 행동으로 검사한 결과이며 독립 경험 수가 아님. 원래 성공 라벨을 수정하지 않고 행동 오류의 분해 필드를 별도로 둠. 실제 세계의 불가능·관측으로 확인된 불가능·관측 부족을 구분하는 것이 목적임.

## 5. 선택기 입력과 실제 감독을 연결해야 함

현재 [검색 코드](../../training/memory_selector/run_travel_state.py)는 `질문 + 기억 text`로 관계 점수를 만들고, 같은 질문의 현재 상태 네 가지에 그 점수를 재사용함. 현재 카탈로그·관측은 뒤의 [효용 판독층](../../training/memory_selector/train_travel_state_gate.py)이 제안된 상위4 묶음과 함께 읽음.

이 구조는 참조 검색과 고정 묶음 제공/보류를 검사하는 데 맞음. **현재 관측에 따라 후보 기억 자체를 바꾸도록 학습한 결과는 아님.** 따라서 데이터에 현재 상태를 추가하고도 선택기 입력에 넣지 않으면 원래 문제는 남음.

다음 핵심 비교의 입력은 `현재 질문 + 실제 현재 관측 + 같은 후보 기억`으로 고정함. 0.6B 학습 전·LoRA·4B·9B가 같은 정보를 받고, 전달 예산 안에서 기억 집합 또는 빈 집합을 선택하게 함. 여기서 ‘같은 정보’는 같은 한계 내의 관측을 뜻하며 미래 출력·효용 라벨을 미리 제공한다는 뜻이 아님. 기존 query-only LoRA는 이전 기준선으로 명시하고, 현재 상태를 포함한 학습의 효과를 별도로 비교함.

## 6. 이미 있는 행동 결과를 활용하되 추가 이득의 여지를 확인함

후속 기록에서 지침을 `original`로 고정하고 예산이 다른 `all`을 제외하면 다음과 같음.

| 측정 | 결과 |
| --- | ---: |
| 정책 행 | 672 = 96상태 × 7정책 |
| 중복 정책을 합친 상태–기억 묶음 | 333 |
| 고유 작업자 입력 | 309 |
| 원천 | 기존 12가족 |
| 행동에 따라 성공 여부가 달라지는 상태 | 30 |
| 최선의 고정 정책 | 55/96 |
| 상태마다 관측된 행동 중 최선을 고른 사후 수치 | 58/96 |
| 위 두 수치의 차이 | 3상태 |

따라서 기존 ‘상위4 제공/보류’ 96쌍보다 다양한 묶음 결과를 재사용할 수 있음. [행동 결과 색인](data/data-remediation-review-20261109/observed-bundle-index.jsonl)을 준비했으며, 각 입력·선택 기억·원 실행 ID·별칭 정책·성공·오류·비용을 연결함. 새 학습에 바로 투입하는 파일은 아니며 `learner_export_allowed=false`로 표시함.

58은 **기록된 행동들의 사후 최대치**임. 시도하지 않은 묶음이나 다른 작업자의 상한이 아님. 현재 기록 안에서는 단순 정책보다 성공을 더 올릴 여지가 작으므로, 이 자료의 승패로 학습 선택기의 일반적 가치를 판단하기 어려움. 성공이 같아도 근거 없는 구체적 선택 수가 달라지는 상태는 31개이므로 오류와 비용의 비교도 보존함.

새 수집은 실패 결과를 보고 유리한 사례만 골라서는 안 됨. 결과를 보기 전에 정보가 필요한 경우·현재에 이미 있는 경우·전제가 달라진 경우·일부 근거가 빠진 경우를 포함하는 규칙을 정하고, 중립·실패까지 모두 수집함. 개발에서 단순 정책의 성적과 관측 행동 간 차이를 확인하되, 확인 집합을 차이가 커 보이는 사례로 선별하지 않음.

## 7. 권장 실행 순서

1. **64개 재검토를 진행하며 판정 기준을 확정함.** 세 관계의 경계, 관측과 일반화의 구분, 근거 없는/사실적으로 잘못된 판단을 먼저 정리함. 새 라벨이 확정되기 전 원본의 진단 역할을 유지함.
2. **선택기 입력 계약과 행동 결과 형식을 고정함.** 질문·현재 관측·기억을 함께 읽게 하고, 실제 결과는 작업자·지침·snapshot·전달 묶음별로 기록함. 묶음 효과를 각 기억의 개별 효과로 복사하지 않음. 시도하지 않은 묶음의 결과는 미측정으로 둠.
3. **독립 원천 수집을 재검토와 병행함.** 같은 기억의 필요성·중복·적용 조건이 바뀌는 경우를 우선하고, 실제로 필요한 경우에만 복수 기억 결합을 추가함. 20–30부모 × 변형은 제작 목표이지 일반화가 충분한 표본 수는 아님. 같은 여행 틀을 더 만드는 것과 다른 경험 원천을 늘리는 것을 따로 집계함.
4. **기존 자료의 선택기 비교와 보완 자료의 확인을 구분함.** 기존 45계획·train12는 진단에 사용함. 새 원천의 분할·조건을 먼저 고정하고 0.6B/LoRA/4B/9B의 선택과 고정 작업자 결과를 평가함. 선택기 종류·데이터·작업자를 한꺼번에 바꾼 차이를 데이터 효과로 해석하지 않음.

보완안의 ‘무엇을 더 확인할지 학습’은 유망하지만 확인 도구·비용·상태 전이가 추가되는 별도 확장임. 첫 개선 회차는 **이미 가진 후보 중 무엇을 제공/보류할지**에 집중하는 편이 적절함. 순수 논리 과제의 점수나 worker의 UNKNOWN 교정이 주 연구 목표를 대신하지 않도록 함.
