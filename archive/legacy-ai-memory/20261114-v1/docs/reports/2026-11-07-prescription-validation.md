# 기억의 관찰·처방·적용 조건 분해 검증

2026-11-07 · 완료. SWE-bench Lite의 새 타깃 2개에서 네 조건을 각 4회, 총 32회 실행했다. 실제 경험 한 개의 내용 일부를 바꿔 성공률·미제출률·비용 차이를 계측하는 절차는 작동했다. **득실의 방향을 확정할 통계적 증거는 아직 부족하다.**

N은 무기억, F는 원문에서 처방 구간을 삭제한 관찰·검증 맥락, FP는 원문 처방 포함, FPA는 FP에 적용 조건을 추가한 것이다. 모두 시작 시 제공하며 자동 조회 비교는 아니다.

## 이 결과로 알 수 있는 것

**부분의 기여와 전체 기억의 순효과를 구분해서 측정할 수 있었다.** 관련 문제가 가까운 24213에서는 F→FP 성공이 1/4→3/4였고, 무기억은 2/4였다. 다른 문제에서는 전체 기억 조건이 모두 공식 0/4였다. 평균 숫자와 문제별 결과를 함께 보아야 한다. 대상의 가까움은 사전 가설이며 난이도와 분리해 무작위화한 요인이 아니다.

**같은 처방의 유리·불리한 변화 후보를 보조 지표에서 따로 볼 수 있었다.** F→FP에서 차원 동등성의 미제출은 3/4→1/4로 줄었지만 접두사에서는 1/4→3/4로 늘었다. 평균 미제출률은 둘 다 4/8로 같아 이 반대 방향의 변화가 상쇄됐다. 성공률은 +25%p였으므로 어떤 지표를 효용으로 정의하느냐도 중요하다. 미제출률 변화만으로 최종 과제 효용의 손해를 입증한 것은 아니다.

**적용 조건의 보조 지표 개선과 최종 성과를 구분했다.** FP→FPA에서 접두사 제출은 1/4→3/4로 늘었지만 공식 성공은 0/4 그대로다. 전체 제출은 4/8→6/8, 성공은 둘 다 3/8이다. 적용 조건이 최종 성공에 도움이 됐다는 증거는 이번 표본에서 얻지 못했다.

**미제출을 버리면 결론이 달라진다.** 공식 채점된 제출만 보면 FP는 3/4, FPA는 3/6 성공이어서 A가 성공률을 25%p 낮춘 것처럼 보인다. 그러나 전체 배정 기준은 둘 다 3/8이다. 이는 서로 다른 조건부 분모의 차이다. 원래 official_resolved=null을 보존하고, 공통 예산 안에서의 delivered_success는 미제출을 0으로 포함했다.

**초반 관측을 기억의 고정 성질로 라벨링할 수 없었다.** 24213에서 N은 처음 두 번 성공했지만 뒤 두 번은 미제출이었다. 첫 반복의 기억 세 조건도 모두 미제출이었으나, 최종 FP/FPA는 각 3/4 성공했다. 실제 첫 요청은 조건 안에서 네 반복 모두 같았다. 개별 실행의 득/실 라벨이나 기억의 항상 유익·유해한 성질을 만들 근거는 아니다.

## 실패·행동의 사후 진단

24213의 제출된 9개 패치는 모두 공식 통과했고, 그 문제의 나머지 7회는 10응답 소진으로 미제출이었다. 따라서 여기서 관측한 성공 차이는 이 예산 안에서 제출까지 마친 차이다. 작업 중 패치가 정답이었는지는 미제출 기록만으로 평가하지 않았다. 이를 수정 능력 자체의 차이로 단정할 수 없다.

접두사 문제에서 제출된 11개 패치는 모두 공식 `assert m * k is S.One` 검사에서 실패했다. 사후에 제출 패치의 7개 서로 다른 버전을 새 기준 컨테이너에 적용해 진단하니, 모두 `milli*W == W/1000` 등 값 수정을 통과했지만 숫자 취소의 SymPy 객체 정체성 검사와 `W*milli` 방향의 값 비교는 통과하지 못했다. 공식 점수 0이 수정 진척 0을 의미하지 않았다. 이 속성 검사는 첫 실패를 본 뒤 만든 진단으로, 사전 효용 지표나 새 성공 점수로 사용하지 않았다. 비제출 5회의 빈 패치는 원본 코드 대조일 뿐 작업 중 수정을 재구성한 것이 아니다.

기억 속 과거 `exp`와 `ohm/farad` 재현을 실제로 실행한 명령은 모든 조건에서 0이었다. 성공한 24213 패치는 `equivalent_dims`를 사용했고, 과거 Function 분기의 무차원 정규화를 그대로 추가한 제출은 없었다. 단순 검색 표지는 그 문제에서 모든 조건 4/4에 나타나 기억 채택 여부를 구별하지 못했다. 따라서 과거 검사를 그대로 따라 해서 예산을 소진했다는 초기 가설은 이번 직접 실행 표지로 뒷받침되지 않았다.

FP의 접두사 미제출 원본에는 현재 scale-factor 경로의 긴 조사, 자체 작성 검사 실패 후 수정, 통과한 로컬 검사 후 패치 파일을 만들고도 최종 제출 호출을 못 한 사례가 있었다. 이것이 기억 처방 때문에 생긴 인과 경로인지는 분리 검증하지 않았다. 환경의 rg 부재도 일부 호출에서 확인되므로 탐색 실패·도구 선택·검증 과다·제출 순서를 따로 기록할 필요가 있다.

원본 명령·호출 ID·패치 군집은 trace-review.json, 값/정체성 진단은 posthoc-property-diagnostic.json에 있다. 기본 test_action_count는 pytest/assert 같은 문자열 표지이며 코드 교체용 assert까지 포함할 수 있어 실제 검증의 완전한 계측으로 해석하지 않는다.

## 회고와 다음 검증

이번 파일럿은 구성요소 개입, 성공·미제출 분모, 비용 연결의 측정 가능성을 확인했다. 한 소스·두 타깃·네 반복·10응답만으로 어떤 기억 특성이 일반적으로 유익·유해한지는 판단할 수 없다. 작은 차이를 입증할 규모도 아니었다. 처음 계획에서 Requests를 제외하면서 문제 다양성과 정밀도가 더 줄었다.

1. 다음에는 모든 조건의 맨 끝에 동일한 제출/예산 안내를 둔다. 이번 N은 그 안내로 끝나지만 기억 조건은 뒤에 기억 954~1838자가 붙는다. 이 위치·길이 효과는 내용과 분리되지 않았다. prompt-placement-review.json은 관측과 가설이며 현재 프롬프트를 바꾸지 않았다.
2. 10응답과 더 여유 있는 예산을 별도 조건으로 두고, 모든 조건에서 중간 패치를 같은 시점에 저장한다. 첫 정답 패치 도달, 추가 검증, 실제 제출을 나누어 보아야 한다. 이번 6응답 소스 보정→10 규칙이 적절한 작업 난이도를 보장한 것은 아니다.
3. 동일한 함수명·수정 정보·검사 내용을 유지한 서술형/지시형 대조를 추가한다. P의 정보 포인터와 행동 지시, 검증 지시를 나누어야 어느 부분의 효과인지 좁힐 수 있다. 원문 procedure에서 P를 삭제한 F와 별도 facts 카드는 같은 조건이 아니다.
4. 소스와 카드 수를 늘리고 같은 타깃에 서로 다른 기억을 배정한다. 현재 가까운 문제와 먼 문제는 서로 다른 과제라 난이도와 적용성을 분리하지 못한다. 공통 유해 특성이나 유익한 기억을 고르는 정책은 소스까지 분리한 새 확인 자료에서 검증한다.

위 내용은 다음 회차 설계이며 추가 유료 모델 실행은 하지 않았다. 현재 데이터로 개별 기억의 유익/유해 정답 라벨을 확정하거나 카드 특성 예측기를 학습하지 않는다.

## 질문과 사전 가설

같은 실제 경험에서 관찰 F를 유지한 채 과거 해결 처방 P를 추가하면 후속 문제의 해결률·비용·행동이 어떻게 달라지는가? P에 적용 조건 A를 붙이면 달라지는가?

4조건은 N(무기억), F(관찰과 검증 맥락), FP(F와 원문 처방), FPA(FP와 적용 조건)다. 주 비교는 FP−F, 보조 비교는 F−N 및 FPA−FP다. P는 구체적 정보·길이도 추가하므로 순수한 명령형 문체 효과라고 해석하지 않는다. FA 조건이 없으므로 P×A 상호작용도 추정하지 않는다.

새 소스 SymPy 24066에서 실제 에이전트 실행을 한 번 수집한다. 성공·실패를 그대로 보존하며 성적에 따른 소스 교체나 재시도는 하지 않는다. 소스 전용 작성자가 해당 실행 기록으로 만든 procedure 카드를 사전 선택한다. 별도 facts 후보는 보관하되 이번 비교에 사용하지 않는다. 원문에서 P 구간을 정확히 지정하고 삭제한 F를 만들며, 공식 결과와 로컬 검증의 한계는 모든 기억 조건에 유지한다. 타깃 결과를 보고 기억을 고치지 않는다.

타깃은 SymPy 24213/24909다. 차원 수집 함수의 동등성 문제와 단위 접두사 곱셈 문제로, 원인이 가까울 것으로 예상한 문제와 약하게 관련된 문제를 하나씩 고른다. 이는 공개 문제·기준 코드에 따른 사전 가설이며 유익·유해 기억의 정답 라벨이 아니다. 선행 수정이 후속 기준 코드에 이미 포함되어 있으므로 처방을 그대로 복사하는 효과가 아니라 다른 분기·예외에 적응하는 전이를 본다. 공개 벤치이며 사전학습 오염 여부는 확인할 수 없다.

## 실행과 측정

2타깃 × 4조건 × 4회 = 32회. 원래 64회 배정의 SymPy 행만 남겼다. 배정표는 결과 전에 seed 2026110701로 고정했다. 각 타깃에서 조건별 실행 위치를 네 반복에 걸쳐 순환한다. 각 실행은 새 컨테이너이며 기억은 시작 시 한 장 제공한다. 모든 기억 조건의 카드 ID와 중립 안내를 통일하고 입력에서 내용 해시를 숨긴다. 첫 실제 API 요청 전체에서 F↔FP↔FPA의 지정 문자열 외 차이가 없는지 확인한다.

모델·도구·환경·제출 방식은 통일한다. 모든 타깃 조건에 동일한 응답 횟수 예산 안내를 준다. 소스 한 문제를 무기억 6응답으로 한 번 보정 실행하고, 공식 해결이면 타깃 예산 6, 그렇지 않으면 10으로 정한다. 이 축소 규칙도 첫 모델 호출 전에 고정했다. 타깃 모델 실행 전에 예산을 고정한다. 소스 본 실행은 최대 32응답이다. 보정·소스·작성자 실행은 타깃 효과 표본에 포함하지 않는다.

일차 결과는 공통 예산 안에서 공식 채점에 성공한 제출이다. 예산 소진으로 미제출이면 공식 판정은 null로 보존하고 전달 성공은 0으로 센다. 공식 회귀 실패, 전체 배정당 평균 API 비용·응답 수·시간, 실제 도구 호출과 패치·테스트를 보조 지표로 남긴다. 검색이나 기억 노출만으로 사용·손해·매개 인과를 주장하지 않는다. 적은 반복으로 API 비용의 유의성은 주장하지 않는다.

타깃별 성공률 차이를 동일 가중 평균한다. 고정된 과제·기억·모델·예산에서 반복의 조건부 독립을 가정한 양측 95% Hoeffding 구간을 사용한다. 타깃 2개, 조건당 각 4회이면 반폭은 약 67.9%p로 매우 넓다. 원래 네 타깃 설계의 48.0%p보다도 정밀도가 낮다. 이는 과제/소스 모집단의 신뢰구간도 세 비교의 동시 신뢰구간도 아니다. 작은 효과의 입증보다 측정 절차·큰 방향 차이·실패 기전의 탐색에 적합하다. 이전 연구의 분석법이나 보고서는 변경하지 않는다. [원 논문](https://www.tandfonline.com/doi/abs/10.1080/01621459.1963.10500830).

## 환경·비용·중단 규칙

SWE-bench Lite test revision 6ec7bb89b9342f664a54a6e0a6ea6501d3437cc2를 고정한다. 원본 이미지의 코드 blob은 기준 커밋과 같았으나 실행 비트가 달라 파생 이미지에서 정확한 기준 트리를 복원한다. 기준 이후를 가리키는 Git ref와 도달 불가 객체도 제거한다. 이전 실패와 이미지 ID는 보존한다. Requests 역사 커밋 하나의 badTimezone 진단은 원문을 남기고 해당 진단만 분리해 객체 무결성을 재검사한다. 소스·의존성 코드는 고치지 않는다. Requests 소스의 API상 merge SHA가 후속 기록에 없어 정확한 PR head의 조상 관계를 대신 검증하며 둘을 기록한다.

선정 가족의 소스와 타깃 모두 원본 코드 실패/정답 패치 성공 대조를 통과해야 모델을 실행한다. 최초 Requests 대조 실패로 해당 가족을 제외했고, 남은 SymPy 세 문제는 모두 통과했다. 두 타깃의 공개 로컬 테스트도 원본·정답 코드에서 네이티브 bin/test로 대조했다. pytest가 설치되지 않은 이미지에서 처음 진단이 실패한 기록도 보존했으며 의존성은 설치하지 않았다. 로컬 진단과 공식 채점은 구분한다. 정답 패치·채점 전용 테스트·소스 PR 설명은 소스 에이전트와 기억 작성자에게 주지 않는다. 에이전트 조사 컨테이너는 기존 2 CPU/4 GiB/네트워크 없음 설정, 공식 채점 대조는 채점기 기본 bridge/자원 제한 없음 설정이다.

추가 세션의 비용 중단 기준은 $1.50이며 응답/실행 후 확인하므로 엄격한 상한은 아니다. 과거 확인 비용은 $1.22385878464이고 초기 HTTP 404 1건의 비용은 미확정이다. 기존 사용자 승인 총 $10 이내를 유지한다. API 오류, 비용 누락, 환경 실패, 불완전 채점이면 중단하고 원인을 보존한다. 타깃 결과에 따른 반복 추가·재시도·문제 교체는 하지 않는다.

## 정보 접근과 해석 경계

소스 에이전트와 기억 작성자의 실제 입력에는 타깃 정답·채점 테스트를 넣지 않았다. 연구자는 공개 타깃 문제·기준 코드·원본/정답 대조 결과를 알며, 네이티브 실행기 문제를 진단하면서 SymPy 24213 eval-script의 추가 회귀 테스트 일부를 봤다. 따라서 연구자까지 타깃 채점 정보에 눈가림됐다고 주장하지 않는다. 적용 조건 A는 소스에서 실제 관찰한 Function 분기·무차원 판정 전제를 연구자가 명시한 문장이다. 접근 범위는 information-access-note.json, 작성자 입력은 원본 API 요청과 author-evidence.json으로 확인한다.

P 삭제로 남는 F는 별도 facts 카드가 아니라 원문 procedure의 문제 관찰·로컬 검증 결과·공식 결과·한계다. 구체적 함수 이름·수정법·재현 검사 상당수가 P에 들어 있으므로, FP−F는 그 묶음의 추가 효과다. ‘동일한 정보의 사실형/지시형 표현 차이’로 확장해 해석하지 않는다.

F−N은 F 본문 외에 공통 기억 안내·메타데이터·검증/주의 문구가 함께 추가되는 전체 제공 패키지 효과다. FP−F와 FPA−FP에서는 그 공통 부분을 그대로 유지한다. 기억이 시작에 노출된 것은 자동 조회·실제 채택을 의미하지 않으며, 이번 회차는 검색 시점·조회 도구를 비교하지 않는다.

available_at는 과거 소스 사건의 논리적 가용일을 나타낸다. 실제 소스 풀이·카드 작성은 2026년에 수행했다. 소스 수정이 타깃 기준 커밋보다 먼저 존재한다는 관계는 검증했지만, 당시 실제 온라인 에이전트가 기억을 축적한 시계열 실험을 재현한 것은 아니다. 모델의 사전학습에 타깃이 포함됐는지는 확인할 수 없다.
