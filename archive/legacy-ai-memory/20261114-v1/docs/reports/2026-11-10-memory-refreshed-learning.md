# 재측정 자료의 보강 효과와 선택 손실 비교

24회 학습과 실제 가중치 재검산을 완료함. **대조 자료를 보강하면 네 범주 분류 정확도는 개선되지만, 확장 후보에서 실제 선택 성공은 개선되지 않았음.** 학습 선택은 40–43/96 성공으로 검색 상위 2개·참조 규칙의 55/96보다 낮음. 악화 23개에 대한 held-family recall은 모든 조건에서 0이며, 기존 선택 손실의 안정적인 추가 이득도 확인하지 못함. 새 모델·임계값 탐색으로 결과를 덮지 않고 이번 비교를 종료함.

실행은 같은 12개 개발 가족의 탐색적 교차 분할임. 새 독립 출처 검증이나 MemoryArena 전체 작업 성공률로 해석하지 않음. [공유 결과와 재현 명령](../../evaluation/results/memory-refreshed-learning-20261110-v1/README.md), [후보 확대의 전체 상태별 변화](data/memory-refreshed-learning-analysis-20261110/pool-choice-changes.csv)를 함께 보존함.

## 학습 전 고정한 질문

[동일 환경 재측정](2026-11-10-memory-worker-refresh.md)으로 확보한 기억 후보에서, 추가 대조 자료와 기존 선택 손실이 작은 선택기의 실제 선택 결과를 개선하는지 비교함. 원래 237묶음과 확장 408묶음은 모두 같은 새 작업자 실행의 라벨임. 이번에는 추가 9B 작업자 호출 없이 저장된 상태–행동의 결과로 선택을 평가함.

| 자료 | 네 범주 분류 CE | CE + 기존 선택 손실 |
| --- | --- | --- |
| 원래 237묶음 | original_ce | original_select |
| 보강 408묶음 | augmented_ce | augmented_select |

각 조건은 기존 3가족 분할과 초기값 731·1729를 사용하므로 총 24회 학습임. 모든 조건을 고정 base에서 새로 시작하며 이전 adapter를 이어 학습하지 않음. 이전 12개 모델을 이번 표의 기준선으로 재사용하지 않음.

## 고정 설정과 실행 범위

- 선택기: `microsoft/harrier-oss-v1-0.6b`, revision `f9b9dc8d367d443f2479d27aa5d8d2850c0774ee`; q/v LoRA rank 8·alpha 16, 기존 128차원 MLP.
- 입력: 목표 + 현재 관측 + 제안 기억 묶음. 관계 비트·정답·정책명은 모델 입력에 추가하지 않음. 최대 2,048토큰이며 잘림 금지.
- 학습: 기존과 같은 8 epoch, fold별 64상태, 상태당 평균 CE, 4상태/update, 총 128 update. 학습률·손실 가중치·온도·microbatch·optimizer를 유지함. 실제 train/held 특징과 예측을 보존함.
- 선택: `P(개선)-P(악화)`가 0보다 크면 최상위 묶음을 제공하고 그렇지 않으면 보류함. 동점은 전달 토큰·예제 ID 순서로 결정함. 비용 가중치·임계값을 이번 결과에 맞춰 조정하지 않음.
- 평가: 네 조건 모두 같은 held-family 후보를 점수화함. 확장 후보 집합을 주 비교로, 원래 후보 집합을 보조로 보고함. 학습 마지막 epoch를 사용하며 결과가 좋은 초기값이나 checkpoint를 고르지 않음.
- 자원: 사용 중인 다른 학습 프로세스가 없음을 확인한 로컬 RTX 4080 SUPER 사용. 프로세스 메모리 상한 50%, 시작 및 다음 fit 전에 가용 메모리 7 GiB 이상 요구. 학습 전체 14,400초·실제 checkpoint 재검사 1,800초 상한. Colab·유료 API·새 작업자 실행 없음.

이전 원래 자료 12회 학습은 약 58분이었음. 추가 후보를 처리하는 이번 24회는 후보 수 비례의 거친 예상으로 약 2.6시간이며 속도를 보장하는 값은 아님. 예산은 이 관측을 참고해 실행 전에 고정함. 만료된 이전 회차의 06:00 마감은 재사용하지 않음.

상태 노출과 optimizer update는 맞추지만 보강 조건이 처리하는 후보와 토큰은 더 많음. 동일 계산량의 비교라고 주장하지 않음. 모든 파생 사례는 부모 가족과 같은 fold에 두며 새 독립 문제군은 0개임.

## 판정과 검산

주 결과는 같은 96상태에서 선택한 행동의 성공·악화·입력 근거 준수임. 분류 정확도·악화 precision/recall·상태 내 후보 순위는 그 원인을 살피는 보조 지표임. 무기억도 근거를 준수하며 성공한 상태를 망친 경우와, 근거 없는 정답 일치가 깨진 경우를 따로 보고함. 불필요한 제공·놓친 개선·전달 토큰과 모든 후보 점수화 비용도 보존함.

두 초기값의 효과 방향과 가족별 변화를 모두 보고함. 가족 단위 불확실성은 이미 분석한 12가족의 탐색적 기술값이며 독립 확증으로 부르지 않음. 단순 참조 규칙의 성공은 55/96, 관측 후보의 사후 최선은 58/96이므로 성공 수만의 개선 여지가 작다는 한계도 유지함.

입력·라벨·분할을 새 원자료와 대조한 후 학습함. 실제 노출·update·초기값·base 고정·adapter/optimizer 변화를 검사하고, 저장 특징/판독층의 독립 재계산과 실제 adapter 재적재를 구분해 수행함. 정책 선택은 실제 측정한 후보 또는 무기억에만 연결하고 미측정 행동의 성과를 채우지 않음.

학습 성적이 낮거나 추가 손실 효과가 없더라도 그 결과로 이번 네 조건 비교를 마침. 새 손실·모델·문턱 탐색을 자동으로 늘리지 않음. 현재 자료에 없는 실제 연속 진행·실패 이력, 새 출처 일반화, MemoryArena 전체 종단 성능은 이번 결과의 주장 범위가 아님.

위 내용은 실행 전 계획이며, 아래에는 문구 정정과 실제 결과를 추가함.

## 입력 계약의 문구 정정

고정한 protocol의 “IDs … are not neural inputs”는 너무 넓은 표현이었음. 예제·상태·분할 메타데이터와 결과 라벨을 별도 입력으로 주지 않는다는 뜻이며, 기존 텍스트에 `[memory_id]`로 표시된 **기록 식별자는 모델이 읽음**. 두 fit 완료 시 이 사실을 확인해 [정정 기록](data/memory-refreshed-learning-20261110/input-contract-clarification.json)을 남겼고, 입력·학습 설정은 바꾸지 않았음. 네 조건 모두 같은 식별자 형식을 사용하나, 식별자 변화에 견디는 학습을 입증하는 비교는 아님.

실행 전 계획의 원문은 공유 묶음의 `execution/pre-fit-report.md`에 보존함. 최종 결과를 덧붙인 이 문서와 원문을 구분하며, 원문 해시는 [학습 전 고정 기록](data/memory-refreshed-learning-20261110/pre-fit-freeze.json)으로 확인함.

## 지표 해석에서 구분할 내용

학습 중 `selection_regret`는 후보 점수와 무기억 점수에 softmax를 적용한 **확률적 선택의 기대 손실**임. 최종 평가의 `regret_sum`은 실제로 선택한 한 행동과 관측 후보의 사후 최선을 비교하는 **결정적 선택의 손실**임. 같은 수치가 아니며, 전자가 0이 되어야 후자가 좋아지는 것은 아님. 분류 확률로 만든 점수의 범위가 제한되어 있어, 정답 분류 확률을 넣어도 성과가 다른 후보가 함께 있으면 전자는 양수로 남을 수 있음.

현재 학습 라벨은 정답 일치의 득실임. 답에 필요한 근거를 준수했는지는 별도 평가하며, 무기억의 근거 없는 정답을 깨뜨린 경우와 근거를 준수한 성공을 깨뜨린 경우를 구분함. 이번 손실을 이미 근거 준수까지 최적화하는 목표로 해석하지 않음.

`input_contract_success`는 주어진 근거로 맞게 답하거나, 필요한 근거가 전달되지 않았다면 `UNKNOWN`으로 보류하는 입력 계약임. 사실 정답률과 정의가 다름. 규칙은 이 구성 자료의 참조 형식을 이용하므로 임의의 자연 과제에도 같은 성능을 보장하는 기준선은 아님.

작업 성공은 고정한 9B의 저장된 greedy 출력에 선택을 연결한 값임. 모든 행동을 여러 번 반복한 평균 효과나 실제 긴 에이전트 실행의 성공 확률을 추정한 것은 아님. 수집 시 4개 입력의 반복 일치는 좁은 실행 안정성 확인으로 유지함.

자료 보강에 따른 작업 성공 변화는 CE에서 **+1 / −1**, 선택 손실을 쓰면 **−2 / 0**임. 선택 손실의 추가 효과는 원래 자료에서 **+3 / 0**, 보강 자료에서 **0 / +1**임. 어느 비교에서도 두 초기값에 걸친 뚜렷한 성공 개선을 얻지 못했음. [가족 단위 쌍 비교](../../evaluation/results/memory-refreshed-learning-20261110-v1/paired-comparisons.json)도 함께 공개함. 12가족의 탐색적 불확실성으로, 유의한 일반화 효과의 증거로 삼지 않음.

## 무엇이 병목으로 남았는가

**후보 간 순위가 약함.** 성과가 다른 후보 비교 177쌍에서 순서를 맞힌 수는 원래 CE **65 / 84**, 원래 선택 손실 **66 / 90**, 보강 CE **86 / 85**, 보강 선택 손실 **92 / 88**임. 보강 후에도 약 절반 수준임. 실제 성과가 갈리는 4칸 대조 22묶음을 모두 분류한 수는 원래 조건에서 0, 보강 조건에서 1–2개임. 전체 정확도의 개선을 어려운 관계 판독의 해결로 해석할 수 없음.

**악화 감독이 충분히 학습·전이되지 않았음.** 평가 악화 23개는 6가족에 있지만, 모든 조건에서 정답 예측은 0개임. 원래 선택 손실·초기값 731만 악화를 3개 예측했으며 세 개 모두 오답이고, 다른 조건은 악화 예측 자체가 0개임. 보강 학습 자료에서도 악화 정답은 초기값별 3fold 합산 **7–16/46**에 그침. 여기서 46은 23행이 각각 두 fold의 학습에 들어간 중복 포함 분모임. 보강 모델의 개별 train 정확도도 73.6–87.1%로 완전 적합은 아님. 따라서 새 출처 문제만으로 설명하거나 모델이 망가졌다고 단정할 수 없음. [분할별 악화 지원 수](data/memory-refreshed-learning-analysis-20261110/analysis.json)를 보존함.

**보류와 비용은 현재 목표에서 약하게 다뤄짐.** 학습 선택은 92–95/96상태에서 기억을 제공하며, 근거가 없는 `missing` 상태에도 20–24/24회 제공함. 현재 목적함수는 정답 일치의 득실이고 비용 가중치는 0임. 모든 후보와 무기억이 실패하는 상태에는 선택 손실이 0이므로, 그 상태에서 불필요한 제공을 줄일 직접적인 선호가 없음. 이는 목적함수의 확인된 성질이며, 과다 제공의 유일한 원인이라는 인과 주장은 아님. 근거를 준수한 무기억 성공을 망친 수는 학습 선택 1–2개, 상태 참조 규칙 0개임.

## 같은 모델에서 후보만 늘렸을 때

| 학습 조건 | 원래 후보의 성공 | 확장 후보의 성공 | 후보 확대 후 성공→실패 |
| --- | ---: | ---: | ---: |
| 원래 자료 + CE | 52 / 54 | 40 / 42 | 13 / 12 |
| 원래 자료 + CE·선택 손실 | 54 / 54 | 43 / 42 | 11 / 12 |
| 보강 자료 + CE | 55 / 52 | 41 / 41 | 14 / 11 |
| 보강 자료 + CE·선택 손실 | 54 / 52 | 41 / 42 | 13 / 10 |

확장 집합에는 원래 후보가 그대로 남아 있고, 관측 후보의 사후 최선도 58/96으로 같음. 그럼에도 같은 가중치·문턱의 선택이 바뀌면서 10–14개 성공을 잃음. 반대 방향의 실패→성공은 원래 CE·초기값 731의 1개뿐임. 원래 후보에서의 52–55/96만 보면 드러나지 않던 선택 취약성이 확인됨. 이 비교는 새 후보 경쟁의 스트레스 진단이며 새 자연 출처의 난이도를 대표하지 않음.

사후 설명 예시는 `augmented_select`, 첫 초기값 731에서 조건별로 상태 ID가 가장 앞선 성공 회귀를 사용함. 좋은 사례나 checkpoint를 골라 주 결과를 만들지 않았으며, 전체 8조건×96상태의 변화는 CSV에 남김.

`0f5fff20dbab0a91--case-0--needed`는 Mason의 7일차 식당과 Emma의 **2일차** 숙소를 요구함. 원래 후보에서는 맞는 두 기록을 골랐지만, 확장 후보에서는 Emma의 **6일차** 숙소로 바뀜. 기억 수는 둘 다 2개, 전달 길이는 114 대 113토큰임. 단순 동점 처리로 바뀐 것이 아니라 잘못된 묶음의 점수가 더 높았음.

## 비용과 검산

전체 학습은 로컬 RTX 4080 SUPER에서 **146.3분**, 24모델 모두 8epoch·128update를 완료함. 6fit를 합친 학습 토큰은 원래 자료 조건당 8,578,048개, 보강 조건당 14,346,880개로 약 1.67배임. 최고 할당 GPU 메모리 3.40GiB, 예약 메모리 3.67GiB임. 실제 가중치 재검사는 4.23분이며 종료 후 GPU compute 프로세스가 없음을 확인함. 새 9B 작업자 호출·유료 API 호출·Colab 할당은 0임.

확장 후보의 모든 점수화에는 정책당 448,340 selector 토큰과 26.1–28.3초가 들었음. 선택한 기억만의 비용으로 축소하지 않았음. 전달 기억은 학습 선택 12,064–14,763토큰, 검색 상위 2개 10,495토큰, 상태 참조 규칙 5,166토큰임. 작업자 비용은 이전 L4 실측의 토큰을 연결한 값이므로, 로컬 선택기 시간과 합쳐 측정한 종단 지연이나 금전적 절감으로 보고하지 않음.

- 실제 base·초기 head/adapter·optimizer 128step·adapter 112개 tensor 변화를 24모델 모두 재검사함.
- 실제 checkpoint의 평가 예측 **3,264개**는 저장 벡터·확률과 정확히 일치하며, 원래/확장 후보의 선택 **1,536개**도 일치함.
- 저장 train/held 벡터와 head를 독립적으로 계산한 **8,424개** 확률의 최대 오차는 `1.83e-7`이며 분류가 모두 같음.
- 입력 토큰 ID **408개**, 동일 초기화·상태 노출·가족 분할·원시 작업자 **504개 라벨** 연결을 검산함.
- 로컬 관련 검사 **40개**, 결과 커밋 `f1d3bfc`의 새 clone 검사 **40개**를 모두 통과함(skip 0). 새 clone에서 README의 74행·444저장 예측과 분석 JSON·CSV 768행의 바이트 일치도 확인함. [명령·환경·로그](../../evaluation/results/memory-refreshed-learning-20261110-v1/fresh-clone-verification.json)를 보존함.
- 재적재 시 나온 Mistral regex 경고는 [별도 확인](data/memory-refreshed-learning-20261110/tokenizer-replay-check.json)함. 모델은 `qwen3`이며 재적재 tokenizer의 408개 입력 토큰 ID가 학습 당시와 모두 같음. 실행 중 regex나 토큰화를 변경하지 않았음.

공유 ZIP은 약 60.1MiB이며 저장 입력·예측·벡터·head·실행/검산 기록을 포함함. 실제 adapter·optimizer를 포함한 약 376.3MiB 전체 검토 묶음은 Git 밖에 보존하고, 위치와 해시를 [공유 안내](../../evaluation/results/memory-refreshed-learning-20261110-v1/README.md)에 기록함. CPU 검산과 실제 가중치 재실행의 요구 자료를 구분함.
