# 데이터별 상황과 학습 보완 검토

2026-11-11. **기존 자료는 근거 판독, 적용 조건, 상태별 필요성, 실제 제공 효과를 나누어 연구할 수 있는 기반임. 다음 보완은 자료의 역할을 유지하면서 빠진 관계 대조를 채우는 방향이 적절함.** 모든 자료를 하나의 유익/유해 이진 정답으로 합치지 않음.

API 적용성의 기존 학습/개발/시험은 각각 50/18/28상태이며 라이브러리 가족도 분리돼 있음. 실행 근거가 있다는 장점은 유지함. 4B·9B 작업자 결과는 같은 상태를 재사용한 조건별 효과이므로 새 독립 경험으로 합산하지 않음. Django 정보 조각 자료도 한 출처의 8상태 진단이며, 위 코드/API 계열의 작은 기전 진단으로 유지하는 것이 적절함.

**첫 번째 보완 지점은 비슷한 기억 사이의 구분임.** Mem2Act 학습 73질문의 후보 730개 중 604개가 다른 출처 그룹에서 옴. 승인한 정답 표현을 가진 다른 기록을 음성으로 넣지 않는 것은 잘못된 음성을 피하는 보수적인 설계임. 다만 그 결과 같은 ID가 다른 사람에게 속하거나, 같은 숫자가 다른 필드를 뜻하는 어려운 관계는 충분히 시험하지 못함. ‘다른 출처’가 반드시 쉬운 후보라는 뜻은 아니며, 실제 난이도는 별도로 측정해야 함.

PersonaMem 학습 54질문의 후보 540개 중 54개만 양성 주석이 있고 486개는 미주석임. 현재 코드는 이를 음성으로 강제하지 않아 적절함. 그러나 이 과제에서 좋은 분류 점수를 얻어도 같은 사용자의 여러 비슷한 기억을 잘 골랐다는 뜻은 아님. 원문 한 발화의 필요/중복 구분과 후보 전체의 검색 성능을 별도로 보고해야 함.

**두 번째 보완 지점은 부분 정보와 기억 조합임.** 120출처 학습의 127질문 중 감독 대상 정보가 있는 123질문은 모두 기록 하나로 주석한 정보를 공급할 수 있음. 여기에는 PersonaMem의 개인화 맥락도 포함되므로 모두를 필수 사실이라고 부르지는 않음. 나머지 4질문은 검토된 사실 목록이 비어 있음. 여러 필드를 요구하는 Mem2Act 8질문도 현재는 한 기록이 모든 필드를 포함함. 최근 BEAM도 학습 13·개발 13질문 모두 필수 근거 그룹이 하나임.

따라서 이 두 자료만으로 `A는 부족, B도 부족, A+B는 충분`을 학습했다고 주장하기 어려움. 여행에는 여러 참조 기록을 결합하는 자료가 있으므로 그 구조를 활용하되, 고정된 사람·날짜·슬롯 규칙 밖으로 넓혀야 함. 원문에서 실제로 분산된 근거를 찾는 수집과, 출처를 표시한 통제 분절을 구분해 보강할 수 있음. 원문 분절로 만든 두 조각은 새 경험 두 개로 세지 않음.

**세 번째 보완 지점은 상태 종류와 정답의 강한 결합임.** 최근 BEAM 학습과 개발에서 `known/updated`의 양성 라벨은 모두 0임. 기확보 상태는 각 13질문 모두 주된 과거 근거를 그대로 복사함. 숫자 갱신은 두 분할 모두 증가 12·감소 1건이며, 같은 값 유지 사례는 없음. 개발에서는 과거 범위의 필요성을 미확정으로 남긴 질문이 3개 있지만 학습에는 해당 경우가 없음.

이는 현재 정의한 좁은 대조에서는 자연스러운 정답 구성임. 다음에는 정보가 새로 보이더라도 다른 대상·속성의 정보이거나 필요한 항목 일부만 채우는 경우를 추가해야 함. 증가·감소 양방향, 같은 값의 재확인, 무관한 최신 기록도 포함하면 단순한 ‘새 관측이 있으면 보류’나 수치 크기 신호를 점검할 수 있음. 새로 만든 수치와 상태는 통제 증강으로 명시하고 원문 사실인 것처럼 저장하지 않음.

**전달 예산이 실제 선택을 요구하는지도 데이터마다 다름.** 고정 작업자 tokenizer와 각 실험의 전달 형식으로 다시 세면 Mem2Act 학습 73은행 중 69개, 개발 15은행 중 12개는 후보 전체가 512토큰 안에 들어감. PersonaMem은 학습 54·개발 16은행 모두 예산을 넘지만, 후보 대부분이 미주석이라 묶음의 충분성을 비교할 정답이 부족함. BEAM 학습·개발은 각각 8/13·7/13은행이 전부 들어감. 예산 내 전체 전달을 계속 기준선으로 두고, 같은 주제의 여러 유효·무효 기록 때문에 실제 선택이 필요한 은행을 수집해야 함. 인위적 문장 채우기로 길이만 늘리지 않음.

**네 번째 보완 지점은 학습 가중치와 데이터 역할임.** 기존 코드처럼 상태마다 같은 총 가중치를 주고, 양·음성이 함께 있는 상태 안에서 절반씩 나누면 다음과 같음.

| 학습 자료 | 양성에 배정되는 명목상 손실 가중치 비중 |
| --- | ---: |
| 120출처 자료 전체 | 46.5% |

이는 상태별 동일 가중치에서의 계산이며 실제 gradient 크기나 optimizer 궤적을 측정한 값은 아님. PersonaMem은 후보 하나만 감독하므로 필요한 상태에서는 양성만, 기확보 상태에서는 음성만 학습함. 최근 BEAM은 절반의 상태가 모두 음성이어서 제공을 억제하는 감독 비중이 커짐. 이후 보류가 늘어난 현상의 원인 후보이나 인과적으로 확정할 수는 없음. 데이터 혼합, 관계 감독 분리, 개발 자료의 임계값 보정을 비교할 근거는 됨.

**실제 득실 자료는 관계 자료와 다른 방식으로 활용해야 함.** 최근 여행 재측정의 408묶음은 12가족·96상태에서 나왔고, 묶음마다 관측된 성공이 달라지는 상태는 28개임. 261묶음은 어떤 측정 묶음을 골라도 결과가 같은 상태에 속함. 결과는 둘 다 실패 172, 둘 다 성공 139, 개선 74, 악화 23묶음임. 중립 311묶음을 무조건 버리면 필요 없는 개입과 실패 상태의 보정을 배우기 어려워짐. 같은 상태의 순위 손실은 결과가 다른 묶음에 적용하고, 중립 상태는 절대 성공·보류·비용 평가에 남기는 구분이 적절함. 한 번의 고정 작업자 결과를 모든 모델에 통하는 효용 정답이나 성공 확률로 취급하지 않음.

[검토 목록 15개](data/data-scenarios-review-20261111/review-queue.jsonl)에 사례·범위·조치를 남김. 새 학습 정답은 모두 `null`이며 독립 검토 완료를 의미하지 않음. 개발 사례는 이미 관찰한 문제의 분석용이고, 이를 수정한 변형을 새로운 독립 시험으로 세지 않음.

**학습에 먼저 반영할 후보는 세 가지임.**

1. **관련 정보 판독과 현재 제공 필요성을 나눠 학습함.** 같은 정보는 현재에 이미 보여도 질문과 관련 있다는 관계 자체는 유지됨. 기존 관계·관측·분기 주석을 활용해 ‘어떤 요구와 연결되는가’와 ‘현재 부족한 정보를 보충하는가’를 별도 출력으로 둠. 공통 encoder와 작은 출력층으로 비교할 수 있음. 미주석은 손실에서 제외하고, 관계 모순을 실제 손해 라벨로 바꾸지 않음. 비교는 현재 단일 출력과 같은 입력·학습량에서 수행함. 새 학습이 기존 검색 순위와 필요한 근거 확보를 보존하는지도 함께 봄.
2. **의미 유지 쌍과 판단 변화 쌍을 함께 학습함.** 현재 관측의 바꿔쓰기는 판정이 유지돼야 하고, 주체·필드·완료 상태의 실제 변경은 판정이 달라져야 함. 같은 부모 사례 안에서 양쪽의 절대 분류와 상대 순위를 함께 평가함. 과거 대조 손실이 줄어도 두 판정을 모두 맞히지 못했던 문제가 있으므로 상대 점수 차이만 학습하지 않음. 양·음성 개수와 길이를 통제하고, 필수 사실이 달라진 변형은 라벨도 다시 검토함.
3. **이전 관계 자료를 함께 학습하고 제공 기준을 따로 검증함.** 최신 BEAM만 추가 학습하는 조건과 이전 출처 관계를 섞는 조건을 비교함. 부모 출처의 노출과 총 업데이트 수를 맞추고 단순 반복에 의한 데이터 증가로 주장하지 않음. 가중치 조정과 임계값 보정은 별도 비교로 두며 개발 자료에서 정함. 현재 과제의 오판 감소와 이전 과제의 근거 확보 유지가 함께 필요한 평가 항목임.

묶음의 충분성을 판단하는 출력층은 보완할 가치가 있지만, 먼저 단독 기록으로는 부족하고 조합으로 충분한 정답을 마련해야 함. 새로운 출력층을 붙이는 것만으로 그 감독이 생기지는 않음. 실제 효용 예측도 관계 감독의 대체 목표로 일괄 적용하지 않고, 효과가 측정된 상태·작업자·행동 조건에서만 별도 평가하는 것이 적절함.

학습 과정에 적용 조건을 명시하고 중간 판단을 교정해 최종 선택 변화를 보는 방식은 [Concept Bottleneck Models](https://proceedings.mlr.press/v119/koh20a.html)의 개입 가능한 중간 개념에서 참고할 수 있음. 프로젝트에서 이미 시도한 개념 병목 자체를 새 아이디어로 주장하지 않으며, 이번 후보는 데이터의 검토된 속성을 분리 감독하고 오류를 추적하는 데 초점을 둠. 의미를 보존하는 변화와 판정이 달라져야 하는 작은 변화를 구분하는 설계는 [CheckList](https://aclanthology.org/2020.acl-main.442/)와 [Contrast Sets](https://aclanthology.org/2020.findings-emnlp.117/)를 참고함. 이 논문들이 우리 자료의 효과를 보장하는 것은 아님.

이미 실행한 옛 수치 가림을 새 개선안으로 반복하지 않음. [가림 실험](2026-11-11-external-update-masking.md)에서는 일부 오답이 복구됐지만 보류가 늘어 전체 정답이 감소했음. 필요한 맥락과 낡은 값이 한 기록에 섞여 있다는 점은 주석 축으로 남기되, 가림·삭제의 효용은 실제 출력으로 다시 확인해야 함.

**다음 데이터 버전은 기존 원문과 분할을 보존하면서 네 부분을 갖추는 것이 적절함.** 출처와 판단 시점, 모델에 허용되는 현재 상태·기억, 검토된 관계와 미확정 항목, 별도로 측정한 작업자 결과임. 관계에는 같은 대상/필드인지, 현재 이미 있는지, 조건이 여전히 맞는지, 어떤 부족한 근거를 공급하는지를 가능한 범위에서 기록함. 모두를 완전 주석하려고 미확정을 억지로 음성으로 만들지 않음.

수집은 같은 사용자·같은 주제 안에서 주체/필드/시점이 갈리는 원문과, 여러 기록에 근거가 분산된 사례를 우선함. 기존 정확 복사·먼 출처 대조는 기능 점검과 비교 기준으로 남김. 새로운 부모 출처를 먼저 나누고 그 안에서 증강하며, 한 부모의 변형 수와 독립 출처 수를 분리해 보고함. 효과가 큰 상태만 평가에 남기지 않고 어려운 진단 조건과 고정 수집 분포의 평가를 별도로 유지함.

이번에 완료한 것은 데이터 구성 재집계, 생성·주석 규칙 검토, 사례별 보완 목록과 학습 비교안임. 새 모델 학습·GPU·작업자/API 호출·확인 분할 추론은 수행하지 않음.
