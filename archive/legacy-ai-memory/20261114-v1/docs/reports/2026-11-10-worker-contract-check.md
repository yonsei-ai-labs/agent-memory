# 작업자 계약 점검: 근거를 쓰게 하면 정보 부족을 구분하는가

**근거 ID·판단 상태·답변을 함께 출력하는 보완안은 부분 효과만 보였으며, 사전 통과 기준을 충족하지 못함.** 확인 자료에서 정보 부족 정답은 0→6/24로 늘었지만, 풀 수 있는 항목은 24→20/24로 감소함. 이 보완안을 채택해 실제 기억 득실 데이터를 확대하거나 선택기를 학습하지 않았음.

이번 비교는 메모리 선택기의 학습이 아니라 **고정 작업자의 기본 기능 점검**임. [공유 결과·CPU 재현](../../evaluation/results/memory-worker-contract-20261110-v1/README.md), [동결 자료](../../datasets/worker_contract/20261110-v1/README.md), [현재 연구 상태](../current-status.md)에 연결함.

## 왜 이 점검을 먼저 했는가

기존 득실 자료에서는 규칙 선택이 55/96, 측정 후보의 사후 최선이 58/96이었음. 규칙의 실패 41상태 중 38개는 측정한 어떤 행동을 골라도 실패였음. 선택기의 성능을 해석하기 전에, 필요한 정보를 줘도 작업자가 조건을 적용하지 못하거나 정보 부족을 표현하지 못하는 문제를 확인할 필요가 있었음.

이전 기능 점검의 정보 부족 정답은 기존·강화 지침 모두 0/24였음. 이번에는 새 손실함수·모델 크기 비교 대신, 기존 출력 방식과 근거를 명시하는 **한 보완안**만 비교함.

## 실행 전에 고정한 조건

- 작업자: 기존과 같은 `Qwen/Qwen3.5-9B`, revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a`. 실제 가중치 4파일·모델 config 해시가 기존 작업자와 일치함. BF16·SDPA·greedy·thinking 비활성, 신경망 학습 없음.
- 자료: 기존 36개 기능 문제와, 이름·날짜·가격·ID·표현·기록/카탈로그 순서를 바꾼 확인 36개. 각 묶음의 항목 정답은 정답 가능·불가능·정보 부족 각각 24개임. 같은 부모의 변형이므로 새 독립 출처가 아님.
- 기본 방식: `{"dinner":"ID","accommodation":"ID"}`.
- 보완안: 각 항목에 `evidence`, `status`, `choice`를 출력함. 정보 부족은 `UNKNOWN`, 충분한 근거로 불가능이 확인되면 `NONE`을 사용하도록 지시함. 시스템 지침과 출력 형식을 함께 바꾼 인터페이스 비교이며, 형식만의 인과 효과로 부르지 않음.
- 두 방식의 사용자 입력·사실·기록 ID는 동일함. 과거 점검과 달리 양쪽 모두 불투명한 근거 ID를 표시하고 출력 상한은 공통 256토큰으로 둠. 기존 결과를 새 기준선으로 재사용하지 않음.
- 정답·자료 구분·조건명은 업로드하지 않음. 72문제의 사실로 정답을 계산하고 기존 36개 정답과 대조함. 정보 부족 48항목은 **동일하게 보이는 입력에서 서로 다른 두 과거 상황에 따라 답이 달라짐**을 확인함.
- 본 실행 144개와 사전 지정 안정성 반복 2개, 전용 L4 한 회차. 코드·입력·판정은 실행 전 커밋 `f05e08c`에서 고정함. 결과를 본 프롬프트 수정·추가 호출은 없음.

입력은 최대 428토큰/668토큰이며 잘림 없이 실행함. 정답 생성·입력 분리·가짜 인용 검출·인터럽트 후 종료 시도를 포함한 검사 7개를 실행 전에 통과함.

## 확인 자료 결과

각 정답 종류의 분모는 **항목 24개**, 두 답 동시 정답의 분모는 **문제 36개**임.

| 지표 | 기본 방식 | 근거·상태·답변 |
| --- | ---: | ---: |
| 풀 수 있는 항목의 정답 | 24/24 | 20/24 |
| 불가능 항목의 `NONE` 정답 | 11/24 | 12/24 |
| 정보 부족 항목의 `UNKNOWN` 정답 | 0/24 | 6/24 |
| 두 항목 모두 정답 | 9/36 | 12/36 |
| 정보 부족인데 구체 ID를 답함 | 24/24 | 13/24 |
| 정보 부족인데 불가능으로 답함 | 0/24 | 5/24 |
| 형식 오류 / 출력 한도 도달 | 0 / 0 | 0 / 0 |

확인 문제의 쌍 비교는 개선 6·악화 3·둘 다 정답 6·둘 다 오답 21개임. 기존 36문제에서는 두 답 동시 정답이 **10→8/36**, 정보 부족 정답은 **0→0/24**였음. 확인 변형에서의 개선을 안정적인 전체 개선으로 해석하지 않음.

확인 자료의 정보 부족 개선 6개는 모두 **같은 장소 재사용 조건**에서 나왔음(6/12). 가격 비교 조건의 정보 부족은 여전히 0/12임. 이름·표현·수치·순서를 함께 바꿨으므로 어느 한 요소가 차이를 만들었는지는 이 실험으로 구분할 수 없음.

필요한 참조가 실제 있는 48항목에서는 보완안의 근거 ID 인용이 모두 맞았음. 그러나 이것만으로 현재 조건을 올바르게 적용하지는 못했음. 참조가 없는 24항목에서는 빈 근거 목록을 맞게 낸 것이 6개뿐임. 두 기록에서 항목의 ID를 복사하는 능력과, 사람·날짜까지 맞는 근거인지 판단하는 능력을 구분해야 함.

## 원문에서 확인한 실패

[사례별 입력·정답·실제 출력](../../evaluation/results/memory-worker-contract-20261110-v1/case-review.json)을 보존함. 아래는 사후 설명용 사례이며 독립 주석 표본이 아님.

- **다른 사람의 기억을 근거로 사용함.** Mira의 숙소를 묻지만 주어진 숙소 기록은 Zoe의 것임. 보완안은 그 기록 `E27`을 인용하고 `H735`를 답함. 필요한 사람의 기록이 없다는 판단이 해결되지 않았음.
- **참조는 맞지만 현재 가격 조건을 위반함.** 과거 숙소 가격은 200, 현재 같은 숙소는 280임. 가격 180인 대안은 이용 불가이므로 정답은 `NONE`인데, 맞는 과거 근거를 인용하고 현재 가격 280의 숙소를 선택함.
- **두 항목의 조건을 따로 적용하지 못함.** 식당은 이용 불가지만 숙소는 이용 가능한 문제에서, 두 항목 모두 `NONE`으로 답함.
- **일부 정보 부족 판단은 개선됨.** Mira의 식당 기록 대신 Zoe의 기록만 있는 확인 문제에서는 식당을 `UNKNOWN`으로 보류하고, 근거가 있는 숙소는 정상 선택한 사례도 있음. 이 성공은 위 전체 실패와 함께 보존함.

형식 오류·잘림은 없었고 실제 입력/출력 토큰과 파싱도 일치함. 이 범위에서는 저장·파싱 실패로 결과를 설명할 근거가 없음. 다만 thinking 비활성·고정 지침에서의 결과이며 모델의 최대 능력이나 모든 인터페이스의 한계로 일반화하지 않음.

## 판정과 비용

사전 기준은 정보 부족 정답 20/24 이상 및 기본 방식 대비 개선, 정답 가능 22/24 이상, 불가능 20/24 이상, 알려진 조건의 정답 감소 2/48 이하, 필요한 근거 인용 44/48 이상, 형식 오류 1/36 이하·잘림 0·반복 안정성이었음.

보완안은 **정보 부족 정확도·정답 가능 정확도·불가능 정확도·알려진 조건의 정답 유지**를 통과하지 못함. 알려진 조건 정답은 기본 35/48에서 보완 32/48로 줄었음. 근거 인용·형식·잘림·반복 안정성은 통과했으나 전체 승격 조건은 실패임.

| 본 실행 72문제씩의 비용 | 기본 방식 | 근거·상태·답변 |
| --- | ---: | ---: |
| 입력 토큰 합계 | 29,754 | 47,034 |
| 출력 토큰 합계 | 1,230 | 6,886 |
| GPU 생성 시간 합계 | 99.6초 | 510.4초 |

같은 L4의 생성 시간은 약 5.1배, 출력 토큰은 약 5.6배였음. 전체 controller는 13.5분, 작업자 스크립트는 모델 로딩 포함 12.5분임. 관측 잔액은 558.10→557.53 CU로 0.57 CU 감소함. 결과 회수 후 전용 세션 종료를 확인했고 이후 활성 세션·사용률은 0이었음. [자원 기록](../../evaluation/results/memory-worker-contract-20261110-v1/resource-accounting.json)을 보존함.

146개 실제 입력/출력 토큰·파싱·정답 연결을 CPU에서 재생했고 두 반복의 입력·판정이 일치함. GPU에서 가중치를 다시 실행한 검사는 아님. 정보 부족에 대한 올바른 `UNKNOWN` 응답도 실제 여행 작업 완료 성공에 더하지 않았으며, 기존 408개 득실 라벨을 이 결과로 고치지 않았음.

## 다음 단계에 주는 의미

이번 확인으로 ‘답에 근거 ID만 붙이면 작업자의 문제를 해결할 수 있다’는 가정은 지지되지 않았음. 관계 판독과 최종 활용의 간격을 별도로 측정해야 한다는 기존 방향은 유지됨.

현재 보완안으로 대규모 효용 라벨을 수집하거나 선택기 학습을 재개하지 않음. 새로운 프롬프트를 계속 탐색하는 대신, 다음 단계에서는 **검증 가능한 관계·충분성 정답과 작업자의 실제 결과를 분리한 상태×기억 대조**를 먼저 설계해야 함. 그 자료에서 작업자가 근거를 활용할 수 있는 범위와, 선택을 바꿔 실제로 개선할 수 있는 범위를 확인한 뒤 학습 규모를 정하는 것이 적절함. 이번 작은 기능 점검의 부정 결과를 기억 선택 연구 전체의 기각으로 해석하지 않음.
