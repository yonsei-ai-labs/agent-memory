# 관련성과 현재 필요성을 나누는 학습 비교

2026-11-11. 원문 근거를 재검토한 통제 대조에서 추가 학습의 관계 판독 개선을 확인함. 관련성 보조 손실은 불필요 제공을 줄이지만 필요한 기억 누락도 늘려, 단일 학습보다 일관되게 우수하다고 판단하지 않음.

출발점은 “같은 경험에서 무엇을 제공하면 득이 되고, 무엇을 생략해야 하는가”임. 직전 데이터 리뷰에서 발견한 전부 알려짐/전부 모름의 단순한 상태 구분을 보완함. 원문에서 확인한 서로 다른 속성을 나누고, 현재 관측된 속성을 바꾸어 같은 기억의 필요성이 달라지게 함.

학습 18출처·20질문·246상태, 개발 8출처·8질문·100상태를 구성함. 원문 80구간을 사용하며 새 자연 경험을 추가한 것은 아님. 여러 기억을 합쳐야 충분한 상태를 포함하되 전체 은행 제공도 같은 512토큰 상한에서 비교함. 자세한 출처·주석 범위는 [자료 설명](../../datasets/memory_incremental_evidence/20261111-v2/README.md)에 기록함.

학습은 기존 source-scale train-60 Harrier 0.6B 체크포인트에서 동일하게 시작함. 기존 q/v LoRA와 128차원 판독층을 계속 학습함. 필요성 출력과 관련성 출력은 공통 은닉층을 사용함.

| 비교 | 손실 |
|---|---|
| single | 현재 필요한 기억의 상태별 균형 교차엔트로피 |
| dual | single + 0.5 × 요청과 관련된 기억의 교차엔트로피 |
| dual_replay | dual + 0.5 × 기존 자료 80출처의 필요성 교차엔트로피 |

세 방법 모두 새로운 예제·업데이트 수·초기화·복습 자료의 순전파를 같게 유지함. 사용하지 않는 보조 손실의 계수를 0으로 둠. 시드 731·1729, 2epoch의 마지막 체크포인트로 고정하며 개발 결과로 epoch나 임계값을 다시 고르지 않음. 이전 학습 80출처 복습과 이전 개발 자료 재평가를 통해 새로운 상태 학습과 기존 필요 기억 보존의 상충을 확인함.

여기서 `replay`는 기존 **자료**를 섞는다는 이름임. 80출처 중 초기 train-60 체크포인트가 학습했던 출처는 41개이고 나머지 39개는 당시 학습하지 않았던 train-120 자료임. 따라서 순수한 망각 방지 효과와 추가 출처 감독의 효과를 분리하는 실험은 아님. 새 대조 18출처 중에서도 초기 체크포인트가 학습한 출처는 8개임. 결과에서는 ‘기존 자료 혼합’으로 표현함.

선택 평가는 필요성/관련성 분류, 누락 필드 완전 확보, 불필요 제공, 상태 변경 쌍의 동시 정답, 표현 변화 일관성을 보고함. 작업 평가는 고정 Qwen3.5-4B가 요청 필드를 JSON으로 복원하는 성적임. 무기억·BM25·임베딩 검색·문자열 중복 제거·전체 은행·검토된 근거 진단·모든 학습 정책을 같은 현재 상태에서 비교함. 실제 도구 호출이나 전체 원래 작업의 성공을 뜻하지 않음.

개발 출처는 과거에도 본 자료이고, 상태는 통제된 작성물이며, 단일 검토자의 필드 주석임. 따라서 새로운 자연 출처 일반화나 실제 에이전트 성공 개선의 입증으로 해석하지 않음. 단순 기준선이 잘하는 경우도 그대로 보고함. 기존 모델·고정 자료·미개봉 BEAM 확인 집합은 보존함.

실행 전 원문 위치·값·출처 분리·부분 관측 라벨을 검산했으며, 최종 관련 CPU 테스트 23개가 통과함. 고정 설계는 [protocol.json](../design-data/memory-incremental-evidence-20261111-v2/protocol.json)에 보존함.

v1 실행 중 원문 전체를 다시 읽어 qa_351의 주석 문제를 발견함. 원문은 USD와 EUR 사이 예측을 요청했을 뿐 기준통화/상대통화 방향을 명시하지 않았음. 자동 인용·값 검산으로는 이 의미 오류를 발견하지 못했음. 단일 학습 1개와 두 번째 학습의 일부를 실행한 시점에 중단하고 파일을 보존함. v2에서는 방향 없는 통화 쌍과 기간으로 바꾸고 동일 초기 가중치에서 전체 비교를 다시 실행함. 개발·복습 파일은 그대로이며, v1 예비 성적은 최종 비교에 합치지 않음. 변경 이유는 원문 근거이며 성적을 보고 예제를 골라낸 것이 아님.

28질문 모두에 대해 [원문 재독 검토표](../design-data/memory-incremental-evidence-20261111-v2/source-reading-review.jsonl)를 남김. 역할·주체·범위를 확인하고, 원래 과제보다 좁힌 부분도 명시함. 예를 들어 공항은 IATA 코드가 아니라 원문 공항명만 복원하고, 영화 사례는 필드 설명에 영화명을 밝혀 원래 지시 대상 추론을 단순화함. 이는 같은 에이전트의 재검토이며 독립 사람 검토를 대신하지 않음.

실제 작업자 호출 전 입력 검사에서 내부 필드 키 `meaning`·`signifier`가 정답 단어를 노출할 수 있음을 확인함. 모든 작업자 입력과 채점 키를 `field_1`, `field_2` 형식으로 익명화함. 선택기는 목표·관측·기억 본문만 읽으므로 해당 키를 받지 않았고 학습에는 영향이 없음. [수정 기록](../design-data/memory-incremental-evidence-20261111-v2/worker-schema-amendment.json)을 보존하고, 수정 전 작업 입력은 실행하지 않음.

## 관계 학습 결과

아래 범위는 시드 731·1729의 두 결과임. 개발 100상태는 8출처·8질문의 통제 변형이고, 두 렌더링 중 관측 없음은 동일 입력임. 고유 맥락은 92개이며 독립 표본 단위는 8출처임. 관계 점수는 출처별 balanced accuracy의 평균임. 선택 정책은 모든 학습에서 점수 0.5로 고정함.

|---|---:|---:|---:|---:|

불필요 제공은 주석상 현재 필요하지 않은 기록 수이며 실제 손해 건수가 아님. 기존 판독기의 불필요 제공이 적었던 데에는 많은 필요한 기억도 보류한 영향이 있음. 학습 732쌍을 각각 2회 모두 사용했고 모델별 업데이트는 124회임. 학습 자료 판독은 99.7–100%로 적합됐지만 개발 성적과 구분함.

같은 상태에 양성·음성이 함께 있는 56상태의 104개 순위 대조에서는 기존 73.1%→모든 추가 학습 100%임. 다만 모든 후보가 필요한 상태는 이 순위 지표에 포함되지 않음. 관련 기록 두 개를 올바르게 순위화해도 하나의 점수가 제공 기준보다 낮으면 전체 근거 확보에는 실패함. 높은 순위 점수를 완전한 필요성 판독으로 대체하지 않음.

## 이전 자료 보존과 남은 약점

| 방법 | 이전 source-scale 개발 관계 점수 | 이전 BEAM 개발 관계 점수 |
|---|---:|---:|
| 기존 고정 판독기 | 93.6% | 71.1% |
| 단일 필요성 학습 | 94.1–94.2% | 75.6–77.5% |
| 관련성 보조 학습 | 91.6–92.8% | 83.3–85.0% |
| 보조 학습+기존 자료 혼합 | 92.1–92.3% | 83.1–85.1% |

source-scale 점수는 기존 평가 계약대로 도메인별 출처 평균을 다시 평균한 값이고, BEAM은 출처별 평균임. 데이터 간 점수 크기를 직접 비교하지 않고 같은 자료의 전후를 비교함. BEAM 라벨은 이번 학습·혼합에 사용하지 않았음. 이 결과는 이전에 검토한 개발 자료로의 관계 판독 전이를 보여주며, BEAM의 새 작업자 성공이나 미개봉 확인 집합 결과를 뜻하지 않음.

한 기록에 두 속성이 있고 일부만 알려진 경우가 중요한 남은 약점임. 학습에서는 한 출처의 6쌍을 모두 맞췄지만, 개발의 다른 한 출처 10쌍에서는 기존 7개 보존→추가 학습 4–7개 보존에 머묾. 예를 들어 `meaning and signifier`가 함께 있는 기록에서 한 개념을 이미 관측했더라도 다른 개념이 필요하면 기록을 보존해야 함. 이 관계는 학습·개발 각각 한 출처뿐이라 구조의 일반적인 한계로 단정할 수 없으며, 다음 데이터 보강의 구체적인 대상임.

모든 은행은 상한 512토큰보다 훨씬 짧고 개발 최대 57토큰임. 필요 근거가 항상 은행 안에 존재하며 관측·실패 이력은 작성된 문장 틀임. 보조 손실과 기존 자료 혼합의 독립적인 추가 가치, 부족한 은행에서의 보류, 실제 예산 경쟁 및 자연 진행 이력으로의 전이는 아직 확인하지 못함.

## 고정 작업자의 실제 출력

같은 Qwen3.5-4B가 개발의 직접 표현 50상태를 수행함. 채점 대상은 요청 필드 복원이며 실제 도구 실행·예약·전체 원래 과제 성공이 아님. 위 관계 평가 100상태와 분모가 다름. 누락된 필드의 값은 무기억 입력에 문자 그대로 노출되지 않음을 확인함. 원문에 명시된 `video interview` 같은 동등한 명사구는 호출 전에 고정한 허용 표현으로 채점하고, ID는 대소문자를 구분함.

| 정책 | 값 일치 /50 | 값 일치+입력 근거 /50 | 평균 전달 메모리 토큰 |
|---|---:|---:|---:|
| 무기억 | 13 | 11 | 0 |
| 기존 고정 판독기 | 26 | 24 | 5.50 |
| BM25 상위 2개 | 44 | 44 | 23.08 |
| 문자 중복 제거+BM25 | 45 | 45 | 22.96 |
| 임베딩 검색 상위 2개 | 50 | 50 | 22.48 |
| 은행 전체 제공 | 49 | 49 | 31.24 |
| 검토된 근거만 제공하는 진단 | 50 | 50 | 10.82 |
| 단일 필요성 학습 | 44–47 | 44–47 | 11.00–11.30 |
| 관련성 보조 학습 | 43 | 43 | 9.52–9.80 |
| 보조 학습+기존 자료 혼합 | 43–44 | 43–44 | 9.64–9.70 |

추가 학습은 기존 판독기 대비 20–24상태를 개선하고 1상태를 악화시켜, 근거 있는 정답이 순 19–23상태 늘었음. 무기억 대비 개선은 32–36상태, 악화는 0상태임. 따라서 이번 비교로 무기억 대비 실제 손해 감소를 주장하지 않음. 임베딩 검색은 50/50으로 더 좋았고, 학습 선택기가 이를 능가했다는 근거는 없음.

학습 정책의 실패는 모두 필요한 입력 근거가 빠진 경우였음. 정답 근거 진단은 50/50이며, 학습 정책에서 근거가 충분했지만 작업자가 실패한 경우는 0건임. 따라서 이번 자료에서는 작업자 능력보다 제공 기준·완전한 근거 보존을 우선 점검하는 것이 적절함. 이것은 해당 8출처의 짧은 필드 복원 결과이며 일반 작업자의 상한을 뜻하지 않음.

은행 전체 제공의 유일한 실패는 `qa_327:ie:4:direct`임. Bitcoin 가격과 USD 기록에 다른 코인 지갑 기록도 함께 제공하자 작업자가 `Cordano`를 답함. 같은 상태에서 가격 관련 두 기록만 제공한 검색과 필요한 근거 진단은 Bitcoin을 맞힘. 추가 기억에 따른 실제 악화를 한 사례로 관측했으나, 무기억에서 성공하던 상태를 망친 경우는 아니고 일반적인 손해율로 확대할 수 없음.

학습 정책은 임베딩 검색보다 전달 메모리 토큰을 약 50–58% 줄였지만 정답도 줄었음. 작업자 평균 생성 시간은 검색 2.21초, 학습 선택 2.25–2.27초이며 선택기의 배치 평균 순전파 0.055–0.066초가 추가됨. 로딩·서빙 경합을 포함한 종단 지연 실험은 아니지만, 이번 측정으로 처리 시간 이득을 주장할 근거는 없음. 토큰 절약을 자동으로 총비용 절약으로 바꾸지 않음.

## 현재 기여와 다음 우선순위

확인한 성과는 원문에서 출발해 **관측 변화 → 필요한 기록 변화 → 실제 필드 복원 결과**를 연결하는 측정 절차와, 이 대조를 학습한 작은 모델의 개선임. 관련성과 현재 필요성을 분리한 감독도 구현·검산했지만 보조 손실 자체가 가장 좋은 선택 정책이라는 증거는 얻지 못함. 더 복잡한 판독층을 추가하기보다 단일 학습을 기준선으로 유지하는 것이 적절함.

다음은 한 기록의 일부만 알려진 대조를 여러 독립 출처에서 보강하는 것이 우선임. 같은 사실을 각각의 기록/합쳐진 기록으로 배치하고, 모두 모름·일부 확인·모두 확인에서 보존해야 할 근거를 검토하면 현재 드러난 과도한 기록 삭제를 시험할 수 있음. 이때 지금의 개발 오답을 고쳐 같은 개발에서 성공했다고 일반화하지 않고, 새 출처와 처음 보는 문장 표현을 따로 확보해야 함. 실제 예산 제약과 자연 진행 이력도 별도 검증 단계로 유지함.

공유 산출물은 [결과 묶음](../../evaluation/results/memory-incremental-evidence-20261111-v2/README.md)에 정리함. 원문·고정 데이터·초기 모델 해시를 보존했으며, 16,352개 저장 후보 행의 두 출력과 6개 LoRA의 각 112개 텐서 변화, 전체 노출 횟수·정책 선택·작업 채점을 CPU로 검산함. 작업자는 168고유 입력과 3반복을 실행했고 반복 3개는 동일 출력임. 650정책 결정은 독립 호출 수가 아님.

로컬 RTX 4080 SUPER에서 수정본 학습·평가는 약 33.3분, 작업자 실행은 약 6.2분이었음. 중단한 v1에는 약 10.2분을 추가로 사용했음을 별도로 남김. 학습은 최대 약 2.51GiB, 작업자는 약 8.56GiB의 PyTorch 할당을 기록함. GPU 계산 프로세스 종료를 확인했고 Colab·유료 API·실제 외부 도구 호출은 사용하지 않음.
