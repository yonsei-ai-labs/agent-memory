# 같은 기억을 정보와 지침으로 제공하는 작은 비교

2026-11-05 · 고정한 12회 완료. 같은 본문에 사용 안내 한 문장만 바꾸는 비교와 성과·비용·행동 측정은 가능했다. 정보형과 지침형의 해결률은 같았으며, 두 대상에서 메모리 유무의 관측 차이는 반대 방향이었다. 조건별 두 반복이므로 어느 방향의 득실도 확정하지 않는다.

## 질문과 비교

같은 기억 본문을 참고 정보로 안내할 때와 따를 조사 절차로 안내할 때, 예산 내 해결·비용·관측 행동이 달라지는지 살핀다. 두 대상에서 `무메모리 / 정보 참고형 / 지침형`을 각각 두 번, 총 12회 실행하도록 배정했다. 표현 조건마다 별도의 기억을 요약하지 않고 [앞서 작성한 예시](../design-data/memory-framing-examples-20261105.json)의 동일 본문을 사용한다. 제안형은 이번 배정에 포함하지 않는다.

두 대상은 각각 이미 30회·46회 실행한 탐색 과제다. 현재 준비된 환경에서 표현 개입을 간단히 시험하기 위해 선정했다. 이전 결과를 알고 선택했으며 새 확인 집합이나 대표 표본으로 취급하지 않는다. 두 쌍 모두 부분적으로 관련될 뿐, 적용성이 높은 집단과 낮은 집단을 통제해 대비한 실험이 아니다. source와 target도 일대일 대응하므로 두 사례의 차이를 출처 성공·실패의 효과로 분리할 수 없다.

## 입력을 어떻게 통제했는가

정보형과 지침형에서 바뀌는 것은 사용 안내 한 문장이다. 출처 카드 ID, 본문, 공식 결과, 근거, 적용 한계와 현재 코드에 맞는지 확인하라는 공통 안내는 그대로 둔다. 문장 길이는 같지 않으므로 특정 문구 개입의 효과로 해석한다. 정보와 명령의 순수한 의미 효과를 모두 분리한 설계는 아니다.

두 조건의 본문은 모두 과거 조사 절차를 담고 있다. 정보형에도 공통 적용성 확인 안내가 있으므로 순수한 사실 목록과 절차 목록의 비교가 아니다. 무메모리 대비에는 본문·출처 표시·공통 안내가 함께 추가되므로 그 전체 제공 정책의 효과로 읽는다. 본문만의 기여와 일반적인 조사 촉구의 기여는 이번 배정으로 분리하지 않는다.

기존 고정 제공 안내에는 `You are not required to follow it.`가 있었다. 이번 지침 안내와 엇갈리는 단서를 피하려고 이 한 문장만 제거한 `fixed_preload_notice="neutral"` 옵션을 추가해 두 메모리 조건에 동일하게 적용했다. 기존 모드의 기본값은 보존했다. 상위 프롬프트·입력 역할·도구·위치는 같다. 자동 어휘 검색을 거치지 않고 지정한 카드를 시작에 제공하며 본문 해시는 디스크에 보존하되 모델 입력에서는 숨긴다.

실행 전 원문 해시와 문구 외 동일성을 검사했다. 로컬 검사 50개가 통과했고 중립 안내를 명시적 고정 제공 외의 모드에서 쓰지 못하도록 검사한다. 실행 후 실제 API 첫 입력에서도 같은 통제가 유지되는지 검사했고 모두 통과했다. [검사 로그](data/framing-smoke-20261105/prelaunch-tests.log), [구현 검증](data/framing-smoke-20261105/implementation-validation.json).

## 환경·출처·순서·예산

모델은 기존 OpenRouter의 `openai/gpt-6-luna`, medium, OpenAI 제공자 고정이며 fallback을 허용하지 않는다. 모든 실행에 32회 모델 요청, 에이전트 600초, 실행당 비용 중단 기준 $0.05를 적용한다. 별도 중간 채점은 하지 않는다. 최종 제출만 공식 채점하고 필요한 모든 테스트가 관측됐는지 검사한다.

새 모델 비용의 배치 중단 기준은 $0.75, 다음 실행 전 여유 금액은 $0.10이다. 비용은 요청 종료 뒤 검사하므로 요청 하나까지 포함한 완전한 하드 상한은 아니다. 이전에 확인된 응답 비용 $1.03600578964와 별도로 기록하며 기존 $10 선호 예산에 합산한다. 초기 API HTTP 404 한 건의 미확인 비용은 그대로 불명으로 남긴다.

같은 이미지 ID·초기 소스 트리와 보존된 원본 실패/정답 성공 대조의 유효성을 확인했다. 두 출처의 병합 커밋이 대상 기준 커밋의 조상임을 다시 검사했다. 현재 HEAD의 조상이 아닌 ref 도달 커밋은 없었다. 과거 Git은 모든 조건에서 계속 접근 가능하며 도달 불가능한 객체와 모델 학습 데이터까지 검사한 것은 아니다. 컨테이너 네트워크는 끈다.

실행 전 현재 앱 코드에서 Sphinx의 `_apply_type_aliases`, Django의 `deferred_to_data`가 없음을 확인했다. 다른 사전 지정 조사 관련 이름들은 존재했다. 처음 없던 이름을 찾는 행동은 적용성을 확인하는 정상적인 조사일 수도 있으므로 그 자체를 손해로 판정하지 않는다.

seed `2026110502`로 반복별 대상 순서, 대상·반복 블록 안의 세 조건 순서를 섞고 고정했다. 조건·반복 수를 중간 결과에 따라 늘리지 않는다. 두 번째 반복의 Django 무메모리도 마지막 위치에 배정됐으므로 균형 순서라고 주장하지 않는다. 실제 시각·캐시·사용량을 남긴다.

정상적인 한도 도달의 미제출은 배정에서 유지하고 전달 성공 지표에서는 0으로 센다. 원래 공식 판정은 `null`이다. 비용 불명·API 오류·불완전 평가·환경 오류에는 중단하고 모델 생성을 자동 재시도하지 않는다.

## 분석을 미리 정한 범위

주 대비는 `지침형 − 정보 참고형`의 예산 내 해결률 차이다. 정보형과 무메모리, 지침형과 무메모리 비교는 보조 대비다. 비용은 성공 실행만 골라 비교하지 않고 전체 배정 평균을 쓴다. 공식 회귀는 실제 평가가 있는 실행에서 관측된 실패로 보고한다.

과제별 결과를 먼저 보고하고 두 과제를 같은 가중치로 평균한 수치도 남긴다. 이진 성과의 보수적 범위는 대비에 들어가는 과제·조건 셀의 Clopper–Pearson 구간을 Bonferroni 조정해 결합한다. 이는 고정된 두 과제에서 반복의 iid 가정 아래 대비별 95% 범위이며, 새 과제 모집단에 대한 구간은 아니다. 비용의 유의성이나 일반적인 유익·유해 방향을 두 반복으로 확정하지 않는다.

행동 지표는 사전에 열거한 출처 식별자가 있는 `rg`/`grep` 형태의 검색 명령, 최초 검색 요청 단계, 초기 앱 코드에 없던 이름을 검색한 실행 수다. 실제 모델 도구 call ID와 명령을 연결하고 원문을 보존한다. 쉘 문자열 휴리스틱이며 모든 조사 행동을 잡지는 못한다. 카드 내용의 채택·내부 주의·낭비·최종 실패의 원인을 자동 판정하지 않는다. 모델이 기억을 따른 실행만 따로 골라 주 성과를 계산하지 않는다.

Django에는 이미 알려진 로컬 검사와 공식 검사 기대값의 충돌이 있다. 그 현상이 다시 나타나더라도 이번 표현 때문에 생겼다고 바로 해석하지 않는다. 사후에 다른 집합에서 본 숨겨진 테스트 내용을 카드에 추가하지 않았다.

## 실행 전후 운영 기록

초기 준비에서 R07에 무메모리 설정이 없다는 점을 만나, 같은 검증된 Django 이미지의 R03 설정을 템플릿으로 바꿨다. 배정을 고정하거나 모델을 호출하기 전이었으며 미완성 은행·사전 점검·오류를 [별도 보존](data/framing-smoke-20261105/failed-preparation-1/reason.json)했다. 모델 설정·환경을 가져온 뒤 이번 실험의 도구 프롬프트와 조건을 명시적으로 고정했다.

과금 메타데이터만 조회하는 보조 스크립트의 최초 구문 오류도 보존하고 수정했다. 모델 실행기나 고정 계획은 변경하지 않았으며 해당 오류로 모델 호출이 재시도되지 않았다. 이 보조 작업은 완료된 generation ID의 조회와 사후 분석만 수행한다.

### 평균으로 합치면 가려지는 차이

두 과제를 합치면 세 조건 모두 **2/4 해결, 50%**다. 그러나 메모리 유무의 관측 차이는 Sphinx에서 +50%p, Django에서 −50%p였다. 이는 이번 표본에서 나온 차이며, Sphinx 기억에 유익·Django 기억에 유해라는 정답 라벨을 붙일 근거는 아니다. 무메모리 자체도 두 과제 각각에서 한 번 성공하고 한 번 실패했다.

과제별 메모리−무메모리 대비의 보수적 95% 범위는 Sphinx −88.19~+99.37%p, Django −99.37~+88.19%p다. 어느 쪽도 방향이 정해지지 않는다. 두 과제에 같은 가중치를 준 대비는 다음과 같다.

| --- | ---: | ---: | ---: |
| 지침형 − 정보형: 주 대비 | 0%p | −92.09~+92.09%p | +$0.001594655 |
| 정보형 − 무메모리 | 0%p | −95.73~+95.73%p | −$0.001817183 |
| 지침형 − 무메모리 | 0%p | −95.73~+95.73%p | −$0.000222527 |

정보형의 전체 평균 비용은 $0.00871210125, 지침형은 $0.01030675625다. 지침형이 관측상 약 18.3% 높았고 모델 요청 수도 75회 대 64회였다. 성공 실행만 고른 수치가 아니다. 두 반복·단일 문구·통제하지 않은 캐시·서로 다른 실행 경로 때문에 안정적인 비용 손해나 정보형의 우월성을 확정하지 않는다. 모델 비용과 해결 성과를 임의 가중치로 합친 단일 점수도 만들지 않았다.

### 실제 행동에서 확인한 것

Sphinx의 사전 지정 출처 이름 검색은 무메모리 0/2, 정보형 1/2, 지침형 2/2였다. 지침형의 두 실행이 모두 더 빨리 검색한 것은 아니다. 한 번은 첫 모델 응답에서 `get_type_hints`를 검색했고 다른 한 번은 네 번째 응답에서 검색했다. 정보형의 해당 검색은 첫 응답에서 나왔다. 검색 빈도와 조사 속도를 같은 지표로 취급하지 않는다.

Django에서는 초기 앱 코드에 없는 `deferred_to_data`를 메모리 네 실행 모두 첫 모델 응답에서 검색했고 무메모리는 0/2였다. 해당 이름은 공개 문제 설명에 없으며, 첫 요청에서 기억 문맥을 제거하면 이름도 사라진다. 카드 내용과 행동의 연결을 조사할 근거는 확보했지만 정보형과 지침형의 차이는 이 지표에서 없었다. 오래된 이름을 확인한 것만으로 낭비나 실패 원인이 입증되지는 않는다.

### Django의 실패를 기억의 손해로 단정하기 어려운 이유
