# 조회 도구의 적절성 점검

2026-11-03 · 첫 전달 보고서를 보존한 뒤 수행한 별도 점검

## 질문과 기존 증거의 범위

사용자는 자율 조회 0회가 기억의 필요성 때문이 아니라 조회 도구가 적절하지 않았기 때문일 수 있다고 지적했다. [첫 보고서](2026-11-03-memory-delivery-smoke.md)는 [해시](data/2026-11-03-delivery-report-freeze.json)로 고정한 뒤 추가 점검을 시작했다. 당시 명시적 조회 지시는 성공했지만 자율 검색 2회에서는 조회가 없었다. 명시적 호출 성공은 발견·호출 편의성이 적절하다는 증거가 아니다.

## 실제 요청·코드에서 확인한 문제

| 항목 | 확인한 사실 | 해석의 한계 |
| --- | --- | --- |
| 도구 목록 | 실제 API `tools`에는 `bash` 하나만 있음. 기억은 그 안의 예약 명령으로 호출 | 작동 불능은 아니지만 별도 함수 도구보다 추가적인 사용 규칙이 필요함 |
| 안내 위치 | `1606`의 첫 사용자 입력은 11,545문자. 기억 안내는 문제·작업·제출 지시 뒤에 있음 | 위치가 원인이었다고 입증한 것은 아님 |
| 기본 작업 규칙 | 매 응답에 적어도 하나의 bash 도구 호출을 요구함 | 별도 기억 함수만 호출할 때에는 지시 충돌 가능. 기존 bash 조회를 금지한 규칙은 아님 |
| 호출 문법 | `memory search --query '...'`를 단독 호출해야 함. 일반 셸 바이너리나 자유로운 파이프 명령이 아님 | 쉘에 익숙한 에이전트에게 실제 쉘과 다른 조합 규칙을 요구함 |
| 검색·저장소 | 실제 경험 하나의 카드 두 개와 어휘 겹침 검색 | 대규모·풍부한 기억의 접근 정책을 대표하지 않음 |
| 조회 한도 | 한 번만 검색할 수 있고 빈 결과도 한도를 사용함 | 첫 검색 실패 뒤 재질의할 수 없음. 이 제약이 미조회를 유발했는지는 미확인 |

실제 입력 근거는 [기존 자율 조건의 첫 요청 · 별도 원본](../reproduction.md) (`runs/20261103T140317Z-cc29eee1/api/0001.request.json`)에 있다. 기억의 존재와 가치가 발견되기 쉬웠다고 가정할 수 없지만, 현재 기록만으로 에이전트가 설명을 못 봤다고 단정하지도 않는다.

## 검색어 점검

문제 설명에서 만든 사후 점검용 검색어를 고정된 검색기에 넣었다. [원본 점수](data/2026-11-03-memory-query-review.json)

| 검색어 | 관측 |
| --- | --- |
| `golden section search equal bounds` | 두 카드 모두 점수 0, 빈 결과 |
| `pvlib _golden_sect_DataFrame NaN` | 사실 카드가 `pvlib`, `nan`의 겹침으로 선택됨 |
| `iam physical aoi n=1 nan` | 두 카드 모두 `nan` 하나가 겹쳐 동점. ID 순으로 사실 카드 선택 |
| `pvlib scalar numpy array pandas series zero division` | 일반적인 배열·자료형·0 관련 단어가 많이 겹쳐 사실 카드 선택 |

이 검색어들은 검색 정확도 벤치마크나 정답 라벨이 아니다. 관련한 기억이 없으면 빈 결과가 적절할 수 있으므로 빈 결과 자체를 검색 오류라고 판정하지 않는다. 검색기가 다룰 수 있는 범위와 카드의 실제 관련성이 제한적이라는 진단이다. 기존 미조회 실행에서는 검색 결과를 본 적이 없으므로 ‘검색 결과가 나빠서 조회하지 않았다’는 설명을 증명하지 못한다.

## 새 비교를 고정

[interface-smoke-v1](../../experiments/swe_memory/plans/interface-smoke-v1.json)에서 기존 과제 두 개를 각각 두 인터페이스로 새로 실행한다. 이미 검토한 과제의 연결·행동 점검이며 새 과제로의 전이 평가가 아니다. 조건별 1회, 총 4회로 제한한다.

- `bash_command`: 기존의 단독 예약 명령.
- `native_tool`: API 도구 목록에 별도의 `memory_search(query)` 함수를 제공.
- 두 조건 공통: 핵심 요구사항의 `MUST include AT LEAST ONE bash tool call`을 ‘사용 가능한 도구 호출 하나 이상’으로 변경. 기억 사용은 선택 사항으로 유지. **후속 감사에서 다른 위치의 bash 요구 한 줄이 남아 있음을 발견했다. 아래 정정을 참조한다.**
- 동일하게 유지: 모델·제공자·추론 설정, 기억 본문·표시·검색기·한도, 과제 이미지·문제·나머지 작업 지시·예산.
- 순서: 1606에서는 native → bash, 1707에서는 bash → native. 두 조건 모두 새 컨테이너·대화에서 실행.
- 주 관측: 조회 여부·실제 입력 노출·시점·검색어·빈 결과·형식/한도 오류. 공식 점수와 비용은 함께 기록.

이 비교에는 도구 메타데이터 노출·호출 문법·해당 사용 안내의 차이가 함께 있다. ‘도구 이름 하나’나 ‘안내 위치 하나’의 순수한 효과라고 해석하지 않는다. 원래 실행과 새 native 실행만 비교하지 않고, 같은 공통 프롬프트를 사용하는 새 bash 실행도 수행한다. 무조회 실행도 모두 포함한다.

## 구현 검증

native 함수 인수는 호스트 셸 코드로 실행하지 않고 문자열 데이터로 처리한다. bash와 같은 저장소·검색·한도를 사용하며, 반환 `call_id`와 다음 요청의 카드 포함을 연결해 기록한다. 일반 bash 실행과 실제 에이전트 파서·도구 출력 포매터를 함께 사용하는 왕복 검증을 포함한 로컬 테스트 21개가 통과했다. 평가 자료나 저장소 전체를 컨테이너에 노출하지 않는다.

## native 조회의 별도 양성 대조

네 실행을 마친 뒤 [guided-memory-tool-20261103T143424Z-5b9bf7 · 별도 원본](../reproduction.md) (`runs/guided-memory-tool-20261103T143424Z-5b9bf7/memory-summary.json`)에서 함수 조회를 명시적으로 요청했다. 실제 모델의 첫 응답이 `memory_search`를 호출했고, 카드가 반환되어 2번 API 요청에 포함됐다. 모델은 카드 ID를 출력하고 종료했다. 실제 요청 2회, 조회 1회, 형식 오류 0회이며 API 비용은 $0.000401590이다. 코드의 mock 검사뿐 아니라 실제 API를 통한 왕복도 확인했다.

이 대조는 함수 호출·호스트 처리·대화 연결이 동작한다는 근거이며 자발적 조회의 증거가 아니다. 기존 bash 양성 대조와 마찬가지로 자율 조회율이나 네 비교 실행에 합치지 않는다.

## 결론과 다음 설계

**기존 인터페이스에는 개선할 설계상 약점이 있었지만, 이 작은 비교에서는 별도 함수 도구로 바꾼 것만으로 자율 조회가 늘지 않았다.** 조회 도구가 유일한 원인이었다고도, 아무 영향이 없다고도 결론낼 수 없다. 두 과제의 무메모리 성공과 한 출처의 다른 함수 경험만 있는 저장소도 함께 고려해야 한다. 에이전트가 의식적으로 기억이 불필요하다고 판단했다는 설명은 로그로 입증하지 않았다.

후속 구현의 기본 후보는 명시적 스키마와 구조화된 인수를 가진 native 도구다. 이는 인터페이스와 기록을 명확하게 하기 위한 선택이며, 성능 우월성을 확인했다는 뜻은 아니다. 다음 실험은 다음 순서가 적절하다.

1. **이용 가능한 기억의 범위를 알린다.** 저장소·하위 시스템·관측 종류 등의 짧은 인덱스로 어떤 경험이 있는지 안내한다. 사용을 강제하지 않고 이 안내를 별도 실험 변경으로 기록한다.
2. **경험과 과제의 실제 관계를 확보한다.** 과제 설명과 현재 코드에서 확인 가능한 같은 API·하위 시스템의 과거 경험을 수집한다. 평가 정답·미래 결과를 검색이나 카드 작성에 쓰지 않는다. 두 쉬운 기능 점검 문제는 효능 입증 집합으로 확대 해석하지 않는다.
3. **필요 판단·검색·활용을 나눠 검사한다.** 조회 여부, 어떤 카드가 반환됐는지, 실제 입력에 포함됐는지, 이후 행동이 바뀌었는지를 별도로 기록한다. 조회가 없으면 ‘기억을 읽은 뒤의 효과’ 분석으로 넘어가지 않는다.
4. **시점의 효과에는 별도 대조를 둔다.** 자율 조회를 유지하면서, 같은 카드의 시작 제공·사전에 정한 시점 제공을 별도로 비교하면 자율 선택과 내용 노출을 혼동하는 문제를 줄일 수 있다.

네 비교 실행의 API 비용은 $0.016382445이며 native 양성 대조를 포함한 추가 비용은 **$0.016784035**다. 첫 전달 점검·출처 수집·카드 작성·두 양성 대조까지 이번 진행 전체의 API 합계는 **$0.047988870**, 모델 요청은 109회다. 사후 과금과 제공자를 [별도 검증 기록](data/2026-11-03-memory-interface-validation.json)에 남긴다. CPU·이미지 빌드·저장 비용은 포함하지 않았다.

## 2026-11-04 후속 정정 — 남은 bash 지시

야간 후속 감사에서 `For each response` 아래의 `Provide one or more bash tool calls to execute`가 여전히 실제 API 입력에 있음을 확인했다. 위 비교에서 바꾼 것은 핵심 요구사항 한 곳이며, 프롬프트 전체의 bash 필수 지시를 모두 해소한 것은 아니었다. [실제 입력 감사](data/2026-11-04-prompt-consistency-audit.json)에 원본 경로와 해시를 남겼다. 기존 실행·성공률·무조회 기록은 바꾸지 않는다.

이 한 줄은 기억 함수만 호출하는 행동과 충돌할 수 있다. 다만 bash와 기억을 함께 호출하는 경로는 있었으므로 무조회의 원인이라고 단정하지 않는다. [야간 보고서](2026-11-04-overnight-research.md)의 R04에서 기존 문구와 이 한 줄만 수정한 문구를 새 실행으로 비교한다. 무메모리·시작 제공 대조에도 같은 문구 변경을 적용해 일반적인 표현 효과와 조회 조건의 변화를 구분한다.
