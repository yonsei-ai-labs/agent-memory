# 현재 실험 상태와 데이터 재점검

2026-11-05 · 원본·집계·분석 범위 재검토 · 새 모델 호출과 네트워크 요청 0회

**검사한 원본 기록의 변경·누락이나 최근 실험 수치의 불일치는 발견하지 않았다. 전체 집계의 갱신 누락과 기록 유형의 혼재를 수정했고, 앞선 누적 비용의 범위를 정정했다. 연구 자료는 탐색과 측정 절차 검증에 쓸 수 있지만 일반적인 메모리 득실을 확증할 규모·구성은 아니다.**

## 현재 상태와 실제 표본

실행 중인 실험 프로세스와 Docker 컨테이너는 없었다. 생성된 배치 기록 13개 중 12개는 완료, R05 하나는 중단 상태다. R05는 24개 배정 중 6개를 실행하고 멈췄으며 18개는 미실행으로 유지한다. 이전 R10의 시간 부족에 따른 미실행과 이후 별도로 실행한 구성요소 기능 검증을 합치지 않았다.

| 기록 유형 | 개수 | 의미 |
| --- | --- | --- |
| 메모리 비교 대상 실행 | 128 | 7개 문제에 대한 여러 회차·조건·반복; 공식 채점 127회, 미제출 1회 |
| 경험 수집 실행 | 4 | 서로 다른 출처 문제 4개; 공식 해결 2개, 미해결 2개 |
| 기억 작성 | 4 | 출처 경험을 카드로 작성한 별도 모델 호출 |
| 조회 연결 점검 | 4 | 명시적으로 도구 사용을 요청한 점검; 자율 조회 성과와 구분 |
| 초기 환경 점검 | 4 | 채점 2회, API 오류 1회, 모델 호출 전 환경 오류 1회 |
| 사후 분석·재검사 | 43 | 모델 실행 표본으로 세지 않는 진단 기록 |
| 합계 | 187 | 144개 모델 설정 기록과 43개 사후 분석 기록 |

모델 설정 기록 144개 중 실제 API 요청이 있는 기록은 143개다. API 요청 시도는 2,144회, 응답과 generation ID가 있는 요청은 2,143회다. generation ID의 중복은 없었다. 요청 실패 1회는 초기 환경 점검에 속한다.

대상 7개는 다음처럼 분포한다. 동일 문제의 반복을 독립적인 새 문제로 세면 안 된다.

두 문제에 76/128회, 약 59.4%가 집중되어 있다. 대상 실행의 요청 모델은 Luna 125회, DeepSeek 3회다. 전체 모델 설정 138/6과는 다른 집계이며 모델 간 일반 성능 비교로 사용하지 않는다.

실제로 로드된 은행에서 카드 ID·본문 해시의 조합은 16개지만 원천 경험은 4개뿐이다. 같은 출처의 원문·삭제 변형을 독립 경험 16개로 해석하지 않는다. 출처의 공식 성공·실패도 전이 대상에서 그 기억이 유익·유해하다는 정답 라벨은 아니다.

## 무엇을 다시 확인했는가

- 모델 실행 원본 산출물 **29,345개**를 기존 SHA-256 목록과 대조했다. 변경·누락은 없었다.
- API 응답 원문의 사용량, 요청별 기록, 요약의 호출 수·비용·오류 수를 대조했다. 응답이 있는 2,143건은 사후 과금 메타데이터의 ID·해시·비용도 확인했다. 비용은 요청별 허용 오차 $10⁻⁹ 미만으로 맞았다.
- 요청 시작·종료 이벤트가 존재하는 실행은 모든 요청의 대응과 입력 파일 해시가 맞았다. 초기 세 실행은 이 기능 도입 전이라 시작 이벤트가 없다는 제한을 그대로 남겼다.
- 공식 채점 보고서와 요약의 판정·목표/유지 테스트 개수가 맞았다. 초기 두 채점 실행의 완료 증거는 원본 요약이 아니라 이미 보존된 별도 평가 감사에 있다.
- 배치의 고정 계획·설정 해시와 실제 실행 설정을 대조했다. 완료·중단·미실행을 구분했다.
- 야간 관계형 CSV 6개의 해시와 행 수가 보존되어 있다. 중간 패치 306개와 경로·해시가 명시된 채점 근거 252개 참조도 다시 확인했다. 반복 참조를 중복 제거한 채점 근거 파일은 64개다.
- 최근 구성요소 실험의 증거 목록 65개 파일이 그대로였다. 원본에서 분석을 다시 수행한 셀별 수치·모든 대비·입력 개입 검사·요청별 자료가 기존 결과와 같았다.

이 검사는 기록 정합성과 보존 상태에 관한 것이다. 모델의 사전학습 오염, 벤치의 대표성, 과거 Git 접근의 효과, 의미상 원인 분리까지 통과했다는 뜻은 아니다. 이번에는 모델·패치·공식 테스트를 새로 실행하지 않았다.

## 발견한 집계 문제와 조치

### 전체 목록이 최근 10회를 포함하지 않았다

`data/runs.json`과 `runs.csv`는 177개 기록에서 멈춰 있었다. 최근 구성요소 결과는 전용 폴더에 정상적으로 있었지만 전체 목록에는 들어 있지 않았다. 기존 두 파일을 [수정 전 사본](data/workspace-review-20261105/before-manifest.json)으로 보존하고 현재 187개 기록으로 갱신했다.

### 사후 분석이 비용 기록이 불완전한 모델 실행처럼 보였다

기존 exporter는 `summary.json`이 없는 모든 manifest에 `cost_complete=false`를 붙였다. 모델을 호출하지 않은 사후 검사 43개도 그 대상이었다. 또한 이들 중에는 `run_id`가 없어 ID 기반 집계에서 섞일 위험이 있었다.

이제 `record_id`, `record_kind`, `model_configured`, `summary_present`, `cost_evidence_applicable`을 명시한다. 모델이 없는 기록의 비용 완전성은 적용 대상이 아니므로 `null`이다. 실제 API 오류의 비용 불명은 계속 `false`로 남는다. 출처 수집·카드 작성·연결 점검을 대상 실행의 분모에서 구분하고, 구성요소·배치 등의 분석용 필드도 보존한다. 알 수 없는 새 단계는 자동으로 대상 실행에 넣지 않는다.

수정한 분모·비용 의미를 검사하는 로컬 테스트 3개와 전체 export의 고유 ID·건수·최근 10회 포함 검사가 통과했다. 원본 manifest·summary·요청·평가 파일은 수정하지 않았다. [현재 데이터 안내](data/README.md), [갱신한 CSV](data/runs.csv).

### 누적 비용의 범위를 정정한다

앞선 보고서의 **$1.0300574892는 초기 환경 점검을 제외한 소계**였다. 이를 전체 누계라고 쓴 표현은 부정확했다. 워크스페이스 전체의 요청 기록을 기준으로 다음처럼 정정한다.

| 범위 | 모델 설정 기록 | 확인되는 응답 보고 비용 |
| --- | --- | --- |
| 초기 환경 점검 | 4 | $0.00594830044 |
| 야간 이전 메모리 파일럿 | 14 | $0.04798887000 |
| 고정한 야간 세션 구성원 | 116 | $0.92843569420 |
| 최근 구성요소 기능 검증 | 10 | $0.05363292500 |
| 확인되는 비용 합계 | 144 | **$1.03600578964** |

응답이 있는 요청의 사후 과금 메타데이터 합계는 $1.036005741로, 응답 보고 합계와 약 $0.00000004864 차이가 난다. 요청별 정밀도 차이가 누적된 수준이며 최근 10회의 비용은 정확히 일치한다.

초기 `20261103T124906Z-4370e44a`의 API 오류 1건은 HTTP 404, generation ID와 사용량 정보가 없다. 이 요청을 비용 0으로 확정하지 않는다. 따라서 위 금액은 **확인되는 비용의 합계**이고 미확인 오류 요청까지 모두 대조한 확정 총청구액이 아니다. 이후 야간·최근 구성요소 실험의 비용 증거에는 이 누락이 없다. 인프라 비용도 별도다.

고정한 옛 보고서·배정·감사 결과는 그대로 두고 이 문서에서 범위를 정정한다. [범위별 비용 대조와 카드 출처](data/workspace-review-20261105/scope-reconciliation.json).

## 연구 질문에 지금 데이터가 답할 수 있는 범위

최근 구성요소 실험은 한 출처·한 대상에서 다섯 조건을 두 번씩 실행한 것이다. 다섯 조건 모두 2/2 성공했고, 전체 기억의 평균 비용 $0.00675206과 무메모리의 $0.00402858도 원본에서 재집계해 같은 값을 얻었다. 입력의 특정 구간을 조작하고 성과·비용의 조건부 차이를 계산할 수 있다는 검증이다. 표본이 작고 관측 성공률이 상한에 있어 어느 부분이 성과를 올리거나 내리는지는 판정하지 못했다.

현재 자료로 할 수 있는 것은 각 회차 안의 입력·조회·노출·행동·실패 경로를 추적하고 다음 가설을 만드는 일이다. 다음 해석은 아직 지지하지 않는다.

- 여러 회차를 한꺼번에 합쳐 메모리의 평균 개선률을 계산하기: 회차별 과제·내용·프롬프트·한도가 다르다.
- 한 번의 성공·실패 차이를 카드의 확정 유익·유해 라벨로 쓰기: 실행 변동과 대상 조건의 효과가 남아 있다.
- 관측 문장과 절차 문장 대조를 순수한 정보·행동 지시의 의미 효과로 부르기: 서로 정보가 섞이고 길이도 바뀐다.
- 여러 문구 변형을 많은 독립 출처로 세거나, 이번 7개 문제에서 얻은 결과를 일반화하기.
- 중간에 통과한 패치를 사후에 성공 제출로 바꾸기: 실제 미제출 1회는 미제출로 유지한다.

다음 실험 전에 과거에 본 대상과 새로운 확인 대상을 구분하고, 출처·대상의 재사용할 정보와 주 개입을 명시해야 한다. 지금 데이터를 버릴 필요는 없지만, 추가 반복만으로 구성의 편중과 원인 분리 문제가 해결되지는 않는다.

## 보존과 재분석 시 주의할 실제 상태

Git은 초기화되어 있지만 첫 커밋과 등록된 remote가 없다. 원본 `runs/`는 `.gitignore`로 제외되므로 향후 Git 복제만으로 복원되지 않는다. 이번에 만든 수정 전 사본은 같은 디스크의 변경 이력 보존이며 외부 백업은 아니다. 다른 위치의 개인 백업 유무까지 확인한 것은 아니다.

기존 `audit_session.py`와 `export_research_tables.py`는 세션 시작 시각 이후를 상한 없이 고르는 구현이다. 현재 상태에서 옛 명령으로 야간 결과를 다시 내보내면 최근 실행까지 섞일 수 있다. 이번 감사에서는 보존된 야간 결과의 **명시적 run ID 116개**로 범위를 고정했고 옛 출력은 덮어쓰지 않았다. 새 누적 집계는 갱신한 `summarize.py`, 현재 정합성 검사는 `audit_workspace_state.py`를 사용한다. 세션 감사 도구의 범위 선택 자체는 후속 실행 전에 명시적 세션 구성원으로 보완해야 한다.
