# 실험 진행에 대한 검토 피드백

2026-11-10. 실험을 수행하지 않은 별도 검토 세션(Claude Code)이 작성함. 실험을 수행하는 에이전트에게 전달하기 위한 의견이며 새 실험 결과가 아님. 새 학습·작업자 호출·GPU 할당은 없었고 기존 파일은 수정하지 않았음.

**핵심: 재현성은 이미 충분함. 같은 엄격함을 “이 실험이 가설을 가를 수 있는가”에 써야 함.** 11/9 저녁 이후의 선택기 실험은 틀림없이 재현되지만, 학습 선택기에 유리한 결과가 나올 수 없는 시험대에서 수행됐음.

검토 범위는 다음과 같음.

- 11/9–10 보고서와 계획은 직접 읽었음.
- 아래 96상태 수치는 [재측정 자료](../../datasets/memory_decisions/20261110-refresh-v1/README.md)의 `all-supervision.jsonl`에서 다시 계산했고 기존 보고서와 일치함. 명령은 문서 끝에 있음.
- 11/3–8 단계는 요약을 통해 파악했고, 원장과 원 보고서의 일부 수치만 대조함.

## 유지할 점

- 부정 결과를 덮지 않고 그대로 보고함.
- 관계 주석과 실제 득실을 별도 필드·평가로 유지함.
- 로컬 재현이 어긋났을 때 수집을 멈추고 한 환경에서 전부 다시 측정함.

## 1. 학습 전에 개선 여지를 계산하고, 작으면 학습하지 않음

현재 상태를 반영한 참조 규칙(`state_rule`)의 96상태 결과를 나누면 다음과 같음.

| 규칙 정책의 결과 | 상태 수 |
| --- | ---: |
| 성공 | 55 |
| 실패: 은행에 근거가 없음. 무기억을 포함한 모든 행동이 실패 | 24 |
| 실패: 두 참조를 정확히 전달해도 무기억을 포함한 모든 행동이 실패 | 14 |
| 실패: 측정한 다른 후보는 성공 | 3 |

근거:

- 규칙의 실패 41건 중 38건은 측정한 어떤 행동을 골라도 실패임. 선택으로 바꿀 수 있는 것은 3건임(과거에만 있음 2, 현재에도 보임 1, 가용성 변경 0). 검색 상위 2개와 `rule2`도 같은 55·38·3임.
- 이 간격은 11/9 저녁에 이미 기록됐음. [파일럿 회고](2026-11-09-travel-state-utility-pilot.md)에 관측 상한 58이 있고, [중심 가설 노트](../ai-memory-state-aware-selection-learning-2026-11-09.md)도 55와 58의 간격이 작다고 적음.
- 그 뒤 같은 12문제군으로 학습 64회를 수행함: [입력 ablation](2026-11-09-memory-state-ablation.md) 24, [선택 손실](2026-11-10-memory-contrast-loss.md) 12, [적합 진단](2026-11-10-memory-fit-diagnostic.md) 4, [보강 자료](2026-11-10-memory-refreshed-learning.md) 24.
- 같은 자료에서 상위 4개 대 2개의 +4상태도 문제군 재표집 구간이 0을 포함했음([진단](2026-11-09-current-research-diagnosis.md)). 3상태 여지는 12문제군의 잡음보다 작음.
- 이전 시험대도 같은 구조였음. API 개발 자료는 최선 고정 11 = 사후 최선 11([통합 리뷰](../../training/memory_selector/reviews/2026-11-08-integrated/README.md)), Django 초기화는 항상 제공 6/8 = 사후 최선 6/8([파일럿](2026-11-08-memory-unit-pilot.md))이었음.

요청:

- 새 자료마다 `사후 최선 − 가장 강한 단순 정책`을 문제군 단위로 먼저 보고함. 그 차이가 해당 문제군 수에서 구별 가능한 크기보다 작으면 선택기 학습을 시작하지 않고 시험대를 고침.
- 정확한 근거를 줘도 작업자가 못 푸는 요청은 선택 평가에서 분리함. 위 14상태는 6개 요청·6문제군에 몰려 있음. 정답 근거를 제공한 조건의 성공률을 선택 실험 전에 측정함.

## 2. 가설이 참일 때 차이가 나는 시험대를 먼저 만듦

근거:

- 선택이 사람·날짜·항목의 대조로 끝남. 그 대조를 하는 규칙이 사후 최선 58 중 55를 얻음.
- 전달 묶음은 49–254토큰으로 512토큰 상한에 닿지 않음. 같은 예산에서 무엇을 남길지는 시험되지 않음.
- 필요한 정보가 현재에도 보이는 24상태에서 무기억 19, 상위 2개 제공 19임(개선 1·악화 1). 상태를 보고 보류해도 성공 수는 늘지 않고 토큰만 줄어듦.
- 진행·실패 이력은 자료에 없음. 각 보고서가 이를 명시함.

요청:

- 같은 요청 문장에서 현재 상태 C1/C2에 따라 최선의 기억 M1/M2가 뒤바뀌는 교차 사례를 2–3문제군에 먼저 만듦. 후보는 갱신되거나 서로 충돌하는 기록, 관련 기록이 예산을 넘는 은행, 실패 뒤 재시도 시점임.
- 이는 [실행안](../ai-memory-four-issues-catchup-plan-2026-11-10.md)의 “상태와 기억의 교차 검증”에 해당함. 실행 기록은 찾지 못했음.
- 상태를 읽지 않는 정책(질문만 쓰는 검색·규칙)이 넘지 못하는 선이 생기는지 작업자 실행으로 확인한 뒤에 문제군을 늘림.

## 3. 알려진 계측 결함을 안은 채 실험을 쌓지 않음

근거:

- **`UNKNOWN` 미출력.** 504개 출력 중 0건이라 은행에 근거가 없는 24상태는 항상 실패임. 11/9 [후속 실험](2026-11-09-travel-policy-followup.md)에서 0/24를 확인했고, 시도한 보완은 시스템 지침 교체 한 번임.
- **지침 충돌.** 96상태의 사용자 턴 1,536건 전부에 `Return NONE for a component if no listed choice satisfies its conditions`가 있고 `UNKNOWN`은 시스템 지침에만 있음. 강화 지침도 시스템 메시지만 바꿨음(`training/memory_selector/travel_policy_protocol.py`의 `messages`). 이 문장이 없는 36건 점검에서도 0/24였으므로 원인으로 확정하지는 않음. 제거해야 할 교란임.
- **악화 라벨.** 23묶음 중 16개는 무기억의 근거 없는 정답 일치가 깨진 경우임. 근거를 준수한 성공을 망친 것은 7묶음·2상태·2문제군임. “악화 recall 0/23”의 대부분은 우연히 맞은 기준선을 예측하라는 요구임.
- **단일 greedy 출력.** 로컬 offload 재현 검사 80건 중 1건에서 판정이 달라졌음([보고서](2026-11-10-memory-contrast-loss.md)). 라벨 하나가 실행 환경의 수치 차이에 좌우됨.

요청:

- 36건 계약 점검에서 출력 형식 변형 2–3종을 먼저 비교함. 참조 기록 ID를 먼저 적게 하는 구조화 출력, `UNKNOWN` 예시 제공, 사용자 턴 문장 정리가 후보임. [세 미해결점 검증안](../ai-memory-three-issues-validation-plan-2026-11-09.md)에 이미 있는 비교임.
- 고쳐지지 않으면 근거가 없는 조건을 성공 분모에서 분리해 보고함. 그 조건의 지표는 근거 없는 구체 선택으로 둠(48항목 중 무기억 9, 상위 2개 30, 상위 4개 31).
- 학습·평가 목표를 근거 준수 성공과 근거 없는 구체 선택으로 옮김. 근거 기준의 손해는 2상태뿐이므로 지금은 학습 목표가 아닌 기술 통계로만 보고함.
- 새 수집에서는 득실이 갈린 상태에 한해 반복 표집으로 성공 확률을 기록하는 방안을 비교함.

## 4. 탐색과 확증을 나눔

근거:

- 12개 개발 문제군 위의 탐색 실험마다 사전 고정·가중치 재적재·새 clone 재현을 수행함. 커밋 63개 중 새 clone 재현 기록이 10개임.
- dev 20·test 40 문제군은 실행 기록이 없음([새 문제군 검증안](../ai-memory-fresh-source-evaluation-2026-11-09.md)).
- 8 epoch·λ=1·τ=0.5·제공 문턱 0은 조정용 분할 없이 고정됐음.
- 모델은 학습 자료도 74–90%만 맞혔음(보강 학습 73.6–87.1%, 입력 ablation 83.8–90.3%). 학습 fold의 악화도 7–16/46만 맞혔음. 덜 학습된 임의 설정 하나의 실패는 가설의 기각이 아님.

요청:

- 탐색은 학습 문제군 안쪽의 문제군 단위 분할로 epoch·문턱·가중치를 고름. 검산은 입력·라벨 해시 대조와 저장 예측 재집계로 충분함. 결과는 탐색으로 표시함.
- 확증은 설정을 한 번 동결하고, 본 적 없는 문제군에서 한 번 실행함. 전체 검산 절차는 이 단계에 적용함.

## 5. 기준선과 편법 검사를 학습 전에 돌리고, 지표를 선택에 맞춤

근거:

- 기억을 읽지 않는 구조 기준선 65.4%가 학습 모델 최고 63.2%보다 높다는 것이 학습이 모두 끝난 뒤에 나왔음([데이터 리뷰](2026-11-10-memory-training-data-review.md)).
- 네 범주 라벨의 두 비트 중 하나는 무기억 성공 여부임. 같은 상태의 후보끼리는 값이 같아 순위에 기여하지 않음. 선택 손실의 기울기는 CE의 약 9–13%였음.
- 제공 문턱 0·비용 가중치 0에서는 92–95/96 제공이 결정 규칙의 귀결임.
- 효용 선택기는 base에서 새로 학습해 64상태로 사람·날짜 대조를 다시 배워야 했음. 확장 후보에서 Emma 2일차 0.617보다 6일차 0.685에 높은 점수를 줬음. 기존 검색·판독은 24요청 중 23개에서 두 참조를 상위 2개 안에 넣었음.
- 여행 검색 LoRA는 도메인 안에서 R@10 68.6→92.0%였지만([보고서](2026-11-09-candidate-search-learning.md)), 외부 LongMemEval-S 근거 확보는 252→161/470이었음. 새로 확보한 문항은 0, 잃은 문항은 91임([보고서](2026-11-10-selector-size-and-transfer-validation.md)).

요청:

- 자료마다 학습 전에 사전 확률·상태만·기억만·개수/길이·규칙 기준선을 계산하고, 모델은 그중 가장 강한 것과 비교함.
- 주 지표를 같은 상태 안의 후보 순위(현재 177쌍)와 선택 후 결과로 둠. 네 범주 정확도는 보조 지표로 내림.
- 무기억 성공(상태 단위)과 제공 후 성공(묶음 단위)을 따로 예측하는 비교를 추가함.
- 참조 판독 점수나 규칙 일치 특징을 입력으로 주고 효용 모델에는 중복·보류 판단을 남기는 조건을, base에서 새로 학습하는 조건과 비교함.
- 미세 조정한 부품은 고정 base와의 외부 자료 비교를 통과한 뒤에 개선으로 보고함.

## 6. 현재 상태를 한 장으로 유지함

근거:

- 날짜가 11-09·11-10인 문서가 36개, 약 25만 자임(미추적 포함).
- 루트 `README.md`에는 11/10 결과가 없고 검색 92.0%가 최신 결과로 남아 있음.
- `training/experiments.json`의 마지막 항목은 11/9 후보 검색임. 이후 8개 실험이 없음: 상태·효용 파일럿, 정책 후속, 입력 ablation, 선택 손실, 적합 진단, 작업자 재측정, 보강 학습, 선택기 검증.
- 중심 가설 노트와 인계용 실행안을 포함한 문서 14개와 자료 폴더 8개가 git 밖에 있음.
- 중심 질문이 문서마다 다름. 데이터·측정이 주 기여라는 문서, 상태 기반 선택이 중심 가설이라는 문서, 선택 모델은 한 가지 방법이라는 문서가 같은 날 작성됐음.

요청:

- 한 장짜리 상태 문서를 두고 실험마다 갱신함. 내용은 중심 질문, 현재 기준 표, 알려진 결함, 다음 실험 하나와 그 중단 조건임.
- 원장 등록과 진입 문서 갱신을 실험 완료 조건에 넣음.
- 미추적 문서는 커밋하거나 정리함.

2. 교차 사례를 2–3문제군에 구성하고 개선 여지를 측정함.

## 사용자가 정할 부분

지금까지 가장 분명한 결과는 선택기가 아니라 측정에서 나왔음.

- 기록을 더 주면 성공이 줄 수 있음: 상위 4개 51, 상위 2개 55.
- 근거 없는 기억은 추측을 늘림: 근거가 없는 조건의 구체 선택이 48항목 중 9에서 31로 늘었음.
- 정확한 참조를 줘도 14상태는 실패함.
- 참조를 맞게 고르는 것과 성공은 다름: 두 필수 참조를 모두 준 177묶음이 개선 57·둘 다 성공 78·둘 다 실패 33·악화 9로 나뉨.

이 측정을 주 기여로 둘지, 학습 선택기를 주 가설로 유지할지에 따라 2번의 설계가 달라짐. 이 결정은 실험 에이전트가 아니라 사용자의 몫임.

## 검토의 한계

- 모델 순전파·학습·작업자 실행을 다시 하지 않았음. 저장 결과의 재집계와 문서 대조임.
- 사용자 턴 문장과 `UNKNOWN` 실패의 관계는 확인하지 않은 가설임.
- 문서·커밋 집계는 2026-11-10 17:40 KST의 작업 트리(HEAD `8561fe7`) 기준임.
- 11/3–8 단계의 세부는 요약에 의존했음.
- 이 문서는 결과 색인과 README에 연결하지 않았음. 해당 파일에 다른 미커밋 변경이 있어 건드리지 않았음.

stats = collections.Counter()
for rs in by.values():
    best = max(ok(r) for r in rs)   # 무기억과 측정한 모든 묶음 중 사후 최선
    rule = ok(pol(rs, 'state_rule'))
    stats['규칙 성공'] += rule
    stats['사후 최선'] += best
    if not rule:
        if best: stats['실패: 다른 후보는 성공'] += 1
        elif rs[0]['condition'] == 'missing': stats['실패: 은행에 근거 없음'] += 1
        else: stats['실패: 참조를 줘도 모든 행동 실패'] += 1
for k, v in stats.items(): print(v, k)
print(sum('UNKNOWN' in r['text'] for r in rows), '/', len(rows), 'UNKNOWN 출력')
