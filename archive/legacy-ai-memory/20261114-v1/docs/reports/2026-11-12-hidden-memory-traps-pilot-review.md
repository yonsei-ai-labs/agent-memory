# 새 숨은 함정 파일럿의 독립 검토

2026-11-12. [인계 노트](../ai-memory-hidden-memory-traps-pilot-handoff-2026-11-12.md)와 [새 납품 데이터](../../datasets/hidden_memory_traps/pilot-20261112-v1/README.md)를 검토함. **이전 초안의 의미·대조·길이 문제가 실제로 보완됐고, 통제된 기억 평가 파일럿으로 사용할 근거가 있음. 실행 전에는 전달 예산 계산과 UNKNOWN에 대한 해석을 수정해야 함.** 원본 노트·데이터·다른 작업 트리는 변경하지 않음.

[별도 검산 코드·수치·모델 해석 기록](data/hidden-memory-traps-review-20261112-v2/README.md)을 보존함. 새 학습·작업자 호출·GPU 할당·유료 호출은 없음.

## 검토한 버전과 범위

자료는 main 커밋 `d1177d4`의 4세션·92판단·552사례·1,536기록임. 생성 코드는 별도 작업 트리 `953217b`임. 부모 패킷 manifest SHA-256은 `a097c765a1100c1c1f4e8c3e624697107a55e642e13e9d81e21a4efa03d472ff`임.

앞선 보완 자료 `memory_state_supplement/20261112-v3`는 manifest `010189…`인 이전 84판단 패킷에 기반함. **새 자료와 이전 보완본은 서로 다른 버전**임. 같은 이름의 `pilot-20261112-v1` 경로라도 manifest와 코드 커밋을 함께 확인해야 함.

## 숨긴 문장과 검토 문제의 의미

현재 정답표를 열기 전에 문장 42개의 해석과 판단 16개의 답을 별도 파일로 기록한 뒤 대조함. 문장은 핵심 사건의 뜻이 42/42 맞았고, 판단은 가능한 답 집합 전체가 16/16 일치함. 예외·범위·처음과 현재·없는 예약을 구별하여 답할 수 있었음.

- 이전의 “작은 모임”은 여행 내내 밤마다 파티를 한다는 문장으로 강해져 카탈로그 `No parties`와의 관계가 명확해짐.
- 변경처럼 보이는 보완의 명시/간접 문장이 같은 사건을 가리키도록 정리됨.
- 예외 예약에는 요청 원문이 남아, 확인 기록만으로도 한 번의 예외임을 알 수 있음.
- 검토용 판단 16개에 카탈로그와 과제 지침이 있어 답 집합을 검산할 수 있음.

이 검토자는 설계를 이미 읽은 Codex 모델이며, 사람이 눈가림으로 판단한 결과는 아님. 따라서 이를 독립 인간의 95% 일치 기준 충족으로 대체하지 않음. 여행의 다른 도시에서 밤을 보낸다는 문장은 이 과제의 “현재 사용할 예약”을 무효화하는 뜻으로 해석했으며, 실제 환불·계약 취소를 확인한 사실은 아님.

## 긴 기억 은행이 실제로 포함됨

각 세션 마지막 판단의 간접 표현 조건에서 길이를 다시 계산함. 토큰은 고정 작업자 tokenizer의 본문 기준이고 채팅 템플릿은 제외함.

| 단계 | 실제 전달 기억 블록 | 기록 목록 조건의 전체 입력 | 전체 대화 조건 입력 |
| --- | ---: | ---: | ---: |
| S | 2,196–2,368 | 3,300–3,501 | 5,733–5,846 |
| M | 16,956–18,459 | 18,060–19,595 | 29,818–32,128 |
| L | 78,061–79,803 | 79,194–80,922 | 103,468–104,963 |

마지막 조건 입력 48개의 토큰 수도 실제 메시지에서 다시 계산해 저장 수치와 일치함. README의 `Record list` 열은 추가 기억만의 길이보다 카탈로그·지침을 포함한 해당 조건의 입력 길이로 읽는 것이 정확함.

**이번 새 자료에는 “전체 기억이 대부분 2k 안에 들어간다”는 이전 보완본의 한계가 그대로 적용되지 않음.** M/L에는 전달 예산이 실제로 작동함. 다만 주변의 코드 생성 표·검색 목록을 늘린 통제 조건이며 자연 발생 긴 업무 이력의 대표성을 입증한 것은 아님. 길이·부가 내용·후보 수가 함께 바뀌므로 순수한 토큰 길이 효과로 부르지 않음.

각 단계의 184사례에서 필요한 기록의 누락은 S·M의 2k/8k 모두 0, L의 2k는 9개·8k는 2개임. 조건별 후보와 필요한 근거 집합에 따른 수치이며, 실제 작업자 실패나 학습 선택기의 개선 수가 아님. 긴 은행에서도 BM25가 근거를 잘 확보하는 경우가 많아 오용·불필요 제공과 실제 답변을 함께 측정해야 함.

## 실행 전 수정 1 실제 전달 블록으로 예산을 계산해야 함

현재 `inputs.py::bm25_budget`은 각 기록의 토큰 수를 합산함. 실제 입력에는 머리말과 줄바꿈이 추가되고, 기록을 이어 붙인 뒤 토큰화한 수는 개별 합과 다름.

| 조건 | 별도 기록 합은 예산 이내 | 실제 전달 블록 초과 | 최대 초과 |
| --- | ---: | ---: | ---: |
| BM25 2k | 552/552 | 254/552 | 49토큰 |
| BM25 8k | 552/552 | 132/552 | 50토큰 |

예를 들어 `58357e6d94c7d840607cf928-t51:hidden:M`의 8k 조건은 기록별 합 8,191이지만 실제 블록은 8,242로 8,192를 초과함. 2k 조건의 한 사례도 합 2,047·실제 2,097임. 큰 길이 효과를 뒤집을 규모는 아니지만 같은 예산의 정책 비교 전에 바로잡는 것이 적절함.

후보를 하나 추가할 때마다 시간순으로 정렬한 `trial`에 대해 `count_tokens(_block(trial)) <= budget`을 검사하고, 최종 입력에서도 다시 확인하면 됨. 수정 후 선택 ID·메시지 해시·근거 누락 수를 새 버전에서 재생성해야 함. 현재 기록된 9/2누락을 수정 후 결과로 복사하지 않음.

## 실행 전 수정 2 UNKNOWN에서 실제 손해 방향을 가정하지 않음

인계 노트와 protocol은 정답이 UNKNOWN인 곳에서 “무기억이 맞으므로 기억은 손해만 줄 수 있음”을 설계상 사실로 설명함. **항상 UNKNOWN을 내는 정책의 정답 여부와 실제 무기억 작업자의 성공은 다름.** 실제 작업자는 근거 없이 장소를 고를 수 있고, 취소 근거를 전달하면 그 오류를 줄일 수도 있음.

현재 UNKNOWN 정답은 12시점이며, 그중 4시점에는 필요한 취소 근거 ID가 동시에 주석돼 있음. `needs_memory=false`와 `required_memory_ids`의 뜻을 구분해야 함.

- `needs_memory`의 현재 계산은 “정답이 UNKNOWN인가”에 의해 결정됨. 이를 기억의 실제 필요성·효용 정답으로 학습시키지 않음.
- 정답에 구체적 ID가 있는지, 필요한 근거가 있는지, 현재 제공된 입력으로 충분한지를 별도 항목으로 정의하는 것이 적절함.
- UNKNOWN 시점도 실제 무기억·기억 조건에서 양방향 득실을 측정하고 제외하지 않음. 상수 UNKNOWN 기준선은 별도로 보고할 수 있음.

효용을 모두 `null`로 둔 데이터 자체는 이 구분을 보존하고 있음. 수정할 핵심은 설명과 필드 사용 계약이며 실제 결과를 미리 한 부호로 제한하지 않는 것임.

## 학습 전 보완 3 판독 입력과 미주석 후보의 계약

다른 기록이 있어야 무효로 판정할 수 있는 원 주석은 20개임. 새 데이터는 `judge_with`와 후보 은행을 제공하지만, 실제 작은 선택기가 읽을 문자열은 별도 확정해야 함. 요청과 후보 하나만 입력하면 근거가 빠질 수 있음.

M에는 미주석 후보 1,356출현, L에는 4,496출현이 있음. 생성상 무관한 부가 내용이라는 설명은 있으나, 이를 학습에 넣으려면 명시적인 무관 주석 또는 loss 마스킹을 정해야 함. 누락을 자동 음성으로 처리하지 않음.

특히 7.8만 토큰 은행을 현재 검증한 4,096토큰 판독 입력에 그대로 넣을 수 없음. 정답 ID에 의존하지 않는 후보·문맥 구성과 누락 시 `insufficient` 처리를 먼저 정해야 함. 이 패킷을 기존 Harrier 학습기에 바로 넣을 수 있는 자료로 설명하지 않음.

## 버전과 문서에서 주의할 부분

이전 보완본의 기록 키 중 새 자료에도 존재하지만 본문이 바뀐 것이 338행임. 이 수는 명시/간접 표현을 구분한 행 수임. 원 사건 순서가 바뀌었는데 세션·요청 번호 기반 ID는 재사용되기 때문임. **부모 manifest를 포함한 키로 구분하고, 이전 라벨·캐시·증강을 새 자료에 ID만으로 결합하지 않음.** 이전 보완본 자체가 손상됐다는 뜻은 아님.

“부가 메시지에 닮은 인물이 없음”이라는 설명도 좁혀야 함. 표에 있는 부가 기록 108행에서 실제로 해당 세션의 닮은 이름이 나타남. 이들은 짐 목록·단체 대화에 등장하며 예약 사실을 제공하지는 않음. 이름이 검색을 교란할 수 있다는 점까지 포함해 설명하면 됨.

현재 자료는 무작위 순서를 갖는 53턴 대본의 접두부 평가임. 과거 답은 정답으로 고정되어 있으므로 실제 작업자가 앞 질문에서 틀린 뒤 그 답이 자기 기억에 쌓이는 온라인 실험은 아님. 이 범위 안에서 “통제된 누적 과거를 읽는 비교”로 설명하는 것이 정확함.

## 판단과 권장 순서

이전 초안보다 의미·대조·실제 길이가 개선됐으며, 현재 연구의 데이터·측정 기여에 맞는 파일럿임. 예산 계산과 UNKNOWN 해석을 수정하고 보완된 검토표의 인간 의미 검토를 거친 뒤, 제한된 작업자 측정으로 진행하는 것이 적절함.

검산을 통과한 것은 규칙·원문·입력의 일관성임. 독립 단위는 여전히 이전에 사용한 4세션이고, 문장 틀은 종류별 3개이며, 실제 득실·선택기 우위·온라인 일반화는 미측정임. 정책이 의도한 특정 함정에서 구조적으로 약해지는 사실을 그 정책의 일반적인 열세로 확대하지 않음. 원자료·중립·반대 결과를 보존하며 다음 단계를 판단함.
