# 기억의 부분별 기여를 측정할 수 있는가: 기능 검증

2026-11-05 · 고정한 10회 실행과 사후 감사 완료. **부분을 바꿔 제공하고 성과·비용 차이를 계산하는 경로는 통과했다. 어느 부분이 유익하거나 유해한지의 방향과 일반성은 확인하지 못했다.**

## 목적과 사전 판정 기준

기억 안의 특정 부분을 넣거나 뺐을 때의 성과·비용을 계산하고, 그 차이가 실제로 선언한 입력 개입에서 나왔는지 검증한다. 이번 검사는 효능 방향의 확증이나 사실·지침 일반의 우열 비교가 아니다.

기술적으로 통과하려면 다음을 모두 만족해야 한다.

- 원문에서 선언한 구간만 제거한 변형이며, 대상 정답으로 내용을 만들지 않는다.
- 실제 첫 API 입력에서 그 구간 외의 카드 ID·안내·모델 설정·도구·기본 문제 입력이 같다.
- 제공하기로 한 부분은 첫 요청에 실제 포함되고, 제외하기로 한 부분은 그 위치에 없다.
- 모든 시작한 실행의 비용·종료·채점이 기록되며, 기대 가능한 미제출도 분모에서 제외하지 않는다.
- 조건부 기여와 조합 효과를 사전에 정한 식으로 계산하고 작은 표본의 불확실성을 표시한다.

## 실제로 바꾼 것

출처는 이전에 실제 수행한 Sphinx 8435의 절차 카드 한 장이다. 원문 전체를 그대로 유지한 조건과, 그 안의 두 문장 묶음을 삭제한 조건을 만든다. 카드를 새 모델로 다시 요약하거나 현재 대상의 정답 지식을 추가하지 않았다.

| 구간 | 원문에서의 내용 | 실험에서의 역할 |
| --- | --- | --- |
| 공통 맥락 C | 출처 문제, 적용 한계, 로컬·공식 결과 구분 | 네 카드 조건에 동일하게 유지 |
| 관측 묶음 F | 재현 예제에서의 오류와 제출 구현·관측 결과 | 유무를 비교 |
| 절차 묶음 P | 주석 처리 경로를 조사하고 별칭을 처리한 잠정 접근법 | 유무를 비교 |

F에도 과거 행동에 대한 사실이 있고 P에도 구체적인 정보가 있다. 따라서 명칭만으로 순수한 사실과 순수한 행동 지시의 의미 효과를 분리했다고 주장하지 않는다. 이번에 측정하는 것은 **원문 구간의 추가·삭제 효과**다. 제거하면 입력 길이와 문맥도 달라지며, 길이를 맞춘 별도 대조는 이번 기능 검증에 포함하지 않는다.

조건은 `무메모리 / C / C+F / C+P / C+F+P`이고 각 두 번, 총 10회다. C는 출처 정보를 가진 대조이지 무메모리가 아니다. 별도의 무메모리를 두어 전체 카드 제공 효과도 계산한다. 첫 반복의 순서는 고정 seed로 섞었고 둘째 반복은 그 역순이다. 각 조건이 상보적인 위치를 차지하지만 두 번의 독립 무작위 순서는 아니다.

대상은 Sphinx 10325다. 앞선 R10에서 공개 문제 설명으로 선정해 환경만 준비했고 모델 실행은 하지 않았던 과제다. 연구자는 환경 점검에서 정답 대조를 이미 실행했으므로 완전히 보지 않은 과제라고 부르지 않는다. 새 대표 표본도 아니다. 이전 R10은 미실행으로 보존하고 이번 계획은 별도 실행으로 기록한다.

출처 문제는 `autodoc_type_aliases`, 대상 문제는 `inherited-members`가 여러 클래스를 처리하는 기능이다. 같은 저장소의 autodoc이라는 연관은 있지만 해결에 필요한 세부 지식은 다르다. 공개 설명에서 확인되는 이 차이 때문에, 이번 조합을 기억의 이득이 반드시 드러나는 양성 대조로 취급하지 않는다. 기능 검증에서 쓸 수 있는 준비된 조합과, 전이 효과를 식별하기에 적합한 연구 표본은 구분해야 한다.

## 실행기의 보완

기존 시작 제공은 어휘 검색 결과에 의존했다. 이번에는 적격성·출처 시점 검사를 통과한 특정 카드를 직접 고정해 제공하여, 문장 삭제가 카드 선택까지 바꾸지 않게 했다. 원래 표시하던 본문 SHA-256도 모델 입력에서만 생략했다. 그러지 않으면 문장과 함께 의미 없는 해시 문자열까지 달라진다. 원본·은행·반환 기록의 해시는 계속 검사한다.

같은 모델·제공자·추론 설정, 이미지, 기본 프롬프트, 32회 호출·600초의 에이전트 한도를 유지한다. 실행당 비용 중단 기준은 $0.05, 이번 묶음은 $0.75다. 비용 한도는 요청 종료 뒤 점검하므로 완전한 요청 단위 하드 상한이 아니다. 이전 비용과 합산해 기존 $10 기준 안에서 관리한다. 고정 카드 허용량을 소비한 `searches=1`은 이번 모드에서는 질의 검색 횟수가 아니며 `fixed_preload_returned` 이벤트로 구분한다.

완전한 비용 기록·API 오류 없음이 확인된 `LimitsExceeded / no_submission`은 전달 실패로 남기고 다음 배정을 진행하도록 명시적으로 허용했다. 원래 공식 채점 값은 `null`을 유지한다. 비용 미상·환경 오류·불완전 채점은 중단하며 자동 재시도하지 않는다. 기존 중단 배치를 소급 변경한 것은 아니다.

[환경 점검](data/component-feasibility-20261105/environment-precheck.json)에서 기존 원본 실패·정답 성공 대조와 이미지 해시가 유효함을 확인했다. 현재 HEAD의 조상이 아닌 ref 도달 커밋은 0개였다. 과거 Git 이력은 모든 조건에서 그대로 접근 가능하다. 도달 불가능한 객체·학습 데이터의 오염까지 검사한 것은 아니다. 네트워크는 끈 상태다.

유료 실행 전에 로컬 검사 43개를 통과했다. 고정 제공이 어휘 겹침 없이도 동작하는지, 미래 출처를 거부하는지, 입력에서 내용 외 차이가 없는지, 비용이나 평가가 불완전한 결과를 정상으로 오인하지 않는지, 대비 산식과 불확실성이 올바른지를 검사했다. [검사 로그](data/component-feasibility-20261105/prelaunch-tests.log), [이전 코드 보존 목록](data/component-feasibility-20261105/pre-change/manifest.json).

## 계산하는 수치

`p(S)`는 고정된 대상·모델·예산에서 S를 제공했을 때 공식 해결물을 제출할 확률이다.

```text
주 대비: 관측 내용 위에 절차를 추가한 기여 = p(C+F+P) − p(C+F)
관측 내용의 기여, 절차 있음             = p(C+F+P) − p(C+P)
공통 맥락 위의 각 부분 기여             = p(C+F) − p(C), p(C+P) − p(C)
조합 효과                             = p(C+F+P) − p(C+F) − p(C+P) + p(C)
전체 기억 효과                         = p(C+F+P) − p(무메모리)
```

모든 배정 실행의 평균 비용에도 같은 대비를 적용한다. 공식 목표·유지 테스트 결과를 함께 남긴다. 성공 실행만 골라 비용을 비교하지 않는다. 카드 제작과 출처 수집은 기존 자료를 재사용했으므로 이번 추가 모델 비용에는 들어 있지 않다. 새 출처를 수집하는 정책의 총비용으로 외삽할 때는 따로 포함해야 한다. 캐시는 관측하며 초기화하지 않았다. 두 실행의 평균 비용 차이에 신뢰할 만한 비용 신뢰구간을 붙이지 않는다.

이진 성과는 각 셀의 Clopper–Pearson 구간을 대비에 들어가는 셀 수에 맞춰 Bonferroni 조정해 조합한다. 이는 이 과제에서 반복이 독립·동일 성공 확률이라는 가정 아래의 보수적인 **대비별 95% 범위**다. 과제 모집단의 신뢰구간이나 모든 대비를 동시에 보호하는 다중검정 결과는 아니다.

[정밀도 진단](data/component-feasibility-20261105/precision-diagnostic.json)은 실제 결과가 아닌 정확한 가상 계산이다. 두 조건의 진짜 성공 확률이 모두 50%이고 각 두 번 독립 실행하면, 관측 성공률 차이가 50%p 이상 나는 확률이 62.5%다. 그러므로 이번 10회로 유익·유해 방향을 확정하는 것을 통과 조건으로 삼지 않았다. 측정 경로가 동작하는 것과 필요한 정밀도를 확보하는 것은 별도다.

### 실제 입력과 결과를 연결했는가

통과했다. 두 반복 모두 실제 첫 API 요청에서 P 구간만 삭제하면 C+F 조건의 요청 전체와 같고, F만 삭제하면 C+P 조건과 같았다. 나머지 삭제 대조도 동일했다. 기억 구간을 제거한 모든 조건의 요청은 도구 정의와 모델 설정까지 같았다. 같은 조건의 두 반복도 첫 요청이 같았다. 카드 제공 8회에서는 모두 첫 요청부터 지정한 내용이 노출됐고 무메모리 2회에는 없었다. 이 검사는 입력 노출의 증거이며 모델이 내용을 실제로 활용했다는 증거는 아니다.

### 어느 부분이 득·실인지 판정했는가

아직 판정하지 못했다. 모든 조건이 2/2여서 성공률 대비의 점추정은 전부 0%p다. 주 대비 `p(C+F+P)−p(C+F)`의 보수적 95% 범위는 **−88.82~+88.82%p**다. 전체 기억과 무메모리의 대비도 같다. 매우 작은 표본에서 얻은 0%p를 효과 없음이나 동등성의 증거로 해석할 수 없다. 관측 성공률이 이미 상한에 있는 이 조합에서는 성과 차이가 드러나지 않았다.

비용 대비는 숫자로 계산된다. 비용의 양수는 지출 증가, 음수는 감소다.

| 비교 | 관측 평균 비용 차이 / 실행 |
| --- | --- |
| C 위에 F 추가 | +$0.00146745 |
| C 위에 P 추가 | −$0.00117600 |
| C+F 위에 P 추가 — 주 대비 | +$0.00003648 |
| C+P 위에 F 추가 | +$0.00267993 |
| F와 P의 조합 효과 | +$0.00121248 |
| 전체 기억 − 무메모리 | +$0.00272347 |
| C − 무메모리 | +$0.00121954 |

예를 들어 전체 기억의 평균 비용은 무메모리보다 약 67.6% 높았다. 하지만 C+F의 두 실행만 해도 $0.00390과 $0.00954로 달랐다. 조건당 두 번이고 캐시도 통제하지 않았으므로, 이 차이를 안정적인 손해 크기나 특정 문장의 유해성으로 확정하지 않는다. 실제 성공률과 비용을 함께 기록할 수 있다는 것, 그리고 방향 판정에는 별도의 정밀도가 필요하다는 것을 확인했다.

### 이 방향을 이어갈 때 필요한 다음 검증

기존 문제와 과거 실행 기록을 재사용하고 원문 구간을 삭제하는 방식으로 대조를 만들 수 있었다. 새 문제나 유익·유해 정답 라벨을 사람이 대량 작성해야만 시작할 수 있는 방향은 아니다. 반면 현재의 한 카드·한 과제 반복을 늘리는 것만으로 사용자가 원하는 일반적인 득실 요인을 알아낼 수는 없다.

1. 공개 문제 설명과 출처 근거로 재사용 가능한 정보가 있는 여러 출처·대상 쌍을 정한다. 같은 저장소라는 이유만으로 강한 전이를 가정하지 않으며, 이전 결과를 본 과제는 탐색 층으로 남긴다.
2. 별도 탐색 집합에서 성공률의 상한·하한에 몰리는지와 실행 변동을 확인한다. 쉬운 과제에서 효율을 보려면 예산 조건도 미리 정해 실제 제출 성과를 비교한다. 좋은 결과가 나오는 조합만 사후 선별해 확인 집합으로 쓰지 않는다.
3. 다음 확인에서는 부분의 추가·삭제 또는 적용 조건 표시처럼 한 개입과 주 대비를 먼저 고정한다. 원하는 최소 차이와 허용 오차에 맞춰 서로 다른 과제 수·반복 수를 정하고, 새 집합에서 검사한다. ‘사실 대 지침’이라는 일반적인 의미 효과를 주장하려면 정보의 중첩과 길이 차이에 대한 추가 대조가 필요하다.

현재 판정은 **기술적 측정 가능, 득실 식별의 정밀도 미확보, 일반화 미검증**이다. 이번 결과로 유익·유해 라벨을 생성하거나 유리한 조건을 고르지 않는다. 이후 계획과 제안은 [후속 설계](../ai-memory-next-validation-plan.md)에 있으며 이번에는 추가 실행을 시작하지 않았다.
