# 새 문제군에서 기억 제공의 득실과 효용 판독층을 확인한 결과

2026-11-09. **새 12개 문제군에서 실제 과거 기록 생성, 작업자 평가, 효용 판독층 학습·검산을 완료했다.** 관련 참조는 기존 검색과 학습 검색 모두 찾았지만, 실제 제공 효과는 달랐다. 학습 검색의 기억 제공은 무기억 대비 23개 상태를 개선하고 5개를 악화시켰다. 추가 효용 판독층의 성공률 개선은 확인하지 못했다.

이번 결과의 핵심은 **관계 판독 정답과 실제 득실을 연결해서 측정할 수 있게 됐으며, 성공률만으로는 손해 일부가 가려진다는 것**이다. 새 출처 일반화나 학습 선택기의 필요성을 입증한 결과는 아니다.

## 실행 범위와 데이터 품질

[사전 계획](../ai-memory-travel-state-transfer-2026-11-09.md), [고정 입력](../../datasets/travel_state_transfer/20261109-v1/README.md), [공유 산출물·재현](../../evaluation/results/travel-state-pilot-20261109-v2/README.md).

공개 TravelPlanner validation에서 이전 요청 및 출발지·목적지·기간 묶음과 겹치지 않는 120문제군을 train/dev/test 60/20/40으로 고정했다. 이번 실행은 train의 사전 지정 12개만 사용했다. 나머지 108개의 입력 명세는 준비됐지만 실제 이력·현재 결과는 아직 수집하지 않았다. dev/test 결과는 열지 않았다.

실제 과거 응답 36개에서 540개 선택 항목을 만들었다. 모두 카탈로그 안의 유효한 ID였다. 원래 속성·평점·가격 조건을 만족한 항목은 409/540, 그중 최저가와 ID 동률 규칙까지 맞힌 항목은 252/540이었다. 틀린 과거 선택도 실제로 선택한 기록으로 보존했다. 이 자료를 모두 성공한 과거 경험이라고 부르지 않는다.

현재 요청 24개 × 네 상태 × 여섯 정책 = 576개 정책 행이다. 같은 요청의 변형을 독립 출처로 세지 않는다. 독립적으로 묶는 단위는 12문제군이며 파일럿의 선택 도시는 12개다. 동일 입력의 greedy 출력을 공유하여 현재 고유 호출은 365개였고, 별도 반복 2개의 출력 토큰이 일치했다.

고정 Harrier 0.6B 검색 LoRA·판독 LoRA/MLP와 동일 Qwen3.5-9B worker를 사용했다. 새 GPU LoRA 학습은 하지 않았다. 추가 학습은 저장된 frozen 특징에 대한 CPU 선형 효용 head다. 이 과제는 공개 여행 카탈로그에 근거한 합성 후속 예약 선택이며, 전체 여행 일정이나 공식 MemoryArena/TravelPlanner 점수가 아니다.

## 실제 선택 결과

각 칸은 두 현재 선택을 모두 맞힌 상태 수이며 상태별 분모는 24다. `NONE`은 충분한 근거로 가능한 선택이 없음을, `UNKNOWN`은 필요한 과거 근거를 알 수 없음을 뜻한다. 기억 없이 우연히 맞힌 답도 주 성공률에는 포함한다.

| 현재 상태 | 무기억 | 전체 기억 | 기존 검색 | 학습 검색 | 참조 규칙 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 과거 선택이 현재 관측에는 없음 | 3 | 16 | 19 | 18 | 18 |
| 필요한 과거 선택이 현재에도 보임 | 19 | 16 | 18 | 18 | 19 |
| 현재 가용성이 바뀜 | 11 | 7 | 15 | 15 | 18 |
| 필요한 참조가 기억 은행에도 없음 | 0 | 0 | 0 | 0 | 0 |
| **합계 / 96** | **33** | **39** | **52** | **51** | **55** |

현재 관측에 이미 있는 기록을 보류하는 `state_rule`도 55/96이었다. 네 상태의 구성 비율은 통제 설계이며 자연 발생 빈도가 아니다.

학습 검색 제공과 무기억의 짝 비교는 다음과 같다.

| 상태 | 개선 | 악화 | 변화 없음 |
| --- | ---: | ---: | ---: |
| 현재 관측에 없음 | 17 | 2 | 5 |
| 현재에도 보임 | 1 | 2 | 21 |
| 가용성 변경 | 5 | 1 | 18 |
| 참조 없음 | 0 | 0 | 24 |

개선 23개는 12문제군, 악화 5개는 4문제군에 분포했다. 이는 고정 worker의 이번 greedy 실행에서 관측한 차이다. 확률적 반복의 평균 처리 효과를 추정한 것은 아니다.

## 검색 정답만으로 설명되지 않는 부분

필요한 두 참조가 은행에 있는 요청 24개에서 기존·학습 검색 모두 48/48개 참조를 최종 4기록에 포함했다. 따라서 기존 검색 52와 학습 검색 51의 차이를 필요한 참조를 더 잘 찾은 효과로 해석할 수 없다. 함께 전달한 다른 기록과 길이 등이 달랐다.

새 은행은 27/45/63개이고 참조는 두 개다. 특히 27개 은행은 32후보가 전체 은행을 포함한다. 이전 26–336개 은행, 참조 1–12개, 최종 10기록의 92% 검색 성적과 직접 증감 비교하지 않는다. 이번 검색 난도에서는 학습 검색의 추가 우위가 드러나지 않았다.

참조 규칙의 두 기록은 모든 참조 보유 상태 72개에서 학습 검색의 네 기록에 포함되는 진부분집합이었다. 나머지 두 기록을 제거한 비교에서는 **5개 상태 개선·1개 악화**, 합계 51→55였다. 특히 가용성 변경에서는 15→18이었다. 전달하는 추가 정보가 결과를 바꿀 수 있음을 보여주는 관측이다. 내용과 길이의 효과를 분리한 실험은 아니며, 한 번의 생성 차이로 내부 원인을 확정하지 않는다.

예를 들어 Honolulu의 재사용 요청에서는 무기억이 `NONE/NONE`을 냈고, 실제 과거 기록을 받자 정확한 식당·숙소 `R577/H1087`을 골랐다. Amarillo의 다른 요청은 과거 숙소 가격 528 이하의 현재 가능한 숙소를 요구했다. 무기억은 가격 445인 `H1049`를 골라 맞혔으나 네 기억을 제공하면 가격 900인 `H3339`를 골라 틀렸다. 필요한 두 기록만 남기면 다시 `H1049`를 골랐다. 상세 원문·정답 집합·선택된 기록은 [사례 파일](../../evaluation/results/travel-state-pilot-20261109-v2/diagnostics/examples.json)에 있다.

## 성공률이 가리는 손해

참조가 없는 24상태에서는 어떤 정책도 요구된 `UNKNOWN/UNKNOWN`을 반환하지 못했다. 무기억은 대부분 `NONE`으로 응답했다. 이것은 현재 worker의 불가능/근거 부족 구분 실패이며, 전부 검색기 탓으로 돌릴 수 없다.

그러나 두 선택 항목씩 총 48항목을 보면 행동은 같지 않았다.

| 정책 | UNKNOWN | NONE | 필요한 참조 없이 구체적 ID 선택 |
| --- | ---: | ---: | ---: |
| 무기억 | 0 | 39 | 9 |
| 학습 검색 | 0 | 17 | 31 |
| 전체 기억 | 0 | 0 | 48 |

관련 참조가 없는 기억을 제공하면 구체적인 추측이 늘었다. **성공 여부만 사용하면 모두 ‘둘 다 실패’로 묶여 이 차이를 학습하지 못한다.** 위 수치는 실제 예약 피해나 전체 손해 건수가 아니라, 통제된 출력에서 측정한 근거 없는 구체적 선택이다. 원래 성공률 정답을 사후 변경하지 않고 [별도 진단·확장 신호](../../evaluation/results/travel-state-pilot-20261109-v2/diagnostics/extended-feedback.json)로 보존했다.

## 추가 효용 판독층

실제 제공/보류 결과를 개선·악화·둘 다 성공·둘 다 실패로 나눠 선형 softmax head를 학습했다. 라벨 수는 23/5/28/40이었다. 사전에 고정한 설정으로 문제군 하나를 제외한 11개로 학습하고 남은 하나를 예측했다. 12개 탐색 fold이며 미래 test 성적이 아니다.

| 정책/판독층 | 성공 / 96 | 기억 제공 / 96 | 추가 기억 입력 토큰 합 |
| --- | ---: | ---: | ---: |
| 항상 학습 검색 기억 제공 | 51 | 96 | 21,003 |
| 현재+제안 기억 특징, 4범주 head | 51 | 92 | 20,139 |
| 현재만 읽는 대조 head | 52 | 74 | 16,219 |
| 학습 라벨을 섞은 대조 | 49 | 94 | 20,561 |
| 참조 규칙+이미 확인한 기록 보류 | 55 | 48 | 5,022 |

주 head는 중립인 네 상태만 보류했고 악화 5개는 막지 못했다. 현재만 읽는 head는 주로 이미 확인한 상태의 제공을 줄였지만, 간단한 규칙보다 낫지 않았다. **새 판독층의 실용적 우위는 이번에 입증되지 않았다.** 소수 데이터·단일 고정 설정이며 구조 전반의 무효를 결론내리지 않는다.

무기억/학습 기억의 관측 결과 중 매번 좋은 쪽을 아는 가상의 상한은 56/96이다. 이는 **현재의 ‘0개/4개’ 두 행동에 한정된 상한**이며, 다른 기억 묶음이나 worker의 상한이 아니다. 실제 두 참조를 전달한 규칙 행동까지 선택지에 포함하면 관측 상한은 58/96이다. 따라서 항상 4개를 제공하는 51점에서 두 행동 gate가 개선할 수 있는 것은 최대 5상태였지만, 전체 연구 가능성의 상한을 56점으로 해석해서는 안 된다.

추가 토큰은 공통 현재 입력에 비해 기억이 더한 worker 입력 토큰이다. 전체 worker 입력 합은 무기억 95,887, 전체 기억 325,104, 학습 검색 116,890, 상태 규칙 100,909다. 캐시된 특징으로 학습·재생한 이번 head 결과에는 완전한 온라인 검색·인코더 비용이 들어 있지 않으므로 순비용 개선을 주장하지 않는다.

## 검증·실행 이력

- 정답 집합을 별도의 SQL 구현으로 재계산: 과거 540항목·현재 1,152항목 일치.
- 저장된 채팅 템플릿으로 입력을 다시 구성하고 토큰·텍스트를 재계산: 614개 저장 행 일치. 이 수는 캐시 재사용 행을 포함한다.
- 저장 특징과 실제 판독 가중치로 1,080개 점수, 192개 검색 순위를 검산. 최대 확률 오차 `1.19e-7`.
- CPU 효용 head 36개 checkpoint의 제외 예측 288개 재계산. 최대 확률 오차 `4.44e-16`; 학습 문제군만으로 정규화했는지 확인.
- 새 로컬 clone에서 기본 검사 50개·CPU head 검사 2개 통과. 비공개 원본 출력이나 GPU 없이 공유 자료만으로 주 결과·후속 진단·토큰·판독 가중치·효용 head 검산을 모두 재현했다.
- 동일한 현재 입력이 다른 배치 패딩 때문에 다르게 보이지 않도록 사전 규칙대로 같은 텍스트의 특징을 통일했다. 원래 특징 좌표의 최대 차이는 약 0.00255였다. 이를 의미 정보로 사용하지 않았다.
- A100 할당 두 번은 timeout. 첫 L4 실행에서는 JSON 코드 블록을 strict 파서가 거부해 과거 생성 중 중단했다. 원시 응답 22개를 보존·재사용하고 코드 블록 외곽만 읽도록 수정했다. 원시 선택값과 정답을 바꾸지 않았다.
- 최종 실행은 L4에서 완료했고 산출물 회수 후 종료했다. 두 L4 실행의 컨트롤러 경과 시간 합은 약 26.9분이다. 이는 정확한 청구 시간 산정이 아니다. 로컬 GPU와 새 유료 모델 API 호출은 사용하지 않았다.

전체 encoder forward를 CPU에서 독립 재실행한 검산은 아니다. [원본 해시·검산 결과](../../evaluation/results/travel-state-pilot-20261109-v2/README.md)와 실패 이력을 함께 공유한다.

## 다음 단계에 대한 판단

1. **worker의 `UNKNOWN`/`NONE` 구분을 별도 작은 점검에서 먼저 해결한다.** 이번 실패를 기록한 채 인터페이스 변경을 새 버전으로 검증한다. 기존 결과를 성공으로 고쳐 쓰지 않는다.
2. **효용 신호를 성공·근거 없는 구체적 선택·비용으로 나눈다.** 현재의 4범주만으로는 ‘둘 다 실패지만 더 나쁜 행동’이 구분되지 않았다. 이 세 신호를 예측하는 학습은 후속 가설이며 이번 결과를 보고 재학습해 좋은 숫자를 고르지 않았다.
3. **규칙으로 풀리는 명시적 참조를 넘어선 자료를 확보하고 새 출처를 확인한다.** 동일한 조건 관계가 자연스럽게 재등장하는 다른 경험, 표현 변화, 실제로 더 긴 과거 이력을 수집한다. 무관한 기록으로 은행만 키우지 않는다. 남겨둔 dev/test와 별도의 다른 환경·도메인 평가를 구분한다.

현재 120개 명세를 그대로 대량 실행하기 전에, 간단한 규칙과 작업자 인터페이스가 만들어낸 한계를 먼저 반영하는 편이 적절하다. 연구 중심은 계속 **같은 경험을 무엇까지 보존하고 언제 전달해야 이득인지 측정·예측하는 것**에 둔다.

## 추가 회고: 학습 목표와 정책이 어긋난 위치

사용자의 회고 요청 후 저장 가중치·특징·예측을 다시 읽었다. 새 학습·worker 호출·GPU 할당은 하지 않았다. 아래는 사후 진단이며 기존 정답·비교 설정을 바꾸지 않았다. [수치와 재현 방법](../../evaluation/results/travel-state-pilot-20261109-v2/README.md)에 근거를 남긴다.

**입력을 읽지 않는 기준선도 51점이었다.** 각 fold의 학습 자료만으로 계산한 평균 성공 증가는 0.170–0.216으로, 제공 임계값 0.05보다 모두 높았다. 이 평균만 따르는 정책은 모든 상태에서 제공해 51/96이다. 주 head도 51/96이므로 성공률에서는 이 무입력 기준선을 넘지 못했다. 분류가 어느 정도 학습됐다는 것과 유용한 개입을 배웠다는 것을 더 엄격히 구분했어야 한다.

**학습 때 잡은 손해가 제외 문제군으로 옮겨가지 않았다.** 주 head의 4범주 정확도는 학습 880/1,056(83.3%), 제외 예측 64/96(66.7%)였다. 학습 집계에서 손해 사례를 보류한 것은 44/55(80%)였지만, 제외한 문제군에서는 0/5였다. 학습 집계의 각 행은 같은 사례가 11개 fold에 반복된 것으로 추가 독립 데이터가 아니다. 실제 손해는 5상태·4문제군뿐이다. 자료 부족과 일반화의 약점을 보여주지만, 표현·정규화·학습 목표 중 어느 하나가 원인이라고 확정할 수는 없다.

제외 예측의 64개 분류 정답 중 60개는 ‘둘 다 성공/둘 다 실패’ 구분이다. 실제 개선은 4/23개만 개선 범주로, 손해는 0/5개를 손해 범주로 분류했다. 그럼에도 대부분을 제공한 것은 희소 손해와 낮은 제공 문턱의 결합이다. 현재만 읽는 대조는 분류 정답이 55/96으로 더 낮아도 정책 성공은 52/96이었다. 분류 정확도 하나로 정책을 평가하면 이 차이를 놓친다.

**정책이 기존 판독기의 정보를 충분히 사용하지 않았다.** 모든 후보 점수가 0.5 미만인 참조 부재 상태가 18/24개였는데, 실행은 여전히 상위 4개를 전달했다. 상위 두 기록만으로 정확한 참조를 모두 찾은 질문도 23/24개였다. 새 효용층이 선택할 수 있었던 것은 0개와 4개뿐이어서, 규칙 비교에서 이득이 있었던 두 기록 전달을 선택할 수 없었다. 낮은 점수에서 보류, 상위 2개/4개 비교를 먼저 포함했어야 한다.

0.5를 적용하면 참조 47/48개와 비참조 7/1,032개가 남는다. 완벽한 해결책은 아니며, 이 기준의 새 worker 성적은 측정하지 않았다. 파일럿을 본 뒤 임계값을 골라 확인 성능으로 제시해서는 안 된다.

**성공률 기반 목표가 중요한 행동 차이를 지웠다.** 참조 없는 상태의 구체적 추측 증가(9→31)는 모두 ‘둘 다 실패’여서 손해 라벨에 포함되지 않았다. 토큰·지연 비용도 분류 손실에 들어가지 않았다. 따라서 이번 head는 메모리의 모든 득실을 배우는 모델이 아니라 성공 여부의 네 범주를 배우는 제한된 모델이었다.

**작업자 오류와 선택기 오류를 더 일찍 분리해야 했다.** 기록된 여섯 정책 중 어느 것을 골라도 실패한 상태는 38개다. 이 중 24개가 참조 부재 조건이고, 나머지 14개는 필요한 참조를 제공하는 정책도 있던 상태다. 손해 5개 중 3개는 무기억에서 참조를 전달받지 않았는데 정답과 일치했던 결과가 뒤집힌 경우이고, 2개는 이미 현재에 참조가 보이던 경우였다. 참조를 받지 않았다는 사실만으로 실제 내부 추론이나 우연 여부를 단정하지 않는다. 이 사실로 주 정답을 바꾸지도 않는다. 다만 현재 라벨은 한 worker·한 표현의 실현 결과이며 안정적인 적용 조건의 차이와 같다고 볼 수 없다.

이번 파일럿에서 데이터 수집, 새 worker 인터페이스, 실제 효용 측정, 새 head 비교를 함께 시작한 것은 성급했다. 다음 순서는 worker의 기본 계약 확인 → 기존 점수와 전달 개수를 사용하는 단순 정책 비교 → 관계·성공·근거 없는 선택·비용을 분리한 출처별 데이터 보강이다. 학습은 그 위에서 수행하고, 단순 기준선에 남는 한계를 넘어서는지를 확인해야 한다.

## 이후 실행한 비교

[기억 개수·보류·작업자 지침 후속 실험](2026-11-09-travel-policy-followup.md)에서 실제 추가 추론을 완료했다. 기존 지침의 상위2는55/96으로 상위4의51/96보다4개 더 맞혔고, 점수 기준 보류는 성공51/96을 유지하면서 근거 없는 상태의 무근거 구체 선택을31→12/48항목으로 줄였다. 강화 지침은 기본 계약 점검11→9/36, 상위4 성공51→48/96으로 악화됐다. 새 모델 학습은 없었다.

위 회고의0.5 진단은 전체 후보의 점수를 보았지만, 새 실행은 실제 재순위화 후보32개 안에서만 적용했다. 따라서 참조 없는 상태에서 전부 보류한 수는 회고의18/24와 새 정책의19/24가 다르다. 이전 결과와 회고 숫자를 소급 수정하지 않았다.
