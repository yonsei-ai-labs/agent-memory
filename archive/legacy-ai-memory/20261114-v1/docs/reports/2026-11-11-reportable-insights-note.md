# 결과 보고에 쓸 수 있는 인사이트와 쓸 수 없는 주장

2026-11-11. 실험을 수행하지 않는 별도 검토 세션(Claude Code)이 작성함. “지금까지의 실험에 결과 보고를 쓸 만한 인사이트가 있는가”라는 질문에 대한 검토 의견이며 새 실험 결과가 아님. 새 학습·작업자 호출·GPU 할당은 없었고 기존 파일은 수정하지 않았음.

**핵심: 중간 결과 보고를 쓸 만한 인사이트는 있음. 보고의 중심은 “학습한 선택기의 성과”가 아니라 “어떤 기억이 해로운가”에 두어야 함.** 가장 강한 결과는 현재 상태가 무효로 만든 기억이 이미 되던 성공을 깨뜨린다는 것이고, 서로 겹치지 않는 두 가족 묶음에서 반복됐음. 외부에 내놓을 결론으로 닫으려면 이 결과를 문장 틀 밖의 자료에서 한 번 확인해야 함.

검토 범위는 다음과 같음.

- 대상은 11월 11일의 세 실험임: [상태 대조 파일럿](2026-11-11-memory-state-screen.md), [필요성 학습](2026-11-11-memory-need-learning.md), [회귀·표현 변화 검증](2026-11-11-memory-selector-regression.md).
- 세 실험의 성공 횟수는 커밋된 결과 묶음의 작업자 원 출력에서, Recall은 저장된 선택 결과에서 다시 계산했고 보고서 수치와 모두 일치함. 코드와 출력은 [재계산 자료](data/reportable-insights-20261111/README.md)에 있음.
- [직접 성공·순위 학습](2026-11-10-memory-direct-ranking.md)의 수치는 보고서에서 옮겼고 다시 계산하지 않았음.

용어는 다음과 같이 씀.

| 용어 | 뜻 |
| --- | --- |
| 작업자 | 기억을 받아 과제를 푸는 고정 모델(Qwen3.5-9B). 저녁과 숙소 두 항목을 정함 |
| 선택기 | 어떤 기억을 줄지 고르는 작은 모델(Harrier 0.6B와 LoRA) |
| 가족 | 같은 원천 요청에서 만든 상태 6개의 묶음. 서로 독립인 단위는 상태가 아니라 가족임 |
| 상태 쌍 | 목표와 기억 은행은 같고 현재 상태만 달라, 필요한 기억이 서로 다른 두 상태 |
| 이미 충분한 상태 | 필요한 사실이 현재 관측에 다 보여서 기억 없이도 성공하는 상태 |

자료에는 두 유형이 있음. 계획 교체 유형(`retry_branch`)의 목표는 “먼저 Clara의 3일차 선택을 쓰고, 첫 시도가 실패했다는 표지가 있으면 Alice의 1일차 선택을 쓰라”는 형태임. 항목 확인 유형(`observed_component`)은 참조한 사람의 저녁과 숙소 중 이미 확인한 항목이 상태마다 다름.

## 1. 쓸 수 있는 것

### 1.1 해로운 것은 불필요한 기억이 아니라 현재 상태가 무효로 만든 기억임

근거가 가장 강한 결과임. 이미 충분한 상태에 기억을 더했을 때 기억 없이 되던 성공이 깨지는지를, 더한 기억의 종류별로 셈. 파일럿 6가족과 확인 6가족은 서로 겹치지 않음.

| 더한 기억 | 유형 | 서로 다른 입력 | 성공이 깨진 입력 | 깨진 가족 |
| --- | --- | ---: | ---: | --- |
| 지금 보이는 내용의 반복 | 두 유형 | 30 | 0 | 없음 |
| 목표가 참조하지 않는 다른 사람의 기록 | 항목 확인 | 12 | 0 | 없음 |
| 실패한 1차 계획의 기록 2개 | 계획 교체 | 12 | 7 | 12가족 중 7 (파일럿 4/6, 확인 3/6) |
| 1차 계획의 기록 1개와 보이는 내용의 반복 1개 | 계획 교체 | 12 | 4 | 12가족 중 4 (파일럿 2/6, 확인 2/6) |

- 계획 교체 유형의 이미 충분한 상태에는 “1차 계획 결제 실패, 대안 계획을 쓸 것”이라는 표지와 대안의 두 선택이 모두 보임. 여기에 1차 계획의 기록을 주면 작업자가 1차 계획으로 되돌아감.
- 사례 `3af64b4b7e7480980b61768f`: 기억이 없으면 Alice의 저녁 R8278·숙소 H195로 맞힘. Clara의 숙소 기록 하나가 섞이면 숙소만 Clara의 H1917로 바뀌고, Clara의 기록 둘을 주면 저녁도 Clara의 R3754로 바뀜.
- 기록 1개가 섞여 깨진 4가족은 모두 기록 2개에서도 깨진 가족임.
- 회귀·표현 변화 검증에서 손해가 0건이었던 것도 이 구분과 맞음. 그 실험의 정책들은 이미 충분한 상태에 보이는 내용의 반복만 주었고 1차 계획의 기록은 주지 않았음.
- 표의 셋째 행은 반대 상태 기억 조건, 넷째 행은 기존 판독기의 제공임. 반대 상태 기억 조건은 두 실험의 사전 계획에 있었음. 기억을 네 종류로 나눈 것은 결과를 본 뒤의 분류임.
- 12가족 중 7의 95% 구간은 32–81%, 12가족 중 4는 14–61%임. 표본이 작아 비율의 크기는 말하기 어렵고 “드물지 않게 일어남”까지 말할 수 있음.
- 범위는 상태 표지가 있는 계획 교체 문장 틀 하나와 작업자 하나임.

### 1.2 목표만 보고 고르면 구조적으로 절반까지만 맞음

문제 정의의 근거로 쓸 수 있음. 발견이 아니라 자료 설계에서 나오는 결과임.

- 확인 자료의 12쌍은 모두 목표 문장과 기억 은행이 같고 필요한 기록만 다름.
- 목표만 읽는 모델은 12쌍 모두에서 두 상태에 같은 기록을 골랐으므로 쌍마다 한쪽만 맞힐 수 있음. 목표만 학습한 모델은 그 상한인 12/24, 기존 판독기는 6/24였음.
- 상태까지 읽고 학습한 모델은 12쌍 모두 양쪽을 맞힘(24/24).
- 필요한 근거를 주면 24/24, 주지 않으면 0/24였고 파일럿과 확인에서 같았음. 기억이 있어야만 풀리고 주면 풀린다는 뜻이므로 측정 장치는 작동함.
- 따라서 전체 성공 24→36의 차이 12건은 설계가 정한 상한의 차이임. 사전 계획에도 “규칙이 구조상 정답을 고를 수 있는 자료”라고 적혀 있음. 학습 효과의 크기로 제시하면 안 됨.

### 1.3 상태에 따른 필요성은 작은 모델이 배울 수 있음

가능성 확인으로 쓸 수 있음. 아래는 모든 모델에 같은 상태 입력을 준 비교이며, 같은 36상태를 세 가지 표현으로 본 것임. 두 seed는 `731 / 1729` 순서임.

| 선택 정책 | 필요 묶음 정답 /36: 원문 | 일반 문장 | 무관한 이력 추가 | 작업 성공 /36: 원문 | 일반 문장 | 무관한 이력 추가 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 무기억 | — | — | — | 12 | 12 | 12 |
| 기존 판독기 | 3 | 6 | 6 | 15 | 18 | 18 |
| 목표만 학습 | 6 / 6 | 3 / 7 | 5 / 4 | 18 / 18 | 15 / 19 | 17 / 16 |
| 상태까지 학습 | 36 / 36 | 32 / 35 | 34 / 33 | 36 / 36 | 33 / 35 | 34 / 33 |
| 문장 틀을 아는 규칙 | 36 | 36 | 36 | 36 | 36 | 36 |

- 같은 상태 입력을 받은 기존 판독기는 3/36이므로, 36/36은 입력이 아니라 학습의 효과임.
- 학습에는 필요성 라벨만 썼고 작업자의 성공 라벨은 쓰지 않았음. 학습 자료는 11가족·66상태임.
- 상태까지 학습한 모델은 이미 충분한 12상태에서 아무것도 주지 않아, 전달 기억이 목표만 학습한 모델의 2,802토큰에서 1,904토큰으로 줄었음.
- 표현을 바꾸면 32–35/36으로 내려감. 실패 10건 중 9건은 필요한 근거를 빠뜨린 것임.
- 목표만 학습한 모델의 6/36은 학습 때 보지 않은 상태 입력을 받은 결과임. 원래 입력(목표만)에서는 필요 묶음 12/36, 작업 성공 24/36이었음.
- 두 seed의 36/36은 같은 36상태를 두 번 본 것이며 독립 반복이 아님.

## 2. 쓸 수 없는 주장

| 주장 | 쓸 수 없는 이유 |
| --- | --- |
| 학습한 선택기가 규칙보다 낫다 | 규칙이 모든 조건에서 36/36임. 다만 이 규칙은 생성 문장 틀을 알고 만든 것이라 “규칙이면 충분하다”도 말할 수 없음. 틀이 없는 자연 문장에서 비교해야 함 |
| 상태 학습이 손해를 줄였다 | 목표만 학습한 모델도 이미 충분한 12상태에 기억을 주고 손해가 0건이었음. 1.1의 손해는 반대 상태 기억과 기존 판독기에서 관측한 것임 |
| 24→36이 학습 성과의 크기다 | 1.2와 같이 설계가 정한 차이임 |
| 다른 과제에서도 통한다 | 생성한 여행 계획 한 도메인, 문장 틀 2개, 작업자 하나, 통제해서 만든 상태임. 확인 가족도 도시·카탈로그·문장 틀을 학습 가족과 공유함 |
| 추가 학습에 부작용이 없다 | 이전 과제 219질문에서 상위 10개 Recall은 91.88→91.50%로 유지됐으나, 0.5 임계값으로 제공을 정하면 88.18→84.11 / 85.38%로 내려감. 두 seed 모두 8계획 중 7에서 낮아짐 |
| 감독 신호를 성공에서 필요성으로 바꿔서 됐다 | 직접 성공·순위 학습은 96상태에서 46–51로, 가장 긴 묶음 52와 참조 규칙 55에 못 미쳤음. 이번 실험과는 자료와 학습 목표가 함께 달라 원인을 하나로 가를 수 없음 |

## 3. 보고서에 넣는 순서

제안임.

1. 질문: 과거 기억은 언제 도움이 되고 언제 해로운가.
2. 문제 정의: 필요한 기억은 목표가 아니라 현재 상태가 정함(1.2). 측정 장치가 작동한다는 근거를 함께 둠.
3. 주 결과: 현재 상태가 무효로 만든 기억은 성공을 깨뜨리고, 반복이나 무관한 기억은 깨뜨리지 않음(1.1).
4. 가능성: 작은 모델이 상태별 필요성을 배우며, 표현이 바뀌면 일부 실패함(1.3).
5. 부정 결과와 한계: 2절의 표.

## 4. 결론을 닫는 데 필요한 확인

1.1이 문장 틀 밖의 자연 문장에서도 나오는지 한 번 확인하면 됨. 준비된 [BEAM·LongMemEval 지식 갱신 자료](../ai-memory-external-update-data-2026-11-11.md)가 같은 구조임.

| 통제 자료 | 외부 자료의 대응 조건 |
| --- | --- |
| 대안의 선택이 이미 보이는 상태 | `current_new`: 새 값을 말한 발화가 현재 대화에 있음 |
| 여기에 1차 계획의 기록을 더함 | `current_new_plus_old`: 옛 값을 말한 기록을 더함 |

- 순서는 [자료 문서 5절](../ai-memory-external-update-data-2026-11-11.md#5-평가에-쓰는-순서)과 같음. 예행(LongMemEval-S 282호출)으로 작업자와 채점을 점검하고, 판정 규칙을 적어 둔 뒤, 확인(BEAM 확인 분할 384호출)을 한 번 실행함.
- 주 지표는 `current_new`에서 맞힌 문항 중 `current_new_plus_old`에서 옛 값을 답한 문항의 수와, 그런 문항이 있는 대화의 수임. 옛 값은 BEAM 확인 분할 64문항 중 35문항·27대화에서 판정할 수 있음.
- **보완할 점: 무관한 기록을 더하는 대조 조건이 지금 자료에 없음.** 1.1의 주장은 “무효가 된 기억만 해롭다”이므로, 옛 값 기록 대신 방해 기록을 더한 조건이 있어야 가를 수 있음. 확인 분할의 작업자 출력은 아직 아무도 보지 않았으므로 실행 전에 조건을 추가해도 확인 자료가 손상되지 않음.
- 결과가 나오면 “통제 조건과 자연 문장 모두에서 관측”으로, 나오지 않으면 “상태 표지가 있는 통제 조건에 한정”으로 보고함. 두 문장과 통과 기준을 실행 전에 적어 둠.
- 아직 모르는 것은 9B 작업자가 근거를 받고 이 문항들을 푸는지와 문자열 채점이 사람의 판단과 맞는지임. 예행에서 먼저 확인함. 실행 진입점 세 파일은 GPU에서 실행해 본 적이 없음.

## 5. 이 검토의 한계

- 선택기 점수와 학습은 다시 계산하지 않았음. 저장된 선택 결과와 작업자 원 출력에서 계산한 것임.
- 1.1의 입력 수는 독립 표본 수가 아님. 독립 단위는 12가족이고, 계획 교체 유형의 이미 충분한 상태는 가족마다 하나임.
- 작업자 출력은 greedy 한 번의 결과임. 같은 입력의 반복은 실험마다 2개뿐이라 성공 확률의 변동은 알 수 없음.
- 3절과 4절은 제안이며 채택된 계획이 아님.
