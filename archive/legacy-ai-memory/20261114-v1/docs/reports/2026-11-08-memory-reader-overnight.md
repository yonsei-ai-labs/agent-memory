# 데이터 설계를 우선한 추가 학습·진단 — 11월 8일 아침 보고

**같은 자료에서도 현재와 기억을 읽는 방식을 바꾸면, 새 출처에서 두 관계를 훨씬 잘 구분할 수 있었다.** 함께 읽은 모델은 두 외부 집합에서 106/108·107/108, 기존 별도 벡터 방식은 68/108·82/108이었다. 다만 이는 실제 기억 효용을 보인 결과가 아니라, 정확한 범위를 비교하는 제한된 학습 진단이다.

이번에 남길 핵심은 세 가지다. 입력을 함께 읽는 경로는 다음 실제 관계 학습에서 비교할 가치가 있다. 개발 점수의 승자가 다른 출처에서도 항상 우세하지는 않았다. 그리고 행 수보다 **필요한 대조가 몇 개의 독립 출처에서 성립하는지**를 먼저 설계해야 한다. 기존 원본·가중치는 보존했다.

이번 질문은 “판독층을 더 붙이면 좋아지는가”에서 **어떤 대조를 학습해야 현재 상태와 과거 기억의 두 관계를 구분할 수 있는가**로 좁혔다. 기존 원본·기반 모델은 보존하고 새 adapter/head를 만들었다. 아래 범위 진단의 정답은 기억 제공의 이득·손해가 아니다.

## 무엇을 판단시키는 실험인가

예를 들어 현재 요청이 `tests/test_basic.py`, 이미 검사한 범위가 `tests/test_chain.py`, 기억이 `tests/test_basic.py` 검사에 관한 것이라면 답은 두 개다. **현재 요청에는 맞고, 아직 검사하지 않은 범위다.** 요청과 검사 기록이 다르다는 이유로 두 답을 한쪽으로 묶으면 틀린다.

이전 모델이 특히 어려워한 것은 이런 “한쪽 관계만 일치”하는 조건이다. 이번에는 자료 구성, 두 출력을 읽는 방식, 실제 학습량을 나눠 확인했다. 이 예의 파일명은 click의 실제 기준 커밋에 존재하지만, 현재 요청·완료 상태의 조합은 실험을 위해 구성했다. 정확한 문자열 비교 규칙은 이 진단을 100% 풀 수 있다.

## 데이터를 어떻게 골랐나

기존 명령 관측 81개를 다시 살펴, 필터 때문에 전체 검사 범위를 보장하지 못하는 등 계약에 맞지 않는 27개와 대조할 범위가 하나뿐인 16개를 제외했다. 나머지 38개에서 실제 선택한 파일·모듈 이름만 사용했다. “명령에 파일이 나왔다”를 “검사가 통과했다”로 바꾸지 않았다.

공개 자료는 고정한 SWE-smith 실행 shard 안에서만 찾았다. 처음 256개 기록에서 10개 실행·19개 명령과 연결 응답을 검토했다. 이어 기존 자료의 길이 편법을 확인한 뒤, 사전에 정한 다음 768개 기록에서 같은 길이의 실제 범위 쌍을 찾았다. 조건을 만족한 3개 실행·6개 명령만 추가 확인했다. 목표 저장소 세 곳 중 두 곳만 통과했어도 기준을 낮추지 않았다. source 성공 여부와 정답 patch로 선별하지 않았다.

새 공개 파일 16개는 정확한 upstream commit에서 존재를 확인했다. 기존 로컬 자료의 11개 문제군·범위 34쌍도 원래 기준 commit과 대조했다. 파일명 존재 확인은 관측한 현재 상태나 실제 작업 효용의 증명이 아니다. 이번 추가 선별·검토는 한 에이전트가 수행했고, 사람의 독립 이중 주석을 거친 자료는 아니다. ## 학습에서 달라진 것

같은 Harrier 0.6B와 고정 revision에서 새 LoRA를 시작했다. 큰 자료 1,316행·seed 731·512업데이트의 마지막 checkpoint 비교다. 학습 과정·가중치 변화·저장 예측을 검산했다.

| 방식 | 학습 동시 정답 / 1,316 | 핵심 학습 / 296 | 개발 동시 정답 / 594 | 핵심 개발 / 132 |
| --- | ---: | ---: | ---: | ---: |
| 현재·기억을 별도 벡터로 읽고 MLP로 비교 | 1,037 | 17 | 449 | 5 |
| 두 출력의 MLP만 분리 | 1,033 | 17 | 434 | 1 |
| 현재·기억을 한 입력으로 함께 읽기 | 1,316 | 296 | 462 | 51 |
| 역할 질문을 따로 주고 공유 판독층 사용 | 745 | 10 | 338 | 0 |
| 위 방식의 내부 긍정 의미를 두 역할에서 통일 | 1,316 | 296 | 560 | 107 |

마지막 두 방식은 입력 사실·파라미터 수·초기 가중치가 같다. 원래 라벨은 “요청과 일치”가 0, “이미 검사함”이 1이었다. 공유 판독층 안에서는 긍정 관계가 같은 출력을 가리키게 하고, 손실·평가 전에 원래 라벨 순서로 되돌렸다. 외부 정답을 바꾼 것이 아니다. 이 작은 설계 변화가 한 seed의 학습을 크게 바꿨지만, 일반적인 학습 간섭 원인을 증명하거나 새 알고리즘이라고 주장하지 않는다.

함께 읽기는 약 540초, 역할별 입력은 약 1,052초로 같은 업데이트에도 비용이 달랐다. 실제 서비스에서 현재·기억 벡터를 여러 후보 사이에 재사용하면 비용 관계가 달라질 수 있다. 이번 batch 추론 시간을 온라인 선택기 지연으로 해석하지 않는다. [전체 구조 비교](../../training/memory_selector/reports/2026-11-08-scope-expansion-wave2.md).

기존 pair를 1,536회 학습한 추가 실행은 Colab 세션 소실로 가중치를 회수하지 못했다. 중간 JSON의 개선 기록은 있으나 검산된 결과에서 제외했다. 따라서 **기존 구조의 학습량을 충분히 늘린 비교까지 끝냈다거나 새 구조가 본질적으로 더 낫다고 결론 내릴 수 없다.** [누락한 실험과 부분 기록](../../training/memory_selector/reports/2026-11-08-scope-expansion-wave3-failure.md).

자료 확대 네 조건은 같은 512업데이트여서 작은 자료의 한 행은 56–57번, 큰 자료의 한 행은 6–7번 학습됐다. 따라서 작은 자료와 큰 자료의 성적 차이를 순수한 데이터 수량 효과로 읽으면 안 된다. [자료 구성·중간층 실험](../../training/memory_selector/reports/2026-11-08-scope-expansion-wave1.md).

## 새 출처에서는 어떻게 됐나

회수·검산한 20개 모델과 별도 선형 ridge 열 조건을 모두 평가했다. 모델·checkpoint 목록과 해시는 외부 예측 전에 고정했다. 아래는 개발에서 선택한 **best**이며 위의 마지막 512회 표와 구분한다. 함께 읽기·역할 정렬의 best는 256회다.

| 방식 | apispec·word_cloud 전체 / 108 | 핵심 / 24 | boltons·click 길이 통제 전체 / 108 | 핵심 / 24 |
| --- | ---: | ---: | ---: | ---: |
| 고정 표현 + MLP | 48 | 1 | 55 | 0 |
| 별도 벡터 + LoRA + MLP | 68 | 4 | 82 | 2 |
| 판독층만 두 개로 분리 + LoRA | 68 | 1 | 76 | 0 |
| **현재·기억 함께 읽기 + LoRA** | **106** | **24** | **107** | **24** |
| 역할 의미 정렬 + LoRA, seed 731 | 75 | 11 | 108 | 24 |
| 역할 의미 정렬, seed 732의 짧은 반복 | 79 | 13 | 108 | 24 |
| 정확한 문자열 비교 규칙 | 108 | 24 | 108 | 24 |

![같은 모델의 두 외부 집합 결과](data/scope-external-20261108/figures/both-holdouts.png)

두 집합 모두 알려진 조건은 48행이다. 함께 읽기는 이 48행을 모두 맞혔고, 핵심 8조건의 세 표현도 모두 맞혔다. 기존 별도 벡터는 핵심 조건의 세 표현을 모두 맞힌 수가 각각 1/8·0/8이었다. 저장소는 집합당 두 개뿐이며, 같은 조건의 세 표현을 독립 경험처럼 세지 않았다. 신뢰구간·유의성 검정으로 큰 표본처럼 포장하지 않는다. 여기서 새 출처란 추가 감독 학습에서 제외했다는 뜻이며 사전학습 자료와의 비중복을 증명한 것은 아니다.

**개발 선택의 승자였던 역할 정렬 모델에는 중요한 약점이 남았다.** 첫 외부 집합에서 seed 731은 apispec 50/54, word_cloud 25/54였다. 짧은 다른 seed도 52/54·27/54로 같은 차이를 보였다. 기존 별도 벡터 대비 첫 집합은 12행 개선·5행 악화였고, 길이 통제에서는 26행 개선·악화 0행이었다. 좋은 집합의 108/108만 보고 구조를 확정하면 안 된다. 함께 읽기의 대응 비교도 각각 40개선·2악화, 26개선·1악화로 기록했다.

선형 ridge 열 조건은 외부 전체 12–52/108, 길이 통제 12–69/108이었다. 학습 자료를 완벽히 맞히는 선형식도 새 출처 일반화를 보장하지 않았다. [20개 모델·ridge 열 조건의 전체 표와 검산](../../training/memory_selector/reports/2026-11-08-scope-external-evaluation.md), [모든 짝 비교 648행](data/scope-external-20261108/paired-cases.csv)을 보존했다.

### 실제 예측을 보면

`boltons`의 `032659ac53385b98a4f0b604`는 기억과 현재 요청이 모두 `tests/test_timeutils.py`, 이미 검사한 것은 `tests/test_mathutils.py`다. 정답은 “요청에 맞음·아직 검사 안 함”이다. 기존 별도 벡터는 “이미 검사함”으로 틀렸고, 함께 읽기와 역할 정렬은 두 답을 맞혔다.

`word_cloud`의 `270219b2dd2104cb0ad5851a`는 기억·요청이 `test/test_wordcloud_cli.py`, 이미 검사한 것은 `test/test_wordcloud.py`다. 같은 원리지만 기존 방식과 역할 정렬은 둘 다 “이미 검사함”으로 틀렸고, 함께 읽기만 맞혔다. 두 예는 미리 정한 A 표현·핵심 대조의 ID 순 선택 규칙을 따른다. 사례 하나로 전체 성적을 대신하지 않는다.

함께 읽기의 오답 세 건도 공통점이 있었다. **현재 요청은 미확인이지만 완료 기록은 알려진 상태**에서, 요청은 미확인으로 맞히고 이미 끝난 검사를 미완료로 잘못 읽었다. 모두 C 표현이었다. C는 학습 A/B에는 없지만 개발 자료에는 있었다. 한 관계의 정보가 없을 때 다른 관계의 확실한 사실까지 흔들리는지, 표현 변화가 영향을 주는지를 분리할 후속 대조가 필요하다. 세 사례 전부를 상세 보고서에 남겼다.

확신 점수도 곧바로 선택 정책으로 쓸 수 없다. 사전에 정한 “두 출력 최고 softmax가 모두 0.9 이상”인 첫 외부의 알려진 조건에서, 역할 정렬 seed 731은 29행 중 10행을 틀렸다. 이 점수는 보정된 공동 확률이나 실제 기억 손해율이 아니다. threshold를 외부 결과에 맞춰 조정하지 않았다.

## 자연 코드 관계에서는 아직 개선이 확인되지 않았다

기존 74행에서는 선형/MLP, 판독층 크기, 학습 길이, 함께 읽은 고정 표현을 비교했다. 긴 MLP는 학습 fold를 91.8%–100% 맞혀도 저장소 밖 정답은 세 seed에서 35/74·35/74·34/74였다. 닫힌 해 선형식으로 학습을 전부 맞히는 것도 가능했지만 일반화가 좋아지지 않았다. **추가 층이나 더 긴 학습만으로 해결됐다는 결과는 없다.** [자연 관계 판독 진단](../../training/memory_selector/reports/2026-11-08-natural-readout-diagnostics.md), [함께 읽은 고정 표현](../../training/memory_selector/reports/2026-11-08-natural-joint-readout.md).

분할을 다시 보니 74행 중 66행은 해당 학습 fold에 같은 주석 facet도 같은 질문 블록도 없었다. 18개 facet 중 여러 저장소에 나온 것은 하나뿐이었다. 기존 평가는 새 저장소 전이와 새로운 관계 유형으로의 전이가 섞여 있다. 다만 같은 유형을 본 8행도 원래 전체 입력 모델은 3행만 맞혔으므로 이 분포만으로 실패를 설명하지 않는다. 추상적인 논리 개념까지 처음이라는 뜻도 아니다. [행별 근거와 감사](../../training/memory_selector/reports/2026-11-08-natural-relation-coverage.md).

원래 자료에는 현재 입력이 같은데 기억에 따라 정답이 바뀌는 대조가 9그룹·18행뿐이다. 나머지에서 기억의 필요성을 총 정확도만으로 판단하기 어렵다는 제한은 원래 데이터 설명에도 있다. 이 수는 이번에 새로 발견한 결함이라고 포장하지 않는다. 다음 자료는 **같은 종류의 관계가 여러 독립 출처에서 반복되고, 현재와 기억 양쪽을 보아야 풀리는 대조**가 충분해야 한다.

## 다음 실험을 권하는 방식

새 모델을 더 많이 비교하기 전에, 실제 기억 적용에서 빈번한 관계 두 가지부터 보강하는 편이 좋다. 예를 들면 **과거 처방의 전제가 현재도 필요한가/이미 충족됐는가**, **과거 API·인자가 현재 호출 경로에서도 적용되는가**다. 주제마다 한 저장소만 모으지 말고 같은 관계의 독립 출처를 학습·개발·평가에 확보한다. 수집량은 검토를 통과한 출처와 핵심 대조 수로 관리한다.

각 묶음에는 과거 근거, 판단 시점까지 얻은 현재 관측, 관측/구성 여부, 라벨 이유, 반대 상태의 실제 근거, 모르는 부분을 함께 남긴다. 함수 선언에 이름이 없다는 사실과 `**kwargs`를 통해 인자를 실제 받아들이는지 같은 실행 의미를 구분해야 한다. 문구만 뒤집어 부정 라벨을 만들지 않는다. 같은 부모의 표현 변경과 연결된 기억·현재 사례는 같은 분할에 둔다.

범위 진단에서 유망한 작은 모델과 단순 규칙·동결 head·현재만 보는 모델을 새 자료에서 비교한다. 완벽한 문자열 규칙을 이겼다고 주장할 수 없는 과제에 층을 계속 붙이지 않는다. 관계 판단이 좋아지면, 그다음 고정 작업 에이전트에서 기억 제공/보류를 비교한다. 성공·추가 오류·제출·확인 비용·토큰·시간을 따로 측정하고, 한 번의 성공/실패를 곧바로 기억의 이득/손해 정답으로 확정하지 않는다.

추가 학습 신호 후보도 구체화할 수 있다. 이번 계약처럼 두 판단의 독립성이 명확한 사례에서는, 요청 정보만 바꿀 때 완료 판단을 유지하도록 대조를 만들고 분류 손실에 일관성 제약을 더하는 비교가 가능하다. 이것은 이번에 실행한 결과가 아니라 다음 실험안이다. 실제 코드 관계에서 독립성이 성립하는지 먼저 확인해야 하며, 두 답을 정확히 맞히는 손실을 단순 점수 차이 손실로 대체하지 않는다. 이번 외부 결과를 본 뒤 수정한 모델에는 새 평가 자료가 필요하다.

가능한 연구 기여는 “작은 모델에 LoRA를 했다” 자체보다 **서로 다른 현재 조건에서 과거 경험의 적용 경계를 배우는 데이터와 평가, 그리고 그 판단이 실제 작업에 주는 순이득**이다. 이번 밤은 그중 학습 진단과 데이터 설계에 관한 근거를 추가했다. 실제 SWE 성공 개선과 기억의 순효용은 아직 남은 검증이다.

## 실행 범위·실패·자원

이번 밤에는 같은 0.6B 기반 모델에서 자료·고정/학습 표현·판독 방식·학습 길이를 바꿨다. 새 대형 모델이나 유료 모델 API는 실행하지 않았다. 자연 관계 CPU 진단의 87조건·522개 fold별 head·6,438개 예측도 같은 74행을 여러 방식으로 본 기록이며, 새로운 경험을 수집한 수가 아니다.

회수한 GPU 학습은 첫 13조건·구조 비교 6조건·짧은 반복 1조건이다. 최초 연결 실패 한 번, 외부 평가 업로드 실패 두 번, 가중치를 회수하지 못한 긴 학습·반복 실행 하나를 함께 기록했다. 첫 13조건은 학습 완료 후 CLI 신호가 끊겼지만 닫힌 ZIP·업로드 해시·실제 가중치를 회수해 검산했다. 이 회수 성공을 원래 controller의 `incomplete` 상태 위에 덮어쓰지 않았다. 반면 긴 학습의 중간 기록은 검산된 결과에 포함하지 않았다.

Colab 잔량은 599.26→593.70 CU로 **관측 감소 5.56 CU**였다. 실행 사이에 반영된 잔량 차이도 있으므로 개별 실행의 즉시 차이 합계를 정확한 청구량이라고 부르지 않는다. 로컬 Laya GPU는 사용하지 않았다. 종료 후 활성 할당 0·사용률 0을 확인했다. [자원·실행 원장](data/overnight-20261108/run-ledger.json)에 실패·회수·종료와 원본 상태 파일 해시를 함께 남긴다.

큰 외부 평가 묶음은 4 MiB씩 나누어 전송했고, 원격에서 52조각 및 전체 217,750,415바이트의 SHA를 확인한 뒤 추론했다. 업로드 서버 오류는 제한된 횟수와 전체 시간 상한 안에서만 재시도한다. 원본 로그·계정 상태는 공유 자료에 넣지 않았다.

## 검증과 다시 보는 방법

검증의 층위를 구분한다. 저장 예측의 정답·지표·해시 확인, 실제 고정 head/캐시를 이용한 재계산, LoRA 가중치 변화·노출·저장/복원 확인을 각각 기록했다. 외부 추론은 optimizer 없이 고정한 checkpoint로 수행했고, 고정 head의 9,780개 예측은 실제 가중치·표현에서 다시 계산해 최대 확률 오차 약 2.38×10⁻⁷ 이내였다. 이것이 LoRA encoder의 외부 순전파를 별도 장치에서 다시 실행했다는 뜻은 아니다.

공유 자료만 복사한 새 임시 사본에서 README의 첫 실행, 데이터·분할 감사, 모든 공유 예측 재계산, 학습 자료 내보내기가 통과했다. 학습·운영 검사는 로컬 66개 통과, 공유 사본 59개 통과·2개 skip이었다. skip은 이전 로컬 생성 자료를 요구하는 조건부 검사다. 평가 검사는 공유 사본에서 11개가 통과했다. 원래 고정 자료 5,528파일과 첫 학습 산출물 54파일도 보존 검사를 통과했다. 최종 검사 결과와 정확한 검사 범위는 [검증 기록](data/overnight-20261108/verification.json)에 남긴다. 이 임시 사본은 공유 대상 파일의 복사본이며 새로 push한 원격 저장소의 clone은 아니다.

```bash
python3 -m data_pipeline.relations check
python3 -m evaluation.reproduce_relations
python3 -m data_pipeline.audit_scope_expansion datasets/scope_relations/20261108-expansion-v1
python3 -m data_pipeline.audit_relation_coverage
python3 -m evaluation.verify_scope_predictions evaluation/results/scope-external-20261108-best
python3 -m evaluation.verify_scope_predictions evaluation/results/scope-external-20261108-ridge
```

이 명령들은 GPU·모델 다운로드 없이 포함된 자료로 실행한다. 전체 다섯 범위 예측 묶음에는 44,580개의 예측 기록이 있고, 기존 자연 관계 묶음은 444개다. [전체 재현 안내](../reproduction.md), [자료 안내](../../datasets/scope_relations/README.md), [모든 사례·그림의 근거](data/scope-external-20261108/README.md), [설계 변경 이력](../ai-memory-overnight-2026-11-08-plan.md)에서 더 살펴볼 수 있다. 전체 가중치 감사와 새 학습에는 Git 밖의 원래 upload/results 묶음이 추가로 필요하다.
