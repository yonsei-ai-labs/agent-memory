# AI 메모리 연구 탐색 회차 종합: 정보의 득실과 학습 선택기의 검증

2026-11-08. 최신 실제 개발 이슈 학습까지 포함한 공유용 종합 노트다. 실험 작성자의 보고서와 저장된 원자료를 읽고, 별도 집계로 핵심 수치를 확인했다. 이번 정리에서 새 학습·모델 생성·GPU 할당은 하지 않았다. 기존 고정 자료와 실행 코드는 수정하지 않았다.

**기억을 제공했을 때의 개선·악화·비용을 측정하는 경로를 구축했고, 제한된 과제에서 실제 차이를 관측했다. 학습한 작은 선택기의 안정적인 우위는 확인하지 못했다. 마지막 실제 개발 이슈 실험에서도 관련 기억의 첫 선택에 실패했다.** 이번 회차는 이 두 결과를 함께 보존하는 탐색 연구다. 모든 연구 질문이 해결됐다는 의미의 완료는 아니다.

## 1. 연구 질문과 시스템

연구 질문은 **과거 코드 경험의 어떤 정보가 현재 작업에 도움이 되거나 해가 되며, 작은 별도 모델이 그 차이를 판단해 제공할 기억을 고를 수 있는가**다.

기억은 과거 실행에서 만든 외부 텍스트다. 작은 선택 모델이 현재 관측과 기억을 읽고, 작업자는 제공된 기억을 사용·수정·무시하며 코드를 생성한다. 작업자의 생성 결과를 실행해 성과와 비용을 측정한다. 선택기의 학습과 작업자의 모델 크기를 구분한다.

| 구분 | 이 회차에서의 역할 |
| --- | --- |
| Harrier 0.6B | 현재와 과거 경험의 관계를 읽는 모델. 고정 표현+선형/MLP와 LoRA 등을 비교 |
| Qwen3.5-4B | 기억 제공/보류에 따른 코드를 생성하는 고정 작업자 |
| Qwen3.5-9B | 4B에서 미리 정한 선택을 그대로 적용한 전이 비교 작업자 |
| 실행 검사 | 반환·원본 변경·검증 범위·설정 계약 등 현재 요구의 충족 여부 판정 |

다음 세 판단은 각각의 결과로 보고한다.

1. **진단 관련성:** 과거 경험이 현재 문제의 점검 단서를 주는가?
2. **직접 적용성:** 과거의 구체적인 절차를 현재 조건에 그대로 실행해도 되는가?
3. **관측 효용:** 실제 작업자에게 제공하면 무기억 또는 고정 정책 대비 성공·악화·비용이 어떻게 달라지는가?

관련성이 있다고 추가 정보가 생기는 것은 아니고, 절차를 직접 적용할 수 있다고 작업자가 잘 활용하는 것도 아니다. 부적합한 절차를 수정해서 쓸 가능성도 있어 세 라벨을 서로 복사하지 않는다.

## 3. 실제 기억 효용: 일부 개선과 주 선택기의 실패

4B에서 96상태×10행동=960개 기본 코드를 생성했다. 행동은 무기억, 네 기억의 전체/절차 제공 8개, 전체 기억 동시 제공이다. 선택기는 무기억과 단일 기억 8개 중 고르고 전체 기억은 별도 기준선이다. 학습/개발/확인은 50/18/28상태다. 효용 학습은 고정 Harrier 표현 위의 작은 판독층에서 수행했으며 작업자를 추가 학습하지 않았다.

| 정책 | 4B 성공 /28 | 4B 개선 / 악화 | 9B 성공 /28 | 9B 개선 / 악화 |
| --- | ---: | ---: | ---: | ---: |
| 무기억 | 15 | 0 / 0 | 18 | 0 / 0 |
| 개발에서 고른 고정 기억 | 14 | 0 / 1 | **21** | 3 / 0 |
| 전체 기억 제공 | 11 | 2 / 6 | 17 | 3 / 4 |
| 사전 주 선택기: 가치 회귀 731 | 13 | 2 / 4 | 16 | 1 / 3 |
| 선호 학습 731 | **17** | 2 / 0 | 20 | 2 / 0 |
| 선호 학습 732 | **17** | 2 / 0 | 20 | 2 / 0 |
| 개발에서 고른 작은 보정층 | 11 | 3 / 7 | 16 | 4 / 6 |

선호 학습의 +2/28은 무기억 대비 약 +7.1%p의 탐색 관측이다. 개발에서는 이 방법을 고르지 못했고, 9B에서는 사전에 고른 고정 기억보다 낮았다. 4B에서도 확인 결과를 보고 사후에 고른 최선 고정 행동은 17/28이다. 학습 선택기가 꼭 필요하다는 근거로 제시하지 않는다.

같은 28상태의 단일 기억 행동 224개 중 **46개**는 4B와 9B의 무기억 대비 효과가 달랐다. 기억의 효용은 현재 조건과 작업자의 기본 능력·활용 방식에 의존한다는 제한된 근거다. 두 작업자의 차이를 파라미터 수만의 인과 효과로 해석하지 않는다.

비용도 이득으로 확인되지 않았다. 주 선택기의 Harrier 인코딩은 상태당 평균 0.456초였다. 별도 warm 단계의 측정값을 더한 28상태 시간은 무기억 40.62초, 주 선택기 포함 59.27초였다. 실제 모델 동시 상주 시스템의 end-to-end 지연은 아니며, 모든 정책의 총비용을 측정한 것도 아니다.

개발 자료의 더 근본적인 제한도 있다. **고정 행동과 상태별 관측 oracle이 모두 11/18**이어서 성공 수로 상황별 선택의 추가 이득을 구별할 여지가 없었다. 9B 확인에서도 최선 고정 행동 21/28과 관측 oracle 22/28의 간격은 한 상태다. 이 자료에서 복잡한 선택기를 개선하는 것과 연구 가설을 잘 검증하는 것은 별개의 문제다.

## 4. 정보 복원: Django 초기화 관측이 바꾼 실행 결과

실제 과거 경험에서 추출한 초기화 관측 E와 수정 절차 P를, 두 Django 버전의 네 프로세스 상태에 제공했다. 8상태×5조건의 기본 생성 40개와 동일 입력 재생성 4개다. 실행 코드는 실제 Docker 환경에서 검사했다.

| 조건 | 현재 설정 계약까지 충족 /8 | 무기억 대비 개선 / 악화 |
| --- | ---: | ---: |
| 무기억 | 2 | — |
| 수정 절차 P | 1 | 1 / 2 |
| 수정 절차 + 일반 주의 안내 | 2 | 1 / 1 |
| 초기화 관측 E | **6** | 4 / 0 |
| 수정 절차 + 초기화 관측 P+E | **6** | 4 / 0 |

주 대비 P+E−P는 계약 통과에서 +5/8이지만, forms 렌더링만 보면 5→6으로 +1이다. 나머지 차이는 현재 설정 모듈을 사용·보존하라는 계약과 연결된다. 모든 실패를 초기화 자체의 실패로 부르면 안 된다.

E만 고정 제공해도 관측 행동 oracle과 같은 6/8이었다. 또한 기억을 보지 않고 현재 상태를 직접 확인하는 사람이 작성한 초기화 규칙은 8/8이었다. 규칙은 실행 가능성 대조이며 모델에게 그 규칙을 전달한 성적은 아니다. 기억의 정보 구성 효과를 관측했지만, 학습 선택기 우위를 입증한 실험은 아니다. 한 출처 경험과 구성한 프로세스 상태라는 한계도 있다. [상세 결과](2026-11-08-memory-unit-pilot.md).

## 5. 마지막 실험: 실제 개발 이슈로 넓혔지만 선택 일반화 실패

공개 SWE-rebench OpenHands 기록 77개를 30개 저장소에서 선정하고, 그중 과거 수정 경험 16개와 현재 실제 이슈 40개를 연결했다. 입력은 현재 이슈 설명과 과거 기억이다. 미래 작업자의 명령·관측·정답 patch를 선택 입력에 넣지 않았다. **진단 단서의 관련성 주석이며 실제 효용 라벨은 0개**다.

| 분할 | 현재 이슈 | 이슈-기억 쌍 | 관련 / 다른 원리 / 미확인 |
| --- | ---: | ---: | --- |
| 학습 | 27 | 432 | 18 / 391 / 23 |
| 개발 | 7 | 112 | 9 / 102 / 1 |
| 평가 | 6 | 96 | 4 / 85 / 7 |

현재 이슈는 총 24개 저장소에 걸쳐 있고 분할 사이 현재 저장소는 겹치지 않는다. 다만 기억 은행은 공유하고 평가 저장소의 다른 과거 이슈도 포함하므로, 완전히 새로운 저장소·새 기억의 독립 평가로 부르지 않는다. 주석은 한 assistant가 수행했고 역사적 선후는 검증하지 않았다.

Harrier 0.6B에서 선형·MLP, 현재만/기억만 대조, LoRA, LoRA+후보 순위 손실을 각 두 seed로 비교했다. 주 학습은 128업데이트로 각 학습 쌍을 4–5회 사용했다. 개발 macro-F1로 checkpoint와 방법을 정하고 평가 라벨은 Colab 학습 묶음에서 제외했다.

| 방법 | 평가 macro-F1: seed 731 / 1729 | 관련 기억 첫 선택: 731 / 1729 |
| --- | --- | --- |
| 고정 표현 + 선형 | 0.2880 / 0.2989 | 0/4 / 0/4 |
| 고정 표현 + MLP | 0.3565 / 0.3131 | 0/4 / 0/4 |
| 현재 문제만 + MLP | 0.3131 / 0.3131 | 0/4 / 0/4 |
| 기억만 + MLP | 0.2984 / 0.3010 | 0/4 / 0/4 |
| LoRA + MLP | 0.2538 / 0.2924 | 0/4 / 0/4 |
| LoRA + 후보 순위 손실 | 0.2489 / 0.2764 | 0/4 / 0/4 |

관련 단서가 있다고 주석한 평가 이슈는 4개다. 12개 모델은 같은 4개를 평가했으며, 독립 평가 사례 48개가 아니다. BM25와 학습 긍정 빈도로 고른 고정 후보 기준선은 각각 1/4, 저장된 단독 임베딩의 코사인은 0/4였다. 네 이슈만으로 일반적인 검색·학습 방법의 우열을 확정하지 않는다.

개발에서 고른 LoRA+순위 손실도 두 seed 모두 평가 여섯 이슈에서 같은 `specific_precedence`를 최상위로 골랐다. 미리 정한 0.5 문턱에서는 모두 보류했다. 개발 F1의 고정 선형 대비 차이는 약 0.000021에 불과했다. 분류 점수의 미세한 차이가 적절한 기억 선택을 보증하지 않았다. 항상 ‘다른 원리’라고 답해도 평가 정확도가 88.5%이므로 전체 정확도도 주 지표로 부적절하다.

별도 CPU 적합 진단에서는 같은 고정 표현과 MLP를 학습 자료만으로 2,048업데이트해 **두 seed 모두 432/432**를 맞혔다. 개발·평가는 채점하지 않았고 새 평가 후보로 선택하지 않았다. 고정 표현이 현재 학습 주석을 맞힐 수 있다는 근거이며 새 이슈에서 일반화한다는 근거는 아니다. 주 실험과 배치·노출량이 달라 학습 길이만의 순수 효과도 아니다.

최종적으로 확인한 실패는 **이 자료·고정 학습 예산·선택 규칙에서 관련 기억을 고르지 못했다**는 것이다. LoRA 일반의 무효나 모델 구조의 본질적인 한계를 입증한 것은 아니다. 학습 긍정 18쌍, 개발의 무관련 이슈 0개, 주석 경계의 모호함, 최적화 예산을 각각 보완해야 한다. [마지막 실험 보고서](2026-11-08-development-memory-leads.md), [데이터 카드](../../datasets/development_memory_leads/20261108-v1/README.md).

## 6. 이번 회차가 뒷받침하는 주장

- **측정 가능성:** 고정 작업자와 현재 상태에서 기억 제공/보류를 실행해 개선·악화·비용을 수치로 연결할 수 있다. 현재 근거는 작고 제한된 과제에 조건부다.
- **조건 의존성:** 같은 절차도 반환 위치·원본 변경 요구·현재 초기화 상태에 따라 결과가 달라졌다. 정보의 존재, 적용 가능성, 실제 활용을 따로 측정할 이유가 있다.
- **정보 보존:** 과정 정보를 추가해 요구 충족이 달라진 사례를 확보했다. 길이·정보량·코드 예시가 함께 바뀌므로 표현 방식 하나의 효과는 분리하지 못했다.
- **학습 선택기의 현재 한계:** 일부 탐색적인 개선은 있지만 사전 주 모델·개발 선택의 안정적 우위는 없었다. 마지막 실제 이슈 실험도 선택에 실패했다.
- **검증할 수 있는 연구 기반:** 출처·입력·개입·모델·예측·실행 판정·비용·선택 시점을 연결하고, 실패와 미확정 결과를 보존했다. 일부 검산 통과가 주석의 의미적 정답이나 전체 시스템 정확성을 보장하지는 않는다.

아직 뒷받침하지 못하는 주장은 자연 SWE 과제에서의 일반적인 해결률 개선, 어떤 기억 특성의 보편적 인과 효과, 학습 선택기의 필요성, 새 작업자에 대한 효용 전이 보장이다. 초기의 큰 개선 수치나 마지막의 0/4 하나로 각각의 일반 결론을 만들지 않는다.

## 7. 다음 연구를 시작한다면

1. 실제 경험과 별도 현재 작업을 독립 출처에서 연결한다. 현재에 이미 알려진 정보·기억이 추가하는 정보·조건이 어긋나는 정보를 구분하고, 관계 주석의 독립 검토를 확보한다. 효과가 없거나 단순 해법으로 충분한 사례도 남긴다.
2. 원문 근거와 가능한 적용 조건으로 기억 조각을 고정한 뒤, 같은 현재 관측에서 포함/제거·제공/보류를 실행한다. 평가 성적이 좋은 상태만 사후에 남기지 않는다. 개발에도 여러 출처와 보류 사례를 포함하고, 상황별 선택으로 얻을 여지를 점검한다.
3. 관련성 분류와 실제 효용 학습을 별도 목표로 둔다. 기존 손실·입력 기준선을 유지하며 한 가지 변경을 비교하고, 학습 적합·개발 선택·새 확인을 순서대로 검증한다. 선택기 인코딩까지 포함한 비용으로 고정 기억·검색·단순 규칙을 이기는지 본다.

결과 4범주 감독, 개념 개입, 보류 학습, 층 혼합, 검증된 근거 증류는 [후속 문헌 노트](../ai-memory-alternatives-to-contrastive-learning-2026-11-08.md)의 **제안**이다. 마지막 완료 실험은 진단 관련성의 3분류·후보 순위 학습이며, 이 후보들을 새로 실행한 결과로 혼동하지 않는다.
