# MemoryArena 여행 참조 판독: 데이터 수집·학습·평가

MemoryArena의 공개 여행 자료를 정리하고 **Harrier 0.6B의 고정 판독층과 LoRA 두 방법을 실제로 학습했다.** 학습에 쓰지 않은 기본 계획 8개에서 파생한 1,153개 요청의 참조 기억 선택은 고정 MLP 66.5%, LoRA 두 방법 100%였다. 학습·가중치 저장·예측 검산을 완료했고 Colab은 종료했다.

이번 결과는 **정확한 과거 기록과 명시적 참조 문장을 주었을 때, 6개 후보 중 참조 대상을 찾는 능력**이다. 실제 기억 제공의 득실, 전체 여행 계획 성공률, 공식 MemoryArena 성적은 아직 측정하지 않았다. 주석을 만드는 규칙도 구성상 100%이므로, 별도 학습 모델의 필요성이나 새로운 방법의 우월성이 입증된 결과는 아니다.

## 데이터와 평가 단위

[고정 데이터 명세](../../datasets/memoryarena_travel/20261109-reference-v1/README.md)와 [학습 전 설계](../ai-memory-travel-selector-training-2026-11-08.md)에 출처·분할·주석·설정 변경을 보존했다.

| 단위 | Train | Dev | Test |
| --- | ---: | ---: | ---: |
| 기본 계획 | 30 | 7 | 8 |
| 원래 연속 과제 묶음 | 180 | 42 | 48 |
| 명시적 참조 요청 | 4,288 | 940 | 1,153 |
| 요청–기억 후보 쌍 | 25,728 | 5,640 | 6,918 |

원본 270묶음은 45개 기본 계획을 각각 6번 사용한다. 같은 기본 계획의 모든 변형을 같은 분할에 두었다. 원래 TravelPlanner train과도 이 45개가 일치하므로 별도 신규 출처로 더하지 않는다. **38,286쌍을 38,286개의 독립 경험으로 세지 않는다.** Test는 이번 추가 학습에서 제외한 계획이며 기반 모델의 사전학습 미노출까지 확인한 것은 아니다.

입력은 현재 여행자·여행 길이·원문의 참조 문장과 후보 기록의 사람·날짜·항목·값이다. 기본 여행자의 계획과 현재 차례보다 앞선 공개 참조 계획을 정확한 과거 기억으로 가정한다. 현재·미래의 정답 계획, 후보 ID, 주석, 분할은 모델 입력에 넣지 않는다. Test 관계 정답도 Colab에 업로드하지 않았다.

라벨은 `그대로 참조 / 비교 기준으로 참조 / 해당 참조 대상 아님`이다. 마지막 라벨은 **해로운 기억**을 뜻하지 않는다. 같은 사람의 다른 날짜, 다른 사람의 같은 날짜, 다른 항목을 음성 후보로 포함했다. 학습에서 같은 기억 ID 2,038개가 요청에 따라 참조와 비참조 양쪽으로 나타난다.

38,286쌍 모두 원문 구간·이전 시점·참조 대상을 검사했고, 분할 간 동일 입력 쌍은 없었다. 가장 긴 입력은 178토큰으로 한도 256 아래였다. 보수적인 문법 규칙으로 주석하고 AI 에이전트가 train/dev 50개 요청을 사례별로 확인했다. **사람이나 독립 주석자의 검토는 없다.** 질문 양식과 분야는 분할 사이에 공유되며, 전체 요청에서 참조 문장을 추출하는 문제도 모델 밖에서 해결했다.

## 학습과 결과

기반 모델은 `microsoft/harrier-oss-v1-0.6b`, revision `f9b9dc8d367d443f2479d27aa5d8d2850c0774ee`다. 현재 문장과 기억을 함께 읽고 마지막 유효 토큰의 정규화된 표현을 판독한다. 고정 선형/MLP, 현재 문장 단독, 기억 단독, LoRA+분류, LoRA+분류·후보 순위 손실을 비교했다.

LoRA는 q/v projection에 rank 8을 쓰고 MLP 판독층을 함께 학습했다. 학습 파라미터는 adapter 1,146,880개와 판독층 131,587개다. 두 LoRA는 초기 파라미터와 학습 순서가 같으며 seed 731 하나를 사용했다. 고정 모델은 모든 학습 행을 12회, LoRA는 2회 학습했다. Dev의 **기본 계획별 Top1 평균**으로 checkpoint와 방법을 선택하고 동점이면 먼저 나온 것을 유지했다. 선택된 두 LoRA checkpoint는 첫 epoch의 1,072업데이트이며, 최종 2,144업데이트 가중치도 별도로 보존했다. 방법 간 동점 규칙에 따라 주 모델은 LoRA+분류다.

| 방법 | Dev 요청 Top1 | Test 정답/1,153 | Test 요청 Top1 | Test 계획별 Top1 평균 |
| --- | ---: | ---: | ---: | ---: |
| 무작위, 고정 seed | 15.7% | 204 | 17.7% | 17.9% |
| BM25 | 42.6% | 404 | 35.0% | 34.2% |
| 날짜 표현 정규화 BM25 | 50.6% | 465 | 40.3% | 40.2% |
| 고정 표현 + 선형 | 52.7% | 630 | 54.6% | 53.8% |
| 고정 표현 + MLP | 64.4% | 767 | 66.5% | 66.3% |
| 현재 문장만 + MLP | 16.5% | 171 | 14.8% | 14.9% |
| 기억만 + MLP | 17.2% | 175 | 15.2% | 15.2% |
| **LoRA + 분류, 주 모델** | **100%** | **1,153** | **100%** | **100%** |
| LoRA + 분류·후보 순위 | 100% | 1,153 | 100% | 100% |
| 주석 규칙 재실행, 구성상 상한 | 100% | 1,153 | 100% | 100% |

현재 목표 날짜와 참조 날짜가 다른 629요청에서 고정 MLP는 341개, 두 LoRA는 629개를 맞혔다. 같은 날짜 524요청에서는 각각 426개와 524개였다. 두 LoRA 모두 선택한 참조의 재사용/비교 종류까지 맞혔다. 후보 각각을 독립적으로 3분류하면 오분류가 남아 macro F1은 0.99845와 0.99853이다. **Top1 100%가 모든 후보의 모든 판단이 정확하다는 뜻은 아니다.** 후보 순위 손실의 추가 이득도 이 포화된 과제에서는 확인하지 못했다.

### 보류 진단과 실제 사례

Test 채점 전에 별도 진단을 고정했다. 주석된 참조 후보 하나를 제거한 5개 후보 집합에서 보류하는지 측정한다. Dev에서만 고른 임계값 0.25를 적용한 주 LoRA는 원래 집합 1,153개에서 모두 정확히 제공했고, 제거 집합에서는 **1,150/1,153개를 보류**했다. 순위 손실 추가 모델은 원래 집합에서도 3개를 보류했다. 이는 후보 삭제 진단이며 자연스럽게 유용한 기억이 없는 상황의 성공률이나 득실 확률 보정은 아니다.

[사례 파일](../../evaluation/results/memoryarena-travel-references-20261109-v1/examples.json)은 각 조건에서 원래 Test 순서상 처음 해당하는 사례를 담는다.

- **날짜를 구별한 개선:** Kimberly의 첫날 숙소를 Hazel의 둘째 날 숙소와 비교하는 요청에서 MLP는 Hazel의 첫날 숙소를, LoRA는 둘째 날 숙소를 골랐다.
- **보류 실패:** Ava의 첫날 저녁 식당을 기준으로 삼는 요청에서 해당 기록을 빼면 LoRA는 Avery의 첫날 저녁 기록을 높은 점수로 골랐다. 이름 혼동 가능성을 보여 주지만 원인을 입증한 것은 아니다.
- **출처 오류와 값 일치:** Zoey의 여섯째 날 아침 식당을 요구했을 때 MLP는 다섯째 날 저녁 기록을 골랐지만 두 기록에 같은 식당 값이 있었다. MLP의 값 일치율은 68.1%로 참조 정답 66.5%보다 높았다. 둘 중 어느 수치도 작업자의 실제 성공률은 아니다.

## 검산·자원·재현

[공유 예측 묶음](../../evaluation/results/memoryarena-travel-references-20261109-v1/README.md)에 원래 예측을 손실 없이 압축해 보존했다. GPU 없이 6모델의 **229,716개 저장 예측**, 분할·dev 선택·조건별 지표·보류 진단을 재계산할 수 있다.

```bash
python3 -m evaluation.travel_reference_exports verify \
  evaluation/results/memoryarena-travel-references-20261109-v1
```

별도 CPU 가중치 감사에서 head·adapter 변화, optimizer step, 모든 행의 학습 노출, dev 선택을 확인했다. 두 LoRA의 112개 adapter tensor가 모두 바뀌었다. 고정 모델 4개의 저장 특징과 head를 NumPy로 다시 계산한 최대 확률 차이는 0.0000013 미만이다. GPU 학습 중 checkpoint 재로딩 확인도 통과했다. **전체 인코더 순전파를 독립 환경에서 다시 실행한 검증은 아니다.**

코드 검사는 학습 영역 126개 중 121개 통과·기존 CPU Torch 조건부 검사 5개 skip, 평가 영역 34개 통과였다. 이번 가중치 감사는 별도의 CPU Torch 환경에서 실제 수행했다. Colab 연결·실패·종료 검사는 외부 호출을 모의하며 이 검사로 GPU를 할당하지 않는다.

커밋 `aa13d48`의 [별도 clone 재현](../../evaluation/results/memoryarena-travel-references-20261109-v1/fresh-clone-checks.json)에서도 README의 74행 검사·444개 예측·여행 229,716개 예측을 확인했다. 공개 원본 재다운로드 후 생성 데이터 전체 해시와 학습 업로드 파일이 원래 실행과 일치했고 Test 정답 키는 0개였다. 학습 검사는 `Ran 121, OK (skipped=7)`, 평가 검사는 34개 통과였다. 새 clone에는 과거 수치·범위 실험의 로컬 생성 자료가 없어 관련 class/검사 skip이 추가되며, 이번 여행 자료의 실패는 없다.

첫 Test 계산 뒤 BM25의 소수 동점이 Python 해시 순서에 따라 달라짐을 발견했다. 토큰 정렬과 `math.fsum`으로 수정하고 서로 다른 해시 seed에서 확인했다. [평가 전 고정 기록](../../evaluation/results/memoryarena-travel-references-20261109-v1/evaluation-plan-lock.json)과 [수정 기록](../../evaluation/results/memoryarena-travel-references-20261109-v1/evaluation-amendment-bm25-order.json)을 함께 남겼다. 원래 평가도 로컬에 보존했고, 데이터·신경망 예측·모델 선택·기존 학습/dev 지표는 바뀌지 않았다. 이 표의 BM25는 수정한 결정적 계산이다.

Colab은 연결·전송 실패와 세션 소실을 포함해 **6회 할당**했다. 초기 L4 실행에서 네 고정 모델을 회수했으며 중단된 LoRA는 재사용하지 않았다. 마지막 A100에서 두 LoRA를 완료하고 중간/완료 checkpoint ZIP 6개와 최종 결과를 회수했다. A100 제어 구간은 약 23.8분, 여섯 구간 합계는 82.3분이며 설치·전송·회수도 포함하므로 정확한 GPU 과금 시간이 아니다. 관측 단가는 L4 1.94, A100 6.73 Colab 단위/시간이었다. [실패를 포함한 자원 기록](../../evaluation/results/memoryarena-travel-references-20261109-v1/resource-history.json)에 원인·범위·해시를 남겼다. 로컬 GPU와 유료 LLM API는 사용하지 않았다. 완료 후 사용률 0.00/시간과 해당 세션 부재를 확인했다.

가중치는 Git 밖의 `training/memory_selector/outputs/memoryarena-travel-training-20261109-a100/artifacts/lora-ce-seed731/best/`에 있다. `adapter/`와 `checkpoint.pt`의 판독층, 고정한 기반 모델과 입력 템플릿을 함께 사용해야 한다. 전체 전달·가중치 검토에는 이전 `memoryarena-travel-training-20261109-retry1`과 최종 `memoryarena-travel-training-20261109-a100`의 **upload.zip과 results.zip 네 파일**이 필요하다. 이전 실행에 보존한 고정 특징 캐시까지 있어야 전체 판독층 재검산이 가능하다. 해시는 자원 기록에 있다.

## 연구 판단과 다음 비교

이번 자료에서는 **현재 요청과 기억을 함께 읽도록 추가 학습하면, 명시적 관계 선택을 배울 수 있다**는 결과를 얻었다. 이전 실패만으로 기반 모델이 망가졌다고 판단할 근거는 없으며 이번에는 동일한 원본 기반 모델에서 새로 시작했다. 반면 규칙으로도 해결되는 좁은 과제, 기본 계획 8개의 Test, 한 seed, 깨끗한 참조 이력이라는 한계가 크다. 더 큰 모델이나 층을 추가하기 전에 실제 효용과 연결하는 쪽이 우선이다.

후속 비교는 고정 작업자에게 같은 시점에서 **기억 없음 / 후보 전체 / 검색 선택 / 학습 선택**을 제공하는 것이다. 실제로 생성한 과거 기록을 사용하고 `실패→성공 / 성공→실패 / 둘 다 성공 / 둘 다 실패`, 토큰과 선택기 포함 시간을 함께 기록한다. 올바른 참조가 필요해도 작업자가 이미 알면 이득이 없고, 잘못된 출처라도 같은 값이면 도움이 될 수 있다. 이 간격을 측정해야 처음의 “메모리의 득과 실을 판단할 수 있는가”에 답할 수 있다. 이번 회차에는 이 작업자 실행을 포함하지 않았다.
