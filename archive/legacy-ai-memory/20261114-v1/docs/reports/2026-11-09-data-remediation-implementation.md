# 데이터 보완 실행과 연구 질문 정렬

2026-11-09. [내용 점검·보완안 추가 검토](2026-11-09-data-remediation-review.md)에서 지적한 입력·근거·결과 의미를 코드와 별도 자료 버전으로 보완함. 기존 데이터·예측·학습 가중치는 그대로 보존함. 새 학습·GPU 할당·유료 호출은 수행하지 않았음.

## 연구 질문과 현재 도달 지점

전체 연구의 출발점은 **에이전트 메모리의 득과 실을 판단할 수 있는가**임. 이를 어떤 정보를 보존하고, 어떤 상황에서 어떻게 사용했을 때 성공·오류·비용이 달라지는지 측정하고 설명·예측하는 방향으로 구체화함. 아래 질문은 그 목표에 연결되는 한 가지 실험 방향이며, 전체 연구의 핵심 질문으로 확정한 것은 아님.

> 주 모델과 메모리 저장소를 동일하게 유지했을 때, 현재 목표·진행 상황·실패 이력을 고려하는 메모리 선택 모델이 같은 컨텍스트 예산에서 에이전트의 작업 성공률을 높일 수 있는가?

**관계 판독은 득실을 예측·설명하는 신호이고, 학습한 선택기는 그 신호의 실제 가치를 검증하는 방법임.** 관계 판독 정확도, 득실 예측 성적, 선택 정책의 성공·악화·비용을 각각 평가함. 성공률 증가만으로 기억의 어느 정보가 어떤 조건에서 도움이 됐는지까지 설명했다고 보지 않음. 0.6B base/LoRA와 4B·9B를 비교할 때는 선택기 역할에서 비교하며, 그 비교 중 작업자는 바꾸지 않음.

| 질문의 조건 | 이번 자료에서 확보한 것 | 아직 부족한 것 |
| --- | --- | --- |
| 동일 주 모델 | 저장된 9B 작업자의 revision·가중치 해시·생성 설정·프롬프트 보존 | 새 선택 모델의 선택 결과를 같은 작업자로 실행하는 비교 |
| 동일 메모리 저장소 | 각 상태의 동일 후보와 원문 기록을 복원함 | 새로운 원천의 과거 경험. 상태 간 통제 변형은 있어도 정책별로 후보를 바꾸지 않아야 함 |
| 현재 목표·상황 | 현재 요청과 실제 제시한 도구 관측이 렌더러에 포함됨 | 순차 진행 기록과 실제 실패 이력. 현재 96개 snapshot에는 없음 |
| 같은 컨텍스트 예산 | 저장된 작업자 tokenizer로 제공 내용 512토큰 상한을 검산함 | 큰 저장소에서 예산이 실제로 제약되는 조건. 현재 최대 사용량은 254토큰임 |
| 작업 성공 개선 | 같은 상태에서 관측된 묶음·무기억 결과를 연결함 | 새 출처의 정책 성공 개선, 여러 단계 에이전트의 최종 작업 성공 |

따라서 이번 결과는 **득실 측정과 상태를 고려한 선택 실험에 필요한 데이터 기반의 일부를 보완한 것**임. 진행·실패 이력을 고려한 모델의 효과나 새 일반화 성능을 확보한 결과가 아님. 현재 travel 작업자는 두 최종 선택을 응답하는 구성으로, 긴 에이전트 실행 전체와 구분함. 진행·실패 이력은 조사할 수 있는 조건이며 모든 사례에 억지로 넣어야 하는 필수 요소는 아님.

## 완료한 보완

### 1. 근거와 재검토 자료

[검토 v2](../design-data/memory-data-remediation-20261109-v2/README.md)에 안내문·현재 관측 잘림 표시·출처 보충 자료를 포함함. 기존 64행에 query별 잔여 음성 표본 27개를 추가해 91행을 구성함. 새 원천은 0개임. 검토자용 ZIP은 기존 정답·선정 사유와 분리했으며 파일·범위·원문 일치를 검증함.

과거 원자료 16개를 해시로 대조하고, 출처 이슈 설명을 복원함. 그 결과 다음 두 문제를 구분했음.

- **Redis 옵션 요약 오류:** 과거 이슈가 보고한 것은 auto-close 문제이나 인용된 실제 수정은 `single_connection_client` 전달을 분리함. 기존 카드의 “auto-close 옵션을 수정했다”는 부분은 해당 수정 근거와 일치하지 않음. 실제 수정만 서술하는 정정 문안을 저장함.
- **Python 문맥 누락·수정 범위 확대:** Python 3.13 설명은 실제 과거 이슈에 있었으나 검토 묶음에서 빠져 있었음. 다만 인용된 수정은 whitespace-only docstring guard임. 일반적인 공백 trimming 처리나 실제 해당 버전 실행 성공으로 확대하지 않도록 정정함.

18개 기존 양성과 경계·출처 문제 5개를 다시 읽고 [23개 비맹검 초안](../design-data/memory-data-remediation-20261109-v2/first-pass-nonblind.jsonl)을 작성함. 기존 양성은 12개 유지·5개 미확인·1개 다른 점검 목표라는 의견임. **이 값은 독립 정답·전체 데이터 오류율·새 성능 점수가 아님.** 수정 카드를 반영하면 관계 입력도 바뀌므로 기존 라벨을 자동 승계하지 않음. 검토 검증기는 이러한 초안을 학습용 확정 정답으로 내보내지 않음.

### 2. 선택기 입력과 실제 행동 결과 연결

[현재 상태 데이터 v2](../../datasets/memory_decisions/20261109-observed-v2/README.md)를 내보냄. 기존 12개 train family의 96개 상태·540개 과거 기록을 사용함. 672개 정책 결과를 동일 상태·동일 전달 순서의 333개 관측 행동으로 합쳤고, 고유 작업자 입력은 309개임.

현재 요청·관측과 실제 제공용 기억 문장을 함께 읽는 렌더러를 추가함. 원래 작업자 메시지와 생성 ID까지 대조함. 정답·정책 이름·조건 이름은 입력에 포함하지 않음. 결과가 없는 행동은 미측정으로 유지함. 후보 순서는 라벨과 무관한 고정 순서이며, 최종 전달 순서는 별도로 보존함.

이 자료는 탐색적 학습에만 사용할 수 있음. 같은 family의 변형·행동은 함께 분할하고, 기존 train 자료를 새 독립 평가 집합이라고 부르지 않음. 선택기가 새 조합을 내면 기존에 실행한 것과 일치하는지 확인하고, 일치하지 않으면 결과를 추정해 채우지 않음.

### 3. 성공·오류·비용의 의미 분리

성공 정답은 변경하지 않음. “근거 없이 불가능하다고 답함”과 “가능한 선택지가 있는데 불가능하다고 답함”을 별도로 기록함.

| 관측 행동 333개·응답 요소 666개에서의 진단 | 수 |
| --- | ---: |
| 과거 근거가 전달되지 않았는데 NONE이라고 답함 | 154 |
| 공통 판정 근거상 가능한 선택지가 있는데 NONE이라고 답함 | 48 |
| NONE의 실제 타당성을 현재 공통 근거로 판정할 수 없음 | 83 |

83개는 오류 없음으로 바꾸지 않고 `null`로 보존함. 이는 일부 진단 라벨이 미확정이라는 뜻이며, 기존 작업 성공 판정을 변경한 것이 아님. 작업자 토큰·기록된 생성 시간은 보존하고, 알 수 없는 선택기 비용은 0 대신 `null`임. 333개 행동의 성공을 단순 합산한 비율은 정책 성능으로 사용하지 않음.

## 다음 학습·수집의 구체적 경계

다음 우선 작업은 **새 독립 출처의 과거 경험과 현재 상태를 연결하고, 기억 제공 여부에 따른 실제 결과를 비교할 자료를 확보하는 것**임. 기존 자료는 12개 train family를 재구성한 것이므로 행 수 증가를 경험의 다양성 증가로 보지 않음. 첫 산출물은 원천–기억–현재 관측–제공/미제공 실행–결과·비용이 연결된 검토표와 실행 명세로 둠.

자료·코드를 확인한 후속 구체안은 [다음 세 단계의 실행 가능성 점검](../ai-memory-next-steps-feasibility-2026-11-09.md)에 정리함. 공개 도구 호출 자료의 의미 오류와 실제로 추가해야 하는 입력·채점·학습 작업을 포함함.

1. **득실을 구분할 조건 확보:** 같은 기억에 대해 필요한 정보가 현재에 없는 경우, 이미 관측된 경우, 적용 전제가 달라진 경우를 실제 출처에서 찾음. 진행·실패 기록이 관련될 때 그 기록을 포함함. 적용성 주석만으로 유익·유해 정답을 미리 정하지 않음. 과거/현재의 시점·원문 위치·독립 원천을 기록하고, 증강 전 원천별 분할을 고정함.
2. **제공 효과 측정:** 고정 작업자·같은 사전 상태에서 기억 제공/미제공을 짝지어 실행함. 개선·악화·둘 다 성공·둘 다 실패와 비용을 보존함. 반복이 필요한 사례는 실행 변동을 함께 확인함. 기억 조각의 역할은 관측·조건·절차 등의 포함/제거로 점검하되, 묶음 전체 효과를 개별 기억의 효과로 복사하지 않음. 결과를 보고 효과가 큰 사례만 확인용 평가 집합에 남기지 않음.
3. **판독·예측·선택 연결:** 관계·상태 신호가 관측된 득실을 예측하는지 확인하고, 작은 모델 학습을 통해 선택 정책으로 연결함. 무기억·예산 안의 고정 기억·검색·규칙과 비교하며 이후 0.6B base/LoRA·4B/9B 선택기 비교로 확장함. 현재 목표만 / 목표+현재 관측 등 입력 제거 비교는 실제 확보한 신호 범위에서 수행함. 실패 이력이 없는 자료로 그 효과를 주장하지 않음.

기존 23개 초안의 독립 판단과 남은 68개 검토는 보조 자료의 품질 점검으로 병행함. 이를 전부 완료하는 것이 새 출처 수집의 선행 조건은 아님. 불명확한 관계는 미확정으로 남기고 출처 충실성·관계·추가 정보·실제 효용을 분리함. 코드 관계 과제에 대한 세부 개선만으로 전체 메모리 연구가 진전됐다고 판단하지 않음.

먼저 같은 사전 상태에서 한 번의 기억 선택만 달리하는 비교를 수행하는 것이 적절함. 어느 정책이 기억을 받은 뒤 만든 명령·실패를 다른 정책의 시작 시점 입력으로 소급하지 않음. 이후 동적으로 여러 번 선택하는 실험에서는 공통 시작 상태·고정 초기 기억 저장소·동일 도구 및 시간 상한을 유지하고, 정책별로 달라진 진행 경로 전체를 평가함.

주 지표는 상태별 성공 차이이며, 기존 성공을 망친 수·개선한 수·선택기 포함 비용을 함께 측정함. 동일 컨텍스트 예산은 같은 상한을 뜻함. 전체 기억이 상한을 넘는 조건은 별도 진단이며 주 비교에 섞지 않음. 불확실성은 독립 원천 단위로 집계하고, 성공한 사례만 새 평가 자료로 선별하지 않음.

## 검증과 재현

```bash
python3 -m data_pipeline.memory_relation_review --output /tmp/memory-review-v2-new
.venv/bin/python -m data_pipeline.memory_decision_dataset --output /tmp/memory-decisions-v2-new
.venv/bin/python -m unittest evaluation.tests.test_memory_outcome_labels evaluation.tests.test_memory_remediation -v
```

저장된 tokenizer를 읽는 `tokenizers` 설치 환경이 필요함. 새 20개 검사는 오류의 미확정 처리, 근거 인용, 사후 라벨 노출 방지, 미래/다른 family 기억 거부, 누락 행동, 예산, 동일 출력 재생성을 다룸. 관련 기존 검사 20개도 통과함. 공유할 파일만 담은 새 사본에서 기존 Python 환경으로 40개 검사와 바이트 단위 재생성을 확인함. [검증 기록](../design-data/memory-data-remediation-20261109-v2/verification.json)에 원본 해시를 보존함. 보완 묶음 준비와 1차 근거 검토를 완료했으며, 독립 주석 확정·새 경험 확보·효과 개선 검증은 남아 있음.
