# 동일 작업자 환경의 기억 득실 재측정

**고정한 484호출을 모두 완료하고, 504개 상태–행동의 실제 결과를 새 데이터 버전으로 확정함.** 비어 있지 않은 기억 후보끼리 성공이 다른 상태는 **7→28개**, 성공이 다른 후보 비교쌍은 **16→177개**로 늘었음. 선택을 학습할 대조가 보강된 결과이며, 선택기 성능이 개선됐다는 결과는 아님. 이번에는 작업자 출력을 수집했고 Harrier 선택기는 추가 학습하지 않았음.

## 관계와 실제 득실의 연결

사전에 구성한 19요청의 네 가지 기억 조합을 세 현재 상태에서 비교함. `참조`는 현재 요청의 사람·날짜·항목이 맞는 기록이고 `유사`는 같은 항목이지만 사람 또는 날짜가 다른 원래 기록임. 각 조합은 모두 2기록임.

| 현재 상태 | 참조+참조 | 참조+유사 | 유사+참조 | 유사+유사 |
| --- | ---: | ---: | ---: | ---: |
| 필요한 기록을 현재 관측에 갖고 있지 않음 | 14/19 | 2/19 | 5/19 | 3/19 |
| 필요한 기록이 현재 관측에 이미 있음 | 15/19 | 15/19 | 15/19 | 15/19 |
| 현재 가용성이 바뀜·과거 기록은 관측에 없음 | 14/19 | 10/19 | 8/19 | 5/19 |

위 표는 실제 과제 성공 수임. 현재 관측에 근거가 없는 두 조건에서 유사 기록을 하나라도 넣은 조합의 **입력 근거 준수 성공은 모두 0/19**임. 실제 정답과 일치하는 것과 입력 근거에 맞게 행동하는 것이 다름을 확인함. 반대로 근거가 이미 있는 조건에서는 네 조합 모두 같은 15상태에서 성공했음. 관계상 맞지 않는 기록을 일괄 악화 정답으로 붙이면 이 차이가 사라짐.

57개 네 칸 대조 중 실제 성공이 갈리는 것은 22상태, 입력 근거 준수 여부가 갈리는 것은 28상태임. 필요한 기록 2개를 제공한 57배정에서도 실패는 14건 남았음. 기억의 참조 일치만으로 작업자 성공을 보장할 수 없음.

### 실제 출력 사례

아래는 결과를 본 뒤 고른 설명용 사례이며 별도 성능 표본이나 데이터 선별 기준이 아님. 전체 입력·기억 원문·정답 집합·출력·상태 ID는 [내용 검토 JSON](data/memory-worker-refresh-20261110/content-review.json)의 `examples`에 연결함.

- **현재 근거가 없을 때 사람 구분이 필요한 사례:** Jacob의 3일차 식당과 Ben의 3일차 숙소를 요청함. 정확한 두 기록을 주면 `R577/H1087`로 성공함. 다른 사람의 기록으로 둘 다 바꾸면 `R9515/H5022`를 반환해 실패함. 한쪽만 바꿔도 해당 항목을 잘못 고름. 같은 목표에서 필요한 기록이 현재 관측에 이미 있으면 무기억과 네 기억 조합 모두 성공함.
- **악화 숫자의 해석이 필요한 사례:** 필요한 장소가 현재 모두 이용 불가인 상태에서, 무기억은 근거 없이 `NONE/NONE`을 출력해 실제 정답과 일치함. 다른 날짜 기록을 주면 `NONE/H3262`로 바뀌어 실제 정답을 틀림. 네 범주상 악화이지만 무기억도 입력 근거 규칙을 위반했으므로, 근거 있는 성공을 망친 사례와 구분해야 함.
- **필요한 근거를 제공해도 실패하는 사례:** 현재 호텔은 과거 가격 934 이하·평점 3 이상이어야 함. 정확한 가격 기록을 줬지만 작업자는 가격 300·평점 1인 `H4543`을 고름. 허용되는 호텔은 `H107/H192`임. 이 경우 기억 누락을 보완하는 것만으로 작업자의 조건 검사를 해결하지 못함.

## 아직 부족한 데이터

악화는 9→23묶음, 5→9상태, 4→6가족으로 늘었음. 그러나 **무기억도 입력 근거를 준수하며 성공했던 상태의 악화는 4→7묶음이고, 여전히 같은 2상태·2가족**임. 나머지 16묶음은 무기억의 근거 없는 정답 일치가 깨진 경우임. 새 악화 14묶음 중 3개만 전자에 속하며 모두 기존 한 상태에서 나옴. 악화 라벨의 양적 증가를 다양한 손해 상황의 확보로 확대하지 않음. 원래 주 라벨은 유지하고 이 두 축을 별도로 평가함.

독립 가족은 여전히 12개, 현재 요청 24개, 구성한 현재 상태 96개임. 실제 진행·실패 이력이나 새 도메인을 추가하지 않았음. 필요한 참조가 은행에서 빠진 24상태는 이번 증강 대상이 아니며, 기존 57비어 있지 않은 후보는 모두 둘 다 실패함. 적절한 UNKNOWN 응답·선택기 보류를 학습할 대조도 충분하다고 보기 어려움.

추가 기록은 원문 전체이므로 사람·날짜 외에 장소·가격·속성도 달라질 수 있음. 기록별 길이 차이는 최대 8토큰으로 제한했지만 관계 외 모든 정보가 같은 단일 변수 인과 실험은 아님. 가격·항목·관계에 대한 간단한 규칙, 길이·개수 기준선과 비교해야 함. 과거 기록이 실제로 생성됐다는 사실도 당시 과거 목표의 성공을 보장하지 않음.

검토 중 기존 생성기의 가격 차이 확인 분기가 `mode == 'price'`인데 실제 자료는 `comparison`을 사용한다는 점을 발견함. 고정된 생성기는 이번 회차 재현을 위해 보존함. 대신 실제 가격 비교용 18기록쌍의 가격 차이를 독립 재검사했고 같은 가격은 0쌍이었음. 관련 검사도 실제 모드명으로 수정함. 이번 선택 기록에는 영향이 없지만, 새 자료의 생성기로 그대로 확장하기 전에는 이 분기를 새 버전에서 수정해야 함.

## 실행·검산과 공유

- 모델과 입력은 수집 전 고정함. Qwen3.5-9B는 기억을 받은 뒤 답하는 고정 **작업자**이며, Harrier 0.6B 선택기의 크기 비교가 아님.

추가 후보는 이미 검토한 19요청·57상태의 네 칸 대조를 유지함. 식사·숙소 각각의 참조 기록/같은 주제이지만 사람 또는 날짜가 다른 실제 기록을 교차함. 228대조 행동 중 57개는 기존 후보와 같아, 새로운 상태–행동은 171개임. 기록을 새로 쓰지 않으며 각 대조 묶음은 2기록, 기록쌍 토큰 차이는 8 이내임. 전체 정책의 전달 예산은 기존과 같은 512토큰 상한임.

원래 333행의 출력도 모두 새로 생성함. 동일 입력의 정책 별칭·상태 별칭은 한 번의 새 출력을 공유하며 독립 실행으로 중복 계산하지 않음. 이전 Colab 출력이나 호환성 검사에서 거부한 로컬 출력은 새 라벨에 사용하지 않음. 원래 라벨은 별도 버전으로 보존하고 차이는 사후 비교로만 기록함.

## 작업자와 실행 제한

작업자는 `Qwen/Qwen3.5-9B`, revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a`로 고정함. 실제 가중치 해시를 기존 출처와 대조함. BF16·SDPA·batch 1·greedy·thinking off·최대 출력 64토큰·입력 잘림 금지를 유지함. worker에는 메시지와 입력 식별자만 전달하며 정답·관계 비트·정책 이름은 전달하지 않음.

Colab L4 할당을 한 번 시도함. controller는 3,900초, worker는 3,300초로 제한하며 다운로드·종료를 포함해 사용한 자체 세션을 회수함. Colab에서 실제 출력이 0개인 상태로 실패하면 로컬 BF16 CPU offload를 한 번 허용함. 로컬 GPU 가중치 상한 11 GiB, 전체 16,200초로 제한함. 부분 Colab 출력을 로컬 출력과 합쳐 완료시키지 않음. 실행 환경과 device map은 모두 저장함.

기존 기록의 평균 호출 시간은 Colab 약 2초·로컬 offload 약 27초였음. 이는 예산 계획에 참고한 과거 관측이며 이번 실행 시간의 보장은 아님. 모델 및 데이터 준비가 끝난 뒤 할당해 유휴 GPU 시간을 줄임.

## 검증과 라벨

무기억·원래 비어 있지 않은 후보·한쪽 대조·양쪽 대조에서 결과와 무관하게 해시로 고른 네 고유 입력을 실행 시작에 반복하고, 전체 480입력 실행의 같은 메시지와 대조함. 입력 token ID와 연결된 모든 상태–행동의 **비비용 결과 축**이 같아야 학습용 자료로 확정함. 정답 ID가 여러 개일 수 있으므로 출력 token 차이는 별도로 보고함. 원래 데이터의 출력과 같은 것을 통과 조건으로 삼지 않음.

실패한 답·잘못된 형식·토큰 한도 도달도 저장하고 채점함. 일부만 완료된 실행이나 안정성 라벨 불일치는 완성된 학습 자료로 발표하지 않음. 유리한 후보나 상태만 남기는 결과 기반 제외를 하지 않음.

원문·현재 상태·전달 기억을 다시 구성해 실제 메시지·token ID·파싱을 대조함. 기존 채점과 독립 SQL 해답 집합을 비교한 뒤 다음 신호를 별도로 보존함.

- 새 무기억 결과와 기억 제공 결과의 개선·악화·둘 다 성공·둘 다 실패.
- 입력 근거에 맞는 성공, 근거 없는 구체적 행동·불가능 판단, 미확인 판단.
- 전달 토큰·worker 입력/출력 토큰·실행 시간. 아직 실행하지 않은 선택기의 비용은 미측정으로 둠.
- 지정 참조의 포함·누락과 현재 관측과의 중복. 이 관계 주석을 실제 효용 정답으로 대체하지 않음.

원래 후보 집합과 확장 후보 집합을 나누어 경쟁 후보가 있는 상태·후보 순위 대조·악화 범주의 분포를 집계함. 원래 3개 가족 분할을 유지하며 파생 사례는 부모 가족과 같은 fold에 둠. 데이터가 준비되면 원래/보강 자료 × CE/CE+선택 손실의 같은 조건 비교에 사용함.

이 단계는 기존 개발 자료의 관측 대조를 보강하는 작업임. 새 출처 일반화, 실제 연속 진행·실패 이력, MemoryArena 전체 종단 성능을 검증하는 단계는 아님.
