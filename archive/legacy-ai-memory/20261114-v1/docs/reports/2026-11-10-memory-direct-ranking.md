# 제공 후 성공을 직접 학습하는 후보 순위 진단

**2026-11-11 학습 완료.** 제공 후 성공의 이진 학습은 50–51/96, 순위 손실을 더하면 46–51/96임. 이전 4범주 선택의 40–43보다 높지만 긴 묶음 52·참조 규칙 55에 못 미침. 아래 실행 전 계획과 실제 결과를 구분함. 기존 408개 관측의 진단이며 새 출처 연구 성과를 확인하는 실험이 아님.

[피드백 검토](2026-11-10-ranking-and-collection-feedback.md)에서 점수 교체만으로 보강 모델의 성공이 41–42→45–47/96으로 바뀌었지만, 긴 묶음 52·참조 규칙 55에는 못 미쳤음. 이번에는 실제 추가 학습을 수행하며, 기존 결과를 새 조건의 결과로 재사용하지 않음.

## 고정한 비교

| 조건 | 학습 목표 |
| --- | --- |
| binary | 제공 후 작업 성공을 예측하는 scalar logit, 상태별 평균 BCE |
| binary_rank | 동일 BCE + 같은 상태의 성공/실패 후보 순위를 맞히는 softplus 손실 |

Harrier 0.6B의 pinned base `f9b9dc8d367d443f2479d27aa5d8d2850c0774ee`에서 두 조건 모두 새로 시작함. q/v LoRA rank 8·alpha 16, 128차원 MLP의 출력 한 개, head 학습률 0.001·LoRA 학습률 0.0001·순위 가중치 1임. [동결 자료](../../datasets/memory_ranking/20261110-v1/README.md)에 설정·분할·입력 해시를 보존함.

순위 손실은 sigmoid 이전 점수 차이를 사용함. 각 상태의 양성×음성 쌍을 평균하고, 정보가 있는 학습 상태 사이에서 평균되도록 정규화함. 같은 결과만 있는 상태는 BCE 감독에 유지함. 상태당 후보 수가 많다고 학습 가중치가 자동으로 커지지 않음.

기존 목표+현재 관측+제안 묶음 문자열과 `task_success` 라벨을 유지함. 근거 준수나 `UNKNOWN` 보류로 라벨을 교체하지 않음. relation 정답·검색 점수·사후 작업자 출력·fold 이름을 신경망 입력에 추가하지 않음. 문자열 안의 기존 기록 ID는 그대로 존재함.

## 내부 검증과 비교 범위

- 기존 3개 가족 분할의 바깥 학습 8가족을 해시로 6가족 학습·2가족 검증으로 나눔. 검증 선택은 현재 결과를 보기 전에 고정함.
- 내부 학습은 두 조건·3분할·초기값 731로 6회임. 8·16·24 epoch의 검증 성공 수, 상태 평균 순위 정확도, 낮은 BCE, 짧은 학습 순서로 epoch를 선택함.
- 내부 epoch 선택을 모두 완료한 뒤 바깥 학습 8가족에서 각 조건·분할·초기값 731/1729를 새로 적합함. 바깥 12개 LoRA 결과와 train 적합을 모두 보고함.
- 학습률·순위 가중치·출력층·제공 문턱은 이번 결과로 탐색하지 않음. 바깥 가족 결과로 epoch를 바꾸지 않음.
- 이전 4범주 실험은 참고 기준임. 이번에는 scalar 목표와 상태 묶음 배치 구성이 바뀌므로, 목적함수의 주 비교는 새 두 조건 사이에서 함.

주 지표는 같은 96상태에서 항상 최상위 비어 있지 않은 묶음을 골랐을 때의 작업 성공과, 결과가 다른 후보의 순위임. 동점은 전달 토큰·예제 ID 순서로 결정함. 미측정 행동의 결과를 채우지 않음. 전체 408후보가 주 비교이며 원래 237후보는 보조 진단임.

제공/보류는 보조 평가로 분리함. 고정 base가 현재 상태만 인코딩한 특징에서 무기억 성공 MLP를 CPU로 학습함. 내부 BCE로 16/64/128/256 epoch 중 하나를 정한 뒤 바깥 학습 가족에서 두 초기값으로 재적합함. 묶음 성공 확률이 무기억 성공 확률보다 클 때 제공함. 문턱 0·비용 가중치 0은 고정이며 보정된 최적 정책이라는 주장은 하지 않음. 상태 단위 정답을 추론 시 읽지 않음.

긴 묶음 52/96·순위 0.777을 넘어 참조 규칙 55/96·0.879에 접근하는지를 개발 진단의 목표로 둠. 실패하면 train 적합과 가족 전이를 구분하고 두 조건 비교를 종료함. 통과해도 학습 선택기의 필요성이나 새로운 독립 출처의 개선으로 보고하지 않음.

## 자원과 검산

로컬 RTX 4080 SUPER에서 다른 compute 프로세스가 없음을 확인한 뒤 실행함. 프로세스 메모리 상한 50%, 시작·각 fit 전에 가용 7 GiB 이상을 요구함. 학습 전체 4시간, 실제 checkpoint 확인 15분 상한임. 작업자 호출·Colab 할당·유료 API는 이번 학습에 사용하지 않음.

입력 토큰·state에서 후보 제거·가족 분할·손실 기울기·상태 가중치를 실행 전에 검사함. 결과에는 실제 adapter·head·optimizer·학습 노출·내부 검증 예측·바깥 train/held 예측·특징·환경·시간을 저장함. 저장 특징의 독립 계산과 실제 바깥 checkpoint의 예측 확인을 구분함. 무제한 모델 탐색이나 매번 새 clone 검산으로 범위를 늘리지 않음.

```bash
python -m training.memory_selector.train_memory_direct_ranking \
  --data datasets/memory_ranking/20261110-v1 \
  --output runs/memory-direct-ranking-20261110-v1/training
```

위 명령은 GPU 학습 환경을 요구하고 GPU를 실제 사용함. 이번 회차의 실행 환경은 이전 로컬 학습의 `runs/memory-state-ablation-20261109-v1/environment/bin/python`임.

이 비교 이후에는 기존 train의 수정 이력·현재 상태 분기 대조를 소수 검토함. 세 조건 선별을 영구 제외 규칙으로 사용하지 않으며, 손해·쉬운 성공·전체 실패의 일부도 점검함. dev 20·test 40은 설계 탐색에서 사용하지 않음.

## 실제 결과: 주 비교

기존 12가족·96상태의 바깥 분할 예측을 합침. 각 행의 두 수치는 초기값 731/1729 순서이며, 두 초기값을 독립 과제로 합산하지 않음. 작업자 결과는 기존 실행에서 조회한 값이며 이번 학습에서 새 작업자를 호출하지 않음.

| 선택 | 성공 /96 | 순위 정확도 /177쌍 | 상태 평균 순위 정확도 |
| --- | --- | --- | --- |
| 무작위 비어 있지 않은 묶음 | 기대값 43.42 | 0.500 | 0.500 |
| binary | 51 / 50 | 0.684 / 0.712 | 0.683 / 0.662 |
| binary_rank | 46 / 51 | 0.667 / 0.706 | 0.677 / 0.686 |

관측 후보의 사후 최선은 비어 있지 않은 묶음만 고르면 57/96, 무기억까지 허용하면 58/96임. 순위 177쌍은 28상태·10가족에서 나온 상관된 비교이며 독립 표본 177개가 아님. 전체 성공의 분모는 96상태·12가족임.

긴 묶음을 넘고 참조 규칙에 접근하려던 진단 목표를 통과하지 못함. 네 학습 정책 모두 규칙이 실패한 상태를 추가로 해결한 경우는 0이며, 규칙이 성공한 상태 중 각각 4·5·9·4개를 놓침. 기존 4범주 실험과는 출력·배치·학습 길이도 달라졌으므로 이전 대비 상승을 순위 손실 하나의 효과로 해석하지 않음.

순위 손실 추가의 이득도 일관되지 않음. 같은 초기값의 binary 대비 순 변화는 −5상태 / +1상태임. 가족 단위 탐색적 bootstrap 95% 구간은 각각 −10.4~0.0%p / −5.2~+7.3%p임. 12가족의 재사용 진단이므로 확증적 유의성 검정이나 외부 일반화의 근거로 사용하지 않음.

## 학습 적합과 보류 판단

바깥 학습 자료의 순위 정확도는 binary 0.964–1.000, binary_rank 0.982–1.000임. 모든 바깥 적합에서 학습 상태의 관측 최선 묶음을 선택했음. 내부 6회 적합도 마지막 epoch의 학습 순위를 모두 맞혔음. 따라서 이번 결과는 단순히 작은 학습 자료도 전혀 맞히지 못하는 상태와 다름. 학습 적합과 보류 가족의 성적 차이가 크며, 과적합·좁은 출처·작업자 실패의 예측 어려움을 이 한 비교로 분리할 수 없음.

내부 검증이 선택한 epoch는 binary가 fold 0/1/2에서 8/24/8, binary_rank가 16/16/16임. 같은 선택 규칙으로 정한 두 학습 절차의 비교임. 업데이트 수를 맞춘 순수 손실 제거 실험으로 부르지 않음.

별도로 학습한 무기억 성공 점수와 비교해 보류하는 보조 정책은 다음과 같음.

| 조건 | 항상 제공 성공 | 별도 무기억 점수와 비교한 성공 | 제공 상태 /96 |
| --- | --- | --- | --- |
| binary, 731 | 51 | 50 | 66 |
| binary, 1729 | 50 | 50 | 65 |
| binary_rank, 731 | 46 | 44 | 62 |
| binary_rank, 1729 | 51 | 40 | 46 |

두 점수를 그대로 비교하는 정책을 채택하지 않음. 특히 순위 목표가 포함된 점수는 후보 간 순서와 별개로 절대 크기가 달라질 수 있으며, 서로 보정된 성공 확률이라는 근거가 없음. 직접 관측한 것은 보류 정책의 회귀이며, 점수 보정 문제만이 원인이라고 확정하지 않음.

## 구체적인 실패와 비용

`0c5cca3797145f2f--case-1--changed`는 Clara의 2일차 저녁 가격과 Iris의 4일차 숙소 가격을 비교 기준으로 삼음. 참조 규칙은 두 기록 112토큰을 전달해 성공함. 초기값 731의 두 학습 조건은 이 두 기록에 Iris의 다른 날짜 숙소 두 개를 더한 234토큰 묶음을 골랐고, 그 실행은 실패함. 필수 기록을 모두 포함하는 것과 실제 작업 성공이 같지 않은 사례임. 추가 기록이 어떤 내부 추론을 유발했는지는 이 출력 비교만으로 확정하지 않음.

항상 제공한 네 학습 정책의 전달 기억은 14,627–16,992토큰, 참조 규칙은 10,215토큰임. 96상태의 모든 후보를 점수화할 때 선택기 입력은 448,340토큰, 기록된 forward 시간 합은 27.0–27.9초임. 별도 무기억 점수까지 계산하면 534,368토큰·33.9–34.7초임. 로컬 RTX에서 배치별 시간을 나눈 값이며 로딩·CPU 무기억 head의 별도 지연을 포함한 실시간 종단 비용이 아님. 기존 L4 작업자 시간과 합쳐 실시간 속도 향상으로 주장하지 않음.

이번 제한된 두 학습 절차 비교는 여기서 종료함. 같은 자료에서 손실 가중치나 새 구조를 추가 탐색하는 대신, [상태별 수집 파일럿](2026-11-11-memory-state-screen.md)에서 필요한 기억의 변화와 작업자 활용 가능성을 먼저 확인함.

## 완료·검산과 재현

실행 전 동결 커밋은 `57d1e04`임. 내부 6회·바깥 12회 LoRA와 상태 단독 무기억 head 6개를 저장함. 로컬 학습은 13,055.8초(약 3시간 38분)로 4시간 상한 안에 완료함. 실제 가중치 감사는 127.1초임. 이 회차의 새 작업자 호출과 Colab 할당은 0임.

- CPU에서 36개 train/held 분할의 저장 특징·head를 재계산해 6,528개 예측과 6개 내부 epoch 선택을 검산함. 입력 토큰 480개 문자열의 일치와 encode/decode 원문 일치도 확인함. 라이브러리의 tokenizer regex 경고가 있었으나 고정 토큰화는 변경하지 않았으며, 경고의 원인을 해결했다는 주장은 하지 않음.
- 실제 바깥 checkpoint 12개를 다시 로드해 보류 후보 1,632개의 특징·점수·선택을 확인함. 모델별 adapter tensor 112개·optimizer state 116개·step 수·초기 head/adapter를 검산함. 내부 checkpoint의 독립 모델 순전파는 수행하지 않음.
- [공유 묶음](../../evaluation/results/memory-direct-ranking-20261110-v1/README.md)은 예측·저장 특징·head·학습 곡선·출처·가중치 감사 보고서를 포함함. base/adapter 전체 가중치와 optimizer는 로컬 원본에 보존하고 Git 공유 묶음에서는 제외함.
