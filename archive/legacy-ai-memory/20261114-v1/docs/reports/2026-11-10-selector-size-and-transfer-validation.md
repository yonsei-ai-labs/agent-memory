# 기억 선택 모델 크기 비교 및 외부 전이 검증

현재 학습 개선이 Qwen3.5-4B·9B보다 일반적으로 낫다는 근거는 확인되지 않았음. **같은 작업자의 여행 결과에서는 최근 작은 득실 선택기가 40–43/96, Qwen 4B가 56/96, 9B가 54/96 성공함.** 별도의 외부 검색 평가에서도 이전 여행 검색 LoRA는 고정 Harrier보다 주석된 근거를 덜 확보함. 두 LoRA는 서로 다른 checkpoint·학습 목표이므로 하나의 모델 결과로 합치지 않음.

4B와 9B 사이의 작은 차이를 일반적인 크기 우열로 해석하지 않음. 두 모델 모두 직접 응답 모드의 같은 입력·후보·예산으로 실행했으며, 여행은 이미 개발에 사용한 12가족, 외부는 공통 BM25 후보 안의 근거 선택 평가임. [공유 결과 및 CPU 재현](../../evaluation/results/memory-selector-validation-20261110-v1/README.md)에 저장 예측을 보존함.

## 실행 전 고정한 질문

- 기존 개선이 Qwen3.5-4B·9B를 **기억 선택기**로 사용했을 때도 경쟁력이 있는지 확인함.
- 여행에 학습한 검색 LoRA의 개선이 다른 대화 출처에도 유지되는지 확인함.
- 새 학습 없이 기존 가중치를 고정함. 여행의 효용 판독기와 검색 LoRA는 다른 실험의 모델이므로 결과를 합쳐 하나의 모델 성능으로 부르지 않음.

## 두 평가

1. 여행의 기존 96상태에서 같은 408개 비어 있지 않은 묶음과 96개 무기억 행동을 사용함. Qwen이 선택한 행동을 같은 고정 작업자의 저장된 504개 결과에 연결함. 성공·악화·불필요한 전달·선택 비용을 측정함. 이 12문제군은 이미 개발에 사용한 자료로 새 출처 평가가 아님.
2. [LongMemEval의 정제된 S 자료](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned)의 500문항을 평가 전용으로 사용함. 질문만으로 전체 이력의 발화 조각을 BM25 검색하여 후보 8개를 만들고, 같은 후보에서 상위 4개를 비교함. 개별 조각은 날짜·화자를 포함하여 최대 256 Qwen 토큰, 전달 예산은 최대 1,024토큰임. 정답 근거를 후보에 강제로 넣지 않음.

외부 비교는 BM25, 고정 Harrier, 기존 검색 LoRA, Qwen 4B, Qwen 9B임. 모든 작은 모델에 같은 범용 검색 지시문을 사용함. 입력에는 질문·날짜·실제 발화만 포함하며 정답·정답 대화 ID·정답 발화 표시·질문 유형·보류 정답은 제외함.

Qwen은 BF16·SDPA·탐욕적 디코딩·추론 모드 끔을 주 비교로 사용함. 실행 전에 해시로 고른 여행 8상태·외부 16문항에서는 추론 모드 켬(최대 1,024출력 토큰)과 후보 역순 진단을 추가함. 제한된 추론 예산의 결과를 모델의 최대 능력으로 해석하지 않음. 형식 오류·한도 도달도 보존하며 유리한 재시도를 하지 않음.

## 무엇을 주장할 수 있는가

- 외부 평가는 공통 후보 안의 선택 평가임. 전체 이력 검색의 누락을 후보 근거 확보율로 별도 보고함.
- 외부 자료에서 검색 LoRA를 전체 이력의 후보 생성기로 실행하지 않았음. 공통 후보 통제를 위해 고정 BM25 후보 안의 cosine 순위로 평가함. 원래 여행 실험의 hybrid 검색·별도 판독기 전체 시스템과 동일한 평가가 아님.
- 정답 세션을 찾았는지와 정답이 표시된 발화의 **모든 문자 범위**를 확보했는지를 따로 측정함. 일부 조각만 고르고 완전한 근거로 집계하지 않음. 두 지표 모두 의미적 충분성이나 최종 답변 성공의 정답은 아님.
- 답할 수 없는 30문항은 긍정 근거 확보율의 분모에서 제외하고 Qwen의 충분성·보류 판단을 별도 집계함. 고정 상위 4개 검색기는 보류 정책이 없으므로 보류 능력을 주장하지 않음.
- 외부 자료의 실제 작업 성공·메모리 득실·공식 LongMemEval QA 점수는 이번 평가로 알 수 없음. 여행의 실제 작업 결과와 외부 선택 지표를 분리함.
- 새 출처는 프로젝트의 추가 학습 자료와 분리되지만, 기반 모델의 사전 학습에 LongMemEval이 포함됐는지는 확인할 수 없음. 실제 에이전트의 순차 진행·실패 이력 효과를 검증하는 실험도 아님.
- Qwen은 묶음을 함께 읽고 직접 선택하며, 작은 효용 모델은 개별 후보 점수를 사용함. 실용적인 시스템 비교이지 모델 크기만 바꾼 구조 통제 실험은 아님.
- Qwen은 전용 Colab L4, Harrier는 원래 transformers 4.57.6 환경의 로컬 4080 SUPER를 사용함. 서로 다른 하드웨어의 시간을 직접 배수로 비교하지 않음. Colab은 종료·회수 처리를 포함한 3시간 상한으로 제한함.

## 실행 전 자료 점검

500문항 중 76문항의 원본 이력에 질문 시각보다 늦은 세션이 발견됨. 44문항·75개 정답 세션에도 해당함. 모두 같은 날짜 안의 시각 차이이며 미래 **날짜**의 세션은 0개임. 이를 일괄 삭제하고 기존 정답을 유지하지 않음. 원본 500문항 평가와, 이력이 질문 시각 이하인 424문항의 결과를 별도로 보고하기로 **모델 실행 전에** 정함. 이 자료를 시점이 검증된 실제 과거 경험으로 부르지 않음.

공통 후보 8개는 답할 수 있는 470문항 중 정답 세션 전체를 369문항, 정답 표시 발화 전체를 286문항에서 포함함. 실제 후보의 4,000개 문자 범위를 원본과 대조했고, Qwen 4B·9B 토크나이저가 동일함을 확인함. 최대 입력은 여행 2,539토큰·외부 2,119토큰으로 잘림 없이 실행 가능함.

## 외부 출처의 근거 선택 결과

같은 BM25 후보 8개에서 상위 4개를 선택함. 주 지표의 분모는 답할 수 있는 **470문항**이며, 답할 근거가 없는 30문항은 따로 평가함. 정답이 표시된 발화 전체를 후보 안에 포함한 문항은 286개임. 이 286개는 필요한 조각을 4개 이내로 고를 수 있었음. 이 후보 집합의 한계이며, 자료 전체의 의미적 답변 가능성 상한은 아님.

| 방법 | 주석 발화 전체 확보 / 470 | 정답 세션 전체 확보 / 470 | 시각 일관성 부분집합의 발화 확보 / 401 |
| --- | ---: | ---: | ---: |
| BM25 상위 4개 | 212 (45.1%) | 322 | 179 |
| 고정 Harrier 0.6B | 252 (53.6%) | 343 | 209 |
| 기존 여행 검색 LoRA | 161 (34.3%) | 305 | 148 |
| Qwen3.5-4B 선택 | 274 (58.3%) | 350 | 225 |
| Qwen3.5-9B 선택 | 273 (58.1%) | 349 | 222 |

고정 Harrier가 놓치던 주석 발화를 새로 확보한 문항·기존 확보를 잃은 문항은 4B **27·5개**, 9B **29·8개**임. 여행 검색 LoRA는 **0·91개**임. 같은 문항의 쌍 비교이며 모델 사이의 단순 합계 차이만 보지 않음. 통계적으로 독립인 새로운 에이전트 과제 470개를 확보했다는 뜻은 아님.

근거가 없는 30문항에서 Qwen의 `sufficient=false` 출력은 4B 23개, 9B 27개임. 그러나 이 평가는 공통 상위 4개 선택이므로 충분성 출력으로 전달을 실제 중단하지 않음. 이를 보류 정책의 성공률로 부르지 않음. 답할 수 있는 470문항에서도 각각 159개·232개에 불충분을 출력했으므로 부정 응답 빈도만으로 좋은 신뢰도 판단을 주장할 수 없음.

전체 이력에 답이 있어도 공통 후보 8개나 선택한 4개에는 근거가 부족할 수 있음. 따라서 위 159개·232개를 곧바로 충분성 판단의 오답으로 집계하지 않음. 주석된 발화의 완전 확보 역시 의미적 충분성의 정답과 동일하지 않음.

같은 후보 8개에서 상위 4개를 선택했을 때, 정답 표시 발화를 모두 확보한 문항은 고정 Harrier 252/470(53.6%), 여행 검색 LoRA 161/470(34.3%)임. LoRA가 추가로 확보한 문항은 0개, 기존에 확보하던 것을 놓친 문항은 91개임. 후보에 필요한 발화가 모두 있었던 286문항만 보면 각각 88.1%, 56.3%임.

| --- | ---: | ---: | ---: |
| 사용자 단일 세션 | 64 | 58 | 55 |
| 여러 세션 결합 | 121 | 39 | 24 |
| 선호 | 30 | 8 | 7 |

| 어시스턴트 단일 세션 | 56 | 27 | 26 |

이 지표는 **주석된 발화의 확보율**임. 같은 사실이 다른 발화에 반복되어 있으면 주석 발화를 놓쳐도 답할 가능성이 있으며, 모든 주석 발화를 확보해도 작업자가 틀릴 수 있음. 이를 실제 답변 성공률이나 메모리 득실로 바꾸어 부르지 않음.

실패 사례 `f0e564bc`는 가방과 피부 관리 제품에 쓴 돈의 합계를 묻음. 고정 Harrier는 실제 지출 $800·$500이 적힌 사용자 발화를 각각 4위·1위에 배치함. LoRA는 이를 8위·5위로 내리고 일반적인 예산·피부 관리 조언을 상위에 올렸음. 주제는 관련되지만 필요한 사실이 빠지는 구체적인 사례임.

성능 하락 확인 후 실시한 **사후 진단**을 주 비교와 분리함.

- 원래 여행 평가의 8출처에서 해시로 고른 8질문을 같은 실제 adapter로 다시 계산함. 734개 표현의 이전 벡터와 최소 cosine은 0.999908, 상위 10개 집합은 8/8 동일함. 전체 순위는 1/8만 정확히 같으므로 이전 전체 성과를 완전히 재현했다고 부르지 않음. GPU·torch 버전 차이가 있는 수치 재실행임.
- 원래 학습의 여행 전용 지시문으로 외부 질문만 다시 인코딩함. 정답 표시 발화 완전 확보는 고정 Harrier 243/470, LoRA 165/470임. 지시문 변경만으로 주 비교의 하락을 설명하기 어려움. 이 결과로 주 지시문이나 모델을 사후 선택하지 않음.
- LoRA는 상위 4개 중 어시스턴트 발화를 더 많이 선택함(568→903/2,000조각). 평균 전달 조각 길이도 121.6→148.0토큰으로 늘어남. 이는 관측된 변화이며 성능 하락의 원인을 증명하는 제거 실험은 아님.

## 같은 작업자에서의 선택 결과

후보를 선택하는 모델만 바꾸고 실제 작업자는 기존에 측정한 고정 9B로 유지함. 같은 96상태·408개 비어 있지 않은 묶음·96개 무기억 행동의 결과를 사용함. 새로운 작업자 호출은 없으며 각 상태–행동의 한 번의 저장된 greedy 결과에 선택을 연결한 값임. 반복 실행의 평균 효과나 전체 MemoryArena 성능이 아님.

| 전달 정책 | 작업 성공 / 96 | 입력 계약 준수 / 96 | 무기억 성공을 악화 | 기억 제공 / 96 | 전달 토큰 합계 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 무기억 | 33 | 19 | 0 | 0 | 0 |
| 고정 4개 | 52 | 52 | 3 | 96 | 21,343 |
| 학습 검색 상위 2개 | 55 | 55 | 2 | 96 | 10,495 |
| 현재 상태 참조 규칙 | 55 | 55 | 1 | 48 | 5,166 |
| 최근 작은 득실 선택기: 네 조건·두 초기값 | 40–43 | 28–40 | 4–5 | 92–95 | 12,064–14,763 |
| Qwen3.5-4B 선택 | 56 | 54 | 2 | 94 | 13,427 |
| Qwen3.5-9B 선택 | 54 | 53 | 3 | 95 | 13,160 |

작은 선택기의 범위는 지표별 최솟값·최댓값이며 하나의 실행이 모든 최솟값을 동시에 가진다는 뜻이 아님. [기존 네 조건·두 초기값의 전체 결과](2026-11-10-memory-refreshed-learning.md)를 그대로 유지함.

4B 선택기의 96상태 결과는 작업 성공 56개, 입력 계약 준수 54개임. 무기억보다 개선 25개·악화 2개이며, 근거를 준수하던 무기억 성공을 망친 경우는 1개임. 여기서 입력 계약 준수는 전달된 근거로 맞게 답하거나, 필요한 근거가 없으면 `UNKNOWN`으로 보류하는 것을 뜻함. 정답 문자열 일치와 다른 지표임.

4B는 94/96상태에서 기억을 제공함. 필요한 정보가 이미 현재 관측에 있는 `visible` 24상태에도 모두 제공했으며 성공은 무기억과 같은 19/24임. 상태별로는 개선 1개·악화 1개가 상쇄됨. 필요한 근거가 은행에 없는 `missing` 24상태에서는 22회 제공했지만 성공 0개임. 검색·선택만으로 없는 근거를 되찾을 수는 없음.

9B도 `visible` 24상태에 모두 기억을 제공했고 성공 19/24, 개선 1개·악화 1개임. `missing`에서는 23회 제공했으나 성공 0개임. 전체 무기억 대비 개선 24개·악화 3개이며, 근거를 준수하던 무기억 성공을 악화한 것은 1개임. 큰 모델도 이 입력·지시에서 불필요한 제공을 충분히 줄이지 못함.

사례는 `visible` 중 상태 ID가 가장 앞선 `015f64adf40542a3--case-0--visible`로 고정함. 요청은 Jacob의 3일차 식당과 Ben의 3일차 숙소이며, 현재 관측에 이미 각각 `R577`·`H1087`이 명시되어 있음. 4B·9B 모두 같은 두 사실을 다시 적은 `C3` 묶음을 선택함. 지시문에도 이미 아는 사실을 고려하고 도움이 될 기억이 없으면 빈 묶음을 고르도록 되어 있었음. 관련 기록을 찾는 판단과 새로 필요한 정보를 고르는 판단의 차이를 보여주는 사례이며, 하나의 사례로 모델의 내부 원인을 설명하지 않음.

작은 효용 선택기의 네 학습 조건·두 초기값을 모두 비교하며 가장 좋은 실행만 고르지 않음. 기존 결과를 이번에 다시 CPU 검산하여 8,424개 저장 판독값·3,264개 실제 가중치 재검사 기록·504개 작업자 라벨의 연결을 확인함. 이번 검산에서 신경망 순전파를 다시 수행한 것은 아님.

## 형식과 추가 추론의 진단

주 비교의 엄격한 판독 규칙을 결과를 보고 변경하지 않음. 4B 직접 응답에서는 596개 중 형식 오류가 4개였음. 여행 1개는 선택 ID 대신 `NONE`을 썼고, 외부 3개는 요청한 전체 8개 순위 대신 유효한 상위 4개만 썼음. 오류 시 여행은 무기억, 외부는 빈 선택으로 처리하는 고정 규칙을 적용함.

사후 민감도 진단에서는 명시적인 `NONE`과 중복 없는 유효한 4개 ID만 별도로 인정함. 4B의 외부 주석 발화 완전 확보가 274→276/470으로 변하고 여행 성공은 같음. 끝나지 않은 추론에서 ID를 찾아내거나 없는 답을 보충하지 않음. 이 진단으로 주 결과를 교체하지 않음.

실행 전 고른 24문항에서 4B 추론 모드의 23개가 1,024출력 토큰 한도에 도달하여 완결된 응답을 내지 못함. 유효 응답은 1/24이며 추론 시간은 약 25.8분임. 이는 **이 출력 예산에서의 실행 가능성** 결과이며 추론 모델의 최대 능력이 낮다는 증거가 아님.

같은 24문항의 후보를 역순으로 제시한 4B 진단에서는 선택 출력이 18개 바뀜. 선택 ID 집합이 바뀐 것은 15개, 같은 ID의 순서만 바뀐 것은 3개임. 외부의 주석 발화 완전 확보는 7/12→7/12, 여행 성공은 6/8→5/8임. 일부 변경은 불필요한 추가 기록이나 순서 차이이므로 모든 변경을 오답으로 집계하지 않음. 작은 사전 지정 부분집합의 진단임.

9B 주 비교 596개는 형식 오류·출력 한도 도달이 모두 0개임. 추론 진단 24개는 모두 1,024토큰에 도달하여 유효한 최종 응답을 내지 못했으며 생성 시간은 약 29.7분임. 이 예산으로는 해당 추론 모드를 평가하기 어려웠음. 형식 실패 시 무기억으로 처리하므로 여행 성공이 4/8로 나와도 이를 실제로 좋은 보류 결정을 내린 결과로 해석하지 않음.

9B 후보 역순 진단 24개는 모두 유효했음. 출력이 바뀐 것은 16개이며, 집합 변경 15개·같은 집합의 순서 변경 1개임. 외부 완전 확보는 7/12→7/12, 여행 성공은 6/8→6/8로 같음. 총점이 같아도 선택한 추가 기록과 순서에는 민감성이 남음.

## 실행 복구와 재현 범위

입력·모델 revision·후보·프롬프트·판독·예산은 모델 실행 전 커밋 `8c2f22c`로 고정함. 첫 L4 실행은 서버의 런타임이 사라져 중단됨. 원인은 확정하지 않음. 종료 요청은 이미 사라진 세션에 대해 404를 반환했으나, 이후 서버 세션 목록과 할당 수 0을 별도로 확인함. 첫 실행의 마지막 진행 로그는 497번째 응답이지만 회수된 원시 예측은 384개뿐임.

재실행은 추론 설정·입력·코드를 유지한 채 전체 문항을 다시 수행함. CLI의 노트북 WebSocket 연결도 실제 코드 실행 전에 실패하여, 같은 소유 런타임의 기존 노트북 커널에 실제 bootstrap 작업을 전달함. 연결 방식만 바꿨으며 유휴 상태를 가장한 동작은 사용하지 않음. 두 실행에서 회수된 384개 겹치는 응답의 입력 토큰·출력 토큰·판독이 모두 일치함. 첫 실행 예측은 주 결과에 합치지 않음.

따라서 주 비교·진단의 계획된 1,288호출을 이번 전체 GPU 실행 횟수로 보고해서는 안 됨. 첫 시도의 회수되지 않은 완료 응답도 있으며, 그 시도는 별도 실행 비용임. 실패 기록·회수된 첫 예측·실제 업로드 파일·종료 기록과 원래 결과 ZIP의 해시를 공유 묶음에 보존함. 계정 잔액은 공유 로그에서 제외함.

저장 토큰·벡터 검산과 실제 GPU 순전파 재실행은 구분함. 공유 묶음에는 검색 LoRA adapter를 포함하되 기반 모델 가중치를 포함하지 않음. 최근 득실 선택기 24개의 adapter·optimizer는 [기존 전체 검토 묶음](../../evaluation/results/memory-refreshed-learning-20261110-v1/README.md)의 위치·해시를 따름.

최종 재실행은 주 비교 1,192개·진단 96개를 모두 완료하고 다운로드·종료를 마침. 재실행 제어 시간은 114.2분이며, 첫 할당부터 최종 종료까지 약 142분으로 원래 180분 상한 안임. 서버 목록에서도 이번 L4가 남아 있지 않음을 확인함. 같은 계정의 다른 A100 세션은 이번 작업의 종료 대상이 아님.

## 연구 방향에 대한 판단

작은 선택기가 무기억보다 나아졌다는 것만으로 학습의 필요성을 입증하기 어려움. 현재 자료에서는 단순 참조 규칙이 55/96 성공하며 제공 횟수와 전달량이 훨씬 적음. 큰 모델과 비교해도 최근 학습 선택기가 뒤처지므로, 새 손실의 분류 성적을 범용 선택 개선으로 발표하는 것은 부적절함.

고정 Harrier는 외부 공통 후보에서 252/470을 확보하므로 작은 기반 모델 자체가 작동하지 않는 상황은 아님. 이전 검색 LoRA가 여행에서 좋아진 점과 외부에서 악화한 점을 함께 보존해야 함. 현재 진단만으로 데이터 부족·학습 목표·입력 구조 중 하나를 단독 원인으로 정할 수는 없음.

처음의 메모리 득실 연구와의 연결은 유지됨. 필요한 사실의 확보, 현재 상태에서 추가 정보의 필요성, 충분한 근거를 받은 작업자의 성공이 서로 다름을 측정했음. 다음 판단은 기존 선택기의 같은 상태 내 올바른 묶음·비슷하지만 틀린 묶음의 순위와 불필요한 제공을 점검하는 데 두고, 방법을 정한 뒤 **새 출처의 실제 득실**로 확인하는 것이 적절함. 이번 외부 근거 선택 점수를 최신 득실 선택기의 새 출처 효용 검증으로 대체할 수 없음.
