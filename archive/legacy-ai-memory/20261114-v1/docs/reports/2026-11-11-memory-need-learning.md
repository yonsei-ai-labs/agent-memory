# 기존 검색·판독을 상태별 기억 선택으로 연결한 결과

2026-11-11 완료. **새 확인 6가족·36상태에서 목표만 학습한 선택기는 24회, 현재 상태까지 학습한 선택기는 36회 작업에 성공함. 두 학습 seed에서 같았음.** 상태 선택기의 전달 기억은 2,802→1,904토큰으로 32.0% 감소함. 작업자는 같은 Qwen3.5-9B, 검색기·기억 은행·전달 상한도 동일함.

현재의 명시적 상태 규칙도 36회 성공함. 이번 성과는 기존 검색·판독에 **상태 대조 데이터와 필요성 감독을 결합해 실제 작업 개선까지 연결했다는 점**임. 신경망이 규칙보다 필요하거나 우수함을 입증한 결과는 아님.

[공유 예측·가중치·검산](../../evaluation/results/memory-need-20261111-v1/README.md), [데이터](../../datasets/memory_need/20261111-v1/README.md), [사전 선택한 출처](../../datasets/memory_need_sources/20261111-v1/README.md), [학습 코드](../../training/memory_selector/train_memory_need.py)를 함께 읽음. 사전 계획은 공유 archive의 `pre-execution-plan.md`, `pre-training-plan.md`, `pre-worker-plan.md`와 해시로 보존함.

원래 train 파일럿 12가족과 이번 생성 24가족을 합쳐 원래 train 60가족 중 36가족을 사용함. 제외한 1가족도 관찰한 출처이며, 남은 train은 24가족임. 원천 dev 20·test 40은 사용하지 않음. 이번 개발·확인 6/6가족은 원래 train 내부의 별도 분할임.

## 학습과 선택 평가

Harrier 0.6B의 기존 여행 판독 LoRA와 MLP에서 시작함. 검색 LoRA는 고정하고 두 조건에 같은 목표 기반 후보를 제공함. 후보에 정답을 강제로 삽입하지 않았으며 확인 자료에서 필요한 기록 36개가 모두 후보 안에 있었음.

`goal`은 목표·기록, `state`는 여기에 공개 진행 문장과 이미 관측한 사실을 추가함. 전체 카탈로그는 작업자에게 유지함. 두 조건의 지시문·초기 가중치·손실·학습률·후보·전달 임계값은 같음. 상태별 양성·음성 평균을 균형화한 분류 손실을 사용하고, 모두 음성인 이미 충분한 상태도 학습함. 실제 작업 성공 라벨은 학습에 사용하지 않음.

seed 731/1729, 8epoch, 학습 상태당 최대 16후보, 평가 최대 32후보임. head 학습률 0.001·adapter 0.0001, 점수 0.5 이상에서 예산 내 선택함. 개발 평가 2/4/8epoch에서 정확한 필요 집합→근거 Recall→적은 추가 기록→이른 epoch 순으로 선택함. 목표 모델은 두 seed 모두 2epoch, 상태 모델은 모두 8epoch를 선택함. 확인 성적을 보고 재학습하거나 임계값을 바꾸지 않음.

| 확인 자료의 선택 정책 | 필요 집합 정답 /36 | 두 상태 모두 정답 /12쌍 | 이미 충분한데 제공 /12 |
| --- | ---: | ---: | ---: |
| 기존 동결 목표 판독기 | 6 | 0 | 12 |
| 동결 판독기 + 새 상태 입력 | 3 | 0 | 12 |
| 목표만 추가 학습, 두 seed | 12 / 12 | 0 / 0 | 12 / 12 |
| 상태까지 추가 학습, 두 seed | **36 / 36** | **12 / 12** | **0 / 0** |
| 항상 보류 | 12 | 0 | 0 |
| 목표 참조 규칙 | 12 | 0 | 12 |
| 공개 상태 규칙 | 36 | 12 | 0 |

동결 상태 진단은 state 학습 조건과 같은 입력·0.5 임계값을 사용함. 기존 동결 목표 정책은 원래처럼 예산 안에서 기록을 채움. 따라서 두 동결 조건 간 차이를 상태 입력 하나만의 효과로 해석하지 않음. LoRA와 head를 함께 갱신했으므로 adapter만의 기여도 분리하지 않음.

## 실제 작업의 이득·손해

고정 작업자 Qwen3.5-9B에 동일한 공개 현재 상태를 제공하고 전달 기억만 바꿈. 이미 확인한 항목 대조는 1기록·128토큰, 실패 분기 대조는 2기록·256토큰 상한임. 같은 상한이며 실제 전달량까지 같게 강제하지 않음.

8정책×36상태의 288결정을 147개 고유 메시지로 묶어 실제 실행하고 2개를 반복함. 같은 메시지의 결과를 공유한 것이므로 288개 독립 실행이나 두 seed의 72개 독립 상태로 세지 않음.

| 전달 정책 | 전체 성공 /36 | 기억이 필요한 대조 /24 | 이미 충분한 상태 /12 | 무기억 대비 개선 / 악화 | 기억 토큰 합계 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 무기억 | 12 | 0 | 12 | 0 / 0 | 0 |
| 기존 동결 목표 판독기 | 16 | 6 | 10 | 6 / 2 | 2,877 |
| 목표만 추가 학습, 두 seed 동일 | 24 | 12 | 12 | 12 / 0 | 2,802 |
| 상태까지 추가 학습, 두 seed 동일 | **36** | **24** | **12** | **24 / 0** | **1,904** |
| 필요한 근거 / 공개 상태 규칙 | 36 | 24 | 12 | 24 / 0 | 1,904 |
| 반대 상태의 기억 | 9 | 0 | 9 | 0 / 3 | 2,847 |

성공한 출력은 모두 필요한 근거도 확보한 상태였음. 목표 학습 대비 상태 학습의 추가 성공 12건은 기억이 필요한 대조에서 발생함. 두 학습 조건 모두 이미 충분한 12상태에서는 성공했으므로, **목표 학습 대비 손해를 줄였다고 주장하지 않음.** 상태 학습은 여기서 추가 기억을 모두 보류해 전달량을 줄였음.

별도로 기존 동결 정책은 이미 충분한 상태에서 2건, 반대 상태 기억은 3건의 성공을 깨뜨림. 필요한 사실이 현재 모두 보여도 추가 기억으로 작업자가 틀릴 수 있음을 다시 관측함. 관련성이 없거나 중복이라는 이유만으로 모든 기억에 유해 라벨을 붙이지 않음.

사례 `02ff3f411332bea2e5e6cd62`에서는 Iris의 2일차 숙소가 현재 이미 보임. 목표 모델은 숙소 기록을 다시 전달해 저녁을 해결하지 못했지만 상태 모델은 저녁 기록을 골라 두 답을 모두 맞힘. 사례 `3af64b4b7e7480980b61768f`에서는 실패 후 사용할 Alice의 두 선택이 이미 보임. 기억 없이 성공했지만 과거 Clara 계획을 추가하면 잘못된 계획으로 돌아감. 상태 모델은 보류했고 성공을 유지함. 전체 정책·원문은 archive의 `utility-evaluation/case-examples.json`에 있음. 사후 설명용 범주마다 state_id 순 첫 사례를 선택했으며 학습에 되돌려 쓰지 않음.

## 비용과 검산

목표 학습의 54기록·2,802토큰이 상태 학습에서 36기록·1,904토큰으로 줄어듦. 판독 forward는 확인 36상태 합계 약 11.4–12.7초이며 RTX 4080 SUPER에서 배치로 측정함. 토큰화는 포함하지만 모델 로딩·공통 검색·인덱스 구축·네트워크 등은 제외함. 작업자 시간은 별도 L4에서 측정했으므로 이를 서비스 지연 개선으로 주장하지 않음. 규칙도 같은 성공을 내므로 선택기의 비용 대비 필요성은 아직 입증되지 않음.

- 저장 특징·head로 **25,056예측**을 재계산함. 최대 logit 오차 1.55×10⁻⁶ 미만임. 후보 순위·개발 checkpoint 선택·학습 노출·출처 분할도 검산함.
- 선택된 **실제 가중치 4개·확인 예측 4,368개**를 GPU에서 다시 실행해 일치함을 확인함. 각 모델의 adapter 112 tensor 변화와 optimizer 116개 상태·업데이트 수를 확인함. 이 검산은 추가 학습을 하지 않음.
- 과거 생성 74개, 작업 평가 149개의 실제 입력·출력 토큰을 검산함. 각 단계의 반복 2개는 원 출력과 같았고 토큰 한도 종료는 없었음. 두 반복만으로 작업 성공 확률의 불확실성을 추정하지 않음.
- 공유 묶음은 전체 저장 점수와 **확인 특징 6,552개**를 CPU로 검산할 수 있음. 초기·선택 adapter/head도 포함함. 전체 base 가중치·optimizer는 로컬 원본에 남김.

커밋 `fdd0754`의 공유 파일만 새로 clone하여 위 CPU 검산·데이터 품질 검사·관련 테스트 6개·초기 adapter 복구를 통과함. 기존 74행·444저장 예측 검사도 통과했고 clone 작업 트리는 그대로였음. 무시된 로컬 원본 없이 실행했으며 새 GPU 추론은 하지 않음. [명령과 실제 출력](../../evaluation/results/memory-need-20261111-v1/fresh-clone-verification.json)을 보존함. 전체 로컬 평가 테스트 167개·학습 테스트 197개 통과는 이 새 clone의 제한된 검사와 구분함.

학습 4회를 완료했으며, 대화 중단으로 두 번째 seed의 목표 학습 1epoch 이후 프로세스가 사라진 부분 시도 1회도 보존함. 완료한 모델은 유지하고 미완료 fit만 동일 초기값·seed로 재시작함. 첫 epoch 손실도 중단 전과 동일했음. 전체 벽시계 2,917.9초에는 중단 시간이 포함되며 원래 90분 상한을 늘리지 않음.

중단 당시 RAM에 있던 입력 토큰 목록은 고정 입력·tokenizer로 재구성함. 이를 당시 저장된 실행 추적으로 부르지 않음. 실제 가중치 순전파 검산은 별도임. `confirmation_labels_read=false`는 확인 정답을 파싱해 학습·개발 계산에 사용하지 않았다는 뜻이며 파일 무결성 해시는 검사함.

생성 호출은 과거 72·현재 147·반복 4, 합계 223회임. 외부 유료 모델 API 호출은 없으며 Colab L4 두 세션을 사용함. 두 세션 모두 결과 회수 후 종료했고 서버에서도 해당 세션이 없음을 확인함. 계정 사용량 관측에는 다른 할당이 섞일 수 있어 정확한 이 실험 단독 청구량으로 부르지 않음. [자원 기록](../../evaluation/results/memory-need-20261111-v1/resource-accounting.json)을 참조함.

## 해석과 다음 단계

이번에 살릴 부분은 **검증 가능한 과거 사실 → 현재 상태에 따른 필요성 대조 → 실제 제공 효과**의 연결임. 필요성 판단을 잘 학습한 작은 모델이 동일 작업자·은행·예산 상한에서 실제 성공을 높이는 경로를 확인함.

범위는 두 통제 문장 틀과 확인 6가족임. 출처 도시·카탈로그·표현을 공유하며 자연 에이전트 실패 이력, 다른 도메인, 새 문장 틀 일반화는 검증하지 않음. 보류도 이미 충분한 상태에서의 중복 전달 중단이며 은행에 필요한 기억이 없는 상황의 보류와 구분함. 선택이 필요한 상태를 설계한 자료이므로 일반 사용 분포의 평균 득실 추정도 아님. 큰 모델을 선택기로 쓰는 비교나 공식 MemoryArena 점수는 이번 결과에 포함하지 않음.

다음에는 이번 모델·설정·평가를 고정하고, 남겨 둔 출처에서 표현과 진행 이력이 더 다양한 소수 사례를 먼저 검토하는 것이 적절함. 원문 관측·필요 근거·반대 상태를 확인한 뒤 같은 작업자 비교를 적용함. 같은 틀의 행 수를 늘리거나 확인 결과에 맞춰 설정을 더 고르는 확장은 하지 않음.
