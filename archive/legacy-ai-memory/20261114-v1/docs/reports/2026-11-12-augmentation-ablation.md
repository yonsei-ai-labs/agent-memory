# 데이터 보강의 원인 분해: 관계 대조의 추가 효과와 과잉 제공

2026-11-12. 세 조건 × 두 seed의 학습을 완료함. **기록 형식·고유 입력 수·정답 분포를 맞춘 상태에서도, 부분 관측 관계를 함께 학습한 조건이 필요한 기억을 더 잘 보존했음.** 형식 노출 조건의 22·17/48이 관계 대조에서 48·48/48로 개선됐고, 같은 고정 작업자의 필드 복원도 65·63/96 → 88·87/96으로 늘었음. 불필요 제공과 기존 자료의 회귀도 관측되어 함께 보고함.

## 어떤 과제에서 효과를 보였는가

이번 과제는 **현재 알고 있는 정보와 과거 기록을 함께 사용해 요청된 항목을 완성하는 정보 복원**임. 현재 관측에 필요한 정보가 일부 있거나 전부 있는 상황에서, 작은 선택기가 과거 기록 전체를 제공할지 보류할지 결정하고 고정 작업자가 요청 항목을 답함.

예를 들어 서버 템플릿과 설정 크기를 확인해야 하는데 현재 관측에는 `Ubuntu`만 있고, 과거 기록에 `Ubuntu / medium`이 함께 있음. 이때 필요한 것은 설정 크기를 보완하는 기록을 제공하는 판단임. Format 선택기는 일부 중복된 기록 전체를 보류하여 크기를 답하지 못했고, relation 선택기는 같은 기록을 제공하여 두 항목을 완성했음. 측정한 작업은 서버 설정 정보의 복원이며 실제 서버 배포 성공률을 측정한 것은 아님.

전체 96상태 중 현재 관측에 요청 정보가 모두 있는 36상태는 모든 비교 조건에서 성공했음. **정보가 부족하여 과거 기록이 필요한 나머지 60상태**에서는 다음과 같음.

| 전달 정책 / 선택기 학습 | 정보가 부족한 상태의 복원 성공 /60 |
| --- | ---: |
| 무기억 | 0 |
| 단순 추가 학습 | 31 / 35 |
| 형식 노출 | 29 / 27 |
| 관계 대조 | **52 / 51** |
| 전체 제공 / 검색 상위 2개 | 52 |

두 숫자는 seed 731 / 1729 순서임. 이 표는 과제를 설명하기 위한 사후 부분집계로, 원래 고정한 96상태 주 결과를 대체하지 않음. 집계 기준은 고정 `test-labels.jsonl`의 `remaining_fields`가 비어 있지 않은 worker 상태임. 새로운 정답이나 성공 사례만으로 평가 대상을 만든 것이 아님.

**전체 제공과 비교한 가치 판단:** 후속 복원 96상태는 각각 compound 기록 1개를 가진 은행이므로 현재 선택기의 행동은 제공·보류 두 가지임. 저장된 원 출력을 상태별로 짝지으면 둘 다 성공 36, 제공만 성공 52, 보류만 성공 0, 둘 다 실패 8임. 따라서 이 두 행동의 관측 결과에서 매번 사후 최선을 고르더라도 전체 제공과 같은 88/96임. 이는 모든 가능한 작업 방식의 이론적 상한이 아니라 이번 고정 작업자·입력·기록 전체 제공/보류에서 관측된 최선임.

현재 후속 복원 자료에서는 성공률을 통해 별도 선택기의 전체 제공 대비 추가 가치를 입증할 여지가 없었음. 전체 입력 토큰 절감도 약 2.3–2.6%이며 선택기 비용을 포함한 순이득은 입증하지 않음. 그러므로 아래 학습 개선은 상태–기억 대조 자료의 원인 진단 결과로 보존하고, 실용적인 메모리 선택 시스템의 성능 우위로 제시하지 않음. 이 자료에서 같은 성공 지표를 더 높이기 위한 추가 학습을 우선하지 않음.

**논문·발표에서 사용할 중심 주장:** “현재 관측을 고려한 과거 정보 복원 과제에서, 부분 관측 상태와 과거 기억의 관계를 대조하는 학습 자료가 필요한 기록의 잘못된 보류를 줄였음. 같은 모델·학습량·기록 형식·정답 분포의 비교에서 이 개선은 고정 작업자의 복원 성공 63–65/96 → 87–88/96으로 연결됐음.”

기여는 현재 관측에 따라 기억의 필요성이 달라지는 과제를 구성하고, 그 관계 조합의 학습 노출을 통제해 선택 오류와 후속 작업의 변화를 함께 보여준 데 있음. 이 데이터 설계·학습 방법의 효과는 기존 12출처로 구성한 통제 과제에서 실증됨. 전체 제공의 성공 88/96과 과잉 제공 증가도 함께 보고하므로, 모든 기억을 주는 정책보다 작업 성공이 높아졌다는 주장으로 바꾸지 않음.

## 확인한 질문

이전 보강 실험은 단순 추가 학습보다 좋아졌으나, 고유 입력 235개와 395개, atomic과 compound 형식의 차이가 함께 있었음. 이번에는 **형식을 익힌 효과와 ‘같은 기억에 아직 필요한 정보가 남은 상태’를 함께 경험한 효과**를 더 구체적으로 나눔.

| 조건 | 공통 학습 자료 | 달라지는 160항목 | 고유 입력 / 후보 쌍 / 양성 쌍 |
| --- | --- | --- | --- |
| 단순 반복(repeat) | atomic 160상태 + 기존 train anchor 80상태 | 원래 atomic 자료 반복 | 235 / 876 / 330 |
| 형식 노출(format) | 같음 | compound를 사용하되 현재 관측이 없거나 필요한 정보가 모두 알려진 상태 | 395 / 716 / 310 |
| 관계 대조(relation) | 같음 | 같은 compound를 사용하면서 일부만 알고 있는 상태까지 포함 | 395 / 716 / 310 |

모두 30학습 출처 그룹·400상태 항목임. 주 비교는 format과 relation이며, 이 둘은 행마다 원문·기억 본문·요청·후보별 필요성 정답이 같음. 기록 형식과 양성/음성 수, 손실 가중치도 정확히 같음. Format의 80행에서 현재 관측을 제거하되 기억은 여전히 필요하므로 양성 라벨을 유지함. Atomic 공통 자료에는 양쪽 모두 부분 관측이 있음.

반복되는 무관측 항목은 네 가지 동등한 요청 문장으로 구분하고 relation에도 같은 문장을 사용함. 문장 틀별 양성/음성은 각각 25/15로 같아 문구가 라벨을 표시하지 않도록 함. ID 차이는 고유 입력으로 세지 않음.

예를 들어 기억에 상품 ID `7589`와 주문 ID `ORD45678`이 함께 있고 두 값을 요청할 때, format은 현재 관측이 없는 상태를, relation은 상품 ID만 이미 확인한 상태를 제시함. 두 경우 모두 주문 ID가 필요하므로 기록 제공 정답은 같음.

관측의 의미를 바꾸므로 관측 길이까지 완전히 같지는 않음. 두 조건의 전체 선택기 입력 토큰은 67,756과 68,324로 약 0.84% 차이였음. 이번은 부분 관측 조합의 학습 노출을 제거한 통제 비교이며, 모든 표현 증강 방법과의 우열이나 모델 내부의 추론 기제를 입증하는 실험은 아님.

## 학습·평가 조건

- 같은 seed의 기존 single checkpoint에서 Harrier 0.6B·rank-8 q/v LoRA·need 판독층을 계속 학습함. 구조와 손실함수는 바꾸지 않음.
- seed 731/1729, 각 2epoch·200update. 마지막 checkpoint와 임계값 0.5를 고정하고 모든 학습 종료 후 가중치 해시를 고정한 다음 평가함. 임계값·epoch·seed를 평가 결과로 선택하지 않음.
- 기존 12출처의 384상태를 모두 평가함. 이 출처는 학습에는 없지만 **결과를 이미 확인한 기존 평가 자료**임. 새 독립 확인으로 부르지 않음. 같은 출처의 변형 상태도 독립 경험으로 세지 않음.
- 주 지표는 부분 관측 compound 48상태의 기록 보존임. 전체 선택·이미 충족된 상태의 보류·기존 BEAM 회귀도 함께 측정함.
- 작업자는 기존 Qwen3.5-4B이며, compound/prose 96상태에서 정확히 같은 메시지 해시의 저장 답변을 재사용함. 평가한 1,056정책 결정은 192개 고유 원 입력에 연결됨. 새 작업자 호출은 없음.

## 선택과 후속 복원 결과

각 셀은 seed 731 / 1729의 순서임.

| 방법 | 필요 복합 기억 보존 /48 | 남은 근거 완전 확보 /240 | 불필요 제공 기록 | 필드 복원 /96 |
| --- | ---: | ---: | ---: | ---: |
| 단순 반복 | 27 / 30 | 182 / 195 | 11 / 14 | 67 / 71 |
| 형식 노출 | 22 / 17 | 173 / 172 | 5 / 7 | 65 / 63 |
| 관계 대조 | **48 / 48** | **236 / 237** | 11 / 17 | **88 / 87** |
| 전체 제공 / 검색 상위 2개 | 모두 보존 | 모두 확보 | 여과 없음 | 88 |

48과 240은 선택 평가의 서로 다른 하위 집단이고, 96은 compound/prose 후속 작업 부분집합임. 48/48은 전체 판단이 100% 맞았다는 뜻이 아님. 선택 평가 전체의 관계 대조에는 필요 기록 누락 4·3개와 불필요 제공 11·17개가 남았음.

Format 대비 relation의 실제 복원 개선은 seed별 **23건·24건, 새 악화 0건**임. 두 seed 모두 12출처 중 11출처에서 평균 복원이 개선됐고, 나머지 한 출처는 같았음. 두 seed에서 동시에 개선된 상태는 20개임. 동일 메시지는 같은 저장 답변을 공유하므로 이를 독립적인 작업자 반복 실행으로 계산하지 않음.

필요/불필요 분류의 출처별 balanced accuracy는 format 86.5·86.0% → relation 97.5·96.7%임. 전체 후보의 ROC-AUC도 약 0.9748·0.9745 → 0.9945·0.9933으로 개선됨. 0.5에서 제공량이 늘어난 현상과 함께 점수의 분류 구분도도 개선됐음. 이것은 후보별 필요성 분류 지표이며 많은 후보 사이의 검색 순위 성능을 뜻하지 않음.

**해석:** 이 조건에서는 형식 노출만으로 부분 관측 오류가 해결되지 않았고, 해당 관계 조합의 학습 노출이 추가로 도움이 됐음. 형식 대조를 일부러 부분 관측이 없는 조건으로 제한한 제거 실험이라는 범위를 유지함. 실제로 얻은 성과는 더 큰 모델이나 새 손실함수의 효과가 아니라 **어떤 상태–기억 조합을 학습 자료에 포함해야 하는지에 대한 근거**임.

## 사례와 부작용

**개선 — Ubuntu는 확인했지만 서버 크기는 모름.** 같은 과거 기록에 `the Ubuntu template`와 `with a medium configuration`이 있음. 두 format 모델은 기록 전체를 보류하여 `Ubuntu, null`을 답하게 했고, 두 relation 모델은 기록을 전달하여 `Ubuntu, medium`을 복원함. 두 seed의 동시 개선 20상태 중 ID 순 첫 사례이며 사후 설명용 선택임.

**과잉 제공 — 이미 아는 사용자 ID를 다시 전달함.** 요청은 사용자 ID이고 현재 관측에 `abc789`가 있음. 기억에는 알림 ID `XYZ123`와 사용자 ID가 함께 있음. 두 format 모델은 보류했으나 두 relation 모델은 기억을 제공함. 답은 양쪽 모두 맞았지만 불필요한 전달임. 두 seed에서 함께 발생한 해당 형태의 추가 제공 4상태 중 ID 순 첫 사례임.

BEAM에서는 과잉 제공이 늘었음. 이 표는 기존 개발 자료의 관계 판단이고, 새 BEAM 작업자 성공을 측정한 결과가 아님. 모델을 범용 기본 선택기로 교체하지 않음.

전체 제공·검색의 후속 복원은 88/96임. Relation은 같은 수준에 도달하거나 한 건 낮으며 이를 넘었다고 주장하지 않음. 관계 대조의 평균 기억 토큰은 13.05·13.54개로 전체 제공 18.75개보다 약 28–30% 적었지만, 전체 작업자 입력 감소는 약 2.3–2.6%임. 새 온라인 지연이나 실시간 비용 절감을 측정하지 않음.

## 재현과 해석 경계

학습·평가에는 로컬 RTX 4080 SUPER 한 프로세스를 사용했고 약 21.7분에 완료함. PyTorch 최대 할당 메모리는 약 2.40GiB였음. 프로세스 종료와 GPU compute 작업 없음까지 확인함. Colab 할당·유료 API·새 작업자 호출은 없음.

- 데이터·의미 대조 검사 16개 통과. 주 비교의 고유 입력·후보 정답·손실 질량·문장 틀 균형과 출처 격리를 검산함.
- 실제 head·저장 벡터로 후보 예측 11,432개와 두 출력층의 확률을 CPU에서 재계산함. 모든 0.5 판정이 같았음. 여섯 LoRA의 tensor 112개씩에 실제 변화가 있고, 모든 감독 쌍이 정확히 2회 학습됐음을 확인함.
- 1,056정책 결정의 메시지 해시·원 답변·원래 고정 채점을 재계산함. 압축본을 새 임시 폴더에 풀고 가중치·벡터·데이터에서 같은 결과가 나옴을 확인함. 전체 encoder를 CPU에서 새로 실행한 검산은 아님.
- 단순 반복의 후속 복원 67·71/96은 과거 control과 같았음. 다만 seed 731은 기존 예측 576개 중 6개의 0.5 판정이 달랐고, seed 1729는 저장 확률이 모두 같았음. 첫 seed의 최대 확률 차이는 약 0.525였음. 입력·라벨·시작 가중치·부모 학습 코드·패키지 버전은 동일함을 확인했으나 학습의 비트 단위 재현 원인까지 규명한 것은 아님. 과거 수치를 새 비교값으로 대체하지 않고 이번 세 조건을 함께 보고함.
- 정답 문자열의 사후 동의어를 추가하지 않고 원래 고정 채점을 유지함. 전체 제공의 8개 실패 중 표현 차이와 역할 혼동의 구분은 [이전 채점 검토](2026-11-12-partial-record-learning.md)에 있음.
