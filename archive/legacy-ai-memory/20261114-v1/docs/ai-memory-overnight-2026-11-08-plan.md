## 데이터 설계 우선순위

1. 기존 원본 81개 관측의 명령을 재검토한다. 기존 두 범위 선택에서 빠진 세 번째 이상의 **실제 명시된 범위**를 찾는다. 현재 요청/완료 상태를 조합한 자료는 합성 조건이며 실제 에이전트 경험으로 세지 않는다.
2. 조건이 분명한 자료만 포함한다. 현재 요청과의 정확한 범위 일치, 완전한 완료 기록에 같은 범위가 있는지의 두 질문을 유지한다. 검사 명령이 범위를 선택한 사실과 검사가 실제 완료·통과한 사실을 혼동하지 않는다. 기록 부재와 불일치는 다른 라벨이다.
3. 다른 출처를 추가할 경우 고정 revision의 원본에서 명령·도구 응답·시점을 연결한다. 공개 과제 식별자와 실제 로그의 저장소/경로가 맞는지도 검토한다. patch·최종 판정·후속 관측은 판단 입력으로 사용하지 않는다. 무관한 자료는 보류 사유를 남기고 제외한다.
4. 기억이나 현재 한쪽만 보고 답을 외우지 않도록 같은 기억의 다른 현재, 같은 현재의 다른 기억을 포함한다. 요청만 바꾸면 완료 정답은 유지되고, 완료만 바꾸면 요청 정답이 유지돼야 한다. 모든 대조의 정답은 입력만으로 다시 판정 가능해야 한다.
5. 같은 부모 사례의 바꿔쓰기·범위 조합은 같은 분할에 둔다. 원래 검토한 출처의 확장은 개발 자료이며 새 독립 경험이라고 부르지 않는다. 새 출처도 학습·설정 선택에 쓰면 독립 확인에서 제외한다.
6. 행별 포함/제외 근거, source hash와 위치, 관측/가상 여부, 라벨 이유, 분할을 표로 보존한 뒤 학습한다. 양적 목표보다 이 검토가 우선이다. 합성 192/768/3,072행이라는 이전 제안은 오늘 반드시 채울 목표가 아니다.
