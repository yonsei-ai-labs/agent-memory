# 다음 데이터와 모델 실험에 대한 판단

2026-11-07. 사용자 질문: 추가 실험의 가치, 기존 자료의 증강, 선형 판독기·모델 층 분석, Qwen3.8-27B와 MoE 비교.

**2026-11-08 보완:** 초기화 한 사례에 연구가 집중되는 문제를 확인했다. 다음 우선순위는 독립 개발 경험과 실제 현재 작업의 연결을 보강하는 것이다. 아래 11월 7일 제안은 당시 기록으로 보존하며, 현재 수집 범위·보강 방법·학습 연결은 문서 끝의 **「5. 11월 8일 보완: 경험의 폭과 학습 자료를 함께 늘린다」**를 따른다. 추가 실행 결과는 [초기화 파일럿](reports/2026-11-08-memory-unit-pilot.md)과 [낮 학습 보고](reports/2026-11-08-memory-selector-daytime.md)에 있다.

**추가 실험할 가치는 있다. 다음 목표는 자료를 늘렸을 때 새 출처에서도 관계 판단이 개선되는지, 어떤 입력·표현·판독 방식이 그 개선에 필요한지 확인하는 것이다.** 큰 모델 비교와 작은 모델 분석을 연결하되, 관계 정확도를 실제 기억의 이득·손해로 바꾸어 해석하지 않는다. 이 문서는 제안이며 새 학습이나 모델 추론 결과가 아니다.

## 현재 근거가 지지하는 범위

- 통제한 범위 과제에서 고정 표현 36.1% → LoRA 66.7% → 상태 대조 추가 69.4%의 동시 정답을 확인했다. 학습 경로를 유지할 근거다. 개발 출처는 두 개이며, 범위 필드의 길이만 비교하는 규칙도 개발 100%를 얻는다.
- 실제 코드 관계 74행에서는 고정 Harrier 전체 입력과 현재 상태만이 모두 38/74였다. 전체 입력이 개선한 행과 악화한 행은 각각 세 개다. 범위 LoRA를 전이한 실험은 아니었다.
- 기존 9B의 19/74는 비추론 다음 토큰 판독 프로토콜의 결과다. 모순을 한 번도 예측하지 못했으므로, 큰 모델의 능력이나 교사 품질을 예측할 기준으로 삼기 어렵다.

원자료 검토는 [후속 학습 독립 검토](../training/memory_selector/reviews/2026-11-07-followup/README.md), 실행 결과는 [보고서 색인](reports/README.md)을 따른다.

## 1. 데이터를 두 종류로 확장한다

### 신규 경험: 일반화를 확인할 독립 출처

[SWE-rebench OpenHands trajectories](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories)와 [SWE-smith trajectories](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories)를 먼저 사용한다. 기존 공개 로그에서 과거 명령·관측·복구·코드 변경을 뽑으면 원본 에이전트를 새로 실행하는 비용을 줄일 수 있다. 이 로그가 현재 관계나 기억 효용의 정답까지 제공하는 것은 아니다. SWE-smith의 합성 결함과 같은 경험의 서로 다른 직렬화도 구분한다.

첫 수집 기준은 큰 성공률보다 **판단 근거를 확인할 수 있는가**다. 다음 유형을 우선 찾는다.

| 유형 | 필요한 현재·과거 근거 | 만들 대조 |
| --- | --- | --- |
| 도구·API·버전 전제 | 해당 도구·함수·인자·설정의 존재와 의미 | 같은 처방이 현재 버전에서 성립/불성립/미확인 |
| 검사와 관측 범위 | 실제 명령 선택 범위와 완료 기록 | 일부·전체 범위, 같은 의미의 다른 명령 표기 |
| 출력 계약 | dtype·shape·namespace 등 실제 반환 관측 | 같은 표면 주제에서 다른 계약 또는 근거 부족 |
| 작업 상태와 중복 | 판단 전에 완료한 작업·검사 | 같은 기억이 아직 필요한 상태/이미 충족된 상태 |

같은 기억에서 현재 조건을 바꾸는 대조와, 같은 현재에서 실제 후보 기억을 바꾸는 대조를 함께 수집한다. 가능하면 두 현재 × 두 기억의 네 조합을 검토한다. 대각선이 항상 정답이 되도록 기계적으로 라벨을 만들지 않는다. 여러 기억이 동시에 적용될 수 있다.

판단 시점도 고정한다. 예를 들어 공통 초기 조사 뒤에 선택한다면 그때까지 관측한 코드·환경만 입력으로 허용하고 조사 비용을 기록한다. 실행 이후 출력이 필요한 기존 사례를 시작 시 선택 자료처럼 사용하지 않는다. 현재 과제의 숨은 정답 패치·평가 테스트는 입력에서 제외한다.

실무상 첫 단계는 신규 20–30개 출처에서 검토된 관계 100–200행 정도를 확보하는 것이다. 수집·주석이 성립하면 기존 [확대 계획](../training/memory_selector/reports/2026-11-07-scaling-and-larger-model-plan.md)의 신규 50개 이상·200–400관계 목표로 간다. 이는 작업 규모의 제안이며 통계적 검정력이 충분하다는 산정이 아니다.

### 기존 경험: 표현과 조건에 대한 연습 자료

기존 자료의 증강도 가치가 있다. 다만 같은 출처의 파생 자료는 독립 경험으로 세지 않는다.

| 변형 | 라벨 처리 | 검증할 내용 |
| --- | --- | --- |
| 사실·조건을 유지한 바꿔쓰기 | 의미 보존을 검토한 뒤 유지 | 지시형/서술형·표현 변화에 대한 강건성 |
| 관계에 필요한 전제 하나 변경 | 현재 코드·국소 실행으로 새로 확인 | 작은 조건 차이에 따른 판단 변화 |
| 필요한 관측 가림 | 실제로 근거가 부족해졌는지 검토 | 모순과 미확인을 구별하는 능력 |
| 같은 길이의 다른 범위·표기 | 새 범위 의미와 라벨 검토 | 길이 단서로 풀리는 편법의 차단 |
| 다른 표기의 같은 범위 | 명령 파싱·실행 의미로 검토 | 문자열 동일성을 넘어선 판단 |
| 주제는 같지만 전제가 다른 실제 기억 교체 | 새 조합마다 검토 | 관련성과 적용성의 구별 |

단순한 이름 치환은 의미를 바꾸거나 코드를 깨뜨릴 수 있다. 기존 이름과 같은 길이라는 이유만으로 유효한 실행 사례가 되지 않는다. 합성·통제 진단과 실제 환경 사례를 표시해서 분리한다. 성공한 출처만 남기거나, 실패한 출처의 기억을 일괄 음성으로 만들지 않는다.

분할은 **증강 전에** 고정하고 같은 출처·원본 문제·파생 결함·바꿔쓰기를 한 그룹에 둔다. 합성 증강은 학습 쪽에 우선 사용하고, 새 실제 출처의 확인 자료는 보존한다. 근거 위치, 변형 부모, 생성 방법, 검토자, 판단 시점, 미확정 사유를 남긴다. 행 수와 출처 수를 별도로 보고한다.

[Augmented SBERT](https://aclanthology.org/2021.naacl-main.28/)는 강한 쌍 판독기로 추가 쌍을 라벨링해 작은 임베딩 모델을 학습하는 선례다. 우리에게도 후보 생성·검토 순서의 참고가 된다. 그러나 [반사실 SNLI 증강의 부정적 결과](https://arxiv.org/abs/2010.04762)처럼 변형을 늘리는 것만으로 일반화가 좋아지지는 않을 수 있다. 자동 라벨을 그대로 정답으로 삼지 않는다.

증강 효과는 같은 신규 출처 test에서 실제 자료만 / 실제 자료+증강을 비교한다. 전체 감독 노출을 맞춘 비교와 추가 학습 예산을 쓴 실용 비교를 구분한다. 기존 자료 반복을 늘린 대조도 두어 새 변형의 가치와 업데이트 수 증가를 분리한다.

## 2. 판독층을 더 쌓기 전에 표현을 진단한다

아래 세 비교의 구체적인 입력·학습·평가 조건은 [기존 성과 재검토와 세 가지 판독 실험](ai-memory-reader-diagnostics-plan-2026-11-07.md)에 정리했다. 저장 예측의 개선 사례를 분해하고, 기존 모델을 고정한 길이·서식·조건 대조부터 확인한다.

현재 구현은 상태 q와 기억 u를 따로 인코딩하고 `[q, u, q*u, abs(q-u), 길이]`를 MLP에 넣는다. 토큰끼리 직접 비교한 뒤 요약하는 구조와는 다르다. 함수명·버전·부정·실행 순서 차이를 두 벡터가 충분히 보존하는지부터 확인할 가치가 있다.

먼저 다음 순서로 비교한다.

1. **고정 표현의 선형 판독기.** 현재 MLP와 같은 관계 특징을 사용한 정규화된 로지스틱 회귀를 기준선으로 둔다. q와 u의 단순 연결만 쓴 선형 점수는 상호작용을 제한한다. 곱·절댓값 차이까지 넣은 선형 판독기는 원래 두 입력에 대한 완전한 선형 함수가 아니므로 특징 구성을 명시한다.
2. **층별 고정 표현.** Harrier는 공식 [고정 revision 설정](https://huggingface.co/microsoft/harrier-oss-v1-0.6b/blob/f9b9dc8d367d443f2479d27aa5d8d2850c0774ee/config.json)에서 28층이다. 우선 7/14/21/28층의 같은 토큰 위치·정규화·판독기·학습 예산을 비교한다. 마지막 층이 관계 판독에도 최적이라는 보장은 없다. 층 선택은 개발 자료에서 하고 확인 자료에서는 고정한다.
3. **함께 읽는 입력.** 같은 작은 backbone에 질문·현재 근거·기억을 함께 넣고 관계를 판독하는 구성을 비교한다. 전체 근거를 같은 입력 한도 안에 유지하고, 별도 인코딩 방식과 판독층 파라미터·토큰·지연을 함께 보고한다. joint 입력은 두 내용을 비교한 뒤 표현을 만들 수 있어, 압축 과정의 병목을 살피는 실험이 된다. [Sentence-BERT](https://aclanthology.org/D19-1410/)의 bi-/cross-encoder 구분이 설계 참고다.
4. **그 뒤 필요한 학습만 추가.** 고정 표현이 충분하면 작은 head로 유지한다. joint 입력이 좋아지면 그 경로의 LoRA를, 특정 층의 차이가 일관되면 같은 수의 블록을 골라 LoRA 위치를 비교한다. 단순 층 추가는 같은 특징의 선형/MLP, 비슷한 파라미터 수로 폭을 늘린 MLP와 통제 비교한다.

중간 표현의 선형 분류 성적은 그 정보가 해당 판독기로 읽힌다는 증거다. 원래 모델이 실제로 그 정보로 판단한다는 인과 증거는 아니다. 판독기 용량·암기 가능성에 대한 [control-task probing 연구](https://aclanthology.org/D19-1275/)를 참고하고, 길이·서식 기준선 및 새 출처 성적을 함께 본다. 중간층이나 cross-encoder가 더 나을 것이라는 것은 우리의 가설이지 현재 관측 결과가 아니다.

처음부터 28층 × 여러 head × 여러 LoRA 위치를 모두 탐색하지 않는다. 네 층의 고정 표현과 선형 판독으로 범위를 좁히고, 자료 확대 후 소수 비교를 2–3개 seed로 반복한다. 현재 74행은 설계·진단용으로 유지한다.

## 3. Qwen3.8-27B와 MoE를 같은 관계 과제에서 비교한다

공식 모델·공개 API 목록을 다시 확인했다.

| 후보 | 역할 | 식별 |
| --- | --- | --- |
| [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) | 27B dense의 직접 관계 판독 기준 | OpenRouter `qwen/qwen3.8-27b` |
| [Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) | 전체 35B·토큰당 활성 약 3B MoE의 직접 판독 기준 | OpenRouter `qwen/qwen3.6-35b-a3b` |

25B-A3B 이름의 [Whittle 커뮤니티 배포](https://huggingface.co/logic65/Qwen3.6-Whittle-25B-A3B)도 존재한다. 해당 저장소는 서로 계보·형식이 다른 변형을 함께 설명하므로, 첫 비교는 공식 35B-A3B로 고정하는 편이 명확하다. 25B 변형은 실제 파일·revision·양자화·계보를 정한 별도 후속 비교로 둔다.

2026-11-07 공개 endpoint 조회에서는 각각 24개·11개가 반환됐다. [읽기 전용 조회 기록](reports/data/next-data-model-planning-20261107/openrouter-public-endpoints.json)에 남겼다. 실제 추론의 성공·품질·가격을 검증한 것은 아니다. API 제공사의 revision을 HF revision과 동일하다고 단정하지 않는다.

MoE의 활성 규모는 계산량 해석에 관련되고, 메모리 계획에는 전체 가중치도 필요하다. 개략적으로 BF16 가중치만 27B×2바이트≈54GB, 35B×2바이트≈70GB이며 런타임 공간은 추가다. 현재 L4에서 비양자화 전체 적재를 전제로 확장하기보다 기존 OpenRouter의 고정 제공사를 먼저 검토한다. 양자화·실행 경로가 다르면 그 차이도 기록한다.

### 작은 비교 프로토콜

1. 현재 74행의 원본 입력·라벨·순서를 고정한다. 데이터 제작·교사 후보 선정을 위한 개발 비교이며 새 독립 test로 부르지 않는다.
2. 별도 명확한 검사 12개 안팎으로 지시·세 라벨의 의미·출력 파싱을 점검한다. 형식 오류를 미확인으로 바꾸지 않는다. 검사 성적과 프로토콜 수정 이력을 보존한다.
3. 두 큰 모델과 9B를 **같은 생성 판독 프로토콜**로 비교한다. 기존 한 토큰 A/B/C 결과를 새 생성 방식의 모델 크기 비교에 그대로 사용하지 않는다. 우선 전체 입력만 평가하고 제거 대조는 다음 단계로 둔다.
4. 비추론 조건을 우선 맞추되 제공사가 실제로 지원하는지 확인한다. 별도 추론 허용 조건은 토큰·시간·비용 상한을 고정하고 다른 결과로 보고한다. 추론을 켠 27B와 끈 9B를 크기 효과로 설명하지 않는다.
5. 의미 라벨의 구조화된 출력과 짧은 근거 위치를 저장한다. 긴 설명의 그럴듯함을 정답 기준으로 쓰지 않는다. 각 사례는 새 대화에서 처리한다. 제공사·모델 ID·양자화·프롬프트 해시·reasoning 설정·종료 사유·원본 응답·토큰·비용·시간을 보존한다.
6. 정확도·macro F1·모순 재현율·미확인의 오판·그룹 전체 정답을 보고한다. 미응답·절단·형식 실패는 배정 분모에 포함하고 별도 원인도 센다. 입력 제거 후에도 기존 정답을 쓰는 점수는 진단으로 분리한다. 제거 후 관계의 정답을 평가하려면 새 입력의 근거로 다시 주석한다.

두 모델의 세대·학습·dense/MoE 구조가 함께 다르므로, 이 비교는 실용적인 판독 기준점이다. 순수한 파라미터 수나 MoE 구조의 인과 효과를 증명하지 않는다. 아직 두 모델의 우리 과제 성적은 없다.

## 4. 관측 결과로 다음 투자를 정한다

| 관측 | 우선 검토할 해석과 다음 일 |
| --- | --- |
| 큰 모델은 검토된 관계를 잘 맞히고 작은 모델은 어려움 | 작은 모델의 표현·입력·학습 신호를 비교. 큰 모델은 검토할 주석 후보를 제안하는 역할부터 사용 |
| 중간층의 고정 선형 판독이 마지막 층보다 나음 | 새 출처에서도 재현되는지 확인한 뒤 층 선택·혼합을 검토 |
| 함께 읽는 입력이 별도 인코딩보다 나음 | 관계를 비교하기 전에 압축하는 과정이 병목일 가능성. 계산·캐시 비용과 함께 평가 |
| 같은 정보의 바꿔쓰기에서만 개선 | 표현 강건성 개선으로 보고하고 독립 경험 일반화와 구분 |
| 큰 모델도 명확한 검사에서 라벨을 혼동 | 지시·근거·정답 의미와 실행 설정부터 점검. 더 큰 모델의 출력으로 라벨을 덮어쓰지 않음 |
| 관계 판독은 좋아졌지만 에이전트 성공·비용은 그대로 | 후보 기억의 실제 재사용 가치와 정책 연결을 재검토 |

큰 모델의 성적이 충분히 검증되면 사람 검토를 거친 증강·증류 교사로 이용할 수 있다. 큰 모델 간 합의나 낮은 temperature만으로 정답이 보장되지는 않는다. 기존 미확정 근거를 채우거나, 제공/보류의 관측하지 않은 성과를 만들어 넣지 않는다.

권장 순서는 **큰 모델의 작은 개발 비교와 소수 층 판독 → 신규 경험·검토된 증강 → 고정된 새 출처에서 재평가 → 실제 제공/보류 정책의 성공·비용 평가**다. 모델 비교는 자료 수집의 다음 우선순위를 정하는 용도로 쓰며, 기존 자료를 늘리는 일로 독립 확인을 대체하지 않는다.

## 5. 11월 8일 보완: 경험의 폭과 학습 자료를 함께 늘린다

사용자는 사례를 깊이 이해하되 초기화처럼 좁은 문제에 연구가 갇히지 않도록 요청했다. 다음 단계의 중심은 **여러 개발 경험에서 현재 상태·과거 기억·실제 제공 효과를 연결하는 자료**다. 작은 별도 모델의 추가 학습은 유지하고, 이번 Django 8상태는 완료된 진단 자료로 둔다. 이 절은 수집·학습 계획이며 새 자료나 학습 결과가 아니다.

### 좁아진 원인과 수집 범위 수정

[기존 수집기](../data_pipeline/screen_memory_prerequisite_sources.py)의 검색 조건은 실행 파일 부재, import 부재, 검사 실행 계약, 초기화 오류 네 종류다. [당시 계획](design-data/memory-prerequisite-sources-20261108/selection-plan.json)은 application bug·실패 assertion과 코드 수정에 의존한 복구를 제외했다. 이는 실행 전제만 보는 당시 목적에는 맞았지만, 전체 개발 기억의 후보를 대표하는 방식은 아니다. 같은 검색기를 더 오래 돌리는 것만으로 수집의 폭이 넓어지지 않는다.

새 수집은 오류 키워드 하나가 아니라 **조사→가설/수정→관측/검사**의 연결을 검토한다. 오류가 없었던 조사·성공한 접근·실패한 대안도 포함하고, 각 trajectory의 첫 오류만 선택하는 방식에서 벗어난다. 다음은 검토 범위이며 정답을 자동 생성하는 분류표가 아니다.

| 경험 유형 | 보존할 근거 | 현재 작업에서 판단할 관계 |
| --- | --- | --- |
| 원인 조사·실패한 접근 | 관련 코드, 시도한 가설, 반증 관측 | 같은 실패를 피할 단서인지, 현재에는 조건이 달라 다시 시도할 가치가 있는지 |
| 수정 전략·코드 불변 조건 | 수정 전제, 변경 위치, 국소 검사 | 같은 원리가 적용되는지, 표면 증상만 비슷한지 |
| 회귀·검사 범위 | 실행한 검사와 빠진 경로, 실제 출력 | 현재 수정의 검증에 충분한지, 다른 범위를 다시 확인해야 하는지 |
| API·버전·데이터 계약 | 실제 호출·버전·입출력 관측 | 과거 호출이나 변환이 현재 계약과 맞는지 |
| 환경·작업 상태 | 도구·설정·이미 수행한 작업 | 선행 작업이 필요한지, 이미 충족됐는지 |

환경·초기화는 이 중 하나로 유지한다. 유형별 효과나 유익/유해 비율을 미리 맞추지는 않는다. 겹치는 유형은 복수로 표시하고, 단순 해법으로 충분한 경우·효과 없는 경우·재현 실패도 목록에 남긴다.

### 데이터 보강 경로

1. **실제 이슈 실행 로그에서 독립 경험을 확보한다.** [SWE-rebench OpenHands 공식 카드](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories)를 다시 확인했다. 실제 GitHub 이슈의 다단계 행동·관측과 issue 식별자를 제공하므로 자연 발생 개발 경험의 첫 자료원으로 사용한다. 과거 성공 여부는 출처의 결과일 뿐, 미래 기억의 효용 라벨이 아니다. 기존 로컬 경험도 같은 명세로 포함한다.
2. **실행 가능한 조건 대조는 별도로 보강한다.** [SWE-smith](https://arxiv.org/abs/2504.21798)는 실제 코드에서 검사 실패를 일으키는 합성 과제를 만든다. 이미 가진 [tool 실행 로그](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories)와 연결해 조건 대조의 후보로 쓰되, 자연 이슈와 합성 결함을 별도 표시한다. 같은 코드·결함 부모·다른 직렬화를 독립 출처로 합산하지 않는다. 과거 수정안을 현재 정답으로 그대로 전달하는 조합은 제외한다.
3. **검토된 관계 자료를 먼저 학습에 사용할 수 있다.** 출처 근거와 현재 관측으로 판단 가능한 적용 조건·중복·미확인을 주석한다. 큰 모델을 쓰더라도 발췌와 주석 후보 제안에 한정하고, 원문·코드·국소 실행으로 검토한 뒤 사용한다. 실제 효용이 아직 없는 행은 관계 보조 과제에만 쓴다. 모든 행의 전체 작업 재실행이 끝날 때까지 관계 학습을 무조건 미룰 필요는 없다.
4. **실제 효용이 필요한 표본에 실행 비용을 쓴다.** 사전에 정한 현재 작업·판단 시점에서 기억 제공/보류를 비교한다. 재구성 가능한 동일 checkout·파일·환경 상태를 복제하고, 고정 작업자와 예산으로 의미 있는 작업 단계 또는 전체 작업을 이어간다. 로그가 있다는 이유만으로 중간 상태의 완전 재생이 가능하다고 가정하지 않는다. 재생할 수 없는 출처는 근거/관계 자료로 남긴다.
5. **증강은 학습 자료의 보조로 사용한다.** 의미를 유지한 표현 변화, 필요한 관측의 가림, 실행으로 확인한 전제 변경을 쓴다. 먼저 출처별 분할을 정하고 파생 자료는 부모와 같은 분할에 둔다. 새 실제 출처의 확인 성적과 기존 문장 변형의 성적을 구분한다.

### 한 행의 완성도와 평가 분리

자료는 다음 단계를 명시한다. 빈 효용을 0이나 무효로 채우지 않는다.

| 단계 | 갖춰야 할 것 | 가능한 사용 |
| --- | --- | --- |
| 출처 경험 | 과거 문제·명령/코드·관측·근거 위치·원본 ID | 기억 후보 은행 |
| 현재와 연결된 관계 | 별도 현재 문제·기억 전 관측·적용 관계·주석 근거 | 관계 감독 학습 |
| 실제 제공 결과 | 동일 상태의 제공/보류·성공·회귀·토큰·지연·실행 예산 | 효용/선호 학습 및 정책 분석 |
| 독립 확인 | 개발에서 사용하지 않은 가족·고정 정책·동일 후보/예산 | 일반화와 실제 순가치 평가 |

첫 정책 비교는 공통 초기 조사 후 한 번의 선택으로 고정하는 것을 제안한다. 특정 명령 직전의 조회를 채택한다면 별도 프로토콜로 표시한다. 현재 작업의 미래 로그·공식 정답 패치·기억을 받은 뒤 생성한 명령을 선택기 입력으로 넣지 않는다. 같은 문제의 다른 rollout과 출처-대상 연결 관계는 같은 그룹에 둔다. 기억 은행은 대상 평가 전에 고정하고, 실제 시간 순서를 주장하려면 별도로 날짜·commit 관계를 검증한다.

후보 추출·표현 검토에 사용할 데이터와 최종 평가 자료를 먼저 구분한다. 검토자는 확인 자료의 미래 로그·해법을 열어 후보를 고르지 않는다. 현재 관측·저장소·재현 조건으로 정한 표본은 효과가 작거나 규칙이 충분하더라도 유지한다. 학습용 실행의 우선순위는 추후 모델의 불확실성으로 정할 수 있지만, 그런 적응적 선택을 고정 평가 집합에 적용하지 않는다.

### 다음 작업 규모와 학습 연결

첫 확대 작업 목표는 **5개 이상 저장소의 20–30개 독립 경험 가족과, 근거가 검토된 100–200개 현재-기억 관계**다. 이는 수집 가능성을 확인할 목표이며 학습 충분성·검정력 보장이 아니다. 자연/합성 출처, 유형, 저장소, 독립 가족, 재현 가능한 대상, 실제 효용 행을 따로 센다. 개발·확인도 여러 가족에 걸치게 하고, 목표 수를 채우려고 미확정 관계를 정답으로 만들지 않는다.

실행 표본의 구체 수와 예산은 이 자료의 재현 가능성이 확인된 다음 고정한다. 관계 주석을 실제 성공률 라벨로 바꾸지 않고, 제공/보류 결과가 쌓이면 작은 모델의 효용 또는 선호 학습으로 연결한다. 기본 입력은 현재 관측+기억이며, 상태만·기억만·전체 관계 비교로 무엇을 이용하는지 확인한다. 항상 제공·항상 보류·검색·전제 확인 규칙을 같은 후보와 예산에서 비교하고 선택기 비용을 포함한다.

**진행 순서를 경험·관계 자료 보강 → 소수 고정 학습 비교 → 새 출처의 실제 제공 정책 평가로 조정한다.** 단일 사례의 추가 진단은 자료 채택·평가 계약·반복되는 모델 실패의 원인을 바꿀 때에 한정한다. 좁은 예제를 더 잘 맞히는 목적만으로 모델 크기·층·손실 탐색을 계속 늘리지 않는다.

이번 보완에서는 기존 수집 기준과 공식 자료 설명을 확인하고 계획만 수정했다. 새 GPU 할당·모델 호출·전체 코퍼스 다운로드·학습 데이터 추가는 없었다.
