# 기억의 구성요소별 득실을 측정하는 후속 실험

2026-11-05 · 사용자 목표에 맞춰 재구성한 설계 초안. 아래 확장 조건·표본 수는 실행 결과나 확정된 사전 등록이 아니다. 별도로 고정해 실행한 한 과제의 기능 검증은 [별도 보고서](reports/2026-11-05-component-measurement-feasibility.md)에 기록한다.

주 질문은 **기억의 어떤 부분·성질이 어느 대상 조건에서 성과를 높이거나 낮추며, 그 기여가 얼마인가**다. [야간 실험](reports/2026-11-04-overnight-research.md)은 구현 검증과 탐색 사례로 보존한다. 11월 4일 초안의 전달 정책 비교를 먼저 확대하는 순서는 이 질문에 충분히 직접적이지 않아, 내용의 구성요소 비교를 우선하고 조회 정책은 후속으로 옮긴다. 기존 고정 계획과 결과는 변경하지 않는다.

2026-11-07 구체화: [다음 검증 프로토콜](ai-memory-validation-protocol.md)에 `외부 경험 없음 / 관측 F / F+과거 처방 P / F+P+구체적 적용 조건 A`의 순차 대조, 주 대비·최종 효용·행동의 분리, 적용성·평가 민감도 감사와 별도 확인 절차를 정리했다. 실제 source 구간을 보존한 [네 조건 예시](design-data/content-validation-example-20261107.json)도 작성했지만 실험 배정·유료 호출은 하지 않았다. A와 P의 상호작용까지 추정하려면 F+A가 추가로 필요하다.

효과의 단위와 가상 수치 예시는 [측정 노트의 구성요소 비교](ai-memory-measurement-notes.md)에 정리했다. 전체 기억의 무메모리 대비 효과, 특정 부분을 추가·삭제한 조건부 효과, 여러 부분이 함께 있을 때의 상호작용을 나눈다. 성공률·회귀·비용을 함께 보고하며 한 실행의 성공/실패를 확정 유익/유해 라벨로 쓰지 않는다.

본 실험 전에 첫 후보 구성요소, 출처 근거, 편집 규칙, 예상 행동과 주 성과 대비를 고정한다. 적용 조건의 명시 여부, 현재 버전과의 일치, 단정 강도는 후보 성질이며 이미 입증된 위험 요인이 아니다. 특정 성질을 검증할 때는 그 성질을 바꾼 대조가 필요하고, 구성요소 전체를 삭제한 결과로 원인을 대신하지 않는다.

사용자는 내용의 다양성과 함께 같은 기억을 정보·행동 제안·지침으로 다르게 제공하는 비교를 제안했다. [내용과 사용 안내 설계](ai-memory-content-and-framing.md)에 두 축을 분리했다. 다음 작은 비교의 후보는 본문을 고정한 `무메모리 / 정보 참고형 / 지침형`이며, 기존 부분 삭제 비교와는 다른 개입이다. 성공·실패 출처 각각 하나로 세 사용 안내의 예시를 만들었고, 실험은 아직 실행하지 않았다. 체크리스트 배치·조건 추가·지시 역할 변경은 별도 요인으로 다룬다.

후속 진행: 위 후보는 기존 두 대상의 [12회 탐색](reports/2026-11-05-memory-framing-smoke.md)으로 실행했다. 정보형·지침형의 해결률은 같고 과제별 메모리 유무의 관측 차이는 반대였으나 방향을 확정하지 못했다. 이후 사용자 승인으로 새 출처 두 개·대상 네 개의 [별도 24회 배정](reports/2026-11-05-new-content-transfer.md)을 준비했다. 새 경험 주제를 넓히되 절차 카드로 종류를 고정하므로 사실형·절차형 내용 자체의 인과 비교와는 구분한다.

2026-11-06 완료 기록: 새 24회도 세 조건 모두 6/8 해결이었다. 지침형−정보형은 0%p, 고정 네 과제의 보수적 95% 범위는 −94.41~+94.41%p다. 사전 지정 출처 이름 검색은 모든 조건에서 0회여서 이 지표에서도 차이를 포착하지 못했다. 다음 확인에는 적용성이 명확한 사례·새 원천 경험과 더 넓은 행동 지표를 사전에 정해야 한다. 출처 공식 실패 안의 일부 관측과 대상 공식 실패 안의 부분 변경도 따로 기록했지만 이를 메모리 이익으로 판정하지 않았다. 이번 결과를 보고 기존 배정의 반복·조건을 늘리거나 주 지표를 바꾸지 않았다.

## 1. 내용의 기여를 먼저 비교한다

| 실험 | 주 비교 | 주 지표 | 해석의 범위 |
| --- | --- | --- | --- |
| 구성요소의 기여 | 같은 출처 카드의 요소 유무를 교차 | 예산 내 공식 해결물 제출률·회귀·비용의 차이 | 고정한 전달 방식·다른 요소·대상 분포에 조건부인 효과 |
| 같은 본문의 사용 안내 | 동일 본문에 정보 참고형·제안형·지침형 안내 | 성과·전체 배정 비용·사전 정의한 행동 변화 | 안내 문구 개입의 효과; 문장 길이·표현의 일반화는 별도 확인 |
| 특정 성질의 기여 | 같은 내용에서 조건 표시·표현 등 사전 정의한 부분만 편집 | 성과·비용과 사전 정의한 행동 변화 | 그 편집의 효과; 일반적인 유해성 라벨과 구분 |
| 후속 제공 정책 | 내용·선택 규칙을 고정하고 시작 제공·선택적 조회 비교 | 전체 배정의 성과·비용, 조회율 | 실제 채택·시점·부가 비용을 포함한 정책 효과 |

첫 내용 실험에서는 노출 시점과 형식을 고정하고 시작에 제공하는 방식을 사용할 수 있다. 이는 카드가 실제 입력에 포함됐을 때의 기여를 재기 위한 진단이며, 최종 서비스의 최적 전달 방식이라는 주장이 아니다. 후속 자율 읽기 비교에서도 조회한 실행만 골라 분석하지 않고 처음 배정한 전체 실행을 유지한다.

한 과제에서 기준 성공·기억 실패가 한 번 나타난 사례를 확정된 유해 기억 라벨로 쓰지 않는다. [측정 노트](ai-memory-measurement-notes.md)의 평균 효과와 개별 잠재 결과의 구분을 따른다.

구성요소 삭제를 다시 비교할 경우의 후보는 같은 새 과제·출처 쌍에서 `무메모리 / 사실 F / 지침 P / F+P`의 네 조합을 비교하는 것이다. 독립적으로 이해 가능한 F와 P를 만들 수 있을 때만 이 구성을 쓴다. P가 F를 가리키는 생략 표현뿐이면 사실을 공통으로 둔 지침 추가 비교로 좁힌다. 내용에 없는 사실을 새로 만들어 채우지 않는다. '사실이 있는 상태에서 지침을 더했을 때의 성과 차이' 같은 주 대비와 다른 조건의 보조 대비를 실행 전에 선택한다. 이 삭제 비교는 동일 본문의 사용 안내 비교를 대신하지 않는다.

지침에 새 사실이 섞이는 문제, 길이·위치·일반 조언의 효과도 검사한다. 첫 비교를 묶음 추가의 전체 효과로 보고할 수 있지만, 지시의 의미만 원인이라고 주장하려면 맞춘 대조가 더 필요하다. 과제 20개·조건별 2회라면 네 조건은 160회지만, 이는 산술적인 실행 규모 예시이며 효과를 입증할 표본 수는 아니다. 실제 표본 수는 원하는 최소 차이·과제와 출처의 변동·비용을 확인해 정한다.

R09의 조회 안내 비교는 후속 정책 연구 후보로 남긴다. 준비만 했던 Sphinx 10325는 11월 5일 별도 구성요소 기능 검증에 사용했으므로 이후의 독립 확인 과제로 세지 않는다. 앞선 조회율 차이를 새 내용 연구의 성과로 바꾸어 쓰거나, 기존 과제를 독립된 확인 집합에 조용히 포함하지 않는다.

## 2. 데이터를 만드는 부담을 과제·출처 선택으로 줄인다

새 문제를 사람이 작성하지 않고 기존 벤치의 문제 설명·버전·커밋 관계로 후보를 고른다. 과거 출처를 먼저 수행하고 그때 실제 관측한 코드·명령·결과로 카드를 만든다. 출처에 없던 대상 정답을 카드 교정에 넣지 않는다. 같은 과제의 재시도 경험과 다른 과제로의 전이는 분리한다.

대상마다 ‘시점상 사용 가능한 출처가 있는가’, ‘관련 서브시스템인가’, ‘실제 출처 패치가 upstream 변경과 같은가’를 기록한다. 대상 정답을 보기 전의 선정과, 선택 결과를 보고 흥미로운 사례만 추가한 탐색을 구분한다. 모든 후보와 제외 사유도 남긴다. 같은 저장소 출처 하나만 반복 재사용하면 그 은행에 조건부인 효과만 말할 수 있으므로, 확인 실험에서는 출처와 저장소를 함께 넓힌다.

첫 확장 단계는 결과를 보지 않은 여러 저장소의 20–30개 대상에 대한 실행 가능성·비용 점검으로 잡을 수 있다. 이는 작은 평균 개선을 입증할 표본 수라는 뜻이 아니다. 해당 점검에서 선택한 정책을 최종 평가 집합에서 다시 조정하지 않는다. 이번에 재사용한 과제는 최종 확인 집합에서 제외하거나 탐색 층으로 명시한다.

## 3. 반복 수와 서로 다른 과제 수는 대체 관계가 아니다

새 과제 `i`에서 두 정책의 반복 평균 차이를 `D_i`, 실제 조건부 평균 효과를 `δ_i`라 하자. 과제들이 독립 표집되고 조건부 실행이 독립이라는 가정 아래 다음 분해가 성립한다.

```text
Var(D_i) = Var(δ_i)
           + E[p1_i(1−p1_i) + p0_i(1−p0_i)] / R

두 조건의 이진 실행 잡음 항 ≤ 0.5 / R
```

R을 늘리면 같은 과제에서의 실행 잡음은 줄지만 새로운 과제 간 효과의 차이는 사라지지 않는다. 다음은 효과의 과제 간 표준편차를 임의로 0.15로 놓고, 양측 5%·명목 검출력 80%의 정규 근사를 적용한 **설계 민감도 예시**다. 야간 데이터로 표준편차나 필요한 N을 추정한 결과가 아니다.

| 가정한 평균 개선 | 조건별 반복 | 근사 과제 수 | 두 조건 대상 실행 수 |
| --- | --- | --- | --- |
| 10%p | 1 | 411 | 822 |
| 10%p | 2 | 214 | 856 |
| 10%p | 4 | 116 | 928 |
| 20%p | 2 | 54 | 216 |
| 20%p | 4 | 29 | 232 |

[전체 가정·계산값](reports/data/2026-11-04-sample-size-sensitivity.json), [CSV](reports/data/2026-11-04-sample-size-sensitivity.csv). 사용한 식은 `N≈ceil((z0.975+z0.80)² × (σδ²+0.5/R) / Δ²)`다. 조건부 이진 분산의 상한을 쓰지만 정규 근사이므로 실제 검출력을 보장하지 않는다. 저장소·문제군의 군집, 모델 드리프트, 평가 누락, 여러 비교에 따른 조정도 아직 포함하지 않았다. 고정된 벤치 자체의 효과와 새 과제 모집단의 효과는 다른 추정 대상이다.

따라서 현재 1–4회 반복의 차이는 큰 사례 후보를 찾는 단서로 쓴다. 다음 확장에서는 많은 반복을 한 과제에 집중하기보다 서로 다른 과제를 확보할 필요가 있다. 정확한 배정은 중요한 최소 효과, 평가 대상, 과제·저장소 간 변동, 실제 비용을 정한 뒤 시뮬레이션으로 다시 산정한다.

## 4. 실행 전 고정할 것

- 모델·제공자·추론 설정, 코드·이미지·소스 트리·프롬프트·은행·검색기 해시와 모든 한도.
- 과제 목록·출처 시간 관계·제외 사유, 발견용과 확인용 분리, 주 비교 하나와 보조 비교.
- 과제·반복 블록 안의 실행 순서 무작위화와 저장된 배정 seed. 같은 seed가 모델의 동일한 숨은 난수를 보장한다고 가정하지 않는다.
- 공식 성과와 비용의 분모, 정책 이후 선별을 하지 않는 규칙, 평가 오류 처리와 중단 규칙.
- 실제 Git 접근 범위. 미래 커밋·태그 접근을 제한한다면 같은 작업 트리·의존성을 유지한 환경 대조를 먼저 통과한다. 외부 카드가 없는 것과 과거 정보가 전혀 없는 것을 구분한다.

API 예산 안에서 정답 패치를 만들고도 제출하지 못한 경우는 주 지표의 전달 실패다. 공식 채점 결과는 미제출로 비워 두고 예산 내 해결물 전달 지표에서 실패로 센다. 컨테이너·API·채점 장애는 별도 상태로 보존한다. R05처럼 정상적인 한도 도달이 전체 배치를 멈추는 문제에 대해, 11월 5일 실행기에 명시적 `allow_expected_no_submission` 옵션을 추가했다. 비용이 완전하고 API 오류가 없는 `LimitsExceeded`만 다음 배정으로 진행하며, 비용·환경·채점 오류는 중단한다. 이 분기와 거부 조건은 유료 실행 전 검사했다. 기존 중단 회차는 사후에 완료로 고치지 않았다.

성공률이 높은 과제에서 효율 차이를 검증하려면 **기억 정책 × 사전 고지된 예산**도 후보가 된다. 짧은·보통 예산 모두 에이전트에 같은 방식으로 알리고 제출 절차에 필요한 단계도 계획하게 한다. 짧은 예산에서도 실제 제출·공식 성과를 측정하며, 긴 실행의 사후 통과 패치를 짧은 예산의 성공으로 바꾸어 세지 않는다. 조회 호출이 모델 요청 하나를 더 쓰는지, 같은 응답의 다른 도구 호출과 함께 수행되는지도 실제 기록으로 확인한다. 요청 한도는 계산량·실행시간·도구 행동 수와 같은 단위가 아니므로 비용과 행동 수를 함께 보고한다. 이는 아직 실행하지 않은 후속 설계다.

## 5. ‘해로운 기억의 공통점’은 다음 단계에서 확인한다

처음에는 최종 결과를 보지 않고 표시할 수 있는 후보 특징만 정한다. 현재 버전에 없는 식별자, 적용 조건의 누락, 출처 근거보다 강한 단정, 실패 판정의 모호한 표현 등이 후보이며 아직 검증된 위험 요인이 아니다. 성공·실패·변화 없음 사례 모두에서 노출 빈도와 과제 구성을 함께 본다.

특징 하나를 삭제·완화·조건 복구하는 편집을 정한 뒤 새 실행으로 비교한다. 행동이 바뀌어도 성과나 비용이 개선되지 않으면 행동 효과까지만 주장한다. 실제로 유용한 산출물은 실행 전에 관측 가능한 특징으로 기억을 제공하거나 보류하는 정책이고, 그 정책의 가치는 별도 과제에서 항상 제공·미제공과 비교해야 한다.

확대 회귀 검사는 공식 점수와 함께 유지한다. 원본과 정답 패치에서 이미 실패한 테스트를 기억의 추가 피해로 세지 않는다. 공식 채점 밖의 검사 범위와 선택 시점을 남기고, 사후 검사 결과를 에이전트나 평가용 기억으로 돌려주지 않는다.

테스트 버전도 적용 조건에 포함한다. 이번 Django에서는 기존 테스트의 쿼리 기대값과 공식 테스트 패치의 기대값이 달랐고, 정답 패치도 기존 테스트를 실패했다. ‘과거에 유효했던 검증 절차를 언제 그대로 재사용할 것인가’가 후속 가설이 될 수 있다. 이 대상의 숨겨진 평가 내용을 알려주는 지침을 같은 대상에 적용해 일반적인 기억 이득으로 보고하지 않는다. 출처 경험에서 얻은 조건부 규칙을 다른 과제에서 검증해야 한다.


## 2026-11-07 파일럿 이후의 우선순위

[처방 분해 32회](reports/2026-11-07-prescription-validation.md)를 완료했다. FP−F 관측 +25%p와 F−N −12.5%p는 넓은 구간으로 미확정이다. 가까운 문제의 제출은 모두 정답이었고, 미제출이 성공 차이를 만들었다. 먼 문제에서는 모든 제출이 같은 계약 위반으로 공식 실패해 성공률만으로 조건을 구별할 수 없었다. 주 결과·사후 분석·모델 호출을 섞지 않는다.

다음 실행은 현재 은행을 임의 수정해 이어붙이지 않고 별도 계획으로 고정한다. 우선 공통 마지막 예산/제출 안내를 모든 조건에 같은 위치에 두고, 더 여유 있는 응답 예산과 동일 시점 패치 저장으로 수정 도달과 제출 지연을 분리한다. 내용 분해에서는 같은 함수명·수정 정보·검증 정보를 유지한 서술형/지시형 조건을 만들어 정보량과 지시를 분리한다. 다수 source와 같은 target에 대한 서로 다른 기억을 교차해야 적용성과 과제 난이도를 구분하고 공통 특성으로 확장할 수 있다.

현재 F는 원문 procedure의 처방을 삭제한 잔여 맥락이므로 별도 facts 카드와 같지 않다. 과거 검사를 직접 복사했다는 표지는 0이었으며 단순 검색·test_action 문자열 표지만으로 기억 채택·손해 원인을 확정하지 않는다. 32개 배정과 327 API 요청은 독립 기억 32개/327개가 아니다. 이 후속 우선순위는 제안이며 추가 유료 실행은 없다.


## 같은 조건 반복을6회로 늘린 후

[추가 16/누적48 결과](reports/2026-11-07-prescription-replication.md)를 완료했다. 추가분 FP−F 관측 +0.0%p와 합계의 탐색 관측 +16.7%p를 분리한다. 한 소스·두 문제 구조와 내용/길이/위치/예산의 해석 한계는 그대로다. 이후 확대는 같은 두 문제의 반복보다 새 소스와 새 타깃 및 같은타깃에 대한 서로 다른 기억의 교차 배정을 우선한다. 이 우선순위는 후속 제안이며 추가 16 밖의 유료 모델 실행은 하지 않았다.

새16에서 FP−F는0%p여서 초기처방추가 신호를 강화하지 못했다. F−N 관측방향과 API비용 차이도 회차별로 달랐다. 이후에는 반복수만 늘려 유의한 값을 찾기보다 새source·target에서 동일정보의 서술/지시를 분리하는 확인을 우선한다.

## 논문 재검토 후의 구체적 후보

[2026-11-07 논문 재검토](ai-memory-literature-revisit-2026-11-07.md)에서 원본 근거와 요약의 차이를 먼저 진단하는 후보를 추가했다. 기존 출처의 도구 부재·대체 검사 실행 정보가 사용한 procedure에서 빠졌고, 기존 48회 중45회가 rg 또는pytest 부재를 다시 겪었다. 이 사후 관찰은 복원 이득의 검증 결과가 아니다.

새 source/target에서 N(무기억)/R(고정 규칙의 원문 근거)/S(요약)/S+O(과정 정보 복원)를 비교하고 S+O−S를 주 대비로 삼는 안을 우선 검토한다. 길이·정보량이 함께 바뀌므로 첫 결과는 패키지의 효과다. 이 비교 뒤 같은 원자적 주장 집합의 서술/지시를 별도 실험한다. 상태와 적용 전제를 확인하는 절차, 검증 자체의 비용, 기억 갱신 방식은 후속 축으로 남긴다. 새로운 표본 수·실행 배정·추가 비용 지출은 아직 확정하거나 실행하지 않았다.

## 외부 리뷰 후의 구체화

[조각 개입 설계](ai-memory-intervention-study-plan-2026-11-07.md)에 수치 판정·삭제/복원·논문 실험 대응을 추가했다. 먼저 기존 탐색 과제로 공통 마지막 제출 안내와 수동 개입 없는 패치 계측·여유 예산을 교정하고, 첫 내용 실험부터 새 source/target을 사용한다. M=S+O로 정의하면 M−O=S가 정확히 성립해 과정 정보 복원과 삭제를 같은 대비로 측정할 수 있다.

M−N의 순이득과 M−(M−u)의 조각 기여를 따로 보고한다. 복원 해시 일치는 구현 검사이며 통계적 재현이 아니다. 여러 삭제 중 좋은 것을 고른 경우 새 출처·대상에서 고정 확인한다. 직접 수정법·원리·실행 과정의 적용성을 분리하고, 비용 감소만으로 무해성을 확정하지 않는다. 64회 파일럿 예시의 조건부 Hoeffding 반폭도 약48%p라 작은 개선의 확증 규모가 아니다. 최종 목록·예산·표본 수·실행 배정은 아직 미확정이다.


## 과정 정보 복원 파일럿 이후

[새 결과](reports/2026-11-07-process-restoration.md)는32배정 중31개 실행 종료·외부 중단1개다. N/R/M은각6/8, S는성공6·실패1·미확정1이며 주 대비는미확정이다. 세 과제의 전조건 성공과 한 과제의 전조건 실패로 구별 능력이 낮았다. 중단1개를 실패0으로 바꾸거나 완결 실행만의 비율로 이득을 주장하지 않는다.

중간 패치 계측으로 무기억 한 실행의 공식 통과 상태 상실을 확인했다. 기존 검사 파일은 원본통과·정답실패였고 공식 요구와 충돌했다. 이는 과거 명령을 복원한 기억의 손해를 입증한 사례가 아니다. source의 검증 범위·전제·실패 뒤 평가 피드백을 보존하는 조각을 다음 후보로 삼는다.

다음 확인은 새로운 source·target에서 동일 기억의 조각 포함/정확한 삭제를 비교한다. 일반적인 요구사항 재검토 안내도 대조해 기억 정보 자체의 기여를 구분한다. 과거 검증이 현재 요구와 맞는 경우와 충돌하는 경우를 결과 전에 구분하고 성공·회귀·비용을 함께 본다. source의 실제 경험만 사용하며 현재14534의 정답이나 검사 패치를 같은 대상에 주입해 전이 이득이라고 보고하지 않는다. 이번 네 대상은 발견 자료로 남긴다.

여러 과제·source와 같은 대상에 대한 다른 기억을 확보하는 것이 우선이다. 과제별0/100% 집중과 작은 표본의 부호를 유익·유해 정답 라벨로 쓰지 않는다. 동일 정보의 서술/지시 비교는 명제·함수명·검증 정보를 맞춘 별도 실험으로 유지한다. 이 후속은 설계 제안이며 이번 파일럿 밖의 추가 유료 모델 실행은 없다.

## 파일럿 원자료 리뷰 뒤 우선순위 보완

[상세 리뷰](reports/data/process-restoration-20261107/review/README.md)에서 주 결과를 바꾸지 않고 개입의 단위를 다시 확인했다. 복원한 검사 명령 V는 생성 facts 카드에 이미 있었고 선택한 procedure에서만 빠졌다. 현재 대비는 전체 요약 손실이 아닌 선택 카드의 보강 효과다. 반면 source의 독립 Django 초기화 예제는 두 카드 모두에서 빠졌다. 사후 설정 누락 문구는 Django의 R0/4·N/S/M 각각4/4였고 다른 초기화 오류를 포함하면 R1/4다. R은 여러 정보를 함께 바꾸므로 초기화 조각의 인과 효과가 아니다.

첫 후보를 source 근거가 있는 초기화 단위의 복원/정확한 삭제로 좁힌다. 새 source·target에서 S와 S+초기화 단위를 비교하고 오류 발생·명령 수·전체 비용·최종 성공을 따로 판정한다. 일반적인 초기화 주의 안내와 현재 환경 정보를 이미 가진 조건을 함께 검토해 환경 사용법·추가 숙고·중복 제공의 효과를 분리한다. 현재 네 대상의 재실행은 발견용 교정이며 독립 확인으로 세지 않는다. generic 안내만으로 충분하다면 기억 특유의 이득을 주장하지 않는다.

그다음에 검사 대상·버전·계약과 피드백을 보존하는 단위를 검토하고, 같은 정보의 서술/지시는 별도 축으로 둔다. 원래 성공률 주 지표를 새 설정 오류 지표로 교체하지 않으며, 새 실험의 주 비교·중단 처리·선정 규칙은 실행 전에 고정해야 한다. 이번 리뷰의 새 모델 생성은0회이고 새 표본 배정·지출은 시작하지 않았다.
