# 기억의 득실 검산 자료: 점검 결과와 보완 방향

2026-11-12. 작성: Claude(외부 검토). 저장된 원 출력·라벨만으로 다시 계산했다. 새 학습·작업자 실행은 없고, 자료와 결과 파일은 수정하지 않았다. 따로 표시한 한 줄(BEAM 현재 관측)만 보고서 수치를 옮긴 것이다.

**검토 반영 (같은 날 오후).** Codex가 이 노트를 원자료로 교차 검토했다([검토 보고서](reports/2026-11-12-gain-loss-supplement-review.md)). 숫자 재현은 통과했고, 아래 다섯 곳을 고쳤다.
1. **④ "무효 기록만 뺀 조건"은 새로 실행할 필요가 없다.** 지금 자료의 모든 시점(2,240개)에서 "최신 기록만"과 기록·순서·본문이 같다. 취소 뒤 재예약 같은 사건이 없기 때문이다.
2. **출력 일치는 원인 확정이 아니다.** "무효 기록을 따랐다" 361건은 모두 무효 기록과 일치한다. 하지만 21건은 다른 유효 결정과도 일치하고, 그중 15건은 그 결정도 제공된 문맥에 있었다. 그래서 "원인"이 아니라 "틀린 답이 일치한 기록을 추적함"으로 쓴다.
3. **`fresh`는 "기록에 없는 값"이 아니다.** "이전 결정과 일치하는 식당·숙소 조합이 없음"이라는 뜻이다. 90건 중 64건은 식당과 숙소가 각각 과거에 나온 재조합이다.
4. **"무기억 대비 손해 0"은 배달 경로 세션에만 해당한다.** main의 계획 변경 대조에는 7/12가 있다.
5. **해석 범위를 좁힌다.** 공개 자료는 "이번에 검토한 공개 갱신 문항과 전달 조건에서는 손해가 적게 관측됐다"로 쓴다. 9B와 27B는 각자 자기 세션을 진행해 과거가 다르다(800위치 중 90곳). 그래서 두 모델의 차이를 모델 크기만의 효과로 읽지 않는다.

## 1. 요약

**주장하려는 기여:** 기억이 이득과 손해를 만드는 상황을 통제해서 만들고, 같은 상태의 결과를 짝지어 손해의 원인(틀린 답이 어떤 기록을 따랐는지)까지 다시 계산할 수 있는 자료.

**점검 결론**
- 이득은 대부분의 자료에서 검산된다.
- 손해는 직접 만든 여행 자료 두 묶음에서만 충분히 나온다. 배달 경로 실험의 여행 세션과 main의 계획 변경 대조이다. 공개·자연 자료의 손해는 0–6건이다.
- 따라서 기여는 "손해를 만들 수 있고, 틀린 답이 일치한 기록까지 추적되는 통제 자료"로 한정한다. 공개 자료는 "이번에 검토한 공개 갱신 문항에서는 손해가 적게 관측됐다"는 대조로 쓴다.

**보완 순서**

| 시기 | 보완 |
|---|---|
| 발표 전, 비용 없음 | ① 손해 정의 통일과 득실 장부<br>② 교차 재계산과 라벨 표본 검토<br>③ 유형별·세션 단위 보고 |
| 작은 실행, 승인 필요 | ④ 무효 기록만 뺀 기준 조건 (검토 결과 지금 자료에선 불필요) |
| 발표 후 | ⑤ 손해 자료 확장<br>⑥ 자연 자료의 손해 |

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 상태 | 한 요청 시점. 같은 상태에서 전달 조건만 바꿔 결과를 비교한다 |
| 독립 단위 | 여행은 세션(가족 하나당 세션 하나), LongMemEval-S는 문항, BEAM은 대화 |
| 이득 | 기준 조건에서 실패하고 비교 조건에서 성공 |
| 무기억 대비 손해 | 기억 없이 성공했는데 기억을 준 뒤 실패. 기억이 성공을 망친 경우 |
| 정답 기록 대비 손해 | 필요한 기록만 줬을 때는 성공했는데 다른 전달 형태·선택에서는 실패. 잘못된 기억이나 형태가 만든 손실 |
| 일치 추적 | 틀린 답이 일치한 것: 무효 기록 / 다른 사람·다른 날의 결정 / 모름 / 이전 결정과 일치하는 조합 없음. 여러 기록과 동시에 일치하면 모호로 표시하며, 원인 확정 라벨이 아니다 |

## 4. 핵심 자료의 확인 결과 (배달 경로 실험의 여행 세션)

**검산**
- 원 출력을 다시 파싱하고 채점했더니 15,740행 모두 저장된 결과와 같다.
- "무효 기록을 따랐다"로 분류한 오답 361건은 모두 실제 무효 기록의 선택과 일치한다. 단 21건은 다른 유효 결정과도 일치한다(맨 위 검토 반영 2).
- "모름"으로 분류한 1,168건은 모두 UNKNOWN을 담고 있다.
- 같은 입력을 다시 호출한 444건은 모두 같은 출력이었다.
- 라벨 표본 3건(취소된 조건부, 유지된 조건부, 바뀐 참조)을 요청 원문과 대조했고 모두 맞았다.
- 라벨은 사람이 붙인 것이 아니다. 세션의 사건 기록(예약·변경·취소)에서 규칙으로 만들었다.

**손해의 크기와 분포**

main 20세션에서 모든 조건이 공통으로 가진 상태만 셌다.

| 전달 형태 | 9B 손해 /396 (잘못된 기록을 따름) | 27B 손해 /400 (잘못된 기록을 따름) |
|---|---:|---:|
| 대화 그대로(자기 세션) | 74 (64) | 6 (5) |
| 같은 대화를 새 세션에 붙임 | 69 (63) | 10 (7) |
| 기록 목록 | 64 (55) | 24 (12) |
| 기록 목록 + 유효 표시 | 51 (39) | 24 (9) |
| 최신 기록만 | 40 (36) | 21 (10) |
| 필요한 기록만 | 0 | 0 |

- 무기억 대비 손해는 모든 조건에서 0건이다. 기억 없이는 풀 수 없는 과제이기 때문이다. 이 자료의 손해는 정답 기록 대비로 재야 한다.
- 손해는 몇 세션에 몰려 있지 않다. 9B 기록 목록의 64건은 20세션 전부에 나왔고, 한 세션에서 많아야 5건이다. 27B는 24건이 16세션에 나왔다.

**형태마다 손해가 나는 모습이 다르다 (9B)**

| 전달 형태 | 틀린 답이 주로 일치한 것 | 주된 유형 |
|---|---|---|
| 기록 목록 | 무효 기록을 따름 39 | 취소된 조건부 29, 바뀐 참조 22 |
| 대화 그대로 | 다른 사람·날의 결정을 따름 61 | 먼 참조 27, 유지된 조건부 20, 취소된 조건부 17 |
| 최신 기록만 | 다른 결정을 따름 36 | 취소된 조건부 22 |

27B는 대화 형태의 손해가 6건뿐이다. 기록 목록과 최신 기록만에서는 취소된 조건부(각 16건)에서 손해가 났다.

**바로잡는 이전 설명.** 앞서 "같은 정보도 기록 목록으로 주면 손해가 커진다"고 설명했는데, 이는 바뀐 참조와 취소된 조건부만 본 결과였다. 9B의 전체 손해는 대화 74건, 기록 목록 64건이다. 유지된 조건부에서는 대화가 19/39, 기록 목록이 36/39였다. 맞는 표현은 다음과 같다.
- 기록 목록은 무효 기록을 따라간다.
- 9B는 대화에서 비슷한 다른 결정을 따라간다.
- 27B는 대화에서 손해가 거의 없다.

## 5. 보완 방향

### ① 손해 정의 통일과 득실 장부 (CPU, 발표 전)
- **문제:** 손해의 기준이 자료마다 다르다. 무기억 대비, 정답 기록 대비, 현재 근거 대비가 섞여 있다. 그래서 "손해 몇 건"이 자료 사이에서 비교되지 않는다.
- **보완:** 모든 자료를 같은 형식의 득실 장부로 만든다.
  - 한 행은 `(자료, 독립 단위, 상태, 작업자, 비교 조건, 기준 조건, 두 결과, 변화, 손해 종류, 원인, 원 출력 job_id)`이다.
  - 손해 종류는 무기억 대비와 정답 기록 대비로 나눈다.
  - 원인은 위 용어표의 네 가지로 적는다.
- **완료 기준:** 한 스크립트로 장부와 3절의 표가 다시 나오고, 이 노트·보고서의 숫자와 일치한다.

### ② 교차 재계산과 라벨 표본 검토 (CPU + 사람 약 1시간, 발표 전)
- **문제:** 실행·분석·라벨을 각각 한 에이전트가 맡았다. 배달 경로 실험은 Claude, 나머지는 Codex이다.
- **보완:**
  - 서로의 자료를 깨끗한 사본에서 독립적으로 다시 계산한다. Codex가 배달 경로 자료를, Claude가 main의 계획 변경·복합 기록 자료를 맡는다.
  - 여행 손해 사례 40건을 무작위로 뽑는다. 요청·기록·답·라벨만 보이는 표로 사람이 라벨을 확인한다.
- **통과 기준:** 재계산 불일치 0건, 라벨 동의 38/40 이상.
- **미달 시:** 어긋난 유형을 고친 뒤 해당 자료의 손해 수를 다시 보고한다.

### ③ 유형별·세션 단위 보고 (CPU, 발표 전)
- **문제:** 일부 유형만 보이면 결론이 뒤집힌다(4절의 바로잡은 설명). 요청 단위 숫자만 쓰면 같은 세션 안의 요청을 독립으로 세게 된다.
- **보완:**
  - 형태·선택 비교는 항상 모든 요청 유형의 표를 함께 낸다.
  - 주요 대조에는 세션 단위 집계와 부호 검정을 붙인다.
- **이미 계산한 세션 단위 대조 (20세션):**
  - 취소된 조건부, 대화 > 기록 목록: 9B 10:0, 27B 10:1
  - 바뀐 참조, 대화 > 기록 목록: 9B 16:0
  - 취소된 조건부, 필요한 기록만 > 최신 기록만: 9B 18:0, 27B 14:0

### ④ "무효 기록만 뺀" 기준 조건 — 검토 결과 새 실행 불필요
- 지금 자료에서 "현재 시점까지 나중의 변경·취소로 효력을 잃은 예약을 뺀 기록"은 모든 시점에서 "최신 기록만"과 같다(2,240/2,240, Codex 검토). 취소 뒤 재예약이 없기 때문이다. 따라서 이 대조는 기존 "최신 기록만" 결과로 이미 확인된다.
- 새 조건이 되는 경우는 두 가지뿐이다.
  - (a) 현재 질문과 관련된 무효 기록만 빼는 라벨 기반 진단
  - (b) 재예약·보완처럼 사건 구조가 다른 새 자료
- 어느 쪽이든 실행 전에 기존 조건과 기록이 실제로 다른지 CPU에서 먼저 확인한다.

### ⑤ 손해 자료 확장 (발표 후, 실행 비용)
- **문제:** 손해 자료가 작고 한 가지 틀이다. 문장 틀 1개, 배달 경로 본 실험 20세션, main 12가족이다.
- **보완:**
  - 요청 문장 틀을 3개 이상으로 늘리고, 아직 쓰지 않은 여행 가족으로 세션을 40개 이상으로 늘린다.
  - 봉인된 시험용 가족(new-b 40개)은 마지막 확인용으로 남긴다.
- **완료 기준:** 유형별 손해의 방향이 문장 틀마다 같다.

### ⑥ 자연 자료의 손해 (발표 후)
- **문제:** 이번에 검토한 공개 갱신 문항에서는 손해가 적게 관측됐다. "필요한 기록만 주기"도 최선이 아니다.
  - BEAM 근거 구간, 27B: 대화 26/28, 필요한 기록만 22/28
  - main의 BEAM 결과: 필요한 근거만 44/52, 예산 채우기 47/52

  즉 자연 자료에서는 "정답 기록 대비 손해"라는 정의가 약하다.
- **보완:**
  - 자연 자료의 손해는 원인이 확인되는 경우만 센다. 예를 들어 옛 값으로 답한 경우이다.
  - main 외부 갱신 방식(현재 근거 + 옛 기록)으로 갱신이 있는 문항을 늘린다.

## 6. 발표에서 쓸 기여 문장

> 기억이 이득과 손해를 만드는 상황을 통제해 만들고, 같은 상태의 결과를 짝지어 다시 계산할 수 있는 자료를 만들었다. 틀린 답이 무효가 된 기록이나 비슷한 다른 기록과 일치하는 유형까지 추적할 수 있다. 전달 형태마다 손해가 나는 유형이 달랐고, 이번에 검토한 공개 갱신 문항에서는 손해가 적게 관측됐다.

**쓰지 않을 표현**
- "기록 목록이 손해를 키운다." 유형에 따라 반대다.
- 배달 경로 세션의 손해를 무기억 대비로 설명하는 것. 그 세션에서 무기억 대비 손해는 0이다. main의 계획 변경 대조에는 7/12가 있다.
- 오답과 일치한 기록을 "원인"으로 확정하는 것.
- "자연 자료에는 손해가 드물다"는 일반화. 공개 자료에서도 손해는 검산할 수 있다.

**함께 밝힐 한계**
- 인공 과제이고 문장 틀이 1개이다.
- 손해 자료는 20세션과 12가족이다.
- 라벨은 사건 기록 규칙이나 구축 에이전트가 만들었다.
- 독립 검산 전이다.
