# 기억의 내용과 사용 안내를 나누어 비교하기

2026-11-05 초안 · 2026-11-06 실행 상태 갱신. 기존 두 대상의 [12회 탐색](reports/2026-11-05-memory-framing-smoke.md)과 새 출처 두 개·대상 네 개의 [24회 확장](reports/2026-11-05-new-content-transfer.md)을 완료했다. 새 회차는 세 조건 모두 6/8 해결, 주 대비 0%p로 득실 방향을 확정하지 못했다. 아래의 더 넓은 후보 비교·인과 가설은 해당 실행으로 모두 검증된 것이 아니다.

**같은 과거 경험도 참고 정보로 제시하는지, 고려할 제안으로 제시하는지, 따를 절차로 제시하는지에 따라 행동과 효용이 달라질 수 있다.** 이 가능성을 별도 연구 질문으로 둔다. 내용의 다양성과 표현 방식의 다양성을 두 축으로 정의하면 무엇을 바꿔서 결과가 달라졌는지 비교하기 쉽다.

초안 당시 카드의 원천 경험은 4개이며 성공·실패 출처가 각각 2개였다. 후속 확장에서 새 출처 2개를 한 번씩 실행해 전체 원천 경험은 6개, 성공·실패 출처는 각각 3개가 됐다. 독립 출처의 수는 여전히 작다. 기존 `facts`와 `procedure` 카드는 정보의 선택·분량·구체적인 이름까지 달라서, 그 차이를 같은 정보의 표현 효과로 해석할 수 없다. 구성요소 기능 검증은 원문 부분의 삭제 비교였고 사용 안내 비교와 다른 개입이다. [초안 당시 데이터 감사](reports/2026-11-05-workspace-data-review.md), [기능 검증](reports/2026-11-05-component-measurement-feasibility.md).

## 다양화할 두 축

| 내용의 후보 유형 | 실제 출처에서 얻을 재료 | 유의할 점 |
| --- | --- | --- |
| 환경·API 관측 | 특정 버전의 지원 옵션, 실제 오류, 반환 형태 | 과거 관측을 현재의 보편적 사실로 승격하지 않음 |
| 코드 탐색 정보 | 확인한 파일·클래스·서로 다른 처리 경로 | 이름과 경로의 현재 존재 여부를 적용성에 포함 |
| 조사·행동 순서 | 재현 → 코드 경로 확인 → 수정 → 검증의 기록 | 전체 성공과 각 행동의 기여를 구분 |
| 실패·반례 | 실행했지만 해결하지 못한 접근, 발생한 오류 | 실패의 원인이 확인되지 않았으면 그대로 명시 |
| 검증 경험 | 로컬 통과와 공식 실패의 차이, 검사의 범위 | 과거 검사가 현재 목표도 검증한다고 가정하지 않음 |
| 적용 조건·불확실성 | 버전, 입력, 설정, 근거가 미치는 범위 | 조건 추가·삭제는 별도의 내용 개입 |

유형은 완전히 배타적인 분류가 아니다. 하나의 카드가 여러 유형을 포함할 수 있다. 첫 비교에는 출처의 어느 명제·문장 구간을 사용했는지 함께 기록한다. 새로운 출처와 저장소를 확보하는 일과 같은 출처에서 문구 변형을 늘리는 일을 별도 집계한다.

| 사용 안내의 후보 | 본문을 사용하는 방식 | 비교에서 바뀌는 것 |
| --- | --- | --- |
| 정보 참고형 | 과거 조사에 관한 참고 정보로 읽음 | 명시적 행동 권고가 약함 |
| 제안형 | 기록된 조사 행동을 현재 과제에서 고려할 선택지로 읽음 | 권고의 존재 |
| 지침형 | 기록된 조사 행동을 현재 과제에서 따를 절차로 읽음 | 권고의 강도 |

문단·불릿·체크리스트·JSON은 **배치와 형식의 축**이다. 조건부 표현은 **적용 조건의 축**이다. 정보형에 없던 조건·근거·경고를 지침형에만 추가하면 정보량도 달라진다. 처음부터 이 축을 모두 함께 바꾸지 않고 각각의 개입 범위를 기록한다.

## 같은 본문으로 만드는 첫 대조

우선 원문을 그대로 둔 채 앞의 사용 안내 한 문장만 바꾸는 비교를 준비한다. 세 조건 모두 출처·공식 결과·적용 한계·근거·본문은 같다. 현재 과제에 옮길 수 있는지 먼저 확인하라는 공통 안내도 동일하게 둔다.

```text
정보 참고형: 다음 기록은 과거 조사에 관한 참고 정보다.
제안형:     다음 기록의 조사 행동은 현재 과제에서 고려할 선택지다.
지침형:     현재 과제에서 다음 기록의 조사 행동을 따르라.

[이하 동일한 출처·관측·행동 기록·결과·적용 한계]
```

이는 **동일 본문의 사용 안내 문장을 바꾸는 효과**다. 과거의 설명을 현재의 권고로 바꾸면 규범적 의미가 달라지는 것이 개입 자체다. 정보형에도 공통 적용성 확인 안내가 있으므로 이를 아무 지시도 없는 순수 정보 처리와 동일시하지 않는다.

Sphinx 8435와 Django 14667의 기존 절차 카드로 각각 세 변형, 총 여섯 개의 [검토용 예시](design-data/memory-framing-examples-20261105.json)를 만들었다. 본문은 원문과 해시가 같고 각 예시 안에서는 사용 안내 한 문장만 다르다는 것을 로컬에서 확인했다. 성공 출처와 실패 출처가 하나씩 있으나 새 원천 경험을 만든 것은 아니다. 실험 은행·실행 설정·결과 표에는 넣지 않았다.

후속 실행 기록: 사용자의 작은 테스트 요청에 따라 이 예시 중 정보형·지침형을 실제 은행으로 만들고 Sphinx 8627·Django 16910에서 무메모리를 포함한 12회를 배정했다. 두 대상 모두 기존에 본 문제이므로 아래의 새 과제 확인 제안과 구분한다. 예시 원문은 그대로 보존했다. 실제 통제·배정·결과는 [별도 보고서](reports/2026-11-05-memory-framing-smoke.md)를 따른다.

예시의 공통 적용성 안내는 연구자가 새로 작성한 것이며 모든 표현 조건에 동일하다. 안내 문장 길이는 서로 다르다. 동일 토큰 수나 순수한 지시 강도의 효과를 이미 통제했다고 주장하지 않는다. 본문 해시 일치는 문자열 보존의 검사이며 출처 내용의 진실성·현재 적용성 검증을 대신하지 않는다.

다음 단계의 자연스러운 전체 재작성 비교에서는 원문에서 명제 목록을 먼저 만들고 각 표현이 어떤 명제를 포함하는지 대응표를 남긴다. 정보형에도 행동형이 언급한 API·순서·조건·실패 결과가 모두 있어야 한다. 대상의 정답·숨겨진 테스트를 보고 누락 사실을 채우지 않는다. 새 사실이 생기면 표현 효과와 내용 추가 효과를 구분한다. 여러 문구 버전을 사용해 한 표현의 우연한 효과에 기대지 않되, 문구 버전을 독립 과제로 세지 않는다.

## 먼저 시험할 질문과 배정

주 질문 후보는 **동일 본문을 지침으로 안내했을 때 정보로 안내했을 때보다 예산 내 해결률과 전체 배정의 평균 비용이 어떻게 달라지는가**다.

첫 실행 후보는 `무메모리 / 정보 참고형 / 지침형`의 세 조건이다. 제안형은 효과가 관측되거나 지시 강도에 관한 별도 질문을 검증할 때 추가할 수 있다. 현재 노트는 실행 배정이 아니며 과제 수·반복 수·예산을 확정하지 않았다. 실행 수는 `대상 수 × 3조건 × 반복 수`이며 필요한 정밀도와 출처·대상 간 변동을 보고 규모를 정한다.

탐색 결과로 조건을 추가하면 별도 회차로 기록하고, 선택한 비교는 새로운 확인 집합에서 검사한다. 진행 중인 고정 배정의 조건·반복 수를 결과에 따라 바꾸지 않는다.

- 같은 출처·대상 쌍 안에서 본문, 전달 시점, 역할, 위치, 도구, 모델, 제공자, 한도, 출처 메타데이터를 고정한다. 본문 해시 같은 불필요한 차이는 모델 입력에서 숨기되 디스크에서는 보존한다.
- 시작에 고정 제공하여 검색·조회 선택 효과를 우선 분리한다. 형식의 효과를 확인한 뒤 자율 조회와 교차한다.
- 반복 블록 안에서 실행 순서를 무작위화하고 시각·캐시를 기록한다. 같은 반복 번호를 동일한 모델 난수로 취급하지 않는다.
- 과제별로 출처 내용을 옮길 조건이 맞는지, 일부만 맞는지, 맞지 않는지, 불명인지 사전에 표시한다. 공개 문제 설명·코드·출처 근거를 쓰고 대상의 실험 결과나 정답으로 정하지 않는다.
- 유형별로 새로운 출처·대상을 넓힌다. 지금까지 본 일곱 대상과 기존 카드로 문구를 다듬었다면 그 대상은 확인 집합과 구분한다.

추가 후보인 ‘일반적인 조사 조언’은 특정 경험 때문인지 일반적인 행동 촉구 때문인지 구분하는 보조 대조다. 일반 조언도 효과가 있을 수 있으므로 무효한 중립 조건으로 취급하지 않는다. 내용이 달라지는 비교라는 점도 남긴다.

## 득실과 행동을 함께 측정한다

고정된 대상·출처 쌍에서 예산 내 공식 해결물 제출 확률을 `p(표현)`, 전체 배정의 평균 비용을 `c(표현)`이라 두면 다음을 비교한다.

```text
정보로 제공한 기억의 전체 효과 = p(정보형) − p(무메모리)
지침 안내의 추가 효과           = p(지침형) − p(정보형)
지침 안내의 추가 비용           = c(지침형) − c(정보형)
```

비용의 양수는 추가 지출이다. 회귀·미제출·인프라 오류도 별도 남긴다. 일부 실패한 실행이나 기억을 따르지 않은 실행을 분모에서 빼지 않는다. 신뢰구간은 비교 단위와 반복 구조에 맞춰 보고하며 서로 다른 문제와 출처에 대한 일반화를 구분한다.

| 관측 | 얻을 수 있는 근거 | 넘어서는 해석 |
| --- | --- | --- |
| 카드 유래 이름 검색·경로 확인 | 제공 내용과 연결되는 관측 행동 | 검색했다는 이유만으로 도움이 됐다고 판정 |
| 수정 전 적용 조건 확인 | 조건 확인 행동의 발생 | 모델의 내부 이해·주의를 확정 |
| 과거와 같은 오류 후 재시도·전환 | 반복·전환의 횟수와 시간 | 최종 결과를 본 뒤 모든 재시도를 낭비로 분류 |
| 공식 해결·유지 테스트·비용 | 최종 효용의 조건별 차이 | 행동 변화만으로 최종 득실이나 매개 원인을 확정 |

행동 지표는 출처·대상 쌍별로 실행 전에 구체적인 명령·파일·패치 조건으로 정의하고 실제 도구 로그로 판정한다. 지침을 따른 실행만 추려 성공률을 비교하면 선택 편향이 생길 수 있으므로 전체 배정을 비교한다. 행동과 성과의 동시 변화는 경로의 단서이며 그 행동이 성과를 매개했다는 완결된 인과 증명은 아니다.

검증할 만한 가설은 다음과 같다. 모두 아직 입증되지 않았다.

1. 적용 조건이 맞을 때 지침 안내는 필요한 탐색을 앞당겨 비용을 줄일 수 있다.
2. 조건이 맞지 않을 때 지침 안내는 과거 경로의 고집·불필요한 수정·회귀를 늘릴 수 있다.
3. 명시적인 적용 조건은 잘못된 전이를 줄일 수 있으나 확인 비용도 늘릴 수 있다.

적용 조건별로 무작위 배정한 표현의 효과 차이는 측정할 수 있다. 하지만 다른 과제 집단 사이의 차이를 곧바로 ‘적용성 하나 때문에 생긴 차이’라고 해석하지 않는다. 적용 조건 자체의 원인을 확인하려면 같은 과제·기억에서 조건의 명시 여부 등을 별도로 조작해야 한다.

## 관련 연구와 이번 제안의 범위

[Reflexion](https://arxiv.org/abs/2303.11366)은 과제 피드백을 언어로 회고해 기억에 보존하고 후속 시도에 활용한다. [ExpeL](https://arxiv.org/abs/2308.10144)은 훈련 과제의 경험에서 자연어 지식을 추출하고 추론 시 과거 경험과 통찰을 회상한다. 이들은 경험을 저장·변환해 행동에 활용하는 선행 접근이며, 동일 본문의 정보형·지침형 효과를 우리 조건에서 입증해 주는 결과는 아니다.

내용과 사용 안내를 교차시키는 설계는 여러 요인과 상호작용을 분리해 보는 [요인 실험의 원리](https://www.itl.nist.gov/div898/handbook/pri/section3/pri3331.htm)를 참고한다. 구체적인 기억 분류, 개입, 행동 지표와 표본 설계는 우리의 연구 제안이다. 선행 접근과 겹치는 재현부터 시작해도 되며, 이후의 기여는 어떤 조건에서 표현이 득실을 바꾸는지 새 데이터로 확인하는 데 둔다.
