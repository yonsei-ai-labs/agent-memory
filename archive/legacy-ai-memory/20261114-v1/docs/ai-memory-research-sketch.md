# AI 에이전트 메모리 득실 연구 스케치

2026-11-02 · 탐색적 파일럿 초안

후속 조사: [메모리 득실 문헌 검토](ai-memory-benefit-harm-review.md)와 [인과 효과 검증 설계](ai-memory-causal-evaluation-plan.md)에 선행 연구의 근거·한계, 대조 조건, 반복 실행, 비용과 누출 통제를 상세히 정리했다.

현재 실행 권고는 2026-11-03의 [재검토와 첫 실험 실행안](ai-memory-pilot-reassessment.md)을 따른다. 첫 주 비교는 무메모리·시작 제공·자율 검색으로 갱신했다. 아래는 초기 구상이며 원본·요약 비교는 후속 진단으로 남긴다.

모델과 비용은 [Luna·DeepSeek 중심의 진행안](ai-memory-model-selection.md)에 정리했다. 두 모델의 짧은 무메모리 점검 후 주 모델 하나로 탐색하고, 필요한 개입과 모델 간 확인에 예산을 사용한다.

**작은 벤치 실험에서 성공과 실패 경험을 모으고, 이를 기억으로 제공했을 때 다음 문제의 수행이 어떻게 달라지는지 살펴본다.** 기존 연구와 유사한 설정으로 시작해 실행 과정에서 인사이트와 후속 가설을 찾는다. 초기 목표는 비교 결과와 근거 로그가 있는 사례를 확보하는 것이다.

대상은 에이전트가 이전 과제의 실행 경험을 외부에 저장하고, 다른 과제를 풀 때 다시 사용하는 메모리다. 기존 벤치의 문제와 채점기를 활용하고, 경험 데이터는 에이전트의 실제 실행에서 얻는다.

**먼저 관찰할 질문은 다음과 같다.**

- 메모리가 성공률을 높이거나 탐색 비용을 줄이는가? 반대로 실패나 비용 증가를 만드는가?
- 도움이 된 것은 과거 경험에 담긴 사실 정보인가, 행동 순서나 전략에 대한 지침인가?
- 실패 경험에서도 유용한 기억을 얻을 수 있는가? 성공 경험에서 만든 기억도 해로울 수 있는가?
- 도움이 되거나 해로웠던 기억에는 어떤 공통점이 있으며, 현재 문제와의 관계는 어떠한가?

**첫 파일럿은 벤치 하나와 에이전트 하나로 시작한다.** SWE-bench의 작은 부분집합과 mini-SWE-agent를 우선 후보로 둔다. Terminal-Bench도 후보이며, Harbor는 mini-SWE-agent를 지원하므로 같은 에이전트를 기반으로 확장할 수 있다. 구체적인 벤치 버전, 문제 목록, 모델과 예산은 실행 전에 정한다. [mini-SWE-agent 실행 문서](https://mini-swe-agent.com/latest/usage/swebench/), [Harbor 지원 에이전트](https://docs.harborframework.com/agents/pre-integrated-agents)

1. 경험 수집용 문제와 평가용 문제를 미리 분리한다. 규모 예시는 각 10문제이며, 실행 부담을 확인하기 위한 출발점이다.
2. 수집용 문제를 메모리 없이 실행하고 명령, 관측 결과, 수정 내용, 최종 채점 결과를 보존한다. 성공과 실패를 모두 남긴다.
3. 같은 실행 기록으로 원본 경험과 요약 메모리를 준비한다. 요약에는 관측 사실, 시도와 결과, 추출한 교훈, 적용 조건, 원본 근거를 남긴다. 원본 로그도 계속 보존한다.
4. 별도의 평가 문제를 아래 세 조건에서 실행한다. 시작 시 관련 경험을 입력에 넣는 방식으로 먼저 실험한다.

| 조건 | 제공하는 과거 경험 | 비교 목적 |
| --- | --- | --- |
| 메모리 없음 | 없음 | 기준 성능과 비용 |
| 원본 경험 | 선택한 과거 실행 기록 | 과거 경험에 접근하는 효과 |
| 정리한 기억 | 같은 경험에서 추출한 요약과 교훈 | 경험을 정리해 제공하는 방식의 효과 |

모든 조건에서 현재 문제의 대화 맥락과 기본 도구는 유지한다. 모델, 에이전트, 문제의 초기 환경과 실행 예산을 맞추고, 원본과 요약 조건에는 같은 과거 경험을 선택한다. 주입 분량과 절단 방식도 기록한다. 평가 동안 기억 저장소를 고정하고 실행 간 정보를 섞지 않는다. SWE-bench에서는 과거 경험이 평가 대상 코드 시점보다 앞서는지도 확인한다. 평가 문제의 정답과 숨겨진 채점 테스트는 기억에 포함하지 않는다.

**득과 실은 성능과 비용을 나누어 기록한다.**

| 관점 | 기록할 내용 |
| --- | --- |
| 문제 해결 | 공식 채점 성공률과 메모리 없는 조건 대비 차이 |
| 관측된 개선과 회귀 | 실패에서 성공으로, 성공에서 실패로 바뀐 사례 |
| 효율 | 실행 시간, 토큰·호출 비용, 행동 횟수와 기억 생성·검색 비용 |
| 수행 과정 | 먼저 탐색한 위치, 선택한 명령, 반복 시도, 반대 증거에 대한 대응 |

각 조건을 반복 실행해 변동성을 살핀다. 한 번의 성공·실패 전환은 원인 분석 후보로 취급한다. 작은 파일럿에서는 개별 기억의 유해성을 확정하기보다, 추가 확인이 필요한 사례를 찾는다. 실패로 일찍 끝나 비용이 줄어든 경우도 있으므로 비용과 성공률을 함께 해석한다.

**기억의 내용과 실제 행동을 함께 살펴본다.** 처음에는 다음 특징을 관찰 후보로 둔다. 이들은 아직 검증되지 않은 가설이며, 실패 사례뿐 아니라 성공하거나 별 영향이 없었던 사례에서도 비교한다.

- 사실 정보와 행동 지침 중 어떤 내용이 사용됐는가.
- 적용 조건이나 예외가 명시되어 있는가.
- 기억이 전제한 버전·도구·환경이 현재와 맞는가.
- 관측 근거보다 강한 일반화나 지시가 추가됐는가.
- 현재 실행에서 반대 증거가 나왔을 때 접근을 바꾸는가.

기억의 가치는 현재 문제와 환경에 따라 달라질 수 있다. 또한 과거 실행이 실패했다는 사실만으로 특정 시도가 실패 원인이었다고 단정하지 않는다.

**후속 실험은 관찰된 현상에서 정한다.** 특정 지침이 행동을 바꾼 사례가 반복되면 같은 경험을 사실형과 지침형으로 제공해 비교하거나, 의심되는 문장만 제거·수정해 다시 실행한다. 지침의 효과를 볼 때는 일반적인 문제 해결 조언도 대조 조건으로 고려한다. 발견한 패턴은 별도 문제나 추가 실행에서 확인한다. 지속적인 기억 축적·갱신과 Verified 규모로의 확대는 이후 단계로 둔다.

첫 산출물은 **조건별 결과표, 원본 로그와 제공한 기억, 근거가 붙은 성공·실패 사례, 다음에 검증할 가설**이다. 준비할 항목은 벤치와 문제 목록, 모델·실행 예산, 기억 추출 형식, 로그 저장 형식이다.

선행 연구의 출발점으로는 성공·실패 경험에서 전략을 추출하는 [ReasoningBank](https://arxiv.org/abs/2509.25140)와 실제 저장소 이력을 이용해 메모리의 이득과 회귀를 분석하는 [MemDev-Bench 프리프린트](https://arxiv.org/abs/2610.27524)를 참고한다. 유사한 실험을 재현하면서 관찰과 설명을 구체화한다.
