# 11월 8일 추가 문헌 확인: 선택기 자체보다 검증할 관계를 좁히기

작은 선택기를 붙이거나 효용을 학습하는 것만으로는 새로운 기여라고 보기 어렵다. 이번 실험의 후보 기여는 **코드 경험의 직접 적용성, 수정해서 활용할 가치, 작업자에게 이미 불필요한 정보**를 실행 근거와 함께 구분하는 데 있다. 아직 이를 실증한 결과는 아니며, 아래는 문헌이 실험 설계에 주는 제약과 아이디어다.

| 확인한 1차 자료 | 가져올 점 | 우리 결과에 적용할 한계 |
|---|---|---|
| [Agent Memory as Recommendation](https://arxiv.org/html/2610.34673v1), 2026-10-26 preprint | 후보 검색·학습 순위·토큰 예산 아래 묶음 구성을 분해한다. 값싼 특징과 학습 ranker도 강한 비교 대상이다. | 후보 네 개의 판독 정확도를 큰 기억 저장소의 검색 성능으로 부르지 않는다. 전체 기억 조건도 측정해 단일 기억의 점수만으로 묶음 가치를 가정하지 않는다. |
| [What Should an Agent Remember?](https://arxiv.org/abs/2610.00366), 2026-09-30 preprint | 보존된 정보에 접근할 수 있는가와 그 안에서 잘 고르는가를 분리한다. | 우리의 full/procedure 비교는 보존 내용의 변화다. 같은 내용에서 판독기만 바꾼 효과와 별도 보고해야 한다. |
| [Lightweight Chunk Selection for Mobile RAG](https://arxiv.org/html/2608.03148v1), 2026-08-04 preprint | 작업 모델의 질문 hidden state와 검색 표현을 결합하는 작은 MLP를 제안한다. | 작은 MLP 자체의 신규성을 주장하기 어렵다. 현재 dense 작업자는 MoE routing 신호가 없고, 생성 전 표현을 얻는 추가 비용도 기록해야 한다. |
| [MemPilot](https://arxiv.org/html/2610.06830v1), 2026-10-05 preprint | 성능·비용·지연의 목표를 나누고, 처리 단계의 한계 효용을 추정한다. | 한 성공 점수와 토큰을 임의 가중합한 단일 최고값만 보고하지 않는다. 우리 단일 단계의 모든 행동 비교는 이 논문의 다단계 RL 재현이 아니다. |
| [Sufficient Context](https://arxiv.org/abs/2411.06037), ICLR 2025 | 근거가 충분한지와 작업 모델이 실제로 활용하는지를 구분한다. 불충분한 근거도 작업자에게 유용할 수 있다. | 관계 정답을 작업자 성과의 정답으로 그대로 복제하지 않는다. 직접 재사용에 실패하는 경험의 원리를 작업자가 수정해 활용하는 경우도 측정한다. |
| [A Reality Check on Context Utilisation](https://aclanthology.org/2025.acl-long.968/), ACL 2025 | 합성 문맥에서의 성공이 실제 검색 문맥의 다양성과 복잡성을 대변하지 않을 수 있음을 보인다. | 실제 라이브러리를 실행했어도 우리의 adapter는 작성한 미니 과제다. 자연 SWE 경험과 실제 작업 로그에 대한 후속 확인이 필요하다. |

논문에 보고된 수치는 그 저자들의 과제·모델·비용 체계에 한정된다. 여기서는 새로운 SOTA 모델 추천이나 수치 재현의 증거로 사용하지 않았다. preprint의 주장과 우리의 실행 검산을 구분한다.

## 당일 비교에 연결한 학습 아이디어

1. **두 목표가 서로 다른 관계를 배우게 하기.** [PCGrad](https://arxiv.org/abs/2001.06782)는 충돌하는 task gradient를 보정한다. 범위의 두 판단이 뒤섞인 기존 실패에 맞춘 비교다. 개발의 어려운 조건에서 개선은 관측했지만, 한 seed와 제한된 범위 진단이므로 일반 효능이나 실패의 단일 원인을 증명하지 않는다.
2. **변하지 않아야 할 판단을 명시적으로 유지하기.** 현재 요청을 유지하고 검사 이력만 바꾼 사례에서는 요청 판단이 유지돼야 한다. symmetric KL을 넣되 같은 대조 배치를 기본 CE에도 제공한다. 이는 [R-Drop](https://arxiv.org/abs/2106.14448)의 dropout 일관성을 재현한 것이 아니라 서로 다른 관측 사이의 조건부 일관성이다.
3. **대조 손실을 바르게 비교하기.** [Supervised Contrastive Learning](https://arxiv.org/abs/2004.11362)을 두 관계별 projection에 적용했다. 이전 상대 margin과 별개이며, 현재 설정에서는 어려운 조건을 해결하지 못했다. 대조 손실만 작아졌다는 이유로 관계를 배웠다고 판단하지 않는다.
4. **중간 판단을 배우고 조합하기.** [Concept Bottleneck Models](https://arxiv.org/abs/2007.04612)를 참고해 반환값·원본 변경을 보조 감독하거나 명시적으로 조합한다. 조합 규칙과 네 절차를 사람이 정했으므로 일반적인 코드 추론을 모델이 전부 배운 것은 아니다. 가능한 두 구현의 soft probability를 곱하는 것도 독립성 가정이며 신뢰도가 자동 보정되는 것은 아니다.
5. **한 벡터 압축 이후에 잃는 정보를 확인하기.** [Poly-encoders](https://arxiv.org/abs/1905.01969)의 구조적 아이디어를 참고해 고정 encoder의 line-end 표현에 작은 attention reader를 학습한다. 실제 구현은 우리 진단용이며 해당 논문의 재현은 아니다. pooled 조건과 같은 parameter 수·초기값·배치를 맞추고, 더 오래 학습한 기존 MLP와도 비교한다.

## 이번 자료로 할 수 있는 주장과 다음 자료가 필요한 주장

범위 자료는 역할 분리의 학습 가능성을, API 자료는 명시된 함수 계약과 과거 절차의 적용성을 진단한다. 여기에 고정 코드 작업자의 기억 제공/보류 실행을 붙여야 그 작업자에 대한 관측 효용을 얻는다. 이 세 점수의 분모를 합치지 않는다.

효용 자료에서 제일 먼저 확인할 것은 “학습하면 높아지는가”가 아니라 “현재 상태마다 더 좋은 기억 행동이 달라지는가”다. 무기억 또는 특정 고정 행동이 항상 최선이면 복잡한 선택기를 학습시킬 근거가 약하다. 이 경우 부정 결과를 남기고, 실제 코드 경험의 전제 변화·검사 생략·잘못된 수정 유도 같은 더 적절한 사건으로 자료를 보강해야 한다. 성과가 좋은 사례만 골라 같은 평가를 다시 꾸미지 않는다.
