# 메모리 득실 연구: 논문 재검토와 다음 실험 아이디어

작성: 2026-11-07. 이날 확인한 논문 버전의 본문·실험·관련 부록을 기준으로 정리했다. 논문의 결과, 기존 실험에서 새로 확인한 관찰, 아래의 연구 제안을 구분한다. 이번 작업의 새 모델/API 실행은 **0회**다.

## 판단: 방향은 유지하되, 질문을 더 좁힌다

**“기억이 유용하기도 해롭기도 하다” 자체는 이미 연구되고 있다. 우리가 파고들 만한 질문은 같은 경험에서 어떤 정보를 보존하거나 바꾸었을 때 실제 코드 해결 성과와 비용이 달라지는가다.** 원본 경험과 가공 기억의 비교, 같은 정보의 서술·지시 표현 비교, 적용 확인 비용의 분리를 차례로 진행하는 편이 좋다. 새로운 기억 시스템 전체를 먼저 만드는 것보다 현재 연구 질문과 데이터 제작 부담에 잘 맞는다.

특히 [Memory Tax](https://arxiv.org/html/2610.34073v1)는 기준 기억 방식 대비 득실을 직접 분석하고, [MemDev-Bench](https://arxiv.org/html/2610.27524v1)는 코드 에이전트에서 원본 실행 과정과 여러 메모리 시스템을 비교한다. 따라서 일반적인 득실 분해만으로 새로움을 주장하기는 어렵다. **출처 근거를 통제한 내용 개입을 실제 패치 채점과 연결하고, 해결 도달·검증·제출 비용을 구분하는 연구**가 더 선명하다. 이는 이번 검토에서 얻은 연구 방향이며 최초성의 확인은 아니다.

현재 결과도 좁게 읽어야 한다. [처음 32회](reports/2026-11-07-prescription-validation.md)의 FP−F는 +25%p였지만, [추가 16회](reports/2026-11-07-prescription-replication.md)에서는 0%p였다. 누적 48회의 +16.7%p는 결과를 본 뒤 표본을 확대한 **탐색적 합계**다. 출처 하나·대상 두 개이며, P는 지시 말투 외에 함수명·수정 정보·검증 정보·길이도 추가한다. 이를 “행동 지침이 사실보다 우수하다”는 증거로 삼을 수 없다.

### 2.1 실제 사용한 절차 기억에는 출처 실행의 도구·검사 정보가 빠졌다

여기서 얻은 가설은 구체적이다. **최종 코드 수정 요령만 요약하면 재사용 가능한 실행 과정 정보가 빠지고, 이를 근거와 함께 복원하면 일부 시행착오를 줄일 수 있다.** Memory Tax와 MemDev-Bench에서 얻은 아이디어를 우리 로그에 연결한 추론이다. 현재 대상 결과를 이미 봤으므로 다음 확인은 새로운 source/target에서 해야 한다.

## 3. 가장 먼저 해볼 실험: 무엇을 보존했는가

### 질문과 네 조건

같은 출처 경험을 고정하고 아래 네 조건을 비교한다. R은 무작위 전체 이력 투입이 아니라 사전에 정한 규칙으로 추출한 원문 근거 묶음이다. 선택 규칙·대상 과제 선정은 대상 결과를 보기 전에 고정한다.

| 조건 | 제공 내용 | 비교로 알 수 있는 것 |
| --- | --- | --- |
| N | 외부 출처 경험 미제공 | 실제 무기억 기준 |
| R | 출처의 원문 관측·명령·결과 발췌 | 과거 경험의 원문 근거를 제공한 전체 효과 |
| S | 그 출처에서 만든 해결 요령 카드 | 현재와 비슷한 가공 기억의 전체 효과 |
| S+O | 같은 S에 출처의 도구·검사 과정 관측 O를 복원 | 그 요약에 과정 근거를 더한 효과 |

**주 대비는 S+O−S**, 보조 대비는 R−N, S−R로 둔다. 단계 하나씩 진행하기 위해 말투·검색·축적 알고리즘은 이 실험에서 함께 바꾸지 않는다. 이는 본 프로젝트의 제안이며 위 논문의 실험을 그대로 재현하는 구성이 아니다.

성과 또는 비용 지표에 대한 조건별 평균을 V라 하면, 다음은 우리가 택한 기준에 대한 산술 분해다.

```text
경험 제공 효과       = V(R) − V(N)
기억 가공의 추가 효과 = V(S) − V(R)
가공 기억의 순효과    = V(S) − V(N)
                     = 앞의 두 효과의 합
```

V가 성공률일 때와 비용일 때를 따로 계산한다. 낮을수록 좋은 비용의 부호를 성공률과 혼동하지 않는다. R이 길면 S−R에는 압축·정보 선택·길이·구조가 함께 들어간다. S+O도 길이와 정보량을 함께 더한다. 처음에는 **제공 패키지의 효과**로 보고한다. 내용 단위 O 자체의 기여를 더 좁히려면 후속으로 R에서 O 삭제, S에 O 복원, 비슷한 길이의 다른 출처 단위 삭제·복원을 대조한다. 무관 문장이나 일반 조언도 행동을 바꿀 수 있으므로 이를 완전히 비활성인 대조로 가정하지 않는다.

### 데이터 제작 부담을 줄이는 방법

새 문제나 정답을 사람이 만들 필요가 없다. 기존 출처의 명령·출력·패치·공식 판정을 근거 단위로 고정하고, 원문 발췌 R과 요약 S의 각 주장에 근거 ID를 연결한다. O는 관측한 내용만 담고 현재 대상 환경에도 그대로 맞는다고 단정하지 않는다. source 결과를 관측했더라도 **대상 정답 패치·숨겨진 검사·사후 오류 진단을 기억 작성에 넣지 않는다.**

당장 사용할 수 있는 [과정 정보 카드 초안](reports/data/literature-revisit-20261107/process-memory-prototype.json)을 만들었다. 실제 소스의 세 관측에만 연결한 **검토용 자료**이며 실행 은행에는 넣지 않았다. 과거 사실 서술과 조건부 안내 표현을 구별했고, 후자는 연구자가 작성한 표현임을 표시했다. 이 초안이 이미 검증된 좋은 기억이라는 뜻은 아니다.

새 source 4개 × 대상 각 2개 × 4조건 × 2반복이면 대상 실행은 64회다. 이것은 제작·실행 규모 예시이며 필요한 표본 수나 확인 실험의 최종 배정이 아니다. 같은 대상에 다른 출처 기억도 배정해야 기억의 적용성과 대상 자체의 난이도를 구분하기 쉬워진다. 새 출처 확보와 원본 실패/정답 성공 대조부터 점검한다. 동일 두 과제의 반복만 늘려 유의한 수치를 찾지 않는다.

## 4. 그다음: 같은 정보를 서술할 때와 지시할 때

사용자가 처음 제안한 질문을 더 직접적으로 검증하는 실험이다. **정보 종류와 문장 표현을 서로 다른 축으로 다룬다.** 해결 절차를 과거형으로 서술해도 절차 정보이며, 도구 관측을 명령형으로 바꾸었다고 새 해결 원리가 되는 것은 아니다.

먼저 원자적 주장 목록을 고정한다. 양쪽에 같은 함수·API 식별자, 조건, 수정 내용, 검사 방법, 관측 결과, 출처 근거가 들어가도록 점검한다. 그 뒤 한쪽은 “과거에는 X를 수행했다”, 다른 쪽은 “해당 조건이면 X를 수행하라”로 작성한다. 조건부 적용 문장을 지시형에만 추가하면 정보도 달라지므로 서술형에도 같은 적용 조건을 넣는다. 길이·순서·헤더·출처 판정·마지막 예산/제출 안내를 맞추고 여러 표현 템플릿을 사용한다.

주 대비는 **같은 사실 집합에서 표현을 바꾼 평균 효과**다. N을 함께 두어 서술형과 지시형이 각각 무기억보다 좋은지도 본다. 지시형이 서술형을 이겼어도 둘 다 N보다 낮으면 순이득을 주장할 수 없다. 완벽한 의미 동등성을 단어 수만으로 증명할 수 없으므로 주장 단위 대조표와 독립 검토를 남긴다.

기존 F/FP는 정보량이 다르고, 앞선 동일 body 안내 비교는 바깥 사용 안내만 바꿨다. 새 실험과 구분한다. 과정 정보 복원 실험에서 쓸 만한 단위가 확보된 뒤 이 비교를 진행하면 카드 제작 부담을 줄일 수 있다.

## 5. 적용 조건은 문구보다 행동 절차로 검사한다

BASM과 MemHarness를 참고하면 다음 질문은 “주의 문장을 읽었나”보다 **현재 상태와 기억의 전제를 비교하고, 맞지 않으면 사용을 보류했나**다. 다음은 API로 가능한 별도 진단 설계다.

정해진 시점까지의 동일한 관측 이력·작업 트리를 보존한 뒤, 남은 실행을 `기억 없음/있음 × 일반적인 현재 상태 재검토 안내 없음/있음`의 네 조건으로 나눈다. 일반 재검토 안내는 두 기억 조건에서 동일하게 준다. 기억 전제를 비교하는 자세한 전용 절차를 추가한다면 그 자체를 별도 개입으로 기록한다. 그래야 추가 숙고·재검토만의 효과와 기억이 있을 때의 추가 효과를 구분할 수 있다.

분기 시점은 고정 응답 번호 또는 사전 정의한 사건과 미발생 시점 규칙으로 정한다. 좋은 패치가 나온 이력만 골라 분기하지 않는다. 현재 checkpoint 구현은 `git diff --binary HEAD`만 저장하므로 이 용도로 충분하지 않다. **미추적 파일을 포함한 파일 상태, 대화·도구 이력, 남은 예산**을 복원하는 작업이 더 필요하다. API 내부 난수까지 복제했다고 가정하지 않는다.

이 비교는 해당 관측 이력에서 시작한 **이후 실행의 조건부 효과**다. 처음부터 기억을 쓰는 전체 정책의 효과와 다르다. 선행 구간의 비용도 전체 비용에 포함하고, 마지막에는 새 과제의 전체 실행으로 확인한다. MemHarness식으로 상태를 인위적으로 변경한 사례는 보조 진단 세트로 분리하며 표준 SWE-bench 해결률에 합치지 않는다.

## 6. 검증은 이득이면서 비용일 수 있다

AMV-Guard에서 가져올 핵심은 “항상 더 확인하라”보다 **후보 행동을 바꿀 수 있는 전제를 확인하는가**다. 예를 들어 과거 테스트 명령을 재사용하려 할 때 실행기 존재 여부는 관련 전제이고, 출처 전체 재현을 매번 수행하는 것은 별도의 비용을 만든다. 후보 행동을 고정한 진단과 에이전트가 자유롭게 다시 계획하는 전체 실행을 분리한다.

후속 비교는 동일 카드에서 추가 확인 없음, 일괄 확인 안내, 행동 전제에 대한 최소 확인 안내다. 일반 재검토나 무기억 상태의 확인도 대조해 “추가 숙고 자체”를 함께 평가한다. 안내만 제시한 것과 실제 확인 도구를 강제한 것은 다른 처치이므로 혼용하지 않는다. 도구 호출·모델 요청·실행시간·최종 제출까지 모두 센다.

현재 가까운 대상에서 제출 패치 15개는 모두 성공했지만 9회는 미제출이었다. 이것만으로 그 9회가 이미 정답에 도달했다거나 과도한 검증 때문에 실패했다고 말할 수 없다. 다음 실행에서는 동일한 사전 시점에 패치를 저장하고 **실행 종료 후** 공식 검사한다. 동일 패치 해시·기반 이미지·검사 명세의 중복 채점은 묶을 수 있다. 저장 시점이 성기면 “최초로 관측한 통과 시점”이며 정확한 최초 해결 시점은 아니다.

주 지표는 여전히 예산 내 실제 제출·공식 성공이다. 중간 패치가 사후 통과해도 당시 에이전트가 성공을 알았거나 짧은 예산에서 제출했다고 세지 않는다. 검증 비용 감소와 해결률 증가를 각각 보고한다.

## 7. 득실을 어떻게 수치로 정의할 것인가

기억 m, 대상 t, 예산 b와 고정된 실행 조건에서 다음을 구분한다.

```text
δ(m,t,b) = P(예산 내 공식 성공 | m 제공)
           − P(예산 내 공식 성공 | m 미제공)

Δ비용(m,t,b) = E[전체 비용 | m 제공] − E[전체 비용 | m 미제공]
```

실제 배정 전체를 분모로 삼고 정상 한도 미제출은 전달 성공 0으로 센다. 평가 장애·API 오류는 사전 규칙으로 별도 기록한다. 반복과 실행 순서 무작위화로 선택된 사례의 평균 대비를 추정할 수 있지만, 서로 다른 과제·출처의 효과까지 한 카드의 반복으로 추정할 수는 없다.

“도움이 된 기억 몇 개/해로운 기억 몇 개”도 기준을 정하면 측정 목표가 된다. 사전 정의한 source/target 사례 집합에서 양의 δ의 크기와 음의 δ의 크기를 각각 평균내는 방식이다. 다만 적은 표본의 추정값을 양수/음수로 나눠 평균내면 잡음을 득실로 세는 편향이 생긴다. 불확실성 구간·별도 확인 자료·사전 최소 차이를 사용하고 **미확정** 범주를 유지한다. 단 한 번의 `무기억 성공/기억 실패` 전환은 확정된 유해 기억 라벨이 아니다.

MemRL의 재사용 보상, CICL의 예측 점수, ACE의 자체 평가 카운터는 유용한 정책 입력 후보지만 위 δ와 같지 않다. 장기적으로는 해당 점수로 제공/보류를 예측하고, 새 과제에서 항상 제공·항상 보류와 비교한다. 현재 한 출처와 두 대상의 결과로 선택기를 학습·평가했다고 주장하지 않는다.

결과를 본 뒤 찾은 위험 특징은 가설로 남긴다. 예컨대 오래된 식별자, 전제 누락, 검증 정보 손실이 후보라면 다른 정보는 유지하고 해당 부분을 삭제·복원·완화하는 새 실행으로 검사한다. 행동 변화만 확인되면 행동 효과까지, 성과·비용까지 바뀌면 그 변화까지 주장한다. 행동이 성과를 매개했다는 인과 주장에는 더 강한 개입과 가정이 필요하다.

## 8. 기억 축적·재작성 연구는 별도 단계로 둔다

Useful Memories…와 ACE에서 얻을 장기 아이디어는 **불변의 원본 경험 + 근거에 연결한 가공 카드 + 편집 이력**이다. 같은 경험 순서에서 원본 추가만 하는 방식, 새 경험을 독립 요약해 추가하는 방식, 기존 요약을 반복 재작성하는 방식을 비교할 수 있다. 평가용 새 과제는 고정하고 그 결과로 요약을 다시 고치지 않는다.

현재는 적용·표현·검색·축적을 한 번에 바꾸지 않는다. 우선 한 경험의 내용 효과를 측정할 수 있어야 여러 경험의 축적 손실을 해석할 수 있다. 이는 우선순위 판단이며 재작성 손실이 현재 데이터에서 확인됐다는 뜻은 아니다.

## 다음 작업의 순서

1. 새 출처 후보의 환경·공식 대조와 원문 근거 추출부터 점검한다. 기존 48회는 가설 발견 자료로 보존한다.
2. N/R/S/S+O의 실행 가능한 소규모 계획을 고정한다. 주 대비·전체 예산·공통 제출 안내 위치·중간 패치 저장·배정 순서·중단 규칙을 먼저 정한다.
3. 과정 정보가 성과나 비용에 영향을 주는지 관찰한 뒤, 같은 주장 집합의 서술/지시 비교로 좁힌다. 결과가 없으면 적용 조건·예산·과제 구성 중 무엇이 구별되지 않았는지도 기록한다.
4. 여러 출처와 대상에서 반복되는 신호가 생기면 상태 비교·선택적 적용·축적 방식으로 확장한다. 동일 과제에서 조건을 계속 바꾸며 얻은 개선을 독립 확인으로 세지 않는다.
