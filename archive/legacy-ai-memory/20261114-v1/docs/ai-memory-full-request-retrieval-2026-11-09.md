# 전체 질문과 과거 기억 은행을 이용한 관계 검색 실험

2026-11-09, GPU 할당 전 고정한 계획. 관계 기반으로 필요한 기억을 찾는 학습을 먼저 시험하고, 실제 득실 검증은 별도로 유지한다.

## 연구 질문

참조 문장 하나와 6개 후보를 주던 조건에서 벗어나, **원래 요청 전체와 당시까지의 모든 과거 기록을 주어도 작은 모델이 필요한 여러 기록을 찾을 수 있는가?** 최종 결과는 검색 성적이며 작업자의 성공·비용 개선으로 해석하지 않는다.

기존 MemoryArena 여행 자료의 공개 참조 계획을 재사용한다. 새 에이전트 경험을 생성한 것은 아니다. 기존 기본 계획 45개의 train/dev/test 30/7/8 분할을 유지한다. 같은 test 계획은 이미 이전 실험에서 검토됐으므로 새 출처 일반화 검증이 아니다. 원시 질문을 그대로 사용하되, 이름·날짜·항목을 명확히 연결할 수 없는 관계가 하나라도 있으면 해당 질문을 제외한다. 이는 평가를 쉬운 명시적 관계로 제한하는 선택이다.

## 입력과 정답

- 원래 전체 질문: train 813, dev 189, test 219. 독립 경험 수가 1,221개라는 뜻은 아니다.
- 당시 과거 기억 26–336개. 현재 질문의 정답과 미래 기록은 제외한다.
- 질문마다 정답 기억 1–12개. 같은 기록이 재사용·비교에 모두 쓰이면 검색 정답은 하나다.
- 기준은 명시적으로 지칭한 사람·날짜·항목의 기록이다. 같은 값의 대체 기록이나 암묵적으로 도움 되는 기록까지 정답에 넣지는 않는다.
- 과거 참조가 생략된 날짜를 쓰는 경우 기존 생성 규칙처럼 현재 요청 날짜를 적용한다. 주석 규칙을 그대로 실행하는 기준선은 구성상 100%다.

원시 데이터 revision `da1a37c8b19280e18627ca01cf368195a5e1d92e`, SHA256 `2f955d444f6f3ad3c5da2064359ab19f8fc1f90621ff9d00723a450a009c3732`. 원문·과거 기록·분할·참조 위치를 전수 재구성하고 train/dev의 18개 질문을 표본 검토했다. 모델 토크나이저로 질문 지시문과 기록 길이의 합 상한이 682토큰이므로 768 이내에서 자르지 않는다. 표본 검토는 독립 이중 주석이 아니다.

## 고정 비교

| 방법 | 입력과 학습 |
| --- | --- |
| BM25 | 전체 질문과 모든 기록, 서수 정규화 |
| 고정 Harrier 임베딩 | 질문만 검색 지시문, 문서는 지시문 없이 인코딩, cosine |
| BM25+임베딩 | RRF 상수 60, 상위 32개 후보 |
| 고정 joint encoder + MLP | 전체 질문과 기록을 함께 읽은 마지막 토큰, 1024→128→2 판독층 |
| LoRA + 같은 MLP | q/v rank 8, alpha 16, 동일 입력·손실·초기 head·학습 표본 |
| 주석 규칙 | 구성상 완전한 일치 기준. 학습 모델의 필요성을 지지하는 독립 기준선이 아님 |

Harrier `microsoft/harrier-oss-v1-0.6b`, revision `f9b9dc8d367d443f2479d27aa5d8d2850c0774ee`. 마지막 토큰 풀링과 검색 질문 지시문은 [공식 모델 카드](https://huggingface.co/microsoft/harrier-oss-v1-0.6b/blob/f9b9dc8d367d443f2479d27aa5d8d2850c0774ee/README.md)를 따른다. joint 판독은 우리 실험용 추가 구조다.

재순위화 두 방법은 같은 상위 32개만 순서를 바꾼다. 평가 후보에 정답을 강제로 삽입하지 않는다. 학습은 모든 정답과 hybrid 검색의 높은 음성 후보를 합해 질문당 16개를 사용한다. 균형 이진 분류 손실과 모든 정답에 균등 질량을 둔 순위 손실(가중치 0.2)을 함께 적용한다. 질문당 한 업데이트, seed 731. 고정 MLP 12epoch, LoRA 2epoch이며 dev 계획별 macro nDCG@10이 가장 높은 첫 checkpoint를 선택한다. 업데이트 수 차이는 명시하며 동일 학습량의 구조 우열로 해석하지 않는다. head LR 0.001, LoRA LR 0.0001.

## 평가와 누출 방지

Recall@5/10/20/32, nDCG@10, 필요한 기억을 전부 포함한 질문 비율을 질문별·기본 계획별로 보고한다. Recall@32는 앞단 검색 상한이다. 표본 수는 계획 8개도 함께 적는다.

학습 환경에는 test 라벨을 보내지 않는다. 정답을 제거한 질문도 함께 보내면 원본과의 차이로 라벨을 알아낼 수 있으므로 **missing 변형은 전부 로컬에 남긴다**. 평가용 원래 후보 상위 44개를 미리 점수화하고, 로컬에서 정답을 제거한 고정 hybrid 순서의 상위 32개를 재구성한다. 제거 후 BM25의 IDF와 임베딩을 다시 계산하는 실험은 아니다. 최대 정답 12개라 44개 안에 필요한 32개가 남는다.

보류 임계값은 dev의 위 제거 진단에서 잘못 제공한 비율 5% 이하를 만족하면서 원래 질문의 정답 전달을 최대화하도록 정한다. 구현은 임계값 이상인 기록을 모두 선택하고 계획별 macro recall을 최대화한다. 동률이면 높은 임계값을 택한다. 이 세부 정의는 test 결과 회수 전에 고정했다. 실제 자연 발생 미확인 질문의 보류 능력이나 위험 보장은 아니다. test 결과를 보고 임계값을 바꾸지 않는다.

동결된 config·upload.zip, 가중치 revision/hash, 초기/학습 head와 LoRA, optimizer, 질문 노출 수, 학습 곡선, 원시 예측과 특징 캐시를 보관한다. CPU에서 고정 head와 검색 순위를 재계산하고 가중치 변화를 검산한다.

기본 파라미터는 float32, encoder 연산은 BF16 autocast다. 고정 특징은 float16으로 저장한 뒤 float32로 변환해 계산한다. cosine은 변환 후 다시 정규화한다. LoRA의 학습 중 특징은 float32 판독층에 바로 전달하므로 두 경로가 비트 단위로 같은 수치 조건은 아니다.

## 실행 한도와 해석

Colab A100 한 세션, 학습 스크립트 3,600초·컨트롤러 3,900초 한도. 기존 로컬 GPU는 사용하지 않는다. 완료/실패 모두 결과 회수 후 해당 세션을 종료한다. 새 큰 모델·유료 API 호출은 없다.

성적이 좋아지면 전체 요청 속 여러 관계를 읽는 학습 가능성의 근거다. 규칙을 이기는지, 암묵적 경험 재사용으로 전이하는지, 작업자의 실제 득실을 개선하는지는 별도 문제다. 성적이 낮으면 앞단 후보 누락과 후보 내 판독 실패, 단일/복수 참조 및 은행 크기로 나누어 다음 개선점을 정한다. 이 회차에서 test를 보고 반복 튜닝하지 않는다.
