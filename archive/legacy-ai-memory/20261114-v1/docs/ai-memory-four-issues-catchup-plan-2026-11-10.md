## 공통으로 유지할 계약

- 선택기는 기존 Harrier 0.6B·q/v LoRA rank 8·128차원 MLP를 유지한다. 작은 자료에서 적합이 가능함을 확인했으므로, 이번 보완에서 새 모델 규모·층·손실 종류를 추가하지 않는다.
- 목표 G, 현재 관측 C, 순서 있는 제안 기억 묶음 M을 구분한다. 실제 진행·실패 이력이 없는 현재 자료로 그 활용 효과를 주장하지 않는다.
- 주 비교의 작업자, 기억 은행, 현재 관측, 후보 행동 집합, 채점과 전달 상한을 같게 둔다. 선택기는 이미 실행한 후보 묶음 또는 보류를 선택한다.
- 관계·충분성 주석과 실제 성공·오류·비용을 별도 필드로 유지한다. 미측정·미확정은 0이나 음성으로 바꾸지 않는다.
- 기존 데이터와 체크포인트는 보존한다. 새 실행 결과는 새 버전으로 저장하고, 서로 다른 작업자 환경의 과거·신규 라벨을 학습용 한 자료에 섞지 않는다.
- 기계적 검산 통과와 연구 가설의 지지를 구분한다. 성능 차이가 없거나 불확실하면 그 결과로 해당 단계를 마무리하고 주장을 제한한다.

이 숫자는 준비한 범위다. 실제 생성·검산 완료 수는 실행 결과에서 별도로 확인한다. 동일 메시지의 별칭은 한 번의 새 출력을 공유하며 독립 호출로 중복 계산하지 않는다.

2. 한 작업자 실행 환경에서 무기억·원래 후보·추가 후보를 모두 새로 생성한다. 이전 Colab 출력이나 거부된 호환성 검사 출력을 새 라벨에 재사용하지 않는다.
3. 사전 지정한 네 안정성 입력을 반복한다. 입력 token ID와 연결된 모든 상태–행동의 성공·근거·구성요소 오류·미확인 판정을 대조한다. 출력 token 차이와 비용 차이는 별도 보존한다.
4. 실제 메시지·입력/출력 token·파싱·원본 정답과 독립 SQL 해답 집합을 검산한다. 실패 답변·형식 오류·길이 한도 도달도 배정과 함께 보존한다.
5. 새 무기억 결과와 새 제공 결과를 짝지어 네 범주 라벨을 다시 만든다. 이전 라벨과의 변화는 별도 분석으로 남긴다.

## 미해결 2 경쟁 후보의 실제 선택 신호를 보강한다

### 수행할 일

재측정 자료를 R이라고 두고, **R의 원래 후보 부분집합**과 **R의 원래+추가 후보 집합**을 비교한다. 작업자 환경이 달라진 과거 237묶음과 새 확장 자료를 직접 비교해 자료 보강 효과라고 부르지 않는다.

1. 원래/확장 후보 각각에서 상태별 행동 수, 네 결과 분포, 악화가 있는 상태·문제군 수를 센다.
2. 무기억과 제공의 결과가 다른 상태 수, 비어 있지 않은 묶음끼리 결과가 다른 상태 수, 서로 다른 효과를 가진 순위 쌍의 수를 분리해 센다. 성공이 같아도 근거 오류·비용이 다른 경우는 별도 집계한다.
3. 같은 주제에서 사람·날짜·현재 가용성·현재 중복 여부가 다른 실제 기록을 사용한다. 기존에 검토한 19요청의 대조를 출발점으로 삼고, 관계상 부적절하다는 이유만으로 악화 라벨을 붙이지 않는다.
4. 추가 자료는 부모 문제군과 같은 fold에 둔다. 결과가 달라진 사례만 새 확인 집합으로 골라 남기지 않는다. 학습용 어려운 사례 표집을 추가하면 원래 분포 평가와 구분한다.

- [x] 추가 후보가 실제로 경쟁 선택 신호를 늘렸는지 동일 환경 안에서 확인한다. 늘지 않았다면 자료 보강 가설의 부정 결과로 남기고 대규모 재학습에 들어가기 전에 과제·후보 구성을 검토한다.
- [ ] 개수·길이·ID·순서 기준선과 관계 주석 검토를 통해 새 대조의 편법 및 다른 속성 변화도 기록한다. 같은 12문제군의 보강을 새 출처 확보로 세지 않는다.

학습에 들어가면 아래 고정 비교를 수행한다. 각 행·열의 평가 후보 집합은 같게 두고 원래 후보 평가와 확장 후보 평가를 각각 보고한다.

| 학습 자료 | 네 범주 CE | CE + 기존 선택 손실 |
| --- | --- | --- |
| R의 원래 후보 | 새 환경의 기준선 | 새 환경에서의 손실 효과 |
| R의 원래+대조 후보 | 자료 보강 효과 | 자료와 손실의 결합 효과 |

기존 설정의 초기값 2개·부모 문제군 fold 3개·8 epoch·동일 상태 배치와 최종 epoch 선택을 유지하면 총 24회 학습이다. 새 데이터 버전이므로 과거 환경에서 학습한 12개 모델을 이 표의 기준선 대신 사용하지 않는다. 노출·업데이트 수를 맞추고 추가 후보의 토큰·계산량은 별도로 보고한다. 시간 상한은 준비된 자료의 길이와 사전 처리 시간 점검으로 정한 뒤 실행 전에 고정한다.

## 미해결 1 현재 상태 활용과 기억 매칭을 구별한다

### 입력 ablation

R의 확장 자료와 **CE 하나를 기준으로 먼저** 다음 입력을 비교한다. G는 목표, C는 현재 관측, M은 제안 묶음이다.

| 입력 | 역할 |
| --- | --- |
| G+M | 현재 관측을 명시적으로 읽지 않는 주 대조 |
| G+C+M | 현재 관측 추가의 주 비교 |
| G+C | 어떤 묶음인지 몰라도 상태의 난도로 예측하는지 확인하는 진단 |

각 조건을 같은 초기값·판독층·노출·업데이트·분할에서 별도로 학습한다. 작업자가 받는 현재 관측과 공통 제안 집합은 바꾸지 않는다. 상류 제안에 이미 상태 기반 규칙이 반영됐으면 이를 공개해 “상태 정보가 완전히 없는 대조”로 부르지 않는다.

위 24회 비교의 R확장+CE가 G+C+M 기준을 제공한다. 같은 2초기값·3fold를 유지하면 G+M과 G+C는 12회 추가 학습이다. G만 읽기, 입력 가림, 가산 모델 등은 필요할 때 추가하는 진단으로 남기고 이번 기본 실행 수에 자동 포함하지 않는다. 기존 22후보의 적합 진단을 같은 자료에서 반복 최적화하지 않는다.

### 상태와 기억의 교차 검증

같은 목표에서 유효한 C1·C2와 M1·M2의 네 조합을 만든다. 관측 상태를 바꾸는 것과 목표 문구를 바꾸는 것을 구분한다. 기존 식사·숙소 기록의 네 칸 대조는 **두 기억 성분의 교차**이므로, 그 자체가 상태×기억 상호작용을 검증한 것은 아니다. 이를 여러 현재 상태와 연결해 필요한 조합과 근거를 검토한다.

- 관계 주석은 주체·날짜·참조·적용 조건·현재 중복·부족한 근거를 원문 span에 연결하고 작업자 결과를 보지 않고 검토한다. 임시 주석을 자동 확정하지 않는다.
- 관계 진단은 상태 하나나 기억 하나만으로 정답이 결정되지 않게 구성한다. 전체 후보 수·제안 개수·길이·ID가 정답을 알려주는지 점검한다. 실제 효용 라벨의 균형을 맞추려고 관측 결과를 바꾸지 않는다.
- 네 조합의 실제 효용은 각각 새 실행 결과에서 읽는다. 관측 효용의 후보 간 순위가 상태에 따라 바뀐 조합에서는 예측 순위도 그 변화를 포착하는지 본다. 실제 효용이 바뀌지 않은 조합에서 점수 반전을 요구하지 않는다.
- 개별 분류 외에 대조 쌍 양쪽·네 조합 전체의 정답, 상태 안의 순위, 최종 선택·근거 오류를 보고한다. 관계 정답과 네 범주 효용 점수는 서로 대신하지 않는다.

### 완료 기준과 주장 범위

- [ ] 세 입력의 독립 학습 비교와 동일 초기화·노출·checkpoint 규칙 검산을 마친다. 입력을 가린 검사만으로 학습 기여를 판정하지 않는다.
- [ ] 현재 관측으로 무기억 성공 예측만 좋아졌는지, 제공 후 성공·같은 상태 내 순위·실제 선택까지 좋아졌는지 분리해 보고한다.
- [ ] 관계 진단의 판독 방법과 정답을 명시하고, 효용 모델의 양수 점수를 관계 정답으로 쓰지 않는다. 별도 관계 판독층을 사용했다면 별도 모델의 진단으로 표시한다.
- [ ] 단독 입력·개수/길이·관계 규칙 기준선과 교차 대조 결과를 보존한다. 새 문제군 확인 전에는 내부 추론 전체나 보편적 관계 이해를 증명했다고 주장하지 않는다.

비교를 완료했지만 G+C+M의 추가 이득이 없으면 그 결과를 남긴다. 새로운 층이나 더 큰 모델을 바로 추가하는 대신, 과제의 관계 신호·작업자 오류·선택 가능한 차이가 충분했는지 검토한다.

## 미해결 3 손해 감지와 불필요한 제공을 보완한다

### 평가를 먼저 분리한다

| 평가 대상 | 지표와 단위 |
| --- | --- |
| 악화 범주 인식 | 악화 precision·recall, 악화 점수 분포·보정 오차. 지원 묶음·상태·문제군 수를 함께 표시 |
| 실제 손해 억제 | 상태별 무기억/단순 정책 대비 성공→실패, 근거 없는 구체 행동·잘못된 불가능 판단 |
| 선택기의 보류 | 기억 미제공 비율, 놓친 개선, 무기억도 근거 있게 성공한 상태의 제공과 비용 |
| 작업자의 보류 | UNKNOWN/NONE 구분, 근거 부족 응답과 불가능 판단의 정확성 |
| 실제 비용 | 모든 후보 점수화·검색·작업자 입력/출력 토큰·시간을 측정 범위별로 보고 |

선택기가 기억을 보류하는 것과 작업자가 UNKNOWN으로 답하는 것은 다른 행동이다. 두 지표를 하나의 보류 정확도로 합치지 않는다. 중립 범주에 작은 양수 효과 점수가 남아 기억을 제공하는 현상도 분류 정답과 별도로 검사한다.

### 수행할 일

1. R에서 실제 악화·중립·개선과 오류 증가가 있는 사례를 출처별로 집계한다. 악화가 소수 문제군에만 있으면 전이 한계로 표시한다. 실제 악화 예측이 아니라 현재 조건 이름을 맞히는지 대조한다.
2. 먼저 위의 자료 보강×기존 손실 비교를 마친다. 새 클래스 가중치·다중 출력층·비용 보상까지 한 번에 바꾸지 않는다.
3. 기존 제공 경계 0을 기준으로, 개발 자료에서 한 번 정한 보수적 제공 경계와 짧은 후보 선택 규칙을 비교한다. 두 초기값 중 평가가 좋은 것을 골라 보정하지 않는다.
4. 보정은 별도 dev 자료 또는 학습 가족 내부 분할에서 한다. 같은 평가 fold로 문턱을 선택하고 그 성적을 독립 평가라고 보고하지 않는다. 기존 12가족을 이용한 선택은 탐색으로 표시한다.
5. 성공이 같은 상태에서는 근거 오류·총비용의 차이를 확인한다. 중복 기억을 악화 정답으로 고치거나 전달 토큰만 보고 전체 비용 절감이라고 부르지 않는다.

### 완료 기준과 판정

- [ ] 기존 단순 정책 대비 성공·악화·근거 오류·보류·비용을 같은 상태에서 비교한 표가 있다.
- [ ] 개발에서 보정한 규칙을 동결하고 새 문제군에서 판정한다. 악화 recall과 실제 악화 수를 모두 보고하며 하나의 개선으로 다른 하나까지 해결했다고 말하지 않는다.
- [ ] 확인 전에 주 성공 지표, 최소 실용 개선, 허용 성공 저하 폭, 악화·오류 기준과 비용 상한을 수치로 고정한다. 새 문제군 수가 해당 차이를 구별할 수 있는지 문제군별 변동으로 점검한다.

성공률 우위를 주장하려면 사전 고정한 주 비교에서 문제군 단위 차이와 불확실성이 그 주장을 지지해야 한다. 성공률 유지와 오류/비용 개선을 주장할 경우에는 사전 허용 범위 안의 성공률 유지부터 확인한다. 악화 사례가 적거나 구간이 넓으면 손해 방지가 해결됐다고 판정하지 않는다. 과거 0/9를 몇 개 더 맞혔다는 사실만으로 일반적 손해 감지를 입증하지 않는다.

## 보존할 결과와 최종 판단

각 단계는 계획/준비/실행/검산/미완료를 구분해 원본 위치와 manifest에 연결한다. 새 자료에는 모델 revision·실행 환경·device map·입력/출력 token·전달 순서·worker 결과·실패/누락·선택기 비용을 보존한다. 재현 검사는 데이터 재구성, 저장 특징/판독층 재생, 실제 adapter 재인코딩의 범위를 구분한다.

최종 판단은 다음 세 주장으로 나눠 작성한다.

1. **현재 관측의 예측 기여:** 공정한 입력 ablation에서 무엇이 개선됐는가.
2. **상태와 기억의 관계 활용:** 편법을 통제한 교차 대조와 새 문제군에서 어떤 조합을 구별했는가.
3. **선택의 추가 가치:** 같은 작업자·은행·예산에서 단순 정책 대비 성공·악화·오류·비용이 어떻게 달라졌는가.

첫 번째만 개선되면 예측 개선으로, 두 번째만 확인되면 관계 진단으로 범위를 한정한다. 실제 선택의 추가 가치가 확인돼야 유용한 기억 선택 정책을 확보했다는 결론으로 이어간다. 기존 22후보의 완전 적합이나 분류 점수 상승을 그 결론의 대체 근거로 사용하지 않는다. 상세 확인 항목은 [기존 30개 후속 점검 노트](ai-memory-three-issues-validation-plan-2026-11-09.md)에 연결한다.
