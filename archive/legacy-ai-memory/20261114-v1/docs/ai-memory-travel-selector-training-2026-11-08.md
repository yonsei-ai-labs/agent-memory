# 여행 기억 선택기 첫 학습 — 실행 전 설계

사용자 요청: MemoryArena 사용 가능성 검토에 이어 데이터를 모아 실제 학습까지 진행한다. 이 문서는 실행 전에 비교와 해석 범위를 고정한다. 결과는 별도 보고서에 남긴다.

완료 후 추가: [11월 9일 결과 보고](reports/2026-11-09-memoryarena-travel-references.md)에 실제 학습·회수·평가와 한계를 정리했다. 아래 내용은 실행 당시 설계와 수정 이력이다.

## 자료의 독립성과 실험 범위

MemoryArena 여행 270행은 45개의 기본 계획을 각각 6회 사용한다. 원본 TravelPlanner 공식 train 45개도 확인했다. `annotated_plan`의 메타데이터와 빈 날짜 패딩을 제외하면 이 45개 계획과 모두 일치한다. 이를 별도 신규 출처로 더하지 않는다. TravelPlanner의 참고 DB는 과거 계획의 장소·속성 확인에 활용할 수 있다.

첫 실험은 **MemoryArena에서 파생한 자체 그룹 분할**이다. 기본 계획 단위로 train 30개, dev 7개, test 8개를 고정하고, 각 계획의 6개 변형을 함께 둔다. 3·5·7일 여행을 분산하며 이미 내용까지 검토한 첫 묶음은 dev에 둔다. 공식 전체 test의 벤치 점수와 구분한다. 분할 이후 test 내용으로 주석 규칙이나 학습 설정을 수정하지 않는다.

## 첫 학습의 구체적인 과제

현재 요청에 등장하는 과거 여행자의 정보 중 **어느 사람·날짜·항목을 그대로 참조하고, 어느 정보를 비교 기준으로 쓰는지** 판독한다. 예를 들어 두 번째 날의 숙소를 고르면서 'Emma의 첫날 숙소보다 비싸고 다른 방 종류'를 요구하면, 현재 목표 날짜와 참조 날짜가 다르다.

입력은 현재 여행자·여행 길이, 현재 요청에서 판단할 명시적 참조 문장, 과거 기억 후보 하나다. 참조 문장은 원문에서 그대로 추출한다. 전체 현재 요청은 출처 기록에 보존하되 이 단계의 모델은 명시적 참조 문장 단위를 판단한다. 참조 문장 추출까지 학습한 전체 에이전트라고 부르지 않는다. 해당 문장의 참조 대상이 명확한 경우에만 주석하고, 사람·날짜·항목이 불명확한 경우는 억지로 정답을 만들지 않고 제외 이유를 남긴다.

관계 라벨은 `그대로 참조`, `비교 기준으로 참조`, `해당 참조 대상 아님`이다. 음성 후보는 같은 사람의 다른 날짜, 같은 날짜의 다른 사람, 다른 항목을 포함한다. 단순히 무관한 여행만 음성으로 넣지 않는다. 후보의 순서·ID·분할·주석 필드는 모델 입력에 넣지 않는다.

첫 단계의 기억은 공개된 **참조 이력**으로 구성한다. 기본 여행자의 제공된 계획과 현재 차례보다 앞선 여행자의 공개 참조 계획을 사용하며, 현재·미래의 정답 계획은 입력에서 제외한다. 이는 오류 없이 기록된 과거 계획을 가정하는 통제 실험이다. 에이전트가 실제로 생성한 기억이나 그 오류까지 다룬 실행이라고 부르지 않는다.

이 조건을 먼저 쓰는 이유는 과거 계획 자체의 오류와 현재 관계 판독 실패를 분리하기 위해서다. 이후 실제 작업자가 만든 과거 기록으로 평가해야 한다. 관계 라벨을 기억의 실제 이득·손해 라벨로 치환하지 않는다.

## 데이터 검토와 기준선

모든 추출 사례에 원문 묶음 ID, 현재 차례, 참조 문장의 위치, 후보의 이전 차례·사람·날짜·항목, 주석 근거를 보존한다. 학습용 입력에서는 이 중 필요한 자연어 내용만 남긴다. 현재 차례 이후의 기록이 들어가면 내보내기를 거부한다.

자동 주석의 적용 범위와 제외 비율을 train/dev에서 확인한 뒤 동결한다. 이 에이전트가 원문과 직접 대조한 사례의 목록을 남긴다. 사람이나 독립 주석자의 검토가 완료됐다고 주장하지 않는다. 같은 기억이 다른 요청에서 다른 라벨을 받는지, 사람·날짜만으로 정답을 외우는 편법이 있는지 확인한다.

BM25 또는 토큰 검색, 간단한 사람·날짜·항목 규칙, 무작위 선택을 기준선으로 둔다. 규칙이 성공하면 숨기지 않는다. 학습기의 필요성은 기준선과의 차이로 판단한다. 정답 근거에서 만든 규칙과 일반 검색의 차이도 구분한다.

오래된 다른 사람의 기록이 우연히 같은 호텔·식당 값을 담을 수 있다. 이 경우 참조 대상을 틀려도 작업 답에는 도움이 될 수 있다. 따라서 **참조 대상 정답**과 **선택한 값의 일치**를 별도 측정한다. 후자도 실제 작업자 효과와 동일하지 않다.

## 학습 비교와 자원

기존의 고정 checkpoint `microsoft/harrier-oss-v1-0.6b@f9b9dc8d367d443f2479d27aa5d8d2850c0774ee`를 사용한다. 새 데이터의 효과를 보기 위해 이 회차에서 기반 모델까지 바꾸지 않는다.

비교는 고정된 함께 읽기 표현 위 선형/MLP, LoRA + 분류 손실, LoRA + 분류·후보 순위 손실이다. 현재 요청만·기억만 읽는 고정 표현 기준선도 확인한다. 분류 점수 외에 요청별 올바른 후보 선택, 날짜가 다른 조건, 비교 조건을 나누어 보고한다. 대조/순위 손실 감소 자체를 성공으로 해석하지 않는다.

정확한 업데이트 수·학습률·최대 길이·시드·중단 시간은 데이터 검토가 끝난 뒤 첫 GPU 할당 전에 config에 고정한다. 모든 학습 행이 실제 업데이트에 사용됐는지 기록한다. dev에서 checkpoint와 방법을 고르고, test 정답은 Colab에 업로드하지 않는다. 저장 모델 재로딩과 가중치 변화·저장 예측의 검산을 완료해야 학습 성공으로 기록한다.

11월 9일 학습 직전 [config](../training/memory_selector/configs/travel-references-v1.json)를 고정했다. 첫 비교는 seed 731 하나로, 고정 판독층 12회 노출·LoRA 2회 노출을 사용한다. 학습 자료 25,728쌍을 모두 노출하며 시드 안정성까지 확인한 비교라고 주장하지 않는다. 실제 사용된 문장은 가장 긴 경우에도 178토큰으로, 최대 256토큰 아래에서 자르지 않는다.

사용자 계정의 Colab에 현재 활성 세션이 없음을 읽기 전용으로 확인했다. 전용 L4 세션 하나를 준비 완료 후 할당하며, 1회 약 60분의 상한과 회수·종료 처리를 사용한다. 기존 세션의 종료를 확인하기 전 중복 할당하지 않는다. 다른 에이전트의 로컬 GPU는 사용하지 않는다.

### 실행 중 계산 방식 수정 기록

첫 할당은 사전 확인 뒤 커널 재접속 시간 초과로 학습을 시작하지 못했고, 종료를 확인했다. 다음 할당에서는 고정 특징 67,362개와 네 고정 판독기의 학습·저장이 완료됐다. LoRA는 업데이트마다 4개 요청을 각각 순서대로 인코딩해 100업데이트에 약 128초가 걸렸다. 이 속도로 두 방법을 2회씩 학습하면 1회 실행 시간 한도를 넘기므로, 테스트 정답을 확인하기 전에 해당 학습 프로세스만 중단했다. 결과를 회수하고 GPU를 종료했다.

[v2 계산 설정](../training/memory_selector/configs/travel-references-v2.json)은 4개 요청의 24개 후보를 함께 인코딩하고, 짧은 입력에 불필요한 gradient checkpointing을 해제한다. 요청별 손실을 동일하게 평균하는 목표, 학습률, 시드, 2회 노출, dev 선택 기준은 유지한다. 손실 값과 gradient가 기존 순차 계산과 같은지는 별도 수치 검사로 확인한다. BF16 인코더의 배치 방식 변경에 따른 수치 경로까지 동일하다고 주장하지 않는다.

회수한 고정 특징·완료된 네 판독기는 원래 입력·모델·학습 설정과 파일 해시를 확인해 재사용한다. 중단된 LoRA 가중치는 재사용하지 않고 두 LoRA 모두 원래 기반 모델에서 시작한다. 이전 실행과 새 실행의 코드·설정·산출물 해시를 각각 보존한다. 이 수정은 처리 속도 문제에 따른 것이며 평가 점수를 본 뒤 목표나 분할을 바꾸는 절차가 아니다.

추가 전송 실패도 결과에서 제외하지 않는다. 큰 캐시 묶음을 올린 실행은 노트북 연결이 끊겨 학습을 시작하지 못했다. 이후 터미널 실행으로 바꾸면서 이미 학습된 고정 판독기의 특징 캐시는 로컬에 두고 필요한 가중치·예측·출처만 전송했다. 첫 터미널 실행은 로그 다운로드 시간 초과를 제어 코드가 학습 실패로 처리해 종료됐다. 이 오류를 수정하고 모의 검사했으며, 모든 실패 실행의 종료 상태를 보존한다. 최신 실행 경로·실제 자원 사용량은 최종 보고서에 함께 기록한다.

이어진 L4 실행은 첫 epoch의 개발 선택 100%와 2,100번째 업데이트까지 로그를 남겼지만, Colab 상태 조회에서 세션 자체가 사라진 것을 확인했다. 유실 원인은 확정하지 못했으며 가중치를 회수하지 못한 이 실행을 완료된 학습 결과로 보고하지 않는다. 다음 시도는 A100·30분 controller 상한을 사용한다. 학습 설정과 평가 기준은 유지하고, epoch별 head·adapter·optimizer·노출 기록과 방법별 완료 산출물을 별도 ZIP으로 만들어 로컬에 즉시 회수한다. 고정 판독기는 앞서 회수한 L4 결과를 재사용하므로 하드웨어가 같은 순수 속도 비교로 해석하지 않는다.

## 실제 득실과의 연결

이 회차의 필수 결과는 데이터·분할·학습된 모델·보지 않은 기본 계획에서의 관계 선택 평가다. 공식 전체 여행 계획 성공률을 이미 측정했다고 주장하지 않는다.

관계 결과가 나오면, 고정 작업자에게 동일한 상태에서 기억 보류·전체 제공·검색·학습 선택을 주는 작은 후속 평가를 연결한다. 먼저 하나의 실제 계획 판단에서 실행 가능한지 확인하며, 해당 경우에는 전체 여행 성공과 구분한다. 작업자 관측이 없는 사례에는 실제 효용 라벨을 만들지 않는다. 원판 채점기의 누락 분모·문자열 접두어 문제를 보완하기 전에는 전체 여행 점수로 학습하지 않는다.

Test를 채점하기 전에 보류 진단도 별도로 정한다. 현재 후보 집합은 항상 참조 대상이 하나 있으므로, 해당 후보를 제거한 5개 기록에 대해 선택기가 보류할 수 있는지를 추가 측정한다. 모델은 후보 수를 입력받지 않고 개별 관계 확률의 최댓값으로 판단한다. 제공 임계값은 dev의 원래 집합과 제거 집합에서만 고정하고 test에 적용한다. 이는 후보 삭제 진단이며 자연적으로 유용한 기억이 없는 상황이나 실제 득실의 측정과 구분한다.

### 다음에 실제로 검증할 연결

후속 작업자는 고정하고 같은 판단 시점에서 `기억 없음 / 후보 전체 / 검색 선택 / 학습 선택`을 비교한다. 처음에는 실제 과거 작업자가 만든 기록과 관측 가능한 도구 정보를 사용해 작은 여행 판단부터 검증한다. 공개 참조 계획을 사용한 이번 이력 조건과 섞지 않는다. 성공·실패와 함께 입력 토큰·선택기 시간·작업자 시간을 따로 기록한다.

결과는 `무기억 실패→기억 성공`, `성공→실패`, `둘 다 성공`, `둘 다 실패`로 남긴다. 참조 대상을 틀려도 같은 장소 값이면 답을 도울 수 있고, 정확한 기억이어도 원래 풀 수 있는 문제에는 비용만 추가될 수 있다. 관계 판독 결과와 이 실제 관측을 연결해야 처음의 득실 질문을 검증할 수 있다. 아직 이런 실행 결과는 없다.

후보 6개를 모두 전달하는 정책이 이미 충분하면 선택기의 성공률 개선 여지가 작을 수 있다. 이를 숨기거나 개선 사례만 남기지 않고 비용 차이도 함께 비교한다. 현재의 명시적 참조 문장·6후보 결과를 많은 기억을 검색하거나 암묵적 적용 조건을 판단하는 성능으로 확대하지 않는다.
