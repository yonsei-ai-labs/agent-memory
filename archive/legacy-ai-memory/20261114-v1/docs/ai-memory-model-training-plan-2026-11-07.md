# 과거 경험의 현재 적용성을 배우는 모델 학습 실험 노트

2026-11-07 · 학습 담당 계획 v0.1 · 데이터 명세와 실행 설정을 동결하기 전의 설계

**Harrier 0.6B가 현재 상태와 과거 경험을 비교하도록 추가 학습하고, 그 판단이 기억 제공 정책에 실제로 도움이 되는지 검증한다.** 첫 숫자 판독 실험은 기능 점검으로 보존한다. 다음 학습의 주 대상은 적용 조건과 중복 여부이며, 실제 이득·손해는 별도의 제공·보류 실행 자료로 연결한다.

처음 비교할 것은 **고정 Harrier와 판독층**, **LoRA와 같은 판독층**, **LoRA에 상태 대조 학습을 추가한 구성**이다. 모델 크기와 층 수를 동시에 늘리지 않고, 어떤 학습 신호가 새 경험에 대한 판단을 바꾸는지 확인한다. 이 문서는 학습 계획이며 새 GPU 할당이나 학습 실행을 기록한 결과 보고서가 아니다.

[큰 방향 재검토](ai-memory-direction-reassessment-2026-11-07.md), [종합 연구 노트](ai-memory-information-value-note-2026-11-07.md), [첫 학습의 독립 리뷰](../training/memory_selector/reviews/2026-11-07-independent/README.md)를 바탕으로 한다. 기존 실험의 입력·배정·결과는 변경하지 않는다.

**같은 날의 개발 진행:** [검사 범위 관계 파일럿](../training/memory_selector/reports/2026-11-07-scope-relations-pilot.md)을 별도 데이터판으로 실제 실행·검산했다. 통제한 현재 상태에서 범위 동일성과 중복을 배우는 좁은 과제이며, 아래의 자연 적용성·효용 실험을 완료한 것은 아니다. `train_scope.py`는 해당 두 출력과 상태 대조 손실을 구현했고, FP32·6 epoch·9행 배치로 전체 감독 노출과 저장 복원을 확인했다. 미주석 마스크·바꿔쓰기 일관성 손실·새 독립 출처 확인·실제 제공 정책은 남아 있다.

후속으로 [실제 코드 관계 74행의 모델 비교](../training/memory_selector/reports/2026-11-07-natural-relations-model-comparison.md)도 실행했다. 이 전달 자료의 단일 3분류 계약에 맞춰 고정 Harrier 판독층과 Qwen3.5-9B 직접 예측을 비교했으며, 아래 두 출력·LoRA 주 비교와는 별도다. 큰 모델의 미확인 쏠림과 선택지 배치 민감성을 확인해 정답 교사로 바로 사용하지 않는다. 판독층 깊이 확대는 [새 출처를 늘리는 계획](../training/memory_selector/reports/2026-11-07-scaling-and-larger-model-plan.md)에 연결해 보류했다.

## 1 학습에서 검증할 질문

> 같은 기억이라도 현재 조건이 달라지면 판단을 바꾸고, 표현만 달라지면 판단을 유지하도록 학습한 작은 모델이, 단순 규칙과 일반적인 관계 분류보다 나은 기억 사용을 가능하게 하는가?

다음 세 수준을 구분한다.

| 수준 | 질문 | 확인 방법 |
| --- | --- | --- |
| 근거 판독 | 기억의 사실·시도가 출처에 있는가 | 원문 위치와 연결된 보조 주석 |
| 현재 관계 | 명시한 용도로 사용해도 조건에 맞는가, 이미 주어진 내용인가 | 동일 기억의 상태 대조와 새 출처 평가 |
| 정책 가치 | 제공·보류 판단이 성공·회귀·비용을 개선하는가 | 고정 작업 에이전트의 독립 실행 |

주 기여 후보는 **조건 관계를 배우는 학습 신호의 효과와, 그 효과가 실제 정책으로 이어지는 범위**다. LoRA·MLP·대조 손실 자체를 새로운 방법이라고 주장하지 않는다. 관계 점수만 좋아지면 관계 판독 결과로 한정하고, 실제 정책 비교까지 좋아져야 기억 사용 개선으로 보고한다.

현재 324개 수치 주장과 9개 관계 후보는 발견·기능 점검 자료다. 후보 9개는 3출처에서 나왔고 주석 체계와 직접 적용 양성이 미완성이다. 기존 제공·보류 자료도 4출처–대상 쌍·2출처에 그치며, 완결 결과가 과제별로 거의 고정되어 있다. 이를 새 확인 집합이나 충분한 효용 학습 자료로 사용하지 않는다.

## 2 역할과 첫 결정 시점

| 담당 | 산출물 |
| --- | --- |
| 데이터·평가 담당 | 실제 기억과 근거, 판단 전 현재 상태, 관계 주석, 출처 연결 분할, 제공·보류 실행 결과, 독립 평가 |
| 모델 학습 담당 | 입력 변환·검증, 학습 코드와 기준선, Colab 실행·종료, 모델·추론 코드·재현 묶음 |
| 함께 고정할 사항 | 라벨 정의, 판단 시점, 정보 접근 범위, 학습·개발·확인 분할, 주 비교와 비용 단위 |

첫 결정 시점은 **공통의 사전 관측을 마친 뒤, 후보 기억을 작업 에이전트에게 보여주기 전**으로 제안한다. 공개 문제와 동일 절차로 수집한 환경·코드 관측을 사용한다. 이 관측은 모든 비교 조건에 동일하게 제공하고 수집 비용도 기록한다. 관측 자체가 필요한 내용을 알려주어 기억이 중복될 가능성도 평가한다.

메모리 노출 뒤 작성한 예정 명령·패치·실행 결과는 이 시점의 입력이 아니다. 현재 초기화 후보처럼 예정 명령을 쓰는 자료는 실행 직전 판단 자료로 따로 보존한다. 첫 학습과 정책 평가에 두 시점을 섞지 않는다. 시작 시점 자료가 부족하면 해당 단계를 대기 상태로 두고, 실행 중 자료로 조용히 대체하지 않는다.

처음에는 **정해진 후보 한 묶음의 제공·보류**를 다룬다. 후보 묶음은 의미가 완결된 기억이며 임의 문장 절단이 아니다. 후보 검색과 은행 갱신은 고정한다. 후보가 하나라는 설정은 판단의 효과를 분리하기 위한 범위이며, 큰 기억 은행의 검색 성능을 입증하지 않는다.

## 3 데이터 전달 명세

### 모델 입력은 현재 상태와 과거 근거를 분리한다

| 필드 | 포함 내용 | 제외 내용 |
| --- | --- | --- |
| `input.current` | 공개 문제, 판단 전 공통 관측, 이미 제공된 공통 기억 | 후보별 과거 출처 근거, 이후 실행·제출 결과 |
| `input.candidate` | 제공하려는 원문, 출처에서 명시한 적용 조건, 평가하려는 사용 목적 | 정답 관계 주석, 예상 득실을 정답처럼 적은 문구 |
| `input.source_evidence` | 해당 기억의 실제 명령·출력·코드 등 선택된 출처 구간 | 대상 문제의 숨겨진 검사·참조 패치 |
| `annotations` | 관계·중복·근거 주석, 주석자, 이견, 검토 상태 | 모델 입력으로 연결하지 않음 |
| `provenance` | 출처·대상 ID, 파일·구간·해시, 관측 시점, 자연/편집 구분 | 분할·ID·사후 라벨을 특징으로 사용하지 않음 |

현재 후보의 `state_text`는 과거 근거와 현재 상태를 함께 담고 있다. 새 자료에서는 위 필드로 분리한다. 그래야 ‘현재 상태만’ 기준선이 과거 기억을 읽지 않고, ‘기억만’ 기준선도 대상 상태를 읽지 않는다. 후보에 따라 현재 상태 발췌를 정답에 맞게 바꾸는 방식도 피한다.

모델에 제공할 원문 범위를 먼저 정한 다음 주석한다. 명확한 수치·명령·버전은 같은 입력에서 결정적으로 추출할 수 있지만, 파서가 아는 사실과 관계 주석을 구별한다. 발췌에서 중요한 조건이 사라졌다면 그 입력에 대한 판단은 미확인일 수 있다. 원문 전체의 정답을 짧은 입력에 그대로 붙이지 않는다.

### 첫 라벨은 두 가지 관계를 따로 표시한다

| 출력 | 값 | 의미 |
| --- | --- | --- |
| `compatibility` | `compatible / conflict / unknown` | **명시한 사용 목적**에 대해 현재 관측과 기억의 조건·범위가 맞음 / 충돌 근거가 있음 / 판단 근거 부족 |
| `redundancy` | `not_already_present / already_present / unknown` | 해당 정보·절차가 현재 공통 맥락에 이미 주어지거나 충족됐는지 |
| `source_support` | `supported / contradicted / not_established` | 기억의 사실·관측된 시도가 출처에 근거하는지. 후속 보조 학습용 |

`compatible`은 해결 보장이나 제공 정답이 아니다. `not_already_present`도 유용함을 뜻하지 않는다. 직접 수정 지침으로는 충돌해도 진단의 힌트로는 관련될 수 있으므로, `intended_use`를 입력에 명시하고 첫 데이터판에서는 한 용도로 고정한다. 기본 제안은 `direct_instruction`이다. 원리 전이·부분 범위·진단 가능성은 별도 검토 태그로 남기고 첫 제공·보류 라벨로 자동 변환하지 않는다.

**미확인과 미주석은 다르다.** 보이는 근거로 판단할 수 없다는 검토 결과는 `unknown`이다. 아직 주석하지 않았거나 이견을 해결하지 못한 항목은 `null`과 검토 상태로 보존하고 그 출력의 손실에서 제외한다. 현재 후보의 긴 관계 설명을 위 클래스에 자동 매핑하지 않는다.

아래는 형식 예시이며 실제 학습 사례가 아니다.

```json
{
  "schema_version": "relation-v1-draft",
  "sample_id": "example-only",
  "family_id": "source-target-connected-component",
  "decision_stage": "pre_memory_after_common_observation",
  "input": {
    "current": {
      "problem": "공개 문제",
      "observations": [{"text": "배정 전 공통 관측", "observation_id": "obs-1"}],
      "common_memory": []
    },
    "candidate": {
      "text": "출처에 근거한 제공 후보",
      "conditions": ["출처에서 확인된 조건"],
      "intended_use": "direct_instruction"
    },
    "source_evidence": [{"text": "출처 근거 구간", "evidence_id": "src-1"}]
  },
  "annotations": {
    "compatibility": null,
    "redundancy": null,
    "source_support": null,
    "review_status": "unreviewed"
  },
  "provenance": {
    "source_task_id": "source-placeholder",
    "target_task_id": "target-placeholder",
    "origin": "illustrative_only"
  }
}
```

`observation_id`와 `evidence_id`도 연결용이다. 토크나이저에는 허용한 본문·조건·용도만 전달한다. 실제 자료는 근거 파일·줄 구간·SHA, 관측의 시간 순서, 주석자와 근거를 추가로 갖춰야 한다. 실제 효용 결과는 이 JSON의 입력에 넣지 않고 별도 실행 테이블에서 `sample_id`와 연결한다.

### 필요한 대조와 분할

첫 개발 자료는 초기화 전제와 검사 범위에서 시작한다. 각 유형에서 직접 적용 양성, 실제 충돌, 이미 충족된 내용, 근거 부족 사례를 확보한다. 명령 문자열의 존재만으로 풀리는 사례와 의미·범위를 비교해야 하는 사례를 구분한다. 규칙으로 충분한 사례만 모아 신경망의 필요성을 주장하지 않는다.

- **상태 대조:** 같은 기억·사용 목적에서 현재 조건만 달라져 관계 정답이 바뀌는 쌍.
- **표현 대조:** 근거·의미·관계 정답을 유지하며 문구나 코드 표현이 달라지는 쌍.
- **근거 부족 대조:** 필요한 관측이 없는 상태. 단순히 모순으로 바꾸지 않는다.

대조 연결 파일에는 두 `sample_id`, 검토한 변경 내용, 영향을 받는 출력, 기대 관계를 기록한다. 편집한 상태는 실제 실행 환경에서도 가능한지 확인하고 자연 기록과 구분한다. 새로 만든 짝에 기존 실행 성과를 복사하지 않는다.

같은 출처·대상·반복·카드 변형·대조 쌍은 연결 집단 단위로 분할한다. 출처나 대상을 공유하는 집단은 합친다. 현재 3출처와 이미 분석한 Django 평가는 발견 자료로 표시하며 새 출처 확인에 재사용하지 않는다. 확인 자료의 정답과 성과는 평가 담당이 관리하고 모델 선택에 사용하지 않는다.

개발 자료 제작의 첫 규모 목표는 **24–40개 독립 경험 가족**으로 제안한다. 이는 데이터 구성 가능성을 확인할 목표이지 충분한 검정력을 보장하는 수가 아니다. 약 3:1의 학습·개발 배분을 출처 연결과 클래스 지원 범위를 우선해 고정한다. 새로운 확인 집합의 수는 실제 가족별 변동과 필요한 정밀도를 보고 평가 담당과 정한다. 수백 개의 표현 변형으로 가족 수 부족을 대체하지 않는다.

이 규모는 **개발 착수의 필수 조건이 아니다.** 기존 자료와 작은 검토 완료 묶음으로 손실·gradient·저장 복원·평가 코드부터 점검할 수 있다. 실제로 [저장 임베딩을 이용한 CPU 대조 학습](../training/memory_selector/reports/2026-11-07-cached-contrast-pilot.md)을 실행했다. 이런 개발 점검의 성적과 새로운 관계 과제·출처에서의 확인 결과는 구분한다.

자료 인수 시 클래스×관계 유형×runner×저장소 분포, 판단 시점, 원문 중복, 가족 연결, 주석 이견, 근거 길이를 검사한다. 평가하려는 클래스가 여러 독립 가족에서 지지되지 않으면 그 범위의 구조 우열 판단을 보류한다. 균형을 맞춘 진단 패널과 자연 분포의 정책 패널은 별도로 보고한다.

## 4 첫 모델 구조

기본 모델은 `microsoft/harrier-oss-v1-0.6b`, revision은 `f9b9dc8d367d443f2479d27aa5d8d2850c0774ee`로 유지한다. 첫 실행에서 사용한 last-token pooling과 L2 정규화도 유지한다. 이는 [고정 모델 카드](https://huggingface.co/microsoft/harrier-oss-v1-0.6b/blob/f9b9dc8d367d443f2479d27aa5d8d2850c0774ee/README.md)에 맞춘 출발점이며 적용성 판독의 최적 구조라는 뜻은 아니다.

```text
현재 문제 + 공통 관측 + 공통 기억 ── Harrier ── h_current
후보 + 조건 + 사용 목적 + 출처 근거 ─ Harrier ── h_memory
                    ↓
z = [h_current, h_memory, 원소별 곱, 절댓값 차이, 두 입력 길이]
                    ↓
작은 관계층 MLP 128 + GELU
                    ↓
적용 관계 3분류 / 중복 여부 3분류
```

Harrier 가중치는 두 입력에서 공유한다. 현재 상태를 인코딩할 때에는 그 판단 질문을 설명하는 공통 instruction을 쓰고, 과거 기억은 역할을 표시해 직렬화한다. 기존 숫자 판독 instruction은 새 질문에 맞게 교체하고 모든 구성에서 동일하게 고정한다. 입력 필드 순서와 구분자를 버전 관리한다.

기존 두 입력의 곱·차이를 활용하므로 선형 기준선도 관계 특징을 받는다. 이 비교를 ‘상호작용이 전혀 없는 선형 모델 대 관계 모델’이라고 해석하지 않는다. 길이 특징은 모든 구성에서 동일하게 두고 별도 길이 기준선으로 편법 가능성을 점검한다.

각 입력 최대 2,048토큰에서 시작한다. 초과 시 자동 절단하지 않고 오류로 내보낸다. 더 긴 입력이 필요하면 발췌 정책 또는 길이 설정을 개발 단계에서 공통 변경한 뒤 동결한다. 개별 토큰 근거를 대조하는 cross-attention 층이나 joint encoder는 이 구조의 구체적 실패가 남을 때의 후속 비교다.

## 5 학습 구성과 주 비교

이 노트의 R 번호는 새 관계 학습의 이름이다. 종합 노트의 성과 예측 A0/A1/B0/B1 및 첫 숫자 실험의 이름과 구분한다.

| 구성 | 학습하는 부분 | 학습 신호 | 목적 |
| --- | --- | --- | --- |
| R0 | Harrier 고정, MLP와 두 출력층 | 관계 분류 | 고정 표현으로 충분한지 |
| R1 | Harrier LoRA, 같은 MLP와 출력층 | R0와 같은 관계 분류 | 표현의 추가 학습 효과 |
| R2 | R1과 같은 구조·파라미터 수 | 관계 분류 + 상태·표현 대조 | **대조 학습 신호의 추가 효과** |
| R3 후속 | R2와 같은 공통 구조, 출처 판독 출력 추가 | R2 + 출처 근거 보조 손실 | 출처 판독 감독의 추가 효과 |

**주 비교는 R2−R1, 보조 비교는 R1−R0**다. R0–R2에 동일한 고유 문장과 대조 쌍의 양쪽 입력을 제공하고 순서·노출을 맞춘다. R2만 더 많은 사례를 보는 방식으로 대조 손실의 효과를 주장하지 않는다. 초기 MLP와 같은 출력층은 seed별 동일 가중치로 시작한다.

R3는 출처 지지·모순·미확인 주석이 충분히 준비됐을 때만 추가한다. R2에도 같은 입력과 보조 출력 구조를 두되 해당 손실의 가중치를 0으로 놓은 대조를 사용한다. 출처 판독 출력은 과거 기억과 근거의 표현만 받고 현재 대상 상태를 읽지 않는다. 감독 유무와 추가 자료·용량 증가를 동시에 바꾸지 않는다.

저렴한 기준선은 학습 분포의 상수, 구조화 규칙, 현재 상태만, 기억과 출처 근거만, 고정 표현의 선형층이다. 현재 상태만/기억만 비교는 관계항과 반대쪽 길이까지 제거한다. 이들을 모두 큰 GPU 탐색으로 만들지 않고 고정 표현을 한 번 계산해 재사용한다.

## 6 손실과 학습 순서

### 관계 분류와 대조 학습

기본 손실 `L_relation`은 주석된 적용 관계와 중복 여부 각각의 교차 엔트로피 평균을 더한다. `null`인 출력은 마스킹하고, 근거가 부족하다고 검토된 `unknown`은 정식 클래스로 학습한다. 가족별 파생 행 수가 큰 출처가 지배하지 않도록 가족 단위 가중치를 공통 적용한다.

상태 대조에서는 **검토된 compatible–conflict 쌍**에 대해 같은 기억의 점수 순서가 바뀌도록 학습한다. 예를 들어 `s = log p(compatible) − log p(conflict)`라 하면 다음 손실을 사용할 수 있다.

```text
L_change = max(0, margin − (s(맞는 상태, 기억) − s(충돌 상태, 같은 기억)))
L_same   = 같은 의미의 표현 쌍에서 예측 분포의 Jensen–Shannon divergence
L_R2     = L_relation + 0.1 × L_change + 0.1 × L_same
```

초기 margin은 0.5로 제안한다. 미확인 상태를 충돌 상태로 간주해 순서를 강제하지 않는다. 같은 의미의 표현 쌍도 관계 정답과 제공 근거가 유지된 경우에만 해당 출력에 일관성 손실을 적용한다. 대조 연결이 없는 항목에는 손실을 만들지 않는다. 상수 예측도 표현 일관성이 높을 수 있으므로 일관성만으로 성공을 판단하지 않는다.

가중치와 margin은 개발 파일럿에서 확정한다. 확인 평가에서 조정하지 않는다. R2가 좋아지면 두 대조 손실 중 어느 쪽의 기여인지 하나씩 제거하는 비교를 후속으로 한다. 처음부터 보조 손실 조합을 대량 탐색하지 않는다.

### 초기 설정과 충분한 감독 노출

| 항목 | 개발 파일럿 출발값 |
| --- | --- |
| LoRA | q_proj/v_proj, rank 8, alpha 16, dropout 0 |
| 관계층 | hidden 128, GELU, dropout 0 |
| Optimizer | AdamW, head LR 3e-4, LoRA LR 1e-4, weight decay 0 |
| 배치 | 문장 4개, gradient accumulation 4, 기본 유효 배치 16개 |
| 학습 길이 | 먼저 전체 자료 3 epoch, 확인용 공통 길이의 초기 후보는 6 epoch |
| Seed | 파일럿 731, 확인 학습 731·941·1103 |
| 안정화 | gradient clip 1.0, 손실·gradient·실제 optimizer update 기록 |
| 평가 | 매 완전한 epoch마다 개발 평가, 학습 중 확인 집합 미사용 |

배치는 대조 쌍의 두 문장을 함께 포함하도록 구성하며 R0–R2가 같은 문장을 같은 횟수로 본다. 배치 끝의 잔여 문장은 버리지 않고 실제 유효 배치 크기를 반영한다. 반복 추출이 생기면 총 감독 노출과 고유 문장 노출을 모두 기록한다. 클래스 가중치가 필요하면 학습 분포만으로 정하고 모든 구성에 동일하게 적용한다.

3 epoch는 개발 동작·학습 곡선을 보는 시작값이며 충분한 수렴의 보장이 아니다. 개발 자료에서 공통 최종 epoch E와 처리량을 확정한 뒤 확인 학습을 진행한다. **R2−R1의 주 비교는 동일 E·감독 노출의 결과**다. 별도의 개발 최적 checkpoint를 운영 후보로 고르면 동일한 평가 기회를 부여하고 그 결과를 주 비교와 구분한다. 3개 seed 결과를 모두 보고하며 최선 seed만 선택하지 않는다.

FP16 overflow로 optimizer가 건너뛴 step은 완료 업데이트로 세지 않는다. 반복적인 비정상 손실·gradient나 시간 제한으로 미완료된 실행은 수렴 결과에 섞지 않는다. 나머지 모델과 다른 자료 노출을 받은 상태에서 우열을 계산하지 않는다.

## 7 관계 모델의 평가와 중단 기준

주 관계 지표는 **같은 기억의 compatible–conflict 상태 대조 쌍에서 두 문장을 모두 맞힌 비율**이다. 쌍을 각 가족 안에서 평균하고 가족을 같은 비중으로 집계한다. 확률이 조금 움직였다는 이유로 성공 처리하지 않는다. 중복 여부가 바뀌는 대조와 미확인이 포함된 대조는 각각 별도로 보고해 서로 다른 판단을 하나의 점수에 섞지 않는다.

함께 보고할 지표는 다음과 같다.

- 출력별 macro F1, 클래스별 정밀도·재현율, 혼동행렬과 가족별 성적.
- 출력 확률의 NLL·Brier. 확률 보정이 필요하면 개발 자료에서만 맞추고 확인 자료에는 고정 적용.
- 의미가 같은 표현 쌍을 모두 맞힌 비율과 예측의 일관성.
- 미확인 상태를 확정 판단으로 바꾸는 오류, 충돌을 compatible로 판단하는 오류.
- 현재 상태만·기억만·규칙·길이 기준선과의 차이.
- 토큰 수, 후보당 지연, GPU 메모리, 학습·추론 비용, 주석 비용의 기록 범위.

불확실성은 독립 가족 단위로 계산하고 seed 변동은 별도로 제시한다. 적은 가족 수에서 좁은 구간을 주장하지 않는다. 한 runner나 숫자·템플릿으로 라벨을 설명할 수 있는지 다시 검사한다. 근거를 가리거나 짝을 바꾼 진단에는 새 정답 검토 없이 원래 라벨을 재사용하지 않는다.

R2가 R1을 넘지 못하면 대조 신호의 기여를 주장하지 않는다. R1이 R0를 넘지 못하면 LoRA가 필요한지 재검토한다. 규칙이 충분하면 규칙의 적용 범위를 결과로 남긴다. 모든 모델이 어려워하면 모델 확대에 앞서 현재 입력에 판단 근거가 있는지, 라벨과 용도가 일관되는지 점검한다.

## 8 관계 판단을 제공 정책에 연결하는 후속 단계

첫 인수물은 **관계 확률을 반환하는 모델**이다. `p(compatible)`를 기억의 성공 개선 확률로 표시하지 않는다. `conflict` 또는 `already_present`라는 이유만으로 기억 전체를 자동 차단하는 정책도 정답으로 간주하지 않는다. 직접 적용과 진단 힌트의 가치는 다를 수 있다.

추론 인터페이스는 허용된 `input`만 받아 모델·schema 버전, 두 관계의 클래스별 확률, 입력 토큰 수, 추론 시간을 반환하도록 구현한다. 추적용 `sample_id`는 본문에 인코딩하지 않고 그대로 돌려준다. 길이 초과·필수 입력 누락은 입력 오류로 반환하며 학술적 의미의 `unknown` 예측과 구분한다. 제공·보류 결정은 버전이 따로 있는 정책에서 만들고, 오류 시 처리도 정책 평가 전에 고정한다.

실제 정책은 별도 실행 자료가 준비된 뒤 동결한다. 데이터 담당은 동일한 판단 전 상태·후보·작업 모델·예산에서 제공/보류를 배정하고, 배정 확률과 실제 행동·성과·비용을 남긴다. 기존의 작은 결과 차이와 합성 관계 주석을 확정적인 유익·유해 라벨로 바꾸지 않는다.

효용 학습이 가능해지면 관계 표현을 먼저 고정하고, 행동별 성공 `p_withhold, p_provide`와 비용 `c_withhold, c_provide`를 예측하는 작은 출력층부터 비교한다. 각 실행은 **실제로 배정된 행동의 관측 결과만** 감독한다. 외부 중단이나 비용 미확정은 항목별 마스크로 보존하고 반대 행동의 정답을 채우지 않는다. 무작위 배정이 아닌 자료를 그대로 인과적인 이득 추정이라고 부르지 않는다.

관계 학습 표현을 사용한 결과 예측과, 같은 효용 자료로 원래 고정 표현을 사용하는 예측을 비교해야 관계 학습의 추가 가치를 알 수 있다. 과제 상태만 보는 결과 예측도 기준선으로 둔다. 실제 성공과 비용을 각각 보고하고, 둘을 합친 점수의 가중치나 제공 임계값은 개발 자료·사전 예산 기준에서 정한다.

`withhold`는 **해당 후보를 보내지 않는 것**이다. 공통 기억이 있다면 외부 기억이 전혀 없는 조건과 다르므로 이름을 구분한다. 평가 담당은 항상 제공·항상 보류·검색/재순위화·전제 확인 규칙·작업 에이전트의 직접 선택과 비교한다. 같은 현재 정보·후보·전달 상한을 사용하고 각 판단 방식의 비용을 포함한다. 성공률은 선택된 사례만이 아니라 전체 배정에서 계산한다.

조건 문구의 효과와 선택기의 효과도 구분할 수 있다. **절차/절차+조건**을 작업 에이전트에게 전달하는 축과 **항상 제공/학습 선택**의 축을 교차한다. 학습 선택 두 조건에는 같은 완전한 은행 근거와 고정 선택기를 사용한다. 이는 은행에서 조건을 삭제하는 실험이 아니라, 조건을 작업 에이전트가 읽는 효과와 선택기가 사용하는 효과를 구분하는 실험이다. 실제 길이·전달률·비용을 보고하며 다른 정보의 추가를 학습 효과로 돌리지 않는다.

관계 판독만 좋아지고 실제 정책이 개선되지 않으면 그 간격을 분석한다. 새로운 출처에서 실제 정책의 성공이나 비용이 개선돼야 운영상 가치를 주장한다. 진단 힌트만 전달하는 행동, 부분 기억 선택, 능동 확인, 쓰기 정책 학습은 이 단계 뒤의 확장이다.

## 9 Colab 자원과 재현 묶음

기존 [실행 제어기](../training/memory_selector/run_colab.py)의 전용 세션·허용 파일 업로드·회수·종료 방식을 재사용하되 새 데이터와 라벨에 맞는 학습 경로를 별도로 구현한다. 현재 `train_aux.py`는 숫자 3분류 코드이므로 이 노트의 관계 자료를 그대로 넣어 실행할 수 없다.

1. 데이터 검증·규칙 기준선·묶음 생성은 로컬 CPU에서 한다. 로컬 Laya GPU에는 모델을 올리지 않는다.
2. Colab T4 한 세션에서 시작한다. 첫 짧은 실행으로 정밀도·메모리·처리량·가중치 업데이트·저장 복원을 확인한 뒤 같은 준비 데이터의 학습을 진행한다.
3. 원래 실행은 BF16 에뮬레이션을 사용했다. 새 코드의 native BF16 검사와 T4 FP16 경로는 별도 확인하며, AMP overflow 처리와 실제 optimizer step 수를 검사한다. 이전 결과를 새 정밀도 결과로 소급하지 않는다.
4. 할당·설치·학습의 세션 상한은 우선 1,800초다. 회수·노트북 저장·종료에는 별도 제한 시간이 필요하므로 이를 총 사용 시간 30분 보장이라고 쓰지 않는다. 처리량으로 구성별 예상 시간·CU를 계산하고 실행 전에 묶음별 한도를 고정한다. 자동으로 더 큰 GPU나 무제한 재시도로 확대하지 않는다.
5. 긴 작업은 재개에 필요한 상태를 저장하고 종료한 뒤 다음 실행에서 이어간다. 정확한 재개가 구현·검증되기 전에는 분할 실행을 완전한 연속 학습과 같다고 보고하지 않는다.
6. 성공·오류·시간 초과 모두 결과 회수를 시도한 뒤 **자기 세션만 종료하고 서버에서 종료를 확인**한다. 다른 작업이 없다면 계정 사용률 0도 확인한다. 결과를 검토하거나 데이터를 기다리는 동안 GPU 세션을 유지하지 않는다.

로컬 `finally`만으로 강제 프로세스 종료나 네트워크 단절까지 보장할 수는 없다. 재접속 시 저장된 자기 세션 ID와 서버 상태를 대조해 남은 세션의 결과를 회수하고 종료한다. 종료 확인에 실패하면 완료로 기록하지 않는다.

학습 전달 묶음은 다음 항목을 포함한다.

| 항목 | 필요한 내용 |
| --- | --- |
| 실행 원본 | 실제 업로드 코드·데이터·설정 `upload.zip`, 로컬 제어 코드의 실행 당시 사본, 파일 해시 |
| 데이터 계약 | schema·라벨·직렬화 버전, 분할과 가족 연결, 대조 쌍, 출처 manifest |
| 모델 | 정확한 base revision, tokenizer·instruction, 판독층, LoRA adapter, 출력 의미 |
| 학습 상태 | 초기/최종 판독층, optimizer·scaler·RNG·배치 순서·위치, 실제 감독 노출과 update 수 |
| 결과 | 구성·seed별 개발 예측, 학습 곡선, 환경·정밀도·토큰 길이·지연·메모리·CU |
| 인수 검사 | 새 프로세스에서 전체 개발 집합의 모델 재로딩·예측 대조, 추론 입력 허용 필드 검사 |

`results.zip`만으로는 실행 코드·데이터가 전달되지 않는다. `upload.zip`과 manifest를 함께 전달한다. 전체 base 가중치를 포함하지 않을 때에는 내려받을 정확한 revision을 지정한다. 저장 임베딩 위 출력층 검산과 전체 encoder 재실행 검산도 구분한다. LoRA 학습 중에는 원래 고정 encoder의 캐시를 재사용하지 않으며, 추론 캐시 키에는 adapter·전처리 버전까지 포함한다.

## 11 선행연구와 기여 범위

[CounterMem §3.4·부록 C/E](https://arxiv.org/html/2609.31874v1)는 작은 MLP의 기억 선택·보류 학습과 조건 정보의 중요성을 이미 다룬다. 별도 모델을 붙이는 것만으로 새 기여가 되지 않는다. [BASM §5.3](https://arxiv.org/html/2608.22339v1)은 조건 문구와 실행 중 복구를 비교하므로 조건을 명시하는 효과 자체도 선행연구가 있다.

[CICL §3.6·§6](https://arxiv.org/html/2606.08151v4)은 선형·MLP·QLoRA를 사용하지만 실제 코드의 주요 평가는 파일 검색이고 공식 수정 성공과 구분한다. 우리도 관계 분류 성적을 코드 해결 성과로 바꾸어 설명하지 않는다. [MemHarness §4.3](https://arxiv.org/html/2607.28272v1)은 현재 상태에 맞춘 기억 재구성과 정책 학습의 연결을 다룬다. 외부 모델이 작성한 그럴듯한 판단이 작업 에이전트의 행동을 개선하는지는 별도로 검증해야 한다.

이 계획에서 확인하려는 것은 **같은 경험의 적용 조건을 대조해 배우는 신호가 새 출처의 관계 판단과 실제 제공 정책에 더하는 가치**다. 단순 기준선이 충분하거나, 관계 개선이 정책 개선으로 이어지지 않는 결과도 그 범위를 명확히 남긴다.
