# 기억 사용의 추론을 위한 추가 데이터와 대조·증강 설계

2026-11-09. **다음 수집은 기억의 주제를 넓히면서, 근거 결합·충분성 판단·전제 확인·누락 정보 확인을 직접 요구하는 사례를 확보하는 방향이 적절함.** 현재의 검색·관계 판독 결과를 실제 기억 사용으로 연결하는 데 필요한 보강임. 아래는 공개 원문·스키마·라이선스 조사와 후속 설계이며, 새 모델 학습이나 효용 실험의 결과가 아님.

[앞선 공개 데이터 조사](ai-memory-fresh-dataset-survey-2026-11-09.md)는 대화·개발·도구 경험의 원천을 넓혔음. 이번에는 그 자료에서 **무엇을 추론하도록 학습·평가할지**를 구체화함. [기존 수집·증강 원칙](ai-memory-data-collection-and-taxonomy-2026-11-08.md)의 출처 가족 분할과 관계/효용 구분을 유지함.

## 추가 수집원과 맡길 역할

| [MQuAKE](https://github.com/princeton-nlp/MQuAKE) | 변경 전·후 사실 사슬, 여러 단계 질문, 변경된 답 | 기억 갱신의 전파, 오래된 지식과 새 지식 충돌, 사실 조합 | 반사실과 실제 시점 갱신을 구분함. 충돌을 수정한 CF-3k-v2를 우선 사용함 |
| [ToolSandbox](https://github.com/apple-aiml-research/ToolSandbox) | 상태가 있는 도구, 선행 조건, 정보 부족 시나리오, milestone/minefield | 기억에 따른 실행·확인·보류, 잘못된 행동과 비용 | 기본 과제는 cross-session memory 쌍이 아님. 과거 경험을 별도로 만들고 상태를 복원해야 함. 일부 검색 도구는 외부 API를 사용함 |
| [CL-bench](https://huggingface.co/datasets/tencent/CL-bench) | 새 규칙·절차·도메인 지식을 적용하는 문맥과 평가 기준 | 관계 판독을 넘어선 규칙·절차 적용의 외부 평가 | **현재 라이선스는 평가 전용임. 학습·보정·증류·적응·파라미터 갱신 및 학습용 파생 증강에 사용하지 않음** |
| [CL-bench Life](https://huggingface.co/datasets/tencent/CL-bench-Life) | 대화, 문서 수정 이력, 활동 기록처럼 파편화된 문맥 | 갱신·충돌·분산 근거를 실제 생활 형식에서 평가 | **평가 전용임.** 같은 CL-bench 계열이라는 점과 공유 문맥을 고려함 |
| [CRAG](https://github.com/facebookresearch/CRAG/blob/main/docs/dataset.md) | 시점, 동적 정보, false premise, 여러 검색 결과 | 관련 있어 보이는 자료와 충분·신뢰 가능한 근거의 차이, 시점 판단 | 웹 검색 자료가 개인의 경험 기억은 아님. 문서 수정 시각만으로 사실의 유효 시점을 확정하지 않음 |

각 역할은 우리 연구에 대한 제안임. 원래 벤치가 기억의 제공/보류 효과를 측정한다는 뜻은 아님. 실제 경험 출처는 앞선 조사에서 제안한 PersonaMem-v2·정제한 Mem2ActBench·개발 실행 로그와 함께 확보함.

### 정답을 확인하는 구조가 있는 자료를 먼저 활용함

ProofWriter는 사실·규칙·질문에서 결론과 증명을 만들고, 결론에 필요한 누락 사실을 찾는 제한된 abduction 과제를 제공함. 따라서 “관련 있는가”에 더해 **지금의 근거로 결론이 성립하는가, 무엇을 더 알아야 하는가**를 정의하기 좋음. 공식 RuleTaker 저장소는 논리 생성·추론 코드를 제공하지만, README에 따르면 해당 초기 구현은 증명 자체를 반환하지 않음. 그대로 실행하면 ProofWriter의 모든 증명 주석을 재현한다고 가정하지 않음.

FOLIO는 자연어와 논리식의 연결을 제공해 템플릿 논리만으로 구성되는 문제를 보완할 후보임. [논문](https://aclanthology.org/2024.emnlp-main.1229/)의 규모는 1,430개 결론·487개 전제 집합이며 현재 HF v2의 행 수를 확인한 수치가 아님. 전제 집합/story를 가족으로 묶음. HF 미러나 구 공개판을 최신 수정판으로 부르지 않음.

MuSiQue 공식 변환·평가 코드에는 `question_decomposition`, `paragraph_support_idx`, `is_supporting`, `answerable`가 있음. Full의 평가기는 같은 질문에 두 사례가 있음을 확인하고 그룹 단위 충분성 지표를 계산함. **정답 질문은 같고 근거 충분성이 다른 대조**를 만드는 데 특히 유용함. 공식 자료는 CC BY 4.0으로 안내하며, 원천 단일 질문의 dev/test 누출 가능성을 별도로 경고함.

MQuAKE 공식 README는 변경 전후 triple·단일 단계 질문·최종 답을 연결함. CF-3k-v2는 3,000개 사례이며, 질문 바꿔쓰기 세 개를 독립 사례로 세지 않음. 제공하는 사실 사슬의 답은 검산할 수 있으나, 그 사슬이 전체 세계의 모든 대체 경로를 표현한다고 가정하지 않음.

ToolSandbox에서 직접 읽은 `find_current_city_insufficient_information` 시나리오는 현재 위치를 얻는 도구가 제공되지 않은 상태에서 근거 없는 위치 검색을 minefield로 설정함. 이처럼 **정보 부족 상태에서 실행하지 않는 행동을 검사하는 구성**을 참고할 수 있음. 다만 현명한 질문·정확한 설명·보류를 모두 같은 성공으로 볼지는 우리의 새 과제 계약에서 정의해야 함. 공식 실행 점수 자체를 그대로 “적절한 기억 판단”으로 해석하지 않음.

### 문맥 학습 벤치는 외부 평가로 보존함

CL-bench와 Life의 고정 revision에서 실제 첫 JSONL 레코드까지 확인함. 두 자료 모두 `messages / rubrics / metadata` 구조임. CL-bench에는 `context_id`가 있었고, Life의 첫 표본에는 없었음. 같은 문맥·상위 원천을 식별할 추가 확인이 필요함.

이 자료는 전체 문맥을 입력하는 평가임. 이를 기억 검색·압축 과제로 바꾸려면 과거 문맥과 현재 요청을 나누는 규칙을 먼저 정하고, 전체 문맥 조건을 기준선으로 남겨야 함. 원래 벤치와 동일한 평가라고 부르지 않음. 최종 요청·rubric을 보고 정답 관련 부분만 과거 기억으로 만든 조건은 oracle 진단임.

현재 라이선스상 학습에 이용하지 않음. 앞선 조사에 나온 EvoMemBench의 CL-bench 파생 부분도 원천을 추적해 자동 학습 편입에서 제외함. 논문상의 사용 사례나 HF split 이름이 현재 이용 조건을 대신하지 않음. 제한 없는 별도 원천에서 일반적인 추론 유형을 구현하되, CL-bench의 사례·문맥·rubric을 학습 예제로 재작성하지 않음.

| 1. 전제·적용 조건 전환 | 같은 기억·요청을 유지하고 실제 현재 상태를 바꿈 | “이 명령은 도구 X가 설치돼야 실행 가능” 기억에 대해 현재 X 설치/미설치/미확인 | 환경·도구 계약 확인. 미설치를 항상 실패나 피해로 라벨링하지 않음 |

| 5. 참·거짓·미확인 구분 | 질문·관측 시점을 고정하고 지지/반대/무근거를 구분함 | “예약 취소됨”은 취소 기록이 있는 경우, 유지 기록이 있는 경우, 기록이 없는 경우가 다름 | 명시적 부정과 근거 부재를 구분함. 모순된 입력은 별도 표시하거나 제외함 |
| 6. 시간 갱신·범위 | 같은 사건·기억을 유지하고 질문 기준 시점·주체·범위를 바꿈 | 월요일에는 주소 A, 화요일부터 B. “월요일 배송 주소”와 “현재 배송 주소”의 답이 다름 | 사실의 유효 시점과 질문 시점을 대조함. 최근 문장이라는 이유만으로 우선하지 않음 |
| 7. 예외·반례 | 일반 규칙과 용어를 유지하고 적용 전제·예외를 추가함 | “24시간 내 무료 취소”지만 “특가 상품 제외”; 현재 상품이 특가인지가 달라짐 | 명시한 정책·상태로 실행/제약 검사함. 문구만 바꾸고 실제 정답은 유지하지 않음 |
| 8. 절차·상태 전이 | 같은 작업 목표·행동 목록에서 초기 상태·순서를 바꿈 | 로컬 모의 환경에서 연결 후 전송이 필요함. 이미 연결됨/끊김에 따라 첫 행동이 달라짐 | 각 행동의 전제와 최종 상태 검사. 유효한 복수 순서를 정답으로 허용함 |
| 9. 진단 가설 구분 | 같은 실패 증상을 유지하고 가설을 구분하는 관측을 바꿈 | 같은 import 오류지만 패키지 미설치/다른 인터프리터 사용을 구분함 | 최소 재현 환경의 명령·관측·복구 성공으로 확인함. 오류 문자열 유사도는 정답이 아님 |
| 10. 의미 유지·표현 교란 | 사실·논리·답을 유지하고 표현·순서·이름·방해 문서를 바꿈 | 동일한 근거를 두 문장/한 문장, 역순, 다른 고유명사로 표현함 | 구조화한 사실·ID 대응·추론 결과가 같은지 검사함. 단어 중복만 줄어든 사례도 포함함 |

처음에는 2·3·4의 **충분성·결합·누락 전제**, 그리고 1의 **현재 상태 전환**을 우선함. 5·6은 정상적 보류와 갱신을 위한 공통 기반으로 사용함. 7–9는 실행 검증 가능한 환경·출처를 확보한 뒤 확장함. 열 가지를 한 번에 학습 목표로 추가하지 않음.

### 원문·요약·복원 대조도 추론 유형에 연결함

원문 R → 요약 S → 누락 전제/관측을 복원한 S+O를 같은 경험에서 만듦. 내용 압축으로 무엇을 잃었는지 원문 근거에 연결함. “과거 환경에 X가 없었음”과 “현재 환경에도 X가 없음”은 다른 명제임. 요약에 과거 검사 통과를 복원해도 현재 수정이 옳다는 보증으로 쓰지 않음.

효과가 보이면 O만 제공하는 조건으로 과정 정보만의 기여를 확인함. 그 다음 같은 정보량의 서술형·지시형 표현을 비교함. 복원본에 정답 위치·수정법을 새로 넣고 표현 효과라고 해석하지 않음. 전체 원문 조건은 길이·잡음도 함께 달라지므로 S+O−S의 통제된 비교와 분리해 보고함.

## 작은 예제로 보는 정답의 변화

현재 요청: “내일 민수가 묵는 숙소의 조식 시작 시각은?”

- A: “내일 민수는 H호텔에 묵음.”
- B: “H호텔 조식 시작은 07:00임.”
- C: “J호텔 조식 시작은 08:00임.”

주어진 기록만으로 답해야 하는 조건에서 A+B는 07:00을 지지함. A만 있으면 조식 시간이 부족하고, B만 있으면 민수의 숙소 연결이 부족함. C는 같은 주제의 가까운 방해 기억임.

여기에 현재 입력으로 “예약이 J호텔로 변경됨”을 제공하면 적용할 연결은 바뀜. 최신 예약의 유효성과 변경 대상이 확인됐다면 B를 고집하지 않고 C를 활용해야 함. 현재 입력에 J호텔 조식 시각까지 이미 있으면 추가 기억이 없어도 답할 수 있음.

이 예제는 다음을 각각 구분함.

1. 어느 기억이 관련 있는가.
2. 기억들이 함께 충분한가.
3. 현재 정보가 과거의 적용 조건을 바꿨는가.
4. 부족한 경우 무엇을 확인해야 하는가.
5. 그 기억을 실제로 받은 작업자가 더 정확하고 저렴하게 답하는가.

1–4의 정답이 있어도 5의 성능 향상을 미리 붙이지 않음. 작업자가 부적합한 기억을 무시하거나 경고로 활용할 수도 있음.

## 증강 정답을 어떻게 신뢰할까

**구조화한 원형 → 변형 규칙 → 정답 재계산 → 자연어 표현 → 검산** 순서로 구성함.

- 논리 자료는 사실·규칙의 의미 체계를 고정함. OWA에서는 결론과 그 부정 모두 증명되지 않으면 미확인임. 둘 다 성립하면 모순 입력으로 구분함. 단순 미증명을 거짓으로 바꾸지 않음.
- 전제 하나를 지웠다고 충분성이 반드시 바뀌지는 않음. 다른 증명 경로·현재 문제·공통 카탈로그·도구 관측에 같은 정보가 남았는지 확인함. 기존 여행 자료에서 가격을 기억에서 지워도 공통 카탈로그에 남을 수 있었던 문제를 반복하지 않음.
- 누락 전제 후보는 여러 개일 수 있음. 하나의 정답 질문만 강요하지 않고 모든 검증된 해법·그 비용을 저장함. 어떤 사실이 결론을 가능하게 한다는 것은 현실의 원인이라는 뜻이 아님.
- 실행 과제는 초기 DB·도구·버전·관측을 함께 바꿈. 명령의 이름이나 숫자만 바꾼 텍스트를 새 환경의 검증 사례로 세지 않음.
- 자연어 재표현은 수량·주체·부정·시간·양화 범위를 검사함. LLM 생성/판정의 합의만으로 의미 동등성을 확정하지 않음. 정형화할 수 없는 사례는 근거 주석과 독립 검토를 남김.
- FOL 추론기의 timeout/unknown은 데이터의 의미상 미확인 정답과 다름. 정답을 확인하지 못한 증강은 보류함.
- 논리 구조를 알파벳이나 문장 형식으로 드러내지 않음. 정답별 길이·숫자·부정어·출처·표현 분포와 query-only/memory-only 기준선을 검사함.

## 선택기의 입력과 학습 목표

입력은 `현재 요청 + 현재 관측 + 후보 기억 집합`으로 둠. 가능한 목표는 근거 ID, 결론의 지지 상태, 필요한 근거의 충분성, 누락 변수, 제공/확인/보류 행동임. 모든 목표를 처음부터 한 모델에 넣을 필요는 없음.

현재의 query–memory 개별 판독기는 후보를 찾는 기반으로 유지함. **“A만으로는 부족하고 A+B는 충분함”은 개별 점수만으로 학습하기 어려우므로**, 소수의 상위 후보를 함께 보는 집합 판독이나 단계별 선택을 별도로 비교할 필요가 있음. 모델을 크게 바꾸기 전에 충분성·조건 판단을 보조 목표로 추가하는 소규모 비교부터 가능함.

긴 사고 과정의 길이를 보상하지 않음. 먼저 `근거 ID + 짧은 적용 조건 + 부족한 항목 + 선택 행동`처럼 외부에서 확인할 수 있는 출력을 감독함. 설명·증명은 평가 가능한 경로와 결론이 맞는지를 검사하며, 그 출력이 모델 내부 사고의 충실한 기록임을 주장하지 않음.

라벨은 다음처럼 분리함.

| 필드 | 의미 |
| --- | --- |
| `support_status` | 정해진 명제에 대한 지지/반박/미확인/모순 여부 |
| `applicability` | 그 과거 관측·절차를 현재 조건에 사용할 수 있는가 |
| `bundle_sufficiency` | 현재 관측과 선택 기억 집합으로 요구를 충족할 수 있는가 |
| `missing_variables / valid_checks` | 무엇을 더 알아야 하며 어떤 확인이 유효한가 |
| `observed_worker_outcomes` | 실제 제공/보류 조건별 출력·성공·비용. 미실행이면 null |

과거 사실은 참이면서 현재 적용 불가일 수 있음. 적용 가능해도 답에 불충분하거나 현재 입력에 이미 있을 수 있음. 어떤 경우도 실제 유익/유해 라벨로 자동 치환하지 않음.

## 효과를 수치로 어떻게 확인할까

| 층 | 주 지표 | 해석 |
| --- | --- | --- |
| 개별 판단 | 적용 조건·지지 상태별 정확도/혼동행렬, 미확인 정밀도·재현율 | 근거 부족과 반박을 구분했는가 |
| 대조 | 원형과 변형을 **둘 다** 맞힌 비율, 의미 유지 쌍의 정확도·일관성 | 같은 답만 출력하는 지름길을 배제함. 일관되게 틀린 경우도 분리함 |
| 근거 집합 | 충분한 근거를 모두 포함한 비율, 최종 답/실행까지 맞힌 비율, 토큰 비용 | 개별 Recall 상승이 필요한 조합의 확보로 이어지는가 |
| 확인 행동 | 유효한 확인 선택률, 확인 후 정답률, 요청·시간·도구 비용 | 모른다는 판단을 유용한 다음 행동으로 연결했는가 |
| 실제 득실 | 같은 초기 상태에서 제공/보류의 성공률 차이·비용 차이 | 원래 관심인 기억 효과 |
| 일반화 | 새 가족·새 원천·보지 않은 추론 조합별 위 지표 | 같은 부모의 문장 변형을 잘 푼 것과 구분함 |

실제 효용은 동일 snapshot·worker·예산에서 기억 조건을 배정하고 비교함. 무기억 성공/기억 실패의 관측 악화와 그 반대의 관측 개선을 함께 보고함. 확률적인 worker의 한 실행 쌍을 특정 기억의 확정적인 피해 라벨로 쓰지 않음. 반복·환경 난수·독립 가족 수를 남기고 가족 단위 집계/구간을 사용함.

두 기억 A·B의 조합은 네 조건의 평균 성공률 `p00 / p10 / p01 / p11`을 따로 보고함. 상호작용 `p11−p10−p01+p00`도 계산할 수 있으나, 이것만으로 내부 추론 메커니즘을 입증하지 않음. A+B에는 정보량도 늘어나므로 같은 길이의 방해 정보 조건과 내용 누출 확인을 보조 통제로 둠. 예산·제공량이 다른 조건의 성공 차이를 추론 능력의 차이라고 단정하지 않음.

확인 행동의 가치는 확인 뒤 얻을 수 있는 정보와 비용을 함께 정의해야 함. 논리적으로 적절한 질문이라는 정답과 고정 worker에서 비용을 들여 확인할 가치가 있다는 결과는 별도임. 최종 성공·토큰·지연·확인 횟수를 우선 각각 보고하고, 단일 점수의 비용 가중치는 개발 자료에서 사전에 정함.

## 권장 실행 순서

1. **원천별 사례 카드부터 확보함.** 실제 경험의 사람·도구·정책·개발 출처를 넓히면서, 충분성·결합·전제 전환이 명확한 20–30개 부모 가족을 첫 설계 목표로 둠. 논리 보조 자료와 실제 경험의 수를 별도 집계함. 이 수가 통계적 충분성을 보장하지 않음.
2. **가족을 먼저 분할하고 각 원형에 3–5개 검증된 변형을 붙임.** 학습용 파생은 학습 가족 안에서만 생성함. 평가 대조도 평가 부모 안에서 별도로 만들며 학습에 넣지 않음. 같은 원천 문단·전제 집합·사실 사슬을 공유하는 질문의 누출을 점검함.
3. **근거 결합·삭제/복원·누락 전제부터 정답 품질을 확인함.** 형식적 자료는 추론기, 행동 자료는 로컬 상태/도구 검사, 자연 자료는 근거·독립 검토로 확인함. 새 자연 가족의 수와 증강 자식 수를 분리함.
4. **기존 학습 / 표현 증강 / 검증된 추론 증강을 비교함.** 공통 부모·학습 토큰/업데이트 예산·모델·checkpoint 선택을 맞추고, 추가 출처 효과와 변형 효과를 분리함. 먼저 데이터 구성의 기여를 검증하며 layer·loss 변경을 동시에 섞지 않음.
5. **새 원천의 자연 사례를 확인 평가로 남김.** 학습에 쓴 템플릿의 더 긴 버전만으로 일반화를 평가하지 않음. 여러 단계 결합·갱신·예외를 함께 요구하는 보지 않은 조합도 별도 진단함. CL-bench 계열은 평가로만 사용함.
6. **마지막에 실제 worker의 득실을 측정함.** 고정 검색/선택, 학습 선택, 충분한 근거를 주는 상한과 무기억을 비교함. 개선뿐 아니라 부적합 기억의 과잉 사용·불필요한 확인·제출 지연도 저장함.

원래 연구 질문은 유지함. 이 자료 확장의 성공 조건은 “추론 보조 벤치 점수가 상승함”에 더해 **새 현재 상태에서 무엇을 기억으로 제공·확인·보류할지 더 잘 결정하고, 실제 성공·악화·비용이 개선되는가**임.
