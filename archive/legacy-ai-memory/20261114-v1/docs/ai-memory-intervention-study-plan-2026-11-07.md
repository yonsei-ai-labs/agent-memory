# 메모리 조각의 득실: 개입·삭제·복원과 독립 확인 설계

2026-11-07. 사용자가 전달한 외부 리뷰와 [논문 재검토](ai-memory-literature-revisit-2026-11-07.md)를 반영한 후속 설계다. **새 유료 실행은 하지 않았다.** 아래 수치 예시는 합성 예시 또는 설계 계산이며 기존 실험 결과와 구분한다. 실행할 과제 목록·최종 표본 수·배정은 아직 확정하지 않았다.

## 1. 판단과 우선순위

**수치로 검증할 수 있다. 핵심은 기억 전체의 순효과, 특정 조각의 조건부 기여, 그 효과가 나타나는 상황을 따로 정의하는 것이다.** 긍정적인 사례를 설명하는 데서 끝내지 않고, 그 조각의 삭제·복원·조건 교정을 새로운 실행에 배정해야 한다.

외부 리뷰의 네 지적에 동의한다. 현재는 제출 성공과 수정 도달이 분리되지 않고, F/FP는 정보량도 바꾸며, 구체적 옛 처방이 직접 적용되는 양성 사례가 없고, 독립 출처·대상이 적다. 리뷰에서 보고한 18,390개 원본 해시·60개 테스트 통과는 리뷰의 검증 결과로 받아들인다. 이번 설계 작업에서 그 검사를 다시 수행했다고 주장하지 않는다.

다음 순서를 권한다.

1. 기존 탐색 과제에서 공통 마지막 제출 안내·수동 개입 없는 중간 패치 저장·여유 예산을 교정한다.
2. **새 출처·대상에서 과정 정보 복원의 기여 하나를 주 비교로 삼는다.** 정보 표현과 검색 방식은 고정한다. 새 출처를 마지막까지 미루지 않는다.
3. 관찰한 기여를 작은 단위의 삭제·복원으로 좁히고, 같은 명제의 서술/지시와 적용 전제의 역할은 별도 회차에서 비교한다.
4. 발견에 쓰지 않은 출처·대상에서 편집과 판정 규칙을 고정해 다시 검사한다. 확인 결과가 반대이거나 미확정이면 그대로 보고한다.

“원래 기억이 유익한 것을 먼저 확인한 뒤 삭제한다”는 절차도 가능하지만, 같은 작은 표본에서 유익했던 기억만 골라 분해하면 선택 편향이 생긴다. 기억 전체가 평균 0이어도 유익한 조각과 해로운 조각이 상쇄됐을 수 있다. 따라서 첫 실험부터 무기억 기준과 미리 고른 조각의 삭제/추가 대조를 함께 둔다.

## 2. 무엇을 측정해야 어떤 주장을 할 수 있는가

대상 t, 출처 m, 예산 b와 고정된 에이전트에서 `p(X)`는 **기억 조건 X에 배정했을 때 예산 안에 공식 해결물을 실제 제출할 확률**이다. N은 외부 출처 경험을 전혀 주지 않는 기준이다. M은 전체 기억, u는 미리 정한 근거 조각이다.

| 질문 | 비교 | 정당한 해석 |
| --- | --- | --- |
| 기억 전체가 이득인가 | `p(M) − p(N)` | 이 과제·출처·모델·예산에서의 평균 순효과 |
| 이 조각을 빼면 달라지는가 | `p(M) − p(M−u)` | 나머지 기억이 있는 상태에서 u를 제공한 기여 |
| 이 조각만으로도 도움이 되는가 | `p(u) − p(N)` | 독립적으로 이해 가능한 u 단독 패키지의 효과 |
| 문제 있는 조각을 교정하면 좋아지는가 | `p(M−u+u*) − p(M)` | 삭제가 아닌 사전 정의한 교정의 효과 |
| 어떤 상황에서 기여가 바뀌는가 | `Δu(적합) − Δu(부적합)` | 해당 집단에서의 효과 차이. 자연 과제 집단이면 상황 자체의 인과 효과는 아님 |
| 행동을 바꿨는가 | 사전 정의한 행동 지표의 조건 간 차이 | 입력 개입이 행동에 준 효과. 그 행동이 성공을 매개했다는 증명과는 다름 |

음의 `p(M)−p(M−u)`가 충분히 뒷받침되면 “u를 빼는 편이 이 맥락에서 낫다”고 할 수 있다. **전체 기억이 무기억보다 해롭다, u가 언제나 해롭다, 모든 실패가 u 때문이라는 뜻은 아니다.** 반대로 삭제 후 차이가 없다고 필수 정보가 아니라고 확정할 수 없다. 반복 잡음·낮은 검출력·다른 조각의 중복 대체가 원인일 수 있다.

필요성·충분성도 절대적인 표현을 피한다. 삭제로 성과가 떨어지면 그 구성에서의 의존성을, 단독 제공으로 좋아지면 그 패키지의 단독 기여를 뒷받침한다. 특정 문장이 모든 해결에 논리적으로 필요하거나 단독으로 해결을 보장했다고 말하지 않는다.

### 계산 예시: 전체로는 이득인데 일부는 손해일 수 있다

**다음은 실험 결과가 아닌 합성 수치다.** 반복과 불확실성을 설명하기 위한 성공률을 가정했다.

| 가상 조건 | 가정한 성공률 |
| --- | ---: |
| N: 무기억 | 40% |
| O: 과정 정보만 | 70% |
| C: 구체적 과거 처방만 | 35% |
| M=O+C | 60% |

- 기억 전체 순효과: `60−40 = +20%p`.
- O가 있을 때 C의 기여: `60−70 = −10%p`. C를 빼면 10%p 개선된다.
- C가 있을 때 O의 기여: `60−35 = +25%p`.
- 상호작용: `60−70−35+40 = −5%p`.

이처럼 전체 이득과 조각의 손해는 함께 존재할 수 있다. 마지막 두 조각의 조건부 기여를 단순 합산해 전체 효과라고 할 수 없다. [NIST의 요인 설계](https://www.itl.nist.gov/div898/handbook/pri/section3/pri3331.htm)처럼 상호작용을 측정하려면 네 조합이 필요하다. 공통 출처 맥락 B를 모든 조합에 주는 실제 설계라면 기준은 B이지 진짜 무기억 N이 아니다. 순이득을 위해 N을 별도로 둔다.

| 논문·구간 | 실제 실험 형태 | 우리에게 필요한 대응 |
| --- | --- | --- |

| [BASM §3.4·부록 A.2/A.4](https://arxiv.org/html/2608.22339v1) | 길이와 위치를 비슷하게 맞춘 대조, 같은 입력에서 경계 구간 attention만 차단하는 개입, 다른 구간 차단 대조를 둔다. 행동 선택·로그잇과 전체 작업 성과를 구분한다. | API에서는 특정 문장을 삭제·대체·복원하고 길이·일반 숙고 안내를 대조할 수 있다. 이는 입력 개입의 효과이며 attention 경로의 인과 재현이 아니다. 비교 입력의 다른 변화도 기록한다. |

이 논문들에서 가져올 설득 구조는 **전체 성과 → 구성요소 개입 → 다른 설명을 겨냥한 대조 → 행동 진단 → 새 조건에서 확인**이다. 모든 논문이 이 단계를 똑같이 충족하거나 단일 조각의 신경 메커니즘까지 증명한 것은 아니다.

## 4. 첫 주실험: 과정 정보 복원과 삭제를 같은 비교로 만든다

### 가설 H1

같은 출처의 해결 요령 S에 실제 관측한 도구·검사 과정 O를 복원하면, 새 대상에서 예산 내 해결률 또는 비용이 개선된다. 기존 48회에서 도구 부재가 45회 관측된 것은 **이 가설을 만든 탐색 근거**다. 도구 오류를 줄이면 해결률도 오른다고 미리 가정하지 않는다.

| 조건 | 구성 | 비교의 목적 |
| --- | --- | --- |
| N | 외부 출처 경험 없음 | 순효과 기준 |
| R | 사전 선택 규칙으로 만든 같은 source의 원문 근거 묶음 | 원문 경험 제공 및 가공 비교 기준 |
| S | source 해결 요령, 현재와 같은 고정 형식 | 과정 정보가 빠진 요약 |
| M=S+O | 정확히 같은 S + source의 과정 관측 | O의 복원. `M−O=S`가 정확히 성립해야 함 |

**주 대비: `p(M)−p(S)`**. 보조 대비는 `p(M)−p(N)`, `p(R)−p(N)`, `p(S)−p(R)`다. 먼저 정한 주 비교에 대한 불확실성을 보고한다. 가장 좋은 조건만 골라 무기억과 사후 비교하지 않는다.

주 결과는 공식 해결률 차이다. 같은 조건 대비의 오류·비용은 사전 지정한 보조 결과로 각각 보고한다. 성공 개선이 미확정이고 오류만 줄었다면 오류 감소까지만, 비용만 줄었다면 관측한 비용 감소까지 말한다. 이를 성공 개선이나 성과 보존이 확인된 효율 개선으로 바꾸지 않는다. 여러 보조 지표의 확인적 주장에는 다중 비교 규칙도 정한다.

R은 S와 O의 출처를 포괄하는 원문에서 뽑는다. O만 담긴 원문과 해결 요령 S를 비교하고 “요약의 정보 손실”이라고 부르면 안 된다. 발췌는 대상의 결과·정답을 보지 않은 규칙으로 고정한다. 원문 전체를 넣는 것과 선택 발췌를 구분하고 입력 한도·잘림·비용을 기록한다. R/S의 차이는 처음에는 내용 선택·길이·구조가 함께 바뀌는 가공 패키지의 효과다.

O는 우선 세 범주로 나눈다: 도구 부재, 실패한 검사 진입점, 실제 실행한 대체 검사 명령·결과. 모든 주장은 source 근거 ID와 연결한다. source의 검사 성공·공식 판정·증거 한계는 변형 간 보존한다. “출처 컨테이너에서는 그랬다”를 “현재도 반드시 그렇다”로 바꾸지 않는다.

### 추가 피드백을 대조한 결과와 보완

기존 48회의 도구 관측과 실제 delivered_success를 다시 연결했다. 성공 15회 중 14회, 비성공 33회 중 31회에서 해당 도구 오류가 관측됐다. 오류가 없었던 실행도 3회뿐이다. [교차 집계](design-data/component-intervention-20261107/tool-error-outcome-crosscheck.json)를 남겼다. 이 관찰은 오류를 실패 원인으로 지목하지 못하며, 오류 발생·비용·성공 개선은 각각 판정해야 한다. 셋 중 하나만 달라져도 그 범위의 결과로 보고한다.

추가 피드백의 정보 종류 구분을 첫 회차의 기록 기준에 반영한다. `pytest` 부재는 검사 도구를 실행하다 관측했지만 내용의 성격은 환경 정보다.

| 종류 | 현재 예시 | 별도로 기록할 것 |
| --- | --- | --- |
| E: 실행 환경 관측 | `rg` 부재, `pytest` 모듈 부재 | source 관측 시점·환경, 현재 상태에 관한 사전 판단의 근거/불명, 실제 재시도·대체 행동 |
| V: 검사 절차·검증 근거 | `bin/test …test_quantities.py`와 당시 결과 | 검사 범위·전제, 현재 문제와의 관계, 실제 실행한 명령·결과, source 검사와 target 해결 판정의 구별 |

처음에는 O=E+V를 복원하되, E와 V의 행동·적용성은 따로 읽는다. 다음 회차에서 S/S+E/S+V/S+E+V를 모두 비교하면 두 종류의 조건부 기여와 상호작용을 잴 수 있다. 주 실험에 이 조합을 전부 추가하지 않는다. 빠뜨린 정보의 선정 규칙은 source의 실제 실패 명령·대체 실행·검사 관측에서 정하고, 새 target의 결과를 보고 유리한 항목만 복원하지 않는다. 해당 정보가 있는 source를 선별했다면 그 모집단 제한도 명시한다.

### O 단독과 환경 안내 대조가 해결하는 질문은 서로 다르다

**O 단독은 가치 있는 후속 조건**이다. 별도 회차의 N/O/S/S+O는 독립적으로 이해 가능한 두 패키지의 2×2 비교가 된다.

```text
O의 단독 효과       = p(O) − p(N)
S가 있을 때 O 기여  = p(S+O) − p(S)
S와 O의 상호작용    = p(S+O) − p(S) − p(O) + p(N)
```

O만으로 충분한 성과가 나는지, S와 결합했을 때 추가 이득이 있는지를 구분할 수 있다. “O는 유의하지 않고 S+O는 유의하다”는 비교만으로 상호작용을 주장하지 않는다. O와 S+O가 비슷한 점추정이라는 이유만으로 동등하다고 하지도 않는다. 각 패키지의 출처·결과·한계가 단독으로 읽혀야 하고, 공통 출처 맥락 B를 따로 고정한 설계라면 B와 진짜 N을 구분한다.

다만 **“복원 효과”와 “환경 정보 제공 효과”가 본질적으로 별개의 원인인 것은 아니다.** 복원한 조각이 환경 정보라면 그 정보를 제공해서 얻는 이득이 바로 복원 개입의 효과일 수 있다. 완전히 같은 사실·문구를 주면서 연구자가 복원/사전 안내라는 이름만 달리 붙이면 다른 처치가 되지 않는다. 이 경우 주장할 내용은 “요약이 빠뜨린 환경 정보를 복원한 패키지의 기여”다. 그 정보가 과거 경험에서 왔기 때문에 더 유리했다고 주장할 수는 없다.

경쟁하는 실용적 설명을 확인하려면 **현재 환경에서 직접 확인한 시작 안내 A_env**를 후속 기준으로 둔다. 예를 들어 N/M/A_env/A_env+M에서 `p(A_env+M)−p(A_env)`를 보면, 현재 도구 상태를 알려준 뒤에도 과거 경험이 추가 가치를 주는지 알 수 있다. A_env는 공개 환경의 도구·경로 확인만 담고 정답·숨겨진 검사는 포함하지 않는다. O 단독은 “과정 정보만으로 되는가”, 이 비교는 “현재 환경 안내에 더해 과거 기억이 필요한가”를 묻는다. O가 틀리거나 오래됐을 때의 적용성도 따로 기록한다.

A_env를 만드는 확인 비용도 기록한다. 같은 환경에서 한 번 확인해 공유했다면 재사용 횟수에 따라 상각하고, source 기억의 수집·작성 비용과 같은 기준으로 비교한다. 현재 안내를 무료로 얻는다고 가정하면서 과거 기억 비용만 더하지 않는다.

현재 정보를 주는 합리적인 기준에서도 기억 이득이 남아야 한다고 **첫 파일럿의 유효성 조건**을 새로 만들지는 않는다. 처음에는 좁은 개입 효과를 재고, 넓은 연구 기여를 주장할 때 이 기준과 비교한다. 효과가 환경 안내로 설명된다면 재사용 가능한 실행 환경 정보의 가치라는 결론으로 좁힌다. 요약·기억 일반의 우월성을 주장하지 않는다.

### 다음 삭제·복원은 어떻게 하는가

첫 회차의 O는 하나의 사전 정의한 묶음이다. 그 내부 항목은 다음 탐색 회차에서 `M−도구부재`, `M−검사진입점`, `M−대체검사`처럼 하나씩 삭제한다. 다른 문장·헤더·판정·순서는 그대로 두고 문맥이 끊기는 참조가 없는지 검사한다. 문장을 새로 전면 재작성하면 단일 삭제 개입이 아니다.

복원은 두 종류를 구분한다.

- **정확한 원문 복원:** `(M−u)+u`의 바이트 해시가 M과 같아야 한다. 이것은 조작 구현 검사다. 새 반복에서 효과가 돌아오는지는 재현 검사이며, 동일 M에 새 이름을 붙인 독립 처치가 아니다.
- **내용 교정:** 오래된 값·적용 전제를 source 근거가 허용하는 범위로 바꾼 `u*`를 사용한다. 삭제보다 교정이 나은지 새 조건으로 비교한다. 현재 대상 정답에서만 알 수 있는 내용을 교정에 넣으면 정상 메모리 효과가 아니다.

다른 항목 삭제, 비슷한 길이의 근거 문장 대체, 일반적인 확인 안내 등을 후속 대조로 둔다. 이 대조들도 행동을 바꾸므로 완전히 비활성이라고 가정하지 않는다. 지표와 대조 없이 “문장을 빼니 빨라졌다”만으로 그 문장의 의미가 원인이라고 주장하지 않는다.

기존 source를 활용해 [정확한 삭제·복원 예시](design-data/component-intervention-20261107/ablation-example.json)를 만들었다. 기존 대상 결과를 본 뒤 만든 **설계 예시**이며, 새 확인 기억이나 실행 은행이 아니다.

## 5. 두 번째 축: 정보 표현과 적용 전제

### 같은 정보의 서술/지시 비교

같은 명제 집합에서만 표현을 바꾼다. 함수명·전제·수정 내용·검사 명령·관측 결과·출처 한계의 대응표를 만들고, 한쪽에만 새 조언·지식이 생기지 않게 검토한다. 원래 S에 쓰는 명령형 부분도 검사 대상이다. 명령형에 조건·회복법을 새로 추가하면 표현만 바꾼 비교가 아니다.

N을 함께 두고 서술형·지시형 각각의 순효과와 두 표현의 차이를 본다. 여러 템플릿을 사용하고 템플릿 배정을 고정·균형화한다. 길이·필드 순서·출처 판정·공통 마지막 제출 안내를 맞춘다. 의미 동등성을 토큰 수만으로 인증하지 않는다. 이 비교는 H1의 내용 추가 실험과 별도 회차로 둔다.

### 가설 H2: 구체적 처방의 경계와 원리의 경계를 분리하면 전이가 달라지는가

source/target마다 아래 세 가지 적용성을 독립적으로 `예/아니오/불명`으로 기록한다. 평가자는 공개 문제·기반 코드·실제 source 경험을 이용하고, 대상 정답·숨겨진 테스트·대상 결과를 기준으로 라벨을 만들지 않는다.

| 적용성 | 확인할 전제 |
| --- | --- |
| 구체적 수정법 | 같은 실패 경로·표현이 존재하며 옛 수정이 이미 들어 있지 않은가 |
| 일반 원리 | 다른 경로에서도 그 제약·불변식이 관련되는가. 직접 검증과 연구자 추론을 구분했는가 |
| 실행 과정 정보 | 도구·검사 경로·환경 조건이 양립하는가 |

현재 24213은 옛 Function 수정의 직접 반복이 아닌 다른 분기의 전이이고, 24909도 직접 적용 양성 사례가 아니다. 같은 저장소라는 이유만으로 두 종류를 한 라벨로 묶지 않는다. 새 자연 과제에서 직접 적용 가능한 쌍을 못 찾으면 그렇게 보고한다. 동일 source 과제 재시도를 양성 교정에 쓸 수는 있지만 다른 과제로의 전이 점수와 합치지 않는다.

진단 후보는 `M`, `M+구체적 수정법 경계`, `M+수정법/원리 경계 분리`다. 분리한 안내에서 일반 원리를 새로 도출한다면 **추론 정보가 추가된 정책 패키지**로 표시한다. 경계의 효과만 좁히려면 원리·전제에 관한 사실은 공통으로 두고 적용 판단 지침을 바꾼다. 적용 조건이 틀린 기억을 무조건 쓰는 비율과 적용 가능한 기억까지 과도하게 보류하는 비율을 같이 본다.

두 비율은 적용성 판정이 가능한 사전 사례를 분모로 하고, 불명 비율도 보고한다. 기억을 실제 사용한 실행만 남겨 성공률을 비교하지 않는다. 자연 과제 집단 간 차이는 조절 관계다. 같은 상태에서 전제만 바꾸는 보조 진단을 더하면 좁은 원인을 확인할 수 있지만, SWE의 코드·문제·환경을 변경한 점수는 별도 진단으로 보고한다.

## 6. 세 번째 축: 확인의 이득과 확인 비용

### 가설 H3

기억의 모든 내용을 재확인하는 것보다 다음 행동에 필요한 전제를 확인하는 방식이 성과와 비용의 균형을 개선하는가. 기억을 제공한 상태의 `추가 안내 없음 / 일괄 확인 안내 / 행동 전제 확인 안내`를 비교한다. 일반 재검토 안내와 무기억의 확인 대조도 두어 추가 숙고만의 효과를 진단한다.

최소 확인이란 확인 횟수를 무조건 줄이라는 뜻이 아니다. 예컨대 과거 검사 명령을 재사용할 후보라면 현재의 실행기·경로 조건이 판단에 필요한 전제다. 반복된 source 전체 재현이 꼭 필요한지는 별도 선택이다. 안내를 제시하는 실험과 도구 호출을 강제하는 실험은 구분한다.

성과가 보존됐다는 주장을 위해 사전에 허용 하락 폭을 정한 비열등성 질문이 필요하다. “성공률 차이가 유의하지 않고 비용이 낮았다”만으로 효율 개선을 확정하지 않는다. 비용·성공률의 동시 불확실성 기준을 고정한다. 모두 보류하면 위험 행동이 적어지므로 전체 해결률·보류율도 함께 보고한다.

고정 후보 행동의 전제를 바꾸는 진단은 행동이 실제로 그 전제에 의존하는지를 묻는다. 에이전트가 다시 계획하는 전체 실행은 최종 정책 가치를 묻는다. 두 결과를 섞지 않는다. 분기 비교를 구현한다면 대화·도구 이력·미추적 파일을 포함한 작업 상태·남은 예산을 복원해야 한다. 현재의 patch-only 저장만으로 충분하지 않다.

## 7. 공통 계측: 제출과 수정 도달을 구분한다

| 지표 | 분모·계산 | 목적 |
| --- | --- | --- |
| 주 성과 | 전체 배정 중 예산 내 실제 제출·공식 성공 비율 | 실질적인 작업 전달 |
| 중간 해결 도달 | 사전 저장 시점까지 공식 통과 패치를 한 번이라도 관측한 실행 / 전체 배정 | 수정 도달의 진단 |
| 관측한 통과 패치 뒤 미제출 | 중간 통과가 관측됐으나 예산 내 성공 제출이 없는 실행 / 전체 배정 | 전달 과정의 손실. 해당 조건부 비율도 보조로 표시 |
| 회귀 | 사전 공통 검사에서 새 실패가 생긴 최종 작업 상태 | 검사 범위 안의 부작용. 채점 불명·범위 누락을 0으로 처리하지 않음 |
| 비용 | 모든 배정의 모델 비용·입출력 토큰·실제 요청·도구 호출·호스트 시간 | 성공한 실행만 고르지 않는 자원 비교 |
| 행동 | 실제 명령 오류, 반복 탐색, 전제 확인, 현재 경로에 대한 수정 | 작용 경로 단서 |

모든 조건에서 공통 예산/제출 안내가 입력의 마지막에 오도록 한다. 기억 작성·검색·검증 비용과 모델 요청 수의 관계도 기록한다. 응답 하나에 도구가 여러 개 있을 수 있으므로 명령 오류 건수와 소비한 응답 수를 동일시하지 않는다.

기존 탐색 과제에서 예컨대 10/20응답을 교정 후보로 보고, 첫 주실험에는 여유 있는 예산 하나를 결과 전에 고정한다. 후속 예산 비교는 실제로 각 한도를 사전 고지한 독립 실행으로 한다. 긴 실행의 중간 패치가 통과한 것을 짧은 예산 제출 성공으로 바꾸어 세지 않는다.

중간 패치는 응답 번호 격자와 종료 시점에 수동 개입 없이 저장하고 **종료 후 별도 환경**에서 채점한다. 정확히 같은 패치·기반 환경·검사 명세의 재평가는 묶을 수 있다. 미추적 파일·누락된 변경도 확인하고, 저장 실패는 명시적으로 남긴다. 에이전트에는 사후 공식 판정을 돌려주지 않는다. 최초 통과 시점은 저장 격자에서 최초 관측한 시점이며 정확한 최초 해결 시점은 아니다.

사후에 중간 패치가 통과했다고 그 뒤의 확인을 곧바로 낭비로 분류하지 않는다. 당시 에이전트는 그 판정을 몰랐고 다른 회귀를 확인할 이유도 있었을 수 있다. 후속 검증의 비용은 관측하되 그것이 불필요했는지는 별도의 개입 질문으로 남긴다.

회귀 검사는 원본에서 통과하고 적합한 정답 대조에서도 모순되지 않는 범위를 사전에 정한다. 공식 점수 밖의 검사는 보조로 구분한다. source의 로컬 검사 통과를 target 공식 성공으로 옮기지 않는다. 기억이 최종 공식 성공은 높였지만 회귀나 비용을 늘렸다면 그 교환 관계를 같이 보고한다.

전체 배정의 평균 비용 차이를 기본으로 쓴다. `전체 평균 비용 / 전체 성공 확률`은 반복 작업의 성공 한 건당 비용을 보는 보조 비율이며 성공한 실행만의 평균 비용과 다르다. 성공률이 0이면 정의되지 않는다. source 수집·카드 작성 비용은 재사용 횟수별 상각을 따로 보여주며 실행 비용에 이중 합산하지 않는다.

## 8. 표본·통계와 어느 수준을 입증할 수 있는가

### 파일럿과 확인은 목적이 다르다

예를 들어 **출처 4개 × 대상 각 2개 × 네 조건 × 2반복 = 64회**는 계측·효과 후보를 보는 규모다. 대상이 겹치면 실제 서로 다른 대상 수를 따로 센다. 이 첫 단계만으로 일반적인 기억 특징을 확정하지 않는다. 기억 종류를 비교하는 후속에서는 같은 대상에 서로 다른 source 기억을 교차 배정하고, 대상별 기억 수가 달라졌다는 이유로 특정 대상을 과대 가중하지 않는다.

사례별로 같은 조건을 모두 실행하고 순서를 블록 안에서 무작위화한다. source/target/기억 조합별 대비를 먼저 계산한 뒤, 사전에 정한 대상·출처 가중치로 평균낸다. API 응답 수나 테스트 수를 독립 사례 수로 세지 않는다. 공유한 무기억 실행을 여러 기억 비교에 재사용하면 그 공분산도 반영해야 하며 독립 표본으로 복제하지 않는다.

### 작은 개선에는 왜 더 많은 자료가 필요한가

고정된 J개 사례에 각 조건 R번씩 독립 실행하고 사례를 동일 가중한다는 단순 가정에서, 이진 성과 차이의 95% 양측 Hoeffding 반폭은 다음과 같다. **선택한 사례 집합의 조건부 효과**에 관한 보수적 설계 계산이며 새 출처 모집단으로의 일반화를 보장하지 않는다.

```text
h = sqrt(log(2/0.05) / (J × R))
구간 = [추정 차이 − h, 추정 차이 + h] ∩ [−1, 1]
```

| 서로 다른 사례 J | 조건별 반복 R | 네 조건 총 실행 | 반폭 |
| ---: | ---: | ---: | ---: |
| 8 | 2 | 64 | 약 48.0%p |
| 32 | 2 | 256 | 약 24.0%p |
| 64 | 2 | 512 | 약 17.0%p |

이 계산은 실제 데이터의 구간이나 검출력 보장이 아니다. 다중 비교·공유 기준 실행·모델 드리프트·사례 의존성은 별도 취급한다. 출처까지 일반화하려면 여러 source에서의 변동을 확인해야 한다. source 4개에 대한 군집 bootstrap의 좁은 구간만으로 일반화를 확정하지 않는다. 확인 규모는 중요한 최소 효과·기준 성공률·source/target 변동·예산을 정하고 모의실험으로 산정한다. 같은 source/target 반복만 늘리는 것으로 독립 사례 부족을 해결할 수 없다.

### 결과 판정 규칙

- 사전 주 대비의 구간이 0보다 위면, 해당 평가 범위에서 양의 기여를 지지한다. 아래면 음의 기여를 지지한다. 0을 가로지르면 방향은 미확정이다.
- 실용적 최소 효과를 넘는다는 주장은 구간이 그 기준까지 넘는지 따로 확인한다. 예를 들어 +10%p는 설계 시 정할 수 있는 기준의 예시이며 이번 자료에서 검증된 값이 아니다.
- 차이가 유의하지 않음은 동등성·무해성의 증거가 아니다. 효율 개선은 사전 허용 성과 손실과 비용 절감 기준을 함께 검증한다.
- 여러 삭제 후보를 탐색한 뒤 좋은 것만 골랐다면, 그 후보와 규칙을 새 자료에서 고정해 확인한다. 확인 중 성공할 때까지 반복을 추가하지 않는다.
- 한 실행의 성공/실패 전환은 확정적인 “도움받은 개별 실행/피해받은 개별 실행” 라벨이 아니다. 사례별 평균 기여와 불확실성으로 보고한다.

## 9. 논문의 핵심 실험과 그림으로 연결하기

완료한 결과를 가정하지 않고, 다음 형태의 산출물을 목표로 한다.

| 산출물 | 제시할 내용 | 핵심 주장 |
| --- | --- | --- |
| 주 결과 표 | N/R/S/M의 전체 배정 수·성공·미제출·비용·불확실성 | 과거 경험 제공·요약·정보 복원의 순효과 |
| 삭제·교정 표 | M−u 및 M−u+u*의 사전 대비, 전체 배정 비용·성공 | 어떤 조각의 어떤 편집이 성과를 바꾸는가 |
| 효과 그림 | source/target별 대비와 구간, 새 확인 자료 별도 표시 | 평균과 상황별 차이, 재현의 범위 |
| 예산 곡선 | 실제 예산별 제출 성공, 별도의 중간 관측 통과 곡선 | 수정 도달과 전달·검증 비용의 구별 |
| 적용성 진단 | 직접 적용/원리 전이/부적합/불명의 수와 적용·보류 행동 | 관련성과 적용성을 구분했는가 |
| 근거 부록 | source 단위·카드 변형·입력 차이·배정·환경·원자료 연결 | 삭제 외의 변화와 데이터 오염 점검 |

가장 설득력 있는 기여 문장은 “특정 기억 특징이 좋아 보였다”보다 **“실제 경험의 조각 u를 추가·삭제·교정했을 때 사전 정의한 성과가 달라졌고, 그 방향이 새로운 source/target에서도 재현됐다”**다. 행동 진단은 이 결론의 작동 경로를 뒷받침하지만, 내부 신경 메커니즘이나 모든 미래 과제에 대한 보장을 대신하지 않는다.
