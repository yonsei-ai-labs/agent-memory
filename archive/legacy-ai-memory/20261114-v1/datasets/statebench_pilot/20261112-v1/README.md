# STATE-Bench 경험 기억과 개발 파일럿

공개 train 중 기억 출처로 분리한 기록에서 20개 경험을 작성함. 고객지원·쇼핑 각 10개이며, 원문 관측과 현재 확인할 조건·조건부 활용 제안·적용 경계를 구분함. 20개 출처의 지정 근거 80곳을 연결함. 단일 에이전트의 내용 검토이며 독립 다중 주석은 아님.

원문이 뒷받침하는 관측을 검산했으며, 제안한 절차가 항상 옳거나 실제로 이득이라는 라벨을 붙이지 않음. `approved_for_pilot`은 이 제한된 파일럿의 기억 은행으로 사용한다는 뜻임. 선택기 학습에 넣을 득실 정답이 아님.

## 구성

| 파일 | 내용 |
| --- | --- |
| `bank.jsonl` | 20개 고정 기억, 출처 그룹, 검토 범위 |
| `evidence.jsonl` | 원문 메시지·도구 호출 80곳과 해시 |
| `review-exclusions.json` | 원문으로 확인되지 않은 오류 주장 및 정책 캐시 사례의 제외 이유 |
| `pilot-selection.json` | 개발 출처에서 결과를 보기 전에 해시 순서로 고른 8과제 |
| `bank-manifest.json` | 실제 실행 전 고정한 은행·표집 파일의 해시 |
| `bank-verification.json` | 출처 검산과 단독 기억 토큰 길이 |
| `coverage.json` | 의도·범위, 완료·부분 진행, 적용 전제, 결합된 값의 내용 분포 |

기억 하나의 실제 전달 문자열은 안내문·ID 포함 Qwen3.5-9B tokenizer 기준 142–178토큰임. 20개 모두 단독 1,024토큰 예산 안에 들어옴. 이는 선택한 20개를 정리한 결과이며, 이전 원문 후보 2,297개 전체를 압축·검토한 성과가 아님.

## 데이터 설계

- 현재 자료의 분류: 의도·행동 범위 7개, 완료·부분 진행 5개, 적용 조건·근거 5개, 서로 연결된 금액·상태 3개임. 완전한 메모리 문제 분류체계라는 주장은 아님.
- 예: 수량이 이미 있는 장바구니에 추가하려다 상한으로 거부됨 → 기존 수량과 요청 증분을 확인하는 경험으로 정리함. 과거 수량·상한·상품 ID는 현재 정답으로 복사하지 않음.
- 예: 상품 추가는 성공했지만 프로모션 검증은 실패함 → 두 결과를 따로 보존함. 실패했다고 상품을 다시 추가하는 지침으로 만들지 않음.
- 파일명에만 만료 원인이 있는 경우, 에이전트가 오류를 주장했지만 실제 실패 호출이 없는 경우는 오류 경험에서 제외함.
- 관측과 조건부 해석의 의미 일치는 단일 검토 범위임. 해시 검사는 요약의 의미적 타당성이나 효용을 자동 증명하지 않음.

## 실행 범위

고객지원·쇼핑 개발 출처에서 각각 4개를 결과와 무관한 해시 순서로 선정함. 공식 test는 열지 않음. 기억 출처와 개발 과제의 정규화 첫 요청 그룹은 겹치지 않지만, 의미가 비슷한 모든 가족의 독립성을 보장하지 않음.

같은 작업자·은행·도구에서 `무기억 / Harrier 요청 / Harrier 요청+관측`을 비교함. 작업자는 OpenRouter의 Qwen3.5-9B, 사용자 시뮬레이터와 채점기는 GPT-5.4임. Harrier는 추가 학습 없이 고정 표현을 사용함. 이번 단계에서 학습 선택기의 우위를 주장하지 않음.

최대 3개·1,024토큰을 사용자 턴마다 한 번 주입함. 선택기 입력 상한은 4,096토큰으로, 초과하면 첫 요청과 현재 요청은 남기고 오래된 관측 메시지 전체를 제거하여 제거 수를 기록함. 이력이 없으면 두 검색 조건의 입력은 같음. 업무 도구 루프 중에는 기억을 다시 선택하지 않음.

공식 환경·프롬프트·상태 검사를 사용하되, OpenRouter Chat Completions·자체 주입 시점·개발 1회 실행의 통제 파일럿임. 공식 순위표 점수가 아님. 정상적으로 완료된 각 조건의 후속 대화는 달라질 수 있어 전체 정책 결과를 비교하며, 단일 기억 조각의 직접 인과효과로 해석하지 않음.

동일한 API 요청은 캐시를 재사용함. 실제 결제 비용과 정책에 필요한 논리적 토큰 사용량을 구분함. 실행 실패·공급자 제한·입력 형식 수정 기록을 보존하고 공급자가 다른 결과를 같은 비교표로 합치지 않음.

## 재현

원천 자료 준비는 [이전 자료 안내](../../statebench_preparation/20261112-v1/README.md)를 따름. 고정한 파일은 덮어쓰지 않음.

```bash
python3 -m data_pipeline.statebench_pilot_data verify_bank
python3 -m unittest tests.test_statebench_pilot -v
```

새 실행은 API 비용·로컬 GPU가 발생하는 별도 작업임. `evaluation.statebench_live_pilot`은 공개 코드의 버전·은행·공급자·요청 옵션을 검사하고, 비용·호출 수를 제한하며 종료 시 Harrier 프로세스를 회수함. 실제 결과 검산 명령은 [공유 결과](../../../evaluation/results/statebench-pilot-20261112-v1/README.md)에 기록함.
