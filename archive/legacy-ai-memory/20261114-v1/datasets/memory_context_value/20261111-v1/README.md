# 현재 관측에 따른 기억 가치 대조

BEAM의 과거·갱신 발화를 검토해, **같은 목표와 같은 기억 은행에서 현재 관측만 바꾸는** 자료를 구성함. 원문 관계 주석과 실제 작업자 득실은 별도로 보존함. 공식 BEAM 점수나 실제 에이전트 실행 이력으로 해석하지 않음.

| 분할 | 독립 대화 출처 | 질문 | 통제 상태 | 검토된 관계쌍 |
| --- | ---: | ---: | ---: | ---: |
| train | 11 | 13 | 52 | 412 |
| dev | 12 | 13 | 52 | 410 |
| confirm | 27 | 32 | 128 | 1,000 |
| 합계 | 50 | 58 | 232 | 1,822 |

분할과 통계 묶음의 단위는 원래 대화임. 같은 대화의 두 질문, 한 질문의 네 상태, 같은 입력의 여러 정책을 독립 표본으로 세지 않음. 인물·생성 틀이 겹치지 않는 분할까지 보장한 것은 아니므로 독립 사용자 50명으로 해석하지 않음. 정규화된 동일 목표·기억 문장·양성 근거의 분할 간 중복은 0개임. 기존 BEAM 확인 분할을 유지함. 확인 모델 출력은 개발 진단과 학습 완료 후에만 생성하도록 제한함.

## 현재 관측의 네 조건

- `missing`: 현재 관측이 없고 과거 기록에 필요한 수치·맥락이 있음.
- `known`: 검토한 과거 근거가 현재 관측에도 있어 중복 전달의 필요성이 낮음.
- `updated`: 현재 관측에 새 값이 있음. 과거 기록에만 대상·기간 등이 있으면 그 기록의 관계 정답을 `unknown`으로 남김.
- `unrelated`: 다른 관측은 있지만 질문의 답에 필요한 근거는 없음.

관측은 원문 발췌이며, 상태 구성은 통제 개입임. 자연 발생 진행·실패 이력이 아님. 질문의 시점·범위가 이전과 이후에 동일하게 성립하지 않으면 명시적으로 고치거나 제외함. 금액·비율은 원문 화자의 발언을 읽는 정답이며 현실의 법률·금융·건강 사실을 보증하지 않음.

## 수집과 검토

[BEAM 원천](https://github.com/mohammadtavakoli78/BEAM/tree/b2da22eac88bb0874c64665f13457eb99835774a)의 최상위 100대화·200질문과 원천 파일 200개를 고정함. 10M 내부 계획 조각은 별도 출처로 세지 않음. 원천 파일 크기·Git blob SHA1·SHA256을 확인함.

자동 후보 79개와 원문 의미를 읽어 복원한 후보 4개를 검토함. 출처 검토에서 22개, 후보 은행 검토에서 3개를 제외해 58질문을 남김. Codex 한 에이전트의 검토이며, 독립된 사람 검토자 사이의 일치도는 측정하지 않음. 다음 문제를 걸러냄.

- 예산과 실제 가격, 코드 커버리지와 검사 통과율, 시간과 기간의 혼동.
- 목표치와 달성치, 전체와 하위 집단, 현재 사용자와 다른 사람의 혼동.
- 같은 대화의 중복 메시지 ID, 앞뒤가 맞지 않는 수치, 원문에 남은 생성 표식.

모든 은행 후보와 무관한 관측 후보를 읽음. 같은 정답을 제공하는 다른 기록도 양성으로 표시함. 범위가 불확실한 조각은 음성으로 바꾸지 않음. 근거가 두 조각에 나뉜 경우 두 조각을 모두 요구함.

은행은 갱신 이전의 같은 대화에서 BM25로 찾은 후보와 검토한 근거를 포함함. 원문 문단을 사용하며 코드 블록·384토큰 초과 문단은 추출하지 않음. 기존 원천 읽기 함수의 표식 정리 후 문자열에서 구간을 검증함. 요약이나 새로운 사실을 생성하지 않음. 기록 순서는 모델에 유리하게 정답 우선으로 두지 않음.

55은행은 8기록, 3은행은 7기록임. 전달용 날짜·구분자까지 포함하면 19/58은행이 512토큰을 초과함. 은행 전체 길이는 316–1,441토큰임. 예산 제약을 만들기 위해 임의 기록을 덧붙이지 않음.

## 파일

- `*-cases.jsonl`: 목표, 현재 관측, 같은 출처의 기억 은행. 모델 입력은 공개된 렌더링 함수로 구성함.
- `*-labels.jsonl`: 검토된 관계·불확실성·필수 근거 묶음·기대 수치. 모델 입력과 분리함.
- `records.jsonl`, `provenance.jsonl`: 발췌문과 원천 메시지·문자 구간·원문 해시.
- `source-review.jsonl`, `bank-review.jsonl`, `screening-ledger.jsonl`: 채택·제외·불확실성의 근거.
- `question-review.csv`: 원래 질문과 파생 질문, 이전·새 값의 비교표. 고정 입력에서 내보낸 검토용 표이며 모델 입력에 포함하지 않음.
- `source-files.json`: 고정 원천 URL과 해시. 로컬 절대 경로는 포함하지 않음.
- `protocol.json`, `manifest.json`: 결과를 보기 전에 고정한 조건과 입력 해시.

실제 개선·악화는 [결과 묶음](../../../evaluation/results/memory-context-value-20261111-v1/README.md)의 같은 상태·같은 작업자 출력을 대조해 계산함. 작업자가 실패했다고 관련 기억을 학습 음성으로 바꾸지 않음.

## 검산

저장된 자료를 확인하는 CPU 명령은 다음과 같음. 저장 예측 검산은 결과 묶음의 안내를 따름.

```bash
python -m unittest tests.test_context_value -q
python -c 'from training.memory_selector.context_value_protocol import audit; print(audit())'
```

원천 재수집은 다음 순서임. `collect`는 캐시가 없으면 큰 원천 파일을 다운로드함. 결과 디렉터리를 덮어쓰지 않으므로 전체 재구성은 별도 체크아웃에서 수행해야 함.

```bash
python -m data_pipeline.context_value_sources collect
python -m data_pipeline.context_value_sources screen
python -m data_pipeline.context_value_data review-candidates
python -m data_pipeline.context_value_data bank-draft
```

고정된 검토표는 [설계 자료](../../../docs/design-data/memory-context-value-20261111-v1/)에 있음. 원천 후보를 다시 얻는 것과 원문 검토를 자동화하는 것은 다름.
