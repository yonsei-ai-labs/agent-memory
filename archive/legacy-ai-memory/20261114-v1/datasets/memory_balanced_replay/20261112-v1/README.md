# 복습 대조와 새 출처 평가

부분적으로 알려진 복합 기억을 보존하는 학습을 유지하면서, 지금 필요하지 않은 기록의 과잉 제공을 줄일 수 있는지 비교하는 자료임. 원문·관계 주석·작업자 득실을 별도로 보존함.

| 자료 | 상태 | 목표 출처 그룹 | 후보 쌍 | 감독 쌍 |
|---|---:|---:|---:|---:|
| control 학습 | 400 | 30 | 716 | 716 |
| replay 학습 | 400 | 37 | 1,172 | 1,166 |
| 새 평가 | 240 | 12 | 360 | 360 |
| 이전 복합 기억 회귀 | 384 | 12 | 576 | 576 |
| BEAM 개발 회귀·예산 진단 | 52 | 12 | 416 | 410 |
| 이전 incremental 개발 회귀 | 100 | 8 | 258 | 258 |
| 이전 source-scale 개발 회귀 | 93 | 30 | 930 | 498 |

같은 320개 핵심 상태는 그대로 두고, 복습 80상태만 교체함. Replay는 BEAM train 13질문과 Mem2Act train 7질문에 각각 `미확인 / 이미 확인 / 다른 관측 / 조회 실패`를 구성함. 같은 주제라도 요청 속성을 뒷받침하지 않는 후보를 포함함. 기존 갱신 상태는 시도와 완료가 섞일 수 있어 이번 학습에서 제외함. 거의 같은 좌표와 은유적인 회사명 언급은 불확실한 6쌍의 라벨을 가리고, 음성으로 강제하지 않음. 후보 은행의 출처까지 학습·평가 겹침을 검사함.

새 평가 12출처는 [이전 예약](../../memory_partial_records/20261111-v1/source-reservation.json)의 미사용 test 그룹에서 선정함. 원문 두 역할의 문자 구간을 확인하고, 10가지 현재 상태와 atomic/compound 포장을 파생함. 240상태는 독립 경험 240개가 아님. 문장 표현과 조회 실패는 통제하여 작성했으며 실제 에이전트 실행 이력이 아님. 구축 에이전트가 주석을 검토했으며 독립 인간 이중 검토는 없음.

새 평가의 작은 은행은 모두 예산에 들어감. 별도의 BEAM 개발 진단에서 원래 7–8개 기록을 유지하고 128·512토큰 제한을 비교함. 이 개발 자료는 이미 관찰한 자료이며, 새 출처 확인 결과로 부르지 않음. BEAM 확인 분할의 모델 출력은 미실행 상태를 유지함.

- `*-cases.jsonl`: 현재 목표·관측·후보 기억 및 출처. 모델에는 정답·출처 ID·주석을 입력하지 않음.
- `*-labels.jsonl`: 현재 필요성, 근거 범위, 검토된 정답. 없는 후보 라벨은 미확인이며 음성이 아님.
- `source-specs.json`: 새 출처 원문·역할·문자 위치·사전 고정한 정답과 허용 표현.
- `replay-review.jsonl`: 복습의 검토 내용과 가린 후보.
- `protocol.json`, `manifest.json`: 새 모델 출력 전 고정한 설계와 입력 해시. README는 설명 파일이며 고정 입력 목록에 포함하지 않음.

[설계](../../../docs/design-data/memory-balanced-replay-20261112-v1/README.md)에 조건과 실행 한도를 기록함. 검산은 저장소의 고정 원문 캐시와 부모 자료가 필요함.

```bash
.venv/bin/python -m data_pipeline.balanced_replay_data audit
.venv/bin/python -m unittest tests.test_balanced_replay
```
