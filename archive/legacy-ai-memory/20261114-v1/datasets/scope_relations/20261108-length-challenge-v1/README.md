# 길이 지름길을 막은 별도 범위 확인 자료

**새 저장소 두 곳의 실제 파일 식별자 네 개**로 만든 108행이다. 36개 현재 조건을 A/B/C 세 형식으로 표현했다. 실제 실행 episode는 3개, 명령/연결 응답은 6개이며 독립 경험 108개가 아니다. 학습에 사용하지 않는다.

첫 자료 실험 이후, 기존 통제에서 문자 길이를 같게 해도 토큰 수가 달라지는 문제를 발견해 만든 **사후 진단 설계**다. 이 자료의 모델 예측을 보기 전에 포함 기준·범위·라벨을 고정했다. 모델과 checkpoint는 기존 개발 기준으로 선택하며 이 자료로 조정하지 않는다. 최초 [외부 108행](../20261108-expansion-v1/README.md)은 그대로 보존한다.

| 저장소·기준 버전 | 두 범위 | 문자 수 / Harrier token 수 |
| --- | --- | --- |
| mahmoud/boltons `3bfcfdd04395b6cc74a5c0cdc72c8f64cc4ac01f` | `tests/test_mathutils.py`, `tests/test_timeutils.py` | 각각 23 / 5 |
| pallets/click `fde47b4b4f978f179b9dff34583cb2b99021f482` | `tests/test_basic.py`, `tests/test_chain.py` | 각각 19 / 4 |

둘 모두 기존 학습·개발·외부 확인의 11개 저장소에 없었다. 볼턴은 같은 기준 버전의 두 변형 실행에서 관측된 이름을 모았고, click은 `pr_2555`라고 표기된 한 실행의 두 명령이다. 서로 다른 변형의 코드 상태가 같다고 가정하지 않는다. 현재 요청과 완료 기록은 여전히 통제해 만든 조건이다.

## 선별과 근거

[사전 선별 계획](../../../docs/design-data/scope-length-challenge-20261108/selection-plan.json)에 따라 이미 받은 고정 SWE-smith shard의 256–1,023행만 추가 선별했다. 기존 저장소를 제외하고, 실제 전체 파일 선택 명령·유일하게 연결된 응답·agent가 만들지 않은 파일·같은 문자/토큰 길이를 요구했다. 저장소는 처음 나타난 행 순서, 같은 저장소의 후보 쌍은 사전순으로 고른다. 목표는 3개 저장소였지만 두 곳만 충족해 두 곳으로 끝냈다. 결과·patch 열을 읽거나 성공한 경우만 골라내지 않았다.

선택된 여섯 명령과 응답은 모두 확인했고, 파일 네 개가 전체 upstream commit에 존재하는 것도 GitHub 읽기 전용 API로 확인했다. 전체 SHA·blob SHA·링크는 [출처 검토](source-review.json)에 있다. 입력은 파일 식별자만 사용하며 관측된 통과 수·성공 여부를 현재 정답으로 쓰지 않는다. 원본 응답은 [evidence](evidence/)에 보존했다. 연구자 한 명의 검토이고 독립 이중 주석은 아니다.

## 라벨과 길이 검사

기존과 똑같이 기억의 범위가 현재 요청과 정확히 같은지, 코드 변경 후의 완전한 완료 기록에 이미 있는지 묻는다. 입력에 제시한 범위만 비교한다. 완료 기록의 부재는 불일치가 아니라 미확인이다. 문자는 실제 파일 이름을 그대로 유지하며 길이를 맞추기 위해 이름을 조작하지 않았다.

각 저장소·형식 안에서, 두 범위를 바꿔 넣은 알려진 조건의 **전체 상태 문자열과 전체 기억 문자열 token 수도 각각 같다**. 이름의 문자 수/토큰 수만 비교하는 규칙은 전체 48/108, 알려진 12/48, 한쪽만 일치하는 핵심 조건 0/24다. 정확한 문자열 일치 규칙은 정의상 108/108을 맞힌다. 따라서 신경망이 필요함이나 의미상 코드 커버리지 이해를 입증하는 과제가 아니다. 좁은 역할 구별 학습이 길이 지름길 밖으로 옮겨가는지를 보는 진단이다.

원문 명령을 이 컴퓨터에서 실행하지 않았고, 실제 대상 에이전트의 성공·비용·메모리 득실 라벨은 없다. 근거 범위를 넓히는 일과 독립 경험 수를 늘리는 일을 혼동하지 않는다.

## 검산

`verification.json`은 명령·응답 연결, 네 파일의 upstream 증거, 원본과의 저장소/입력 분리, 관계 재생성, 실제 pair/joint/role 입력의 길이 검사를 통과한 기록이다. `artifact-index.json`은 외부 예측 전 동결한 파일 해시다. 해시/정답/저장 예측 검산은 공유 파일로 가능하며, tokenizer를 직접 재실행하는 다음 추가 검사는 `tokenizers`와 첫 실행의 `results.zip`에 든 `tokenizer/tokenizer.json`이 필요하다.

```bash
.venv/bin/python -m data_pipeline.audit_length_challenge datasets/scope_relations/20261108-length-challenge-v1
```

`source-review.json`의 검토된 families로 `construct(families, ['A', 'B', 'C'])`를 적용하면 입력·정답·근거 ID가 완전히 동일하게 재생성된다. 원본 parquet를 다시 선별할 때는 동결한 선별 계획과 `build_snapshot`의 코드를 사용한다.
