# 실제 선택 범위의 근거를 보강한 통제 자료

2026-11-08 아침 실험용. 모델 결과를 보기 전에 자료·분할을 고정한다. **과거 명령의 범위 선택은 실제 관측이고, 현재 요청·완료 상태는 통제해서 만든 조합이다.** 실제 기억 효용 정답은 없다.

## 자료량과 원형

| 학습 입력 | 행 수 | 바뀌는 내용 |
| --- | ---: | --- |
| `train-small.jsonl` | 146 | 기존 출처별 두 범위·서식 A. 원래 162행에서 같은 입력을 합침 |
| `train-wide.jsonl` | 522 | 같은 출처의 실제 추가 선택 범위와 가능한 역할 조합 포함 |
| `train-wide-ab.jsonl` | 1,044 | 같은 사실을 A/B 두 서식으로 표현 |
| `train-public-ab.jsonl` | 1,316 | 검토한 공개 실행의 세 저장소를 추가 |

큰 학습 구성은 7개 저장소, 로컬 출처/공개 repository-revision 연결 그룹 12개, 원본 실행 episode 17개에 근거한다. 마지막 두 수는 서로 다른 집계 단위다. 같은 공개 저장소·기준 커밋의 여러 합성 결함은 같은 가족으로 묶었다. 독립 경험 1,316개가 아니다.

`dev.jsonl`은 기존 Django·pvlib 두 출처의 범위를 확장한 594행이다. 198개 기본 조건의 A/B/C 표현이며 이미 본 출처이므로 개발 자료다. 기존 개발 `legacy.jsonl` 72행은 이 자료와 중첩되는 연결 진단이다. `controls.jsonl` 96행은 이전의 같은 문자 길이 세 범위 통제이며 실제 출처가 없다. 세 분모를 더하지 않는다.

`external.jsonl` 108행은 새 저장소 **apispec·word_cloud** 두 개의 36개 조건을 A/B/C로 표현했다. 학습 업로드 allowlist에서 제외한다. 모델·checkpoint 선택을 고정한 뒤 평가한다. 두 저장소만의 제한된 출처 확인이며 실제 에이전트 수행이나 기억의 득실 평가가 아니다.

## 무엇을 검토했나

기존 원본 bundle의 81개 관측에서 명령·원본 파일 SHA·줄을 대조했다. 허용한 전체 파일/모듈 범위가 없는 27개, 대조 가능한 범위가 하나뿐인 출처의 관측 16개를 제외하고 38개 명령 관측을 사용했다. 선택지에 `-k`, `-m`, `--ignore` 같은 필터가 있거나 이해하지 못한 shell 구성이 있으면 사용하지 않는다. 전체 파일과 특정 테스트 node가 함께 선택된 명령에서는 실제 전체 파일로 선택된 부분만 쓴다.

새 원형은 [SWE-smith 공식 실행 자료](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories)의 `tool` 첫 shard를 고정 revision·LFS SHA로 받았다. 그중 첫 256행을 명령 형태로 선별하고 10개 실행의 19개 명령/연결 응답을 검토했다. **source의 `resolved`와 `patch` 열은 수집 선택에 읽지 않았다.** 입력 질문·기억에도 최종 결과를 넣지 않는다. 행별 검사와 제외 사유는 [public-source-review.json](public-source-review.json), 명령·응답 근거는 [evidence/public/](evidence/public/)에 있다.

PyCQA/flake8의 두 실행, life4/textdistance의 다섯 실행, python-openxml/python-docx의 한 실행은 학습 원형으로 사용한다. 같은 repository/revision에서 실제 명령에 나온 범위를 모으되 서로 다른 mutation의 코드 상태가 동일하다고 가정하지 않는다. 현재 상태는 명시한 가상 조건이며 source에서 선택된 **범위 식별자**만 빌린다. apispec·word_cloud는 별도 확인용으로 남겼다. 선택된 테스트 파일을 에이전트가 새로 생성한 사례는 포함하지 않았다. 이는 저장소에 처음부터 있었음을 Git으로 독립 증명했다는 주장과는 다르다.

공개 로그는 실제 에이전트 실행이지만 과제에는 합성 결함이 있다. 원형 명령과 응답은 연구자 한 명이 검토했고, 파생된 관계 조합은 자동 규칙·대조 조건으로 검사했다. 모든 행이 독립적인 사람 두 명의 주석을 거친 자료는 아니다.

## 라벨 계약과 지름길

두 출력은 `요청: compatible/conflict/unknown`, `완료: not_already_present/already_present/unknown` 순서다. 현재 요청과 **정확히 같은 범위**인지, 코드 변경 이후의 **완전한 완료 기록**에 그 범위가 있는지만 묻는다. 상위 디렉터리·부분 실행·의미상 더 넓은 커버리지를 추론하지 않는다. 원래 명령이 파일을 선택했다고 그 파일의 검사가 완료되거나 통과했다고 라벨을 만들지 않는다. 현재 완료 상태는 본문에 별도로 가정한다.

같은 기억·다른 현재, 같은 현재·다른 기억의 대조가 있으며, 요청만 바꾸면 완료 정답이 유지되고 완료만 바꾸면 요청 정답이 유지된다. 중복된 입력은 하나로 합치고 모든 부모 근거를 남겼다. 각 범위 이름은 해당 source pool에서 관측된 이름이어야 한다. train/dev/external의 저장소와 입력 교차를 검사한다.

중요한 잔여 약점이 있다. **범위 필드를 파싱한 뒤 문자 길이만 비교해도 개발 594행과 외부 108행은 모두 맞힐 수 있다.** 따라서 이 점수만으로 의미 비교를 주장할 수 없다. 실제 새 파일 이름을 무리하게 조작하지 않고 이 한계를 남기며, 같은 문자 길이 통제 96행을 함께 사용한다. 그 통제는 이미 개발 진단에 사용했으므로 새 독립 test가 아니다. [design-audit.json](design-audit.json)에 길이 규칙, 한쪽 입력만 보는 자료 내부의 상한, 조건별 행 수를 기록했다.

학습 입력은 `input.state_text`와 `input.candidate_text`뿐이다. 출처·라벨·관계 종류·현재 상태의 구조화된 정답 필드를 특징에 넣지 않는다. 현재 정보가 없는 사례의 `unknown`을 기억 제공/보류 정답으로 바꾸지 않는다.

## 재현

```bash
python3 -m data_pipeline.audit_scope_expansion datasets/scope_relations/20261108-expansion-v1
```

이 검사는 읽기 전용이다. 전체 재생성은 로컬의 과거 원본 bundle/log와 고정 public parquet, PyArrow가 필요하다. 새 출력 경로에 `data_pipeline.scope_expansion`을 실행하며 기존 폴더는 덮어쓰지 않는다. [manifest.json](manifest.json)은 학습 내보내기 해시와 별도 확인 파일의 해시를 구분한다. source-review·공개 원형·버전별 생성 코드는 전체 검토에 함께 보존한다.
