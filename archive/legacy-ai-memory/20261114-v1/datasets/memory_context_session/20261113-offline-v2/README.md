## 평가 기준

[contract.json](contract.json)에 기계가 읽을 수 있는 계약과 모델에 전달할 공통 지시를 고정함.

- **관계 정답:** 대본상 필요한 기록, 무효 기록, 방해 기록 등의 역할임. 실제 작업자의 성공이나 제공 이득을 뜻하지 않음. 주석이 없는 후보 26출현은 `relation=null`, `loss_mask=0`으로 남김. 다른 기록이 필요한 판단 1개는 보조 근거를 정답 메타데이터에만 기록하며, 검색 입력에 몰래 추가하지 않음. 이 패킷은 선택기 학습용으로 승인된 자료가 아님.
- **UNKNOWN:** 답의 종류와 기억의 필요성을 분리함. 부모 자료의 UNKNOWN 12판단 중 4판단에는 무효화 근거가 있음. 자식 라벨은 `answer_kind`, `evidence_requirement`, `required_record_keys`를 쓰고 `needs_memory`는 내보내지 않음. 정답이 구체 ID인데 보이는 근거가 없어 UNKNOWN을 출력한 경우는 미완료·보류로 기록하며, 잘못된 구체 답변과 구분함.
- **실제 득실:** 같은 직전 상태·실행 계약의 제공/보류 결과가 있어야 측정할 수 있음. `utility`는 계속 `null`임. 두 정책이 서로 다른 이전 답변을 만든 누적 경로의 차이는 세션 효과로 따로 측정함.

조회는 기존 예약의 현재/최초 상태를 보고하는 요청임. 추천은 **새 예약이 없어도 조건에 맞는 카탈로그 ID를 제안할 수 있는 가상 추천**으로 명시함. 어느 질문도 환경에 새 예약을 만들지 않음. 현재 예약이 있는 질문과 없는 질문에는 같은 조회 문장 틀을 사용함.

## v1에서 바꾼 것

선정 규칙은 가장 작은 session ID에서 첫 absent, 첫 open_book, 첫 history, 그 history 이후 첫 ref_changed를 고르는 것임. v1의 39번 질문 대신 48번 질문을 사용함. 47번은 Bruno의 **최초** 예약, 48번은 같은 사람·날짜의 **현재** 예약을 묻고 사이에 외부 관측이 없음. 질문 선택은 사건 종류·시간에 근거하며 새 작업자의 정답률을 보지 않음. v1과 문항이 달라 점수를 직접 개선 비교하지 않음.

정답은 과거 질문 답을 외부 사실로 저장하지 않아도 부모의 92정답이 유지되는 [접두부 검사](../../../docs/design-data/memory-context-stream-20261112-v1/README.md)를 확인한 뒤 재사용함. 읽기 전용 문장의 독립적인 사람 의미 검토를 대체하는 검사는 아님.

기록 키는 부모 manifest·세션·표현·길이·원 기억 ID와 **실제 원문 해시**를 함께 묶음. 다른 부모의 `memory_state_supplement/20261112-v3`와 기억 ID만으로 결합할 수 없음. 모델에는 중립적인 청크 ID와 공개 본문만 전달함. 이전 답변은 누적 대화로만 남고 외부 사실 은행에 들어가지 않음.

## 예산과 CPU 결과

최근 대화만 4,096토큰과 최근 대화 2,048 + 고정 BM25 기억 2,048토큰을 비교하는 입력을 구성함. 머리말·구분자·청크 ID를 포함한 기억 블록과 전체 직렬화 입력의 증가량을 **둘 다** 검사함. 최근 창과 기억의 합산 가변 예산은 4,096토큰, 카탈로그·공통 지시·현재 질문을 포함한 최종 입력 상한은 6,144토큰임.

계산은 tiktoken 0.14.0의 `o200k_base`로 canonical JSON 메시지 목록을 세는 **기준 인코딩**임. 모델의 네이티브 채팅 템플릿이나 실제 provider 사용량을 검증한 결과가 아님. 원본 552사례의 예산 오류는 원본에 보존되어 있으며, 이번 수정 범위는 이 새 4문항 패킷임.

[CPU 검사와 입력 미리보기](../../../evaluation/results/context-session-offline-20261113-v2/README.md)에서 예산·미래 관측·국소 스냅샷 불일치가 모두 0건임. 짧은 모의 답변과 약 256기준 토큰의 긴 모의 답변 모두에서 첫 질문 이후 이전 답변이 보이는 문항은 최근 대화 조건 2/3, 고정 기억 조건 1/3임. 특히 마지막 질문은 두 전달 정책에서 모두 이전 답변을 노출함. 각 모의 답변에서 모드 대응 8쌍 중 5쌍은 여전히 같은 입력이므로 모든 문항에서 누적 효과를 측정할 수 있다는 뜻은 아님.

모의 답변은 정답과 무관한 고정 문자열이며 채점하지 않음. 실제 답변 길이·내용이 달라질 때의 노출, 실제 개선·악화, 성공률은 이후 작은 실제 실행에서 확인해야 함.

32개는 주 입력의 배정 수임. 고유 주 입력은 14개이고 보류 분기까지 포함하면 고유 입력 20개, 고유 제공·보류 입력 쌍 6개임. 동일 입력을 독립 호출이나 반복 관측으로 합산하지 않음.

## 파일과 재현

`session.json`, `observations.jsonl`, `questions.jsonl`은 공개 사실·질문을 보관함. `labels.jsonl`과 `record-provenance.jsonl`은 정답·원문 연결용이며 모델 입력이 아님. `config.json`, `contract.json`, `protocol.json`과 생성/입력 코드의 해시는 `manifest.json`으로 고정함. 이 README는 manifest에서 제외함.

저장소 루트의 Python 3.11 이상과 [고정 의존성](../../../evaluation/requirements-context-session.txt)이 필요함. 검사 환경에는 `o200k_base`의 tiktoken 캐시가 이미 있어야 함. 아래 실행은 모델·API·GPU를 사용하지 않음.

```bash
# 원본 해시, 새 패킷의 바이트 단위 재생성, 예산·노출·스냅샷 검사
.venv/bin/python -B -m evaluation.context_session_inputs

# 실제 입력을 포함한 검사 자료를 새 폴더에 저장
.venv/bin/python -B -m evaluation.context_session_inputs \
  --output /tmp/context-session-offline-checks

# 새 폴더에 같은 패킷 재생성
.venv/bin/python -B -m data_pipeline.context_session_packet \
  --output /tmp/context-session-offline-packet

.venv/bin/python -B -m unittest tests.test_context_session_packet \
  tests.test_context_session_pilot tests.test_context_session_scoring
```

출력이 있는 폴더는 덮어쓰지 않음. 이 버전에는 실제 실행 명령이나 `--live` 옵션이 없음. 다음은 모델·디코딩·네이티브 입력 계약을 고정한 작은 실제 점검이며, 본평가·새 학습·새 출처 확장은 아직 시작하지 않음.
