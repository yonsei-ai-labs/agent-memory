# 첫 코어의 기록·입력·도구 처리 결정

2026-11-14 · 리뷰 반영과 첫 오프라인 구현. 실제 provider·벤치 어댑터는 후속이다.

첫 코어는 DB 설치 없이 단일 프로세스·순차 쓰기로 시작한다. 이 문서가 파일 로그, 요청 출처, 혼합 도구 호출의 기준이다. 연구 범위는 [연구 계획](../research/plan.md), 결과·비용의 정의는 [기록 계약](recording.md)을 따른다. 아래 계약을 적었다는 사실과 런타임에서 검증했다는 사실을 구분한다.

## 1. 모든 사건을 하나의 원본 로그에 확정

```text
runs/<experiment_id>/
  log.jsonl                 # 확정된 기억·비기억 사건 전체의 원본
  blobs/sha256/<digest>     # 불변 본문·요청·응답·manifest
  views/
    banks/                 # 현재 head·연산 결과의 재구성 보기
    snapshots/             # 로그의 manifest 참조에서 재생성
    events.jsonl           # envelope를 펼친 사건 보기
  analysis/<revision>/
```

기억 연산별 확정 파일 대신 **한 줄을 한 commit**으로 둔다. run 시작·종료, 모델 요청·응답, 업무 전이, 채점, 기억 연산 모두 같은 순서 체계에 속한다. 첫 기록자는 하나이며 은행마다 쓰기 소유권을 검사한다. 파일 순회 순서·mtime으로 사건이나 목록 순서를 추론하지 않는다.

| commit 필드 | 의미 |
| --- | --- |
| `journal_version` | journal envelope의 버전. 사건 스키마 버전과 별개 |
| `commit_seq` | 실험 내 commit의 연속 번호, 1부터 시작 |
| `prev_sha256` | 직전 commit의 `record_sha256`. 첫 줄은 null |
| `record_sha256` | 이 필드만 제외한 commit의 정규 직렬화 SHA-256 |
| `operation` | 기억 연산의 ID·요청 해시·확정 결과 참조. 해당 없으면 null |
| `events` | 한 번에 확정되는 사건 배열. `event_seq`는 배열을 펼친 실험 전체 연속 번호 |
| `state_ref` | journal v1.1의 불변 내부 상태 참조. 은행·snapshot·커서·배정·요청 출처 목록을 연결 |

첫 구현은 별도 [journal v1.1 스키마](../../schemas/v1.1/journal-state.schema.json)를 사용한다. 은행 생성·봉인 등 내부 상태만 바뀌면 `events=[]`인 commit도 가능하다. 기존 journal v1.0/fixture와 사건 v1.1은 보존한다. 상태 참조 blob도 로그보다 먼저 확정한다.

저장 성공은 불변 본문 참조·head 변경을 나타내는 `memory.stored`·공개 결과를 나타내는 `memory.returned`를 한 commit에 둔다. 실패한 연산도 결과와 정책/오류 사건을 남긴다. 비기억 사건을 기억 연산으로 위장하지 않는다. 모델 요청 시작은 전송 전에 별도 확정하고, 응답 또는 전송 불명 상태를 뒤에 연결한다.

해시 정규화는 Python JSON의 키 정렬·공백 없는 구분자·`ensure_ascii=False`·`allow_nan=False`·UTF-8로 고정한다. Unicode 정규화는 하지 않고 중복 JSON 키는 거절한다. JSON 수치 직렬화 구현도 기록 버전의 일부로 취급한다. 다른 언어의 JCS와 같다고 가정하지 않는다. blob 해시는 저장한 실제 bytes, 본문 해시는 원문 UTF-8, 노출 해시는 렌더링한 부분 문자열 UTF-8에 각각 적용한다. 문자열 범위는 디코딩한 요청 문자열의 Unicode 코드 포인트 기준 반개구간이다.

### 쓰기와 중단

1. 참조할 blob을 같은 파일시스템의 임시 파일에 쓰고 파일을 `fsync`한다. 해시를 확인한 뒤 불변 최종 이름으로 공개하고 상위 디렉터리를 동기화한다. 이미 있는 동일 해시 파일도 내용 일치를 확인한다.
2. 단일 기록자가 검증한 commit 한 줄과 LF를 추가하고 로그를 `fsync`한다. 로그 최초 생성 때 디렉터리도 동기화한다. 이 완료 뒤에만 연산 성공을 응답한다.
3. 은행·snapshot·사건 보기는 확정 로그에서 만든다. 보기 갱신 실패는 확정 연산을 재실행할 이유가 아니다.

파일 `fsync`만으로 이름 변경의 내구성까지 보장되지 않는다. 디렉터리 동기화가 필요하다는 [Linux 설명](https://man7.org/linux/man-pages/man2/fsync.2.html)을 기준으로 첫 로컬 파일시스템에서 장애 주입으로 확인한다. 모든 OS·네트워크 파일시스템·전원 장애에 같은 보장을 주장하지 않는다. `O_APPEND`만으로 다중 기록자의 원자성을 가정하지 않는다.

| 읽기 결과 | 처리 |
| --- | --- |
| 마지막 줄에 LF 없음 | 미확정 tail 원문을 보존하고 분리 대상으로 표시. 자동 삭제·계속 append하지 않음 |
| LF로 끝난 줄의 파싱·자기 해시·연결 해시·순서 오류 | 손상으로 중단. 마지막 줄이라도 조용히 버리지 않음 |
| 어떤 commit도 참조하지 않는 blob | 미확정 고아 파일. 상태에 적용하지 않고 보존/정리를 분리 |
| `run.ended` 없음 | 불완전 실행. 배정과 이미 발생한 비용·행동을 보존 |
| 종료 사건은 있으나 참조 누락·미완료 요청 존재 | 정상 완료로 승인하지 않음 |

`prev_sha256`만 있으면 마지막 유효 JSON 줄의 변경을 검출하지 못하므로 자기 해시도 둔다. 해시 연결은 우발적 변경·누락 탐지용이다. 전체 로그와 해시를 함께 다시 쓸 수 있는 주체에 대한 진본성 증명은 아니다. 공유/분석 묶음의 원본 해시는 별도 manifest로 보존한다.

재전송은 확정 로그에서 `operation_id`·요청 해시·결과를 찾아 같은 결과를 돌려주며 새 commit을 만들지 않는다. 같은 ID의 다른 요청은 거절한다. 모델이 새 call로 같은 본문을 저장한 것은 새 행동이다. 전체 세션 자동 복구는 첫 범위 밖이며 전송·업무 부작용이 불명확하면 임의 재실행하지 않고 새 run으로 시작한다.

후속 스레드 병렬화에서도 기록자 하나와 잠금으로 전체 번호를 배정할 수 있다. τ² 배치가 [스레드 풀을 사용하는 코드](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/src/tau2/runner/batch.py)를 검토했지만, 지금 병렬 실행이나 별도 DB를 구현할 필요는 없다.

## 2. 요청을 만들 때 출처 manifest도 생성

요청 구성기는 승인된 출처의 JSON 부분 트리를 조립하고 같은 시점에 `input-manifest`를 만든다. 모델·설정·system/user/assistant/tool 메시지·도구 설명/스키마·호출 인수·오류를 포함한 모든 요청 필드를 덮는다. 각 binding은 요청 pointer, 출처 ID, 출처 pointer를 갖는다. 누락·중복·역할 위반·아직 발생하지 않은 출처가 있으면 전송을 거절한다.

출처는 해시만 맞추거나 `public`이라고 이름 붙여 승인하지 않는다. 승인한 템플릿 해시와 현재 run의 과제 초기 입력·공개 업무 사건·모델 응답·기억 반환의 **생산 사건**에 연결한다. 출처 목록 자체는 신뢰 경계 안의 실행기가 작성하고 역할·run·발생 순서를 검사한다. 독립 판정기나 벤치가 새 입력 종류를 추가하면 생산자와 허용 수신자도 계약에 추가한다.

manifest는 최종 전송 요청과 같은 해시를 참조한다. wrapper 적용 전 요청만 검사해서는 충분하지 않다. 전송 직전의 최종 요청과 일치시키고, wrapper가 내용을 바꾸면 승인된 새 출처/변환을 추가해 재검증한다. 인증 헤더는 모델 입력에 포함하지 않는다. 첫 profile은 암묵적인 provider 대화 상태를 쓰지 않는다. 이후 stateful 연결은 전용 capability와 재검증이 필요하다. prefix 토큰 캐시는 대화 상태 재사용과 구분한다.

| 수신자 | 입력 경계 |
| --- | --- |
| worker | 현재 과제의 정상 초기 정보·현재 대화·배정한 지침과 허용 기억 |
| writer | 작성 시점까지 공개된 경험·허용 피드백·해당 작성 지침 |
| 사용자 시뮬레이터 | 원래 벤치의 공개 업무 대화와 사용자 전용 정보. 기억 왕복은 자동 전달하지 않음 |
| grader | 종료 때 고정한 업무 상태와 원래 채점 입력 |
| 분석기 | 원본·배정·주석·채점 자료. 분석 라벨을 모델 요청으로 역주입하지 않음 |

개발 대화·AGENTS.md·인수인계·호스트 경로·다른 조건 출력은 실험 입력의 기본 자료가 아니다. 현재 과제가 원래 제공하는 초기 대화·정책·도구는 유지한다. 새 run은 업무·사용자·대화 객체·가변 작업자 상태를 새로 만들며 session ID 검사만으로 실제 분리를 입증하지 않는다. 파일/코드 도구가 있으면 내부 저장소·다른 run·grader·분석 경로와 symlink 우회도 차단한다.

### 자기 작성 내용과 실제 노출

`memory.input_included`는 manifest의 기억 구간에서 생성하고 반대 방향으로 누락도 검사한다. 반환 사건만 순회해 노출을 추정하지 않는다.

- `source.kind=memory_return`: `returned_event_id`와 실제 항목/버전을 연결한다. 목록 제목·get 본문·이력 재전송을 각각 센다.
- `source.kind=self_authored`: 앞선 모델 응답의 `response_event_id`를 연결한다. 저장 전 인수에는 항목/버전 ID가 null일 수 있다. 가짜 반환이나 ID를 만들지 않는다.
- 자기 작성 잔류를 조회 횟수·금지 읽기로 집계하지 않는다. 같은 요청에 다시 포함된 양과 새로 읽은 양도 구분한다. 단순 문자열 일치로 의미적 출처나 활용을 확정하지 않는다.

`same_episode_read=false`는 도구의 읽기 보기 제한이다. 자기 작성 인수를 대화에서 몰래 지우는 설정이 아니다. preload·가공본·redaction을 구현하면 해당 변환 경로와 노출 출처의 검증을 확장한다. 현재 합성 검사만으로 이 모든 기능이 구현된 것은 아니다.

### 공개 경험은 불변 접두부로 참조

작성에 사용한 공개 경험은 번호가 있는 추가 전용 항목으로 보존한다. `public_context_prefix`에는 경로·run ID·앞부분 항목 수·허용 마지막 사건 번호·**그 앞부분 bytes의 해시**를 둔다. writer 요청도 같은 접두부를 출처로 연결한다. 각 항목은 공개 생산 사건과 내용을 대조한다.

첫 오프라인 구현은 공개 사건에서 접두부를 투영해 불변 JSONL blob으로 저장한다. 원본 추가 전용 순서는 journal이 가진다. 기존 접두부 변경, 미래/다른 run 항목의 끼워 넣기는 거절한다. 이후 정상적으로 덧붙인 관측은 과거 접두부를 바꾸지 않으므로 허용한다. 파일 전체 해시를 비교해 정상 추가까지 과거 입력의 변조로 처리하지 않는다.

### 모델 공개 메타데이터

은행 `head_revision`은 내부 동시성·스냅샷·오래된 커서 판정에 남기되 공개 list/store/get 결과에서는 뺀다. 커서는 불투명하게 발급한다. 목록은 ID·제목·항목 버전과 다음 커서만 제공한다. 원천 과제·조건·성공 라벨·내부 경로를 ID나 오류에 넣지 않는다. 모델이 직접 만든 제목·본문과 의도한 혼합 후보는 원문대로 보존한다. 공개 반환의 실제 byte 수에는 정상 메타데이터도 포함한다.

## 3. 혼합 호출은 부작용 순서까지 보존

τ² 검토 commit의 환경 실행은 한 응답 안의 [도구 호출을 순서대로 처리](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/src/tau2/orchestrator/orchestrator.py#L327-L343)한다. 기억 호출은 작업자 내부에서 가로채고 업무 호출은 어댑터로 보내되, **원래 call 순서대로 실행하고 결과도 그 순서로 결합**한다. 기억 전부를 먼저 처리한 뒤 업무 결과의 순서만 복구하는 방식은 허용하지 않는다.

실행 전 batch 전체를 검사한다. 도메인에 설정된 종료 도구와 다른 호출이 섞였으면 [τ²의 batch 거절 규칙](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/src/tau2/orchestrator/orchestrator.py#L892-L915)에 맞춰 기억을 포함해 아무 부작용도 실행하지 않는다. 오류·종료·call/result 대응도 보존한다. 이 계약을 지원하지 않는 어댑터는 실행 준비에서 거절한다.

기억 왕복은 사용자 시뮬레이터나 벤치 전이를 만들지 않는다. 검토한 τ²는 역할 간 전이마다 단계가 증가하며 일반적인 단일 도구 왕복은 두 전이를 사용한다. 임의 batch의 호출마다 무조건 두 단계라는 뜻은 아니다. 알 수 없는 기억 도구를 정상 환경으로 보내면 원래 단계/오류 한도를 소비하므로 그렇게 연결하지 않는다. 업무 호출 자체의 한도·오류 의미는 보존한다. 이 연결은 실제 어댑터 행동 테스트가 필요하다.

모든 조건에서 `parallel_tool_calls=false`로 제한하는 방식은 선택 가능한 별도 실행 profile이다. 공식 설정과의 차이를 명시하고 비교 조건에 동일하게 적용한다. 조용히 기본값으로 바꾸지 않는다.

## 4. v1.1과 실제 실행 준비

[스키마 안내](../../schemas/README.md)의 v1.1을 새 구현 기준으로 사용한다. v1.0 스키마·draft·fixture는 호환 확인용 원본으로 보존하며 기존 URN/내용을 덮어쓰지 않는다. 새 필드 추가뿐 아니라 의미 변경이 있으므로 버전 없이 서로 대체하지 않는다. v1.0 변환 시 없는 출처/설정을 추정해 채우지 말고 검증 범위 미지원으로 남긴다.

v1.1 계획은 단계별 `instructions.solve`·`instructions.post_task_write`를 해시 참조로 분리한다. 쓰지 않는 단계의 null, 무제한 저장, on-demand의 preload 선택기 없음은 합법이다. 실제 준비에 필요한 미정 값과 구분한다.

| 실제 실행 전 고정할 값 | 이유 |
| --- | --- |
| 사용자 시뮬레이터 구현·모델·제공자·파라미터 | 작업자와 별개인 변동·비용 원천 |
| 벤치 native 한도, τ²의 `max_steps`·`max_errors` | 프레임워크 호출 한도와 벤치 종료 규칙을 함께 재현 |
| 전체 응답 캐시 비활성화와 확인 결과 | 독립 반복에서 과거 완성 응답 재사용 차단. τ²의 `LLM_CACHE_ENABLED`도 확인 |
| adapter 설정 artifact | 혼합 호출 profile·환경/사용자/채점 설정과 실제 해석된 값의 해시 |
| 실제 split·원천 과제 그룹·실행 순서 | 지침 개발/수집과 미관측 전이를 구분하고 시간대 효과를 조건과 분리 |

문서 검토 commit의 기본 사용자 모델과 공식 benchmark preset은 서로 다를 수 있다. 기본값을 복사하지 말고 실제 적용값을 고정한다. [τ² 설정 소스](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/src/tau2/config.py)를 확인한 결과이며 이 commit은 실험 버전 확정값이 아니다.

공식 `split_tasks.json`은 검토 commit에서 airline 30/20, retail 74/40, telecom 74/40의 train/test를 제공한다. 수집·지침 개발에 train, 미관측 전이에 test를 쓰는 안을 실행 계획에서 결정한다. 항공 33·36은 train이며 파생 쌍은 원천 그룹을 같이 둔다. 수정한 기억 프로토콜 결과를 공식 원본 점수와 혼합하지 않는다. [공식 과제 자료](https://github.com/sierra-research/tau2-bench/tree/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/data/tau2/domains)

비용은 원본 사용량과 제공자 보고를 우선하고, 추정에는 가격 출처·시점·계산 버전을 붙인다. τ²의 [비용 함수](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/src/tau2/utils/llm_utils.py)는 일부 하드코딩 가격·LiteLLM 표에 의존하며 계산 실패를 0으로 돌려줄 수 있다. 이를 Luna 실제 비용으로 사용하지 않는다. 미확인은 null/status로 보존한다.

## 5. 합성 검증의 범위와 남은 구현

이전 v1.0 검증기 점검에서는 세션 ID 재사용·system의 비공개 표식·미래 경험 추가·노출 사건 전체 제거·무관한 은행 반환이 해시를 다시 맞추면 통과했다. 이는 당시 검사 범위에 관한 기록이며 실행기의 누출 관측이 아니다.

새 [v1.1 검사](../../scripts/contract_v11.py)와 [음성 사례 테스트](../../tests/test_contract_v11.py)는 journal 순서/해시, 미확정 tail, 공개 경험 접두부, 승인 출처와 요청의 대조, 자기 작성/반환 구간, 노출 사건 누락, run/session·은행/고정 보기 연결과 합성 batch trace를 확인한다. 나중의 정상 관측 추가는 통과하는 양성 대조다. fixture는 모두 illustrative이며 실제 사용량·성공값을 만들지 않는다.

**현재는 파일 기록자·기억 서비스·입력 구성·라우터·가짜 두 회차 실행과 재계산이 동작한다.** [오프라인 코어 실행/검증](../development/offline-core.md)에 구현과 행동 테스트의 범위를 정리했다. 기존 계약 예시 검증과 새 로컬 행동 테스트를 구분한다. 실제 provider wrapper·벤치 어댑터·계획 준비 검사·통계 실증은 후속이며, 로컬/합성 경로의 통과를 해당 경로의 격리 보장으로 대체하지 않는다.
