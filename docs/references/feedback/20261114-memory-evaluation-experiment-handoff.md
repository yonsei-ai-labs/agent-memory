# LLM 에이전트의 메모리 저장·조회 정책 평가 프레임워크

실험팀 인계 · 동료 피드백 검토 · 2026-11-14

첫 파일럿으로 **같은 1회차 경험의 일반 요약과 적용 조건·절차를 명시한 기억**을 비교하는 방안을 제안한다. 2회차에서 Luna가 과거 절차를 관련 업무에 활용하는지, 중요한 조건이 달라졌을 때 적용을 보류하는지 확인한다. 파일럿에서 파악한 실행 변동과 비용은 저장·조회 정책 교차 비교의 반복 수와 조건을 정하는 데 쓴다. [11월 13일 프레임워크 상세 설계](https://github.com/yonsei-ai-labs/ai-memory-lab/blob/d0044c6367e17c1488db4dae37f44e5b358342f9/docs/ai-memory-framework-detailed-design-2026-11-13.md)

## 1. 적용 조건 하나가 다른 후속 과제쌍

`memory.html`에 나온 τ²-bench 항공 과제 33번과 36번은 가설을 설명하기 좋은 예다. 원본에서 33번은 일정 변경 뒤 좌석과 수하물 요청이 이어지고, 36번은 기본 이코노미에 더해 항공편이 이미 출발한 상태다. 파일럿에서는 **항공편이 출발하기 전인 동일한 예약 변경 요청**을 바탕으로, 요금 등급만 달라지는 진단용 과제쌍을 구성한다. [동료 리뷰 memory.html](https://chatgpt.com/library?file_id=libfile_f4b66450e7c081918d57592cb2cb9e0f&account_id=personal) · [τ²-bench 항공 과제 원본](https://github.com/sierra-research/tau2-bench/blob/main/data/tau2/domains/airline/tasks.json#L2247-L2480) · [항공 변경 정책](https://github.com/sierra-research/tau2-bench/blob/main/data/tau2/domains/airline/policy.md#L109-L113)

| 후속 과제 | 기대하는 판단과 관측 |
| --- | --- |
| 일반 이코노미, 다른 변경 요건 충족 | 현재 예약의 등급과 조건을 확인하고 변경을 완료하는가 |
| 같은 요청과 출발 상태, 기본 이코노미 | 현재 예약의 등급을 확인하고 금지된 변경을 시도하지 않는가 |

- 사용자 요청, 도구, 일정과 출발 상태 등 나머지 조건을 맞춘다. 동일한 공식 업무 규칙을 모든 정책 조건에 제공하고, Luna가 현재 등급을 확인할 정보는 정상적인 업무 도구로 접근할 수 있게 한다.
- 과제 변형에 맞춰 기대하는 업무 상태와 채점 기준을 실행 전에 검증한다. 변형 과제 점수는 **τ²-bench 기반 진단 결과**로 기록한다. 등급 확인과 금지된 변경 호출은 과정 지표로 집계하고, 벤치의 업무 성공 판정도 함께 보존한다.
- 같은 과제의 재시도, 절차를 적용할 수 있는 관련 새 과제, 절차의 적용 조건이 바뀐 새 과제의 결과를 각각 보고한다. 같은 원천에서 만든 변형은 한 출처 그룹으로 관리하고, 전이 확인 과제의 실행 기록은 기억 수집과 튜닝에서 제외한다.

## 2. 첫 파일럿 비교 조건

한 번 수집한 1회차 공개 수행 기록을 공통으로 사용한다. 기억 작성은 **과제 종료 후**, 기억 제공은 **2회차 시작 시**로 고정한다. 2회차는 매번 대화·업무 상태·사용자 시뮬레이터를 초기화한다. 비교하는 후속 과제마다 Luna의 모델과 추론 설정, 초기 상태, 업무 도구와 반복 배정을 맞춘다.

| 조건 | 2회차에서 Luna가 받는 정보 | 확인할 질문 |
| --- | --- | --- |
| 무기억 반복 | 현재 과제의 기본 입력 | 다시 실행하는 것만으로 결과가 얼마나 달라지나 |
| 원기록 접근 | 같은 1회차의 공개 수행 기록 | 과거 경험에 접근하는 것만으로도 도움이 되나 |
| 일반 요약 | 같은 기록에 일반 요약 지침을 적용한 기억 | 기본 요약이 남긴 정보로 후속 업무를 수행할 수 있나 |
| 적용 조건·절차 | 같은 기록에서 언제 적용할 수 있는지와 실행 절차를 명시하도록 작성한 기억 | 조건을 명시하는 지침이 적절한 재사용과 오적용을 바꾸나 |

- **일반 요약이 적용 조건을 자발적으로 남기면 그대로 평가한다.** 실제로 남긴 조건과 근거를 양쪽에서 확인한다. 원기록이 읽기 한도를 넘는 경우에는 사전에 정한 접근 범위를 기록한다. 비교 조건별로 실제 노출된 토큰을 남긴다.
- 작성 단계에는 공개 관측과 사전에 정한 피드백만 제공한다. 2회차의 기대 행동, 정답, 채점용 주석은 평가 쪽에서 관리한다.
- 후속 교차 평가에서는 작성 정책별로 고정한 각 기억 은행에 **시작 시 제공과 수행 중 자율 조회**를 모두 적용한다. 1개·N개 선택 진단에서는 같은 기준 기억·조회 방식·읽기 한도를 쓰고, N개 조건에 유사 후보를 추가한다.

## 3. 실행 기록과 결과 해석

| 관측 항목 | 기록할 내용 |
| --- | --- |
| 업무 결과 | 과제 유형별 성공률과 무기억 대비 차이. 같은 후속 과제의 반복 결과를 짝지어 회복, 회귀, 둘 다 성공, 둘 다 실패를 집계 |
| 행동 | 첫 변경 판단 전에 현재 등급을 확인했는지, 변경 금지 과제에서 변경 도구 호출을 시도했는지, 최종 업무 상태 |
| 기억 | 필요한 근거와 적용 조건이 은행에 남았는지, 판단 전에 제목·본문이 실제 모델 입력에 포함됐는지 |
| 비용 | 작성·조회·업무 실행의 토큰, 호출 수, 경과 시간과 금액 |

한 쌍에서 관측된 실패→성공은 회복, 성공→실패는 회귀로 기록한다. 무기억끼리 반복해도 이런 반전이 생길 수 있다. 정책의 성능 효과는 반복 실행에서 추정한 성공률 차이와 불확실성으로 평가하고, 과제쌍과 은행 간 의존성을 집계에 반영한다. [평가 지표와 기여 검토](https://github.com/yonsei-ai-labs/ai-memory-lab/blob/d0044c6367e17c1488db4dae37f44e5b358342f9/docs/reports/2026-11-13-memory-benchmark-metrics-and-novelty.md)

**적용 조건 문장 자체의 효과를 확인하는 진단.** 적용 조건이 빠진 기억을 찾으면, 그 조건만 복원한 판본을 만든다. 제목·목록·본문을 통틀어 해당 기억 정보가 처음 노출되기 직전의 상태를 복원하거나 검증된 방식으로 재생할 수 있을 때, 두 판본으로 분기해 도구·인수와 최종 상태를 비교한다. 상태 복원 범위가 제한되는 경우에는 일반 재실행으로 보고한다. 연구자가 교정한 판본에는 진단 조건을 명시한다. [상세 설계의 개입 절차](https://github.com/yonsei-ai-labs/ai-memory-lab/blob/d0044c6367e17c1488db4dae37f44e5b358342f9/docs/ai-memory-framework-detailed-design-2026-11-13.md#43-추가로-지원할-실험-절차)

## 4. 추가 비교 후보 하나

**현재 조건에 맞는 기억만 제공하는 조회 정책.** 같은 은행과 후보를 사용해, 후보를 그대로 제공하는 조건과 현재 업무 관측으로 적용 가능성을 확인한 뒤 제공하는 조건을 비교한다. 확인에 쓸 입력은 Luna가 해당 판단 시점까지 실제로 볼 수 있는 관측과 기억으로 한정한다. **부적합한 기억의 노출이 줄어드는 정도와 유용한 기억이 함께 걸러지는 정도**를 모두 기록하고, 공식 성공률·회복·회귀 및 필터 호출을 포함한 지연·비용을 본다.

첫 비교에는 적용 조건을 확인하는 단순 규칙이나 Luna의 판단을 사용한다. 별도 분류 모델이 필요해지면 Jev를 같은 입력·후보에서 비교한다. 점수 임계값은 개발용 과제에서 정하고 평가 전에 고정한다. 업무 성공 여부는 공식 채점, 실제 기억 노출 여부는 실행 로그를 사용한다. 모델을 통한 로그 분류는 사람이 표본을 확인하는 보조 주석 후보로 둔다. [Jev 평가 논문](https://arxiv.org/abs/2609.37647)
