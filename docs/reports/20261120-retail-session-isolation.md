# 무기억 상담에 이전 세션이 섞였는가

2026-11-20 · τ² 소매 66과제·49고객 · 기존 요청과 응답을 사용한 오프라인 점검

**실험 코드에서 관찰할 수 있는 범위에서는 이전 상담 이력, 메모, 주문 변경이 무기억 상담에 유입된 흔적이 없었다.** 첫 상담과 재상담 1,254건 모두에서 새 상담원·고객·주문 DB를 만들고, 해당 상담에서 받은 응답만 입력 순서대로 돌려주었다. 이때 재구성한 상담원 요청 16,041건과 고객 요청 8,144건은 보관된 전송용 요청 본문과 모두 일치했다. 한편 저장된 최종 상담 기록 6건에서 시각순 정렬로 일부 발화 위치가 바뀐 문제가 있었다. 이 여섯 건의 주문 DB 판정과 공식 성패는 같은 값을 유지했다. [전체 점검 수치와 해당 상담](../../artifacts/analyses/20261120-retail-session-isolation.json#L10)

점검이 실제 혼입을 검출하는지도 시험했다. 90번의 이전 상담원 문장과 이전 고객 문장을 역할별 첫 요청에 각각 한 번 삽입하자 원본 대조가 두 경우 모두 실패했다. 첫 상담에서 성공했던 카메라 상품 변경을 새 DB에 미리 적용하면 첫 요청 전에 초기 해시 대조가 실패했다. 세 조작은 메모리상 사본에서만 이루어졌다. [원본을 이용한 검출 시험](../../tests/test_retail_session_isolation.py)

## 무기억 상승폭을 같은 과제에서 다시 비교한 결과

무기억의 1회차 대비 +5.3%p는 채점된 189쌍에서 첫 실패 30건을 회복하고 첫 성공 20건을 잃은 순증 10건이다. 각 과제의 첫 상담은 한 번이고 비교할 때 이를 반복 사용했다. 풀이 시드는 1회차 10, 2회차 12였고 고객 발화는 매번 새로 생성됐다. 무기억에서 두 회차의 고객 페르소나 설정이 같은 쌍은 22회복·19손실로 +3건, 설정이 달랐던 쌍은 8회복·1손실로 +7건이었다. 고객 설정과 과제 구성은 함께 달라졌다. 무기억과 빈 메모가 짝을 이룬 198묶음 모두에서 **고객 시뮬레이터의 첫 요청은 동일했다. 양쪽에서 첫 응답까지 받은 192묶음 중 145묶음(75.5%)에서는 첫 고객 발화부터 달랐다.** 같은 과제의 무기억 세 반복을 둘씩 짝지었을 때 상담원의 첫 요청 본문과 시드까지 같은 46쌍 중 41쌍에서 첫 공개 응답 문구 또는 도구 선택·인수가 달랐다. 도구 호출 식별자와 비공개 추론은 이 차이에 포함하지 않았다. 이 쌍들은 일부 상담을 공유한다. 무기억 세 반복이 모두 채점된 57과제 중 20개에서 성공과 실패가 함께 나왔다. 현재 자료는 무기억의 평균 우위를 확정하기에 불확실성이 크다. 다음 기억 내용 비교에서 같은 고객 설정과 결정 직전 발화·주문 상태를 고정하면 이러한 변동을 줄일 수 있다. ## 저장된 대화 순서에서 찾은 문제

τ²는 실행 중 처리 순서대로 발화를 추가한 뒤 최종 보고서를 만들 때 시스템 시각으로 정렬한다. 둘째 반복의 49번 세 조건(단순 정보·교훈·빈 메모), 71번 단순 정보, 77·84번 무기억에서 이 정렬이 실제 요청 순서와 달랐다. 예를 들어 49번 교훈에서 상담원이 교환을 확인한 말을 들은 뒤에야 고객이 감사하며 종료했다. 실행 장부에서는 고객 요청의 종료 시각이 시작 시각보다 약 0.55초 빨라 최종 보고서에 감사 인사가 먼저 놓였다. 84번은 두 주문 조회의 위치가 바뀌었다. 여섯 건에서 발화나 도구 반환 내용이 바뀐 경우는 없었고, 주문을 변경하는 작업의 순서도 같았다. 자연어 개별 판정 항목이 없는 여섯 건 모두에서 실제 순서로 계산한 최종 DB 성패와 공식 점수가 일치했다. 이 사례의 시간순 해석에는 전송 장부의 사건 순서와 실제 모델 입력을 사용한다. [여섯 상담의 원래 위치·시각과 메시지 해시](../../artifacts/analyses/20261120-retail-session-isolation.json#L110) · [고정된 τ² checkout과 연결 안내](../development/tau2-connection.md)
