# 프로필에서 지난 시애틀 귀국편을 찾을 수 있었을까?

2026-11-19 · τ² airline 24번 고객 · 기존 첫 응답 16건과 로컬 도구 재생

1회차에 실제로 예약한 귀국편은 **2024년 5월 25일 시애틀(SEA)→뉴욕(JFK) HAT276**이었다. 2회차 진단용 문의에서는 고객이 노선을 알려 주고 지난번 귀국일의 직항 선택지를 요청했다. 날짜와 편명을 모두 담은 자율 작성 메모 네 편을 골라, 기존 첫 응답과 해당 호출이 돌려주는 정보를 대조했다. 각 행은 메모·문의·도구 정의·모델 설정이 같은 요청을 네 번 보낸 결과다. 두 번째 일기에서는 같은 입력으로 검색과 프로필 조회가 두 번씩 나왔다. 첫 번째 단순 정보에는 노선·편명·날짜가 한 구절에 함께 있었고, 네 번 모두 프로필 조회를 골랐다. 이 네 메모만으로 형식이나 문장 위치의 효과를 가려내기는 어렵다. [실제로 제공한 메모 본문](../../runs/tau2-format-content-decisions-01/control.json)

**프로필을 먼저 조회한 11회**는 모두 같은 고객 ID를 썼다. 2회차 초기 상태에서 프로필 조회를 재생한 뒤, 분석자가 프로필에 연결된 예약 세 건을 모두 열어 봤다. 시애틀을 지나는 구간은 없었다. 5월 25일 구간이 하나 있었지만 뉴어크(EWR)→휴스턴(IAH)이었다. 새 환경에는 1회차에 생성한 예약이 없으므로 이 고객의 프로필로는 지난 시애틀 귀국일을 확인할 수 없었다. [세 예약의 전체 구간](../../artifacts/analyses/20261119-return-date-profile-lookup.json)

**직항을 먼저 검색한 5회**는 모두 SEA→JFK와 2024년 5월 25일을 검색 인수로 썼다. 같은 초기 상태에서 도구는 예약 가능한 네 편을 돌려줬고, 그중에 HAT276이 있었다. 두 도구의 응답은 같은 고객의 기존 무기억 전체 실행에서 해당 인수로 받은 공개 응답과 각각 일치했다. 16건에서 모델이 실제로 낸 것은 첫 도구 호출까지다. 이후 고객에게 어떤 선택지를 안내했는지와 2회차 최종 성패는 이 기록으로 판단할 수 없다. [기존 대화에 들어간 실제 도구 응답](../../runs/tau2-new-customer-forms-continuation-01/jobs/0107/blobs/sha256/cecfad9ba04da7d50001e77e02d52c04336b9ce140f2cec6aacc63bacaddd8d5)

다음에 좁혀 볼 질문은 **같은 프로필 응답을 받은 뒤, 1회차 메모가 있으면 지난 날짜로 검색을 이어 가는가?** 두 번째 일기와 빈 메모에 같은 문의·프로필 호출·반환을 주고, 다음 행동이 정확한 검색인지, 추가 조회인지, 고객에게 날짜를 다시 묻는지 기록할 수 있다. 이 비교는 프로필 조회까지 고정한 조건에서의 후속 행동을 측정한다.
