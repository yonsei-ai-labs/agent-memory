# 세 과제·네 조건 기억 전달 파일럿 결과

2026-11-14 · 실제 OpenRouter·τ² 개발 관측 · 공식 train 과제

**48회 실행·채점을 완료했다. 본문 제공은 실제 입력까지 도달했고, 자율 조회는 발생하지 않았다. 필요한 승객 정보 수정의 미완료가 빈 은행과 본문 제공에서 각각 1회 관측됐다. 이 작은 비교로 기억 내용의 원인 효과나 정책의 동등성을 확정하지 않는다.**

실행 전 [프로토콜](../research/delivery-development-pilot.md)과 [구현·주석 기준 해시](../../artifacts/pilots/20261114-tau2-delivery-development-protocol.json)를 고정했다. 실제 결과는 [관측 receipt](../../artifacts/pilots/20261114-tau2-delivery-development-results.json), 의미 검토는 [공개 메시지 근거와 주석](../../artifacts/analyses/20261114-tau2-delivery-behavior-review.json)에 연결한다.

## 무엇을 비교했나

airline train 40·47·49에 무기억·빈 은행·자율 조회·본문 제공을 각각 4회 배정했다. 조건의 위치를 균형화하고 12개 과제·반복 블록의 실행 순서를 섞었다. 40·49는 같은 예약을 쓰므로 과제 3개·출처 그룹 2개다. 모든 실행에서 새 세션·사용자·업무 DB와 평가용 은행을 배정했다.

작업자는 Luna reasoning low, 사용자 시뮬레이터는 DeepSeek V4.1 Flash 1017이며 OpenRouter의 OpenAI·Fireworks 경로와 fallback 끔을 유지했다. 전체 응답 캐시는 껐고 provider의 prefix 캐시 사용량은 그대로 기록했다. worker/native seed 0 반복과 사용자 모델의 미지원 seed 생략을 유지했다.

은행은 이전 guided 실행에서 작성한 취소 정책·사례 기억 1개의 동일 버전이다. 본문 제공에서도 list/get을 유지했다. 이번 비교는 고정 은행의 전달 진단이며 자율 작성 전체 정책의 평가가 아니다. 일반 취소 조건은 현재 정책에도 있으며, 과거에만 있는 필수 정보를 준 실험으로 표현하지 않는다.

배정·시작·채점은 모두 48회이며 생략·실행 오류·native 도구 오류·미확인 비용은 0이다. 업무 미완료 2회는 정상 종료한 공식 실패로 보존했다. 재실행으로 교체하지 않았다.

본문 제공의 83개 worker 요청에 같은 제목·본문 구간이 포함됐다. 자동 제공은 `memory_snapshot` 출처로 기록하며 가짜 list/get 반환을 만들지 않았다. 사용자 시뮬레이터에는 기억 문맥·도구를 직접 제공하지 않았다. 입력 포함은 인지적 활용을 증명하지 않는다. 자율 조회의 0/12는 기억 내용을 평가하지 못한 관측이다.

사전 1차 비교인 자율 조회 대비 본문 제공은 12개 배정짝 중 11개가 같은 공식 성공 결과, 과제 40 반복 1의 한 짝이 자율 조회 성공·본문 제공 실패였다. 서로 다른 새 대화의 관측짝이며 동일 상태 개입이 아니다. 무기억의 과제별 4회는 모두 성공했고, 과제마다 생기는 6개 반복쌍의 결과 불일치는 0이었다. 같은 실행을 공유하는 쌍을 독립 표본으로 검정하지 않는다.

같은 반복의 무기억·자율 조회는 기존 생년월일을 유지하는 변경을 설명하고 동의를 받은 뒤 수정했다. 도구는 passenger 인수에 생년월일을 요구하지만, 조회한 기존 값을 사용하는 경로가 가능했다. 실패 대화에서도 사용자는 이름 수정 목표를 유지했다. 성공한 14회는 명시적 확인 후 Mei의 성만 변경하고 인원·다른 승객·생년월일을 보존했다.

이 사례는 **필요한 정보가 이미 입력에 있어도 업무에 쓰이지 않을 수 있음**을 보여준다. 본문 제공의 한 실패와 같은 경로가 미노출 빈 은행에도 있었고, 현재 기억은 취소 정책·사례다. 특정 기억 문장이 생년월일 요구나 실패를 일으켰다는 설명은 검증하지 않았다. 감독자 요청 뒤의 이관과 앞선 수정 미완료도 별도로 판단한다.

## 성공 점수와 함께 봐야 할 설명·시나리오

과제 47·49의 32회에서는 취소 호출이 없었다. 두 과제는 무행동 DB 궤적도 통과할 수 있는 채점 구조여서 이 성공만으로 거절 설명과 이관의 적절성을 판단하지 않는다. [사전에 정한 기준](../research/tau2-task-selection-and-rubric.md)에 따라 공개 메시지를 검토했으며 이관 요약을 사용자 설명으로 세지 않았다.

- 과제 47은 16회 모두 대화 중 거절 사유를 설명했다. 이관은 15회였고, 그중 이관 전 설명은 10회였다. 나머지 5회는 이관 후 설명했다. 한 회는 이관하지 않았다. 최초 이관 전 명시적 사람 요청은 관측되지 않아, 이관 근거는 별도 재검토 대상으로 남겼다.
- 과제 49는 16회 모두 이관했고, 이관 전 명시적 거절 설명은 9회였다. 6회에는 먼저 공개된 사람 요청이 있었다. 보험 기록 분쟁 등 다른 이관 근거는 단일 검토자의 잠정 판정으로 남겼다.
- 과제 49의 보험 구매 주장은 판단 전에 **14/16회**에서 실제 발화됐다. 빈 은행·본문 제공의 반복 2에서는 보험 주장이 나오기 전에 이관으로 종료됐다. 이 2회를 원래 분모에서 제외하지 않으며, 보험 주장과 기록의 충돌을 충분히 시험한 사례로 합치지 않는다.

보험 주장 제시 여부와 7/48회에서 나타난 동시 업무 호출은 실행 후 추가한 진단이다. 새 주요 지표나 판정된 위해 건수로 바꾸지 않는다. 모든 의미 주석은 조건을 아는 단일 에이전트의 검토이며 독립 재판정은 아직 없다. 전체 호출·사건 번호·공개 메시지 해시는 분석 JSON에 보존했다.

## 비용·기록과 재검증

622개 모델 요청, 1,726,925 보고 토큰, **$0.062301097**의 provider 보고 비용을 기록했다. 사용자 승인 한도 $3 이내이며 모든 요청의 비용이 확인됐다. 과거 source 수집·작성 비용 $0.0015464252는 별도다. 조건마다 대화 길이와 prefix 캐시 적중이 달라 이 작은 비용 순위를 일반 효율 순위로 사용하지 않는다.

| 역할 | 요청 | 보고 토큰 | 보고 비용 USD |
| --- | --- | --- | --- |
| Luna 작업자 | 345 | 1,473,679 | 0.036263755 |
| DeepSeek 사용자 | 277 | 253,246 | 0.0260373420 |

작업자의 `reasoning.effort=low`를 유지했으며 provider가 보고한 reasoning token은 9,989개였다. 원본 사용량과 실제 반환 모델·제공자는 receipt에 남겼다.

실행 전 고정한 문서·구현 파일 64개와 초기 벤치 자산, source 로그의 해시를 대조했고 원본 감사도 통과했다. 배정·요청 출처·실제 노출·세션/은행 격리·고정 버전·공식 점수·사용량/비용·저장 요약을 확인했다. 원래 v1.1 실행과 source는 보존하고, 자동 제공은 v1.2 확장으로 기록했다. 코어 전체 109개 테스트는 유료 실행 전에 통과했고 해당 구현 해시를 유지했다. 실행 뒤 기본 설계·문서 링크·보관본 검사도 통과했다.

파일 저장의 확장 비용도 드러났다. 원본 journal은 약 5MB지만, 이 실행의 고유 상태 blob 1,032개가 **795,569,849 bytes, 약 759MiB**를 차지한다. 원본 상태 전체를 반복 보존하는 비용과 검증 시간을 다음 확대 전에 계측·보완한다. 파일 방식은 유지하며 기존 원본과 계약을 보존한 새 구현으로 검토한다.

아래는 새 모델 호출이나 원본 변경 없이 실행하는 검사다. 이 기록의 고정 구현·문서와 τ² checkout이 있는 환경을 사용한다.

```bash
uv run --frozen --extra tau2 python scripts/run_tau2_delivery.py --output runs/tau2-delivery-luna-deepseek1017-development-01 --audit-only
uv run --frozen --extra tau2 python scripts/review_tau2_delivery_development.py
```

원시 로그·blob은 기존 방침대로 Git 밖의 `runs/`에 보존한다. Git에는 프로토콜·동결 해시·관측 receipt·공개 근거/주석·검증 스크립트와 이 보고서를 남긴다. 원본 재감사에는 해당 실행 폴더가 필요하다.
