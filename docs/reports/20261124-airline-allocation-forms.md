## 공식 점수와 발권이 갈린 여섯 건

현재 배분이 원래와 같은 조건에서 세 건은 증서를 맞게 쓰고도 실패했다. 경험 일기는 새 예약 세 건의 목적지 필드에 참조값 SFO 대신 JFK를 기록했다. 교훈은 참조 과제에서 Mohamed가 쓸 기프트카드 한 장을 Raj에게 제안했고, 실제 고객 시뮬레이터가 그 제안을 승인했다. 자유 구성은 기존 예약을 취소하지 않고 승객당 수하물 두 개를 등록했다. 세 건 모두 필수 금액 안내는 통과했다. [예약별 참조값과 관측값](../../artifacts/analyses/20261124-airline-allocation-booking-audit.json) · [고객 승인 발화](../../artifacts/analyses/20261124-airline-allocation-dialogue-review.json)

배분을 바꾼 조건에서도 세 건은 고객이 이번 대화에서 바뀐 배분을 직접 지정했고 그대로 발권했다. 세 상담 모두 고객이 먼저 언급한 Liam을 Raj보다 먼저 발권해 두 예약번호의 주인이 참조 DB와 반대였다.

- **경험 일기**에서는 이 순서만 점수를 갈랐다. 실제 최종 DB의 두 신규 예약번호만 맞바꾼 사본이 참조 DB와 완전히 같아졌고, 필수 금액 안내도 모두 통과했다. 고객 대본에는 두 승객의 발권 순서 요구가 없다.
- **정보**에서는 기존 예약을 취소하지 않은 차이도 있었다. **교훈**에서는 승객당 수하물 두 개와 필수 금액 1,000 안내 누락도 있었다.

나머지 두 건 중 자유 구성에서는 고객이 대화 끝까지 어느 번호를 누구에게 쓸지 말하지 않았고, 상담원은 원래 배분으로 발권했다. 절차에서는 분할 결제를 논의하기 전에 사람에게 이관했다. 교환 조건의 공식 0/5에는 서로 다른 원인이 들어 있다. 예약번호를 맞바꾼 사본은 점수 해석을 위한 사후 검산이며, 표는 원래 공식 점수를 사용한다. ## 이 개발 결과를 다음 실험에 쓰는 방법

먼저 같은 공개 원천에서 기본 작성 지침과 “고객이 선택한 대상과 값을 짝지어 보존하고, 허락이 적용된 거래를 밝혀라”는 지침을 비교할 근거가 생겼다. 사람 이름이나 증서 번호를 지침에 넣지 않고 **작성물만으로 두 승객의 선택을 복원하는 비율**부터 측정할 수 있다. 현재 지정이 바뀌면 그 지시를 따르는지도 함께 보아야 한다. 다음 고객에서는 목록 순서와 과거 지정이 반대인 사례를 배정하고, 승객별 실제 결제와 공식 점수를 계속 함께 기록할 필요가 있다. [이미 설계한 기본·보완 지침 비교](../research/airline-payment-allocation-pilot.md)

이번 관측은 개발 고객 1명, 원천 1건, 방식당 작성 1회와 대본별 상담 1회에서 나왔다. 작성 형식의 우열이나 일반 성공률을 추정할 반복은 없다. 작성물과 대화는 한 분석자가 배정과 성적을 가리고 읽었고, 문체나 고객의 공개 발화로 형식·상황을 짐작할 수 있었다. 메모가 행동 직전 입력에 포함됐는지는 검증했으며 특정 문장이 행동을 바꿨는지는 이번 배정만으로 정할 수 없다.

## 재현

실행 구현은 `20f720217207c048e8a705abbb654d67b8825f45`다. 원장을 가진 저장소 루트에서 아래 명령으로 작성·대화 가림 자료를 다시 만들고 공식 결과와 사후 발권 검산을 대조할 수 있다. 두 판독 JSON에는 가린 입력 파일의 해시, 인용, 메시지 위치가 있다. `booking-audit`는 실행 뒤 추가한 오프라인 분석이다. 유료 요청 없이 원래 입력과 로그를 읽는다. 고정 구현과 현재 분석기로 재생한 공식 결과는 바이트 단위로 일치했다. 저장소 기본 검증 세 가지, 기존 테스트 558개와 예약번호만 바꿨을 때 다른 오류가 보존되는지 확인하는 추가 테스트 1개가 통과했다.

```bash
run=runs/tau2-airline-allocation-forms-01
check_dir=$(mktemp -d)
for mode in writers dialogue results booking-audit; do
  uv run --offline --frozen --no-sync python -m scripts.analyze_airline_allocation "$run" "$mode" > "$check_dir/$mode.json"
done
cmp "$check_dir/results.json" artifacts/analyses/20261124-airline-allocation-results.json
cmp "$check_dir/booking-audit.json" artifacts/analyses/20261124-airline-allocation-booking-audit.json
```

원장을 보관하지 않은 체크아웃에서도 저장된 결과 JSON으로 표의 분모, 공식 성공 수, 지정 증서로 발권한 수를 다시 셀 수 있다.

```bash
python3 - <<'PY'
import json

result = json.loads(Path("artifacts/analyses/20261124-airline-allocation-results.json").read_bytes())
for variant in ("past_only", "explicit_same", "explicit_swapped"):
    rows = [r for r in result["consultations"] if r["request"] == variant]
    print(variant, len(rows), sum(r["official_success"] for r in rows), sum(r["allocation_correct"] for r in rows))
PY
```
