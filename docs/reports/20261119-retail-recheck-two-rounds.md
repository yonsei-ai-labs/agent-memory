## 무엇을 고정했나

항공 실험에서 관측한 고객과 겹치지 않도록 τ² 소매 주문 원본을 사용했다. 공식 test에서 확인 고객을 먼저 확보하고, 그들과 겹치지 않는 train 고객을 개발에 배정했다. 각 라운드는 주문 취소·반품 환불·상품 교환에 두 명씩이다. 각 업무 안에서 참조 DB 변경 수가 적은 과제, 그다음 과제 번호 순서로 골랐다. 같은 기준으로 순서를 확정한 뒤 고객을 교체하지 않았다. [고정 프로토콜](../../protocols/pilots/tau2-retail-recheck-two-rounds-v1.json) · [고객 배정·지침·전체 순서](../../artifacts/analyses/20261119-retail-recheck-preflight.json)

첫 상담은 무기억으로 새로 수행했다. 같은 고객의 같은 공개 경험을 받은 Luna가 네 형식을 기존 지침과 보완 지침으로 각각 한 번 작성했다. 보완 지침에 추가한 원문은 “If you write, explicitly state which conditions should be verified again before acting in a future case.”였다. 작성 모델에는 채점 결과나 평가용 정답을 주지 않았다. 실제 첫 작성 요청에서 지침을 뺀 나머지 전송 입력이 같은 고객의 여덟 작성 배정에서 일치했는지 검증했다.

각 메모를 상담 시작에 제공해 같은 과제를 초기화된 DB에서 두 번 다시 풀었다. 수행 시드 12·13 각각에 순수 무기억·빈 메모 대조도 새로 배정했다. 네 형식이 각 고객·시드의 대조를 공유한다. 작성 시드는 11, 첫 상담 시드는 10이며 DeepSeek V4.1 Flash 1017 고객 시뮬레이터에는 시드를 지정하지 않았다. 한 라운드의 독립 고객은 6명이고 같은 작성물의 두 수행은 반복 관측이다. 새 고객에게 메모 하나를 옮기는 효과나 현재 값이 실제로 바뀌었을 때의 효과는 별도 비교가 필요하다.

한 검토자가 배정·성적을 가린 상태에서 작성물을 전부 읽고 현재 또는 후속 결정에서 확인할 구체적인 사실·고객 선택·권한을 지시한 문장을 인용했다. 과거에 확인했다는 묘사와 일반적인 주의 문구는 음성으로 판정했다. 자유로운 표현이나 제목이 지침을 짐작하게 할 가능성은 있다. 각 라운드의 2회차 상담 전에 판정을 봉인했다. 개발에서 한 쌍 이상 이 판정이 어느 방향으로든 달라지면 확인 라운드로 간다는 사전 기준을 충족했다.
