# 과거 실험에서 두 회차 사이에 실제로 달라진 것

2026-11-24 · 보관된 프로토콜과 요청을 사용한 점검 · 추가 유료 호출 0건

**확인한 항공·소매 재수행 자료에서는 1회차 대비 성공률 변화를 메모리의 효과로 귀속할 수 없다.** 항공에서 직접 대조한 후속 상담 390건 전부, 소매 66과제의 재상담 1,188건 전부에서 풀이 시드가 바뀌었다. 한편 소매 1,254건의 실제 요청을 새 세션과 초기 DB에서 재생한 결과는 이전 상담이 무기억 조건에 유입됐다는 가설을 뒷받침하지 않는다. 같은 2회차 안에서 대본과 업무 조건을 공유한 메모 간 비교에는 별도의 근거가 남아 있다. ## 1회차 대비 변화의 근거

항공에서는 완료 기록에서 배정·설정과 개별 저널 해시를 확인하고, 과제별 **실제 무기억 원천**과 각 후속 상담의 초기 시드 및 역할별 첫 요청 본문을 읽었다. 보충 실행의 기존 배정을 중복 집계하지 않았다. 표의 분모는 후속 상담 횟수다. 여러 조건과 반복이 같은 원천과 고객을 공유한다. 비교 대상에는 무기억·빈 메모 등 당시 배정한 대조도 포함한다. [검산 코드](../../scripts/audit_first_pass_comparability.py)

원천 시드는 0, 후속 시드는 2 또는 3이었다. 상담원 첫 요청이 남은 386건은 요청 본문에서도 시드 차이를 확인했다. 나머지 4건은 상담원 요청까지 도달하지 않아 초기 설정에서만 확인했다. 상담원 첫 요청에서 시드와 메모 부분을 빼고 비교한 업무 정책·도구·모델 설정은 386건 모두 원천과 같았다. 그중 296건은 메모 안내 안에 고객 ID를 먼저 받으라는 업무 지시가 반복돼 있었다. 해당 지시를 공유한 메모·빈 메모 비교에서는 안내가 고정되지만, 무기억 원천과의 비교에서는 또 하나의 차이다. 이 수치로 시드나 안내가 바꾼 성공 건수를 추정할 수는 없다. 390건의 후속 세션 ID는 모두 달랐다. 고객 요청에 연결된 메모 노출 사건은 0건이었다. 같은 실험·과제·반복·대본에서 둘 이상의 후속 조건이 고객 요청을 만든 69묶음 모두 고객의 첫 입력이 같았다. 항공에서 고객 요청 본문을 독립 대조한 범위는 각 상담의 첫 요청까지다. 이후 고객의 메모 노출 여부는 저널의 출처 기록에서 확인했다. 설계에서 미리 지정한 변형과, 같은 조건에서 실행 도중에 다른 세션이 섞이는 문제는 이 자료로 서로 다른 수준까지 판정할 수 있다. 1. 같은 과제의 작성 지침을 비교하거나 같은 은행의 전달 방식만 비교할 때, 2회차 고객 대본과 정답, 초기 DB, 업무 정책·도구, 역할별 모델·시드·실행 한도를 1회차와 대조한다. 개별 상담의 새 환경에서 확인한 기록을 **첫 요청 전** 저널에 저장한다. 두 비교에서 공통으로 고정한 메모 사용 안내도 실제 텍스트 해시로 확인해 다른 업무 힌트를 끼워 넣으면 전송을 차단한다. 2. 비교 보고서가 과제 ID나 설정의 기준선 이름만으로 회차 간 성적을 집계할 수 있던 부분을 고쳤다. 전체 관측 전환은 보존하고, 실행 때 남긴 검증 기록과 사전 배정의 원천, 실제 첫 고객 요청, 상담원 요청의 시드가 맞고 공식 채점된 쌍을 별도로 센다. 미시작·미채점·미검증·불일치 상태는 개별 배정에서 확인한다. 검증된 쌍에는 고유 원천과 출처 그룹 수도 표시한다. 이 보고서를 기존 항공 재확인 작성 실험에 적용하자 관측 성적은 23성공·9실패였고, 실행 당시 이 검증 기록이 있는 배정은 0/32건이었다.
