# 기억 평가 프레임워크 진행 보고서와 2주 발전 계획

2026-11-14 · 진행 보고서 초안 v0.4 · 48회 전달 비교 후 갱신

**같은 기억의 시작 시 제공과 자율 조회를 실제 τ² 세 과제·네 조건·48회에서 비교했다. 본문은 제공 조건의 12회 모두에 도달했고 자율 조회는 0회였다. 공식 성공은 무기억·자율 조회 12/12, 빈 은행·본문 제공 11/12였다. 다음 2주는 설명·시나리오 판정과 정보 차이를 보완하고, 같은 경험에서 작성한 기억의 적용 가능성을 비교할 근거를 확보하는 데 집중한다.**

전체 연구 목표는 [저장·조회·전이·누적·득실·비용](../research/plan.md)이다. 이번 2주의 실행 초점은 그중 전달 방식 비교이며 전체 범위를 바꾸지 않는다. 기존 [보고서 네 장 구성](../handoff/report-outline.md)의 실제 진행 근거와 후속 계획으로 사용할 수 있다.

작업자는 OpenRouter의 Luna reasoning low, 사용자 시뮬레이터는 DeepSeek V4.1 Flash 1017이다. 모델·제공자·파라미터와 고정 τ² revision은 [연결 안내](../development/tau2-connection.md), 세 조건의 통제와 배정은 [파일럿 방법](../development/tau2-autonomy-pilot.md)에 있다. 오프라인 테스트 통과와 실제 모델 관측은 구분한다.

초기 보고서 보완은 새 유료 호출 없이 기존 원본을 재분석한 단계였다. 당시 전체 93개 테스트와 공개 메시지 70개 근거 대조, 과제 7개의 오프라인 native DB 검사를 확인했다. 기존 실행의 로그와 저장 요약 해시를 유지했다.

이후 [전달 비교 실행 구성](../development/tau2-delivery.md)을 추가했다. 같은 본문의 실제 worker 입력과 다중 과제·반복 배정을 구현했으며 파일/출처 8개와 실행 구성 8개의 검증을 추가했다. 과제 0·40의 native mock에서 무행동 성공·실패가 구분됐고, 기억 도구 없는 제공과 세션·DB 분리도 검사했다.

추가 후 전체 109개 테스트와 기본 검사가 통과했고 기존 두 자율 조회 파일럿의 원본도 유지했다. 그 구현·프로토콜을 동결한 뒤 사용자 승인 $3 한도로 아래 실제 48회를 실행했다. 오프라인 테스트와 모델 관측은 별도 근거다.

## 실제 관측

### 최근 세 과제·네 조건 48회

[상세 결과와 해석](20261114-tau2-delivery-development-results.md)에 과제별 공식 점수·실제 노출·두 실패 경로·설명과 이관·비용·원본 감사 결과를 정리했다. 배정·시작·채점 48회, 오류·생략·비용 미확인 0이며 622요청·1,726,925 보고 토큰·$0.062301097이다. 과거 기억 수집·작성 비용은 별도다.

자율 조회 대비 본문 제공의 12개 배정짝에서 같은 결과 11개, 자율 조회 성공·본문 제공 실패 1개가 관측됐다. 과제 40 반복 1에서 본문 제공과 빈 은행이 기존 생년월일을 다시 요구한 뒤 수정하지 못했다. 다른 14회는 확인 후 필요한 수정과 나머지 정보 보존을 완료했다. 이 한 짝으로 특정 기억 문장의 해를 판정하지 않는다.

취소 과제 47·49의 32회에는 취소 호출이 없었다. 사용자 거절 설명은 25/32회에서 관측됐으며, 과제 47의 일부는 이관 뒤에 설명했다. 과제 49의 보험 구매 주장은 14/16회에서 판단 전에 제시됐다. 미제시 2회도 원래 분모에 유지한다. 공식 점수·공개 정보의 실제 제시·설명·이관 근거를 함께 봐야 한다.

원본 상태 blob이 약 759MiB라는 저장 비용도 확인했다. 확대 전에 상태 사본과 검증 시간의 비용을 계측·보완할 후보로 둔다. 파일 방식과 기존 원본 보존을 유지하며 SQLite를 도입 조건으로 만들지 않는다.

이하의 저장 0과 9회 비교는 앞서 완료한 별도 관측이다. 48회와 합쳐 하나의 자연 작성 정책 효과나 독립 표본으로 분석하지 않는다.

### 저장 선택과 고정 은행 조회는 서로 다른 실험이다

첫 시도에서는 사후 작성 기회 1회에 `memory_store` 호출이 없었다. 작성자는 `{"message":"No memory was saved."}`라고 응답했으며 저장하지 않은 이유는 확인되지 않았다. 사전 배정한 후속 평가 9회는 `source_empty`로 생략했다. 실패 9회나 자율 조회 0/9로 세지 않는다.

두 번째 시도는 이전 guided 실행에서 생성한 기억 1개의 동일 버전을 고정해 조회만 비교했다. 자율 작성까지 포함한 전체 정책 평가와 구분한다. 비어 있지 않은 은행이 주어진 조건에서의 조회 관측이다.

### 완료한 세 조건 비교

τ² airline train 과제 0을 각 조건에서 3회 실행했다. 평가마다 세션·사용자·업무 환경을 새로 만들고, 은행을 쓰는 조건에는 각각 복제본을 배정했다.

| 조건 | native 성공 | 목록 또는 본문 조회가 있었던 평가 | 제목 또는 본문 입력 포함 | 업무 호출 수 |
| --- | --- | --- | --- | --- |
| 무기억 | 3/3 | 기억 도구 없음 | 0/3 | 4, 2, 2 |
| 빈 은행 | 3/3 | 0/3 | 0/3 | 3, 2, 4 |
| 기억 은행 | 3/3 | 0/3 | 0/3 | 2, 4, 2 |

조회가 가능한 평가의 분모는 **6회**, 전체 채점의 분모는 **9회**다. 9회 모두 최종 업무 DB 해시는 같았다. 전체적으로 예약 상세 조회와 상담원 이관이 각각 9회, 항공편 상태 조회가 7회 있었다. 후속 [업무 사례 검토](20261114-tau2-case-review.md)에서 사용자 거절 설명과 이관 근거를 구분했다.

벤치·작업자 seed 0을 반복했고 사용자 모델에는 미지원 seed를 보내지 않았다. 같은 설정의 반복이며 독립 난수 표본이나 제공 모델의 결정성을 보장하지 않는다.

두 번째 시도는 90요청·243,176 보고 토큰·$0.010635548이었다. 첫 시도의 $0.0018703952를 포함한 새 작업의 보고 비용은 **$0.0125059432**이며 미확인 비용은 없다. 이전 기억의 경험 수집·작성 비용 $0.0015464252는 별도다. 현재의 짧은 과제 비용으로 앞으로 2주 전체의 비용을 확정하지 않는다. 수치와 원본 해시는 [관측 기록](../../artifacts/pilots/20261114-tau2-autonomous-memory.json)을 따른다.

## 결과에서 해석할 수 있는 것

### 자율 조회는 실제 전달로 이어지지 않았다

이 조건의 모델은 기억은행이 있어도 목록과 본문을 읽지 않았다. 따라서 기억 내용이 도움이 됐는지, 해로웠는지, 적용 조건이 충분했는지는 판단할 수 없다. 빈은행과 기억은행의 비용·호출 수 차이를 보지 않은 기억 내용의 효과로 설명하지 않는다.

현재 문맥의 충분성·과거 정보의 가치·지침이나 과제 특성은 후속 가설이다. 이 관측에 따라 이후 48회에 시작 시 제공을 추가해 실제 전달을 확인했다. 정보 가치와 조회 선택의 구분은 다음 비교에도 유지하며 제목 제공도 기억 노출로 센다.

### native 성공은 업무 품질 전체를 보장하지 않는다

과제 0의 기대 행동과 전달 정보는 비어 있고 채점 기준은 DB/COMMUNICATE다. 취소 진행을 거절해야 한다는 자연어 assertion은 실제 reward basis에 포함되지 않는다. DB를 유지한 성공 점수만으로 적절한 거절 설명이나 상담원 이관을 확인할 수 없다.

후속 48회에는 실제 변경이 필요한 과제 40을 추가해 미실행을 탐지했다. 공식 점수를 유지하면서 필요한 도구 호출·금지 호출·설명/이관 근거를 별도로 기록하는 기준은 계속 적용한다.

9회 공개 대화를 검토하니 사용자에게 취소 불가를 명시적으로 설명한 경우는 5회였고, 나머지 4회는 바로 이관했다. 다른 담당자를 요청한 공개 발화는 3회에 있었다. 나머지 6회는 최초 불허 요청 4회와 보험 안내 분쟁 2회로 구분해 이관 적절성을 미확정으로 남겼다. 기본 이코노미 예약에 항공편 변경을 대안으로 제안한 1회도 별도로 표시했다. 이는 조건을 아는 단일 에이전트의 사후 주석이며 새 위반 건수나 성공 점수로 합산하지 않는다.

[다음 과제 후보와 채점 기준](../research/tau2-task-selection-and-rubric.md)은 train 30개를 검토해 개발 후보 6개와 추가 판정 대상 1개를 남겼다. 당시 무행동 DB 검사의 보상은 과제 7·17·40에서 0.0, 거절 과제 0·47·49에서 1.0이었다. 이 구조 검토 뒤 40·47·49를 실제 48회에 사용했다. 과제 39는 참조 취소와 보험 보장 사유의 관계를 추가 확인한 뒤 사용한다.

### 호출의 차이는 자유 서술과 업무 인수를 나눠 살핀다

원래 `actions_changed`는 함수·순서·모든 인수를 비교한다. 블록별 조건 비교 9쌍 모두 차이가 있었으나, `transfer_to_human_agents.arguments.summary`만 제외하면 차이가 남는 비교는 **7/9쌍**이다. 나머지 2쌍은 이관 요약만 달랐다. 이 제외는 요약 내용이 중요하지 않다는 판단이 아니며, 원본 지표와 텍스트는 보존했다.

보조 분석은 다른 문자열·예약 ID·사용자 ID·호출 순서를 유지한다. 7쌍의 차이도 곧 개선이나 회귀를 뜻하지 않는다. 무기억 안에서도 호출 수가 달랐고, 9쌍은 같은 9회 실행을 공유하므로 독립 표본 9개로 검정하지 않는다. 분석 규칙·입력 해시·비교별 결과는 [보조 분석 기록](../../artifacts/analyses/20261114-tau2-action-comparison.json)에 있다.

### 다음 주장에는 아직 비교 근거가 필요하다

현재는 실제 본문 전달·미조회·한 배정짝의 성과 차이를 확인했다. 세 과제와 한 은행에서 얻은 관측이며 일반적인 기억 효과·정책 우수성·동등성은 미확정이다. 같은 은행만 반복했으므로 기억 작성의 변동도 측정하지 않았다.

전달 비교의 다음 질문은 정보 차이와 적용 조건에 따라 그 차이가 재현되는가다. 같은 공개 경험의 요약과 조건·절차 기억을 비교하는 [기존 제안](../research/condition-sensitive-pilot.md)을 후보로 유지한다. 과제·판정이 차이를 측정할 수 있는지 확인한 뒤 1차 가설을 고정한다. 가까운 연구와의 차이는 [발전 방향 노트](../research/novelty-direction-review.md)를 참고하며 실제 발견에 맞춰 판단한다.

| 3~4일차 | 현재 문맥과 과거 경험의 정보 차이가 분명한 개발 과제·허용/금지 경로 확인 | 과제/은행의 출처 manifest, 원본·변형 구분, 채점과 시뮬레이터 검증 | 필요한 행동을 실제로 탐지하고 의도한 적용 조건이 판단 전에 제시됨 |
| 5~7일차 | 같은 공개 경험의 요약/조건·절차 기억 작성 준비, 정보·원본 분리와 오프라인 검증 | 새 지침·은행 버전, 작성 0 보존, 1차 가설·의미 있는 효과·예산 산정안 | 비교할 정보 차이가 성립함. 저장 표현 비교는 시작 제공을 고정해 미조회와 분리함 |
| 8~11일차 | 조정에 쓰지 않은 확인용 과제·출처와 프로토콜 동결 후 제한된 비교 | 성공·미실행·금지 시도·노출·설명·비용 및 무기억 반복 원본 | 배정 전체와 오류·결측을 보존하고 개발 관측과 확인 관측을 구별함 |
| 12~14일차 | 의존성·불확실성·대표 사례·한계 분석, 보고서 정리 | 진행 보고서 v1.0, 추적 가능한 결과표·사례, 다음 실험 결정 | 식별되지 않은 효과도 명확히 보고함. 원인 주장은 실제 개입의 지원 범위에 맞춤 |

**본문 시작 제공과 최소 실행 구성은 완료했다.** `title_preload`는 조회 진입점을 더 구분할 필요가 있을 때 별도 버전으로 추가한다. AppWorld·BFCL, 누적, 저장 시점/표현의 전체 교차는 이후 범위로 유지한다. 2주 동안 모든 축을 동시에 구현하지 않는다.

### 다음 확인 비교를 준비할 기준

무기억·빈은행 대조와 이번 `on_demand`/`full_preload` 원본을 유지한다. 다음 1차 질문 후보는 적용 조건을 남긴 기억이 조건 변경 상황에서 오적용을 줄이면서 필요한 행동을 유지하는가다. 저장 진단은 시작 제공을 고정하고, 조회 선택의 교차는 별도로 배정한다. 필요한 행동·금지 시도·노출·비용과 조회 도구 유지 여부를 새 프로토콜에 명시한다.

- **기억 출처:** 원천 경험·작성 지침·피드백·은행 버전을 고정한다. 고정은행 진단과 자율 작성 전체 정책은 별도다. 저장 0도 결과로 보존하고 비어 있지 않을 때까지 재생성한 뒤 자율 작성 결과로 합치지 않는다.
- **과제 선택:** 요구되는 상태 변경과 적용 조건, 현재 문맥에 이미 있는 정보와 과거에 남은 정보의 차이로 후보를 정한다. 무기억에서 실패한 과제만 골랐다면 개발 단계의 선택으로 표시하고 조정하지 않은 과제에서 다시 확인한다. test는 지침·과제 선택·반복 수 조정에 사용하지 않는다.
- **노출과 격리:** preload는 실제 snapshot 출처로 기록한다. 에이전트가 호출한 것처럼 가짜 list/get 이력을 만들지 않는다. 과거 전체 대화·정답·분석 주석·개발 노트는 공개 입력에서 분리한다.
- **판정 기준:** 공식 점수와 별도로 업무 호출·인수·설명 품질의 검토 기준을 실행 전에 정한다. 사례표에는 정책 근거와 판단 시점의 공개 정보를 붙이고, 불명확한 사례는 미확정으로 남긴다.
- **비교와 비용:** 과제·은행·반복을 분석 단위에 반영한다. 1차 비교, 의미 있는 효과 크기, 반복/중단 규칙과 비용 한도를 고정한 뒤 확인 실행을 시작한다. 사용자 시뮬레이터·작성·조회 등 모든 역할의 비용을 센다.

이득 포착률·손해 회피율 같은 비율은 보조 후보로 둔다. 먼저 조건별 차이와 불확실성을 보고한다. 같은 작은 표본에서 도움/해 과제를 사후 분류한 뒤 같은 결과로 선택성을 입증하지 않는다. 분류가 필요하면 개발 관측과 확인 관측을 분리하고, 분모가 작을 때 비율을 주요 결론으로 쓰지 않는다.

## 2주 뒤 보고할 결과

첫째, 같은 기억의 전달 방식별 결과·실제 노출·행동·비용과 반복 변동을 한 표에서 볼 수 있어야 한다. 둘째, 도움이 된 경우·해가 된 경우·차이를 구별하지 못한 경우를 근거와 함께 설명해야 한다. 셋째, 그 관측이 다음 저장 표현·적용 조건·전이 실험 중 무엇을 우선할지 결정하게 해야 한다.

보고서에는 구현 완료, 실제 실행 관측, 후속 가설을 분리해 적는다. 한 작업자·제한된 과제·고정 또는 제한된 은행의 결과 범위를 유지한다. 실제 노출된 문장이 행동 원인이었다고 주장하려면 추가 통제 비교가 필요하며, 완전한 동일 상태 복원·개입을 이번 2주의 완료 항목으로 미리 가정하지 않는다.
