## 무엇을 측정했나

고정 τ² `c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4`의 airline 공식 train 전체를 사용했다. 과제 선정에 test 결과나 외부 모델의 성공률을 사용하지 않았다. 반복별 native/worker seed는 0·1이며, 각 반복에서 30개 순서를 별도로 섞었다. 배정 seed는 20261115다. DeepSeek wire seed는 생략했다.

Luna reasoning low·OpenRouter→OpenAI와 DeepSeek V4.1 Flash 1017·OpenRouter→Fireworks를 유지했다. fallback·전체 응답 캐시는 껐고 provider prefix 캐시는 사용량에 보존했다. 매 run 새 worker·사용자·업무 DB·session을 만들었으며, 기억 도구·은행·snapshot·기억 지침을 제공하지 않았다.

run마다 native 200단계·오류 10회·요청 200회·보고 비용 $0.10·600초, 전체 요청 12,000회·보고 비용 $1·10,800초를 고정했다. 첫 run 시작부터 배치 종료까지 약 60분 30초였다. 원래 모델 출력 한도(worker 2,048·사용자 512), 직렬화 입력 64,000 bytes, 개별 HTTP 최대 45초 제한도 유지했다.

변경 도구는 고정 native의 `ToolType.WRITE` 표기에서 읽었다. 이 표는 참조답안의 구조별 기술 통계이며 모든 참조 행동이 정책상 옳다는 보증은 아니다.

[별도 오프라인 점검](../../artifacts/analyses/20261115-tau2-train-grading-diagnostic.json)에서도 30개 중 17개가 추가 행동 없는 궤적으로 **DB 채점만** 통과했다. 참조 도구 재생 오류는 0이었고 모델 호출 없이 원천 파일 해시를 보존했다. COMMUNICATE 요구나 실제 설명·승인·정책 준수까지 통과한다는 뜻은 아니다.

따라서 기존 소수 과제의 성공률 천장이 전체 train의 특성은 아니었다. 다만 새 표본의 실패를 전부 기억이 해결할 오류로 취급할 수도 없다. 현재 문맥의 조건을 잘못 적용한 경우, 필요한 정보를 더 조회하지 않은 경우, 실현된 사용자 제약과 고정 채점값을 먼저 검토해야 하는 경우가 함께 있었다.

## 이 측정으로 정하는 다음 단계

1. **정답·시나리오 정합성을 먼저 정리한다.** 7의 질문 시점과 고정값, 39의 보장 사유, 11의 원래 결제수단 제약을 독립 검토할 자료로 남긴다. 현재 시각·사용자 제약을 고치는 진단이 필요하면 새 버전으로 분리한다.
2. **경험 재사용 후보는 구체적인 절차와 연결한다.** 등급/항공편 변경 조건 분리(17), 증서당 예약 제한(23), 허용량과 실제 수량 구분(14), 여러 예약의 관측과 목표 대조(42), 실행 가능 시각 확보(21)가 후속 후보다. 14/23은 같은 사용자·원예약 출처를 공유한다. 이 목록은 효과가 확인된 기억이 아니다.
3. **같은 경험의 본문 제공 가치부터 보고 자율 조회를 비교한다.** 원천에 실제 있었던 사실·정정과 아직 관측하지 않은 사실을 나눠 writer에 숨은 정답을 보충하지 않는다. 개발 선정에 사용한 기록을 본 비교 기준선으로 재사용하지 않고, 새 반복·출처에서 필요한 업무 유지와 오적용을 함께 본다.

이번 조건에는 기억 도구가 없었으므로 자율 조회 0회의 원인을 새로 검증한 결과가 아니다. 새로 확인한 것은 광범위한 무기억 수행의 변동과 실패 경로·평가 한계다. 과거에만 있는 정보가 필요한 과제와 단순한 현재 과제 체크리스트의 효과도 후속 설계에서 구분한다. 저장·조회·전이·누적·득실·비용의 전체 연구 범위는 유지한다.
