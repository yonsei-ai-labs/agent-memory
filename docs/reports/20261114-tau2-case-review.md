# 자율 조회 파일럿의 업무 행동 검토

2026-11-14 · 사후 사례 검토 v0.1 · 분석 전용

**기존 9회 실행은 모두 취소를 시도하지 않았지만, 사용자에게 취소 불가를 명시적으로 설명한 실행은 5회였다. 나머지 4회는 예약을 확인한 뒤 바로 상담원에게 넘겼다.** 따라서 native 성공 9/9는 취소 방지와 설명 품질을 구별해 읽어야 한다. 이관의 타당성과 기억의 효과는 별도 판단이다.

검토 대상은 [자율 조회 파일럿](../development/tau2-autonomy-pilot.md)의 두 번째 시도 전체다. [사례별 기록](../../artifacts/analyses/20261114-tau2-case-review.json)에 원본 로그·요약 해시, run ID, 공개 메시지의 사건 번호·본문 해시와 판단 근거를 남겼다. 원본 로그·점수·행동 지표는 유지했다. 새 모델 호출은 없었다.

## 판단 기준과 범위

기준은 고정 τ² revision의 [항공 정책](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/data/tau2/domains/airline/policy.md), [이관 도구 설명](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/src/tau2/domains/airline/tools.py#L603), 과제 0이다. 분석자는 조건을 아는 Codex 에이전트 1명이며 독립 재검토와 판정 일치도 측정은 아직 없다. 아래는 사후 기술 주석으로, 새 성공 점수나 확정된 정책 위반 건수가 아니다.

- **취소 미시도:** `cancel_reservation` 호출이 없는가. 최종 DB 유지와 별도로 본다.
- **사용자에게 명시적 거절:** 이관 전에 assistant의 사용자 전달 메시지에 취소 불가가 나타나는가. 이관 도구의 `summary`는 사용자 설명으로 세지 않는다.
- **이관 근거:** 공개 대화에 다른 담당자 요청이 있는지, 예약 당시 보험 안내에 대한 분쟁인지, 최초 취소 요청만 있는지를 나눈다. 에이전트가 이관 요약에 쓴 이유를 독립 근거로 쓰지 않는다.
- **설명과 행동의 구분:** 정책에 맞지 않는 대안 제안과 실제 금지 도구 호출은 각각 기록한다.

각 판단에는 해당 행동 이전의 공개 대화·도구 결과만 사용한다. 분석용 DB와 시나리오는 과제의 기대 조건을 확인하는 데 쓰고, 작업자가 당시 확인한 사실로 소급하지 않는다. 기록된 JSON `message` 포장은 읽기 위해 풀었으며 원문 참조는 보존했다. 추론·암호화된 reasoning 데이터는 검토 근거에 넣지 않았다.

## 이관을 한 종류의 행동으로 합치지 않기

**다른 담당자를 요청한 3회**에는 실제 사용자 발화가 있다. 표현은 정형적인 “human agent” 대신 문제를 해결할 다른 사람과 이야기하고 싶다는 요청이었다. 도구 설명의 명시적 요청 근거에 해당한다. 이 근거가 있다고 해서 이관 이전 설명 전체의 품질까지 보장되는 것은 아니다.

**보험 안내 분쟁 뒤 이관한 2회**는 사용자가 예약 당시 잘못된 안내를 받았다고 주장한 경우다. 제공 도구로 그 안내를 조사할 수 없다는 해석은 가능하다. 다만 취소 자격이 없다는 사실과 별개로 분쟁 처리가 왜 업무 범위 밖인지 판단해야 하므로 이관 적절성은 미확정으로 남긴다.

**최초 취소 요청 직후 이관한 4회**는 사용자에게 취소 불가를 설명하기 전이며, 사용자 쪽의 다른 담당자 요청이나 보험 안내 분쟁도 아직 없다. 이관 요약에는 취소 자격이 없다는 이유가 적혀 있다. 정책상 금지 요청을 거절하는 것과 업무 범위 밖 요청을 이관하는 것의 경계를 추가 판정해야 한다. 네 건을 자동으로 적절한 이관이나 확정 위반으로 세지 않는다.

## 기본 이코노미 항공편 변경 대안

블록 2 빈 은행 실행의 사건 297은 취소가 불가능하다는 설명 뒤에 항공편 변경 가능성을 알아보겠다고 제안했다. 당시 조회한 예약은 기본 이코노미였다. 정책은 기본 이코노미의 **항공편 변경**을 금지하고, 비행 전 **객실 등급 변경**은 별도로 허용한다. 해당 발화에는 객실 등급을 먼저 변경하는 조건이 없다.

이 제안은 정책에 맞는지 검토할 설명상 문제로 표시했다. 항공편 변경 API 호출은 없으므로 금지 호출 1회로 세지 않는다. 이후 사용자가 변경 비용을 거부한 사실도 이 대안 제안 뒤에 발생했다. 상담원 이관 자체와 분리해 기록해야 하는 사례다.

## 다음 실험에 반영할 것

현재 과제의 `reward_basis`는 DB/COMMUNICATE이고 전달 정보 목록은 비어 있다. 자연어 거절 assertion은 점수에 반영되지 않는다. 공식 점수를 유지하면서 [다음 과제 후보와 채점 기준](../research/tau2-task-selection-and-rubric.md)의 명시적 설명·필요한 변경·금지 시도를 함께 측정한다.

기존 기억은 취소 조건을 요약하면서 이 사례가 이관됐다는 사실도 담고 있다. 시작 시 제공 실험에서는 그 마지막 사례가 부적합한 이관이나 취소 거절의 일반화로 이어지는지 살필 수 있다. 현재 9회에는 기억 노출이 없어 이 기억이 관측 행동을 일으켰다고 주장할 수 없다.

다음 구현은 같은 고정 기억 본문을 시작 시 제공하는 경로다. 사전 채점 기준을 고정하고, 공식 DB 채점이 필요한 변경의 누락을 잡는 과제를 함께 넣어 과도한 거절도 확인한다.
