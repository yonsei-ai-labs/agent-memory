# 은행 실험의 메모 저장 결함과 수정

같은 궤적의 다섯 가지 작성물을 비교한다는 연구 질문과 기존 작성기의 성공 조건이 달랐다. 기존 작성기는 저장 도구를 선택적으로 제공하고 자연어로 끝내면 빈 저장소도 정상 완료했다. 기존 읽기 실행기는 그 빈 저장소를 유효한 메모 조건으로 받아들였다. 필수 작성 비교에서 누락을 결과로 통과시킨 결함이다. [원래 작성 지침](../../protocols/instructions/optional-experience-writer-v1.txt) · [원래 은행 등록](../../protocols/pilots/tau-banking-memory-v1.json)

## 원기록에서 확인한 범위

| 항목 | 관측 |
| --- | --- |
| 원천 | 독립된 무기억 4상담 모두 공식 채점. 각 과제의 다섯 작성 요청은 그 상담원의 공개 이력 해시와 일치 |
| 작성 20건 | 19건에서 비어 있지 않은 항목 19개 저장. 저장 호출·승인 사건·봉인 버전을 대조 |
| 빠진 형식 | `task_008` 절차 작성. 모델 요청 1회, 1,443자의 절차 답변, 저장 도구 호출 0회, 저장 사건 0개 |
| 빈 메모의 후속 상담 | 자동 제공 상담 1건에서 본문 노출 0, 공식 성공. 이 성공은 절차 메모의 성과에서 제외. 짝인 자율 조회는 처음 요청을 보내기 전에 중지 |
| 비용 | 원천 4건, 작성 20건, 후속 상담 39건. 모델 요청 841건. 확인 $0.205103245, 보류 $0 |

실패가 난 위치는 모델이 절차 문장을 만든 뒤 그 문장을 다음 세션에 보관하는 단계다. 모델의 최종 텍스트는 답변 기록에 남았으나 실제 메모 항목과 버전은 생기지 않았다. 진행 중이던 선택형 실행의 원본은 보존했고 마지막 미전송 배정과 요청별 비용을 별도로 대조했다. [20개 작성 요청과 빈 메모의 실제 노출](../../artifacts/analyses/20261124-banking-storage-audit.json) · [중단 경계와 원장](../../artifacts/pilots/20261124-banking-optional-close.json)

저장이 된 예도 업무 성공과 따로 검산했다. 추천 링크 과제 `task_015`의 1회차에서 은행 문서가 `get_referral_link`의 이름과 두 인수를 알려줬다. 작성자는 교훈 메모에 이를 적었다. 그 메모를 자동 제공한 2회차의 첫 상담원 검색식에는 이 이름이 들어갔다. 같은 고객 첫 발화, 당시 업무 입력·도구 정의, 1회차의 첫 검색식에는 이름이 없었다. 해당 문장, 노출 위치, 검색 인수는 원기록에서 대조할 수 있다. 두 회차 모두 공식 실패였다. 결과를 본 뒤 선택한 사례로, 한 판단에서 나타난 변화와 과제 완료를 구분하는 데 쓴다. [원천·저장·노출·행동 인용](../../artifacts/analyses/20261124-banking-storage-audit.json)

## 수정 후 검증

1. 필수 작성은 저장 도구 하나에 `tool_choice=required`를 적용한다. 실제 저장에 성공하면 종료한다. 원래 1,443자 공급자 응답을 새 응답 검사기에 그대로 재생해 `WRITER_REQUIRED_STORE_MISSING`을 확인했다. 공백 본문을 잘못 보낸 작성자는 남은 요청 한도 안에서 내용을 고칠 수 있다. 제공자 장애나 한도 도달은 기술 결측이다.
2. 2회차 전 과제별 다섯 작성본을 다시 연다. 원천 실행 ID, 원천 로그 해시, 공개 이력 해시, 과제·반복·형식, 저장 버전, 비어 있지 않은 제목·본문을 검증한다. 두 전달 방식이 같은 작성물에 묶였는지도 확인한다. 빈 형식이 있으면 해당 과제 2회차 열 건의 모델 전송은 0건이다.
3. 네이티브 은행 환경과 공식 행동 채점기를 쓰는 모의 전송에서 보관된 1회차를 가져와 다섯 메모를 저장하고 두 방식으로 읽었다. 글만 반환한 경우, 다른 형식·원천을 바꿔 넣은 경우, 필수 형식 하나가 빠진 경우를 따로 검사했다. 이 결과는 실행 계약의 검증이다. 기억이 실제 모델의 업무 성과를 높였는지는 별도의 필수 작성 실행에서 판정한다. [필수 작성·읽기 통합 검증](../../tests/test_banking_memory.py) · [저장·오류 검증](../../tests/test_memory_writing.py)

이제 효과를 주장할 때는 작성 성공, 요청 전 본문 노출, 업무 도구·인수 변화, 공식 성패를 각각 확인한다. 문서 검색에서 이미 얻은 값과 메모에만 있던 값을 구분하며, 같은 성공에서는 검색 횟수·고객 부담·비용을 함께 본다. [관련 연구와 판정 기준](../research/tau-banking-memory-pilot.md)

저장 감사를 재현하려면 저장소 루트에서 `python -m scripts.analyze_banking_memory --optional-storage`를 실행한다. 추가 모델 호출은 없다.
