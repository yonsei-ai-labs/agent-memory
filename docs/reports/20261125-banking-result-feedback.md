# τ³ 은행에서 작성자에게 1회차 성패를 알려 준 결과

**1회차의 공식 성패를 메모 작성자에게 알려 줘도 이 네 과제에서는 후속 성공이 늘지 않았다.** 사전에 주 비교로 정한 자동 제공은 기존 8/20에서 6/20으로 바뀌었다. 같은 과제·형식을 짝지으면 새 메모에서만 성공한 상담이 1건, 기존 메모에서만 성공한 상담이 3건이었다. 자율 조회는 7/20에서 6/20으로 바뀌었고 두 시점 모두 조회가 0건이었다. [사전등록](../../protocols/pilots/tau-banking-result-feedback-v1.json) · [전체 결과와 원기록 식별자](../../artifacts/analyses/20261125-banking-result-feedback-results.json)

## 무엇을 비교했나

무기억 1회차 네 상담을 그대로 썼다. 각 상담의 같은 공개 대화·도구 기록에서 사실·경험·절차·교훈·자유 메모를 하나씩 새로 작성했다. 새 작성자에게 추가한 정보는 해당 원천의 공식 성공 여부 한 값이었다. 작성 지침, 공개 경험, 모델과 설정이 이전 실제 요청과 동일함을 20건 모두 확인했다. 작성자가 실패 원인이나 채점 정답을 받은 경우는 0건이었다. 20건 모두 비어 있지 않은 메모를 저장했다. [설계와 승인 범위](../research/banking-writer-outcome.md) · [기존 상담과 메모](../../artifacts/analyses/20261124-banking-required-results.json)

새 상담 40건은 독립된 세션과 새 초기 환경에서 같은 첫 고객 발화로 시작했다. 형식별 새 메모 하나를 두 전달 방식에서 공유했다. 과거 상담과의 짝은 과제·형식·전달 방식이 같다. 공식 채점 40/40건, 기술 결측 0건이었다. 2회차 무기억 추가 실행은 0건이었다. [배정과 입력 해시](../../artifacts/pilots/20261125-banking-result-feedback-preflight.json)

| 과제 | 1회차 무기억 | 자동 제공 성공, 기존 → 성패 제공 | 자율 조회 성공, 기존 → 성패 제공 |
| --- | --- | ---: | ---: |
| 001 개인 카드 추천·신청 | 실패 | 0/5 → 0/5 | 1/5 → 0/5 |
| 008 우편 판촉 확인·이관 | 성공 | 5/5 → 3/5 | 4/5 → 5/5 |
| 010 추천 보너스 조사·제출 | 실패 | 0/5 → 0/5 | 0/5 → 0/5 |
| 015 추천 링크 발급 | 실패 | 3/5 → 3/5 | 2/5 → 1/5 |
| **전체** | **1/4** | **8/20 → 6/20** | **7/20 → 6/20** |

자동 제공에서 전체 순감소 두 건은 008의 절차·교훈 메모에서 나왔다. 015는 사실 메모가 새로 성공하고 자유 메모가 실패로 바뀌어 과제 합계가 같았다. 자율 조회에서는 2건이 성공으로, 3건이 실패로 바뀌었다. 별도로, 새 상담과 공유된 무기억 1회차를 비교하면 자동 제공은 회복 3건·손실 2건, 자율 조회는 회복 1건·손실 0건이다. 독립된 원천은 네 개이고 두 피드백 조건은 다른 시점에 실행했다. ## 성패 정보가 어디까지 전달됐나

기존·새 메모 40개를 작성 조건과 후속 성패를 가린 채 한 명의 분석자(Codex)가 읽고, 판정의 근거 문장과 위치를 기록했다. 텍스트 자체에서 조건을 짐작할 수 있고 독립 판독자 간 일치도는 측정하지 않았다. [판독 원본](../../artifacts/analyses/20261125-banking-feedback-note-ratings.json) · [인용을 검증한 배정별 판독](../../artifacts/analyses/20261125-banking-feedback-note-review.json)

| 메모에 남은 내용 | 성패를 주지 않은 작성자 | 성패를 받은 작성자 |
| --- | ---: | ---: |
| 실패한 원천에서 해결되지 않은 점을 명시 | 15/15 | 15/15 |
| 성공한 008에서 이관의 적용 조건·범위를 명시 | 5/5 | 5/5 |
| 과제 전체의 공식 성공·실패를 명시 | 0/20 | 1/20 |

**001의 절차 메모**가 공식 결과를 명시한 유일한 새 메모였다. 카드 선택을 끝내지 못했고 사후 평가도 실패였으며 그 이유는 주어지지 않았다고 적었다. 이 문장이 자동 제공 상담원의 첫 실제 요청에 들어간 위치까지 확인했다. 기존·새 절차 메모를 받은 두 상담 모두 첫 검색식에 `Bronze Rewards Card`를 넣었고 공식 채점 기준을 충족한 카드 신청은 없었다. 같은 새 메모의 자율 조회 상담은 본문 노출 0건으로 실패했다. [작성자 성패 입력·저장 문장·첫 검색·채점 추적](../../artifacts/analyses/20261125-banking-feedback-decision-traces.json)

**008의 이관 실패 두 건**에서는 저장과 노출 다음 단계까지 확인할 수 있었다. 원래 성공 상담이 사용한 이관 사유를 기존·새 메모 각 5/5개가 보존했다. 새 절차·교훈 메모의 해당 문장은 두 상담 모두 실제 이관 요청 직전 모델 입력에 있었다. 당시 은행 문서도 두 사유를 함께 제시했다. 상담원은 고객이 확인할 수 없는 혜택을 계속 요구했다는 사유(`customer_demands_after_unavailable_offer_refusal`) 대신 외부 안내를 확인할 수 없다는 사유(`unconfirmed_external_communication`)로 각각 한 번 이관했다. 공식 채점은 사유 인수를 비교했고 두 건 모두 실패였다. 기존 절차·교훈 상담은 채점 사유로 적어도 한 번 이관했다. 이 자료에서 확인한 것은 기록된 선택이며, 모델이 어느 문장에 더 의존했는지는 알 수 없다. [두 이관의 원천·저장 문장·당시 은행 문서·실제 인수·공식 채점](../../artifacts/analyses/20261125-banking-feedback-decision-traces.json)

**010의 추천 보너스 조사**에서는 두 시점의 메모 모두 이관과 조사 종결을 구분했다. 새 메모 다섯 개 중 과제 전체 실패를 명시한 것은 없었다. 공식 본인확인 행동은 이전 7/10에서 새 상담 9/10으로 늘었지만, 고객의 추천 제출이 채점 기준과 일치한 상담은 두 시점 모두 0/10이었다. ## 실제 조회와 성공 상담의 효율

자동 제공은 20/20상담, 상담원 요청 233/233건에 본문이 들어갔다. 자율 조회는 20상담, 상담원 요청 267건에서 목록·본문 호출이 모두 0이었다. 자율 조회의 기존·새 첫 상담원 요청은 20쌍 전부 바이트가 같았는데 첫 검색 인수는 20쌍 모두 달랐다. 다섯 쌍은 최종 성패도 갈렸다. 자동 제공에서 첫 업무 행동의 차이는 도구 인수 변경 17쌍, 호출 여부 변경 3쌍이었다. 첫 판단 이후 고객은 각 상담원의 행동에 반응한다. [요청별 첫 행동과 노출 집계](../../artifacts/analyses/20261125-banking-result-feedback-results.json)

아래는 두 시점에 모두 성공한 같은 과제·형식의 상담만 짝지은 합계다. 비용은 상담에 사용된 금액이다. [짝별 효율과 분모](../../artifacts/analyses/20261125-banking-result-feedback-results.json)

| 지표 | 자동 제공 5쌍, 기존 → 성패 제공 | 자율 조회 4쌍, 기존 → 성패 제공 |
| --- | ---: | ---: |
| 은행 문서 검색 | 30 → 33 | 20 → 23 |
| 업무 도구 호출 | 45 → 42 | 32 → 32 |
| 고객 발화 | 44 → 42 | 41 → 34 |
| 상담 토큰 | 1,486,067 → 1,222,364 | 1,154,217 → 985,924 |
| 상담 비용 | $0.03045 → $0.02649 | $0.02286 → $0.02037 |

자동 제공 공동 성공 쌍에서는 토큰이 17.7% 줄었고 검색은 3회 늘었다. 메모를 열지 않은 자율 조회 공동 성공 쌍에서도 토큰이 14.6% 줄고 검색이 3회 늘었다. 이 소수의 성공 쌍으로 작성자 피드백의 비용 절감 효과를 추정하기는 어렵다.

## 비용과 재현

새 작성은 20요청에 $0.039229750, 새 상담은 744요청에 $0.146793684였다. 추가 비용은 $0.186023434, 이전 비용을 포함한 누적은 **$0.589813143 / $1.50**이며 미확정 비용은 0이다. 유료 실행 구현은 `738f88f`에서 고정했다. 두 체크아웃에서 결과 파일을 재계산해 바이트가 같은지 확인했다. 공식 보상 원본, 공급자 요청·응답, 메모 항목 버전에서 별도로 센 짝별 성공과 노출, 요청 수 및 비용도 일치했다. [승인 기록](../../artifacts/pilots/20261125-banking-result-feedback-authorization.json) · [은행 분석기](../../scripts/analyze_banking_memory.py)
