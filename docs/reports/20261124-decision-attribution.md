## 어떤 판단을 비교하는가

첫 공개 응답을 텍스트와 순서 있는 함수·인수로 비교하고, 어느 참여자가 먼저 달라졌는지 기록한다. 업무 호출은 두 단위로 센다. **같은 차례**에 고객에게 묻기와 예약 조회가 갈리면 즉시 행동이 달라졌다. **상담 전체의 호출 목록**에서 보면 양쪽의 첫 조회가 같은 예약일 수 있다. 함수 인수의 JSON 키 순서와 전송용 호출 ID는 정규화하고, 사업상의 식별자, 일괄 호출 순서, 도구 응답과 발행 호출의 연결은 보존한다. 텍스트가 달랐을 때 요청의 의미나 적절성은 판독 대상으로 남긴다. [공용 비교기](../../src/agent_memory_eval/analysis/decision_attribution.py)

같은 과제·설정·공개 이력에서 결정한 쌍에는 해당 요청의 제목·본문 노출 여부를 붙인다. 실제 입력 manifest와 원천 이벤트를 검증하고 동결한 항목 버전과 대조한다. 고객 발화·업무 도구 결과가 이미 달라졌거나 앞서 상담원 문구가 갈라진 뒤에는 후속 행동을 하류로 표시한다. 한쪽 상담이 먼저 끝나 대응 판단이 없는 경우와 공급자 실패로 응답을 잃은 경우도 구분한다. 같은 입력에서 서로 다른 행동이 나올 가능성은 남으므로 이 표시는 개별 선택의 원인을 확정하지 않는다. [기록 검증](../../src/agent_memory_eval/analysis/recorded_decisions.py) · [τ² 연결](../../src/agent_memory_eval/analysis/tau2_attribution.py)

## 고정 판단에서의 양성 대조

소매 462사례의 네 배정, 총 1,848건을 등록과 원기록에서 읽었다. 안내가 같은 실제·빈 은행 924쌍은 시작 요청의 바이트가 각각 같았다. 1,843건은 업무 응답에 도달했고, 4건은 사전 등록한 비공개 조회 한도에 도달했으며 1건은 공급자 오류였다. 조회 한도 네 건은 원래 정책 지표에서 실패로 집계하고, 업무 응답 간 비교에서는 관측 결측으로 남겼다. [기존 실험과 등록 지표](20261123-retail-conditional-retrieval.md)

고객이 지난 주문을 가리킨 조건부 안내의 77명·154쌍을 양성 대조로 삼았다. 메모를 연결한 쪽만 맞은 쌍 75건, 빈 은행 쪽만 맞은 쌍 3건, 양쪽 정답 31건, 양쪽 오답 45건이었다. 첫 업무 행동에서 목표 주문을 바로 조회한 비율 차이는 72/154, **+46.8%p**다. 두 업무 응답이 모두 있는 150쌍 중 실제 메모의 제목 또는 본문이 보인 것은 128쌍이었다. 이 값은 정해진 고객·은행·안내에서의 주문 선택 성과다. ## 전체 상담의 음성 대조

본문이 보인 55쌍에서 첫 번째로 달라진 **순서 있는 호출**이 같은 비교 가능 시점에서 발행된 경우는 0건이었다. 그러나 항공 0번의 경험 메모와 12번의 사실 메모에서는 1회차가 고객에게 물을 때 2회차가 예약을 바로 조회했다. 두 고객은 첫마디에서 각각의 예약 번호를 이미 말했다. 양쪽 모두 나중에 그 예약을 조회했고 공식 성패는 0번 양쪽 성공, 12번 양쪽 실패였다. 다른 시점의 판단 차이를 메모 덕분에 예약 번호를 알아냈다고 분류하면 근거가 과해진다. 미조회 선분기 68쌍 중 2쌍은 같은 시점의 이관 호출에서 요약 인수만 달랐다. 나머지 51쌍은 전체 호출 목록의 차이가 그 뒤에 나타났다. ## 두 번째 벤치와 의미 판독

고정한 BFCL V4의 실제 공개 과제 `simple_python_0`는 밑변 10, 높이 5인 삼각형의 면적을 묻는다. 이 입력에서 스크립트가 만든 응답으로 인수 키의 재배열, 높이 변경, 미등록 함수명 변경을 검사했다. 같은 비교기가 각각 동일 행동, 인수 변경, 함수 변경으로 판정했다. BFCL 모델 호출과 공식 채점은 0건이다. [BFCL 함수 응답 연결](../../src/agent_memory_eval/analysis/bfcl_decisions.py)

가림 판독용 파일에는 비교 가능한 상담원 선분기의 공동 공개 대화, 두 응답, 익명 쌍 ID를 담는다. 순서는 조건명과 독립적으로 정하고 실제 요청 ID와 대응 순서는 분석자 파일에 보관한다. 판독자는 먼저 두 응답이 같은 업무 요청인지, 다음 행동·순서·필수 조건이 달라졌는지 원문과 함께 기록한다. 이후 조건을 열어 관련 절차·교훈의 저장 문장과 판단 직전 입력을 대조한다. 이 보고서에서 자동으로 검증한 내용은 식별자의 등장과 구조화된 업무 호출이다. 절차·교훈에 대한 모집단의 의미 판정은 미실시다. [인용 및 버전 검증](../../src/agent_memory_eval/analysis/claim_evidence.py)

다음 벤치의 소규모 확인에서는 어떤 판단에 기억을 쓸 기회가 있는지, 어떤 공개 입력에서 정책을 짝지을지, 업무 행동·최종 점수·효율을 어느 분모로 읽을지 먼저 정한다. 미노출 때의 변동과 결측 처리, 규모를 늘릴 기준도 결과를 보기 전에 기록한다. 여기서 재현한 106 대 34는 분석기를 검산하는 값이다. 새 벤치의 효과 크기 기준은 그 벤치의 업무 목표에서 정한다. [공통 측정 명세](../research/metrics.md)

## 재현

가림 판독 자료에는 공동 공개 대화와 두 응답이 담긴 154쌍이 있다. 판독 뒤에 대조할 근거 파일에는 고정 주문 선택 154쌍과 전체 상담 배정 1,000건의 원요청 식별자·인용·노출·성패가 들어 있다. [가림 판독 자료](../../artifacts/analyses/20261124-decision-attribution/blinded.json) · [요청별 근거와 판독 대조표](../../artifacts/analyses/20261124-decision-attribution/evidence.json)

보관된 두 τ² 실행과 두 번 방문 원천·작성 기록, 고정 BFCL checkout이 있는 저장소에서 실행한다. 출력 인수를 생략하면 집계를 표준 출력에 쓴다. 쌍별 근거와 가림 판독 파일은 아래처럼 새 경로에 생성한다. 각 대조는 `--control fixed`, `--control full`, `--control bfcl`로 따로 실행할 수 있다.

```bash
audit_dir=$(mktemp -d)
uv run --offline --frozen --no-sync python -m scripts.audit_decision_attribution \
  --output "$audit_dir/summary.json" --details "$audit_dir/choices.json" \
  --blinded-review "$audit_dir/blinded.json"
cmp "$audit_dir/summary.json" artifacts/analyses/20261124-decision-attribution.json
cmp "$audit_dir/choices.json" artifacts/analyses/20261124-decision-attribution/evidence.json
cmp "$audit_dir/blinded.json" artifacts/analyses/20261124-decision-attribution/blinded.json
```
