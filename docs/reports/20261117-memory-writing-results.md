## 실행과 상태

airline 14번의 두 번째 반복에서 수집한 같은 공개 경험을 사용했다. `none`은 평가 결과를 받지 않았고, `result_only`는 이 경험의 `success: false`만 받았다. 각각 다섯 번, 새 writer 세션·빈 은행에서 선택적으로 `memory_store`를 호출했다. 작성 지침과 그 외 입력은 같았다.

| 조건 | 배정 | 정상 작성 | 저장 호출 없는 빈 작성 | 최종 기억 | API 응답 | 보고 비용 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 피드백 없음 | 5 | 4 | 1 | 4 | 9 | $0.003743650 |
| 실패 결과만 | 5 | 5 | 0 | 5 | 10 | $0.004519300 |
| 합계 | 10 | 9 | 1 | 9 | 19 | **$0.008262950** |

오류·생략·비용 미확인은 모두 0이었다. 승인된 전체 상한은 $1이며 새 source 수집·사용자 시뮬레이터·업무 도구·결정 재전송은 호출하지 않았다. 위 비용은 이번 작성 19요청의 provider 보고 사용량이다.

OpenRouter의 `openai/gpt-6-luna` → OpenAI 단일 경로를 사용했고 반환 모델은 `openai/gpt-6-luna-20260922`였다. reasoning low를 유지했으며 제공된 사용량의 reasoning 토큰 합계는 4,641이다. 추론 본문은 공개 작성 이력에 다시 넣지 않았다.

각 조건의 첫 요청은 다섯 번 모두 같은 hash였고, 조건 사이에서는 피드백 메시지만 달랐다. 같은 모델 seed 0에서도 서로 다른 기억과 빈 작성이 관측됐다. seed를 결정성이나 독립 난수의 보장으로 사용하지 않는다. 감사에 기록된 기억 입력 18구간은 **작성자가 자신이 쓴 내용을 다음 작성 요청에서 다시 본 구간**이다. 후속 업무 작업자의 조회·기억 활용으로 세지 않는다.

## 무엇을 남겼는가

조건을 가린 표시용 case를 먼저 읽고 주석을 저장한 뒤 매핑을 열었다. 평가 상태를 본문에 직접 쓰는 기억도 있어 완전한 눈가림은 아니며, 같은 분석 에이전트의 잠정 판단이다. [원 주석](../../artifacts/analyses/20261117-writing-10-content-annotations.json)은 독립 평가나 행동 효과 판정이 아니다.

| 내용 관측: 은행 단위 | 피드백 없음, 5개 | 실패 결과만, 5개 |
| --- | ---: | ---: |
| 수하물 필요량/허용량 구분을 명확히 서술 | 0 | 0 |
| 일반적인 수하물 제약 문구여서 구분이 불명확 | 1 | 0 |
| 6개 무료 허용량을 다시 서술 | 3 | 2 |
| 경로 해석의 모호함을 가설로 언급 | 3 | 4 |
| 일반적인 변경 전 확인 절차 언급 | 3 | 4 |

9개 기억은 주로 한 예약에 증서 한 장만 쓸 수 있다는 결제 제약, 금액 계산, 기존 세 구간을 유지한 경로 검색, 예약 전 확인 절차를 남겼다. 다수는 평가 결과가 없거나 실패 원인이 알려지지 않았다고 명시했다. 이런 내용 중에는 올바른 규칙도 있으므로 대상 수하물 교훈이 없다고 기억 전체를 무용하다고 판정하지 않는다.

W05는 실패 결과를 받았지만 “6 bags matched the regular-member business allowance”를 겉으로 일치하는 사항으로 기록했다. W09는 “don't add extras if not needed”라는 주의를 남기면서도 세 승객의 무료 수하물 여섯 개를 함께 적었다. 전자는 원래의 허용량 중심 판단을 강화할 가능성, 후자는 ‘추가 없음’과 실제 필요량을 다시 혼동할 가능성을 점검할 후보다. 어느 문장이 행동을 바꿨는지는 아직 측정하지 않았다.

경로 모호함을 다룬 기억 7개도 원인 진단의 정답으로 세지 않는다. 공개 대화에서 고객은 취소된 예약의 경로를 유지하라고 말했으므로, 다른 경로 해석이 타당한지는 별도 검토가 필요하다. 실패 boolean은 이 가설을 검증해 주지 않는다. 원천 예약·항공편 ID와 날짜를 자세히 남긴 W07도 관측했지만, 이 과제 특정 정보가 전이에서 실제 손해를 냈는지는 미확정이다.

## 공개 경험에 있던 정보의 한계

작성자가 본 대화에서 기존 작업자는 먼저 “Business class includes six checked bags”라고 설명했고, 사용자는 “no extra bags needed either”라고 답했다. 마지막 도구 호출은 `total_baggages=6`이었다. 공개 대화에는 수하물 0개가 필요하다는 직접적인 요구가 없었으며 사용자 시뮬레이터의 비공개 의도나 채점 정답은 writer 입력에 포함하지 않았다.

따라서 이번 결과를 ‘실패 결과를 줘도 모델이 올바른 정답을 배우지 못했다’고 단정할 수 없다. 결과 한 비트에는 원인을 고를 정보가 부족했다. 공개 정책·대화만으로도 실제 필요량을 확인해야 한다는 절차 점검은 가능하지만, 특정 정답 수량을 writer가 이미 알고 있었다고 가정해서는 안 된다.

이번 자료는 **경험에 어떤 근거가 있었는지 → 무엇이 기억으로 남았는지**를 점검할 수 있게 한다. 현재 병목 후보는 도구 연결보다 근거의 가용성과 교훈 선택에 있다. 이는 원인 가설이며, 추가 피드백과 재전송 개입으로 확인할 대상이다.

## 범위와 다음 확인

4/5와 5/5의 저장 차이는 작은 단일 source의 기술 통계다. 결과 피드백의 일반 효과나 업무 성공률 개선으로 해석하지 않는다. 과거 자연 실행의 자율 저장 0/1·조회 0/15와도 설정이 다르다. 이번에는 명시적인 별도 사후 검토 지침과 저장 도구를 주었고 조회는 새로 측정하지 않았다.

빈 snapshot을 포함한 10개 모두 후속 입력 크기 검사에 통과했다. 이는 내용의 유용성이나 실제 노출을 뜻하지 않는다. 다음에는 기존 기억을 빈 기억·일반 주의 메모와 비교하고, 원래 옳았던 상태까지 포함해 교정과 훼손을 함께 측정한다. 별도 비평을 추가한다면 공개 정책·대화에서 필요한 수량 확인이 빠졌다는 근거와 작성자의 정보 접근 범위를 명시한다. 정답 0개를 몰래 보충하지 않는다. 새 유료 재전송·비평 작성은 이번 실행에 포함하지 않았다.
