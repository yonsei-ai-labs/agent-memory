# 은행 94개 과제 기억 비교의 실행 준비

첫 배정은 기존 은행 45개 과제에서 기억 작성 225건과 2회차 전체 상담 450건이다. 45개 과제 각각에서 가장 먼저 공식 채점된 1회차 한 건을 택했다. 성패, 지정 문서 검색 결과, 대화 길이는 선정에 쓰지 않았다. 선택된 45건의 공식 성적은 성공 8건·실패 37건이고, 43건에서 지정 문서가 첫 입력 이후의 공개 도구 결과에 들어왔다. 각 상담의 기억 은행에는 자기 원천의 한 형식만 들어간다. 여러 과제의 기억 가운데 알맞은 경험을 골라내는 능력은 별도 비교가 필요하다. 450건은 전체 최대 2,760건에 포함된다. 97개 공식 과제에서 확인용 고객과 같은 사람일 수 있는 두 과제와 별도 자연어 채점이 필요한 한 과제를 제외했다. 등록된 94개 중 과거 081번은 세 원천 모두 첫 업무 판단 전에 종료돼 기억 비교가 가능한 과제는 최대 93개다. 개발과 별도로 확인용 16개 과제의 고객 11명을 유지한다. 과제마다 원천과 열 개 조건을 공유하므로 상담 2,760회와 독립 고객 수는 서로 다른 분모다. [전체 등록과 분석 단위](../../protocols/pilots/tau-banking-memory-cohort-v1.json)

### 돈을 쓰기 전에 확인한 것

- 이전 1회차 138건 중 공식 성적과 공개 경험을 복원한 132건이 작성 대상이다. 다섯 형식으로 구성한 작성 입력 660개의 크기는 23,708~261,056바이트였다. 작성자는 원천의 공개 대화·업무 도구 결과와 공식 성패 한 비트를 받는다. 목표 문서 목록, 모범 행동, 비공개 고객 대본은 분석 자료에 둔다. 132건 중 126건에서 과제 지정 문서가 1회차 검색 결과에 등장했다. 작성자가 그 내용을 선택하는지와 선택한 내용이 다음 업무 판단에 도움이 되는지는 유료 실험에서 관측한다. [원천 결과](../../artifacts/analyses/20261127-banking-source-screen-results.json) · [작성 지침](../../protocols/instructions/required-experience-writer-v1.txt)
- 보관된 은행 상담 40건을 새 판독기로 읽어 공식 성공을 자동 제공 8/20, 자율 조회 7/20으로 재현했다. 실제 작업자 입력에 기억 본문이 들어간 상담은 각각 20/20, 0/20이었다. 각 결과는 원천·작성자·스냅샷·공식 보고서·비용에 연결된다. [보관 결과](../../artifacts/analyses/20261124-banking-required-results.json) · [원기록 대조 테스트](../../tests/test_banking_memory.py)
- 네이티브 은행 환경과 모의 모델 응답으로 새 자율 조회 조건의 한 경로를 확인했다. 작업자의 첫 질문과 시스템 메시지는 해당 1회차와 같다. 검색 용도는 목록·본문 도구 설명에만 있다. 모의 작업자가 조회를 선택한 다섯 상담에서 첫 입력 본문 노출은 0건, 이후 본문 노출은 5건이었고 공식 채점까지 이어졌다. 실제 은행 모델이 검색을 선택하는 빈도는 아직 관측되지 않았다. [조회 설명 원문](../../protocols/diagnostics/bfcl-tool-only-retrieval-v1.json) · [네이티브 연결 검증](../../tests/test_banking_memory.py)

### 450건을 마친 뒤 판단할 것

확대 권고 기준은 전달 방식별 공식 채점률 90% 이상, 첫 요청이 전송된 자동 제공 상담 전부에서 첫 입력에 본문 노출, 자율 조회 본문이 실제 입력에 들어간 과제 5개 이상이다. 다섯 과제는 소수 사례의 반복에 확대 예산을 쓰는 것을 피하기 위해 정한 운영 목표다. 정책의 유용성은 과제·고객별 빈도와 짝비교로 따로 읽는다. 공식 성공률 증감의 방향은 확대 기준에 쓰지 않는다. 자율 조회가 0이면 자동 제공 결과와 도구를 허용한 정책 성과를 보고하고, 조회 정책의 보완 여부를 결정한다. [사전 판정과 비용 분리](../../protocols/pilots/tau-banking-memory-cohort-v1.json)

각 형식은 자기 1회차와 연결해 회복·악화 및 공동 성공 쌍의 토큰·요금·업무 호출을 센다. 자동 제공과 자율 조회의 비용과 성패도 같은 기억끼리 짝짓는다. 회차 간 효율에는 저장된 첫 고객 발화를 재생해 절약된 고객 모델 호출 한 번도 포함된다. 두 전달 방식끼리의 효율 비교는 양쪽 모두 같은 재생을 쓴다. 효과 표는 기억을 배정할 수 있었던 원천을 대상으로 하고 과거 미채점 6건은 별도로 제시한다. 개발·확인 고객의 효과를 따로 보고한다. [채점 코드](../../src/agent_memory_eval/adapters/banking_memory_cohort.py)

최근 138건의 1회차와 이전 필수 작성 단가를 기준으로 첫 450건과 작성 225건은 약 $4.5~4.7로 예상한다. 첫 구간의 제안 상한은 $7이다. 전체 비용 약 $30에는 이 구간이 포함된다. 전송 길이, 캐시, 공급자 실패와 보류액에 따라 실제 금액은 달라진다. [1회차 비용](../reports/20261127-banking-source-screen.md) · [이전 작성·상담 비용](../../artifacts/analyses/20261124-banking-required-results.json)

원천·배정 재계산과 보관 기록 검산은 다음 명령으로 실행한다. 모의 응답을 사용한 테스트까지 포함하며 유료 모델 호출은 발생하지 않는다.
