# 주문번호가 없을 때 조건부 안내는 자율 기억 조회를 늘렸다

고객이 “지난번 그 주문”이라고만 했을 때, 상담원이 첫 업무 행동으로 맞는 주문 하나를 조회한 비율은 기존 안내와 실제 메모에서 **35/154건(22.7%)**, 조건부 안내와 같은 메모에서 **106/154건(68.8%)**이었다. 조건부 안내는 어느 주문인지 불명확하면 고객에게 되묻기 전에 지난 메모를 찾아볼 수 있다는 한 문장을 추가했다. 같은 안내에 빈 메모를 연결하면 정답은 **34/154건(22.1%)**이었다. 고객이 현재 주문번호를 알려 준 경우에는 네 조건 모두 해당 주문을 바로 열었고 기억 조회는 0건이었다. [사전 설계](../research/retail-conditional-retrieval-v1.md) · [배정별 결과](../../artifacts/analyses/20261123-retail-conditional-retrieval-results.json)

## 지난 주문을 알아내는 첫 행동

이전 소매 재방문 실험의 고객 77명, 고객마다 서로 다른 과거 주문 이력 두 개, 당시 작성한 메모를 그대로 사용했다. 같은 고객의 두 이력은 재방문 화면과 현재 대화가 같고 지난 주문이 다르다. 상담원 모델은 이전과 같은 `openai/gpt-6-luna`였다. 매 배정은 새 세션에서 본인확인과 주문 목록 조회를 마친 상태로 시작했다. 네 조건 모두 기억 도구가 열려 있었고, 같은 안내에서 실제 메모와 빈 메모의 첫 입력은 같았다. [고정 배정과 입력 검산](../../artifacts/analyses/20261123-retail-conditional-retrieval-preflight.json)

| 상담원 안내 | 연결한 메모 | 첫 응답에서 기억 조회 요청 | 첫 업무 행동으로 목표 주문만 조회 | 목표 주문 조회율 | 모델 요청 수 |
| --- | --- | ---: | ---: | ---: | ---: |
| 기존 | 실제 | 0/154 | 35/154 | 22.7% | 154 |
| 기존 | 빈 메모 | 0/153 | 30/153 | 19.6% | 154 |
| 조건부 | 실제 | 136/154 | 106/154 | 68.8% | 448 |
| 조건부 | 빈 메모 | 129/154 | 34/154 | 22.1% | 284 |

표의 분모는 관측한 배정 수다. 기존 안내·빈 메모에서 공급자 HTTP 520으로 1건의 응답을 받지 못했다. 조건부 안내·실제 메모에서 메모만 네 번 읽고 첫 업무 행동에 도달하지 않은 4건은 사전 규칙에 따라 0점으로 포함했다. 이번 응답에서는 기억 도구까지 포함해 호출이 정확히 하나여야 하는 엄격한 채점도 같은 정답 수를 냈다.

**사전 등록한 주 비교는 +42.2%p였다.** 지난 주문을 지칭한 같은 사례에서 조건부 안내가 만든 ‘실제 메모와 빈 메모의 정답률 차이’가 기존 안내의 같은 차이보다 얼마나 큰지 계산했다. 네 조건을 모두 관측한 153/154사례를 고객 안에서 먼저 평균했다. 고객 77명 중 이 차이가 양수인 사람은 47명, 동률은 27명, 음수는 3명이었다. 고정된 메모로 고객을 10,000번 재표집한 95% 구간은 **+31.2∼+53.2%p**다. 154사례 전부에서 결측을 0 또는 1로 둔 경계는 **+43.5∼+44.2%p**였다. 경계 계산에서는 결측 고객의 두 이력이 모두 같은 비중을 받고, 관측값 추정에서는 그 고객의 완전한 이력 하나가 고객 전체를 대표한다. ## 메모를 읽고 어느 주문을 골랐는가

조건부 안내·실제 메모의 154건 중 첫 업무 행동을 만드는 입력에 과거 메모 제목이 들어간 배정은 128건, 본문까지 들어간 배정은 127건이었다. 정답 106건 중 **101건**에서 제목과 본문이 행동 전에 실제 모델 입력에 들어갔고, 그중 **91건**에는 목표 주문번호도 있었다. 빈 메모에서도 상담원은 129번 조회를 요청했지만 받은 항목은 0개였다. 같은 조건부 안내에서 실제 메모를 연결한 효과는 **+46.8%p**였다. [요청별 입력 노출과 업무 행동 판정](../../scripts/analyze_retail_conditional_retrieval.py)

보조적으로 두 과거 이력의 목표가 바뀔 때 같은 고객에서 둘 다 맞힌 경우도 셌다. 조건부 안내·실제 메모에서는 **37/77명**이 같은 재방문 대화에서 서로 다른 두 목표 주문을 각각 바로 열었다. 기존 안내·실제 메모와 조건부 안내·빈 메모에서는 각각 0/77명, 기존 안내·빈 메모에서는 두 이력이 모두 관측된 76명 중 0명이었다. 이 집계는 사전 등록한 주 비교를 보충한다. [개별 배정의 고객·원천·첫 행동](../../artifacts/analyses/20261123-retail-conditional-retrieval-results.json)

## 현재 주문번호를 말했을 때와 다음 단계

현재 번호가 지난번과 같은 요청 616건과 다른 요청 616건에서 네 조건 모두 목표 주문만 바로 조회했다. 기억 도구 요청은 1,232건 중 0건이었다. 현재 번호가 달라진 경우 옛 주문을 열거나 주문 변경을 시도한 첫 행동도 0건이었다. 실제 메모에서 조건부 안내가 기억 조회를 늘린 폭은 지난 주문을 지칭할 때 +88.3%p, 번호를 명시한 두 유형에서 각각 0%p였다. 옛 주문 조회 증가폭의 결측 경계는 0∼0%p였고 관측 고객 77명 전원이 동률이었다. 전원 동률이어서 고객 재표집 구간도 0∼0%p로 고정된다. 새 고객에서 드문 오선택이 얼마나 발생하는지는 별도로 확인할 문제다.

사전에 정한 전체 상담 진행 기준을 모두 충족했다. **후속 확인 대상으로 정해 둔 26명에서 첫 업무 판단을 저장한 622건**이 있다. 원래 배정은 624건이고 나머지 2건은 메모만 네 번 조회하고 끝났다. 다음 단계에서 확인할 결과는 첫 판단 이후 고객이 주문을 다시 알려 줘야 했는지, 잘못된 취소를 제안했는지, 현재 동의를 받아 맞는 주문을 취소했는지와 상담 비용이다. 이번 실험의 관측 범위는 기존 고객·저장 메모와 이 상담원 모델의 첫 판단까지다. ## 비용과 재현

구현 커밋 `c6f3efb`에서 1,848개 배정을 전부 시도해 1,847개를 채점했다. 원천 상담과 작성은 기존 기록을 사용했다. 새 작업자 요청 2,272건 중 2,271건의 요금 합계는 **$0.159150895**, 미확정 1건의 최대 보류액은 **$0.007139750**이었다. 두 금액의 합계는 $0.166290645로 승인된 $4 이내다. 지난 주문을 지칭한 154건의 첫 판단에 실제 메모와 기존 안내로 154요청·$0.012015155, 같은 메모와 조건부 안내로 448요청·$0.035661965가 들었다. [조건별 사용량과 원장 감사](../../artifacts/analyses/20261123-retail-conditional-retrieval-results.json)

채점기를 사용하지 않는 별도 집계에서 고유 세션 1,848개를 확인했다. 조건부 문장을 원복한 각 첫 요청은 해당 사례의 이전 요청과 일치했다. 원응답의 도구명과 주문번호, 응답을 생성한 입력의 메모 제목·본문을 다시 읽어 배정별 점수와 고객별 주 비교를 대조했다. 공식 분석기를 두 번 실행한 결과 파일도 바이트 단위로 일치했다. 원본은 로컬 `runs/`에 있고, 개별 점수와 비교값은 Git의 결과 파일에 있다. 아래 명령은 원본이 있는 저장소에서 모델 호출 없이 공개 결과를 다시 만든다.

```bash
retrieval_check=$(mktemp -d)
uv run --frozen --no-sync python -m scripts.analyze_retail_conditional_retrieval \
  --run runs/tau2-retail-conditional-retrieval-01 --output "$retrieval_check/results.json"
cmp "$retrieval_check/results.json" artifacts/analyses/20261123-retail-conditional-retrieval-results.json
```
