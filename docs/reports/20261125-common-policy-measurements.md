## 다음 판단을 고를 공개 근거

각 지점의 무기억 관측은 한 번이다. 017의 첫 응답은 고객에게 보내는 텍스트였고 첫 검색은 상담원의 여섯 번째 요청에서 나왔다. 당시 첫 검색과 공개 원천의 상품명만 넣은 검색을 고정된 공식 검색기에서 따로 실행했다. 두 검색 모두 상위 10건에 기존 사후 진단에서 지정한 세 문서(분쟁 처리, 해당 상품 기본 혜택, 추가 혜택)가 하나도 없었다. 원래 검색의 결과 순서와 해시는 보관본과 같았다. 상품명 보존은 확인됐고, 상품명 그대로의 검색만으로 해당 문서를 얻을 수 있다는 가정은 이 지점에서 성립하지 않았다. 모델이 다른 검색식이나 업무 도구를 선택할 가능성은 열려 있다. [단서·검색식·문서 순위](../../artifacts/analyses/20261125-common-policy-measurements.json)

개발용 양성 대조는 015의 `get_referral_link`에서 시작할 수 있다. 이 도구명은 무기억 원천의 공개 문서에 있었고 사실·경험 메모에 남았으며 두 자동 제공 상담의 첫 검색식에도 들어갔다. 고유 도구명만 공식 검색기에 넣으면 결과가 한 건이고 해당 과제의 지정 문서였다. 이후 공식 상담 성패는 경험 메모에서 성공, 사실 메모에서 실패였다. 단서가 첫 업무 행동까지 이어져도 최종 성공은 달라질 수 있다. 015는 이미 본 개발 사례다. 다음 확인 실험은 같은 판단에 도움 되는 공개 단서와 도달 가능한 문서를 갖춘 **다른 고객**을 고르고, 016·002 같은 낡은 정보와 중복 정보도 함께 비교한다. ## 저장소 밖 설치와 BFCL 고유 기억 도구

소스 배포본에서 wheel을 만들고 새 가상환경에 설치한 뒤 저장소 밖에서 실행했다. wheel에 들어간 JSON 스키마 35개의 바이트를 원본과 대조했다. 고정 BFCL `6ea5797`의 `rec_sum` 백엔드에서 선행 공개 발화의 이름을 `memory_append`로 저장하고 공식 체크포인트를 새 인스턴스에 복원했다. 두 읽기 조건의 첫 업무 입력은 같은 바이트였다. 허용한 쪽은 `memory_retrieve`로 읽은 버전의 본문 1개가 다음 요청에 포함됐고, 접근을 차단한 쪽은 0개였다. 받은 도구 반환으로 답하는 스크립트는 공식 채점에서 각각 성공·실패했다. 양쪽 모두 작성자·상담원은 오프라인 스크립트였다. 이 한 과제로 확인한 범위는 두 고유 연산, 입력 출처, 공식 채점까지의 연결이다. ## 재현

은행 결과는 서로 다른 해시 시드에서 세 번 재계산해 파일 바이트가 일치했다. 기존 은행 진단과 기존 벤치 호환성 v1도 보관본과 일치했다. 기본 검증 세 가지와 전체 테스트 630개가 통과했다. 전체 검사 시작 후 추가한 6개를 포함해 관련 테스트 22개를 최종 코드에서 다시 실행해 모두 통과했다.

은행 명령은 보관된 원천·메모·상담 원장과 같은 버전의 은행 데이터를 읽는다. BFCL 명령에는 고정 체크아웃과 그 코드가 사용하는 `overrides==7.7.0`, `filelock==3.20.0`이 필요하다. 각 출력 위치에는 새 이름을 사용한다.

```bash
uv run python -m scripts.analyze_banking_policy_cycle common-measurements --output /tmp/banking-common.json
uv run python -m unittest discover -s tests -p test_common_measurements.py
uv run python -m scripts.review_banking_evidence --reviewer-only --output /tmp/banking-reviewer
python -m agent_memory_eval.runner.bfcl_memory_check --checkout /path/to/bfcl-6ea5797 --recording /tmp/bfcl-native-control
```

판독자에게는 위에서 생성한 `inputs.json`만 전달한다. 봉인 명령은 판독자가 작성한 평정 파일과 각 판독 항목의 조건 추측을 읽는다. 추측 파일은 공개 `packet_id`를 키로 하고 `preload`, `on_demand`, 보류(`null`) 중 하나를 값으로 갖는다. 최초 봉인 파일이나 해시는 판독자가 따로 보관한다. 마지막 명령은 분석자 환경에서만 실행한다.

```bash
python -m agent_memory_eval.analysis.blind_review --bundle inputs.json --ratings ratings.json --guesses guesses.json --output sealed.json
uv run python -m scripts.review_banking_evidence --sealed-review sealed.json --output /tmp/banking-blinding-check.json
```

두 독립 판독본이 있으면 분석 명령에 `--second-sealed-review second.json`을 추가한다. 같은 원응답을 두 모델 평정에 재사용하면 검증이 실패한다. 결과에는 공통 판독 수, 각 축의 일치·불일치 및 양쪽 모두 결정을 내린 항목 수가 들어간다.
