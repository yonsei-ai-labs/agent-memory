# 작성 기억의 네 조건 한 응답 배치

2026-11-18 · τ² 항공 예약 개발 자료

Luna가 과거 경험에서 작성한 기억을 같은 예약 결정에 넣었을 때 다음 응답이 어떻게 달라지는지 비교하는 실행 경로다. 빈 기억·일반 주의 메모·모델 작성 기억·연구자 메모를 같은 형식으로 제공한다. 작성 원본과 결정 직전 입력을 재구성하고, 전송 직전의 바이트·실제 응답·기억 노출·비용을 연결한다. [실제 작성 결과](../reports/20261117-memory-writing-results.md)와 [한 응답 실행 API](snapshot-replay-runtime.md)를 사용한다.

## 실제 원본으로 확인한 범위

| 항목 | 재검증 결과 |
| --- | --- |
| 작성 기억 | 작성 배정 10개, 본문이 있는 작성 9개, 빈 작성 1개 |
| 로컬 입력 은행 | 작성 은행 10개와 통제 은행 3개, 총 13개 |
| 결정 | 14·2, 14·1, 23·2, 23·1의 첫 예약. 같은 개발 고객과 연결된 네 상태 |
| 한 반복의 대응 관계 | 결정 4개 × 작성 배정 10개 × 조건 4개 = 160행. 각 결정의 요청 본문은 12종 |
| 요청 크기 | 36,807~46,360바이트. 원래 모델 시드는 첫 반복 0, 두 번째 반복 1 |
| 과거 작성 비용 | 작성 요청 19회, 제공자가 보고한 합계 0.008262950달러, 비용 미확인 0회 |
| 이번 확인 | 원본 자료로 입력을 재구성하고 별도 프로세스에서 감사. 새 모델·카탈로그 호출 0회 |

각 결정에서 9개의 작성 본문은 각각 1행, 일반 메모와 연구자 메모는 각각 10행, 빈 입력은 11행에 대응한다. 마지막 11행에는 모델이 실제로 빈 기억을 남긴 배정이 포함된다. 한 반복은 48개 요청으로 모든 조건을 덮는다. 반복 수와 유료 예산은 미정이다. [배치 초안](../../protocols/drafts/tau2-written-memory-batch-v1.json)

## 배정과 감사

같은 결정·같은 반복 안에서 원래 대화, 도구, 파라미터, 기억까지 바이트가 같은 요청은 한 번 전송한다. 입력이 같은 모든 행에 그 전송의 식별자를 연결한다. 작성 배정별 피드백·반복·작성 상태·원본 및 로컬 snapshot 식별자를 보존한다. 각 반복 안의 요청 순서만 별도 배정 시드로 섞는다. 반복은 같은 모델 시드를 유지한 재전송이며 난수 시드 수나 독립 고객 수의 증가를 뜻하지 않는다.

원본 작성 로그와 영구 item 버전, 작성 시점의 공개 문맥, 열 배정의 완료 상태와 비용을 검증한다. 통제 메모에는 내용으로부터 정한 버전을 부여하고, 작성자와 정보 접근 이력은 분석 자료에 둔다. 스테이징은 각 은행을 봉인한다. 실행에서는 한 요청마다 은행을 복제하고 새 세션을 열며, 파일 게이트웨이가 실제 전송한 입력에서 제목과 본문이 포함된 위치를 남긴다.

실제 준비 자료에서는 실행기가 읽는 13개 은행을 네 결정에 각각 적용해 52개 조합을 만들었다. 160개 대응 행 모두에서 그 바이트가 준비 파일 48개의 해당 본문과 일치했다. 빈 작성과 빈 통제는 네 결정에서 각각 동일한 바이트를 만들었다. 원본 폴더 접근과 쓰기를 막은 별도 감사에서도 같은 대응표가 나왔다.

결과의 `distinct_inputs`는 전송 배정당 한 행이다. `allocations`는 작성 배정 × 결정 × 조건 × 반복당 한 행으로 같은 전송에 대한 참조를 공유한다. `representative`는 전송에 지정한 로컬 은행을 표시한다. 여러 배치의 자료를 합칠 때는 `experiment_id`와 `run_id`로 전송을 식별한다. 사용량 합계는 개별 전송에서 계산하고 기존 작성 비용은 따로 기록한다. 정상 응답에 공개 근거 검사를 적용한다. 확인 질문·조회에 해당할 수 있는 `no_target_write`는 별도 의미 판정을 기다리며, 잘린 응답은 오류로 남긴다. 업무 도구 실행과 공식 에피소드 성공은 별도 실험에서 측정한다.

비용 미확인·응답 오류·한도 도달 시 남은 배정을 순서대로 생략하고, 그 배정에 속한 논리 행도 보존한다. 전송 전 비용 예약 거절과 실제 제출은 별도 수치다. 마지막 요청에서 오류가 나면 생략 수가 0이어도 중단이다. 종료 기록이 빠진 배치는 감사에서 미완료로 검출한다. [행동 검사](../../tests/test_written_replay_batch.py)

## 재현 명령

v2 준비물이 없는 환경에서는 먼저 [준비 명령](written-comparison-validity.md)을 실행한다. 원본 실행 두 개와 준비물이 있는 환경에서는 아래 명령으로 새 입력 journal을 생성한다.

```bash
uv run --frozen python scripts/run_written_replay_batch.py --stage \
  --preparation outputs/written-memory-validity-20261117-01 \
  --output outputs/NEW_WRITTEN_REPLAY_STAGE
uv run --frozen python scripts/run_written_replay_batch.py --audit-only \
  --config protocols/drafts/tau2-written-memory-batch-v1.json \
  --output outputs/NEW_WRITTEN_REPLAY_STAGE
```

`--preflight`는 임시 폴더를 사용한다. `--audit-only`는 지정한 journal과 로컬 구현만 읽는다. `--config`를 제공하면 외부 프로필과도 대조한다. `--details`는 준비 단계에서 48개 입력과 160개 배정의 출처 대응표를, 전송 후에는 개별 응답과 생략을 포함한 대응표를 출력한다. 실제 개발 자료의 검증 기록에 이번 journal과 원본 해시를 남겼다. [검증 기록](../../artifacts/analyses/20261118-written-replay-batch-validation.json)

## 후속 실측의 해석

다음 유료 실행은 별도 ready 프로필에 1차 비교·분석 계획, 독립 검토자의 사례 판정과 두 통제 메모의 정보 접근 검토, 반복·은행·입력·시간·비용 한도와 승인을 기록한다. 실행기는 해당 프로필에서 원본과 입력 적합성을 먼저 검사하고, 제공 경로와 깨끗한 구현 commit, 배정 순서를 첫 요청 전에 고정한다. 케이스 근거와 검토자의 독립성 선언은 원문에 연결되며, 의미 판정의 타당성은 검토자가 책임진다.

현재 사례로 확인할 수 있는 것은 같은 예약 상태에서 기억을 시작부터 제공했을 때 다음 응답의 공개 수량·증서 판단이 달라지는지다. 예를 들어 14·2에서 고객의 필요 수량은 공개 대화로 확정할 수 없고, 23·2의 증서 한 장 제한은 이미 현재 정책에 있다. 성공했던 상태에서 새 위반이 생기는지도 같은 비중으로 남긴다. 이후 원경험·단순 요약 대조, 과거에만 있는 정보의 자율 조회, 후속 에피소드의 성공·회귀 및 전체 비용은 [연구 계획](../research/plan.md)에 따라 별도로 관측한다.

독립 검토에 넘길 1차 비교 후보는 23·2에서 모델 작성 기억과 빈 기억을 제공했을 때 예약당 증서 수 위반이 재발하는지다. 같은 결제 규칙을 지켰던 23·1에서는 새 위반이 생기는지도 짝지어 살핀다. 예약 제안, 확인 질문, 다른 도구 호출, 부분 응답, 미시작을 각각 남긴다. 14·2에서는 필요 수량을 확인하는 질문의 여부를 공개 대화로 심사할 수 있다. 이 비교안은 아직 실행 프로필에서 확정하지 않았다.
