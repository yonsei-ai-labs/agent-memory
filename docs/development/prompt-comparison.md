# 같은 저장 형식의 작성 프롬프트를 비교하는 방법

실험 설정의 `conditions`에 기준 조건과 비교 조건을 순서대로 적는다. 각 조건의 `id`는 배정과 분석에 쓰이며 모델에게 제공하는 내용은 공통 작성 지침과 `prompt` 원문이다. 같은 `representation`을 여러 조건에 사용할 수 있다. `prompt_version`과 조합한 전체 프롬프트의 SHA-256으로 실제 전송된 버전을 확인한다. `task_sets`는 개발과 평가에 사용할 과제, `seed_pairs`는 반복별 작성·수행 시드를 지정한다. [사용 가능한 실험 설정 예](../../protocols/pilots/tau2-fact-recheck-v1.json)

저장소 루트에서 다음 명령으로 공개 원천, 순서, 작성 요청 크기, native 환경, 한도와 두 지침을 확인한다.

```bash
uv run python scripts/run_prompt_comparison.py protocols/pilots/tau2-fact-recheck-v1.json --preflight
```

실행할 설정을 `ready`로 고정한 뒤 깨끗한 구현 checkout에서 `--live`를 사용한다. `--workspace`로 첫 실행 원본과 새 실행의 저장소를 지정할 수 있다. 설정의 이름마다 새 `runs/<name>`을 만들며 실행 명세, 실제 모델·단가·구현 commit, 배정 및 개별 원본을 보존한다. 제출된 요청의 청구액이 확인되지 않으면 이후 전송을 중단한다. 이미 제출된 호출은 재전송하지 않는다.

## 첫 실험에서 미리 정한 비교

두 조건은 같은 사실 저장 형식과 공통 지침을 쓴다. B만 해당 경험에서 관측한 값 중 다음 수행 때 재확인할 값을 표시하도록 한 문장을 더한다. 작성된 기억 전체를 시작에 제공하고 각 배정은 새 고객 대화와 초기 DB로 끝까지 수행한다. 빈 작성도 배정대로 평가한다. 개발 과제는 17·20번이다. 기존 상세 사례의 고객 그룹을 제외한 뒤 설정에 적은 해시 순서로 g03·g05를 선정해 각 그룹의 첫 과제인 3·5번을 전향적 평가에 쓴다. 이 평가 과제도 과거 실험에 포함된 적이 있다. 네 과제에 두 번씩 독립 작성·수행하며 2회차에는 순수 무기억과 빈 메모 대조도 배정한다. 모델과 역할별 설정, 읽기 한도, 채점은 기존 두 회차 실험과 같다.

주 비교는 **평가 과제에서 같은 과제·반복의 A와 B가 모두 공식 채점된 쌍**이다. B의 성공 획득·손실, 둘 다 성공·둘 다 실패, 결측을 각각 세고 과제별로 평균한 성공률 차이를 표시한다. 개발 과제와 1회차의 성적별 전환도 따로 읽는다. 작성·수행 비용, 빈 작성, 실제로 받은 제목과 본문을 함께 확인한다. 17·20번에서는 작성물이 재확인할 값을 지목했는지와 2회차 작업자가 기준일·여행일을 어떻게 판단했는지를 공개 발화·예약 행동에 연결한다. 이 사례에 대한 해석은 부수 진단이며, 사후에 본 개별 문장이 행동을 유발했다고 확정하지 않는다.

## 봉인한 기억으로 조회 방식 비교

두 번째 설정은 첫 실행의 완료 기록과 설정 해시를 대조하고, 원래 작성 세션에서 봉인한 항목·버전을 과제와 반복별로 가져온다. 각 은행마다 본문 시작 제공과 선택적 목록·본문 조회를 새 에피소드에 교차 배정한다. 두 읽기 조건은 같은 안내와 native 업무 경로를 쓰고, 목록 조회 제목과 본문 조회 내용을 별도로 기록한다. 첫 실험에서 이미 푼 에피소드는 이 비교에서 다시 쓰지 않는다. 두 실행이 첫 설정의 총 금액·시간·요청 한도를 공유한다. 주 비교는 별도 평가 과제에서 같은 은행을 시작 제공했을 때와 자율 조회했을 때의 공식 성적이며, 목록·본문이 실제로 입력에 도달한 실행 수도 함께 본다. [조회 비교 설정](../../protocols/pilots/tau2-fact-recheck-delivery-v1.json)

```bash
uv run python scripts/run_prompt_comparison.py protocols/pilots/tau2-fact-recheck-delivery-v1.json --preflight
uv run python scripts/report_prompt_comparison.py runs/tau2-fact-recheck-01 outputs/fact-writing-report
uv run python scripts/report_prompt_comparison.py runs/tau2-fact-recheck-delivery-01 outputs/fact-delivery-report
```

생성된 폴더의 `index.md`에서 과제·반복·조건 쌍을 선택한다. 각 실행의 원래 작성 지침·메모·공개 경험, 요청별 실제 제목·본문 노출과 응답, 고객 대화·도구 인수·공식 채점을 확인할 수 있다. `summary.json`에는 배정과 결측을 포함한 비교별 분모, 1회차 성공 여부별 전환, 읽기 행동, 역할·조건별 비용이 있다. 원본 디렉터리와 보고서의 상대 위치를 유지하면 원문 링크가 보존된다. 과거 네 형태의 합산 실행도 같은 보고서로 읽을 수 있으며, `--annotations`로 기존 가림 판정을 주면 양쪽 원문과 인용을 대조한다.

공식 점수가 갈린 쌍에서는 **최종 DB와 필수 안내 중 어느 항목이 달랐는지** 먼저 볼 수 있다. 채점기가 특정 작업자 발화를 인용한 경우 해당 발화로 연결한다. 필수 안내가 실패하면 두 실행의 원문을 나란히 열어 표현 차이도 살펴볼 수 있다. 사후 진단과 공식 점수를 함께 읽는 예는 [재확인 실험 보고서](../reports/20261118-fact-recheck-results.md)에 있다.
