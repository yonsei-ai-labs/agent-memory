# 첫 구현 작업: 오프라인 공통 코어

2026-11-14 · 상세 설계를 실제 동작으로 연결하는 첫 작업 명세

**모델 API·벤치 다운로드 없이 저장→snapshot→새 세션 조회→기록→합성 결과 재계산을 연결한다.** 연구 범위와 벤치 지원 목표는 [연구 계획](../research/plan.md)·[전체 개발 계획](roadmap.md)을 유지한다. 이 문서는 첫 구현의 의존성과 완료 근거를 정한다.

## 작업 순서와 산출물

| 순서 | 구현 위치 | 산출물과 확인할 동작 |
| --- | --- | --- |
| 1 | `contracts/` | 은행·항목/버전·snapshot·도구 요청/오류·공개 경험·결과의 타입. 기존 스키마와 의미를 맞춤 |
| 2 | `memory/` | SQLite 은행·불변 버전·head·연산 기록·snapshot·fork·compose. 본문은 해시 참조 |
| 3 | `policies/`, `runner/` | 작성 단계·읽기 보기·한도·권한을 검사하는 도구 라우터. 기억 도구와 업무 도구를 분리 |
| 4 | `recording/`, `models/` | 사건과 outbox, 실제 렌더링된 요청·도구 반환·입력 포함 연결, 사용량/결측 기록 |
| 5 | 테스트 전용 worker·benchmark와 `runner/` | 서로 다른 두 합성 과제의 수집·자기 경험/혼합 풀·독립 probe를 연결 |
| 6 | `analysis/`의 최소 재계산과 문서 | 배정·채점·결측·관측 결과 짝·쓰기/조회/노출 수를 사건에서 재계산. 합성 결과임을 표시 |

구현은 작은 단위로 진행하고 각 단계의 실제 행동을 검증한다. 표의 순서를 이유로 미구현 책임을 성공한 것처럼 반환하는 stub을 제공하지 않는다. τ² 연결·누적·교차·개입과 통계 전체를 첫 작업에서 완성했다고 보고하지 않는다.

## 반드시 지킬 기억 서비스 계약

모델 공개 API는 `memory_store(title, body, id=null, expected_version=null)`, `memory_list(cursor=null, limit=null)`, `memory_get(id)`다. 내부 API·오류·저장량 정의는 [상세 설계 6절](../design/architecture.md#6-기억-도구와-은행)을 따른다.

- 생성·갱신·head·연산 결과·사건/outbox를 같은 트랜잭션에서 확정한다. 이전 버전과 snapshot은 갱신 후에도 읽을 수 있어야 한다.
- 같은 operation ID의 인프라 재전송은 같은 결과를 반환한다. 동일 ID에 다른 요청은 거절한다. 새로운 모델 tool call의 동일 본문 저장은 별도 행동이다.
- 갱신은 `expected_version`으로 충돌을 검출한다. 두 분기에서 같은 항목을 바꾼 뒤 compose하면 버전 충돌을 숨기지 않는다.
- 은행 소유권·봉인·접근 가능한 snapshot을 검사한다. 항목/버전 ID에 과제 ID나 정답 역할을 넣지 않는다.
- 저장·읽기 한도 초과는 원자적으로 처리한다. 자동 삭제·요약·본문 잘라내기를 도입하지 않는다. 물리적인 과거 버전 보존량과 논리적 현행 기억량을 구분한다.
- 목록은 제목·ID·버전과 보기 revision을 반환한다. 안정적인 정렬·페이지와 `STALE_CURSOR`를 처리한다.
- `same_episode_read=false`는 run 시작 읽기 보기를 고정한다. 모델 대화에 남은 자기 작성 내용까지 지워졌다고 취급하지 않는다.

삭제·검색·벡터 DB 등은 확장 capability로 남긴다. BM25나 고정 2k 상한을 공통 코어에 넣지 않는다.

## 두 회차 합성 실행의 계약

테스트용 `FakeWorker`는 정해진 tool call·응답을 내고, `FakeBenchmark`는 독립 초기화·업무 상태·결과를 제공한다. 임의의 테스트 값은 테스트 파일에 명시하며 실제 모델·벤치 성능으로 해석하지 않는다.

1. 두 원천 과제를 각각 새 은행에서 수행하고 조건에 따라 기억을 작성한다. 종료 후 작성에서 이미 고정한 업무 결과를 바꾸지 못하게 한다.
2. 원천별 snapshot과 같은 버전들을 합친 혼합 snapshot을 만든다. 풀 구성 중 본문을 재작성하지 않는다.
3. 무기억·자기 경험·혼합 풀을 각각 새 대화·새 업무 상태로 시작한다. 1회차 대화와 내부 정답/분석 주석을 worker에 전달하지 않는다.
4. probe는 시작 snapshot의 복제본을 사용한다. 허용된 쓰기가 원본·다른 probe에 나타나지 않는지 확인한다.
5. `list`·`get`·업무 행동을 연결하고 실제 렌더링 요청에서 제목·본문의 포함 위치와 해시를 확인한다.
6. 합성 사건을 export하고 저장된 원본에서 횟수·결과 짝·채점 결측을 재계산한다. 재export·분석에서 같은 event를 중복 집계하지 않는다.

현재 run-plan 스키마의 `benchmark.name`은 `tau2`, `appworld`, `bfcl`만 허용한다. 가짜 벤치를 τ²로 위장하거나 실제 draft에 가짜 task hash를 넣어 ready로 만들지 않는다. 우선 테스트 전용 구성/내부 builder를 사용한다. 공개 합성 실행 profile을 추가한다면 계약 버전·구분·검증을 함께 설계한다.

합성 사건은 `record_kind=illustrative`다. `agent-memory run ...` 같은 실행 CLI는 현재 존재하지 않으므로 구현 이후에만 사용법을 문서화한다. 오프라인 예제 실행기를 만들면 결과·출력 경로도 합성임을 드러내야 한다.

## 실패와 정보 누출을 검출할 행동 검증

| 검증 상황 | 통과 근거 |
| --- | --- |
| snapshot 후 원본 갱신, 여러 probe 쓰기 | snapshot 불변, 분기 격리, 원은행으로 쓰기 반영 없음 |
| 반복 재전송·새 call·버전 충돌·한도 실패 | 재전송만 멱등, 새로운 행동 보존, 실패 시 부분 저장/부당한 한도 소비 없음 |
| 같은 ID의 서로 다른 분기 버전 compose | 묵시적 덮어쓰기 없이 충돌 거절 |
| 제목만 조회, 본문 반환 후 전송 전 중단 | 목록 노출과 본문 노출 구분, 반환을 입력 포함으로 자동 계산하지 않음 |
| 한글·여러 줄·따옴표를 포함한 본문 | 저장 원문 해시와 JSON 렌더링 부분 문자열 해시를 각각 올바르게 검증 |
| 여러 기억 도구 호출 사이의 업무 상태 | 사용자 시뮬레이터·업무 단계가 기억 호출만으로 진행되지 않음 |
| 2회차 초기화·무기억 조건 | 이전 대화·provider session·은행 내용·정답 메타데이터의 우회 유입 없음 |
| 종료 후 작성, 채점 오류, 사용량 미보고 | 업무 결과 고정, 채점/비용 결측을 실패·0으로 강제 변환하지 않음 |
| DB 확정 후 export 장애·재시작 | outbox 재처리, 안정된 event ID, 중복 제거, 불완전 실행 명시 |

과거 보관 데이터에 의존하는 테스트는 기본 흐름에 필요하지 않다. 새 코드가 생성한 작은 자료로 계약 위반을 실제 검출한다. DB 복원만으로 사용자·대화·난수·외부 부작용이 모두 복원된다고 주장하지 않는다.

## 미확정 실제 실험 설정과 완료 보고

API 키·도메인·표본/반복 수·예산의 답을 기다리지 않고 위 공통 코어를 구현할 수 있다. 테스트용 수치는 문서와 별도 테스트에 명시하고 실제 연구의 선택으로 확정하지 않는다.

실제 실행용 `PlanCompiler`는 draft 차단 외에 참조 해시·과제/출처·조건·짝·은행 소유권·adapter capability를 의미 검사해야 한다. JSON Schema의 합법적인 `null`을 모두 오류 처리하지 않는다. 자세한 미정 값은 [인수인계](../handoff/next-session.md)에 있다.

완료 보고에는 구현한 기능, 관련 행동 테스트, 오프라인 예제 명령/출력, 남은 기능을 구분한다. 루트 README·개발 계획·인수인계의 현재 상태도 갱신한다. 코어가 구현돼도 실제 Luna·τ² 성능은 별도 실증 전까지 미측정이다.
