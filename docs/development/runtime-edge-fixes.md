# 비용 누락·항공편 시각·완료 사유 보완

2026-11-16 · 구현 `319780a` · 새 모델 호출 없음

[개선 계획](experiment-layer-improvement-plan.md)에서 분리한 작은 버그 세 개를 수정했다. 파일 로그와 v1.1/v1.2 형식은 유지한다. 과거 원본·동결 기록·보고서를 고쳐 새 동작에 맞추지 않는다.

## 바뀐 동작

| 경로 | 이전 문제 | 수정한 동작 |
| --- | --- | --- |
| OpenRouter 비용 처리 | `usage: null`이면 비용 검사 중 예외가 나 원응답을 기록하지 못함 | 비용 미확인으로 표시하고 원응답을 저장한 뒤 다음 전송을 차단. native 연결 요약·감사도 null 사용량을 읽음 |
| 결정 지점의 항공편 순서 검사 | `01:30:00+1`을 시각으로 파싱하다 실패 | 출발 날짜에 명시된 일수 오프셋을 더해 도착·다음 출발 순서를 비교 |
| baseline·재전송의 마지막 배정 | 마지막 정상 응답이 호출 한도를 채우면 `call_limit`을 남김 | 남은 배정이 없고 오류·비용 미확인이 없으면 `stop_reason=null`. 마지막 응답의 실제 오류·미확인 비용은 유지 |

토큰 합계에서 누락 사용량은 0만 기여한다. 실제 토큰 사용이 0이었다는 뜻은 아니며 `unknown_cost`와 원응답을 함께 확인해야 한다. `SpendGuard`는 비객체 사용량도 미확인으로 취급하지만, 전체 기록 경로의 보장 범위는 현재 계약이 허용하는 사용량 객체·null이다.

시각은 벤치의 날짜 없는 EST 시각 형식을 따른다. 명시적 `+1`은 시계상 도착이 출발보다 늦어도 다음 날이다. 접미사가 없는 기존 야간편의 다음 날 추정은 유지하고, 잘못된 접미사·날짜 초과·명시적 일수와 모순되는 순서는 파싱 불가로 남긴다. 이 검사는 과제 21의 좁은 호출 인수 검사이며 업무 도구 실행·전체 회차 채점과 구분한다.

## 검증과 과거 자료 호환

추가한 행동 테스트 10개와 기존 관련 검사를 합친 50개가 통과했고, 이어 **전체 182개가 488.026초에 통과**했다. 기본 설계·저장소·보관본 검사도 통과했다. null 원응답·미확인 비용·다음 HTTP 차단, native 요약/감사, `+1`과 기존 야간편·잘못된 시각, 마지막 배정 정상 완료·실제 오류 보존을 확인한다. 검사 결과와 소스 참조는 [검증 자료](../../artifacts/analyses/20261116-runtime-edge-fixes-validation.json)에 남겼다. 테스트는 mock HTTP이며 소요 시간은 다른 로컬 작업과 겹친 한 번의 관측이다.

원천 DB의 300개 항공편을 순서 검사에 넣었고, `+1` 도착 36개마다 당일·다음 날 복귀편을 합성해 각각 위반·통과를 확인했다. 이 합성 결과는 기억 효과나 항공 예약 성공률이 아니다.

수정한 코드로 보존된 전달 비교 48회·무기억 채점 55회·결정 재전송 120요청을 감사했다. 저장 요약과 receipt 대조가 통과했고 원본 로그 해시는 유지됐다. 기존 120요청의 `call_limit`은 기록된 값 그대로 읽는다. 당시 제출 응답의 판정·보고 비용·감사 결과 해시도 같다. `+1`을 사용한 새로운 응답은 이번 수정으로 판정이 달라질 수 있으므로, 과거 분석을 정확히 재현할 때는 [고정 코드 실행기](historical-reproduction.md)를 사용한다.

구현 수정 후 현재 launcher에서 분석 commit `c51165b`의 120요청 검토도 다시 통과했다. 네트워크·금지된 프로세스·보호 입력 쓰기 시도는 모두 0이었고 원본·사본·과거 코드 보존과 임시 worktree 정리를 확인했다. 검증 자료의 receipt 참조로 연결한다.
