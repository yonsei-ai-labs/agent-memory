# 같은 과제에서 새로 측정하는 기억의 효과

2026-11-24 · 새 계열의 첫 비교 · 항공·소매 100과제 실행과 원장 검증 완료

새 계열을 시작하기 전에 얻은 모든 성적을 새 계열의 기준선·메모 원천·효과 추정에서 제외한다. 이전에 개선을 보인 조건과 악화를 보인 조건 모두에 적용한다. 원본 저널·정답·보고서와 당시 코드의 고정 재현 경로는 보존한다. 선정에는 이미 사용한 **공식 과제 ID**를 사용한다. 따라서 새 측정은 같은 업무에서 처음부터 다시 푼 결과이며, 아직 접하지 않은 고객에 대한 일반화 검증은 별도 과제가 필요하다. 자동 제공의 순증 9건을 나눠 보면, 실제 저장된 메모가 있던 388쌍에서 회복 34건·손실 32건, 작성자가 비운 73쌍에서 회복 10건·손실 3건이었다. 저장 여부는 작성자가 결정한 사후 구분이다. 자율 조회는 상담원 응답 477건 중 목록·본문 호출이 0건이었다. 자동 제공과 무기억이 모두 성공한 308쌍에서는 자동 제공의 상담원·고객 토큰이 8.0%, 상담 비용이 4.9% 더 들었다. 저장·입력 전달은 검증됐지만 메모 본문이 전반적인 성과 향상을 일으켰다고 판단할 근거는 약하다. | 상담 종료 후 작성 | 5 | 같은 1회차 상담원에게 공개된 대화·업무 도구 응답과 해당 작성 지침. 정보, 경험 경과, 절차, 교훈, 자유 형식을 각각 맡긴다. |

1회차의 공식 성공과 실패를 모두 포함한다. 작성자가 자발적으로 저장을 생략하면 빈 은행으로 배정된 두 상담을 그대로 수행한다. 2회차 무기억과 별도 빈 메모 대조의 추가 배정은 각각 0건이다. 각 상담원·고객 시뮬레이터·대화·업무 DB·기억 은행의 가변 상태는 새로 시작한다. 작성자는 고객의 비공개 대본, 채점 기준·성적, 다른 작성물, 후속 대화를 보지 않는다. 다섯 형식의 작성 순서와 열 조건의 풀이 순서는 결과를 보기 전에 고정한다. [프로토콜과 작성 지침](../../protocols/pilots/tau2-fresh-matched-v1.json)

## 격리를 확인하는 지점

공식 과제·고객 대본·채점 기준, 처음 DB, 양쪽 시스템 문구와 업무 도구, 역할별 모델·시드·한도를 과제별로 고정한다. 두 회차 모두 같은 업무 도구 라우터와 공식 채점기를 사용한다. 소매에서 자연어 채점이 필요한 경우 평가자 전용 경로와 설정도 동일하다. 메모 조건에 공통으로 쓰는 안내는 메모가 어디에 제공되고 선택적으로 어떻게 읽는지만 설명한다. [공통 안내 원문](../../protocols/instructions/matched-memory-read-v1.txt) · [100과제별 사전 확인 기록](../../artifacts/pilots/20261124-fresh-matched-preflight.json)

1회차 저널에서 처음 고객 요청과 양쪽의 실제 요청 설정을 다시 읽는다. 2회차마다 이 기록과 새로 만든 실행 환경을 대조하고, 메모 본문·전용 도구·메모 안내를 포함한 최종 요청을 전송 직전에 검사한다. 초기 고객 요청은 과제별로 바이트가 일치해야 한다. 고객에게 “지난번처럼”이라고 말하라는 후속 지시는 추가하지 않는다. 같은 입력을 받은 고객 모델이 실제로 생성한 첫 발화는 달라질 수 있다. 발화는 세션마다 독립 생성하고, 보고서에 첫 발화가 같았던 쌍의 분모와 분자를 표시한다. ## 범위와 판독

전체 배정은 항공 학습 28·시험 6과제와 소매 학습 26·시험 40과제다. 항공 28명과 소매 49명으로 총 77명의 고객에 해당한다. 100과제 전부를 선택하면 무기억 원천 100건, 작성 500건, 후속 상담 1,000건이다. 먼저 수행하는 항공 21번과 소매 5번도 그 배정에 들어 있다. 항공만 선택하면 21·23번을 먼저 수행한다. 이전 두 번 방문 대본의 2,310개 배정은 이 과제들에 넣지 않는다. [과제별 배정 실행기](../../scripts/run_fresh_matched.py)

- 형식과 전달 방식별로 같은 과제의 새 무기억 원천 대비 실패 회복, 성공 손실, 양쪽 성공, 양쪽 실패, 결측을 센다. 전달 방식끼리는 같은 작성 결과를 받은 두 상담을 짝짓는다. 도메인별로 고유 고객 수와 고객 동일 가중 차이를 표시한다.
- 원천 하나의 성패를 열 조건이 공유한다. 열 조건을 결합해 독립 원천이 열 배가 된 것처럼 계산하지 않는다. 조건당 한 번의 수행이므로 개별 상담의 성패 반전에는 모델 응답의 변동도 포함된다.
- 공개 경험에서 작성된 원문, 저장 생략, 실제 목록·본문 조회, 상담원 요청에 본문이 포함된 시점과 다음 행동을 연결한다. 본문이 노출됐다는 사실만으로 그 메모가 성공을 일으켰다고 판정할 수 없다.
- 양쪽 모두 성공한 쌍을 따로 보아 고객 발화, 업무 도구 호출, 기억 조회, 토큰과 상담 비용을 비교한다. 작성과 채점을 포함한 실제 단계별 비용 및 미확정 보류액도 집계한다.
- 공급자 장애·미채점·미시작은 결측으로 보존한다. 원천을 얻지 못한 경우 해당 과제의 후속 배정, 작성에 실패한 경우 해당 작성물의 두 풀이가 결측이 된다. 단계별 비용 보류와 재시작 시 중복 전송 방지는 새 실행 원장에 기록한다. [새 계열 전용 보고서](../../scripts/report_fresh_matched.py)

과거의 고정 은행·작성 형식·전달 방식 실험은 이 첫 비교에서 공통 출발점을 다시 만든다. 이후의 여러 메모 중 선택, 다른 과제로의 전이, 피드백으로 작성 지침 개선 및 누적은 각각 별도 비교로 등록한다. 전이에서 회차 간 성공률을 비교하려면 목표 과제 자신의 무기억 기준이 있어야 한다. 고객 대본을 바꿔 재방문을 유도하거나 판단 한 지점만 재생한 과거 자료는 새 계열의 전체 상담 성공률에 포함하지 않는다. [연구 범위](plan.md)

실행 코드는 로컬 브랜치 `experiment/fresh-matched-20261124`의 `f597745713bc`에 고정했다. 사용자가 전체 100과제와 총한도 $9를 승인해 선택한 범위, 총액, 프로토콜 해시와 승인 문구를 시작 등록에 남겼다. 모의 검증 비용은 $0이다. [새 실험 승인 기록](../../artifacts/pilots/20261124-fresh-matched-authorization.json)

첫 항공 21번과 소매 5번에서 공급자 응답의 내부 필드가 다음 상담원 입력에 포함되려 하자 전송 전 격리 검사가 멈췄다. 두 고객의 첫 요청은 등록 해시와 일치했다. 확인 비용은 앞서 실제 전송한 6요청의 $0.001702677이고 미확정은 0건이다. 두 1회차를 기술 결측으로, 그에 딸린 작성 10건과 2회차 20건을 원천 결측으로 남긴다. 두 상담의 실제 응답을 각각 세 개까지 재생하고 모의 응답으로 이어서, 공개 발화·도구 호출만 이력에 넘기면 차단 지점을 통과함을 오프라인으로 검증했다.

미시작 98과제의 실행 코드는 `2c20f27fc966`에 고정했다. 최초 원장의 봉인·원요청·비용을 검증하고 한 번만 합산한다. 원래 순서상 다음 항공 17번과 소매 107번에서 작성과 2회차까지 확인한 뒤 나머지를 진행한다. 배정·채점·합산 한도는 최초 등록을 따른다. [이어 실행하는 배정과 원장 해시](../../protocols/pilots/tau2-fresh-matched-continuation-v1.json)

2회차 수행 중 15시 50분경 고객 모델의 같은 공급자 경로가 7과제의 27상담에서 연속 503을 반환했다. 요청별 보류액 합계는 $0.0524781이다. 15시 51분 06초에 실행 프로세스를 일시 정지했다. 당시 진행 표시된 네 상담 모두 아직 모델 요청을 기록하기 전이었다. 15시 53분 36초에 원래 순서의 소매 38번 여덟 번째 상담을 먼저 재개해 3초 뒤 고객 정상 응답을 확인하고 나머지를 재개했다. 네 상담 모두 공식 채점을 마쳤다. 오류 27건은 기술 결측으로 남겼다.

이후 같은 경로에서 30초 안에 503이 두 건 발생하면 새 전송을 잠시 멈추고, 기존 배정 중 한 상담의 정상 고객 응답으로 재개를 판단하게 했다. 사전등록 후 도입한 운영상 속도 조절이다. 역할·모델·배정·과제당 시도 횟수·비용 한도는 원래 등록을 따른다. 429도 관측돼 상담원 또는 고객의 같은 경로에서 429·502·503·504가 반복될 때 같은 방식으로 대기하게 했다. 운영 기록은 `outputs/fresh-matched-20261124/provider-hold.log`에 있다. 여섯 차례 일시 정지 후 원래 배정에서 복구했고, 18시 41분에 실험을 종료했다. 2회차 미채점은 503 32건·429 17건·전송 미확정 1건·최대 단계 도달 1건이다.
