# 기억 실험을 에이전트 행동 연구에 활용하는 제언

2026-11-14 · 파일럿 관찰과 2주 계획을 바탕으로 한 활용 제안, 실행 전

**기억 실험은 기억을 쓰고 여는 결정 자체를 행동으로 관찰하게 해 주고, 재학습 없이 에이전트가 아는 것을 조절하는 개입 도구도 된다. 공식 점수 옆에 행동 지표·내용 개입·쓰기 분석을 더하면 같은 실행에서 에이전트 동작에 대한 발견을 더 많이 얻을 수 있다.** [진행 보고서와 2주 계획](../reports/20261114-progress-and-two-week-plan.md)과 [발전 방향 노트](novelty-direction-review.md)를 보완하는 제안이다. 연구 범위·draft·실행 숫자를 정하지 않는다.

## 기억 실험이 주는 두 가지 관점

| 관점 | 보는 것 | 예 |
| --- | --- | --- |
| 결정으로서의 기억 | 무엇을 남길 가치가 있다고 보는지, 언제 정보를 찾는지 | 저장 여부와 내용, 조회 여부와 시점 |
| 개입 도구로서의 기억 | 같은 시작 상태에서 정보만 바꿀 때 행동이 어떻게 달라지는지 | 본문 제공과 보류, 다른 과제의 기억, 조건 문장 제거와 복원 |

가까운 연구에서도 이 관점으로 일반적인 행동이 드러났다. [Memory Trap](https://arxiv.org/abs/2611.07554)은 사소한 작업에서 생긴 기억이 이후 중요한 작업의 확인 생략으로 이어지는 것을, [Compliance Trap](https://arxiv.org/abs/2607.10608)은 충돌하는 기억을 처음 노출된 판단에서 따르고 잘 회복하지 못하는 것을, [MemDrift](https://arxiv.org/abs/2605.24941)는 기억된 선호가 도구 인수를 바꾸는 것을 보였다.

## 파일럿에서 본 행동 단서

[자율 조회 파일럿](../development/tau2-autonomy-pilot.md)과 [행동 보조 분석](../../artifacts/analyses/20261114-tau2-action-comparison.json)에서 다음 단서를 얻었다. 한 과제·조건별 3회의 관측이므로 다음 실험의 출발점으로 쓴다.

| 행동 | 관찰 | 다음에 볼 것 |
| --- | --- | --- |
| 무엇을 남기나 | 피드백 없이 성공한 뒤 저장하지 않음. guided 기억은 정책 조건과 예약·사용자 ID 같은 사례 세부를 함께 적음 | 실패·결과 피드백 조건에서 저장 결정과 내용의 구체성이 달라지는지 |
| 언제 찾나 | 기억 도구가 있는 6회 모두 list/get 없음. 추론 요약이 있는 응답 7개에서 기억 언급 없음 | 본문 시작 제공과 비교해 정보 가치와 조회 선택을 나눠 봄 |
| 확인 행동 | 같은 조건 안에서도 항공편 상태 조회가 0~2회 | 확인 호출의 자연 변동을 기준선으로 측정 |
| 일관성 | 무기억 3회 모두 성공, 단계 9~15. 이관 요약을 빼도 9쌍 중 7쌍의 호출이 다름 | 기억이 경로를 안정시키는지, 어디서 경로가 갈라지는지 |

## 제언

### 1. 공식 점수 옆에 행동 지표를 둔다

대부분 지금 원본 기록으로 계산할 수 있다. 업무 호출의 이름·인수·순서, 기억 반환과 입력 포함, native 대화 기록이 이미 남아 있다.

| 지표 | 정의 | 현재 기록으로 계산 |
| --- | --- | --- |
| 첫 업무 행동 전 조회 | 첫 업무 호출 전에 기억 반환이나 시작 시 제공 노출이 있었는지 | 가능. 기억 사건과 업무 호출의 순서 |
| 노출 후 첫 행동 | 기억 제목·본문이 처음 입력에 들어간 뒤의 첫 업무 호출과 인수 | 가능 |
| 확인 호출 | 상태를 바꾸는 호출 전에 한 조회 호출 수 | 가능. 호출 이름과 순서 |
| 업무 결정 유형 | 거절·상담원 연결·취소·변경 같은 최종 결정 | 호출과 최종 DB 해시로 1차 분류. 설명의 적절성은 별도 검토 기준 |
| 반복 간 행동 일치 | 자유 서술을 뺀 호출 순서·인수가 같은 비율 | 가능. 행동 보조 분석의 확장 |
| 경로 분기 지점 | 같은 블록의 두 실행이 처음 달라진 턴과, 먼저 달라진 쪽이 작업자인지 사용자인지 | native 대화 기록으로 계산 가능. 분석 코드 추가 필요 |

적용 조건과 관련된 행동은 [측정 문서](metrics.md#조회-필터와-적용-조건-행동)의 변경 판단 전 근거 확보율·금지 행동 시도율 정의를 따른다. 지표는 하나의 점수로 합치지 않고, 정의·분모·판정 규칙을 실행 전에 정한다.

### 2. 기억 내용을 바꾸는 개입으로 출처 판단을 본다

본문 시작 제공 경로가 생기면 같은 경로로 개입 조건을 붙일 수 있다. 연구자가 해로운 기억을 새로 쓰지 않아도, 다른 과제에서 자기 작성한 기억을 재작성 없이 옮기는 것만으로 조건이 다른 경험을 만들 수 있다.

| 개입 | 만드는 방법 | 보이는 행동 |
| --- | --- | --- |
| 제공과 보류 | 같은 은행의 본문을 시작 시 제공하거나 보류 | 기억 정보가 행동을 바꾸는지 |
| 다른 과제의 기억 | 다른 과제에서 자기 작성한 기억을 그대로 제공 | 조건이 다른 경험을 걸러 쓰는지, 그대로 따르는지 |
| 조건 문장 제거와 복원 | 원경험에 있던 적용 조건만 빼거나 되살림 | 조건 정보가 과잉 일반화를 줄이는지 |
| 같은 사용자의 다른 과제 | 같은 사용자의 이전 과제 기억을 제공 | 기억을 믿기 전에 현재 상태를 다시 확인하는지 |

개입은 세션 시작의 최초 노출 전부터 분기한다. 원문과 수정문의 차이·길이·해시를 보존하고, 현재 과제의 정답이나 숨은 상태를 보충하지 않는다. 연구자 개입의 결과는 진단으로 구분해 자율 정책의 성적과 합치지 않는다. [실험 프로토콜](experiment-protocol.md#저장과-조회를-교차하고-내용을-개입하는-평가)의 개입 원칙을 따른다.

### 3. 기억 쓰기를 행동 기록으로 읽는다

에이전트가 쓴 기억은 무엇을 중요하게 보고 어떻게 일반화하는지 보여 준다. 다음 항목을 분석 주석으로 남기면 쓰기 정책 사이의 차이를 설명하기 쉽다.

- **구체성:** 예약·사용자 ID 같은 사례 세부와 일반 규칙의 비율
- **조건 보존:** 언제 적용되는지를 적었는지
- **정보 출처:** 현재 정책을 다시 적은 내용과 경험에서만 얻은 내용(사용자 반응, 도구 동작 등)
- **불확실성 표시:** 관측과 추측을 구분했는지
- **저장 결정:** 성공·실패와 결과 피드백 유무에 따라 저장 여부가 달라지는지

주석은 분석 자료로 따로 보관하고 에이전트 입력에 넣지 않는다.

### 4. 추론 요약은 가설을 세우는 데 쓴다

reasoning low에서 추론 요약이 있는 작업자 응답은 파일럿 53개 중 9개였다. 요약은 "왜 기억을 열지 않았나" 같은 가설을 세우는 데 쓰고, 확인은 본문 시작 제공과 개입 비교로 한다. 조건별 요약 출현율도 함께 기록하면 해석 범위를 알기 쉽다. 합의한 reasoning low 설정은 유지한다.

### 5. 행동이 잘 드러나는 과제를 고른다

τ²의 정책은 이미 시스템 입력에 있으므로, 과거 경험만이 주는 정보가 있는 과제에서 행동 차이가 잘 드러난다. 사용자별 사실, 도구·환경의 특이점, 실패에서 얻은 교훈이 그런 정보다.

airline에서는 사용자 시나리오에 적힌 사용자 ID 기준으로 10명이 여러 과제에 나온다. 변형 과제를 만들지 않고도 관련 새 과제를 구성할 수 있다.

| 사용자 | 과제 | 활용 |
| --- | --- | --- |
| `mohamed_silva_9265` | 14, 23 (train) | train 안의 관련 과제 쌍 |
| `yara_garcia_1905` | 33, 34 (train) | train 안의 관련 과제 쌍 |
| `sophia_silva_7557` | 4, 8, 46, 47 (train), 44 (test) | 같은 사용자의 여러 요청 |
| `aarav_ahmed_6699` | 9 (train), 35, 37 (test) | 같은 세 예약에 대한 다른 요청. 9는 상태 변경 없이 끝나고 37은 business 변경이 필요 |

각 쌍의 조건 정합성과 채점은 과제를 고를 때 확인하고, test 과제는 확인 단계에만 쓴다. 상태 변경이 필요한 과제를 함께 두면 필요한 행동의 누락과 금지 행동의 시도를 구분할 수 있다.

### 6. 행동 특성의 범위를 넓힌다

- **두 번째 작업자 모델:** 작은 블록으로 같은 비교를 하면 관찰한 행동이 Luna의 특성인지 에이전트 일반의 특성인지 구분할 수 있다.
- **지침 문구 반복:** 기억 정책 지침을 두세 가지 문구로 바꿔 보면 행동이 특정 문구에 묶인 것인지 확인할 수 있다. [실험 프로토콜](experiment-protocol.md#보정-실행과-비교-계획)의 선택적 대조에 해당한다.

## 2주 계획에 붙이는 순서

| 2주 계획의 시점 | 붙일 제언 |
| --- | --- |
| 1~2일차 기존 결과 정리 | 조회 시점·확인 호출·반복 일치·경로 분기 지표를 파일럿 원본에 계산 |
| 3~4일차 과제 후보 검토 | 같은 사용자 과제 쌍과 상태 변경이 필요한 과제를 후보에 포함하고 쓰기 주석 기준 마련 |
| 5~7일차 본문 시작 제공 구현 | 다른 과제의 기억·조건 제거와 복원을 같은 제공 경로로 붙일 수 있게 설계 |
| 8~11일차 확인 비교 | 행동 지표를 사전 정의 지표로 함께 기록 |
| 12~14일차 보고 | 대표 궤적에 노출 시점·첫 행동·분기 지점을 붙여 설명 |

## 해석을 단단하게 하는 원칙

- 주석과 개입 원본은 분석 자료로 보관하고 에이전트 공개 입력과 분리한다.
- 연구자 개입의 결과는 진단으로 구분하고 자율 정책의 성적과 합치지 않는다.
- 목록 제목도 노출로 센다. 반환과 입력 포함만으로 활용을 단정하지 않고 짝 비교 결과와 연결한다.
- 같은 실행을 공유하는 비교를 독립 표본으로 세지 않는다.
