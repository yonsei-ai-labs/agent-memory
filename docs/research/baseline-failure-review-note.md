# 기준선 실패 진단 검토와 다음 증명 포인트

2026-11-15 · 리뷰 노트 · 새 모델 호출 0

**[실패 원인 진단](../reports/20261115-tau2-baseline-failure-diagnosis.md)의 사실관계는 원본으로 다시 확인됐다. 실패 11회는 Luna 판단 오류 8회, 사용자 시뮬레이터 이탈 1회, 과제 정의 충돌 2회로 나뉜다. Luna 오류의 다수는 추론 토큰 없이 내린 판단에서 시작됐고, 같은 실수가 출처를 공유하는 다른 과제에서도 반복됐다. 다음 증명 포인트는 같은 결정 상태에서 기억 메모가 오류율을 낮추는지, 그리고 그 효과가 일반적인 주의 환기와 구별되는지다.**

이 노트는 커밋 `c31a9d6`의 진단과, 그 뒤 다른 세션에서 진행 중인 결정 재전송 구현(미커밋)을 함께 본 검토다. 공식 결과 44/55와 원본은 바꾸지 않았다. 의미 판정은 조건을 아는 단일 검토자의 것이며 독립 재판정이 아니다.

## 3. 추가 분석

### 3.1 추론 없이 내린 판단

| 응답 유형 | 응답 수 | 추론 토큰 0 | 평균 추론 토큰 |
| --- | --- | --- | --- |
| 텍스트 응답 | 315 | 56% | 53.8 |
| 조회·계산 호출 | 182 | 69% | 24.5 |
| DB 변경 호출 | 38 | 53% | 44.0 |
| 이관 | 30 | 50% | 44.9 |

Luna 오류 8개의 시작 응답 중 5개가 추론 토큰 0~39였다(17-1, 42-1, 42-2, 39-2, 23-2). 나머지 3개(20-1, 14-2, 21-1)는 115~237로 추론을 하고도 틀렸다. 같은 과제의 성공 반복과 비교하면 차이가 더 보인다. 17-2에서 등급 변경을 포함한 계획을 제시한 응답은 291이었다. 14·23 출처의 첫 결제 견적은 위반한 두 번이 0·39, 맞은 두 번이 170·227이었다.

다만 텍스트 응답의 0 기저율이 56%다. 진단 JSON의 결정 지점 기준으로 Luna의 텍스트 판단 오류 5개 중 4개 이상이 0일 확률은 약 0.27이다. 추론 부족을 원인으로 말할 수 없으며 결정 재전송에서 검증할 예측으로 둔다.

### 3.2 같은 실수가 출처를 공유하는 과제에서 반복됐다

- **증서 제한:** 같은 사용자·예약을 쓰는 14·23의 네 반복 중 두 번이 첫 견적에서 증서 세 장을 썼다. 14-1은 예약 전에 스스로 고쳐(추론 313) 성공했고, 23-2는 그대로 예약해 실패했다.
- **basic economy 제한의 범위:** 17-1의 등급 변경 거절 외에도 7-1이 추론 0으로 "등급을 바꿔도 취소 자격이 생기지 않는다"며 정책에 없는 거절을 했다. 7-1은 끈질긴 사용자 덕분에 업그레이드·취소가 참조 DB와 일치했다.
- **여러 예약의 목표 대조:** 42의 두 반복은 서로 다른 방식으로 실패했지만, 두 번 모두 각 예약을 사용자의 날짜·도시 조건과 끝까지 대조하지 않았다.

세 묶음은 현재 정책에 이미 있는 규칙이거나 일반 절차다. 이 오류들에서 기억이 도움이 된다면 새 정보보다 결정 시점에 규칙을 떠올리게 하는 효과일 가능성이 크다. 예외는 23의 "승객별로 예약을 나눠 증서를 하나씩 쓰는" 방법이다. 정책에는 없고 이전 대화에서 사용자가 제안한 절차이므로, 과거 경험에서만 얻을 수 있는 드문 후보다. 14↔23과 17↔7은 같은 교훈이 다른 과제로 전이되는지 볼 수 있는 자연스러운 짝이다.

### 3.3 공식 점수가 가리는 과정 오류

14-1의 위반 견적과 7-1의 근거 없는 거절은 최종 점수에 드러나지 않는다. 7-1은 첫 취소(59XX6W)도 사용자 확인 없이 실행했다. 정책 7행은 DB를 바꾸기 전 명시적 확인을 요구하지만 괄호 안 예시에 취소는 없다.

과정 오류는 최종 실패보다 자주 나온다. 14·23 출처에서 첫 견적 위반은 네 번 중 두 번이었지만, 그 때문에 최종 실패한 것은 23-2 하나다(14-2는 수하물로 실패). 작은 표본에서 기억 효과를 볼 때는 첫 견적 위반률이나 근거 없는 거절 같은 과정 지표가 최종 성공률보다 민감할 수 있다. 일부는 호출 인수로 자동 판정할 수 있다.

### 3.4 사용자 시뮬레이터가 경로를 바꾼다

| 실행 | 시나리오와 달라진 점 |
| --- | --- |
| 11-2 | 원래 결제수단 환불을 원한다는 지시와 달리 gift card를 거부 |
| 20-1 | Luna의 잘못된 과거 판단 뒤 2025년을 새로 지정. 사용자 system에는 기준 시각이 없음 |
| 23-2 | 시나리오에만 있던 "정책상 증서 한 장" 지식을 예약 뒤 먼저 꺼내 위반을 지적 |
| 7-1 | 세 번째 agent 메시지 뒤에 해야 할 질문을 두 취소가 끝난 뒤에 함 |
| 14-2 | "수하물이 필요 없다"는 지시를 Luna의 무료 6개 언급 뒤 no extra bags로 표현 |

11-2를 빼면 실패의 직접 원인은 아니지만 대화 경로를 바꿨다. 에피소드 실험에서는 실행마다 시뮬레이터 이탈을 따로 기록해야 한다. 결정 재전송은 대화를 고정하므로 이 잡음을 피한다.

### 3.5 같은 요청·같은 seed에서도 응답이 다르다

이전 전달 비교와 자율 조회 원본에서 바이트가 같은 worker 요청(seed 0) 그룹 10개, 요청 38개를 찾았다. 응답이 모두 같은 그룹은 없었고 고유 응답은 34개였다. 원래 seed를 유지한 재전송도 표본이 한 응답으로 수렴하지 않는다. 다만 일부 중복은 생길 수 있다.

## 4. 진행 중인 결정 재전송에 대한 제안

현재 초안은 Luna 오류 8개 상태 × 20회 × (원래 요청·reasoning medium·연구자 메모)다. 메모는 system 끝에 `Notes from earlier work:`로 붙인다. 14·23·21은 호출 인수로 자동 판정하고 나머지 5개는 수동 판정한다. 관련 파일은 `protocols/drafts/tau2-decision-replay-v1.json`, `protocols/diagnostics/decision-replay-researcher-memos-v1.json`, `src/agent_memory_eval/runner/decision_replay.py`이며 아직 커밋 전이다.

가볍게 유지하면서 증명력을 높이는 보완은 다음과 같다.

1. **원래 요청의 오류 재현율부터 본다.** 같은 상태에서 오류가 드물게만 재현되면 개선 여지가 작다. 상태별로 우연한 실수와 고정된 오류를 먼저 나눈다.
2. **예측을 먼저 적는다.** reasoning medium은 추론 0 텍스트 판단(17-1, 42-1, 42-2, 39-2)을 더 많이 고치고, 추론하고도 틀린 실행 상태(21-1, 14-2, 23-2)에서는 메모보다 효과가 작을 것으로 예측한다. 결과가 반대여도 그대로 보고한다.
3. **일반 메모 대조를 더한다.** "행동 전에 관련 정책과 도구 결과를 다시 확인한다" 정도의 비슷한 길이 메모를 넣어, 내용과 무관한 주의 환기 효과를 분리한다. 이 대조가 없으면 메모 효과를 내용의 효과라고 말하기 어렵다.
4. **원래 옳았던 상태에서 손해를 본다.** 39-1의 MSJ4OA 거절, 14-2와 23-1의 맞은 견적, 17-2의 계획 응답에 같은 메모를 넣어 결정이 뒤집히는지 본다. 지금 코드는 오류 상태 8개만 받으므로 새 버전이 필요하다.
5. **오류가 생긴 지점을 따로 둔다.** 21-1과 23-2의 실행 지점은 자기 제안과 사용자 동의를 뒤집어야 하는 자기 교정 시험이다. 제안·견적 지점을 추가하거나 실행 지점의 결과를 따로 해석한다.
6. **메모 위치의 차이를 기억한다.** system 끝의 메모는 에피소드 실험의 시작 제공(system 다음 별도 문맥, 과거 관찰로 표시)과 위치·권위가 다르다. 결과를 에피소드 실험으로 옮길 때 이를 감안하거나 같은 형식의 조건을 하나 둔다.
7. **수동 판정 기준을 미리 정한다.** 예: 17은 등급 변경을 허용·제안했는가, 42-2는 PUNERT의 5월22일 출발을 인정했는가, 39-2는 24시간 이내라고 주장했는가, 5월22·23일 예약을 다가오는 예약에 포함했는가.

보완을 모두 더해도 상태 14개 × 20회 × 4조건, 약 1,120 요청이다. 기준선 worker 요청당 평균 보고 비용이 약 $0.00013이므로 reasoning medium의 증가분을 감안해도 $0.3 안쪽으로 예상한다.

| 메모와 일반 메모의 효과가 비슷함 | 내용이 아니라 주의 환기의 효과. 기억 표현보다 전달 시점·형식이 중요하다는 근거 |
| 어느 조건도 효과 없음 | 입력된 정보가 결정에 쓰이지 않는 사례. 전달됐지만 쓰이지 않는다는 선행연구와 같은 방향의 관측으로 보고 |
| 원래 옳았던 상태가 메모로 뒤집힘 | 오적용 손해. 이득과 함께 보고하고 적용 조건을 담은 표현을 비교할 근거 |

## 6. 한계

- 재분류와 의미 판정은 조건을 아는 단일 검토자의 판단이다.
- 추론 토큰은 제공자가 보고한 값이다. 0이 내부 추론의 완전한 부재를 보증하지는 않는다.
- 비교는 대부분 1~5건 규모의 기술 관찰이며 상관을 원인으로 쓰지 않는다.
- 결정 재전송은 응답 하나만 본다. 최종 업무 성공과 이후 대화의 변화는 에피소드 실험으로 확인해야 한다.
