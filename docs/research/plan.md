# 연구 계획

2026-11-14 · 새 프로젝트의 연구 기준

**같은 LLM이 경험을 어떻게 기억으로 저장하고 선택·조회하느냐에 따라 후속 작업의 성공·실패·진척·비용이 어떻게 달라지는지 측정한다.** 평가 프레임워크·측정 절차·실증 분석을 연구 산출물로 삼는다.

연구 제목은 「LLM 에이전트의 메모리 저장·조회 방식에 대한 평가 프레임워크」다. 영문 작업 제목은 *A Framework for Evaluating Memory Writing and Retrieval in LLM Agents*다.

## 문제와 연구 질문

경험은 계속 늘어나지만 각 판단에 사용할 문맥과 처리 비용에는 한계가 있다. 무엇을 남기고 언제 어떤 기억을 불러올지가 중요하다. 여러 방법이 제안돼 있으므로, 과제·정보·비용 조건에 따라 어떤 저장·조회 조합이 이득과 손해를 만드는지 비교한다.

최종 성공률만으로는 경험에 정보가 없었는지, 저장에서 빠졌는지, 조회되지 않았는지, 입력에 들어와도 잘못 활용됐는지 구분하기 어렵다. 같은 과제 복구와 새 과제 전이, 평균 개선과 일부 과제의 악화도 별도로 본다.

| 연구 질문 | 대응 비교와 관측 |
| --- | --- |
| 언제 무엇을 저장하는 것이 유리한가 | 수행 중·종료 후·병행, 표현 형태, 공개 경험과 생성된 본문 |
| 무엇을 언제 읽는 것이 유리한가 | 시작 제공·자율 조회·병행, 원문과 재가공, 실제 입력 노출 |
| 저장과 조회의 조합 효과가 있는가 | 같은 경험의 은행과 조회 정책을 교차 |
| 어떤 이득과 손해가 생기는가 | 실패 회복·성공 악화·부분 진척, 같은 과제와 새 과제의 차이 |
| 기억이 누적되면 무엇이 달라지는가 | 체크포인트별 개선·이전 과제 유지·회귀·순서 변동 |
| 효과를 얻기 위해 어떤 비용이 필요한가 | 작성·갱신·조회·가공·수행의 전체 비용과 반복 사용 |

저장·조회·반복·전이·누적 변화·득실·비용을 전체 연구 범위로 유지한다. 구현 순서와 연구 범위는 구분한다.

## 현재 방향

| 항목 | 기준 |
| --- | --- |
| 초기 작업자 | Luna를 같은 정책 비교 안에서 고정. 가중치는 갱신하지 않음 |
| 사용자 시뮬레이터 | 사용자 지정 DeepSeek V4.1 Flash 1017. 실제 역할별 경로와 파라미터는 [연결 설정](../development/tau2-connection.md)에서 확인 |
| 초기 환경 | τ²-bench. 실제 버전·도메인·과제와 사용자 설정은 실행 전에 고정 |
| 확장 목표 | AppWorld·BFCL 어댑터와 환경별 공식 채점의 연결 |
| 초기 절차 | 1회차 경험과 기억 작성 후, 2회차 새 세션에서 선택·활용 평가 |
| 후보 풀 | 원천별로 작성한 동일 기억의 자기 경험 은행과 혼합 은행 비교 |
| 추가 절차 | 자연 누적·동일 경험·저장/조회 교차·체크포인트·내용 개입 |
| 도구 | 자율 저장·갱신·목록·본문 조회. 제목도 기억 노출 |
| 제약 | 저장 용량·읽는 양·실행 중단을 구분. BM25·임의의 2k 배분을 기본 가정으로 두지 않음 |

기존 설정의 Luna 모델 ID는 초안에 기록하되, 실제 제공 경로·반환 모델·추론·출력 설정은 실행 시 확인·보존한다. 준비되지 않은 초안을 실제 실행으로 취급하지 않는다.

## 우선 실험할 질문

2026-11-18에 정리한 우선순위는 **1회차 벤치에서 겪은 일을 어떤 형태로 남겼을 때 2회차 벤치의 전체 과제가 더 자주 성공하는지, 어떤 행동에서 성공과 실패가 갈리는지** 확인하는 것이다. 앞선 48요청은 기억을 읽은 직후의 예약 판단을 관측했다. 고객 선호를 다시 쓰는 과제나 예약 직전 한 응답을 보는 실험은 특정 행동을 자세히 살펴볼 진단 사례로 활용한다. [48요청 관측 결과](../reports/20261118-written-replay-48-results.md)

[다음 실험 설계](two-pass-memory-forms-v1.md)는 기존 항공 벤치의 28개 경험을 원천으로 고르고, 네 작성 형태와 새 무기억 에피소드를 짝지었다. 원천 식별자와 공개 입력 해시, 두 번의 독립 작성·수행 블록은 [배정 명세](../../protocols/drafts/tau2-two-pass-memory-forms-v1.json)에 있다.

첫 비교안에서는 Luna가 τ² 여러 과제를 실제 수행한 뒤, 성공한 경험과 실패한 경험 각각의 공개 대화·도구 기록을 네 개의 독립된 작성 세션에 똑같이 제공한다. 작성 시점, 공개 피드백, 모델 설정과 허용 예산을 맞추고 무엇을 남길지는 Luna가 고른다.

| 작성 지침 | 모델이 남길 수 있는 내용 |
| --- | --- |
| 단순 정보 | 관찰한 사실, 값, 누구에게 어떤 조건이 적용됐는지 |
| 에피소드·일기 | 어떤 상황에서 무엇을 시도했고 그 뒤 어떤 응답이나 결과가 있었는지 |
| 교훈 | 경험에서 얻은 원칙이나 주의점, 그 교훈이 적용되는 조건 |
| 절차 | 비슷한 일을 다시 할 때의 확인 순서, 조건별 행동과 멈춰야 할 시점 |

같은 출처 집합으로 형태별 기억 은행을 만든다. 빈 작성, 사실 오류, 형태 사이에 겹치는 내용까지 원래 배정에 포함한다. **첫 2회차 비교안**은 각 조건에서 같은 벤치 과제를 새 세션·초기 업무 상태로 다시 수행하는 것이다. 형태별로 같은 범위의 기억을 시작 시 제공하고 업무 지시·도구·종료 한도를 맞춘 뒤 실제 대화와 도구 실행을 공식 채점까지 이어간다. 같은 과제의 무기억 반복을 기준으로 두고, 공개 원기록 접근과 일반 요약은 작성 방식의 추가 가치를 읽기 위한 별도 기준선으로 둔다. 과제 구성에는 사실 재사용, 앞선 행동의 맥락, 조건에 따른 절차가 중요한 사례를 포함한다. 다음 비교에서는 확정한 은행을 새 과제에 적용해 전이를 보고, 같은 은행을 자율 조회에 연결한다. [비교 단위와 기준선](experiment-protocol.md)

형태별 이득은 동일한 2회차 과제에서의 **무기억 대비 공식 성공률 차이**로 읽는다. 무기억에서 실패하고 기억 조건에서 성공한 경우와 그 반대의 경우를 과제별로 함께 센다. 판단 근거가 1회차에 있었는지, 실제 기억과 2회차 입력에 남았는지, 어느 질문·도구 인수·승인에서 경로가 갈렸는지, 최종 상태가 어땠는지를 연결해 사례를 해석한다. 같은 출처·기억의 반복을 식별하고 실제 기억 길이와 작성부터 수행까지의 비용도 보고한다. 여기서 측정하는 것은 각 작성 지침으로 모델이 선택한 내용과 표현을 합한 효과다. 이 우선순위에 따른 네 형태의 2회차 성과 비교는 제안 단계다.

## 기여 목표

| 목표 | 산출물과 검증 근거 |
| --- | --- |
| 평가 프레임워크와 비교 자료 | 정책·벤치 연결, 기억 버전·노출·행동·결과가 연결된 기록. 같은 조건의 비교와 재계산 가능성 |
| 측정과 진단의 타당성 | 실행 변동을 구분한 득실·진척·기억 품질·전이·비용, 주석과 개입의 일치·설명력 |
| 실증적 발견 | 저장·조회 조합이 언제 회복·회귀·효율 차이를 만드는지 반복·통제 비교와 새 과제로 검증 |

자율 생성 기억의 변경·선택·노출과 후속 수행을 연결하는 분석의 추가 가치를 검증한다. 도구 제공·세션 분리·여러 벤치 지원·새 지표의 개수만으로 신규성을 주장하지 않는다. 가까운 비교 대상은 [관련 연구](related-work.md)의 MemTools·EvoMemBench·BFCL V4 Memory 등이다.

## 얻고자 하는 효과

- 과제에 맞는 저장 시점·내용·조회 방식을 성능·회귀·비용과 함께 선택할 근거.
- 경험 부재·저장 누락·미조회·늦은 노출·부적합 적용을 조사할 기록과 개입 근거.
- 같은 과제의 개선이 전이·누적 안정성으로 이어지는지 판단할 자료.
- 다른 기억 정책의 비교와 후속 정책 개선에 사용할 재현 가능한 계약·예시·원본 연결.

가설 예로는 수행 중의 추측이 종료 후 정리에서 교정되거나 강화되는 경우, 요약에서 적용 조건이 빠져 조건 변경 과제에 손해를 주는 경우, 정확한 기억을 읽고도 행동에 반영하지 못하는 경우가 있다. 이는 앞으로 검증할 현상이며 현재 관측 결과가 아니다. 효과가 작거나 없으면 불확실성과 검증 범위를 함께 보고한다.

## 실행 전 확정할 항목

벤치 commit·과제/출처 분할, 모델 설정, 작성·조회 지침, 피드백, 저장·호출·시간·금액 규칙, 독립 은행·순서·반복 수, 진척·근거 주석, 통계 방법과 비용 배분을 확정한다.

구체적인 비교는 [실험 프로토콜](experiment-protocol.md), 지표는 [측정과 분석](metrics.md), 구현 경계는 [상세 설계](../design/architecture.md)를 따른다. 현재 파일 코어·가짜 흐름과 [무기억 연결](../development/tau2-connection.md)·[native 기억 두 회차 연결](../development/tau2-memory.md)이 있으며 자율 기억 정책 효과의 실증은 아직 수행하지 않았다.
