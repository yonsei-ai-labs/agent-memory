# 연구 계획

2026-11-14 · 새 프로젝트의 연구 기준

**같은 LLM이 경험을 어떻게 기억으로 저장하고 선택·조회하느냐에 따라 후속 작업의 성공·실패·진척·비용이 어떻게 달라지는지 측정한다.** 평가 프레임워크·측정 절차·실증 분석을 연구 산출물로 삼는다.

연구 제목은 「LLM 에이전트의 메모리 저장·조회 방식에 대한 평가 프레임워크」다. 영문 작업 제목은 *A Framework for Evaluating Memory Writing and Retrieval in LLM Agents*다.

## 문제와 연구 질문

경험은 계속 늘어나지만 각 판단에 사용할 문맥과 처리 비용에는 한계가 있다. 무엇을 남기고 언제 어떤 기억을 불러올지가 중요하다. 여러 방법이 제안돼 있으므로, 과제·정보·비용 조건에 따라 어떤 저장·조회 조합이 이득과 손해를 만드는지 비교한다.

최종 성공률만으로는 경험에 정보가 없었는지, 저장에서 빠졌는지, 조회되지 않았는지, 입력에 들어와도 잘못 활용됐는지 구분하기 어렵다. 같은 과제 복구와 새 과제 전이, 평균 개선과 일부 과제의 악화도 별도로 본다.

| 연구 질문 | 대응 비교와 관측 |
| --- | --- |
| 언제 무엇을 저장하는 것이 유리한가 | 수행 중·종료 후·병행, 표현 형태, 공개 경험과 생성된 본문 |
| 무엇을 언제 읽는 것이 유리한가 | 시작 제공·자율 조회·병행, 원문과 재가공, 실제 입력 노출 |
| 저장과 조회의 조합 효과가 있는가 | 같은 경험의 은행과 조회 정책을 교차 |
| 어떤 이득과 손해가 생기는가 | 실패 회복·성공 악화·부분 진척, 같은 과제와 새 과제의 차이 |
| 기억이 누적되면 무엇이 달라지는가 | 체크포인트별 개선·이전 과제 유지·회귀·순서 변동 |
| 효과를 얻기 위해 어떤 비용이 필요한가 | 작성·갱신·조회·가공·수행의 전체 비용과 반복 사용 |

저장·조회·반복·전이·누적 변화·득실·비용을 전체 연구 범위로 유지한다. 구현 순서와 연구 범위는 구분한다.

## 실험자와 플랫폼의 역할

실험자는 기억의 저장 형식, 무엇을 남길지 지시하는 작성 프롬프트, 2회차에서 기억을 조회하는 시점·선택 방법·반환 형식을 조정한다. 예를 들어 같은 1회차 경험과 일기 형식을 유지하면서 작성 프롬프트만 바꿀 수 있다. 조회 방식의 영향을 볼 때는 같은 기억 은행을 사용한다. 여러 설정을 함께 바꿨으면 그 조합의 효과로 해석한다.

플랫폼의 역할은 이 조건으로 벤치를 반복 실행하고, 나중에 새로운 질문으로 다시 분석할 수 있도록 근거를 보존하는 것이다. 각 실행의 설정과 프롬프트 버전, 1회차 원천 경험, 실제 작성물, 조회 요청·반환 내용, 2회차 모델 입력에 포함된 내용, 이후 대화·도구 행동·공식 성적·비용을 연결한다. 실험자는 성공을 얻거나 잃은 지점에서 원본을 열어 고객의 요청이나 승인도 함께 달라졌는지 확인하고, 가능한 원인을 좁혀 후속 비교를 설계한다. [성공을 얻은 사례](../reports/20261118-two-pass-memory-success-factors.md) · [성공을 잃은 사례](../reports/20261118-two-pass-memory-failure-factors.md)

1. **과제를 고를 때 기억을 쓸 기회부터 적는다.** 예약·변경·취소 등 여러 업무에서 지난 사실이 그대로 유효한 경우, 값이나 대상은 바뀌어도 확인 절차를 옮겨 쓸 수 있는 경우, 적용 조건이 달라져 이전 행동을 보류해야 하는 경우를 포함한다. 현재 입력과 도구만으로 충분한 경우도 비교에 남긴다. 예컨대 결제에서는 잔액이 달라져도 확인 순서가 유효할 수 있고, 취소에서는 겉보기 일정이 같아도 탑승객과 고객 승인 범위가 달라질 수 있다. 과제별로 1회차의 공개 근거와 2회차에 다시 확인할 조건을 결과를 보기 전에 적는다. 각 유형에 서로 다른 고객·과제를 넣고, 이미 상세 분석한 고객·과제군은 설계용으로 표시한다. 평가용 고객·유사 과제군은 따로 고른다. [결제와 취소에서 관측된 행동](../reports/20261118-two-pass-memory-success-factors.md) · [승인과 검색 결과 확인에서 갈린 행동](../reports/20261118-two-pass-memory-failure-factors.md)
2. **먼저 여러 과제의 재수행에서 네 작성 지침을 비교한다.** 보존한 1회차 공개 기록과 형식별 독립 작성물을 활용하고, 메모 하나를 고정해 새 세션·초기 업무 상태에서 2회차 전체 에피소드를 여러 번 수행한다. 새로 작성할 때도 작성자는 1회차 공개 기록을 받고 과제 분류·공식 정답은 분석자가 보관한다. 첫 비교에서는 작성한 본문을 모두 시작 시 제공한다. 빈 메모 대조에는 같은 안내를 보내고, 벤치 기본 입력만 주는 순수 무기억 대조도 반복한다. 빈 작성도 배정에 포함한다. 이 설계는 작성할 때마다 달라지는 내용과 같은 메모로 다시 풀 때 생기는 변동을 각각 관측할 수 있다. 1회차 성적별 **회복·성공 유지**와 2회차의 **무기억 대비 개선·악화**를 과제별로 보고한다. 과제별 성공률 차이를 같은 가중치로 요약하고, 같은 고객·은행의 반복을 묶어 불확실성을 표시한다. 같은 점수에서의 진척·비용, 미채점·미시작도 남긴다. [원래 두 회차 설계](two-pass-memory-forms-v1.md) · [측정 단위와 분모](metrics.md)
3. **여러 과제에서 되풀이된 차이를 한 요인씩 검증한다.** 첫 비교에는 형식별 지침이 무엇을 골라 썼는지까지 반영된다. 표현이 원인 후보면 같은 공개 사실·조건을 네 방식으로 표현하고, 필요한 조건이 자꾸 빠지면 형식을 고정해 작성 프롬프트만 바꾼다. 저장된 내용이 작업자에게 도달하는지가 문제라면 같은 은행을 시작 제공과 자율 조회에 교차 배정한다. 전이는 미리 고른 다른 과제에서 같은 은행을 써 보고, 그 과제의 새 무기억 대조와 비교해 별도로 보고한다. 각 비교에서 플랫폼은 원천 → 실제 저장 → 작업자 입력에 들어간 제목·본문 → 고객과의 대화·도구 행동 → 공식 결과·비용을 연결한다. 첫 행동 재생은 이 흐름에서 구체적인 갈림길을 설명하는 보조 진단으로 쓴다. [프롬프트·조회 방식 비교 경로](../development/prompt-comparison.md) · [전이와 누적까지의 실험 절차](experiment-protocol.md)

### 앞선 비교에서 얻은 근거

서로 다른 원천·대상 고객 다섯 쌍에서 교훈 형식을 고정하고 재확인 작성 지침만 바꿨다. 저장물에 현재 확인할 값·권한을 명시한 비율은 기존 6/10에서 보완 10/10으로 올라갔고, 전체 에피소드의 공식 성공은 기존 14/20·보완 17/20이었다. 세 개선 중 두 건에서 고객이 선호를 밝힌 시점이나 최종 동의가 달랐다. 한 건에서는 세 예약을 모두 조회한 뒤 가능한 변경을 수행했는지가 갈렸다. 다음 기전 비교에서는 여러 업무에 걸쳐 고객 제약이 실제 대화에 공개되는 시점을 맞추고, 같은 은행의 자유로운 전체 수행도 함께 관측한다. 기존 네 형식과 자율 조회의 비교는 계속 연구 범위에 둔다. [프로토콜·성적·행동 진단](../reports/20261119-scope-lessons.md)

두 사전 후보에서 다른 고객 전이를 실제 48회 수행했다. 네 형식의 무기억 대비 개선·악화는 합계 3·8쌍으로, 개선 3쌍이 같은 대조 실행 하나에서 나왔다. 26번은 공식 성공 23회 중 5회에서 환불 거절 근거를 상담원에게만 보냈다. 18번은 정확한 총절감액을 안내한 20회 중 5회에서 환불할 결제 수단이 틀렸다. 예약별 환불 수단만 고친 재생에서 그 5회 모두 DB 판정이 바뀌었다. 다음 작성 지침 비교에서는 규칙이 적용되는 단위와 현재 고객에게 다시 확인할 값을 메모에 남기는지, 여러 과제의 실제 행동과 최종 결과에서도 달라지는지를 본다. [전이 성적과 행동 비교](../reports/20261119-bank-transfer.md) · [양방향 환불 수단 재생](../../artifacts/analyses/20261119-bank-transfer-refund-replay.json)

다섯 개발 업무에서 1회차의 네 형식 메모 40개를 그대로 반복 제공한 전체 에피소드 120회를 완료했다. 공식 재채점 117건에서 단순 정보와 교훈은 과제 동일가중 무기억 대비 +20·+15%p였고, 일기와 절차는 +1.7·+5%p였다. 함께 채점된 같은 은행 두 실행의 10/38쌍에서 성패가 바뀌었고, 취소 대상 선별의 단순 정보 개선 두 건에는 실제 본문이 없었다. 두 대조를 모두 앞선 8건은 다섯 과제 중 두 곳에 모였다. 이 결과를 토대로 네 형식과 제공 방법을 유지하고 다른 고객에게 옮긴 비교가 위의 0→26번·17→18번 실험이다. [고정 은행 반복 결과](../reports/20261119-fixed-bank-repeats.md) · [배정·전이 후보](../../protocols/pilots/tau2-fixed-bank-repeats-v1.json)

새 항공 고객 여섯 명의 실측에서 1회차 성공을 유지한 횟수는 형식과 대조 조건마다 5/6으로 같았다. 같은 절차 지침도 한 과제의 두 반복에서 양쪽 대조 대비 개선과 악화가 모두 나타났다. 후속 지침은 실패 기록에서 허용된 다른 행동과 고객에게 확인할 조건을 남기는지, 그 기록이 2회차 질문과 정확한 업무 호출로 이어지는지를 측정할 수 있다. [두 회차 비교 설계](new-customer-forms.md) · [성적·행동·양방향 재생 결과](../reports/20261118-new-customer-forms-results.md)

2026-11-18에 정리한 우선순위는 **1회차 벤치에서 겪은 일을 어떤 형태로 남겼을 때 2회차 벤치의 전체 과제가 더 자주 성공하는지, 어떤 행동에서 성공과 실패가 갈리는지** 확인하는 것이다. 앞선 48요청은 기억을 읽은 직후의 예약 판단을 관측했다. 고객 선호를 다시 쓰는 과제나 예약 직전 한 응답을 보는 실험은 특정 행동을 자세히 살펴볼 진단 사례로 활용한다. [48요청 관측 결과](../reports/20261118-written-replay-48-results.md)

[두 회차 실험 설계](two-pass-memory-forms-v1.md)는 기존 항공 벤치의 28개 경험을 원천으로 고르고, 네 작성 형태와 새 무기억 에피소드를 짝지었다. 원천 식별자와 공개 입력 해시, 두 번의 독립 작성·수행 블록은 [배정 명세](../../protocols/drafts/tau2-two-pass-memory-forms-v1.json)에 있다.

같은 단순 정보 형식 안에서 작성 지침 한 문장을 바꾼 [후속 비교](../reports/20261118-fact-recheck-results.md)에서는 기억에 실제로 담긴 내용, 2회차 공식 성적, 구체적인 업무 판단을 연결한다. 이 비교에서 찾은 숫자 표기에 민감한 채점은 공식 성적을 보존한 채 별도 진단한다.

첫 비교안에서는 Luna가 τ² 여러 과제를 실제 수행한 뒤, 성공한 경험과 실패한 경험 각각의 공개 대화·도구 기록을 네 개의 독립된 작성 세션에 똑같이 제공한다. 작성 시점, 공개 피드백, 모델 설정과 허용 예산을 맞추고 무엇을 남길지는 Luna가 고른다.

| 작성 지침 | 모델이 남길 수 있는 내용 |
| --- | --- |
| 단순 정보 | 관찰한 사실, 값, 누구에게 어떤 조건이 적용됐는지 |
| 에피소드·일기 | 어떤 상황에서 무엇을 시도했고 그 뒤 어떤 응답이나 결과가 있었는지 |
| 교훈 | 경험에서 얻은 원칙이나 주의점, 그 교훈이 적용되는 조건 |
| 절차 | 비슷한 일을 다시 할 때의 확인 순서, 조건별 행동과 멈춰야 할 시점 |

같은 출처 집합으로 형태별 기억 은행을 만든다. 빈 작성, 사실 오류, 형태 사이에 겹치는 내용까지 원래 배정에 포함한다. **첫 2회차 비교안**은 각 조건에서 같은 벤치 과제를 새 세션·초기 업무 상태로 다시 수행하는 것이다. 형태별로 같은 범위의 기억을 시작 시 제공하고 업무 지시·도구·종료 한도를 맞춘 뒤 실제 대화와 도구 실행을 공식 채점까지 이어간다. 같은 과제의 무기억 반복을 기준으로 두고, 공개 원기록 접근과 일반 요약은 작성 방식의 추가 가치를 읽기 위한 별도 기준선으로 둔다. 과제 구성에는 사실 재사용, 앞선 행동의 맥락, 조건에 따른 절차가 중요한 사례를 포함한다. 다음 비교에서는 확정한 은행을 새 과제에 적용해 전이를 보고, 같은 은행을 자율 조회에 연결한다. [비교 단위와 기준선](experiment-protocol.md)

형태별 이득은 동일한 2회차 과제에서의 **무기억 대비 공식 성공률 차이**로 읽는다. 무기억에서 실패하고 기억 조건에서 성공한 경우와 그 반대의 경우를 과제별로 함께 센다. 판단 근거가 1회차에 있었는지, 실제 기억과 2회차 입력에 남았는지, 어느 질문·도구 인수·승인에서 경로가 갈렸는지, 최종 상태가 어땠는지를 연결해 사례를 해석한다. 같은 출처·기억의 반복을 식별하고 실제 기억 길이와 작성부터 수행까지의 비용도 보고한다. 여기서 측정하는 것은 각 작성 지침으로 모델이 선택한 내용과 표현을 합한 효과다. 동결한 첫 실행에서 작성 232개를 완료했고, 2회차 43개의 공식 성적과 1개의 미채점을 기록했다. 15번의 절차 조건에서는 변경이 완료됐고 17번의 단순 정보 조건에서는 공개 기록에 맞는 날짜를 작업자가 잘못 해석했다. 보충 실행을 합쳐 11개 과제의 66개 공식 성적과 미채점 4개를 기록했다. 36번은 이관 뒤 종료 신호가 오지 않아 업무 도구의 성공과 공식 채점 가능성이 갈린 사례다. 1회차 실패 원천 네 과제 중 여기서 공식 2회차 성적이 있는 것은 17번 하나다. [첫 실행 결과](../reports/20261118-two-pass-memory-forms-results.md) · [보충 합산 결과 및 전환표](../reports/20261118-two-pass-memory-forms-combined-results.md)

두 번째 보충 뒤에는 28개 과제·22개 고객 그룹에서 실제 2회차 234개를 채점했다. 첫 반복의 1회차 실패 과제 네 개를 대조하면, 일기와 절차가 각각 한 개씩 무기억 실패를 성공으로 바꿨고 두 조건 모두 20번의 무기억 성공을 잃었다. 34개 결과 반전 중 10개는 작성 은행이 비어 있었고, 같은 무기억의 두 반복은 함께 채점한 10과제 중 2개에서 뒤집혔다. 현재 기록은 적용 조건·이번 고객의 승인·실제 DB 행동까지 연결해 주며, 네 형태의 순위를 확정하기에는 미관측 반복과 상호작용 변동이 남아 있다. [세 원본 합산 결과](../reports/20261118-two-pass-memory-forms-final-results.md) · [전체 352개 배정](../../artifacts/analyses/20261118-two-pass-forms-final-cells/second-pass.csv)

자율 생성 기억의 변경·선택·노출과 후속 수행을 연결하는 분석의 추가 가치를 검증한다. 도구 제공·세션 분리·여러 벤치 지원·새 지표의 개수만으로 신규성을 주장하지 않는다. 가까운 비교 대상은 [관련 연구](related-work.md)의 MemTools·EvoMemBench·BFCL V4 Memory 등이다.

## 얻고자 하는 효과

- 과제에 맞는 저장 시점·내용·조회 방식을 성능·회귀·비용과 함께 선택할 근거.
- 경험 부재·저장 누락·미조회·늦은 노출·부적합 적용을 조사할 기록과 개입 근거.
- 같은 과제의 개선이 전이·누적 안정성으로 이어지는지 판단할 자료.
- 다른 기억 정책의 비교와 후속 정책 개선에 사용할 재현 가능한 계약·예시·원본 연결.

가설 예로는 수행 중의 추측이 종료 후 정리에서 교정되거나 강화되는 경우, 요약에서 적용 조건이 빠져 조건 변경 과제에 손해를 주는 경우, 정확한 기억을 읽고도 행동에 반영하지 못하는 경우가 있다. 이는 앞으로 검증할 현상이며 현재 관측 결과가 아니다. 효과가 작거나 없으면 불확실성과 검증 범위를 함께 보고한다.
