# 실험 프로토콜

2026-11-14 · 연구 비교와 통제의 기준

같은 Luna 작업자에서 저장 시점·형태·조회 정책을 비교한다. 초기 실행 환경은 τ²-bench다. 정확한 모델·환경·과제·반복·비용·중단 설정은 [v1.1 초안](../../protocols/drafts/tau2-two-pass-v1.1.json)에서 실행 전에 고정한다.

## 단위와 원천

| 단위 | 정의 |
| --- | --- |
| 과제 | 요청, 초기 업무 상태, 허용 도구, 정책 문서와 채점 기준으로 정의한 작업 |
| 시도 | 초기화된 과제를 한 번 수행한 에피소드 |
| 경험 | 저장 시점까지 공개된 관측·대화·도구 호출과 결과. 종료 후에는 허용된 피드백도 포함 |
| 기억 항목 | 제목·본문을 가진 기록. 수정할 때 이전 버전을 보존 |
| 기억 은행 | 한 조건과 작업 스트림에 속하는 기억 집합과 버전 상태 |
| 작업 스트림 | 정해진 순서로 과제를 수행하며 조건에 따라 은행을 갱신하는 실행 묶음 |
| 체크포인트 | 사전에 정한 작업 진행 시점의 은행과 실행 상태 |
| 분기 상태 | 같은 판단 직전 상태에서 노출이나 기억 내용을 바꾸는 비교의 출발점 |

원천 과제와 그 변형, 한 은행에서 파생한 기억·실행, 독립된 작업 스트림을 식별한다. 여러 기억 파일이나 도구 호출을 독립 표본으로 세지 않는다. 과제 단위 성능과 은행·스트림 단위 불확실성을 구분해 보고한다.

## 실험 요인과 기준선

### 저장 시점

| 조건 | 수행 중 저장 | 종료 후 저장 |
| --- | --- | --- |
| 기억 없음 | 제공하지 않음 | 제공하지 않음 |
| 종료 후 저장 | 허용하지 않음 | 허용 |
| 수행 중 저장 | 허용 | 별도 정리 단계 없음 |
| 수행 중 저장과 종료 후 정리 | 허용 | 허용 |

수행 중 작성한 기억을 같은 시도에서도 읽을 수 있는지는 별도 설정이다. 허용하면 첫 작업의 행동과 수집 경험까지 바뀔 수 있으므로 자연 실행에서는 그 변화도 정책 효과에 포함한다.

### 저장 형태와 조회 정책

| 요인 | 비교 후보 | 기록할 내용 |
| --- | --- | --- |
| 저장 형태 | 자유 형식, 사건 기록, 단순 요약, 사실·조건, 절차·전략, 실패 원인·주의사항 | 배정한 지침, 실제 본문과 구조, 준수 여부, 내용 변화 |
| 조회 시점 | 작업 시작 시, 수행 중 LLM이 필요할 때, 두 방식 병행 | 요청·자동 제공 여부, 최초 노출과 재조회 시점 |
| 조회 후 처리 | 본문 그대로 사용, 현재 과제에 맞춰 재가공 | 입력 원문, 가공한 내용, 추가 호출·비용 |
| 피드백 | 작업 중 관측만, 실제 사용자 피드백, 사전 정의한 종료 결과 피드백 | 모델에게 공개한 정보의 정확한 범위 |
| 검증 환경 | 벤치·도메인·과제 유형·모델·작업 순서 | 버전, 설정, 출처 그룹과 배정 |

저장 시점·형태·조회 정책의 유효한 조합을 교차 비교한다. 기억이 없는 조건의 저장 형식처럼 의미가 없는 조합은 별도 실험 수로 부풀리지 않는다. 실험 행마다 고정한 요인과 변경한 요인을 명시하고, 구체적인 수준·조합·반복 수는 검토 후 확정한다.

같은 정책 비교에서는 작업자 모델·추론 설정·허용 업무 도구·과제 집합을 맞춘다. 모델·벤치가 달라지는 비교는 별도의 분석 블록으로 두어 모델 능력 차이를 기억 정책 효과로 합치지 않는다.

### 공통 기준선

| 기준선 | 목적과 정보 조건 |
| --- | --- |
| 기억 없는 반복 | 같은 횟수의 재시도에서 자연적인 성공 변동 확인. 과거 대화·노트는 다음 시도로 넘기지 않음 |
| 원경험 기록 접근 | 같은 공개 경험을 원문으로 보존하고 접근하게 하여, 기억 작성·표현의 추가 효과 비교 |
| 단순 요약 | 같은 경험을 정해진 요약 지침으로 저장해 자율 작성·다른 형태와 비교 |

원기록·요약 기준선의 목록·본문 노출과 조회 경로를 명세한다. 현재 과제의 정답이나 공개하지 않은 채점 정보가 과거 경험에 추가되지 않게 한다. 문맥에 원기록 전체가 들어가지 않을 때는 접근 가능한 저장소와 읽기 규칙을 명시한다.

성능과 전체 비용은 함께 보고한다. 자연 실행의 비용 차이를 포함한 정책 비교와, 동일 경험·정보 접근 조건에서 표현이나 조회의 영향을 보는 비교를 구분한다. 별도 계산량 통제 분석을 한다면 그 통제 조건도 독립된 실험 행으로 둔다.

## 두 회차와 확장 절차

### 경험 수집과 독립 평가

```mermaid
flowchart LR
    A[1회차 과제 집합] --> B[조건별 수행과 기억 작성]
    B --> C[은행 스냅샷 고정]
    C --> D[2회차 과제별 은행 복제]
    D --> E[새 세션에서 목록 선택 조회]
    E --> F[후속 수행과 평가]
    F --> G[복제본 변경 종료]
```

1. 실행 전에 출처 그룹·수집 과제·재시도 과제·관련 새 과제·조건 변경 과제를 구분한다. 같은 과제 재시도는 허용하되 새 과제로의 일반화 점수에 합치지 않는다.
2. 조건·순서·독립 반복별 은행을 만들고, 정책 간 같은 과제 순서를 배정한다. 초기 선택 실험은 원천 과제별 은행을 독립 작성하며 누적 수집은 별도 절차로 둔다. 각 과제의 업무 상태·에이전트 대화·사용자 시뮬레이터를 새로 초기화한다.
3. 1회차에서 LLM이 허용된 기억 도구를 사용한다. 수행 중 작성은 현재까지 공개된 경험만 참조하고 종료 후 작성은 정해진 공개 경험·피드백만 참조한다.
4. 수집 완료 은행을 불변 스냅샷으로 고정한다. 실제 항목 수 N, 제목·본문 크기, 버전과 경험 출처를 보존한다.
5. 2회차의 각 과제·반복은 같은 시작 스냅샷에서 별도 은행을 복제한다. 대화·업무·사용자 상태를 초기화하고 외부 기억을 통해 과거 정보에 접근한다.
6. 평가 중 저장이 허용된 정책은 복제본을 갱신한다. 그 변경은 원은행·다른 평가 과제·이후 본실험으로 돌려보내지 않는다.
7. 무기억도 같은 과제 배정·재시도 횟수로 수행한다. 배정 전체의 결과와 실패·결측을 보존한다.

초기 과제·업무 상태와 배정은 맞추되, 같은 사용자 seed가 에이전트 행동이 달라진 이후에도 동일한 대화를 보장한다고 가정하지 않는다. 실제 사용자 관측과 분기를 원본에 남긴다.

평가 때 공개되는 정책 문서·도구 설명 등 환경의 기본 지식은 동일하게 제공한다. 세션 분리는 과거 에피소드 이력의 분리이며 현재 과제에 필요한 정상적인 입력을 없애는 뜻이 아니다. 이전 provider 대화 ID·응답 연결 ID·에이전트 내부 상태도 새 세션에 재사용하지 않는다.

### 자기 경험과 혼합 은행

| 은행 구성 | 평가 질문 | 구성 규칙 |
| --- | --- | --- |
| `own_experience` | 해당 과제의 경험 기억을 후속 시도에서 적절히 재사용하는가 | 분석용 원천 관계로 접근 범위를 정하되 모델에게 정답 항목을 표시하지 않음 |
| `mixed_experience` | 여러 과제에서 작성한 N개 항목 중 현재 조건에 맞는 정보를 선택하는가 | 출처 포함 규칙·배정·목록 순서를 실행 전에 고정. 다른 과제의 기억도 유용할 수 있음 |

관련 기억이 없는 과제에서는 조회하지 않거나 활용을 보류하는 선택도 평가한다. N은 살아 있는 항목 수이며 버전 수·저장 정보량과 다르다. 자연적으로 생성된 N·본문량·목록량의 차이를 포함한 정책 효과와, 크기를 통제한 별도 진단을 구분한다.

순수한 후보 풀 효과를 비교할 때는 원천 과제별로 독립 작성한 동일 기억들을 사용한다. 자기 경험 은행과 그 은행들을 합친 혼합 은행을 만들고, 합치는 과정에서 LLM 재작성·자동 병합을 하지 않는다. 여러 과제를 거치며 이미 갱신된 기억에서 출처 표시만 필터링해 자기 경험을 분리했다고 가정하지 않는다. 과제 간 기억을 공유하며 수집하는 방식은 `continual`에서 별도로 비교한다.

### 추가로 지원할 실험 절차

| 절차 | 고정·변경하는 것 | 해석 |
| --- | --- | --- |
| `continual` | 과제마다 업무·대화는 초기화하고 은행은 순서대로 갱신 | 행동·경험 수집까지 포함한 누적 정책 효과 |
| `common_experience` | 같은 공개 궤적에서 여러 작성 정책으로 은행 생성 | 주어진 경험에서의 표현·작성 효과. 수행 중 작성에는 궤적 접두부만 제공 |
| `write_read_cross` | 공통 경험의 은행 A·B를 조회 정책 X·Y와 교차 | 저장·조회 조합 효과 |
| `checkpoint_probe` | 누적 중 사전 지정 시점의 은행을 복제해 같은 확인 과제 평가 | 개선 속도와 이전 과제 유지·회귀 |
| `intervention` | 최초 기억 정보 노출 전의 동일 상태에서 제공·보류·내용 교정 | 해당 상태의 개입 효과. 연구자 교정 조건은 자율 정책 성적과 구분 |

고정 은행을 읽기만 하는 진단은 별도 설정이다. 기본 평가에서 모든 정책의 쓰기를 일괄 중지하지 않는다. 은행 교환은 저장 형식·후보 정보·권한을 비교 가능하게 맞춘 경우에 수행하고, 형식 변환이 필요하면 변환 정책·내용·비용을 추가 실험 요인으로 기록한다.

## 동일 경험 저장 비교의 세부

동일한 공개 수행 기록에서 여러 저장 정책으로 은행을 만든다. 수행 중 저장에는 기록의 해당 시점 접두부만 제공하고, 종료 후 저장에는 전체 공개 기록과 허용된 피드백을 제공한다. 이때 작성한 기억은 원래 수행 기록의 행동을 바꾸지 않는다.

생성한 은행을 같은 작업자·조회 정책·후속 과제에 적용한다. 저장 과정의 추론·노출·비용 차이를 기록하며, 원기록과 단순 요약 기준선도 같은 원천 경험을 사용한다. 이 비교는 주어진 경험에서의 저장 방식 효과이며 자연 실행 전체를 대체하지 않는다.

경험 출처는 결과를 보고 유리한 사례만 고르지 않는다. 성공·실패 경험을 선별하는 정책을 시험한다면 선별 규칙을 명시하고, 원천 과제·파생 변형은 같은 출처 그룹으로 관리한다.

구체적인 첫 실증 후보로 [일반 요약과 적용 조건·절차 기억 파일럿](condition-sensitive-pilot.md)을 제안한다. 같은 기록의 종료 후 작성·시작 시 제공을 고정한 저장 진단이며, 이후 조회 교차·선택적 적용 가능성 필터로 확장한다. 기존 네 저장 시점·자율 조회·누적 절차를 대체하지 않으며 현재 실행 설정은 미확정이다.

### 저장과 조회를 교차하고 내용을 개입하는 평가

저장 정책 A와 B에서 만든 은행을 각각 조회 정책 X와 Y에 적용해 조합 효과를 비교한다. 같은 출발 은행에서 어떤 기억을 요청·반환·노출했는지 기록한다.

원인을 확인할 때는 최초 정보 노출 직전의 동일 상태에서 제공·보류·본문 교체·적용 조건 변경 등을 비교한다. 앞서 제목이나 요약으로 제공한 정보를 본문 보류만으로 제거했다고 해석하지 않는다. 편집으로 달라지는 분량·표현·출처 표시도 보존한다.

연구자가 정답 정보를 사용해 교정한 기억은 진단용 개입으로 구분하며 자율 작성 정책의 성적으로 합치지 않는다. 국소 개입 효과는 해당 상태와 나머지 기억 조건에 대한 결과이며, 기억 항목 하나의 보편적 가치로 해석하지 않는다.

### 체크포인트에서 전이와 누적 회귀를 평가

사전에 정한 작업 진행 시점마다 은행을 보존한다. 같은 과제 재시도, 관련 새 과제, 중요 조건이 다른 과제의 성능과 이전에 풀던 과제의 회귀를 구분한다. 평가 시점이나 과제 집합을 관측된 최고 성적에 맞춰 사후 선택하지 않는다.

확인용 과제마다 같은 시작 은행을 복제하고 설정된 저장·조회 정책을 수행한다. 평가 중 변경은 원은행·다른 확인 과제·이후 본실험에 반영하지 않는다. 저장을 중지한 고정 은행 판독 진단은 별도 조건이다. 작업 순서와 독립 스트림을 반복해 은행 한 개에서 나온 결과에만 의존하지 않는다.

메모리를 이어받는 반복은 일반 τ²-bench의 독립 반복과 다른 설정이므로, 공식 `pass^k`와 섞지 않고 메모리 적응 실험으로 보고한다. [공식 반복 평가 설명](https://github.com/sierra-research/tau2-bench/blob/main/docs/glossary.md)

## 보정 실행과 비교 계획

첫 실제 실행 후보는 기억 없는 반복이다. 어댑터·채점·기록의 연결을 확인하고 과제별 성공 확률·자연적인 반전·비용을 추정한다. 반복 수는 아직 정하지 않는다. 이 분산만으로 표본 크기가 정해지지는 않는다. 최소 관심 효과, 독립 은행/출처 수, 과제 짝과 반복의 의존성, 목표 불확실성·검정력을 함께 검토한다. 1차 비교·지표와 다중 비교 처리 방식을 사전에 정하고 나머지는 탐색으로 구분한다. 실제 분석 계획은 [측정 문서](metrics.md)를 따른다.

조건을 모아서 순서대로 돌리면 시간대·제공자 변화·호출 제한이 조건과 얽힐 수 있다. 출처/반복 블록 안에서 조건을 무작위로 섞고 seed·예정 순서·실제 시작/종료 시각·재시도를 남긴다. 실패나 결측 때문에 조건을 사후 재배정하지 않는다.

| 선택적 대조 | 확인할 질문과 해석 범위 |
| --- | --- |
| 같은 기억 도구/지침에 빈 은행 제공 | 도구·지침·조회 행동의 부담과 실제 기억 내용의 차이를 분리. 완전히 무기억인 기준선도 유지 |
| 표현마다 여러 작성 문구 | 문구 하나의 효과인지 확인. 하나만 쓰면 결론을 그 문구에 한정 |
| seed로 고정한 목록 순열 | 생성/수집 순서와 위치 효과의 얽힘 확인. `creation_then_id`를 몰래 교체하지 않고 실제 위치 기록 |
| 결과 피드백 제공 여부 | 실패 경험이 피드백 없이 전파되는 경우와 구분. `observations_only`도 유효한 정보 조건 |

이 대조들을 전부 첫 코어의 필수 조건이나 모든 요인의 완전 교차로 넣지는 않는다. 파일럿의 주 질문과 비용에 맞춰 선택하며 선택·배정·범위는 실행 전에 적는다. 공식 split과 사용자 시뮬레이터·캐시·native 한도의 고정은 [실행 준비 계약](../design/core-contracts.md#4-v11과-실제-실행-준비)을 따른다.

### 사후 작성 분기의 비용

수행 단계의 실제 지침·도구·모델/사용자 설정·한도·기억 상태와 공개 궤적이 같으면, 종료 뒤 그 상태를 복제해 여러 사후 작성 지침으로 분기할 수 있다. 종료 후 표현 변형이나 수행 중 작성과 병행 작성의 사후 단계 비교에 해당한다. 조건 이름이 비슷하다는 이유만으로 경험을 공유하지 않는다. v1.1의 단계별 지침 해시로 수행/사후 차이를 분리하고, 같은 수집 비용은 실제 지출에서 한 번만 센다. 분기들은 독립 수집 표본이 아니다.

평가 후 변경을 폐기하는 프로토콜에서는 사후 작성 생략이 가능한 진단 profile을 후속으로 검토한다. 기본 `follow_condition_discard_clone`은 유지한다. 생략한 비용으로 완전한 정책의 운영 비용을 주장하지 않으며, 결과·진단에 미치는 영향과 생략 범위를 기록한다. 이 옵션과 분기 실행기는 아직 구현 전이다.

## 판정과 기록

2회차 무기억 비교와 독립 반복으로 재실행 변동을 확인한다. 원천 과제 재시도, 관련 새 과제, 조건 변경 과제, 독립 출처로의 전이를 구분한다. 현재 과제 ID와 기억 출처 ID의 일치를 선택 정답으로 쓰지 않는다.

작업자의 과거 정보는 외부 기억을 통해 전달한다. 채점 정답·미래 관측·분석 주석은 숨기며 제목·목록도 노출로 기록한다. 기록·은행·도구의 구현 계약은 [상세 설계](../design/architecture.md), 공식 결과와 측정은 [지표](metrics.md)를 따른다.
