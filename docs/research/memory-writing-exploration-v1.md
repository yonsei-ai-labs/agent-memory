# 같은 경험에서 피드백별 기억 작성: 첫 실측

2026-11-17 · 작성 탐색 프로토콜 · 실행 결과는 별도 기록

첫 질문은 같은 공개 경험에서 Luna가 무엇을 남기며, 성공/실패 결과 한 비트가 그 내용을 어떻게 바꾸는가다. airline 14번 두 번째 반복의 종료된 무기억 경험을 고정하고 `none`·`result_only`를 각각 다섯 번 작성한다. 이 원천은 실패 검토로 고른 개발 사례이며 확인용 표본이 아니다.

실행 수치와 자산 해시는 [전용 프로필](../../protocols/pilots/tau2-memory-writing-10-v1.json)을 기준으로 한다. 모델·reasoning low·출력 상한·모델 seed는 연결 프로필에서 고정한다. 배정 순서 seed와 모델 seed는 별개다. 같은 모델 seed의 반복이 독립 난수를 보장하지 않으므로 결과는 이 조건의 탐색 관측으로 보고한다.

## 절차와 종료

1. 같은 공개 문맥·작성 지침에 피드백만 바꾼다. `result_only`는 실제 source의 성공/실패 boolean만 추가한다. 비평은 제공하지 않는다.
2. 반복마다 두 조건의 순서를 정해 둔 seed로 섞고, 새 세션·빈 은행에서 시작한다. 사용자 시뮬레이터·업무 도구·결정 재전송을 새로 호출하지 않는다.
3. 호출·시간·금액·용량 한도를 적용하고 모든 완료·빈 작성·오류·생략을 보존한다. 오류가 난 배정을 유리한 결과로 대체하지 않는다. 지침이나 한도를 실행 중 바꾸지 않는다.
4. 각 snapshot을 보존된 결정 요청에 넣어 크기를 검사한다. `replay_eligible`은 후속 입력 가능성을 뜻한다. 실제 재전송이나 기억 효과의 관측으로 세지 않는다.
5. 원본·비용·모델/제공자·피드백·배정·입력 포함을 감사한 뒤 내용 검토와 조건별 기술 통계를 작성한다.

실행 전 고정 자료는 profile·source log 해시·지침·연결 자산·구현 commit·선택 endpoint다. 현재 공개 catalog 검증은 유료 생성 호출과 구분하고, 실제 실행기에서도 endpoint를 다시 확인한다. 비용 상한은 이번 실행에 대해 별도로 정하며 이전 실험의 한도를 전용하지 않는다.

## 내용을 보기 전에 정한 검토 항목

각 은행을 한 단위로 검토하고, 항목 수·저장 호출 수·최종 본문 bytes를 함께 기록한다. 여러 항목을 쓴 한 은행을 독립 표본 여러 개로 세지 않는다. 동일한 문장이 반복되면 중복도 함께 표시한다.

| 항목 | 관찰 기준 |
| --- | --- |
| 수하물 규칙 | 무료 허용량과 고객이 실제 요청한 수량을 구분하는가 |
| 적용 조건 | 수하물이 불필요한 상황의 행동을 조건과 함께 남기는가, 모든 예약에 같은 수량을 강제하는가 |
| 확인 절차 | 변경 전 구체적 수량·내용 확인을 남기는가 |
| 경험 충실성 | 관측하지 않은 결과·가격·예외를 새로 만들어 내는가, 잘못된 행동을 권장하는가 |
| 과제 특정 정보 | 고객/예약 ID·날짜·원천 숫자에 의존하는가. 이 표시는 전이 위험 후보이며 실제 손해 판정은 아니다 |
| 다른 재사용 내용 | 수하물 외 규칙·절차를 남기는가. 수하물 언급이 없다고 곧바로 기억 전체를 무용하다고 판정하지 않는다 |

본문을 읽는 단계에서는 조건명·피드백을 가린 표시용 case ID를 사용하고, 주석을 저장한 뒤 조건과 연결한다. 같은 분석 에이전트가 원자료에 접근할 수 있으므로 이를 독립적인 사람/모델 평가로 보고하지 않는다. 해석은 잠정 주석이며 독립 검토는 후속이다.

기억 0개는 저장 호출이 없었던 경우와 호출 후 0개인 경우를 구분한다. 잘림·호출 한도·용량 거절·인수 오류·비용 미확인을 내용 선택의 실패와 섞지 않는다. 부분 작성과 용량 초과도 전체 배정 분모에 남기고, 본문을 고치거나 좋은 기억만 골라 작성 정책의 성과로 보고하지 않는다.

## 해석과 다음 단계

조건별로 작성 상태·기억 수/크기·대상 규칙 포함·과잉 일반화 후보·비용을 기술한다. 작은 단일 source의 관측으로 피드백의 일반 효과나 업무 성공률 차이를 확정하지 않는다.

모든 조건에서 빈 작성·주제 이탈이 많으면 작성 지침과 입력의 전달을 검토한다. 재사용할 내용이 관측되면 빈 기억·일반 주의 메모·원래 옳았던 상태를 포함한 결정 재전송을 별도 설계한다. 오류 교정과 새 훼손을 함께 본 뒤 전체 에피소드 확인으로 연결한다. 이번 작성 탐색은 자율 조회의 선택성이나 새 정보 전이를 검증한 것으로 대체하지 않는다.
