# 결정 지점 재전송: 첫 120요청 실행 프로토콜

2026-11-16 · 첫 유료 요청 전에 고정 · 개발 진단

사용자는 8지점×5회×3조건, 총 120요청·보고 비용 상한 $0.50 제안에 “응 한번 해봐”라고 실행을 지시했다. [별도 ready 프로필](../../protocols/pilots/tau2-decision-replay-120-v1.json)을 사용하며 기존 draft·과거 원본과 예산을 전용하지 않는다.

## 목적과 배정

고정된 worker 요청에서 원래 오류가 새 반복에서도 나타나는지, 추론 강도와 연구자 절차 메모가 다음 응답을 어떻게 바꾸는지 탐색한다. 역사적 실패를 기준 오류율로 쓰지 않고 새 `original` 조건과 비교한다. 전체 회차 성공·전이·자율 생성 기억의 효과를 측정하는 실행이 아니다.

provider prefix 캐시는 사용량에 남긴다. 별도 전체 응답 캐시나 재시도 경로는 쓰지 않는다. 동일한 원래 seed를 반복해도 독립 표본을 보장하지 않는다. 금액 guard는 가격 메타데이터와 사전 예약·관측 비용에 기반하며 제공자의 절대 결제 한도 기능은 아니다.

출력은 새 폴더 `runs/tau2-decision-replay-luna-120-01`이다. 알려지지 않은 비용·서비스/모델/연결 오류가 발생하면 자동 재시도하지 않고 남은 배정을 생략한다. 한도에 걸리면 오류/누락을 유지한다. 유리한 결과를 얻기 위한 재개·조건 수정·반복 증가는 하지 않는다.

## 판정 기준

[구현과 판정 범위](../development/decision-replay.md)의 기준을 함께 고정한다. 14·23·21의 45개 응답은 필요한 수량·예약당 증서 수·여정 시각 순서라는 좁은 검사다. 인수 검사 통과를 완전한 업무 정답으로 보고하지 않으며, 대상 쓰기 없음·추가 조회·확인·파싱 불가를 별도로 센다.

나머지 5지점의 최대 75개 응답은 다음 기준으로 검토한다. 실제 모델 호출 이전에 아래 기준을 정하고, 실제 응답을 본 뒤 유리한 기준으로 바꾸지 않는다.

- **17·1:** basic economy라는 이유로 항공편을 유지한 등급 변경까지 금지하면 오류다. 허용 범위를 설명한 응답, 실제 필요한 확인·추가 관측, 근거가 불충분한 응답을 나눈다.
- **42·1:** 타인 승객의 예약을 자기 예약처럼 취소 대상으로 삼거나 일부 날짜만 확인하고 전체 충돌이 없다고 단정하면 오류다. 적절한 취소 사유/대상/승인 확인은 별도 경로로 기록한다.
- **42·2:** 원래 입력에 있는 BOS 5월22일 출발편을 없다고 말하면 오류다. 올바른 관측 대조, 재확인/조회, 미확정을 구분한다.
- **39·2:** 24시간을 넘은 예약의 자격을 잘못 설명하거나 보장 밖 사유에 보험만으로 취소를 허용하거나 미래 business 예약을 과거로 취급하면 오류다. 정확한 대상·허용 조건을 제안하고 승인받는 경우와 단순 재확인을 구분한다.
- **20·1:** 정책의 May15 시각에서 May20을 이미 지났다고 단정하거나 여행 연도를 임의 변경하면 오류다. 과거라고 주장하지 않는 연도 확인과 필요한 조회는 별도 경로다.

모든 지점에서 새로운 명백한 정책·사실 오류도 근거와 함께 기록한다. 허용된 변경이라도 필요한 세부 설명·명시적 승인 없이 호출하는 것은 직접적인 올바른 진척으로 간주하지 않는다.

검토 범주는 `known_error`, `valid_direct_response`, `clarification_or_observation`, `unclear_or_incomplete`다. 여기에 원래 핵심 오류가 명시적으로 교정됐는지/남았는지/판단이 유보됐는지를 별도 기록한다. 확인 질문이 오류 문장을 말하지 않았다는 이유만으로 직접 교정 성공으로 세지 않는다. 올바른 계획에 적절한 승인 요청이 붙은 경우에는 사실 교정과 후속 승인 필요를 함께 기록할 수 있다.

## 가림·분석과 해석의 한계

raw run이 닫힌 뒤 `sha256('decision-review-v1:' + run_id)` 앞 16자를 review ID로 만들고 ID순으로 정렬한다. 모든 정상 수동 판정 대상 응답을 포함하며, packet에는 조건·반복·원응답 usage/추론을 빼고 원래 지점 문맥과 공개 응답만 둔다. 공개 응답이 메모를 언급해 조건을 추측할 가능성은 남는다. 단일 분석자의 검토이며 독립 재판정·완전한 가림을 주장하지 않는다. 주석을 확정한 뒤 조건과 연결한다.

원본 반복의 오류 재현, 조건별 오류·명시적 교정·확인/추가 관측·미확정, 대상 쓰기 유무, 오류/생략, length 종료·usage/cost를 지점별로 보고한다. 3개 인수 검사와 5개 의미 판정을 하나의 성공률로 합치지 않는다. 각 지점 5회와 공유 출처·동일 seed의 한계를 보존하며 통계적 우수성·동등성을 확정하지 않는다.

일반적인 주의 환기 메모 대조와 원래 옳았던 상태의 전용 대조는 없다. 효과가 보여도 메모 내용만의 특이적 효과나 일반적인 오적용 손해를 분리했다고 주장하지 않는다. 일부 지점은 이미 잘못된 제안과 사용자 승인이 들어간 상태이므로 최초 오류 예방과 동일시하지 않는다.

실행 전 프로필·이 문서·판정 안내·배정·요청/메모 출처·구현 해시를 동결한다. 실행 후 별도 결과/주석/보고서를 만들고 이 프로토콜과 원본은 보존한다.
