# 새 소매 고객 77명의 두 번 방문 실험

지난 상담의 주문을 기억하면 맞는 주문을 더 빨리 찾는지, 고객이 오늘 다른 주문을 지정하면 옛 주문을 잘못 제안하는지 함께 측정한다. 앞선 7명에서는 목표가 고객 프로필 목록의 첫 주문일 때 자동 제공·빈 자동 제공이 각각 10/16회와 9/16회, 뒤쪽일 때 6/12회와 0/12회였다. 위치에 따른 차이는 당시 결과를 본 뒤 발견했다. 이번 77명에서는 실행 전에 이 비교를 정했다. [처음 140회의 검산](../reports/20261122-retail-order-choice-replay.md) · [고정 배정](../../artifacts/analyses/20261122-retail-two-visit-preflight.json)

11월 22일 사용자는 **새 총한도 $13과 고객 77명 전원의 끝까지 상담 2,310건**을 선택했다. 26명 표본은 설계 당시의 비용 대안이었다. 모델 요청 상한은 역할별 최대치를 합한 160,468건이고, 전체 경과 시간 상한은 7일이다. [승인 범위](../../protocols/pilots/tau2-retail-two-visit-v1.json)

11월 22일의 실행과 복구에서 첫 판단 2,310건과 정상 종료 상담 2,305건을 관측했다. 지난 방문의 주문을 다시 지칭한 154쌍에서 자동 제공과 빈 자동 제공은 목표 주문을 각각 129건과 27건 바로 조회했다. [첫 판단·전체 상담·중단 기록과 비용](../reports/20261122-retail-two-visit-results.md)

## 누가 무엇을 보나

공식 영문 소매 114과제의 고객 53명을 제외한 뒤, 취소 가능한 주문이 둘 이상인 고객 77명을 모두 선정했다. 고객마다 두 주문을 고정했다. 예를 들어 같은 고객이 지난번에 A를 문의한 이력과 B를 문의한 이력을 별도 환경에서 만든다. 각 이력에 세 가지 현재 요청을 붙인다. [과제 원본과 고객 선정 근거](../../artifacts/analyses/20261122-retail-order-pairs.json)

| 이번 고객 요청 | 무엇을 비교할 수 있나 |
| --- | --- |
| “지난번에 이야기한 주문을 취소해 주세요” | A·B 이력의 현재 발화, 본인확인, 프로필 목록이 동일하다. 올바른 주문은 과거에 따라 달라진다. |
| 오늘 주문번호를 말하고 지난번과 같은 주문을 선택 | 현재 번호로 찾을 수 있을 때 메모가 돕거나 방해하는지 본다. |
| 오늘 주문번호를 말하고 지난번과 다른 주문을 선택 | 상담원이 현재 요청과 충돌하는 옛 주문번호를 따르는지 본다. |

각 요청 유형에는 목표가 프로필 목록 맨 앞인 사례 54개, 뒤쪽인 사례 100개가 있다. 실험자가 만든 과제이며 새 고객은 같은 소매 DB에서 왔다. 주문 목록의 순서는 벤치에 들어 있던 값을 유지한다.

## 순서와 규모

| 단계 | 배정 | 기록 |
| --- | ---: | --- |
| 1회차 상담 | 고객 77명 × 과거 주문 2개 = 154건 | 고객이 주문에 담긴 상품을 묻는다. 새 DB에서 상담을 끝내고 공개된 대화와 도구 결과를 보존한다. |
| 메모 작성 | 원천 154개 × 형식 4개 = 616건 | 같은 원천을 사실·일기·교훈·절차 형식으로 독립 작성한다. 성패 피드백 없이 자율 저장하며 네 작성물은 원천별로 한 은행에 담는다. |
| 2회차 첫 판단 | 154 × 현재 요청 3개 × 조건 5개 = **2,310건** | 같은 고객·요청에 자동 제공, 빈 자동 제공, 자율 조회, 빈 자율 조회, 무노트를 모두 배정한다. 인증과 프로필 조회를 마친 같은 공개 상태에서 시작한다. |
| 끝까지 이어갈 상담 | 기본 제안 26명 × 6사례 × 5조건 = **780건** | 첫 판단과 동일한 세션에서 이어 간다. 전체 진행안은 77명의 2,310건이다. 모집단과 표본 중 어느 쪽을 이어갈지는 첫 모델 응답 전에 고정한다. |

전체 상담 표본은 두 주문 중 첫 목록 주문이 들어 있는 고객 54명에서 18명, 두 주문이 모두 뒤쪽인 고객 23명에서 8명을 고정 해시 순서로 뽑았다. 한 고객의 모든 조건을 함께 보존한다. 작성자가 자발적으로 저장을 생략한 은행도 해당 메모 조건에 포함한다. 원천 상담이나 작성이 기술적으로 실패하면 해당 은행이 필요한 조건에 결측을 기록한다. 빈 대조와 무노트는 자체 배정으로 수행한다. [배정 생성 및 단계별 실행기](../../scripts/run_retail_two_visit.py)

## 무엇을 성과로 볼까

**주 비교**는 지난 주문만 가리킨 요청 154쌍에서 자동 제공과 빈 자동 제공의 첫 행동을 비교한다. 전체 응답에 목표 주문에 대한 `get_order_details` 하나만 있으면 1이다. 여러 주문을 함께 조회하거나 고객에게 되물으면 별도 행동으로 기록한다. 조회 조건에서는 기억만 조회하는 응답을 세 번 거친 뒤 네 번째 응답에서 업무 판단을 마칠 수 있다. 네 번 모두 기억 도구만 요청하면 해당 배정의 첫 판단을 결측으로 기록한다. 메모 도구와 업무 호출을 한 응답에 함께 제안한 경우도 구별한다. 목록 호출, 제목 반환, 다음 입력에 실린 제목·본문을 각각 집계한다.

같은 사례를 짝지어 고객 안에서 평균을 내고 고객마다 같은 비중을 준다. 관측된 분자·분모, 결측 쌍, 고객별 개선·동률·악화, 양측 부호검정, 기술적 결측에 가능한 0·1을 대입한 차이의 범위를 함께 낸다. 위치별로 같은 대비를 구해 ‘뒤쪽 차이 − 첫 위치 차이’를 측정한다. 양쪽에 속하는 고객은 함께 재표집한다. 자율 조회의 비교 상대는 같은 도구가 열려 있는 빈 자율 조회다. 고객이 현재 주문을 명시한 두 변형의 이득과 잘못된 과거 적용도 각각 보고한다. [분석기](../../scripts/analyze_retail_two_visit.py)

**전체 상담**에서는 어느 주문인지 물은 횟수, 틀린 주문을 취소 대상으로 제안한 횟수와 이후 수정, 실제 취소 주문, 명시적인 고객 승인, DB 점수를 측정한다. 고객이 번호를 요청받으면 답하도록 설계했으므로 적절히 되물어도 전체 상담은 성공할 수 있다. 주문 식별 질문과 취소 직전의 필수 승인 질문은 다르게 센다.

고정한 τ² 채점기에 통제 대화를 넣은 결과는 다음과 같다. 이 다섯 건에는 스크립트가 정한 응답을 썼다. [채점기 및 상담 재개 검증](https://github.com/yonsei-ai-labs/agent-memory/blob/40f881aa1f70f5772f52484a4f1a19d0de01162d/tests/test_retail_two_visit.py)

| 상황 | DB 점수 | 동의를 갖춘 올바른 취소 |
| --- | ---: | --- |
| 고객에게 대상과 사유를 설명하고 승인받아 목표 주문 취소 | 1 | 예 |
| 고객 답변 없이 목표 주문 취소 | 1 | 아니오 |
| 고객 거절 뒤 목표 주문 취소 | 1 | 아니오 |
| 다른 주문 취소 | 0 | 아니오 |
| 취소하지 않고 종료 | 0 | 아니오 |

판독자는 조건, 은행, 원천 이력, 분석용 목표 주문이 가려진 대화와 업무 도구 기록을 받는다. 어느 주문인지 되물은 상담원 발화 번호를 `clarifications`에, 취소 제안의 발화·대상·사유를 `proposals`에 기록한다. 고객 응답은 `responses`로 해당 제안에 연결해 동의·거절·철회·불명확으로 표시한다. 대상이나 사유를 판독할 수 없는 대화는 `unresolved`로 남긴다. 분석기가 마지막 제안과 그 뒤 고객 발화가 취소보다 앞서는지 검사한다. 채점된 상담 수와 사람이 판독한 상담 수를 별도로 공개한다.

## 비용과 실행

이전 실측 단가는 상담 608회에 확인 비용 $2.388979274, 메모 작성 176회에 $0.183377700, 첫 판단 140회에 $0.014806295였다. 이를 적용하면 첫 판단까지 약 **$1.49**, 780건을 이어가면 누계 약 **$4.56**, 전부 이어가면 약 **$10.57**이다. 과거 상담 단가에는 미채점과 미확정 청구가 있었고 이번에는 상담 길이와 조회 횟수가 달라질 수 있다. 전체 상담 비용 추정에는 과거 상담 한 건의 평균을 그대로 더했다. 실제 재개 시 첫 판단은 재청구되지 않는다. [소매 상담·작성 영수증](../reports/20261121-retail-transfer-revision.md) · [첫 판단 영수증](../reports/20261122-retail-order-choice-replay.md)

아래 명령은 새 모델 호출 없이 과제, DB 참조 상태, 배정표를 재생성한다. 원본 소매 데이터와 고정된 τ² 설치를 사용한다.

```bash

```

유료 실행은 금액과 범위가 승인되면 같은 초안의 `status`를 `ready`로 둔 사본과 누적 `authorization`을 사용한다. `through`는 `decision` 또는 `continuation`, `continuation`은 첫 응답 전에 선택한 `sample` 또는 `all`이다. `max_usd`·`max_requests`·`max_seconds`는 최초 시작부터의 총한도다. 준비된 프로필 경로를 `python -m scripts.run_retail_two_visit live --profile`에 전달한다. 공급자 가격과 모델을 고정 당시 영수증과 대조하고 매 전송 직전 원문·출력 상한·캐시 단가로 최대액을 보류한다. 프로그램을 다시 시작하면 시작 표시와 영수증을 대조해 중복 전송을 막는다. 추가 한도가 승인된 경우 같은 구현 커밋에서 처음 정한 고객들의 체크포인트를 이어갈 수 있다. ### 전체 상담의 판독과 검산

실행 중 초기의 조건을 가린 공개 대화로 판독 보조 규칙을 작성했다. 이 규칙은 주문번호 한 개, 취소 사유, 상담원의 승인 요청, 고객의 응답을 해당 발화에 연결한다. 판독자는 후보가 명확한 대화에서는 주문 식별과 승인에 해당하는 문구를 대조하고, 거절·대상 변경·여러 후보 등 해석이 필요한 대화에서는 공개 대화의 흐름을 직접 읽는다. 조건을 열기 전에 가명 ID를 해시로 정렬해 전체 배정에서 100건을 뽑았다. 이 표본의 완료 대화는 보조 규칙의 판정과 별도로 판독하고 두 결과가 갈린 항목을 남긴다. 판독자는 이 작업을 수행하는 에이전트다. 사람이 별도로 판독한 건수도 결과에 명시한다. [공개 발화 후보와 판독 봉인](../../scripts/code_retail_two_visit_turns.py)

판독을 마치면 등록한 실행과 가명 ID의 대응표를 근거 발화 번호·대화 해시와 함께 공개한다. 같은 판독 파일을 `--review-index`와 `--reviews`에 전달하면 키 없이 최종 수치를 재현할 수 있다. 별도 검산에서는 완료된 상담의 업무 도구 호출을 새 소매 DB에서 다시 수행하고, 모델에 보낸 각 요청의 원문·고정 단가·응답 영수증을 비용 원장과 대조한다. [DB 및 세션 검산](../../scripts/audit_retail_two_visit_sessions.py) · [요청과 비용 검산](../../scripts/audit_retail_two_visit_billing.py)

### 공급자 장애로 빠진 과거 이력의 복구
