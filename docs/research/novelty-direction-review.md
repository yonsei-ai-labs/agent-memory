# 파일럿 이후 발전 방향과 주장 후보

2026-11-14 · 자율 조회 파일럿에서 얻은 것과 다음 2주의 제안, 실행 전

**파일럿으로 실제 Luna·τ²·기억 도구를 잇는 측정 경로가 동작하고, 기억이 언제 실제 입력에 들어가는지 정확히 추적할 수 있음을 확인했다. 다음 단계는 이 강점을 "같은 기억을 강제로 줄 때와 에이전트에게 맡길 때 이득과 손해가 어떻게 달라지는가"라는 질문에 모아 첫 주장을 세우는 것이다.** 파일럿 뒤 약 2주의 실험 기간을 전제로 한 제안이다. 연구 범위·기존 draft·합의를 바꾸지 않으며 과제 수·반복·예산은 정하지 않았다.

## 파일럿에서 얻은 것

[자율 조회 파일럿](../development/tau2-autonomy-pilot.md)과 [관측 기록](../../artifacts/pilots/20261114-tau2-autonomous-memory.json)을 기준으로 한다.

| 확인한 것 | 다음 단계에 주는 의미 |
| --- | --- |
| 실제 Luna·DeepSeek 1017·τ² 경로에서 세 조건 9회를 사전 배정대로 실행하고 원본 audit 통과 | 같은 경로로 조건·과제·반복을 늘릴 수 있다 |
| 빈 은행과 기억 은행이 같은 system·도구로 전송됨을 대조 | 도구·지침을 주는 영향과 기억 내용의 영향을 나눠 볼 수 있다 |
| 수집 은행이 비었을 때 평가를 실패로 채우지 않고 생략 사유를 기록 | 결측과 미실행을 구분하는 기록이 실제 실행에서 동작한다 |
| 중립 지침에서 자율 작성 0/1, 자율 조회 0/6 | 맡겨 두면 기억이 전달되지 않을 수 있다는 관찰로, 다음 질문의 출발점이 된다 |
| 과제 0은 무기억 3/3, 전체 조건 합계 9/9 통과, 최종 DB 해시 동일 | 기억의 이득을 보려면 개선 여지가 있는 과제를 고르면 된다 |
| 두 시도의 새 보고 비용 $0.0125059432, 실행당 약 $0.001 | 과제와 반복을 넓혀도 비용 부담이 작을 것으로 보인다 |

이번 실행에서는 기억이 노출되지 않았으므로 `memory_bank`와 `empty_bank`의 단계·비용 차이는 실행 변동으로 본다. 자율 사용 0회는 한 과제·중립 지침·결과 피드백 없음·reasoning low 조건의 관측이다. 요약의 `actions_changed`는 transfer 요약 같은 자유 텍스트까지 비교하므로, 업무 호출·인수나 최종 DB 해시로 비교하는 보조 지표를 더하면 행동 변화가 더 선명해진다.

## 이 프레임워크의 강점

- **노출을 정확히 기록한다.** 저장·반환·실제 입력 포함을 제목과 본문으로 나눠 남기므로, 기억이 어느 단계까지 도달했는지 판정 모델 없이 구분한다.
- **도구의 영향과 내용의 영향을 나눈다.** 빈 은행 대조로 기억 도구·지침을 주는 것만으로 생기는 변화를 분리한다.
- **이득과 손해를 함께 본다.** 사전 배정·블록 순서·무기억 반복으로 실패→성공과 성공→실패를 자연 변동과 같이 보고할 수 있다.
- **실제 업무 조건에 가깝다.** 같은 작업자가 쓴 자기 기억을 정책 규칙이 있는 대화형 업무에서 공식 채점으로 평가한다.

## 선행연구와의 관계

2026-11-14 웹 검색으로 초록과 검색 요약을 확인했다. 본문은 읽지 않았으며 전체 목록이 아니다. [관련 연구](related-work.md) 이후 확인한 문헌을 포함한다. 가까운 연구들은 문제의 중요성을 뒷받침하면서 각자 한 단계를 깊게 다룬다. 우리 설계는 그 단계들을 같은 기억·같은 과제에서 이어 볼 수 있다.

저장 시점·형태·조회 축, 단계 분해, 득실 측정은 이 연구들과 연결해 설명한다. 주장의 중심은 이 단계들을 잇는 아래 질문에 둔다.

## 첫 주장 후보: 조회를 에이전트에게 맡길 때의 득실

**조회 여부를 에이전트에게 맡기면 해로운 기억을 거르는가, 유용한 기억까지 놓치는가?** 강제 전달 쪽 연구는 해악을, 자발적 조회 쪽 연구는 사용률을 보여 주었다. 같은 기억 내용에서 전달 방식만 바꿔 이득과 손해를 함께 재는 비교는 이번 검색에서 찾지 못했고, 우리 측정 경로가 바로 이 비교에 맞는다. 주장을 쓰기 전에 가장 가까운 연구를 본문까지 다시 확인한다.

| 전달 조건 | 과거 정보 |
| --- | --- |
| `no_memory` | 기억 도구·지침 없음 |
| `empty_bank` | 같은 도구·지침과 빈 은행. 도구·지침의 영향을 분리 |
| `on_demand` | 현재 파일럿의 선택적 list/get |
| `title_preload` | 시작 시 목록 제목 제공, 본문은 get. 제목도 노출로 기록 |
| `full_preload` | 시작 시 본문까지 제공 |

조건 이름은 제안이다. 모든 조건은 같은 자기 작성 은행 버전을 사용하고, 같은 과제 재시도(이득이 날 수 있는 자리)와 조건이 바뀐 관련 과제(손해가 날 수 있는 자리)를 함께 둔다.

핵심 그림은 `full_preload`를 기준으로 한 두 비율의 평면이다.

- 이득 포착률: 강제 제공이 도움 된 과제에서 (자율 조건 성공률 − 무기억 성공률) / (강제 제공 성공률 − 무기억 성공률)
- 손해 회피율: 강제 제공이 해가 된 과제에서 (자율 조건 성공률 − 강제 제공 성공률) / (무기억 성공률 − 강제 제공 성공률)

`full_preload`는 (100%, 0%), `no_memory`는 (0%, 100%), 이상적인 선택은 (100%, 100%)에 놓인다. 분모가 작은 과제의 비율은 불안정하므로 과제별 비율보다 묶은 차이를 우선한다. 과제의 이득·손해 분류 기준은 반복 수를 고려해 실행 전에 정한다. 강제 제공에서 도움 된 과제와 해가 된 과제의 조회율을 비교하면 자율 조회의 선택성을 볼 수 있다.

| 결과 | 주장 |
| --- | --- |
| 해가 되는 기억을 덜 조회 | 자율 판단이 필터로 작동한다 |
| 도움·해와 무관하게 조회 | 자율 조회의 차이는 판단보다 빈도에서 온다 |
| 계속 조회 0회 | 자발적 미사용을 대화형 업무에서 결과와 함께 확인하고 놓친 이득을 정량화한다 |

어느 결과든 보고할 수 있는 주장이 되며, 제목 노출 기록·빈 은행 대조·무기억 반복 변동이 그대로 핵심 근거가 된다.

### 공식 과제 후보

airline에는 같은 취소 요청 안에 상태 변경 없이 끝나는 과제와 실제 취소가 정답인 과제가 함께 있어, 변형 과제를 만들지 않고도 이득과 손해가 날 자리를 구성할 수 있다. 사용자 시나리오의 `reason_for_call`에 cancel이 있는 과제를 기대 행동으로 1차 분류했으며, 각 과제의 조건 정합성과 채점 기준은 과제를 고를 때 확인한다.

| 기대 업무 변화 | train | test |
| --- | --- | --- |
| 상태 변경 없음 | 0, 9, 28, 41, 47 | 26, 45, 48 |
| 취소 실행 포함 | 7, 39 | 없음 |
| 다른 변경만 | 없음 | 35, 37, 44 |

airline 50개는 모두 DB/COMMUNICATE로 채점하며, 그중 24개는 기대 행동에 DB를 바꾸는 호출이 없다(조회뿐이거나 비어 있음 23개, 상담원 연결만 1개). 과제를 고를 때 전달 요구도 함께 보면 결과 해석이 선명해진다. test 과제는 지침·기준 조정에 쓰지 않는다.

## 2주 진행 제안

지금 있는 실행·기록·분석 구성요소를 이어서 쓴다.

1. **무기억 기준선 넓히기.** 지금 실행 경로로 airline train 과제를 반복 실행해 과제별 성공 확률을 구하고 개선 여지가 있는 과제를 고른다.
2. **시작 시 제공 조건 더하기.** 기억 bridge에 `title_preload`·`full_preload` 입력 구성을 추가하고, 실제 입력 구간 기록은 지금 방식을 그대로 쓴다.
3. **배울 거리가 있는 기억 만들기.** 실패한 경험과 사전 정의한 종료 결과 피드백으로 기억을 쓰는 조건을 검토한다. 결과 피드백은 프로토콜에 있는 정보 조건이다.
4. **실행기를 설정 기반으로 모으기.** 파일럿 실행기와 audit의 구성요소를 과제 목록·조건·반복을 설정으로 받는 실행기로 일반화하면 조건 추가가 빨라진다.
5. **분석 더하기.** 이득 포착률·손해 회피율·조회 선택성과 정규화한 행동 비교를 요약에 넣는다.

진단 순서는 [방향 논의 노트](../design/direction-notes.md#만들면서-확인할-실증-질문)의 무기억 반복 → 시작 시 제공 → 자율 조회 교차를 따른다. 실행당 비용이 작아 과제와 반복을 넉넉히 잡을 수 있다. 더 긴 과제를 감안해도 수백 회가 몇 달러 수준이라고 추정한다.

## 파일럿 진행 판단 기준

1. `full_preload`가 무기억 대비 결과를 바꾸는 과제가 있는가. 이런 과제에서 걸러 낼 이득과 손해가 생긴다.
2. `title_preload`나 `on_demand`에서 조회가 일어나는가. 조회가 있으면 선택성을, 없으면 놓친 이득을 정량화한다.
3. 두 가지를 확인하면 2주 동안 과제와 반복을 늘린다. 과제 수·반복·성공률 구간·예산은 별도 파일럿 프로필에서 고정한다.

## 이후로 이어갈 범위

저장 시점 네 가지 비교, 누적·체크포인트, AppWorld·BFCL 확장, 변형 과제 제작은 연구 범위에 그대로 두고 첫 주장 다음 단계로 이어간다. [적용 조건 기억 파일럿](condition-sensitive-pilot.md)은 같은 비교에 기억 형태를 보조 요인으로 더하는 확장으로 붙일 수 있다.

## 참고

- 문헌은 초록 수준으로 확인했다. 주장을 쓰기 전에 가장 가까운 연구를 본문까지 확인한다.
