# 진행 점검과 노벨티 검토 노트

2026-11-14 · 자율 조회 파일럿 이후의 논의 기록, 실행 전 제안

**지금의 접근(사전 배정한 짝 비교와 실제 노출 추적)은 유지할 만하다. 다만 프레임워크나 저장·조회 축의 비교만으로는 노벨티 주장이 약하다. 첫 주장 후보로, 같은 기억을 강제 제공과 자율 조회로 전달했을 때 이득과 손해가 어떻게 갈리는지를 제안한다.** 파일럿 뒤 약 2주의 실험 기간을 전제로 한 논의다. 연구 범위·기존 draft·합의를 바꾸지 않으며 과제 수·반복·예산은 정하지 않았다.

## 파일럿에서 확인한 것

[자율 조회 파일럿](../development/tau2-autonomy-pilot.md)과 [관측 기록](../../artifacts/pilots/20261114-tau2-autonomous-memory.json)을 기준으로 한다.

| 관측 | 내용 |
| --- | --- |
| 자율 작성 v1.0 | 작성 기회 1회에서 저장 0개. writer가 `No memory was saved.`로 끝나 9개 평가를 `source_empty`로 생략 |
| 자율 조회 v1.1 | 기억 도구가 있는 6회에서 list/get 0회. 제목·본문 노출 없음 |
| 업무 결과 | 9회 모두 native 성공, 최종 DB 해시 9회 동일 |
| 무기억 반복 | 결과 불일치 0/3쌍. native 단계 9~15, 업무 호출 2~4로 경로는 달랐음 |
| 비용 | 두 시도의 새 보고 비용 $0.0125059432 |

- 기억이 노출되지 않았으므로 이번 실행의 `memory_bank`와 `empty_bank`는 같은 정보 조건이다. 조건 간 단계·비용 차이를 기억 효과로 읽지 않는다.
- 과제 0은 기대 행동이 비어 있고 DB/COMMUNICATE로 채점한다. 무기억도 통과하므로 기억의 이득은 관측할 수 없고 손해만 관측할 수 있다.
- 자율 사용 0회(작성 0/1, 조회 0/6)는 한 과제·중립 지침·결과 피드백 없음·reasoning low 조건의 관측이다. 일반적인 사용률로 확대하지 않는다.
- 요약의 `actions_changed`는 transfer 요약 같은 자유 텍스트까지 비교해 9쌍 모두 True다. 자유 텍스트를 뺀 업무 호출·인수나 최종 DB 해시로 비교하는 보조 지표가 필요하다.

## 진행 방식 점검

| 구분 | 내용 |
| --- | --- |
| 유지할 점 | 저장 → 선택 → 노출 → 활용 → 결과의 분해, 실패→성공과 성공→실패를 함께 세는 질문 |
| 유지할 점 | 빈 은행 대조, 블록 순서 배정, 생략을 실패로 채우지 않는 기록, 원본 재계산 audit |
| 조정할 점 | [문서의 진단 순서](../design/direction-notes.md#만들면서-확인할-실증-질문)는 무기억 반복 → 시작 시 제공 → 자율 조회 교차인데, 자율 조회 비교를 한 과제에서 먼저 했다 |
| 조정할 점 | 파일럿마다 전용 스키마·실행기·audit를 추가했다. 분석에 블록 3·실행 9가 고정돼 다음 비교에 재사용하기 어렵다 |
| 조정할 점 | 실행 비용은 병목이 아니다. 과제 0 기준 실행당 약 $0.001이며, 더 긴 과제를 감안해도 수백 회가 몇 달러 수준이라고 추정한다 |

2주 실험 전에는 과제 목록·조건·반복을 설정으로 받는 실행기로 모으는 편이 낫다. 실험 계획 문서는 결정한 값과 미정 값을 표로 나눠 결정 사항이 보이게 한다.

## 첫 주장 후보: 조회를 맡겼을 때의 득실

**조회 여부를 에이전트에게 맡기면 해로운 기억을 거르는가, 유용한 기억까지 놓치는가?** 강제 전달 연구는 해악을 보고했다. 자발적 조회 연구는 사용률이 거의 없다는 것을 보였지만 과제 결과는 재지 않았다. 같은 기억 내용에서 전달 방식만 바꿔 이득과 손해를 함께 잰 비교는 이번 검색에서 찾지 못했다. 없다는 확인은 아니므로 주장 전에 다시 조사한다.

| 전달 조건 | 과거 정보 |
| --- | --- |
| `no_memory` | 기억 도구·지침 없음 |
| `empty_bank` | 같은 도구·지침과 빈 은행. 도구·지침의 부담을 분리 |
| `on_demand` | 현재 파일럿의 선택적 list/get |
| `title_preload` | 시작 시 목록 제목 제공, 본문은 get. 제목도 노출로 기록 |
| `full_preload` | 시작 시 본문까지 제공 |

조건 이름은 제안이다. 모든 조건은 같은 자기 작성 은행 버전을 사용하고, 같은 과제 재시도(이득이 날 수 있는 자리)와 조건이 바뀐 관련 과제(손해가 날 수 있는 자리)를 함께 둔다.

핵심 그림은 `full_preload`를 기준으로 한 두 비율의 평면이다.

- 이득 포착률: 강제 제공이 도움 된 과제에서 (자율 조건 성공률 − 무기억 성공률) / (강제 제공 성공률 − 무기억 성공률)
- 손해 회피율: 강제 제공이 해가 된 과제에서 (자율 조건 성공률 − 강제 제공 성공률) / (무기억 성공률 − 강제 제공 성공률)

`full_preload`는 (100%, 0%), `no_memory`는 (0%, 100%), 이상적인 선택은 (100%, 100%)다. 분모가 작은 과제의 비율은 불안정하므로 과제별 비율보다 묶은 차이를 우선한다. 과제의 이득·손해 분류는 반복 수에 따라 오분류될 수 있으므로 분류 기준을 실행 전에 정한다. 강제 제공에서 도움 된 과제와 해가 된 과제의 조회율을 비교하면 자율 조회의 선택성을 볼 수 있다.

| 결과 | 주장 |
| --- | --- |
| 해가 되는 기억을 덜 조회 | 자율 판단이 필터로 작동 |
| 도움·해와 무관하게 조회 | 자율 조회는 판단이 아니라 빈도의 문제 |
| 계속 조회 0회 | 정책 규칙이 있는 대화형 업무에서 Delivery, Not Storage를 결과와 함께 재현하고 놓친 이득을 정량화 |

이 질문에는 제목 노출 기록, 빈 은행 대조, 무기억 반복 변동이 필수다. 프레임워크의 기여를 이 질문을 잴 수 있게 한 측정으로 설명할 수 있다.

### 공식 과제 후보

airline에는 같은 취소 요청 안에 상태 변경 없이 끝나는 과제와 실제 취소가 정답인 과제가 섞여 있다. 사용자 시나리오의 `reason_for_call`에 cancel이 있는 과제를 기대 행동으로 1차 분류했다. 각 과제의 조건 정합성과 채점 기준은 아직 확인하지 않았다.

| 기대 업무 변화 | train | test |
| --- | --- | --- |
| 상태 변경 없음 | 0, 9, 28, 41, 47 | 26, 45, 48 |
| 취소 실행 포함 | 7, 39 | 없음 |
| 다른 변경만 | 없음 | 35, 37, 44 |

airline 50개는 모두 DB/COMMUNICATE로 채점하며, 그중 24개는 기대 행동에 DB를 바꾸는 호출이 없다(조회뿐이거나 비어 있음 23개, 상담원 연결만 1개). 보수적인 행동이 유리할 수 있으므로 과제를 고를 때 전달 요구를 함께 확인한다. test 과제는 지침·기준 조정에 쓰지 않는다.

## 파일럿 진행 판단 기준

1. `full_preload`가 무기억 대비 결과를 바꾸는 과제가 있는가. 없으면 걸러낼 대상이 없어 질문이 성립하지 않는다. 무기억 성공률이 중간인 과제를 고르고, 실패 경험과 사전 정의한 종료 결과 피드백으로 기억을 쓰는 조건을 검토한다.
2. `title_preload`나 `on_demand`에서 조회가 일어나는가. 0회면 선택성은 잴 수 없고 결과는 재현으로 보고한다.
3. 두 조건이 확인되면 2주 동안 과제와 반복을 늘린다. 과제 수·반복·성공률 구간·예산은 별도 파일럿 프로필에서 고정한다.

## 2주 주장 밖으로 미루는 것

연구 범위에서 지우지 않고 첫 주장 밖에 둔다. 저장 시점 네 가지 비교, 누적·체크포인트, AppWorld·BFCL 확장, 변형 과제 제작이 해당한다. [적용 조건 기억 파일럿](condition-sensitive-pilot.md)은 OpenViking·BASM과 겹쳐 보조 요인 후보로 둔다.

## 한계

- 작업자 모델이 Luna 하나다. 두 번째 작업자의 작은 확인은 별도 분석 블록으로 검토한다.
- 문헌은 초록 수준이다. 주장 전에 본문과 추가 검색으로 가장 가까운 비교를 다시 확인한다.
- JitMem·MemUse의 결과처럼 강제 제공의 효과 자체가 작을 수 있다. 그 경우 이득·손해의 크기와 불확실성을 그대로 보고한다.
