# 은행 문서 검색과 개인 경험 메모의 효과

같은 영어 은행 과제를 다시 푸는 상담원이 지난번의 사실을 되살리는 경우, 지난번의 절차를 적용하는 경우, 현재 은행 문서에서 독립적으로 답을 찾는 경우를 구분한다. 이번 개발 표본의 단위는 과제 4개다. 1회차 무기억 4건에서 사실·경험·절차·교훈·자유 형식으로 20번 작성하고, 각 작성물을 새 세션에 자동 제공하거나 자율 조회하게 해 40번 수행한다. 2회차 무기억 배정은 0이다. [등록 프로토콜](../../protocols/pilots/tau-banking-memory-v1.json)

## 현재 방식의 적절성과 연구에서 가져온 보완

| 질문 | 현재 구현과 관측 | 은행에서 검산할 내용 |
| --- | --- | --- |
| 작성자가 무엇을 알았나 | 작성자에게 마지막 **상담원** 요청의 공개 이력과 답변을 준다. 공식 성패, 고객의 비공개 대본, 정답 행동, 필수 문서 ID는 주지 않는다. 저장 생략을 허용한다. 마지막 상담원 답변 뒤의 고객 행동은 작성자가 못 볼 수 있다. | 메모의 중요한 문장을 1회차 공개 고객 발화·관측된 도구 결과·상담원 주장으로 나눈다. 상담원이 성공을 선언한 문장 하나만으로 결과가 확인됐다고 판정하지 않는다. |
| 어떤 내용을 다시 쓰나 | 다섯 지침의 출력은 자유 본문이며 개인 정보·절차·교훈이 섞일 수 있다. AWM은 이전 경로의 공통 절차와 바뀌는 인수를 구분한다. ReasoningBank는 성공과 실패 경험에서 학습한다. | 메모의 실제 내용에서 지난 거래의 값, 문서·정책의 조건, 다시 확인할 절차, 근거 없는 성공·실패 추론을 구분한다. 이번에는 다섯 형식 모두 같은 공개 기록과 피드백 없음 조건을 유지한다. [Agent Workflow Memory](https://proceedings.mlr.press/v267/wang25bx.html) · [ReasoningBank](https://arxiv.org/abs/2509.25140) |
| 조회가 효과에 이어졌나 | 자동 제공과 자율 조회가 동일한 봉인본을 쓴다. 목록 제목만 본 경우도 정보 노출이다. LongMemEval은 근거를 찾는 단계와 찾아낸 근거를 쓰는 단계를 분해한다. | 조회 가능, 목록 호출, 제목이 다음 요청에 들어감, 본문 조회, 본문이 업무 판단 전 요청에 들어감을 따로 센다. 자동 제공을 검색 성공으로 세지 않는다. 저장 생략·기술 실패·읽지 않음을 분리한다. [LongMemEval](https://arxiv.org/abs/2410.10813) |
| 현재 은행 문서와 개인 메모 중 무엇이 행동을 설명하나 | Mem2ActBench는 도구 선택과 인수의 기억 의존성을 구분한다. τ-Knowledge에는 실제 업무 도구, 고객 측 도구, 양쪽이 함께 바꾸는 DB와 외부 문서가 있다. | 개인 메모에서 보인 값·절차를 행동에 연결할 때 현재 요청의 고객 발화, 정책, 문서 검색 반환, 다른 업무 도구 반환도 대조한다. 두 출처에 모두 있으면 양쪽에 표시한다. 도구 이름·인수 일치와 정책을 제대로 적용했는지는 별개의 판정이다. [Mem2ActBench](https://aclanthology.org/2026.acl-long.370/) · [τ-Knowledge](https://arxiv.org/abs/2603.04370) |

## 업무 조건과 선정

Sierra의 고정 커밋 `c06b07d`에서 공식 개별 과제를 로드하고 네이티브 실행기의 평가 기준과 대조한다. 지식 기반은 698문서이며 모든 조건이 같은 `grep_only` 설정을 사용한다. 개인 메모 도구는 은행 문서 검색과 다른 출처로 기록한다. 독립 환경의 첫 업무 판단에 같은 고객 첫 공개 발화를 복원하고 이후 고객 반응은 정상 생성한다. 고객에게는 메모와 메모 안내를 주지 않는다. [공통 시작 계약](../design/architecture.md#동일-과제의-첫-판단)

은행에는 공식 분할이 없다. 97개 과제 중 기존 첫 발화 복원기가 지원하는 기본 인사에서 시작하고, 참조 문서가 두 개 이상이며 DB 또는 행동으로 채점되는 과제를 대상으로 했다. 네 부류별 사전순 첫 ID는 단일 DB 행동 `task_001`, 지정 행동 `task_008`, 여러 DB 행동 `task_010`, 발견형 도구가 필요한 DB 행동 `task_015`다. 공식 참조 정보는 선정과 채점에만 쓴다. 신청·이관처럼 서로 다른 판단을 담은 의도적 표본이므로 97개 전체로 효과 크기를 외삽하지 않는다.

## 판정과 보고

- 일차 지표는 같은 과제에서 공식 성패가 회복·손실·양쪽 성공·양쪽 실패 중 어디에 속하는지다. 원천 결측과 기술 결측은 별도 열에 남긴다. 대상 4개의 원천을 10개 정책이 공유하므로 관측 40건을 독립 표본으로 검정하지 않는다.
- 작성 → 보관 버전 → 요청에서 본 제목·본문 → 첫 업무 도구와 인수 → 공식 결과를 연결한다. 첫 판단에서 일치한 공개 입력과, 고객·업무 도구 결과가 이미 달라진 하류를 구분한다. 같은 행동, 현재 정보의 중복, 제목만 읽음, 미조회, 정렬되지 않는 경로를 함께 보고한다. 업무 도구가 호출됐다는 사실과 메모가 원인이었다는 주장을 구분한다. [공용 행동 분석](../../src/agent_memory_eval/analysis/decision_attribution.py) · [원문 인용 검증](../../src/agent_memory_eval/analysis/claim_evidence.py)
- 양쪽이 성공한 쌍의 은행 문서 검색, 나머지 업무 호출, 고객 발화, 토큰과 비용을 비교한다. 복원한 고객 첫 발화의 생성비는 1회차 준비에 한 번만 귀속한다. 작성 비용은 별도 표시하고 같은 봉인본을 두 전달 방식에 쓴 사실을 명시한다. 실패·장애의 비용도 전체 원장에 포함한다.
- 절차·교훈의 기여를 주장할 때는 해당 문장과 원천, 당시 볼 수 있었던 대체 출처, 행동을 함께 판독한다. 모델이 설명한 내적 동기와 행동 원문을 구분한다. 작은 표본에서 같은 입력의 정책 차이는 기전 후보로 보고한다. 후속 확인은 근거 있는 문장 제거와 비슷한 길이의 무관 문장 제거를 같은 판단 지점에 배정할 수 있다.

기존 항공·소매의 자율 조회는 본문을 한 번도 열지 않은 경우가 많았다. 은행에서도 이 일이 생기면 자율 조회 정책의 사용률을 결과로 남긴다. 업무 힌트를 추가하는 대신, 다음 실험에서만 도메인 중립적인 조회 안내를 별도 요인으로 등록할 수 있다. 절차 메모가 한 과제의 정답을 압축했는지는 이 표본에서 판독할 수 있고, 다른 과제로의 전이는 별도의 보지 않은 대상 과제가 필요하다. [기존 격리 감사](../reports/20261124-experiment-isolation-audit.md)
