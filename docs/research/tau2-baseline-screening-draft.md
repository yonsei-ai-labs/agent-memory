# 다음 개발 단계: 무기억 탐색과 경험 재사용 후보 선정

2026-11-15 · 논의용 초안 · 새 모델 호출 0 · 실행 프로필 아님

**먼저 Luna의 무기억 수행을 공식 train 전반에서 관찰하고, 경험이 메울 수 있는 실패·비용과 기억이 불필요한 대조를 함께 찾는다.** 아래 30과제 × 2회 = 60회는 탐색 제안이며 승인·동결된 실행 수가 아니다. 실행 한도·비용·배정과 구현이 준비되기 전에는 실행하지 않는다.

기존 [48회 프로토콜](delivery-development-pilot.md)·원본·[결과](../reports/20261114-tau2-delivery-development-results.md)는 보존한다. 이 탐색은 기억 정책 효과나 최종 일반화 검증을 대신하지 않는다. 전체 저장·조회·전이·누적·득실·비용의 연구 범위는 유지한다.

과제당 2회 모두 성공해도 일반적인 천장 효과를 확정하지 않고, 1회씩 성공·실패해도 중간 난도로 확정하지 않는다. 실패 유형·정보의 추가 가치·적용 가능성의 후보를 찾는 데 쓴다. 모든 배정의 분모와 과제/예약 출처의 의존성을 보존한다.

한도에 도달하면 공식 결과가 있는 경우 그대로 보존하고 별도의 종료 이유를 붙인다. 제한 때문에 끊긴 실행과 정상 종료한 업무 실패를 나눠 보고, 미시작·미채점은 성공률의 분모에서 조용히 제거하지 않는다. 전체 한도 도달 시 남은 배정과 중단 위치를 공개한다.

## 3. 현재 소스에서 확인한 후보군

이 표는 **정보·행동 구조를 검토할 묶음**이며 새 Luna 성능이나 난도 순위가 아니다. 공식 train 30개를 빠짐없이 포함한다. 고정 checkout의 tasks·split·DB·정책·도구·채점 소스 7개 해시를 기존 [분석 manifest](../../artifacts/analyses/20261114-tau2-task-candidates.json)와 대조했다. 모델 호출·업무 실행은 하지 않았다. 참조 행동의 수나 함수명만으로 실제 DB 변경·정책 준수·최단 경로를 단정하지 않는다.

| 과제 ID | 먼저 볼 구조 | 경험 재사용의 가설과 확인할 점 |
| --- | --- | --- |
| 0·40·47·49 | 기존 취소 제한·승객 수정 대조 | 현재 문맥으로 충분한 대조로 유지. 취소 기억이 승객 수정을 개선해야 한다고 가정하지 않음 |
| 7·17 | 대화 중 의도 전환·여러 수정 요청 | 이전 절차가 현재 목표의 누락을 줄이는지. 현재 승인·필드 보존을 확인하고 과거의 구체적인 변경을 복사하지 않는지 |
| 14·20·21·23 | 일정·경로·결제 제약을 함께 만족 | 제약 검증·탐색 절차가 재사용 가능한지. 과거 금액·항공편·결제 값을 후속 정답으로 넣지 않음 |
| 4·39·41·42·43 | 여러 예약의 조회·상태·대상 구분 | 대상 선정·검증 순서의 재사용 후보. 과거 예약을 현재 대상으로 오인하는지도 확인 |
| 11·12·15·33 | 항공편·승객·수하물 등의 변경 제약 | 허용된 변경과 유지할 제약을 구분하는 절차 후보. 현재 정책·도구에서도 얻을 수 있는 내용인지 명시 |
| 1·3·5·9·10·27·28·34·36·38·46 | 상태 확인·정책 적용·사용자 주장과 제약 | 기억이 중복되는지, 유효한 확인 절차를 줄이는지, 불필요한 거절·이관을 늘리는지 보는 대조 후보 |

과제 39는 기존 검토에서 보험 보장 사유의 불명확성이 남아 있다. 전체 train 목록에서는 보존하되 모호함을 사전 표시하고, 공식 점수와 정책 적합성의 해석을 구분한다. 진단용 수정이 필요하면 별도 버전으로 만들며 공식 원본은 고치지 않는다.

확인된 출처 중복에는 40/49의 예약, 14/23의 사용자·기존 예약, 39/41의 예약 집합, 4/47의 예약 일부가 있다. 이 목록을 완전한 출처 분할로 취급하지 않는다. 후속 선정 때 전체 사용자·예약·공개 경험의 중복을 확인하고, 여러 과제 ID를 독립 은행·독립 출처 수로 세지 않는다.

## 4. 탐색 뒤 선정할 기준

- 필요한 행동의 누락, 현재 관측의 미사용, 조건의 과잉 일반화, 탐색·추론의 반복 등을 공개 메시지·도구 결과로 분류한다. 시스템·provider 오류와 실행 한도 문제는 별도 기록한다. 모델의 비공개 추론이나 사후 자기 설명을 원인의 근거로 대신하지 않는다.
- 각 후보에 **원천 공개 경험 / 재사용할 내용 / 현재 입력·도구·사용자에게서 얻을 수 있는 범위 / 후속 행동과 채점 / 적용 조건이 바뀐 대조 / 출처 그룹**을 적는다. 단순히 실패했다는 이유만으로 기억이 해결할 과제라고 선정하지 않는다.
- 현재 정책과 중복돼도 절차·탐색 비용의 재사용은 가설이 될 수 있다. 정보가 과거에만 있는 과제와는 구분한다. 정상 정책·도구 결과를 감춰 기억의 필요성을 만들지 않는다.
- 후보 선정에 쓴 실행 결과를 무기억 본 비교의 기준선으로 재사용하지 않는다. 선정 후 새 반복과 사전 배정으로 비교하며, 일반화 확인은 개발에 쓰지 않은 과제·출처에서 수행한다. 공식 train/test 분할 외에 사용자·예약·경험 중복도 확인한다.
- writer에는 원천 공개 경험과 허용된 피드백만 제공한다. 분석자가 본 후속 실패·참조 정답·채점 주석을 기억 내용으로 옮기지 않는다. 작성 0개도 결과로 남기고 빈 은행의 후속 실행을 포함한다.

## 5. 기억 비교로 넘어가는 판단

관련 기억을 시작에 제공한 비교에서, 필요한 업무·금지 시도·비용의 차이를 새 배정으로 확인한다. 이어 같은 버전의 자율 조회와 빈 은행 대조를 연결한다. 연구자가 만든 확인용 기억과 자율 작성한 기억의 결과는 구분한다. 조회한 run만 골라 정책 효과를 추정하지 않는다.

이 탐색에서 재사용할 경험의 기회가 약하면 그 범위를 보고하고, 계획한 BFCL Memory·AppWorld 확장의 과제 구조 검토를 앞당기는 안을 논의한다. 더 어려운 벤치라는 이유만으로 기억이 유용할 것이라고 가정하지 않는다. 과거 정보 회수의 작은 진단과 업무 성공·전이 실험도 분리한다.

## 6. 실제 구현과 실행 전 남은 일

기존 [전달 비교 실행기](../../src/agent_memory_eval/runner/tau2_delivery.py)는 서로 다른 두 조건의 1차 비교와 고정 은행을 요구한다. 이번에 native 무기억 경로를 재사용하는 [전용 배치 실행기](../development/tau2-baseline.md)와 [별도 초안](../../protocols/drafts/tau2-baseline-screening-v1.json)을 추가했다. 가짜 기억 조건·가짜 은행은 넣지 않았다.

배치에는 고정 소스·실제 프로필·배정표, 새/빈 출력 경로, run별 격리, 전체/개별 한도·실패/생략, 공식 결과·공개 관측·역할별 사용량/비용, 읽기 전용 원본 재검증을 구현했다. native 모의 HTTP로 전송 요청의 기억 도구 미노출·한도 중단·새 회차 분리·요약 변조/불완전 원본 거절을 확인한다. 파일 방식을 유지하고 완료한 run의 출처는 과거 commit에 보존해 현재 head의 누적 복사를 줄인다. 실제 확대 시 저장량·검증 시간 측정은 여전히 필요하다.

**완료 범위는 프로토콜/후보표 초안과 무기억 배치의 오프라인 구현·행동 검증이다.** 새 유료 호출·기억 생성·추가 업무 결과는 아직 없다. 실제 호출 전에는 전체 비용 상한과 검토용 제안 값들을 확정하고, 새 실행 프로필·배정·구현 해시를 고정한다.
