# 관련 연구와 기여 비교

2026-11-14 · 기존 조사 자료를 연구 초점별로 재구성

아래 논문·공식 문서 내용은 기존 레포의 2026-11-13 조사와 후속 상세 설계에서 이어받았다. 이관을 새 문헌 재조사·저자 결과 재현·최신 전체 목록으로 표시하지 않는다. 초기 12편 조사 표는 [문헌 자료](../references/README.md)에 별도로 보존한다.

## 벤치와 프레임워크의 비교

| 벤치 또는 프레임워크 | 확인한 측정·비교 | 우리 설계에 활용하거나 구분할 점 |
| --- | --- | --- |
| [τ²-bench 공식 평가](https://github.com/sierra-research/tau2-bench/blob/main/docs/evaluation.md) | 과제별 평가 항목에 따른 최종 상태·필수 전달 정보 등의 성공 판정 | 공식 성공 점수를 유지하고 요구사항별 진척·기억 개입 분석은 별도 검증기로 추가. 예시 행동 순서와의 일치를 진척도로 삼지 않음 |
| [STATE-Bench](https://github.com/microsoft/STATE-Bench/blob/main/README.md) | 공식 대표 지표는 5회 평균 완료율 pass@1, 전부 성공한 과제 비율 pass^5, UX 점수와 과제당 보고 비용 | 신뢰성과 상호작용 품질도 평가 가능. 같은 은행으로 적응하는 반복을 독립 pass^5와 혼합하지 않음 |
| [AgentBoard](https://arxiv.org/html/2401.13178) | 성공률, 하위 목표·상태 일치 기반 진척률과 단계별 곡선, 유효 행동 비율, 난이도·하위 능력 분석 | 실패 상태의 진척과 유효 행동 비율은 기존 지표. 진척률이 최고 도달 상태를 반영한다는 점을 유의해 최종 상태도 별도로 검사 |
| [MemoryArena v2](https://arxiv.org/html/2602.16313v2) | 전체 성공률 SR, 완료한 하위 과제 비율 PS, 하위 과제별 제약 충족률 sPS, 의존 깊이별 성공과 지연 | 실패→실패의 부분 진척을 표현하는 직접적인 선례. PS·sPS의 변화와 회복·회귀 분류를 함께 볼 수 있음 |
| [LongMemEval v2](https://arxiv.org/html/2410.10813v2) | QA 정답 판정, 주석된 근거 위치에 대한 Recall@k·NDCG@k, 저장·색인·읽기 설계 비교 | 관련 근거를 찾는 능력과 답에 활용하는 능력을 구분. 자율 작성 기억에는 동일한 근거 주석이 자동으로 존재하지 않음 |
| [MemoryAgentBench v4](https://arxiv.org/html/2507.05257v4) | 검색·시험 중 학습·장거리 이해·선택적 망각의 과제별 점수와 정확도, 비용·계산량 통제 분석 | 기억 능력과 비용 비교는 기존 범위. 분류·QA 결과를 실제 업무 행동의 성공이나 개별 기억 효용과 동일시하지 않음 |
| [MemoryBench v7](https://arxiv.org/html/2510.17281v7) | 과제별 점수의 정규화 집계, 피드백을 이용한 on-policy·off-policy 학습, 단계별 평가, 기억 처리 시간과 예측 시간 | 같은 경험을 이용한 평가와 자연 경험 수집, 피드백의 효과, 작성·조회 시간 분리는 기존에도 연구됨 |
| [Evo-Memory](https://arxiv.org/html/2511.20857) | 스트림의 누적 정확도, 성공·진척률, 완료 단계 수, 쉬운 과제와 어려운 과제의 배치 순서 비교 | 누적 성능과 작업 순서 효과 자체는 노벨티가 아님. 고정 확인 과제와 공통 순서의 정책 비교로 해석 보완 |
| [EvoMemBench v3](https://arxiv.org/html/2605.18421v3) | 수행 중·과제 간 기억 진화와 지식·실행의 네 설정, 정확도·성공·진척·평균 단계·토큰 사용 | 저장 시점·기억 형태·전이를 폭넓게 다루는 가까운 비교 대상. 네 설정이나 효율을 포함했다는 이유만으로 차별화하기 어려움 |
| [MemGym](https://arxiv.org/html/2605.20833) | 동일 작업자의 기준선 대비 memory gain, 압축률, 압축의 안전·유해 결과와 평가 신호 | 고정 모델의 기억 효과와 국소적인 압축 평가의 선례. 저자도 memory gain이 완전히 독립적인 기억 능력의 분해는 아니라고 명시 |
| [HaluMem](https://arxiv.org/html/2511.03506) | 기억 추출의 정확도·보존률·F1, 오정보 저항, 갱신 정확도·누락·환각, QA와 효율 | 저장·갱신 단계의 오류 측정은 이미 존재. 자유 작성한 경험 기억을 실제 후속 행동과 연결하는 추가 검증이 필요 |
| [MemTools](https://arxiv.org/html/2607.21404) | 기억 생성·저장·검색·활용 구성요소 교체, 데이터와 실행 프로토콜 분리, offline·online 절차, 혼합 구성과 batch·stream 성능 비교 | 현재 프레임워크 구상의 직접적인 비교 대상. 구성요소 교체·실행 시점 설정·공통 인터페이스 자체를 신규 기여로 삼기 어려움 |

STATE-Bench의 [Agent Learning Track](https://github.com/microsoft/STATE-Bench/blob/main/docs/AGENT_LEARNING_TRACK.md)은 학습 궤적에서 만든 산출물을 held-out 작업에 적용하며, 산출물 자체 대신 실행 결과를 평가한다. 공식 조회 훅은 읽기 전용이다. 공식 과제당 비용은 에이전트가 보고한 금액에 의존하므로, 오프라인 기억 생성 비용을 포함한 우리의 전체 비용 집계와 구분해야 한다.

MemoryArena는 PS를 하위 과제의 완료 비율로, sPS를 각 하위 과제 제약의 충족 비율을 평균한 값으로 정의한다. 일부 환경에서는 최종 하위 과제 정답이 SR을 결정하므로 PS와 SR이 같은 양이라고 가정하지 않는다. [지표 정의](https://arxiv.org/html/2602.16313v2#S4.SS2)

HaluMem의 FMR은 False Memory Resistance로, 정의된 방해 기억을 무시한 비율이며 높을수록 좋다. 이를 일반적인 false memory rate와 같은 이름으로 옮기면 방향과 분모를 잘못 해석할 수 있다. 기존 지표는 이름뿐 아니라 단위·분모·판정 기준까지 함께 가져온다. [추출 지표 정의](https://arxiv.org/html/2511.03506)

## BFCL과 환경 확장

BFCL V4 Memory에는 선행 대화에서 기억을 작성하고 snapshot을 저장한 뒤, 대화 이력 없이 같은 snapshot에서 질문별로 평가하는 절차가 이미 있다. 확장 대상이면서 직접적인 관련 연구다. [공식 Memory 설명](https://gorilla.cs.berkeley.edu/blogs/16_bfcl_v4_memory.html)

AppWorld는 여러 앱의 코드/API 실행과 DB 상태 기반 평가를 제공하는 확장 환경이다. [공식 문서](https://github.com/StonyBrookNLP/appworld) 환경을 여러 개 지원하는 목표와 실제 효과 일반화의 검증은 구분한다.

우리 연구에서는 저장 내용·조회·노출과 실제 업무 수행의 회복·악화·진척·전이·비용을 어떤 통제 비교로 추가 설명하는지 검증한다.

## 관련 기억 정책 연구

| 선행연구 | 이미 다루는 범위와 이번 설계의 관계 |
| --- | --- |
| [ReasoningBank](https://arxiv.org/html/2509.25140v2) | 성공·실패 경험에서 전략을 추출하고 후속 작업에 활용한다. 경험을 기억으로 만들어 성능을 높이는 것 자체는 기존 연구 범위다. |
| [AgeMem](https://aclanthology.org/2026.acl-long.981/) | 저장·조회·수정·요약·삭제를 도구 행동으로 다룬다. LLM에게 기억 도구를 제공하는 것 자체의 새로움은 제한적이다. |
| [When Continual Learning Moves to Memory](https://arxiv.org/html/2604.27003) | 경험 표현, 저장 단위, 조회 빈도와 긍정·부정 전이를 분석한다. 저장과 조회의 관계를 묻는 것만으로 독창성을 주장하기 어렵다. |
| [JitMem](https://arxiv.org/html/2609.27334) | 원경험을 저장하고 현재 과제에 맞춰 조회 시 가공하며 τ²-bench도 평가한다. 수행 중·종료 후 작성 시점과는 다른 축이지만, 표현·조회 비교의 가까운 선행연구다. |
| [MemGym](https://arxiv.org/html/2605.20833) | τ²-bench 등을 포함한 기억 평가와 동일 작업자에서의 비교를 다룬다. 주로 수행 중 문맥 압축을 평가하므로 후속 작업으로 이어지는 자율 저장·조회와 구분해 대조한다. |
| [Useful Memories Become Faulty When Continuously Updated by LLMs](https://arxiv.org/html/2605.12978) | 동일 경험의 갱신 방식에 따른 기억 차이와 누적 정리 후 성능 악화를 분석한다. 누적 회귀를 관찰하는 것 자체는 새 기여가 아니다. |
| [MemTrim](https://arxiv.org/html/2610.07311) | 현재 과제와 일부만 맞는 기억이 손해를 주는 현상과 저장·조회 단계의 제어를 다룬다. 기억의 오용이나 손해만으로 차별화하기 어렵다. |
| [Self Evolving Agents Can Repair Failures but Struggle to Generalize from Them](https://arxiv.org/html/2610.22984v1) | 실패 경험을 통한 원래 과제 복구와 새 과제로의 전이를 구분한다. 재시도와 전이를 나누는 것만으로 독창성을 주장할 수는 없다. |
| [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory) | 기억 작성·표현·조회와 작성 시점의 문제를 다룬 연구 글이다. 수행 중 저장과 사후 정리의 비교 역시 구체적인 검증 조건과 추가 근거가 필요하다. |

이 선행연구들이 전체 실험을 이미 수행했다는 결론은 아니다. 기여를 평가할 때에는 단순한 측정 항목의 추가보다 **기존 결과로 설명하지 못한 정책 간 차이와 그 원인을 어떤 교차 비교·내용 개입·후속 검증으로 설명했는지**를 확인한다. 현재는 타당한 실험 골격과 기여 후보를 정리한 단계이며 독창성은 미확정이다. 기존 [문헌 조사 자료](../references/literature/review.json)는 앞선 조사 범위이며, 위 추가 자료까지 모두 포함한 목록으로 해석하지 않는다.



## 기여 주장에 대한 판단

| 주장 후보 | 현재 판단과 가까운 선행연구 |
| --- | --- |
| 메모리 평가를 공통 프레임워크로 지원한다 | MemGym·MemTools가 직접적인 선례. 이것만으로는 차별성이 약함 |
| 모델을 고정해 기억 효과를 평가한다 | MemGym 등의 기본 비교 방식. 실험 통제의 조건으로 사용 |
| 실패 상태의 부분 진척을 측정한다 | AgentBoard·MemoryArena·EvoMemBench에서 이미 측정 |
| 저장·갱신·조회 단계를 구분한다 | HaluMem·LongMemEval·MemTools 등과 겹침 |
| 수행 중과 과제 간 기억을 함께 본다 | EvoMemBench·Evo-Memory·MemoryArena 등과 겹침 |
| 교차 구성과 작업 순서의 효과를 본다 | MemTools의 구성 교체, Evo-Memory의 순서 비교가 선례 |
| 자율 생성 기억의 변경과 노출을 회복·회귀·진척의 개입 결과에 연결한다 | 추가로 검증할 기여 후보. 기존 지표·기능의 결합만이 아니라 어떤 새 진단·설명이 가능한지 증거 필요 |

기능·설정 측면의 가까운 비교 대상에는 MemTools와 EvoMemBench가 있으며, 세션 간 저장·조회 절차에는 BFCL V4 Memory를 함께 대조한다. MemTools는 서로 다른 시스템의 생성·검색 구성요소를 섞고 실행 프로토콜을 바꾸는 실험까지 제시한다. EvoMemBench는 수행 중·과제 간 지식·실행을 함께 평가한다. 따라서 현재 설계의 기능 목록만으로 이들보다 새로운 프레임워크라고 결론 낼 수는 없다.

관련 정책 연구인 [JitMem](https://arxiv.org/html/2609.27334)도 원경험 보존과 조회 시 가공을 비교한다. 전체 기록보다 요약이 항상 좋다거나, 조회 시 가공 자체가 새롭다는 주장도 피한다.

기여는 다음 세 형태로 구체화할 수 있다. 모두 결과로 검증할 후보이며 현재 확보한 성과는 아니다.

1. **실험 절차와 자료의 기여.** 같은 경험에서 만든 여러 기억 버전, 실제 노출, 업무 상태, 결과와 개입 분기를 연결해 재현 가능한 비교 자료를 제공한다. 기존 공개 기능·자료와 대조해 어떤 분석이 추가로 가능해지는지 보인다.
2. **측정의 타당성과 진단 기여.** 관측된 회복·회귀, 부분 진척, 단계별 정보 품질을 실행 변동과 구분하고, 실제 개입 결과를 얼마나 잘 설명하는지 검증한다. 기존 점수와 동일한 정보만 제공하는지도 확인한다.
3. **실증적 발견의 기여.** 작성 시점·내용 변화·조회 정책의 조합이 언제 회복·회귀·효율 차이를 만드는지 반복 검증한다. 예를 들어 수행 중 추측을 종료 후 정리가 수정하는지 강화하는지, 그 변화가 후속 판단을 바꾸는지까지 연결한다.

범위를 줄이기보다 연구 주장과 비교·수치·원본 근거를 연결한다. 새로운 지표의 개수나 기능의 개수를 노벨티로 삼지 않는다.

자율 조회 파일럿 이후 추가로 확인한 문헌(MemUse·Delivery, Not Storage·MERIT 등)과 우리 연구가 더할 수 있는 점은 [발전 방향 노트](novelty-direction-review.md)에 정리했다. 위 표를 보완하는 초록 수준의 확인이다.
