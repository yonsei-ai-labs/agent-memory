# 성패를 안 작성자가 다른 메모를 쓰는가

은행의 무기억 1회차 네 건과 피드백 없이 작성한 다섯 형식의 메모가 대조 자료다. 과제 008은 성공했고 001·010·015는 실패했다. 010에서 도구가 이관 성공을 반환했지만 과제의 공식 결과는 실패였다. 결과를 알려 주면 메모가 이 차이를 보존하고, 이후 상담의 행동이나 성과에도 차이가 나타나는지 조사한다. [원래 상담과 메모](../../artifacts/analyses/20261124-banking-required-results.json)

## 배정

같은 공개 궤적을 같은 모델의 독립된 작성 세션 다섯 개에 제공한다. 첫 요청에서 마지막 피드백 메시지에만 공식 성패 한 값을 넣는다. 그 밖의 바이트가 과거 실제 요청과 같은지 전송 전에 검사한다. 공식 성패의 출처는 이전 채점 이벤트다. 각 원천에서 사실·경험·절차·교훈·자유 메모가 모두 저장되면, 동일한 첫 업무 판단에서 자동 제공과 자율 조회로 각각 새 상담을 시작한다. 모든 비용과 기술 결측을 원래 배정에 남긴다. [고정 프로토콜과 지표](../../protocols/pilots/tau-banking-result-feedback-v1.json)

| 범위 | 1회차 재사용 | 새 작성 | 새 자동 제공 상담 | 새 자율 조회 상담 |
|---|---:|---:|---:|---:|
| 전체 | 4 | 20 | 20 | 20 |
| 작성 단계 | 4 | 20 | 0 | 0 |

두 범위의 작성 요청 해시는 동일하다. 실제 실행은 선택된 등록 한 건만 사용하며, 작성 단계가 선택되면 상담 비용과 배정은 0이다. [전체 배정과 입력 해시](../../artifacts/pilots/20261125-banking-result-feedback-preflight.json) · [작성만 하는 배정](../../artifacts/pilots/20261125-banking-result-feedback-writing-preflight.json)

## 해석

사전 예상은 성패 피드백의 변화가 먼저 메모의 표현에서 나타난다는 것이다. 예컨대 010의 작성자는 이관 성공과 과제 실패를 함께 기록할 수 있다. 실패라는 한 값으로 고객에게 필요한 다음 행동까지 알아낼 수 있는지는 별개의 질문이다. 과거 자동 제공 성공은 001·008·010·015 순서로 0·5·0·3건(각 5건)이었다. 008은 이미 상한에 도달했고, 자율 조회에서는 메모를 한 번도 열지 않았다. [이전 상담 결과](../../artifacts/analyses/20261124-banking-required-results.json)

주 비교는 자동 제공 20쌍의 공식 성공이다. 짝은 같은 과제·형식·전달 방식의 과거 상담과 새 상담이다. 자율 조회에서도 같은 방식으로 회복·손실·동률·결측과 실제 조회 횟수를 센다. 양쪽 다 성공한 상담에서는 검색·업무 호출·턴·토큰·비용을 비교한다. 1회차 대비 변화는 별도로 제시한다. 첫 공개 입력이 같은 판단과 서로 다른 행동·대화가 이어진 이후의 성과를 구분한다.

두 조건의 메모 원문에서는 실패한 과거 상담의 마무리를 다시 권하는지, 한계를 적었는지, 판단하기 어려운지를 구분한다. 예를 들어 고객이 요구한 이관을 조건부로 설명한 문장만으로 추천 제출까지 완료했다고 판정할 수 없다. 성공한 008에서는 이관을 어느 조건까지 일반화하는지 본다. 전체 성패를 메모에 명시한 횟수도 따로 센다. 각 판독의 근거를 해당 원문 인용에 연결한다.

비교에 쓰는 과제는 네 개이고 한 원천에서 만든 다섯 형식은 같은 경험을 공유한다. 두 피드백 조건은 다른 시점에 실행되며, 모델과 후속 고객의 응답에는 변동이 있다. 모든 메모에서 결과를 정확히 적더라도 후속 과제를 더 잘 푸는지는 상담 결과로 확인해야 한다.

지난 같은 규모의 추가 실측 비용은 작성 $0.039135750, 상담 $0.159550714였다. 이전까지의 누적 비용은 $0.403789709다. 이번 승인에 적힌 배정과 누적 상한을 등록한 뒤 실행한다. [이전 실측과 원장](../reports/20261124-banking-required-results.md)

```bash
uv run python -m scripts.run_banking_memory preflight --series result-feedback --workspace .
uv run python -m scripts.run_banking_memory run --series result-feedback --workspace .
uv run python -m scripts.analyze_banking_memory --result-feedback --workspace .
uv run python -m scripts.review_banking_evidence --writer-comparison --workspace . --output outputs/banking-feedback-notes
```

작성 내용 판독은 `blinded-notes.json`에서 한다. 텍스트 자체가 공식 결과를 언급해 작성 조건을 짐작할 수 있다. `note-assignments.json`에는 조건과 봉인본 식별자가 있다. 먼저 문장과 판정을 기록하고, `--note-ratings`로 원문 인용 위치를 검증한 뒤 배정표에 연결한다.

11월 25일 전체 배정을 마쳤다. 성패를 받은 작성자의 메모 20개 중 한 개가 과제 전체의 공식 성패를 명시했다. 기존 대비 자동 제공 성공은 8/20에서 6/20으로 바뀌었다. [과제별 성패·실제 조회·업무 판단의 근거](../reports/20261125-banking-result-feedback.md)
