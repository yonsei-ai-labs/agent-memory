# 고정 기억 전달 방식의 개발 파일럿 프로토콜

2026-11-14 · 실행 전 고정 · 조건부 고정 은행 비교

같은 과거 기억을 시작 시 제공하는 경우와 자율 조회에 맡기는 경우의 업무 결과·노출·행동·비용을 비교한다. [실행 설정](../../protocols/pilots/tau2-delivery-development-v1.json)은 사용자가 승인한 새 실행의 보고 비용 상한 $3과 함께 고정한다. 초기 [초안](../../protocols/drafts/tau2-delivery-comparison-v1.json)은 유지한다.

## 배정과 통제

| 항목 | 실행값과 이유 |
| --- | --- |
| 과제 | airline 공식 train 40·47·49. 기존 성과로 고른 과제가 아닌, [사전 후보 검토](tau2-task-selection-and-rubric.md)의 우선 개발 후보 |
| 판단 대상 | 40은 필요한 승객 성 수정, 47은 보험이 있어도 보장되지 않는 취소 사유, 49는 보험 가입 주장과 현재 기록의 충돌 |

고정 은행이 주어진 상황의 전달 비교다. 자율 작성의 성공률이나 비어 있는 source를 제외한 자연 정책 전체의 성과로 합치지 않는다. 일반 취소 조건은 기본 정책에도 있으며, 현재 은행의 과제 0 사례가 새 예약의 사실을 대신하지 않는다. 과거에만 있는 필수 정보를 제공한 실험으로 표현하지 않는다.

모든 run에서 세션·작업자·사용자·업무 DB와 은행을 새로 배정한다. 무기억에는 과거 기억·도구·기억 지침을 넣지 않는다. 전체 응답 캐시는 끄며 provider의 입력 prefix 캐시 사용량은 원본대로 보존한다. 모델 설정의 seed 0을 반복하고, 미지원 사용자 seed는 보내지 않는다. 호스팅 모델의 독립성이나 결정성을 가정하지 않는다.

## 분석 기준과 중단

1차 비교는 동일 과제에서 `on_demand` 대비 `full_preload`의 공식 성공 관측 차이다. 과제별 배정·시작·채점·성공·오류·생략을 함께 보고하고, 유효 채점만의 비율로 불완전 배정을 숨기지 않는다. 반복과 한 은행, 공유 예약의 의존성이 있어 독립 표본 48개로 검정하지 않는다. 이번 실행은 개발 관측이며 확인용 test에 대한 결론이 아니다.

노출은 실제 요청의 제목·본문·버전과 시점으로 확인하고, 도구 반환·입력 포함·활용을 구분한다. 요청 전송 상태도 함께 본다. source의 원기록·정답·이 문서·분석 주석은 worker·writer 입력에 넣지 않는다.

정책 의미 검토는 기존 `tau2-airline-behavior-review/v0.1`을 사용한다. 40은 필요한 수정의 완료·인원/다른 승객/생년월일 보존·변경 전 확인, 47·49는 취소 시도·거절 설명·이관 근거를 본다. 공식 점수와 의미 판정을 합치지 않으며, 불명확하면 미확정으로 남긴다. 주석은 단일 에이전트 검토임을 밝히고, 사례 선택만으로 효과나 원인을 주장하지 않는다.

비용 미확인·전송 불확실성·전체 한도 도달 시 남은 배정을 생략한다. 실패·생략을 유리한 결과가 나올 때까지 교체하지 않는다. 도구/요청/입력 크기 한도에 막힌 실행도 원인과 배정을 보존한다. 원본을 덮거나 세션을 임의 복구하지 않는다. source 생성 비용은 이번 평가 지출과 별도다.

프로토콜·기존 주석 기준·구현 해시는 [실행 전 고정 기록](../../artifacts/pilots/20261114-tau2-delivery-development-protocol.json)에 남긴다. 실제 결과·해석은 별도 보고서에 작성한다.
