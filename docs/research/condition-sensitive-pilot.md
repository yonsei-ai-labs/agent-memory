# 적용 조건 기억 파일럿과 조회 필터 제안

2026-11-14 · 실험팀 인계 문서를 구체화한 제안, 실행 전

**같은 경험에서 일반 요약과 적용 조건·절차를 담은 기억을 작성하고, 적용 가능한 후속 과제와 조건이 바뀐 과제에서 적절한 재사용·보류가 달라지는지 본다.** 초기 실행 연결과 변동·비용을 확인하는 파일럿 후보이며 전체 연구를 이 비교로 한정하지 않는다. [원문 검토](../handoff/experiment-handoff-review.md), [전체 프로토콜](experiment-protocol.md)을 함께 따른다.

## 비교의 위치와 통제

`common_experience`의 종료 후 작성 비교로 시작한다. 같은 공개 경험·허용 피드백에서 기억을 만들고, 조회를 시작 시 제공으로 고정해 저장 표현의 영향을 관찰한다. 이는 자연 누적·수행 중 작성의 효과나 자율 선택 능력을 곧바로 측정하지 않는다. 이후 동일 은행에 조회 정책을 교차한다.

| 조건 | 후속 세션의 과거 정보 |
| --- | --- |
| 무기억 반복 | 없음. 현재 과제의 기본 정보와 정상 업무 도구는 제공 |
| 원기록 접근 | 같은 공개 경험. 접근 범위·제공/조회 방식·직렬화 명세 |
| 일반 요약 | 일반 요약 지침으로 작성한 은행 |
| 적용 조건·절차 | 언제 적용되는지·절차·주의점을 명시하도록 작성한 은행 |

각 작성 조건은 같은 원천 기록에서 독립적으로 시작한다. 다른 조건의 출력·후속 과제 정답·평가 주석을 보지 않는다. 같은 Luna·제공 경로·작성 설정과 공개 경험을 사용하고 지침 차이·추가 호출을 기록한다. 자연 실행의 동일 대화에서 사후 작성하는 방식과 별도 작성 문맥으로 같은 기록을 주는 방식도 구분한다.

일반 요약이 자발적으로 조건을 보존하면 그대로 평가한다. 조건 표현을 지우거나 조건·절차 기억에 정답을 연구자가 보충하지 않는다. 실제 내용·적용 조건·근거 보존을 양쪽에서 주석하고 자연적으로 달라진 길이·노출 토큰·비용을 보고한다. 표현 지침의 전체 효과와 문장 길이만의 효과를 동일시하지 않는다. 필요하면 분량을 맞춘 별도 진단을 추가한다.

원기록이 문맥을 넘으면 실행 전에 정의한 접근 방식을 사용하고 실제 전달 범위를 남긴다. 임의의 BM25·2k 분할이나 숨은 잘라내기를 추가하지 않는다. 현재 업무 규칙은 모든 조건에 동일하게 제공한다. 기억이 현행 규칙을 반복한 경우와 경험에서 얻은 절차를 보존한 경우도 구분한다. 기본 정보만으로 충분해 효과가 없거나 성능이 포화되는 결과도 유효하다.

## 적용 조건이 다른 후속 과제

같은 원천별로 재시도·적용 가능한 관련 새 과제·중요 조건이 바뀐 새 과제를 구분한다. 원천과 변형은 같은 출처 그룹에 둔다. 확인 과제의 실행·정답은 기억 수집과 지침/임계값 튜닝에 사용하지 않는다.

항공 예시는 **출발 전의 항공편 일정 변경**을 기준으로 economy와 basic economy를 대조하는 진단쌍을 제안한다. 공식 33·36번은 등급 외의 조건도 다르므로 가설 설명에만 쓰고 단일 요인 대조쌍으로 직접 사용하지 않는다. [검토한 원본 과제](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/data/tau2/domains/airline/tasks.json)

| 고정·검증할 부분 | 준비 기준 |
| --- | --- |
| 과제의 변경 요인 | 현재 요금 등급과 그 정합성에 필요한 수정 범위를 명시. 변경 전후 task/DB diff·해시 보관 |
| 나머지 업무 조건 | 요청·출발 상태·노선·일정·사용자 요구·승인·좌석/지불 가능 조건을 맞추고 정상 처리 가능성 확인 |
| 정보 접근 | 현재 등급은 정상 업무 관측으로 확인 가능. 내부 정답·채점 주석은 worker/writer/필터 입력에서 제외 |
| 기대 결과 | 가능한 일정 변경의 완료와 금지된 일정 변경의 적절한 거절을 구분. 불필요한 좌석 변경·우회 변경도 판정 규칙에 명시 |
| 과제 식별 | 중립적인 새 진단 ID와 원본 부모/출처 그룹 연결. 표면적 ID로 허용/금지를 알려주지 않음 |
| 채점 | 변형 task의 기대 DB·설명 요구·실패 조건을 사전 검산. 아무 행동도 하지 않은 상태를 정당한 업무 성공으로 오인하지 않음 |

공식 정책은 항공편 변경과 좌석 등급 변경을 따로 다루며, `update_reservation_flights`는 flights와 cabin을 함께 받는다. 금지 행동 판정은 함수 이름만 세지 않고 직전 예약 상태·요청한 변경 인수·공개된 사용자 승인에 근거한다. 기본 이코노미의 모든 예약 변경 호출을 일괄 금지로 라벨링하지 않는다. [정책](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/data/tau2/domains/airline/policy.md), [도구](https://github.com/sierra-research/tau2-bench/blob/c06b07dd7c4d4ec61ba6ff9bcdf0b15dd7ef36d4/src/tau2/domains/airline/tools.py#L665-L760)

결과는 **τ²-bench 기반 변형 진단**으로 보고한다. 원래 벤치 결과·native 채점 원본과 추가 행동/설명 판정을 보존하고, 수정 과제의 점수를 공식 원본 점수로 표현하지 않는다. 평가를 위해 별도의 업무 규칙 차단기를 몰래 추가하지 않는다.

## 기록과 해석

각 후속 시도는 새 업무 상태·대화·사용자·provider 연결에서 시작하고 은행을 독립 복제한다. 고정 은행 진단에서는 후속 쓰기 중지 여부를 명시한다. 이 진단의 설정을 전체 프레임워크의 기본 쓰기 정책으로 적용하지 않는다.

| 관측 | 기록과 구분 |
| --- | --- |
| 결과 | 과제 유형별 성공 확률 차이·불확실성, 사전 배정 결과 짝, 채점/실행 결측 |
| 행동 | 적용 조건 근거의 확보 시점, 최초 변경 판단, 요청/실행된 도구·인수, 도구 오류와 실제 DB 효과 |
| 기억 | 원천 경험의 근거·조건 보존, 판단 시점 은행 버전, 제목/본문 최초 입력 포함 시점 |
| 비용 | 원천 수집·작성·조회·가공·필터·업무의 고유 호출·토큰·시간·비용과 배분 |

무기억 대 무기억 반복도 수행해 자연 반전을 확인한다. 한 번 쓴 은행을 여러 번 평가한 결과를 독립된 여러 저장 표본으로 세지 않는다. 원천 경험·작성 은행·후속 반복의 구조를 구분한다. 파일럿으로 파악한 변동·비용은 본실험 설계에 활용하되, 작은 과제쌍만으로 전체 표본 규모·일반화 성능을 확정하지 않는다. 결과를 보고 선택한 지침·사례를 독립 test로 다시 사용하지 않는다.

조건 문장 개입은 제목·목록·본문을 통틀어 최초 관련 정보 노출 전 상태에서 분기한다. 복원 범위·대화/사용자/난수·입력 일치를 검증하고, 안 되는 경우 일반 재실행으로 기록한다. 원문/수정문 diff·길이·해시를 보존하고 연구자 교정 효과를 자율 작성 성적으로 합치지 않는다.

## 저장과 조회의 후속 교차

작성 정책별 같은 은행을 시작 시 제공·수행 중 자율 조회에 각각 적용한다. 지침·목록 정책·읽기 한도·변환 여부와 추가 비용을 명시한다. 첫 파일럿의 자동 제공만으로 LLM이 올바른 기억을 선택했다고 결론 내리지 않는다.

1개·N개 후보 비교는 같은 기준 기억 버전에 다른 후보를 더해 구성한다. 새로 작성하거나 정답 역할을 노출하지 않는다. 목록 순서·제목 노출량·읽기 한도·페이지·실제 입력량을 기록하고, 추가 후보의 적용 가능성은 별도 주석으로 판정한다. 항상 유일한 정답 항목이 있다고 가정하지 않는다.

## 선택적 적용 가능성 필터

같은 은행·동일한 필터 전 후보를 두고 통과 제공과 적용 가능성 확인 후 제공을 비교한다. 판정에는 해당 시점에 작업자가 볼 수 있는 현재 업무 관측·공개 기억만 쓴다. 숨은 DB·미래 도구 결과·과제 정답·분석용 역할 라벨을 사용하지 않는다. 근거 부족은 `unknown`으로 보존하고 통과·보류·추가 확인의 규칙을 실행 전에 정한다.

- 독립 문맥의 필터가 읽은 내용과 작업자에게 전달된 내용을 나눠 기록한다. 같은 작업자 대화에 먼저 본문을 넣었다면 미노출 필터가 아니다.
- 제목이 목록에서 이미 보였는지, 필터가 목록 이전인지 get 이후인지, 이후 대화에서 거절된 내용이 다시 유입되는지 남긴다. 판정 설명에 본문이 누출되는 경우도 노출로 센다.
- 부적합 차단·적합 차단·미확정 비율·작업자 노출·성공/회귀·지연/비용을 함께 본다. 적용 가능성과 실제 효용을 동일 라벨로 만들지 않는다.
- 규칙 또는 별도 문맥의 Luna 판단부터 비교할 수 있다. Jev 등 별도 모델은 보조 판정기 조건으로 구분하며 worker 고정 조건과 추가 모델·호출 비용을 명시한다.

Jev v2는 선택/확률 판단·임계값 조정과 한계를 다루지만 기억 적용성 검증을 제공하지 않는다. 이 모델이 필요하면 개발 자료에서 임계값을 고정하고 같은 관측·후보로 비교한다. 일반 분류 성능을 우리 기억 선택의 성능으로 옮기지 않는다. [확인한 논문](https://arxiv.org/html/2609.37647v2)

필터는 현재 미구현이며 실행 필수 의존성이 아니다. 별도 selector 역할을 추가할 때는 현재 사건 스키마의 actor role과의 관계, 판정 원본·worker 노출·비용 연결을 명시하고 계약/호환 검증을 갱신한다. 현재 `curator` 역할에 의미를 묵시적으로 추가하지 않는다.

## 실제 실행 전에 남은 일

코어·τ² 연결과 native 채점을 먼저 검증한다. 그 다음 변형 과제·writer 지침·정보 공개·원기록 접근·은행/반복 배정·모델 설정·노출량·중단/비용·채점과 통계를 별도 draft 계획에 고정한다. [공통 두 회차 초안 v1.1](../../protocols/drafts/tau2-two-pass-v1.1.json)의 네 저장 시점·자율 조회를 이 파일럿으로 교체하지 않는다.

현재는 문서 제안이며 과제쌍 파일·변경된 업무 DB·지침 hash·반복 수·모델 실행 결과는 없다. 첫 공통 코어 개발을 기다리게 만드는 추가 필수 요건으로 삼지 않는다.
