# 이미 작성한 기억의 후속 판단 비교 준비

2026-11-17 · 다음 실험의 오프라인 초안 · 새 유료 실행 없음

[첫 작성 실측](../reports/20261117-memory-writing-results.md)의 10개 snapshot을 모두 유지하고, 빈 기억·일반 주의 메모·모델 작성 기억·연구자 메모를 같은 형식으로 비교할 준비 경로다. [전용 draft](../../protocols/drafts/tau2-written-memory-replay-v1.json)는 실행 프로필이 아니며 표본·비용·독립 판정 기준은 미정이다. 기존 작성 10회의 승인을 다음 유료 실행의 승인으로 사용하지 않는다.

구현 담당과 별도로 코드·원본 대조·네트워크 차단 실행을 검토한 [오프라인 리뷰 기록](../../artifacts/analyses/20261117-written-memory-preparation-review.json)을 보존한다. 이 검토는 후보 결정·기억 내용의 독립 의미 판정을 대신하지 않는다.

## 현재 할 수 있는 준비

```bash
uv run --frozen python scripts/prepare_written_memory_comparison.py \
  --output outputs/NEW_WRITTEN_MEMORY_COMPARISON
```

이 명령은 보존된 작성 run과 baseline run을 읽어 기존 [공통 문맥 renderer](../../src/agent_memory_eval/memory/context.py)로 입력을 만든다. 모델·catalog·사용자 시뮬레이터·업무 도구를 호출하지 않으며 `--live` 경로도 없다. 새 출력 폴더에 요청 payload와 준비 manifest를 쓴다. 원본 내부나 이미 존재하는 폴더에는 내보내지 않는다.

각 후보 결정 × writer run × 네 조건을 한 번씩 구성한다. 이는 배정/짝을 확인하기 위한 준비 행이며 실제 유료 반복 수가 아니다. 모든 조건의 system 안내·메모 역할/위치·업무 도구·원래 대화·모델 파라미터는 같고 기억 항목만 다르다. 모델이 쓴 제목·본문·불투명 ID/버전은 그대로 둔다. 통제 메모의 ID/제목에는 조건명·피드백명을 쓰지 않으며 출처와 작성자의 정보 접근은 분석 manifest/profile에 남긴다.

빈 작성을 제거하지 않는다. 모델 작성의 빈 snapshot과 empty 조건이 완전히 같은 입력이면 같은 hash로 묶는다. 같은 generic/researcher/empty 입력도 writer run마다 독립 기억처럼 세지 않는다. 자연 길이·구체성·문체의 차이는 남으므로 일반 메모 대조를 토큰 길이까지 통제한 효과라고 부르지 않는다.

## 후보 상태와 적격성

| 후보 | 선정 지점과 목적 | 현재 한계 |
| --- | --- | --- |
| 14·2 | 기존 실패에서 유일한 예약 호출 직전. 필요 수량 확인과 허용량 혼동 점검 | 작성에 쓴 원천 궤적과 같아 새 과제 전이가 아님. 비공개 정답 수량을 제공하지 않음 |
| 14·1 | 성공 반복의 유일한 예약 호출 직전. 원래 옳았던 상태의 훼손 후보 | 에피소드 성공은 이 결정의 전체 정책 적합성을 보장하지 않음. 독립 심사 전 |
| 23·2 | 한 예약에 증서 세 장을 넣은 기존 실패 직전. 실제 기억에 남은 결제 규칙의 효용 후보 | 한 장 규칙은 현재 정책에도 있어 새 정보 전이로 해석하지 않음 |
| 23·1 | 성공 반복의 첫 예약 직전. 한 장 규칙을 지키는 상태의 훼손 후보 | 이후 두 예약은 잔액·DB가 달라져 대신 사용하지 않음. 전체 결정 적합성은 독립 심사 전 |

14와 23은 같은 고객과 관련된 개발 자료다. 독립된 과제 네 개로 세지 않으며 같은 원천 그룹으로 기록한다. 과제 정의·채점 충돌이 있는 7·39는 주 비교 후보에서 제외한다. 요청/응답 hash·request ID·run/task/repetition·정상 응답 종료를 원본 사건과 대조하며, 공식 점수와 결정 적합성의 잠정 판단을 구분한다.

모든 후보는 현재 고객 ID를 이미 받은 뒤의 예약 결정이다. 공통 안내문은 과거 메모의 ID를 현재 고객 진술로 취급하지 말라고 알리지만, 이 한 단계 입력으로 인증을 건너뛰지 않았다고 검증할 수 없다. 초기 대화나 전체 에피소드에서 별도의 과정 판정이 필요하다.

## 통제 메모와 판정

일반 주의 메모는 현재 정책·고객 요구·도구 관측을 재확인하고 불확실하면 질문하라는 절차다. 연구자 메모는 무료 수하물 허용량에서 실제 필요량을 추정하지 말고 수량을 확인하라는 절차와 예약당 증서 한 장 규칙을 담는다. 작성자는 이전 채점 진단을 본 상태임을 밝히며, 본문에는 공개 정책과 확인 절차만 남기고 숨은 정답 수량은 넣지 않는다. 독립적인 본문 검토는 아직 필요하다. 연구자 메모를 이론적 상한이나 검증된 실패 원인으로 부르지 않는다.

현재는 응답과 의미 판정을 만들지 않는다. 이전 14·2의 `total_baggages > 0` 검사기를 임의의 옳았던 수량·변형 상태에 적용하면 정당한 양수 수량도 위반으로 오판할 수 있어 재사용하지 않는다. 이후 case별 기준을 정하고 대상 규칙 교정·새 오류·확인 질문·조회/보류·판정불가를 나누어 기록한다. 원래 잘못된 호출을 하지 않은 것과 필요한 업무를 완료한 것은 별개다. 최종 도구 실행·DB·승인은 후속 에피소드로 확인한다.

공개 정책에 이미 있는 규칙의 재상기와 과거 경험에만 있는 새 정보의 활용도 구분한다. 이번 후보로 자율 조회 선택성을 측정할 수는 없다. 새 정보가 필요한 별도 과제와 도구 안내 요인을 후속 트랙으로 유지한다.

## 다음 유료 실행 전 남은 일

1. 후보 상태·통제 메모를 독립 검토하고 1차 비교와 case별 판정 기준을 확정한다.
2. writer/source/동일 입력의 의존성을 반영한 반복 수·분석·순서·표본 계획을 정한다.
3. 입력/은행/역할별 한도와 전체 금액·호출·시간 한도를 정한다. 준비에서 명시된 은행 한도 초과는 거부하고 입력 한도 초과는 `fits_input_limit=false`로 남기며 본문을 잘라 맞추지 않는다. 현재 입력 한도는 미정이므로 준비 통과를 실행 준비 완료로 표시하지 않는다.
4. 실제 전송에는 기존 기록 게이트웨이의 출처 manifest·요청/응답/비용 감사가 연결되어야 한다. 이 준비물은 실제 기억 노출 사건을 대신하지 않는다.
5. 준비한 코드를 커밋한 뒤 깨끗한 작업 트리에서 별도 ready 프로필을 동결하고 새 유료 실행 상한을 승인받는다. 결과 분석 뒤에는 commit 기준 재현 기록을 추가한다.
