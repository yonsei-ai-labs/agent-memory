# 메모의 이관 언급과 결과 피드백: 원인 확인 실험 설계

2026-11-22 · 초안 · 보류 · 유료 실행 승인을 요청하지 않음

**소매 2회차에서 이관을 언급한 메모를 받은 상담은 상담원이 먼저 시작한 변경 0건 이관이 많았다. 이 문서는 그 연결이 메모 내용 때문인지를 확인하는 하위 진단의 초안이다. 검토에서 편집 조건, 확인용 표본, 작성 지표에 문제가 확인돼 지금 형태로는 실행하지 않는다.** 사후 분석은 내용과 이관의 동반만 보였고, 기록만 한 메모에서도 이관이 많아 권장 문구를 원인으로 지목할 수 없었다. [사후 분석](../reports/20261122-retail-handoff-factors.md) · [프로토콜 초안](../../protocols/drafts/tau2-retail-handoff-wording-v1.json)

## 이 실험의 위치

같은 날의 두 점검과 이 초안에 대한 검토가 범위를 정한다. 계획 점검은 다음 비교의 순서를 기억이 쓰일 판단의 선정, 같은 판단 직전의 고정 상태 비교, 별도 고객에서의 자유 상담 확인으로 제안했고, 이관 문구 삭제를 정당한 이관과 계속 진행해야 할 경우를 함께 둔 하위 진단으로 두었다. 사용자는 11월 22일 대화에서 원인 확인을 먼저 하는 순서를 골랐고, 이후의 검토는 판단 선정을 먼저 하고 이 진단을 그 안의 한 경로로 쓰기를 권했다. 실행 순서는 사용자가 정한다. [31쌍 대조](../reports/20261122-retail-transfer-outcome-causes.md) · [계획 점검과 우선순위](../reports/20261122-retail-plan-alignment.md#다음-비교의-우선순위)

## 검토에서 확인된 문제와 필요한 변경

| 확인된 문제 | 근거 | 실행 전에 바꿀 것 |
| --- | --- | --- |
| 키워드 분류가 메모와 발화를 잘못 가렸다 | `Transferable caution` 한 문장으로 112번이 대상에 들어갔다. 고객이 먼저 사람을 찾은 발화를 놓쳤고, 주문 사이에 물건을 옮길 수 없다는 답변이 이관 제안으로 잡힌다 | 메모는 조건을 가린 판독의 판정을 쓴다. 재생 응답은 이관 도구 호출과 말로 한 연결 제안을 따로 세고, 말로 한 제안은 판독으로 정한다 |
| 이관 문장을 지우면 다른 단서도 사라진다 | 계속 진행한 지점의 편집 비교 81쌍 중 19쌍에서 한쪽만 제목 전체가 바뀐다. 주문번호가 든 제목이 있고, 도구가 잘못 반환한 가격과 이관 판단이 한 문장에 있는 메모가 있다 | 두 편집 조건의 제목을 같은 방식으로 처리한다. 본문은 관측 사실을 남기고 이관에 관한 구절만 바꾼 편집본을 미리 만들어 고정한다 |
| 전체 상담을 확인할 새 고객이 없다 | 소매 114과제에서 세 실험 밖의 고객은 4명·8과제이고, 그중 3명은 11월 19일 실험에 나왔다. 남는 50번의 공식 참조 행동은 사람 상담원 연결 한 건이다 | 3부의 표본을 먼저 정한다. 다른 도메인·벤치, 새로 만든 과제, 같은 고객의 재사용 중 무엇을 쓸지와 그 한계를 실행 전에 적는다 |
| 작성 지표가 언급 빈도까지만 잰다 | 이관을 권한 메모와 말린 메모가 같은 한 건이다. 기존 메모 대부분이 피드백이 없었다는 사실을 본문에 적고 있다 | 피드백 조건을 드러내는 표현을 가린 뒤 권장·만류·기록을 판독한다. 판정 기준은 사후 분석에 쓴 것을 그대로 쓴다 |

사후 분석의 재판정 결과도 설계에 반영해야 한다. 기록만 한 메모의 상담도 같은 과제·반복의 무노트보다 상담원이 시작한 이관이 많았고(+7.2%p, 95% 구간 +2.0∼+13.7%p), 두 입장이 함께 있던 곳에서 권장 메모가 기록 메모보다 이관이 많지 않았다(−5.3%p, −13.4∼+2.0%p). 권장 문구만 지우는 편집은 이 관측과 맞지 않는다. 편집 조건은 이관이 있었다는 사실의 언급까지 바꾸는 것과 권고만 바꾸는 것을 나눠야 한다. [입장별 비교](../reports/20261122-retail-handoff-factors.md#권장한-메모와-기록만-한-메모)

## 검토한 방식

| 방식 | 얻는 것 | 잃는 것 | 판단 |
| --- | --- | --- | --- |
| 무노트 상담의 미리 정한 지점에 메모만 넣어 다음 응답 하나를 본다 | 대화가 메모의 영향을 받은 적이 없다. 고객 발화의 변동이 없다 | 지점 정의가 실제 이관 시점과 다를 수 있다. 한 응답은 공식 성패가 아니다 | 채택 |
| 메모 상담의 이관 직전 대화에서 메모만 바꾼다 | 이관이 실제로 일어난 상태를 그대로 쓴다 | 앞선 대화가 원래 메모 아래에서 만들어졌고, 이관이 일어난 상태만 고른다 | 제외. 최초 노출 때부터의 효과를 추정할 수 없다 |
| 고친 메모로 전체 상담을 바로 다시 비교한다 | 공식 성패를 직접 본다 | 고객 대화가 매번 달라지고, 확인에 쓸 새 고객이 없다 | 3부의 표본이 정해진 뒤로 미룬다 |

## 1부: 메모에 노출된 적 없는 상태의 한 응답 비교

**대상은 이관을 다룬 메모가 배정됐던 33과제에서 무노트가 공식 성공한 2회차 상담이다.** 과제마다 두 종류의 지점을 하나씩 쓴다. 같은 과제에 해당 상담이 여럿이면 실험·반복의 고정 순서에서 첫 상담을 쓴다. 기록을 대조한 결과 35개 지점이 존재했다. 지점은 재생 결과를 보고 더하거나 빼지 않는다. [상담별 분류](../../artifacts/analyses/20261122-retail-handoff-factors.json#L4323)

| 지점 | 정의 | 수 |
| --- | --- | ---: |
| 계속 진행한 지점 | 이관이 한 번도 없던 성공 상담에서, 첫 주문 조회 뒤 고객에게 보낸 첫 답변을 만든 상담원 요청 | 25과제·고객 17명 |
| 이관한 지점 | 이관 도구 호출이 있던 성공 상담에서, 그 호출을 만든 상담원 요청 | 10과제·고객 10명 |

공식 성공은 그 지점의 행동이 채점 기준과 어긋나지 않았다는 근거로만 쓴다. 이관한 지점 10개는 주문 변경 뒤의 이관이거나 참조 행동이 DB를 바꾸지 않는 과제의 이관이다.

| 조건 | 입력 | 상태 |
| --- | --- | --- |
| `none` | 기록된 요청 그대로 | 정해짐 |
| `empty` | 메모 안내와 빈 목록 | 정해짐 |
| `original` | 그 과제에 배정됐던 본문 있는 메모 각각 | 정해짐 |
| 이관 언급을 바꾼 편집본 | 이관이 있었다는 사실과 권고를 각각 바꾼 판본 | 다시 설계 |
| 같은 분량의 다른 구절을 바꾼 편집본 | 위 편집과 같은 방식으로 제목을 처리한 대조 | 다시 설계 |

메모 안내는 소매 본인확인 문구를 고친 판본을 쓴다. 연구자가 고친 메모는 진단용 개입이고 자율 작성 메모의 성적에 합치지 않는다. 편집본은 재생 결과를 보기 전에 파일로 고정하고, 원문과 편집문을 나란히 남긴다. 대화·도구 정의·모델·추론 설정·시드·출력 상한은 기록된 요청과 같다. 업무 도구, 고객 시뮬레이터, 채점, 다음 차례의 대화는 실행하지 않는다.

지점마다 이관을 다룬 메모와 그렇지 않은 메모를 각각 네 개까지 쓰고, 넘으면 메모 해시가 작은 순서로 고른다. 이전 편집 규칙으로 센 서로 다른 입력은 461개였다. 편집 조건이 바뀌면 다시 센다. 입력의 순서는 고정 시드로 섞고, 같은 입력의 반복은 이어서 보낸다.

각 응답에서 이관 도구 호출, 주문·주소 변경 도구 호출, 그 밖의 도구 호출은 호출 이름으로 센다. 고객에게 사람 연결을 제안했는지는 조건을 가린 판독으로 정한다. 오류·잘린 응답은 미관측으로 두고 실패나 이관으로 채우지 않는다.

| 비교 | 지점 | 답하는 질문 |
| --- | --- | --- |
| 주 비교: 이관을 다룬 메모의 `original`과 `empty` | 계속 진행한 지점 | 메모 내용이 처음 주어졌을 때 진행하던 상담을 이관 쪽으로 옮기는가 |
| 이관 언급을 바꾼 편집본과 대조 편집본 | 계속 진행한 지점 | 그 변화가 이관 언급에 고유한가 |
| 이관 언급을 바꾼 편집본과 `original` | 이관한 지점 | 언급을 바꾸면 채점과 어긋나지 않던 이관까지 줄어드는가 |
| 이관을 다루지 않은 메모의 `original`과 `empty` | 두 지점 | 메모 일반이 이관 여부를 바꾸는가 |
| `empty`와 `none` | 두 지점 | 메모 안내만으로 달라지는가 |

지점별 비율 차이를 과제, 고객 순으로 평균하고 고객을 10,000번 재표집해 구간을 낸다. 주 비교와 둘째 비교의 구간이 모두 0을 벗어나고 방향이 맞을 때만 이관 언급을 다루는 작성 변경을 3부 후보로 올린다. 결함이 있던 다섯 원천(20·21·36·71·100번)의 메모는 합계와 별도로도 보고한다. 한 응답의 차이는 그 상태에서의 개입 효과다. 계속 진행한 지점은 첫 답변 하나이므로, 고객이 다시 요구한 뒤에 일어나는 이관은 이 비교에 잡히지 않는다. 계속 진행한 지점은 고객 17명, 이관한 지점은 고객 10명에서 나오므로 구간이 넓을 수 있다.

## 2부: 1회차 성패를 알려 준 작성

**같은 과제 재수행의 1회차 경험 66건(공식 성공 47·실패 19, 이관이 있던 14건 포함)을 피드백 없음과 성패만 알려 준 조건으로 다시 작성한다.** 네 형식을 유지하면 66×4×2 = **528회 작성**이다. 두 조건의 작성자 입력은 피드백 메시지 하나만 다르다. 성패만 알려 준 조건에는 공식 성공 여부의 참·거짓만 들어가고 채점 정답·사유는 들어가지 않는다. 작성 지침은 공통 지침, 형식별 한 줄, 저장 도구 사용을 명시한 보완 문단을 그대로 쓴다. 모델·시드·작성 한도는 전이 재실험의 작성과 같고, 작성마다 새 세션과 빈 은행을 쓴다. 두 조건을 한 묶음에서 해시 순서로 섞어 실행한다. [피드백 수준의 입력](../development/worker-written-memory.md#작성-입력과-피드백) · [보완 문단](../../protocols/pilots/tau2-retail-transfer-revision-v1.json)

| 측정 | 정의 |
| --- | --- |
| 이관에 대한 입장 | 피드백 조건을 드러내는 표현을 가린 뒤, 메모가 이관을 다루는지와 권장·만류·혼합·기록 중 무엇인지를 조건을 가린 판독으로 정한다 |
| 이관 없이 성공한 원천의 이관 권장 | 1회차가 이관 없이 공식 성공한 원천에서 이관을 권하거나 무이관을 문제로 적은 메모의 비율. 32번 같은 경우를 센다 |
| 1회차에 고른 상품 번호의 보존 | 1회차 실패가 대체 상품 선택에서 갈린 원천에서, 당시 고른 번호가 메모에 그대로 남은 비율 |
| 저장 여부와 길이 | 저장 도구 호출 성공, 본문 글자 수 |

주 비교는 같은 원천·형식 안에서 두 피드백 조건의 입장 분포 차이이며, 과제·고객 순으로 평균하고 고객을 재표집한다. 가리는 규칙과 판정 기준은 작성물을 읽기 전에 고정한다. 항공의 한 원천에서 피드백 없음 5회와 실패만 알려 준 5회를 비교했을 때 목표한 교훈을 명확히 담은 작성물은 없었다. 성패 한 비트가 메모를 바꾸지 않는 결과도 이 측정의 유효한 결과다. 이 단계는 메모 내용만 측정하고 후속 상담의 성패는 측정하지 않는다. [항공의 피드백별 작성](../reports/20261117-memory-writing-results.md) · [판정 기준](../../artifacts/analyses/20261122-retail-handoff-annotations.json)

## 3부: 전체 상담 확인의 틀

1·2부에서 행동이나 메모 내용이 달라진 변경만 전체 상담으로 가져간다. 무노트는 과제·반복마다 메모 조건과 같은 수로 반복한다. 지표는 상담원이 시작한 변경 0건 이관, 필수 변경 완료율, 고객 안내 판정, 공식 성공이며 실행 전에 고정한다. **이번 탐색에 쓰지 않은 소매 고객은 확인에 쓸 만큼 남아 있지 않다.** 표본의 출처를 정하기 전에는 3부를 계획에 넣지 않는다. 과제 수·반복·금액은 중요하게 볼 차이와 검정력을 정한 뒤에 정한다.

## 비용의 규모

이전 편집 규칙으로 잡은 규모는 1부 4번 반복 1,844요청에 $0.55∼1.7, 2부 528회 작성에 $0.55였다. 캐시된 요청 $0.00013과 캐시 없는 요청 $0.0005(3.6천 토큰)의 관측 단가, 전이 재실험의 작성 176회 $0.183에서 환산했다. 2부의 판독은 모델 요금이 없다. 편집 조건과 3부의 표본이 정해지기 전에는 상한을 제안하지 않는다. 프로토콜 초안의 한도는 비워 두었고, 승인된 값으로 별도 실행 프로필을 고정한 뒤에만 유료 요청을 보낸다.

| 기록된 상담원 요청에 메모 입력만 넣거나 바꿔 한 응답을 보내고 기록·감사하기 | 항공용 [한 응답 실행 경로](../development/snapshot-replay-runtime.md)가 있다. 소매 기록에서 지점을 고르고 조건을 만드는 배치가 필요하다 |
| 편집본 파일 | 없음. 원문·편집문·바꾼 구절의 종류를 메모별로 적고 해시로 고정한다 |
| 성패만 알려 준 작성 | [작성 경로](../development/worker-written-memory.md)가 피드백 수준을 지원한다. 소매 네 형식 배치는 피드백 없음으로 고정돼 있어 별도 버전이 필요하다 |
| 조건을 가린 판독 | 사후 분석에서 메모 125개와 대화 132건에 썼다. 근거 인용을 원문과 대조하는 검사가 분석 코드에 있다 |
| 사전 점검 | 네트워크 없이 지점, 조건별 요청 원문, 요청 수, 요청별 최대액을 출력한다 |

기존 원본과 사후 분석 결과는 고치지 않는다. 새 실행은 새 폴더에 남긴다.
